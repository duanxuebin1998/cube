### `0x10` 写帧的现场特殊格式

标准 Modbus `0x10` 请求中的 byte count 通常等于 `qty * 2`。本次抓包中 Wartsila 主机下发帧的 byte count 字段等于寄存器数量 `qty`，但后续数据区仍包含 `2 * qty` 字节。

现场格式：

```text
[addr][10][startHi][startLo][qtyHi][qtyLo][count=qty][data: 2*qty bytes][crcLo][crcHi]
```

代表帧：

```text
01 10 00 5A 00 04 04 01 F4 C3 50 03 E8 00 C8 1F 78
```

解析结果：

| 字段 | 值 |
| --- | --- |
| 从站 | `1` |
| 起始地址 | `0x005A` |
| 寄存器数 | `4` |
| byte count 字段 | `0x04`，等于寄存器数 |
| 数据寄存器 | `0x01F4`、`0xC350`、`0x03E8`、`0x00C8` |
| 工程含义 | 最低点 `500 mm`、最高点 `50000 mm`、间距 `1000 mm`、最高点距液面 `200 mm` |

> **Wartsila 现场兼容特例：不得只按通用 Modbus 规则收紧。** 当前工程同时接受 `byteCount=qty` 和 `byteCount=qty*2`；无论字段采用哪种口径，实际数据区必须严格为 `2*qty` 字节。按源码 PDU 定义，`pdata = &pdu[6]` 正好指向 `byteCount` 后的首个数据字节，两种格式的数据起点一致。

#### 场景状态迁移

抓包中地址 `1` 的 `0x0007` 工作状态迁移如下：

| 场景 | 状态迁移 |
| --- | --- |
| 罐底分布测量 | `0x0840` 下行到固定点 -> `0x0044` 固定点监测 -> `0x0C64` 开始分布 -> `0x0C60` 分布测量中 -> `0x1840` 下行到最低点/界面附近 -> `0x0840` 下行到固定点 |
| 提零点 | `0x0044` 固定点监测 -> `0x0864` 接收提浮子 -> `0x0860` 液相上行 -> `0x2860` 气相上行 -> `0x2068` 零点待机 |
| 零点开始分布测量 | `0x2068` 零点待机 -> `0x2848` 零点收到分布测量 -> `0x2840` 空气中下行 -> `0x1840` 接近界面 -> `0x0840` 运行到测量点 -> `0x0C64` 开始分布 -> `0x0C60` 分布测量中 -> `0x0840` 回固定点 |
| 1 月 28 日分布测量 | `0x0044` 固定点监测 -> `0x0C64` 开始分布 -> `0x0C60` 分布测量中 -> `0x1840` 接近界面 -> `0x0840` 回固定点 -> `0x0044` 固定点监测 |
| 拔传感器 | `0x0840` 运行到测量点 -> `0x0044` 固定点监测 -> `0x0860` 提浮子上行 -> `0x0820` 提零点过程拔出传感器 -> `0x0860` 继续提浮子上行 |

关键结论：

- `0x0C64` 只短暂出现，表示分布测量开始边沿；主机随后长期看到 `0x0C60`。
- `0x2840` 在零点开始分布场景中大量出现，和 Excel 状态表“空气中、下行/密度测量完成”一致，不能简单等同为错误。
- `0x0820` 只在拔传感器场景出现，伴随密度异常飙高和频率跌落，应作为异常态或错误态模拟。

| 场景 | `0x0050` 点数 | 液位 | 下载点位 | 点位间距特征 |
| --- | --- | --- | --- | --- |
| 罐底分布测量 | `23` | `23448 mm` | 实际下载 `25` 个槽位，非零点 `25` | 约 `500 mm` 起，每约 `1000 mm` 一个点，到 `24503 mm` |
| 零点开始分布测量 | `114` | `23450 mm` | 实际下载 `115` 个槽位，非零点 `115` | 约 `498 mm` 起，每约 `200 mm` 一个点，到 `23300 mm` |
| 1 月 28 日分布测量 | `23` | `23240 mm` | 下载 `0x0064..0x00DC` 约 25 个常规槽位，另有 `0x06A4/6` 读取 | 常规点约 `500 mm` 起，每约 `1000 mm` 一个点；末尾出现非连续补充点 |

典型 23 点场景的点位序列开头和结尾：

```text
点 1:  501 mm, 438.6 kg/m3
点 2: 1503 mm, 438.6 kg/m3
点 3: 2500 mm, 438.6 kg/m3
...
点 21: 20500 mm, 438.7 kg/m3
点 22: 21504 mm, 438.8 kg/m3
```

这里存在一个重要实现判断：`0x0050` 返回的“点数”更像有效分布点数，主机仍可能多读一个 5 点块并自行忽略超出有效点数的槽位。因此项目实现不能只按 `measurement_points` 后立即越界异常；建议对超出有效点数但落在寄存器容量内的点返回 0 或最后缓存值，避免主机误判通讯失败。

#### `0x0032/23` 与 `0x06A4/6` 补充块

1 月 28 日抓包中出现 3 次 `addr1 0x0032/23` 和 3 次 `addr1 0x06A4/6`。这两个块不在当前工程寄存器表中。

`0x0032/23` 样例：

```text
43A2 251F 3F31 CC10 433A 428F 39B0 2928 07D0 43AF 0000 41C8 0000 0019 0000 0000 0000 0000 0001 0000 01F4 C350 0000
```

按 32 位浮点偶对粗解，前几项近似为 `324.29`、`0.69452`、`186.26`、`0.000336`，后部还能看到 `0x01F4` 和 `0xC350`，与 500/50000 参数有关。该块疑似是分布测量参数、算法系数或诊断信息混合区，当前不能按普通 16 位业务寄存器定论。

`0x06A4/6` 样例：

```text
0013 4A45 0000 1223 00C4 0001
```

该块出现于 `0x0032/23` 之后，字段语义未确认。若现场主机依赖这两个地址，当前工程会返回现有寄存器池内容或地址异常，需专项补帧测试。

#### 地址 `2/3/4` 辅助数据块

地址 `2/4` 的 `0x012C/33`、`0x0154/33`、`0x0175/33`、`0x019A/33` 响应更像“1 个 16 位头字段 + 16 个 IEEE754 float32”。按该方式解码：

| 地址/范围 | 样例头字段 | 解码结果特征 |
| --- | --- | --- |
| `addr2 0x012C/33` | `0x0000` | 16 个 float 约为 `-1595..-1551`，像温度或探头原始补偿值 |
| `addr4 0x012C/33` | `0xFFFF` | 16 个 float 均为 `1.0`，像有效标志、缩放系数或默认值 |
| `addr2/3/4 0x00C8/17` | 无独立头字段 | 可按 32 位浮点解出液位附近数值，例如 `23539.0`、`23553.6`、`23552.0`，后续还有 `-1593.0`、`11.0` 等辅助值 |

地址 `3 0x001E/5` 稳定返回 ASCII `1709180821`。如果上位系统用地址 `3` 判断设备身份，模拟时需要至少响应该 ID 块。

#### 异常响应

抓包中 `addr1` 出现 `01 83 02 C0 F1`，表示功能码 `0x03` 的 `Illegal Data Address`。出现时间集中在分布点下载末尾：

| 场景 | 次数 | 含义 |
| --- | --- | --- |
| 罐底分布测量 | `2` | 主机读取到设备不支持或数据未准备的地址，设备返回非法地址 |
| 零点开始分布测量 | `3` | 长分布下载末尾同类异常 |

实现建议：在确认主机实际读取边界前，不要把所有越界读都静默返回 0；非法地址响应也是原设备行为的一部分。但对于主机固定多读 5 点块的情况，仍需区分“容量内但无有效点”和“容量外非法地址”。

## 地址 `2`、`3`、`4` 观察到的寄存器

当前工程只按单个 `SlaveAddress` 响应，不模拟 Wartsila 原系统的多从站轮询。若现场主机仍轮询地址 `2`、`3`、`4`，需要决定是做多地址兼容、地址别名，还是只服务地址 `1` 并接受其它地址超时。

| 从站 | 请求范围 | 抓包现象 | 备注 |
| --- | --- | --- | --- |
| `2` | `0x00C8` 数量 `17` | 高频轮询，响应含多个类似 IEEE754 的寄存器对 | 可能是温度/压力/探头数据块 |
| `2` | `0x012C`、`0x0154`、`0x0175`、`0x019A` 数量 `33` | 分布过程读取，响应含 `0xC4xx`、`0x3F80` 等模式 | 可能是辅助 profile 或温度棒数据 |
| `3` | `0x001E` 数量 `5` | 响应 ASCII `1709180821` | 设备序列号或 ID |
| `3` | `0x00C8` 数量 `17` | 部分场景读取 | 辅助数据块 |
| `4` | `0x00C8` 数量 `17` | 高频轮询 | 辅助数据块 |

## 设备工作状态码

| 状态码 | Wartsila 原始含义 | CUBE/项目含义 |
| --- | --- | --- |

| `0x0044` | 固定点监测中 | 固定点监测 |
| `0x0C64` | 开始密度分布测量 | 密度分布测量中 |
| `0x0C60` | 向上运行，密度分布测量中 | 密度分布测量中 |

## 与当前工程实现的对照

| 项目 | 当前状态 | 风险/待确认 |
| --- | --- | --- |
| 主状态区 `0x0000~0x000F` | 已实现 | 温度偏移、温度倍率、频率倍率需和 Excel 公式确认 |
| 分布参数 `0x005A~0x005D` | 已实现 | `0x005B` 最高点必须按无符号 16 位处理 |
| 分布结果 `0x0050~0x0053` | 已实现 | `0x0052/0x0053` 未完全解码 |
| 密度点 `0x0064` 起 | 寄存器表定义 200 点，当前填充循环只写 100 点 | 若主机读取超过 100 点会得到默认值；公开资料提到 LTD 可采样 250 点，是否需要扩展到 200 或 250 点需确认 |
| `0x10` 特殊 byte count | 同时接受 `bytes == qty` 和 `bytes == 2*qty`，实际数据区均严格校验为 `2*qty` 字节 | 现场 Wartsila 与标准 Modbus 双兼容；不得把现场格式当作短帧拒绝 |
| 多从站地址 `2/3/4` | 当前不支持 | 现场主机若持续轮询这些地址，会表现为超时 |
| 地址 `3` 设备 ID | 当前不支持 | 若上位机依赖 ID `1709180821`，需要模拟 |
| 状态码 | 部分映射 | 完成态、零点收到分布测量、拔传感器异常态需补齐或确认 |
| `0x0032/23` 与 `0x06A4/6` | 当前无明确映射 | 1 月 28 日抓包中有效出现，需确认主机是否把它们作为必答诊断块 |

## Golden frame 候选

后续修正或补测试时，建议直接把这些帧放入协议契约测试：

| 用途 | 请求帧 | 期望 |
| --- | --- | --- |

## 建议后续执行

1. 先基于本次抓包建立 `0x03`、`0x10` golden frame 测试，尤其覆盖特殊 `0x10` byte count。
2. 为 `handle_0x10()` 保持双格式协议契约测试，确认非标准 Wartsila 帧和标准 Modbus 帧写入 `0x005A~0x005D` 后 CPU2 都收到 `500/50000/1000/200`，截短、超长或其它 `byteCount` 必须拒绝。
3. 决定是否需要兼容地址 `2`、`3`、`4`。若现场 Wartsila 主机把这些地址视作必答设备，需要新增多地址响应或地址别名策略。
4. 按 `设备状态表` 对齐 `0x0007` 工作状态，优先确认完成态 `0x2840`。
5. 确认密度点数量上限：当前工程定义 200 点但实际填充 100 点；本次抓包最大有效下载 115 个点，公开资料提到 LTD 可采样 250 点，如需模拟完整 profile，评估扩展到 200 或 250 点。
6. 明确 `0x0032/23`、`0x06A4/6` 是否必须实现；如果上位机仅容忍非法地址，可记录为未支持诊断块，否则需要补寄存器映射。
7. 统一温度和频率倍率说明，避免 Excel 公式、寄存器注释和代码实现三者口径不一致。
