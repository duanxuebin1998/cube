# DM4传感器协议资料

更新日期：2026-08-18

本目录保存DM4传感器当前采用“多参数传感器通信协议 V4.0”的原始资料和入口说明。DM4是物理传感器类型，CPU2/CPU3共享类型固定为`DM4_SENSOR=14`；V4是普通运行协议，Safe是同一DM4传感器的预留运行协议模式。V4.0的参数地址和控制命令语义不兼容V3.0，通信帧、数据编码、应答与错误处理规则延续V3.0。

## 当前边界

- 参数0～25可读，参数65～159可读写；参数26～64为不可访问保留区。
- 密度单位统一为`kg/m³`，动力黏度为`cP`，运动黏度为`cSt`。
- 协议只有密度和液位两种测量模式：`D`进入密度模式，`S`进入液位模式；`L`和`M`不是测量模式，分别控制密度模式下测水和磁零点功能的使能/关闭，且二者互斥。
- 主动发送帧固定为72字节：`55 AA 01 A1`开头，携带参数0～14、16位小端序号和CRC16/MODBUS。
- CRC覆盖字节0～69；主动发送周期为500 ms，抖动上限未知。
- 部分无线主机旧固件会在规范帧偏移50处插入50个`0x00`，形成122字节帧。CPU2只在删除该固定区间后恢复的72字节帧通过全部固定字段、地址和CRC校验时兼容接受。
- 链路为RS485半双工；以完整主动帧最后一个字节为起点等待至少15 ms后，才允许发送关闭主动上报的命令。主动上报到期时传感器优先上报，CPU2收到有效8字节应答后才能进入交互通信。
- 参数65会持久化，CPU2应直接消费主动数据，只在必要的模式切换或配置阶段集中停流交互，避免频繁写0/1。
- 参数0～14不是同一次采样结果，而是组帧时各参数的最新值；完整帧可以原子发布，但不能当作同一测量时刻的数据。
- 同一RS485总线允许多台设备，但同时只能有一台主动上报；地址0也会主动上报。
- CPU2按16位序号统计有效包、确认丢包和丢包率，保存最近异常原包；连续3个包异常时按第3个异常的具体原因进入统一故障管理。串口`V4G`打印质量和异常包，`V4C`清除观察窗口统计。
- 周期抖动、命令最大应答时间、恢复后的首帧延时和序号规则仍待台架确认。
- 参数4为随模式变化的当前测量频率：液位模式返回液位频率，密度模式返回密度谐振频率；CPU2必须结合状态字解释。
- 已使用传感器直连和无线滑环抓包确认72字节规范帧、固定50字节补零现象、R01/R67交互和地址0广播应答；连续异常、丢包率、序号回绕和长期稳定性仍需实机故障注入及长稳验证。
- 普通上电识别只走V4，不发起Safe `HELLO`。Safe进入、退出和业务切换接口尚未冻结，不得把当前DM4识别成功解释为Safe通信已启用。
