## 1. 文档信息

| 项目 | 内容 |
|---|---|

本文面向上位机、CPU2、测试程序和后续固件维护人员，定义 DSM CPU1 SIL 当前 V5.4 固件的对外串口命令、响应帧、校验算法、电源管理、异常语义和兼容性限制。

工程附带的 `DSM_CPU0-CPU1通讯协议.xlsx` 保存了历史命令和样例，但其中部分字段仍对应旧版本。当前行为以本仓库 `master` 工作区V5.4源码为准，历史工作簿只作为辅助参考。

> 重要：`release/v6.1` 和 `v5.0-lemis` 是从 V5.0 派生的独立维护线，不是 V5.4 的顺序升级版本。不同维护线的版本响应、`CS` 命令和 CPU0 内部协议存在差异。

## 2. 协议分层

本固件包含两层通信：

1. **CPU1 对外协议**：USART3，采用 `C + 单字符命令` 请求和定长 ASCII 响应，是本文的主体。
2. **CPU1 与 CPU0 内部协议**：USART2，采用固定 8 字节二进制寄存器帧。部分对外数据由 CPU1 轮询 CPU0 后缓存，部分控制命令会转发到 CPU0。内部协议见附录 A。

对外数据流为：

```text
上位机/CPU2
    │  两字节命令：'C' + 命令字符
    ▼
USART3 接收中断
    │  普通命令设置WorkState；电源域命令只设置待处理位
    ▼
CPU1 主循环
    │  读取缓存、采样本机数据或访问 CPU0
    ▼
USART3 定长响应
```

## 3. 物理层和串口参数

| 项目 | 参数 |
|---|---|
| MCU 外设 | USART3 |
| 发送引脚 | PB10 / USART3_TX |
| 接收引脚 | PB11 / USART3_RX |
| 波特率 | 9600 bit/s |
| 数据位 | 8 bit |
| 停止位 | 1 bit |
| 奇偶校验 | 无 |
| 硬件流控 | 无 |
| 收发模式 | 全双工 UART |
| 字节顺序 | ASCII 帧按发送顺序传输；BCC 为单个原始字节 |

USART3 发送函数只等待发送数据寄存器空，不控制外部收发方向。V4.10 起源码不再在发送前后切换 PB3，也不保留固定方向切换延时。如果板级接口使用半双工 RS-485 收发器，板级硬件必须提供自动方向控制或其他等效的收发方向方案；当前固件不提供该时序控制。

## 4. 请求帧

### 4.1 通用格式

所有对外请求均为两个 ASCII 字节：

| 字节偏移 | 长度 | 内容 | 说明 |
|---:|---:|---|---|
| 0 | 1 | `0x43` / `'C'` | 固定帧头 |
| 1 | 1 | 命令字符 | 区分大小写 |

示例：

```text
查询 CPU1 本机版本：43 76        ASCII "Cv"
查询传感器编号：    43 4E        ASCII "CN"
查询密度数据：      43 66        ASCII "Cf"
```

请求帧没有地址、长度、序号、BCC、CRC 或强制结束符。建议直接发送两个字节；如果上位机额外发送 `\r\n`，当前固件会在有效命令已经解析完成后忽略这两个字符，但不应依赖此行为作为协议定义。

### 4.2 接收状态规则

- 收到 `'C'` 后，固件置位内部 `C_Flag`。
- 随后的第一个非 `'C'` 字节被解释为命令字符。
- 命令有效或无效都会清除 `C_Flag`。
- 单独收到 `'C'` 后没有超时清除机制，任意时间后的下一个非 `'C'` 字节都可能被当作命令。
- 普通命令仍共用一个全局 `WorkState`。`CH/CZ/Ch/Cz/CX` 使用独立待处理位，重复的同类请求会合并而不会重复启动PB4时序。
- 协议仍按串行事务设计；上位机必须发送一个命令并等待对应响应后，再发送下一条不同命令。

## 5. 响应通用规则

### 5.1 定长解析

响应没有统一的帧头和长度字段，必须根据请求命令选择预期长度。除 ACK 和两个版本帧外，正常数据帧一般采用：

```text
固定长度有效载荷 + 1 字节 BCC + 0x0D + 0x0A
```

注意：

- BCC 是原始字节，可能等于控制字符、`0x00`、`\r` 或 `\n`。
- `CV` 和 `Cv` 响应没有 `\r\n`。
- 因此接收端不能只使用“读到换行结束”的文本行解析方式，应按命令对应的固定长度接收。

### 5.2 BCC 算法

历史函数名为 `CalculationBCC`。该算法不是对全部有效载荷字节进行 XOR，而是**跳过有效载荷的第 2 个字节**，即跳过索引 1：

```text
BCC = payload[0]
BCC = BCC XOR payload[2]
BCC = BCC XOR payload[3]
...
BCC = BCC XOR payload[N-1]
```

等价 C 参考实现：

```c
uint8_t DsmCpu1_CalculateBcc(const uint8_t *payload, size_t length)
{
    uint8_t bcc = payload[0];
    size_t i;

    for (i = 2; i < length; ++i)
    {
        bcc ^= payload[i];
    }

    return bcc;
}
```

对接程序必须保留这个历史算法，不能把 `payload[1]` 加入 XOR。

校验样例：

| 有效载荷 | 长度 | BCC |
|---|---:|---|
| `A+016920B+017190` | 16 | `0x2A` / `'*'` |
| `N2009924` | 8 | `0x48` / `'H'` |
| `D03.2952` | 8 | `0x55` / `'U'` |
| `0A442` | 5 | `0x02`，不可打印控制字符 |
| `05.40` | 5 | `0x1A`，不可打印控制字符 |

### 5.3 数字格式

协议使用 C `sprintf` 的固定最小宽度格式：

- `0`：左侧不足位数时补零。
- 宽度是最小宽度，不是最大宽度；数值超出字段能力时会扩展并破坏后续固定偏移。
- 浮点数按指定小数位四舍五入输出。
- 正数符号通常由格式字符串中的固定 `'+'` 提供；负数由 `%f` 自身输出 `'-'`。

上位机应把文档中的字段宽度同时作为有效范围约束，不应只依赖 ASCII 转数值。

## 6. 命令总表

### 6.1 兼容、准备和控制命令

| 请求 | 当前 V5.4 行为 | 响应 | 说明 |
|---|---|---|---|
| `CF` | 仅置应答状态 | `%\r\n` | 兼容旧通信程序，不执行实际采集 |
| `CP` | 仅置应答状态 | `%\r\n` | 兼容旧通信程序，不执行实际采集 |
| `CA` | 仅置应答状态 | `%\r\n` | 兼容旧通信程序，不执行实际采集 |
| `CH` | 启动PB4电源域、初始化MPU6050并预采样 | `%\r\n` | 后续可用 `Ch` 查询角度 |
| `CZ` | 启动PB4电源域、初始化MPU6050并预采样 | `%\r\n` | PB4同时给零点和陀螺仪供电，后续可用 `Cz` 查询零点 |
| `CX` | 使PB4电源域掉电并清除旧样本、滤波和I²C状态 | `%\r\n` | OFF/READY/STARTING下均幂等；完成安全关断后ACK |
| `CL` | 将 PA5 置高 | `%\r\n` | 历史定义为“开启测水探针”；当前 PA5 同时是 FDC2214 软件 I²C SCL |
| `CD` | 向 CPU0 发送密度模式命令 | `%\r\n` | CPU0 功能码 `D`、参数码 `T` |
| `CB` | 向 CPU0 发送液位模式命令 | `%\r\n` | CPU0 功能码 `T`、参数码 `T` |
| `CR` | 立即执行 `NVIC_SystemReset()` | 无立即响应 | 重启过程中会主动发送两次 `%\r\n` |
| `CS` | 当前入口已注释 | 无响应 | V5.2～V5.4不支持；V6.1和部分旧版本支持 |

`CD` 和 `CB` 最终都会发送 `%\r\n`，当前实现不会根据 CPU0 模式切换是否成功改变 ACK。因此 `%` 只表示 CPU1 已执行本地命令处理，不是 CPU0 成功确认。

为兼容一代计量仪，V5.4中的 `CH/CZ` 即使PB4启动或MPU6050预采样最终失败，仍返回原有 `%\r\n`；该ACK仅表示准备命令已被处理，不证明陀螺仪已经READY。主机必须通过后续 `Ch/Cz` 数据响应判断本次数据是否可用，启动失败时后续查询返回既有19字节错误帧。

## 7. 响应帧详细定义

### 7.1 ACK 帧

适用命令：`CF`、`CP`、`CA`、`CH`、`CZ`、`CL`、`CD`、`CB`、`CX`。

| 偏移 | 长度 | 固定值 |
|---:|---:|---|
| 0 | 1 | `0x25` / `'%'` |
| 1 | 1 | `0x0D` |
| 2 | 1 | `0x0A` |

十六进制：

```text
25 0D 0A
```

ACK 帧没有 BCC。

### 7.2 密度数据帧

适用命令：`Cf`、`Cd`。

格式化模板：

```text
正温度：F+%06.0fD+%06.1fT+%06.4f
负温度：F+%06.0fD+%06.1fT%07.4f
```

| 偏移 | 长度 | 格式 | 含义 |
|---:|---:|---|---|
| 0 | 1 | `F` 或 `E` | 正常为 `F`；电压异常时为 `E` |
| 1 | 1 | `+` | 固定字符 |
| 2 | 6 | `%06.0f` | CPU0 密度扫频频率 |
| 8 | 1 | `D` | 密度字段标识 |
| 9 | 1 | `+` | 固定字符 |
| 10 | 6 | `%06.1f` | CPU0 密度，一位小数 |
| 16 | 1 | `T` | 温度字段标识 |
| 17 | 7 | 正温度 `+%06.4f`；负温度 `%07.4f` 的线上前 7 字节 | CPU0 温度字段 |
| 24 | 1 | BCC | 对偏移 0～23 按历史算法计算 |
| 25 | 1 | `0x0D` | CR |
| 26 | 1 | `0x0A` | LF |

代码先使用 `sprintf` 生成完整字符串，再固定在偏移 24 写入 BCC。温度绝对值小于 10 时，温度字段通常能在 7 字节内完整表达；温度绝对值达到两位整数时，格式化结果会扩展到 8 字节，最后一位小数被偏移 24 的 BCC 覆盖。

示例：频率 16920、密度 0.0、温度 19.5700，实际线上帧为：

```text
F+016920D+0000.0T+19.570P\r\n
```

其中温度格式化结果原本为 `+19.5700`，最后一个 `0` 被 BCC `0x50` / `'P'` 覆盖。这是V5.3并由V5.4继续保留的实际固定下标行为，不是推荐的新协议设计。

数据来源说明：CPU1 待机时轮询 CPU0 的密度、温度、动态黏度和两个周期平方值。V5.3/V5.4 的频率不是直接读取 CPU0 参数 16，而是根据 45°周期平方值计算：

```text
Frequency = sqrt(1,000,000,000,000 / SquareMeanOf45degreeSweepPeriod)
```

```text
A+aaaaaaB+bbbbbbC+ccccc.c<BCC>\r\n
```

| 偏移 | 长度 | 格式 | 含义 |
|---:|---:|---|---|
| 0 | 1 | `A` 或 `E` | 正常为 `A`；电压异常时为 `E` |
| 1 | 1 | `+` | 固定字符 |
| 2 | 6 | `%06.0f` | 22.5°扫频周期平方平均值 |
| 8 | 1 | `B` | 字段标识 |
| 9 | 1 | `+` | 固定字符 |
| 10 | 6 | `%06.0f` | 45°扫频周期平方平均值 |
| 16 | 1 | `C` | 字段标识 |

| 25 | 1 | `0x0D` | CR |

### 7.4 陀螺仪角度帧

适用命令：`Ch`。

格式：

```text
A±xxx.xB±yyy.y<BCC>\r\n
```

| 偏移 | 长度 | 格式 | 含义 |
|---:|---:|---|---|
| 0 | 1 | `A` 或 `E` | X 轴字段；电压异常时改为 `E` |
| 1 | 1 | `+` 或 `-` | X 轴符号 |
| 2 | 6 | 数字区 | X 轴角度，一位小数 |
| 8 | 1 | `B` | Y 轴字段标识 |
| 9 | 1 | `+` 或 `-` | Y 轴符号 |
| 10 | 6 | 数字区 | Y 轴角度，一位小数 |
| 16 | 1 | BCC | 校验字节 |
| 17 | 1 | `0x0D` | CR |
| 18 | 1 | `0x0A` | LF |

正值使用 `+%06.1f`，负值使用 `%07.1f`，每个轴固定占 8 字节（字段标识、符号和数字）。

### 7.5 水测量帧

适用命令：`Cl`。

格式：

```text
Dccccc.c<BCC>\r\n
```

实际数值字段使用 `%07.1f`，所以常见形式为：

```text
D00003.3<BCC>\r\n
```

| 偏移 | 长度 | 格式 | 含义 |
|---:|---:|---|---|
| 0 | 1 | `D` 或 `E` | 正常为 `D`；电压异常时为 `E` |
| 1 | 7 | `%07.1f` | FDC2214 换算的外部电容，单位 pF |
| 8 | 1 | BCC | 校验字节 |
| 9 | 1 | `0x0D` | CR |
| 10 | 1 | `0x0A` | LF |

当前算法先读取 FDC2214 通道 0 的 28 位转换数据，换算谐振频率，再按 18 μH 电感和 33 pF 固定电容计算外部电容。计算结果小于 0 时按 0 返回。

V5.0 以前该命令返回 ADC 电压和四位小数；上位机必须根据固件维护线选择解析语义。

### 7.6 液位 AD 帧

适用命令：`Cp`。

格式：

```text
A+aaa.aaB+bbb.bbC+000.00<BCC>\r\n
```

| 偏移 | 长度 | 格式 | 含义 |
|---:|---:|---|---|
| 0 | 1 | `A` 或 `E` | A 路标识；电压异常时为 `E` |
| 1 | 1 | `+` | 固定字符 |
| 2 | 6 | `%06.2f` | `Sweep_A.resonanceAD` |
| 8 | 1 | `B` | B 路标识 |
| 9 | 1 | `+` | 固定字符 |
| 10 | 6 | `%06.2f` | `Sweep_B.resonanceAD` |
| 16 | 1 | `C` | 预留字段标识 |
| 17 | 1 | `+` | 固定字符 |
| 18 | 6 | `%06.2f` | 当前固定为 `0.0` |
| 24 | 1 | BCC | 校验字节 |
| 25 | 1 | `0x0D` | CR |
| 26 | 1 | `0x0A` | LF |

当前 V5.4 沿用V5.3的 `CS` 停用状态，而 `Sweep_A/Sweep_B` 只在扫频函数中更新。因此 `Cp` 可能返回零值或旧缓存，不能把它视为一次新采集结果。

另外，`%06.2f` 仅规定最小宽度。AD 大于 `999.99` 时字段会扩展，破坏后续固定偏移；当前发送代码仍固定在偏移 24 写入 BCC。对接程序不应依赖超宽值仍能形成合法帧。

### 7.7 零点电压帧

适用命令：`Cz`。

格式：

```text
Dvv.vvvv<BCC>\r\n
```

| 偏移 | 长度 | 格式 | 含义 |
|---:|---:|---|---|
| 0 | 1 | `D` 或 `E` | 正常为 `D`；电压异常时为 `E` |
| 1 | 7 | `%07.4f` | PA0 ADC 换算电压，单位 V |
| 8 | 1 | BCC | 校验字节 |
| 9 | 1 | `0x0D` | CR |
| 10 | 1 | `0x0A` | LF |

换算公式：

```text
ZeroVoltage = ADC * 3.3 / 4096
```

样例有效载荷 `D01.6573` 的 BCC 为 `0x5C` / `'\\'`。

### 7.8 供电电压帧

适用命令：`CK`。

格式：

```text
evv.vvvv<BCC>\r\n
```

| 偏移 | 长度 | 格式 | 含义 |
|---:|---:|---|---|
| 0 | 1 | 固定小写 `e` | 供电电压字段标识 |
| 1 | 7 | `%07.4f` | PA4 ADC 经 11:1 分压换算后的电压，单位 V |
| 8 | 1 | BCC | 校验字节 |
| 9 | 1 | `0x0D` | CR |
| 10 | 1 | `0x0A` | LF |

换算公式：

```text
SupplyVoltage = ADC * 3.3 * 11 / 4096
```

示例：

```text
e06.6379v\r\n
```

其中 BCC 为小写 `v`。该帧不会因为电压超限而把首字符改成大写 `E`，因此也是确认实际电压值的唯一直接查询命令。

### 7.9 传感器编号帧

| 偏移 | 长度 | 格式 | 含义 |
|---:|---:|---|---|
| 0 | 1 | `N` 或 `E` | 正常为 `N`；电压异常时为 `E` |
| 1 | 7 | `%07d` | CPU0 返回的传感器编号 |

### 7.10 液位频率帧

适用命令：`Ca`、`Cb`。

格式：

```text
Fddddddd<BCC>\r\n
```

| 偏移 | 长度 | 格式 | 含义 |
|---:|---:|---|---|
| 0 | 1 | `F` 或 `E` | 正常为 `F`；电压异常时为 `E` |
| 1 | 7 | `%07d` | CPU0 参数 4 的液位频率 |
| 8 | 1 | BCC | 校验字节 |
| 9 | 1 | `0x0D` | CR |
| 10 | 1 | `0x0A` | LF |

CPU1 对 CPU0 返回值进行历史兼容处理：

1. 按 `int32_t` 位模式解释返回的 4 字节数据。
2. 负值转换为绝对值。
3. 大于 10000 时减去 10000。

频率 1234 的有效载荷为 `F0001234`，BCC 为 `0x42` / `'B'`。

当前实现没有保存本次 CPU0 读取函数的返回状态，通信失败时可能仍返回 0 或依据上一轮 `CPU0State` 选择响应，详见第 11 节。

### 7.11 组合版本帧

适用命令：`CV`。

格式：

```text
0Addd<BCC>
```

总长度固定为 6 字节，无 `\r\n`。

| 偏移 | 长度 | 内容 | 含义 |
|---:|---:|---|---|
| 0 | 1 | `0` 或 `E` | V5.4正常固定为 `0`；电压异常时为 `E` |
| 1 | 1 | `A` | V5.4为兼容一代程序继续使用固定组合版本前缀的第2字节 |
| 2 | 3 | `%03d` | `(int32_t)(CPU0_SoftwareVersion * 100)` |
| 5 | 1 | BCC | 对前 5 字节计算 |

示例：CPU0 软件版本为 4.42：

```text
ASCII/HEX: 30 41 34 34 32 02
显示形式:  0  A  4  4  2 <0x02>
```

`0A` 是V5.3/V5.4源码中的固定两字符前缀，不应按十进制数字解析；不能仅凭该前缀区分V5.3和V5.4，应使用 `Cv`。

### 7.12 CPU1 本机版本帧

适用命令：`Cv`。

正常响应固定为：

```text
05.40<BCC>
```

总长度固定为 6 字节，无 `\r\n`。

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0～4 | 5 | ASCII `05.40` |
| 5 | 1 | BCC，V5.4 正常值为 `0x1A` |

十六进制：

```text
30 35 2E 34 30 1A
```

V5.3使用全局可写数组保存版本字符串，电压异常后首字符 `E` 会残留到设备复位。V5.4仍使用该数组，但每次响应前先恢复首字符 `0`，再按本次电压状态决定是否改为 `E`。

### 7.13 扫频结果帧

适用命令：`CS`，但当前 V5.4 命令入口沿用V5.3的停用状态。本节仅用于历史兼容和跨维护线识别。

格式：

```text
A+ffffffB+ffffff<BCC>\r\n
```

| 偏移 | 长度 | 格式 | 含义 |
|---:|---:|---|---|
| 0 | 1 | `A`、`E` 或 `a` | A 路标识；A 路谐振 AD 小于 10 时为 `a` |
| 1 | 1 | `+` | 固定字符 |
| 2 | 6 | `%06u` | A 路谐振频率 |
| 8 | 1 | `B` 或 `b` | B 路标识；B 路谐振 AD 小于 10 时为 `b` |
| 9 | 1 | `+` | 固定字符 |
| 10 | 6 | `%06u` | B 路谐振频率 |
| 16 | 1 | BCC | 校验字节 |
| 17 | 1 | `0x0D` | CR |
| 18 | 1 | `0x0A` | LF |

电压异常会先把偏移 0 改为 `E`，随后 A 路低 AD 判断可能再次把它改成 `a`，因此 `a` 的优先级高于 `E`，可能遮蔽电压异常标识。

## 8. 电压异常语义

CPU1 主循环持续检测供电电压：

```text
正常：5.2 V ≤ SupplyVoltage ≤ 12.0 V
异常：SupplyVoltage < 5.2 V 或 SupplyVoltage > 12.0 V
```

电压异常时，下列正常响应会把第一个有效载荷字符改为大写 `E`：

- 密度数据帧
- 密度分析参数帧
- 液位 AD 帧
- 陀螺仪帧
- 水测量帧
- 零点电压帧
- 传感器编号帧
- 液位频率帧
- 组合版本帧
- CPU1 本机版本帧
- 历史扫频结果帧

供电电压查询 `CK` 本身不改首字符，始终以小写 `e` 开头。

上位机应先判断首字符是否为 `E`，再根据原请求恢复该帧的字段语义。`E` 只替换原字段标识，不改变帧总长度和 BCC 位置；BCC按替换后的实际字节计算。

## 9. 错误帧

错误帧统一为 19 字节：

```text
16 字节错误有效载荷 + BCC + \r\n
```

| 错误枚举 | 有效载荷 | 含义 |
|---:|---|---|
| 0 | `A+000.00B+000.00` | 无错误占位 |
| 1 | `A+111.11B+111.11` | 扫频范围内无谐振 |
| 2 | `A+222.22B+222.22` | 电源电压异常 |
| 3 | `A+333.33B+333.33` | 陀螺仪 I²C 通信超时 |
| 4 | `A+444.44B+444.44` | 陀螺仪角度数据无效或尚未准备 |
| 5 | `A+555.55B+555.55` | CPU1 自检错误 |
| 6 | `A+666.66B+666.66` | 预留 1 |
| 7 | `A+777.88B+777.88` | 预留 2；历史值为 `777.88` |
| 8 | `A+888.88B+888.88` | CPU1 与 CPU0 通信超时 |
| 9 | `A+999.99B+999.99` | CPU0 ADD 校验失败或参数码回显不匹配 |

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0～15 | 16 | 上表中的错误有效载荷 |
| 16 | 1 | BCC |
| 17 | 1 | `0x0D` |
| 18 | 1 | `0x0A` |

历史 Excel 表中部分错误字符串末尾带逗号，这是列表分隔符，不是线上发送的 BCC。

当前源码并没有在所有定义场景下使用对应错误帧。例如电压异常通常通过首字符 `E` 表示，而不是发送错误 2。V5.4已保证首次陀螺仪读取失败返回既有19字节错误帧；对接程序仍应同时支持 `E` 首字符和错误帧，不能只依赖错误码表。

## 10. 启动、复位和响应时序

### 10.1 启动主动报文

设备上电后主动发送两次 ACK 帧：

1. 串口和安全自检初始化完成后发送一次 `%\r\n`。
2. 陀螺仪初始化、PWM 初始化、CPU0 传感器编号和软件版本读取完成后再发送一次 `%\r\n`。

随后固件会持续重试 FDC2214 初始化，初始化成功后才进入正常主循环。如果 FDC2214 一直初始化失败，设备不会进入正常命令执行循环。

### 10.2 `CR` 软件复位

`CR` 在 USART3 接收中断中直接调用 `NVIC_SystemReset()`，复位前不发送专用确认帧。上位机应通过复位后的启动 `%\r\n` 和后续版本查询确认设备重新上线。

### 10.3 响应时间

V5.4按以下两类时序处理：

- 普通查询由接收中断设置状态，在主循环下一次调度时执行。
- CPU1 待机循环包含 8 ms 延时和 CPU0 周期轮询。
- `CD`、`CB` 访问 CPU0，内部等待注释上限约为 100 ms。
- READY状态的 `CH/CZ/Ch/Cz` 不重复切换PB4，应在二代500 ms窗口内完成响应。
- OFF状态的 `CH/CZ/Ch/Cz` 会执行当前约600 ms硬件初始化和3次新样本预采样，首个 `Ch` 允许超过二代单次500 ms窗口。
- `CR` 不返回普通命令响应。

真实最大响应时间仍须由目标板抓包确定。发布验收要求二代第一次冷读超时后，第二次 `Ch` 必须在其500 ms窗口内收到新鲜角度帧。

### 10.4 二代计量仪传统DSM兼容要求

本节的二代计量仪专指 `D:\CUBE\LTD_MAIN_CPU2` 当前传统DSM USART6路径，不包括安全传感器协议路径。主机和传感器必须满足：

| 项目 | 要求 |
|---|---|
| 请求入口 | 主机可以直接发送 `Ch`，不保证预先发送 `CH` |
| 单次等待 | 500 ms |
| 最大尝试次数 | 3次 |
| 重试间隔 | 第二、第三次发送前等待300 ms |
| 接收清理 | 每次尝试前清理迟到帧和旧接收数据 |
| OFF收到`Ch` | 自动启动PB4电源域，不得要求主机增加准备命令 |
| STARTING收到重复`Ch` | 合并为同一类待处理请求，不得重新开始约600 ms启动时序 |
| 数据新鲜度 | 只能返回本次PB4上电后取得的新有效样本，不得返回掉电前缓存 |
| 冷启动验收 | 第一次500 ms允许超时，第二次请求必须成功；台架必须记录是否产生上层错误日志 |
| READY响应 | 在500 ms单次窗口内完成 |

第一次请求对应的迟到帧可能在第二次尝试前被主机丢弃，这是已接受的兼容行为。传感器不得因迟到帧被丢弃而回到OFF或重启STARTING；第二次请求到来时应在READY状态返回新帧。

### 10.5 PB4自动和主动掉电

- PB4同时控制MPU6050和零点电路，因此 `CH/CZ/Ch/Cz` 都会唤醒并刷新该电源域活动时间。
- READY连续30秒没有相关成功事务且没有待处理请求时，固件自动关断PB4。
- `CX`请求立即进入受控关断：先失效数据、清理MPU6050/Kalman/时间基线和I²C状态，再拉低PB4并返回 `%\r\n`。
- OFF重复收到 `CX` 仍返回ACK；STARTING收到 `CX` 时取消待处理读数，在当前初始化安全点结束后关断并ACK。
- 正常自动掉电和 `CX` 成功均不发送异步报文，不作为传感器故障。

## 11. 当前 V5.4 已知实现限制与已修复项

本节记录源码实际行为，不代表期望协议设计。对外程序和后续固件整改必须考虑这些限制。

### 11.1 `CD`、`CB` 存在空指针写风险

模式切换调用 `read_write_cpu0_register()` 时传入空数据指针。该函数在收到校验正确且参数码匹配的 CPU0 响应后，无条件执行：

```c
*data = Usart2ReceivePackage.float_data;
```

因此 CPU0 正常响应时可能触发 CPU1 HardFault。与此同时，外部 ACK 也不会反映 CPU0 模式切换结果。

### 11.2 `CS` 停用导致 `Cp` 缓存缺少刷新入口

V5.3起 `CS` 的中断分支已注释，V5.4保持不变；`Sweep_Frequency()` 没有其他对外可达调用路径。`Cp` 使用的 `Sweep_A/Sweep_B` 可能保持初始零值或历史值。

### 11.3 液位 AD 字段可能超宽

ADC 数据可能大于 999，而 `%06.2f` 无法把 `1125.00` 限制在 6 字符内。字段扩展后，后续字段整体移位，但 BCC、CR、LF 仍写入固定下标，造成数据截断和字段错位。

### 11.4 V5.3 `Cv` 的 `E` 标识保持问题已修复

V5.4每次生成 `Cv` 响应前恢复首字符 `0`，再根据本次电压状态决定是否改为 `E`，电压恢复后不再沿用旧异常标识。

### 11.5 液位频率读取可能掩盖通信失败

`get_LevelFrequency()` 忽略本次 `read_write_cpu0_register()` 返回值，并继续解释初始值或接收值；随后是否发送错误帧依赖此前保存的 `CPU0State`，不一定反映本次读取结果。

### 11.6 V5.3首次陀螺仪查询失败无响应问题已修复

V5.4使用独立数据有效标志，并在本次 `MPU6050_Get_Angle()`失败时立即发送既有19字节错误帧，不再等待下一次查询。

### 11.7 V5.3跨命令错误串扰问题已修复

V5.4仍保留 `ErrorState`、`CPU0State` 和 `GYRState` 三类全局状态，但错误帧生成函数改为显式接收本事务错误码：CPU0数据和组合版本响应使用 `CPU0State`，陀螺仪响应使用 `GYRState`，扫频相关响应使用 `ErrorState`。I²C超时回调不再覆盖无关的扫频错误状态；`Cv`是CPU1本机版本查询，始终按本机版本和当前电压状态响应，不再被CPU0或陀螺仪的残留错误阻断。

### 11.8 `CL` 保留了过时的 PA5 操作

V5.0 已把测水方案切换为 FDC2214 软件 I²C，PA5 是其 SCL。USART3 命令处理中仍把 `CL` 解释为“开启测水探针”并拉高 PA5，收到除 `Cl` 以外的其他有效命令时又会拉低 PA5。这与当前 I²C 引脚用途存在冲突，不能把 `CL` 视为可靠的独立电源控制命令。

## 12. 上位机实现建议

### 12.1 推荐事务流程

```text
1. 清空串口接收缓存。
2. 发送两个请求字节：'C' + command。
3. 根据 command 选择预期响应长度。
4. 接收固定长度；不要只按 CRLF 截帧。
5. ACK 帧校验固定三个字节。
6. 数据帧校验尾部 CRLF（版本帧除外）。
7. 按历史 BCC 算法校验。
8. 检查首字符 E 或错误帧。
9. 解析字段并检查数字范围。
10. 完成本事务后再发送下一条命令。
```

### 12.2 命令与预期长度映射

| 命令 | 预期长度 |
|---|---:|
| `CF`、`CP`、`CA`、`CH`、`CZ`、`CL`、`CD`、`CB`、`CX` | 3 |
| `Cf`、`Cd`、`CM`、`Cp` | 27 |
| `Ch` | 19 |
| `Cl`、`Cz`、`CN`、`CK`、`Ca`、`Cb` | 11 |
| `CV`、`Cv` | 6 |
| `CR` | 不等待普通响应，等待设备重启 |
| `CS` | V5.4不支持，不应发送 |

错误场景下，部分数据查询可能改为返回 19 字节错误帧。因此稳健接收器需要在等待预期数据帧的同时识别 19 字节错误帧，或者先读取足以识别帧类型的字节后切换剩余长度。

### 12.3 版本识别

建立连接后建议优先执行：

1. `Cv`：识别 CPU1 本机维护线版本。
2. `CV`：读取当前组合版本前缀和 CPU0 软件版本。
3. `CK`：确认实际供电电压。

不要假设版本数字更大的维护线自动包含V5.4全部协议能力。

### 14.3 上位机和 CPU2 的版本选择规则

1. V3.02 及以后先发送 `Cv`，按实际返回文本识别维护版本；V3.02 之前没有独立 `Cv`，不能把超时直接判断为设备离线。
2. `Cv=05.00` 不能区分标准 V5.0 与 V5.0-Lemis，必须结合设备配置、CPU0 能力或已确认的型号信息；不要通过发送可能改变模式的控制命令盲探测。
3. `Cv=06.xx` 表示 V6 独立分支，不表示包含 V5.1～V5.4；应使用 V6 的七项 CPU0 数据和直接频率语义。
4. 解析密度数据时至少区分 V1.0 与 V2.0 以后；解析水测量 `D` 帧时至少区分 V4.10 以前的 ADC 电压语义与 V5.0 以后的电容语义。
5. 使用 `CS` 前必须确认命令能力：V5.2～V5.4停用，V6.0/V6.1和部分旧版本有效。未知版本不得默认发送。
6. V5.4二代传统DSM继续直接使用 `Ch`：第一次500 ms允许冷启动超时，300 ms后第二次必须成功；V5.2/V5.3及其它维护线仍需按实际抓包确定时序。
7. `CX`只允许在明确识别 `Cv=05.40` 后作为可选维护命令发送；V5.3、V6.1和Lemis均不支持，老主机不发送 `CX` 也能依靠自动空闲掉电。
8. 对 V4.10 及以后不能假设固件提供 PB3 软件方向控制；板级半双工接口必须独立确认自动收发条件。
9. 每个版本必须绑定“请求命令、预期正常长度、可替代错误帧长度、BCC 范围、字段单位、超时”配置。版本未知或配置缺失时应停止控制类命令，不得回退到数字最大的版本。

## 15. 协议验证建议

正式发布本文档前建议完成以下目标板验证：

1. 使用逻辑分析仪或串口抓包确认 USART3 的 9600-8-N-1 和所有命令实际字节。
2. 对每条命令记录正常响应、无 CPU0、无陀螺仪、电压过低和电压过高场景。
3. 确认 BCC 为控制字符、CR、LF 或 0 时，上位机仍能按固定长度解析。
4. 实测 `CD`、`CB` 是否触发 HardFault，并确认 CPU0 实际应答内容。
5. 确认V5.4沿用的 `Cp` 是否始终为零或旧缓存。
6. 覆盖液位 AD 大于 999.99 的帧超宽情况。
7. 验证V5.4 `Cv`在电压异常恢复后首字符能恢复为 `0`。
8. 测量普通查询、CPU0超时、陀螺仪首次上电和复位重连的最大响应时间；重点验证二代第一次500 ms可超时、第二次必须成功。
9. 分别验证V5.4、V5.3、V6.1和Lemis变体，避免交叉套用测试结论；覆盖 `CX` 在OFF、READY和STARTING三种状态下的幂等关断及ACK时点。
10. 验证30秒自动掉电临界竞态、一代1000 ms接收窗口、重复唤醒/掉电和I2C故障注入。
11. 如果产品声明支持其他历史版本，应按本章逐版本增量表建立独立用例，不能用V5.4抓包替代旧版本验证。

完成实机验证后，应把抓包样例、精确超时和已确认的物理收发器类型补入本文档。

本附录不是 CPU1 的对外上位机接口，但它决定部分对外数据和模式命令的实际行为。

### A.1 USART2 参数

| 项目 | 参数 |
|---|---|
| MCU 外设 | USART2 |
| TX | PA2 |
| RX | PA3 |
| 波特率 | 9600 bit/s |
| 数据格式 | 8-N-1 |
| 超时 | 源码注释约 100 ms |

### A.2 帧结构

请求和响应均固定为 8 字节：

| 偏移 | 长度 | 内容 |
|---:|---:|---|
| 0 | 1 | 地址，当前固定 `0x00` |
| 1 | 1 | 功能码 |
| 2～5 | 4 | 原生 32 位数据，小端字节序 |
| 6 | 1 | 参数码 |
| 7 | 1 | ADD 校验 |

ADD 算法为偏移 0～6 的无符号字节求和并保留低 8 位：

```text
ADD = (byte[0] + byte[1] + ... + byte[6]) mod 256
```

读取命令的 4 字节数据区填 0。写命令的数据区为 ARM 小端内存中的 `float32` 原始字节。CPU1 接收响应时检查：

1. 是否收到至少 8 字节；
2. ADD 是否正确；
3. 响应参数码是否与请求参数码一致。

当前实现不校验响应地址和响应功能码。

### A.3 V5.3/V5.4 功能码

| 字符 | 十六进制 | 含义 |
|---|---:|---|
| `R` | `0x52` | 读参数 |
| `W` | `0x57` | 写参数 |
| `T` | `0x54` | 液位模式 |
| `D` | `0x44` | 密度模式 |

### A.4 V5.3/V5.4 参数码

| 参数码 | 名称 | 对外用途 |
|---:|---|---|
| 0 | SoftwareVersion | `CV` 组合版本 |
| 4 | LevelFrequency | `Ca`、`Cb` 液位频率 |
| 6 | Temperature | `Cf`、`Cd` 温度 |
| 7 | Density | `Cf`、`Cd` 密度 |
| 8 | Dynamic | `CM` 动态黏度 |
| 16 | Frequency | V5.3/V5.4 未直接周期轮询 |
| 17 | SquareMeanOf45degreeSweepPeriod | `CM`，并用于计算密度频率 |
| 18 | MeanSquareOf225DegreeSweepPeriod | `CM` |
| 22 | SensorNumber | `CN` |
| 77 | StartFrequency | 历史/调试参数 |
| 78 | EndFrequency | 历史/调试参数 |

传感器编号和液位频率虽然占用帧中的 4 字节数据区，但 CPU1 会按 `int32_t` 位模式解释这 4 个字节，而不是把数值型浮点数转换成整数。因此 CPU0 必须按双方现有的原始位模式约定返回。
