## 1. 一页结论

当前源码的真实对外行为如下：

1. 串口使用 MSP430FR2476 的 `UCA1`，配置为 `19200 bit/s`，源码寄存器配置对应 8N1。
2. 设备进入主循环后持续主动上报，不要求上位机轮询；上报周期没有独立定时器约束。
3. 当前实际发送的业务帧固定为 `0x83` 全量数据帧，总长度固定为 22 字节。
4. 源码虽然保留 `0x81` 电压帧和 `0x82` 称重帧组包函数，但发送入口固定选择 `UART_READ_ALL`，当前不能把这两种帧当作可用行为。
5. 三种合法下行查询都会触发同一个发送标志，最终仍发送 `0x83`；请求与响应没有事务号、命令回显或一一对应关系。
6. 帧校验使用从帧首字节到 BCC 前一字节的逐字节异或。
7. 完整帧必须依靠帧头、响应码对应的固定长度和 BCC 共同判断，不能依靠帧间隔。
8. 上电阶段可能先出现裸单字节 `0x01`、`0x02` 和 `0xAA`，它们不属于带 BCC 的业务帧。
9. 称重字段当前只是 16 位原始比特模式，没有 kg/g、零点、量程或分度值定义。
10. 本协议卷只是 Newhall 独立称重主控的参考协议归档；当前没有证据表明 CUBE CPU2 已实现该协议。

## 5. 上电与运行时序

### 5.1 上电阶段

```text
初始化 16 MHz 时钟
  → 初始化 UCA1
  → 初始化 ADS1220 称重模块
      └─ 失败时立即发送裸单字节 0x01
  → 初始化温度模块
      └─ 失败时立即发送裸单字节 0x02
  → 初始化 ADC
  → 配置看门狗并发送裸单字节 0xAA
  → 开启全局中断
  → 进入主循环
```

| 场景 | 启动阶段可能收到的字节序列 |
| --- | --- |
| 两项初始化均成功 | `AA` |
| 称重初始化失败 | `01 AA` |
| 温度初始化失败 | `02 AA` |
| 两项均失败 | `01 02 AA` |

这些字节没有帧头、长度和 BCC。上位机必须能够跳过它们并重新搜索上行业务帧头 `0xCC`。

### 5.2 主循环阶段

```text
等待 ADS1220 数据就绪并读取称重
  → 置位温度、电压和串口发送任务
  → 若上一 ADC 转换完成，推进到下一通道
  → 发送 0x83 全量帧
  → 读取温度
  → 下一轮
```

由此可知：

- 本帧称重值来自本轮刚完成的称重读取和滤波。
- 本帧温度通常是上一轮读取结果，第一帧温度初值可能为 `0.0`。
- 五路 ADC 值由中断和轮询通道逐步更新，不是同一时刻的同步快照。
- `ReadWeight()` 等待 DRDY 时没有超时；称重链路异常可能让主动上报停止，并由看门狗复位。

## 6. BCC 校验

BCC 为从帧首字节到 BCC 前一字节的逐字节异或：

```text
BCC = byte[0] XOR byte[1] XOR ... XOR byte[n-2]
```

校验通过条件：

```text
XOR(frame[0 ... n-2]) == frame[n-1]
```

等价地，对整帧所有字节异或，结果应为 `0x00`。


### 7.3 电压字段

IA、IB：

```text
voltage_mV = ADC / 1023 × 3300
```

VIN、AVCC、VREF：

```text
voltage_mV = ADC / 1023 × 3300 × 139 / 39
```

结果转换为 `unsigned int` 后发送，小数部分被截断。电压字段当前应按 16 位无符号大端整数解释。

### 7.4 称重字段

ADS1220 每次读取 3 个字节，当前源码只保存前两个字节：

```text
weight_original = (data1 << 8) + data2
```

第三字节被读取后丢弃，因此线上不是 24 位 ADS1220 原始值。

滤波代码意图为：

```text
一级滤波：new_filter = raw × 0.2 + previous_filter × 0.8
二级滤波：最近 4 个一级滤波结果的滑动平均
```

但当前源码在前 3 个样本阶段先计算 `sum / w_cnt`，随后又无条件执行 `sum / 4`。因此前 3 个滤波结果实际仍按 4 个样本除，可能明显偏小；协议接收端应把它视为当前固件行为，而不是稳定的称重标定特性。

`data1`、`data2` 使用普通 `char`，没有显式声明符号性。上位机应先保留两个称重字段的 16 位原始比特模式；正负号、零点、量程、分度值和质量单位必须由产品标定和实机数据另行确认。

### 7.5 温度字段

12 位温度原始值：

```text
tmp = ((data1 << 4) + ((data2 >> 4) & 0x0F)) & 0x0FFF
```

当前换算：

```text
tmp <= 0x7FF: temperature = tmp × 0.0625
tmp >  0x7FF: temperature = -(0x0FFF - tmp) × 0.0625
```

结果存入 4 字节 `float` 联合体，发送顺序为 `c[3]、c[2]、c[1]、c[0]`。工程配置明确目标为小端；上位机可按大端 IEEE-754 float32 作为当前预期解析方式，例如 `25.0 °C` 对应：

```text
41 C8 00 00
```

但源码没有静态断言浮点格式，正式对接前仍应通过当前编译产物或真实串口抓包确认。

负温度公式使用 `0x0FFF - tmp`，与常见 12 位二进制补码的 `0x1000 - tmp` 相差 1 LSB。本文记录源码现状，不在接收端擅自修正。

## 9. 下行查询协议

### 9.1 通用格式

```text
AA 02 CMD PAYLOAD... BCC
```

接收状态机根据第 3 字节 `CMD` 决定固定总长度。

| CMD | 名称 | 接收总长度 | 当前响应 |
| ---: | --- | ---: | --- |
| `0x01` | 读取电压 | 5 字节 | 触发 `0x83`，22 字节 |
| `0x02` | 读取称重 | 5 字节 | 触发 `0x83`，22 字节 |
| `0x03` | 读取全部 | 9 字节 | 触发 `0x83`，22 字节 |
| 其他值 | 未定义命令 | 9 字节 | BCC 正确时同样触发 `0x83` |

接收状态机只检查：

- 第 1 字节为 `0xAA`；
- 第 2 字节为 `0x02`；
- 总长度符合命令分支；
- 最后一个字节的 BCC 正确。

命令后的保留字节没有被解释，命令码也没有保存到响应上下文。

### 9.2 示例

| 命令 | 完整下行帧 | BCC 计算 |
| --- | --- | --- |
| 读取电压 | `AA 02 01 00 A9` | `AA XOR 02 XOR 01 XOR 00 = A9` |
| 读取称重 | `AA 02 02 00 AA` | `AA XOR 02 XOR 02 XOR 00 = AA` |
| 读取全部 | `AA 02 03 00 00 00 00 00 AB` | 前 8 字节异或为 `AB` |

### 9.3 触发和响应边界

合法下行帧与主循环都只设置 `OPERA_UARTCOM` 位标志：

- 多次触发可能合并成一次发送；
- 查询不保证生成一个独立、可追踪的响应；
- 响应不含请求序号、事务号或命令回显；
- 上位机不能区分主动上报帧和查询触发帧；
- 半包没有接收超时，状态机可能长期停留在未完成帧；
- RX ISR 内直接解析完整协议，没有环形缓冲、队列或显式溢出恢复。

## 10. 上位机完整帧判定

推荐使用持续字节缓冲区：

1. 丢弃数据，直到找到 `0xCC`。
2. 检查第 2 字节是否为 `0x03`。
3. 读取响应码并选择固定长度：

| 响应码 | 总长度 | 当前线上可依赖性 |
| ---: | ---: | --- |
| `0x81` | 16 | 组包代码存在，发送入口未启用 |
| `0x82` | 15 | 组包代码存在，发送入口未启用 |
| `0x83` | 22 | 当前实际业务帧 |

4. 缓冲区不足固定长度时继续等待。
5. 收满后计算 BCC，正确才交付。
6. BCC 错误时从当前候选帧头之后继续搜索下一个 `0xCC`。

当前固件正常运行时，主路径可以收紧为：

```text
frame[0] == 0xCC
frame[1] == 0x03
frame[2] == 0x83
frame.length == 22
XOR(frame[0..20]) == frame[21]
```

载荷可能自然包含 `0xCC`，因此不能只按帧头切包。接收超时只能用于放弃异常候选帧，不能替代固定长度和 BCC。

## 11. 当前限制与兼容风险

| 项目 | 当前情况 | 对接影响 |
| --- | --- | --- |
| 自动上报周期 | 不固定 | 不能把固定 Hz 当作协议保证 |
| 长度字段 | 无 | 必须维护响应码到固定长度的映射 |
| 协议版本 | 无 | 后续字段变化难以兼容区分 |
| 事务号 | 无 | 无法严格关联请求和响应 |
| 主动/响应区分 | 无 | 两者当前都表现为 `0x83` |
| 业务错误状态 | `0x83` 不携带 | 正常帧无法报告当前故障 |
| 启动错误 | 裸单字节 | 定长解析器必须先重同步 |
| 称重原始宽度 | 只发送 16 位 | ADS1220 第 3 字节丢失 |
| 称重单位 | 未定义 | 不能直接解释为 kg/g |
| 称重启动滤波 | 前 3 个结果仍除以 4 | 上电初期可能偏小 |
| 温度新鲜度 | 通常落后一轮 | 多字段不是同一采样时刻 |
| ADC 同步性 | 五路轮询更新 | 电压字段不是同步快照 |
| DRDY 等待 | 无超时 | 传感器异常可能停止上报 |
| RX 半包 | 无接收超时 | 状态机可能滞留或吞入后续字节 |
| 电气层 | 未确认 | 不能仅凭源码指定 RS-485/RS-232 接线 |
