# 传感器安全通信残余危险失效率论证

更新日期：2026-07-12

状态：论证框架已建立，定量结论未关闭。

## 1. 目的和声明边界

本文定义安全通信协议 V1 的残余危险失效率计算口径、输入数据和关闭条件。当前缺少整机危险失效率预算、目标链路误码模型、真实长线统计和独立 CRC 能力复核，因此不得给出“满足目标 SIL”的数值结论。

CRC32C 的 32 bit 宽度不能直接推导出通信危险失效率等于 `2^-32`。该数值最多只能在“损坏后 CRC 结果均匀独立”的特定随机模型下作为条件概率近似，不能覆盖突发错误、系统性软件错误、公共原因故障、错误长度边界或主动攻击。

## 2. 论证对象

纳入计算的 CPU2 到传感器通信危险事件至少包括：

1. 损坏的安全数据通过 CRC、格式和语义校验后被接受。
2. 旧帧、重复帧、乱序帧或跨会话帧被当成当前数据。
3. 错传感器、错节点或串线响应被接受。
4. 冻结、过期或模式不一致的数据在 FTTI 内未被判无效。
5. 配置、倍率或标定版本变化后仍按旧解释使用数据。
6. 接收溢出、UART 硬件错误、DMA/缓存错误或软件系统性故障绕过诊断。

主动攻击、密钥认证和开放无线接入不在本协议基线内；若威胁分析认为存在主动攻击，必须另建安全通道和认证论证，不能计入 CRC 的随机故障覆盖率。

## 3. 基本计算模型

对每一类通信危险事件 `i`，使用下式分配和汇总残余危险失效率：

```text
PFH_comm = Σ λ_i × P_dangerous_i × (1 - DC_i)
```

其中：

- `λ_i`：对应故障机制的发生率，来源必须是实测统计、器件数据或经批准的工程假设。
- `P_dangerous_i`：该故障发生后会形成危险数据或延迟安全反应的条件概率。
- `DC_i`：CRC、长度、地址、会话、序号、年龄、配置、状态和诊断联合检测覆盖率。

针对帧损坏，可进一步拆成：

```text
λ_undetected_crc = N_frame_per_hour × P_corrupt_per_frame × P_undetected_given_corrupt
```

`P_undetected_given_corrupt` 必须按最大 128 字节控制帧、固定 44 字节快报帧和现场错误模型分别计算。不得用单一平均帧长覆盖所有安全相关流量。

## 4. CRC32C 专项输入

定量关闭前必须取得并复核以下输入：

| 输入 | 要求 | 当前状态 |
| --- | --- | --- |
| CRC 参数 | Castagnoli 反射多项式 `0x82F63B78`、初值和异或输出均为 `0xFFFFFFFF` | 已由代码和 golden frame 冻结 |
| CRC 覆盖范围 | 控制帧从 `protocol_version` 到负载末尾；快报从 `frame_type` 到 `config_epoch` 末尾 | 已由代码和契约脚本验证 |
| 帧长集合 | 44 字节快报及 32..128 字节控制帧 | 已冻结 |
| 错误模型 | 独立位翻转、突发错误长度分布、字节插入/删除、截断和串扰 | 未取得现场输入 |
| CRC 检测能力 | 对上述帧长的最小距离、保证检测的错误权重和突发长度 | 未完成独立工具复核 |
| 帧率和运行时间 | 各命令及快报每小时发送数量 | 未由 SRS/真实运行冻结 |
| BER 或上界 | 目标线缆、EMC、温度和接地条件下的统计上界 | 未完成 200 米台架 |

CRC 能力复核应保存工具名称、版本、参数、命令行、输出和独立复核人。引用公开 CRC 性能表时必须确认长度单位、是否包含 CRC 位、反射参数和目标消息长度完全一致。

## 5. 非 CRC 诊断覆盖

| 失效类型 | V1 防护 | 仍需量化或验证的残余风险 |
| --- | --- | --- |
| 删除或静默 | 请求超时、`max_silent_ms`、本地有效年龄 | 任务调度和安全动作是否小于 FTTI |
| 插入、重复、乱序 | u32 `seq`、u32 `stream_seq`、单事务/单流 | 序号状态的软件系统性故障和重启边界 |
| 延迟和冻结 | `data_age_ms`、本地单调年龄、`sample_counter` | 传感器计时源故障和 CPU2 时钟故障 |
| 错地址或伪装 | 源/目的 ID、`sensor_id`、会话绑定 | 多点或主动攻击场景不在基线内 |
| 配置不一致 | `safety_param_crc`、版本、能力位、`config_epoch` | 配置摘要生成软件的系统性错误 |
| 模式错误 | `MEASURE_READY`、模式回显、`MODE_MATCH`、`MODE_SETTLING` | 传感器错误声明稳定但物理通道未稳定 |
| UART/DMA 错误 | HAL 错误、超时、溢出和格式拒绝计数 | ORE/FE/NE/PE/BREAK 分类统计和硬件故障注入 |

## 6. 必需试验数据

200 米、9600 bps 长稳和故障注入至少记录：

- 总运行时间、总字节数、总控制帧、总快报帧和各帧长分布。
- CRC 错、短帧、SOF/长度错误、错地址、旧会话、序号异常和配置不一致次数。
- UART `ORE/FE/NE/PE/BREAK`、DMA 错误、溢出、超时、重试、重新 HELLO 和恢复成功次数。
- 每种注入故障的注入次数、被检测次数、未检测次数和安全动作完成时间。
- 零事件结果的统计置信上界及其计算方法；不得把零观测直接解释为零失效率。

## 7. 关闭条件

只有同时满足以下条件，本文状态才能改为“定量论证已关闭”：

1. 整机 SRS 给出安全功能、目标 SIL、FTTI、安全状态和分配给通信链路的危险失效率预算。
2. CRC32C 在 44 字节和最大 128 字节帧下的检测能力经独立工具和人工复核。
3. 目标物理链路误码/突发错误模型和帧率有可追溯依据。
4. 正常、故障注入、200 米长稳和掉电恢复记录完整，分子分母可复算。
5. 软件系统性故障、公共原因、时钟失效和主动攻击边界已由对应安全/网络安全分析覆盖。
6. 汇总 `PFH_comm` 小于 SRS 分配预算，并由功能安全负责人和认证机构接受计算假设。

当前结论：V1 已建立定性防护和 CPU2 主机级验证证据，但残余危险失效率尚不能定量判定，目标 SIL 满足性保持未证明。
