# LTD 共享 Modbus 协议

更新日期：2026-08-10

本目录只维护一套 LTD 标准 Modbus RTU 协议。CPU3 外部 LTD 从站与 CPU2/CPU3 板间通信使用同一组共享地址和字段语义，不再维护独立编号或地址换算表。

## 当前结论

- 本次正式组合为CPU2 `V1.39.0.0` / CPU3 `V1.38.0.0` / `DEVICE_PROTOCOL_VERSION = 33`；CPU2与CPU3必须严格等值配套。协议32首个正式组合仍为双端`V1.37.0.0`。
- 协议30新增23-1～23-6独立共享故障码；协议31复用`0x0116~0x0117`发布Newhall扭力模块温度；协议32在既有传感器类型字段中增加15“多参数V4”，并在调试Input尾部追加4个Float32结果。协议31及更早程序不得与协议32混用。
- CPU2 Holding 使用 `0x0000～0x0FFF`，CPU2 Input 使用 `0x0000～0x29FF`，CPU3 本机 Holding 使用 `0x7000～0x706B`；PDU 地址直接作为寄存器数组索引。
- 支持标准 FC03、FC04、FC10；FC03使用完整参数快照，普通FC04只使用已确认运行态，固定点代次及单点结果额外检查固定点一致性快照。写共享参数或命令必须等待 CPU2 合法 FC10 ACK；共享参数写入成功后立即使 CPU3 参数快照失效并异步补读确认。参数写结果不确定时强制全量补读，普通命令结果不确定不扩大为整套参数失效；恢复出厂保持全量刷新特例。
- 协议 29 沿用协议 27 的固定功能块和协议 28 的命令快照，不移动寄存器；只取消12-11、交换18/21故障类别、统一13-2名称并把13-26密度有效上限提高到3000.0 kg/m³。
- 协议 30 继续不移动寄存器，只新增24 V真实低压、ADC/DMA监控链路和掉电位置保存结果的共享故障码；参数写入成功响应仍表示已接受到RAM，不代表延后FRAM持久化已经完成。
- 协议 31 不移动地址或改变轮询块长度，把`0x0116~0x0117`原未使用扭力参数槽改为Newhall扭力模块温度IEEE754原始位；故障码、参数存储和既有命令语义不变。
- 协议 32 保持既有字段地址不变，将调试Input块由`0x0100~0x011F`扩展到`0x0100~0x0127`：`0x0120~0x0121`磁零点电压、`0x0122~0x0123`动力黏度、`0x0124~0x0125`运动黏度、`0x0126~0x0127`传感器供电电压。板间轮询和LTD外部FC04读取的是同一份CPU2已确认快照；快照未建立或失效时返回Busy，不返回旧数据。
- 协议 33 不改变地址和字段数量，把`0x0606~0x0607`AO电流修正倍率由100改为1000，按Int32补码表达-1.000～+1.000mA；基础AO配置仍为x100，最终目标/实发值为x1000。协议32与33参数快照不得跨版本恢复。
- 当前全量表覆盖1554个已定义字段：CPU2 Holding 164项、CPU3 Holding 44项、普通Input 146项、200点密度Input 1200项。
- `DEVICE_PARAM_VERSION` 保持 3，`DeviceParameters`、CRC 范围和 FRAM A/B 布局不变；协议 25 及更早升级时只按既有规则把 AO 原隐藏预留槽归零，不因地址重排恢复出厂参数。
- 故障码按产生错误的 CPU2 程序版本选择历史表；不得只按 CPU3 版本或共享协议号解释。
- 本目录不维护 PDF 副本；本机 `tools/` 与 `docs/00_程序流程导航/` 同步验证但不纳入 Git。
