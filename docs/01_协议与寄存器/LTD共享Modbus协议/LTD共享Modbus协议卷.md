# LTD 共享 Modbus 协议卷

更新日期：2026-07-16

## 1. 协议定位

LTD 协议是 CPU2 与 CPU3 共用的一套 Modbus RTU 寄存器和命令协议，不再把“CPU3 菜单中的 LTD”与“CPU2/CPU3 板间协议”分成两套协议。

当前开发及最新发布共享协议版本为 `DEVICE_PROTOCOL_VERSION = 23`，正式组合为CPU2 `V1.28.0.0` / CPU3 `V1.26.0.0`。协议23保持协议22的寄存器地址、故障编号、固定点快照和传递方式不变，收敛AO故障动作与非跟随输出语义；旧日志按产生时的CPU2程序版本选择故障表。CPU3本机故障不进入CPU2共享故障数量，CPU3本机 `0x0200` LTD参数段也不进入板间共享契约。CPU2、CPU3必须使用相同共享协议版本，协议21/22/23混搭由既有版本门禁拦截。

CPU3 采用按参数权威端分流的读写方式：

- `FC03`、`FC04`：CPU3 使用最近一次从 CPU2 取得的缓存快照独立响应，避免每次外部读取都占用 UART5。
- `FC10`：CPU3 把完整 32 位字段写入转发给 CPU2；CPU2 返回合法 ACK 后，CPU3 才返回写成功。
- `FC03` 读取 `0x0200` CPU3 本机参数段时直接返回 CPU3 当前有效运行态；不依赖 CPU2 快照。
- `FC10` 写 CPU3 本机参数时只接受单个完整 32 位字段，经范围和权限校验后写入 FRAM，并以写后读回成功作为响应成功条件。
- CPU3 三路 COM 配置在首版中允许读取但禁止通过 LTD 写入，避免承载当前请求的端口在响应完成前改变协议或线制。
- CPU2 快照未就绪、协议版本不匹配、CPU2 通信故障或写入未获得合法 ACK 时，返回 `0x06 Device Busy`。
- 参数写成功后，CPU3 使参数快照失效并主动重读；重读完成前 `FC03/FC04` 均返回 `0x06`。只写命令字段时，ACK 后直接更新命令缓存。

该实现不是逐帧透明透传；对外寄存器、命令和线序与 CPU2 相同，读响应时刻以 CPU3 最近缓存为准。

## 2. RTU 链路格式

| 项目 | 当前约定 |
| --- | --- |
| 物理协议 | Modbus RTU / RS485 |
| 从站地址 | CPU3 使用系统 `SlaveAddress`，合法范围 `1~247`，非法值回退为 `1` |
| 广播地址 `0` | 当前 CPU3 LTD 实现静默忽略，不执行写入、不回包 |
| CRC | CRC16/MODBUS，多项式 `0xA001`，初值 `0xFFFF`，低字节先发送 |
| 寄存器字节序 | 单个 16 位寄存器高字节先发送 |
| 32 位字序 | 起始地址保存高 16 位，下一地址保存低 16 位 |
| 有符号数 | `int32_t` 使用 32 位二进制补码 |
| 浮点数 | IEEE 754 单精度原始 32 位位型，仍按高 16 位寄存器在前 |

所有共享保持寄存器字段均占两个连续 16 位寄存器。`FC10` 只接受偶数起始地址和偶数寄存器数量，防止只改写半个 32 位字段。

## 3. 功能码

| 功能码 | 名称 | 数量限制 | CPU3 LTD 行为 |
| --- | --- | --- | --- |
| `0x03` | 读保持寄存器 | `1~125` | CPU2 段从参数缓存快照返回；CPU3 段从本机有效运行态返回 |
| `0x04` | 读输入寄存器 | `1~125` | 从 CPU2 状态/测量缓存快照返回 |
| `0x10` | 写多个保持寄存器 | CPU2段为 `2~122` 且为偶数；CPU3段固定为 `2` | CPU2段等待 CPU2 合法 ACK；CPU3段等待本机 FRAM 写后读回成功 |

其他功能码返回 `0x01 Illegal Function`。

## 4. 保持寄存器快照（FC03/FC10）

保持寄存器分为两个独立参数域：CPU2 权威段为 `0x0000~0x0159`，共 `346` 个16位寄存器、`173` 个32位字段，其中前172项属于既有参数/元信息快照，最后1项为非持久化AO仿真开关；CPU3 权威段位于 `0x0200~0x026B`。`0x015A~0x01FF`、CPU3 段内预留空洞以及 `0x026C` 之后均不可访问，返回 `0x02 Illegal Data Address`。一次请求不得跨越两个参数域。

| 地址范围 | 32 位字段数 | 内容 | 源码边界 |
| --- | ---: | --- | --- |
| `0x0000~0x0015` | 11 | 命令、传感器/软件版本、上电命令、错误策略、协议版本、自动恢复次数、预留 | `COMMAND` 至 `RESERVED3` |

| `0x0026~0x0039` | 10 | 空载/满载扭力、上下限、变化比例和预留 | `EMPTY_WEIGHT` 至 `RESERVED9` |
| `0x003A~0x0045` | 6 | 零点扭力阈值、忽略区、最大偏差、找零后下行和预留 | `ZERO_WEIGHT_THRESHOLD_RATIO` 至 `RESERVED11` |
| `0x0046~0x0057` | 9 | 液位罐高、盲区、阈值、方式、频率、密度、滞后时间 | `TANKHEIGHT` 至 `OILLEVEL_HYSTERESIS_TIME` |

### 4.2 CPU3 本机参数段

CPU3 本机字段仍统一占两个连续 16 位寄存器，高 16 位在前、低 16 位在后。FC03 可连续读取多个已定义字段，但请求范围内只要包含地址空洞，整帧返回 `0x02`。FC10 每次只允许写一个字段，即起始地址必须是字段首地址且数量必须为 `2`。

| 地址范围 | 内容 | FC03 | FC10 |
| --- | --- | --- | --- |
| `0x0200~0x021D` | CPU3版本、语言、显示数据源、手输值、小数位、密码、息屏、亮度 | 支持 | 除只读版本外支持 |
| `0x0220~0x0229` | COM1配置 | 支持 | 首版禁止 |
| `0x0230~0x0239` | COM2配置 | 支持 | 首版禁止 |
| `0x0240~0x0249` | COM3配置 | 支持 | 首版禁止 |
| `0x0250~0x026B` | SI周期、自动执行时间及报警阈值 | 支持 | 支持 |

CPU3 本机写入先依据菜单同源元数据检查写权限与取值范围，再调用事务式本机参数接口。FRAM 写后读回失败时恢复旧运行态并返回 `0x04 Slave Device Failure`，不得回显写成功。CPU3 参数段不经过 CPU2，因此不改变 CPU2/CPU3 板间 `DEVICE_PROTOCOL_VERSION`。

参数含义、单位、范围和默认值以 [系统参数出厂默认值.md](../系统参数出厂默认值.md) 为配套说明；字段地址的 CPU2/CPU3 双端权威定义分别是：

- `LTD_MAIN_CPU2/Services/Modbus/stateformodbus.h`
- `LTD_DISPLAY_CPU3/Application/system_param/stateformodbus.h`

## 5. 输入寄存器快照（FC04）

输入寄存器有效窗口为 `0x0000~0x0A47`，共 `2632` 个16位寄存器；`0x0A48` 是结束地址，不可访问。

| 地址范围 | 内容 | 结构/字段 |
| --- | --- | --- |
| `0x0000~0x000F` | 设备状态 | 工作模式、状态、错误码、当前命令、零点状态、参数更新标志、装卸液、手动报警抑制 |
| `0x0010~0x002F` | 调试状态 | 编码器、位置、尺带、电机步数/距离、频率、温度、幅值、水位电容、扭力、角度、电机速度/状态 |
| `0x0030~0x003F` | 液位测量 | 液位、空气/油中/跟随/当前频率、探头到位、稳定、手动更新抑制 |
| `0x0040~0x0047` | 水位测量 | 水位、零点/油中/当前电容 |
| `0x0048~0x004D` | 实高测量 | 标定液位、当前实高、罐底参考有效 |
| `0x004E~0x0059` | 单点测量 | 温度、密度、位置、标准密度、VCF20、重量密度 |
| `0x005A~0x0065` | 单点监测 | 温度、密度、位置、标准密度、VCF20、重量密度 |
| `0x0066~0x007F` | 分布汇总/状态 | 平均值、点数、液位、完成锁存/计数、来源、工况阻止、温度/密度偏差报警 |
| `0x0080~0x09DF` | 分布点阵 | 最多 200 点，每点 12 个寄存器：温度、密度、位置、标准密度、VCF20、重量密度 |
| `0x09E0~0x09ED` | 无线滑环匹配 | 结果、MAC 有效/三段、错误码、更新计数 |
| `0x09EE~0x0A15` | 继电器运行态 | 4 路，每路 10 个寄存器：报警值和 8 个状态量 |
| `0x0A16~0x0A1F` | 蓝牙连接/RSSI | 连接有效、RSSI 有效、RSSI、连接错误码、更新计数 |
| `0x0A20~0x0A31` | AO既有运行态 | 目标/最近成功下发电流、来源、驱动故障、故障寄存器、错误码、更新计数、更新时间；协议10地址不移动 |
| `0x0A32~0x0A37` | SI Profile运行态 | 阶段、周期计数、有效点进度；协议18地址不移动 |
| `0x0A38~0x0A43` | AO扩展运行态 | 过程值、百分比、过程有效、仿真开启、DAC回读预留值和有效标志 |
| `0x0A44~0x0A45` | 单点测量完成代际 | 32位计数；CPU2完整发布6字段后递增，供CPU3前后双读一致性校验 |
| `0x0A46~0x0A47` | 固定点监测样本代际 | 32位计数；CPU2完整发布6字段后递增，供CPU3前后双读一致性校验 |

分布点 `i=0~199` 的起始地址为 `0x0080 + i * 12`；六个 32 位字段依次位于偏移 `0、2、4、6、8、10`。

AO扩展运行态均占两个寄存器：`process_value_01mm`为`Int32`、倍率0.1mm；`percent_x100`为`Int32`、倍率0.01%；其余为`UInt32`。过程无效时必须同时检查`process_valid=0`，不能把缓存数值当作当前有效测量。当前`dac_readback_mA_x100=0`且`dac_readback_valid=0`，表示尚未实现AD5421 RDDAC设定码读取，不表示物理环路电流为0。HART电流读取和CPU3只读“AO输出电流”均使用`last_sent_mA_x100`；HART百分比使用`percent_x100/100`。CPU3显示还必须检查完整快照和输出模式，不能把禁用电流或失效缓存当作有效输出状态。

固定点一致性读取采用协议21三阶段握手：先读`0x0A44~0x0A47`两个代际，再读`0x004E~0x0065`两组结果共24个寄存器，最后复读两个代际。只有前后代际完全相同，CPU3才在短临界区一次提交公开输入缓存和两组运行态；任一请求失败或代际变化都丢弃中间结果并重试。外部主机直接访问CPU3时只会看到已完成该校验的公开快照。

### 5.1 数据类型与工程值换算

除 `Float32` 外，32 位字段均按高 16 位在前、低 16 位在后组合原始值。上位机显示统一使用 `工程值=(raw-原始偏移)/倍率`，写入参数时执行逆运算。当前测量结果口径如下：

| 字段类别 | 原始类型 | 原始偏移 | 倍率 | 工程值/单位 |
| --- | --- | ---: | ---: | --- |
| 温度（单点、监测、分布平均及 200 点） | `UInt32` | `20000` | `100` | `(raw-20000)/100 ℃` |
| 密度、标准密度、计重密度 | `UInt32` | `0` | `100` | `raw/100 kg/m³` |
| VCF20 | `UInt32` | `0` | `10000` | `raw/10000` |
| 液位、水位、罐高、测点位置 | `UInt32` | `0` | `10` | `raw/10 mm` |
| 调试传感器位置、绳长、电机距离 | `Int32` | `0` | `10` | `raw/10 mm` |
| X/Y 角度 | `Int32` | `0` | `100` | `raw/100 deg` |
| 调试水位电容 | `UInt32` | `0` | `10` | `raw/10 pF` |
| 水位零点电容、油中电容、当前电容 | `Float32` | 不适用 | 不适用 | 直接显示，单位 pF |
| 当前扭力、扭力参数 | `UInt32` | `0` | `1` | 原始值直接显示；负值边界需结合固件源类型和实机验证 |

示例：温度原始值 `22500` 显示为 `25.00 ℃`，密度原始值 `80000` 显示为 `800.00 kg/m³`，VCF20 原始值 `9995` 显示为 `0.9995`，位置原始值 `12345` 显示为 `1234.5 mm`。

当前固件部分密度模拟/回退路径仍把 VCF20 写为原始值 `1`，按本协议会显示 `0.0001`；符合 1.0000 的原始值应为 `10000`。该项属于固件实现偏差，修复前上位机不得把这些路径的 VCF20 当作有效工况值。

设备状态区的故障码、无线滑环匹配区的错误码、蓝牙连接区的连接错误码和 AO 运行态的最近错误码，均直接输出 CPU2/CPU3 当前32位内部故障码。现场应先确认CPU2程序版本，再按对应版本的 `../../00_构建与版本/故障码/LTD故障代码统一表.xlsx` 解释为十进制“故障类别-故障码”；共享协议版本只用于CPU2/CPU3配套检查，不代替现场选表。寄存器仍保持高16位在前、低16位在后的两个寄存器格式。

### 6.1 带参数命令绑定

带参数命令必须先按工程值写入对应保持寄存器，确认 CPU2 ACK 并读回一致后再写命令寄存器。当前固件实际消费字段如下：

| 命令 | 必填参数字段 | 工程值口径 |
| --- | --- | --- |
| `CMD_MEASURE_SINGLE` | `singlePointMeasurementPosition` | 输入 mm，写入 0.1 mm 原始值 |
| `CMD_MONITOR_SINGLE` | `singlePointMonitoringPosition` | 输入 mm，写入 0.1 mm 原始值 |
| `CMD_RUN_TO_POSITION` | `densityDistributionOilLevel` | 输入 mm；命令实现按原始值 `/10` 作为目标位置 |
| `CMD_MEASURE_DISTRIBUTED`、`CMD_GB_MEASURE_DISTRIBUTED`、`CMD_MEASURE_DENSITY_METER`、`CMD_MEASURE_DENSITY_RANGE`、`CMD_WARTSILA_DENSITY_RANGE` | `densityDistributionOilLevel` | 输入 mm，写入 0.1 mm 原始值 |
| `CMD_CALIBRATE_OIL`、`CMD_CORRECT_OIL` | `calibrateOilLevel` | 输入 mm，写入 0.1 mm 原始值 |
| `CMD_MOVE_UP`、`CMD_MOVE_DOWN`、`CMD_FORCE_MOVE_UP`、`CMD_FORCE_MOVE_DOWN` | `motorCommandDistance` | 输入 mm；命令实现按原始值 `/10` 作为运行距离 |
| `CMD_CALIBRATE_WATER` | `calibrateWaterLevel` | 输入 mm，写入 0.1 mm 原始值 |

命令值 `115` 为保留码，不能按历史“强制提零”语义下发。命令值 `117` 由固件定义为无线滑环匹配，PC 调试工具当前未将其加入通用命令目录。

## 7. 异常响应

| 异常码 | 含义 | 典型触发条件 |
| --- | --- | --- |
| `0x01` | Illegal Function | 功能码不是 `03/04/10` |
| `0x02` | Illegal Data Address | 起始地址或连续范围超出对应窗口 |
| `0x03` | Illegal Data Value | 数量为 0/超限、FC10 未按 32 位对齐、byte count 或帧长不一致 |
| `0x04` | Slave Device Failure | CPU3 本机参数写入 FRAM 后读回校验失败 |
| `0x06` | Slave Device Busy | CPU2 快照不可用、协议不匹配、通信故障或 FC10 未获得 CPU2 合法 ACK |

地址不匹配、CRC 错误和过短且无法形成合法 RTU 请求的帧不回包。

## 9. 版本与验证边界

- 当前开发及最新发布源码为 `DEVICE_PROTOCOL_VERSION = 23`，正式组合CPU2 `V1.28.0.0` / CPU3 `V1.26.0.0`。协议23继承协议22全部地址、故障编号和快照语义，并收敛AO参数与运行态解释。
- CPU3 本机 `0x0200` 参数段属于 CPU3 对外 LTD 能力扩展，不改变 CPU2/CPU3 板间共享结构，因此本次不提升 `DEVICE_PROTOCOL_VERSION`；配套上位机必须按 CPU3 固件版本判断该参数段是否可用。
- 首个正式支持当前`0x0200`参数段、协议19故障码、协议20 AO和协议21固定点代际的CPU3版本为`V1.25.0.0`，配套CPU2版本为`V1.27.0.0`。
- 协议22与协议21及更早版本的故障码数值解释不兼容；协议23沿用协议22故障编号，但AO同一槽位的语义与协议22不兼容。CPU2/CPU3必须成对使用同一协议；外部主站按CPU2程序版本选择故障表，按协议23解释AO字段，按协议21解释固定点快照地址和代际。协议18建立的SI运行态和地址保持不变。
- CPU3 从“LTD 占位不回包”变为实际协议响应，属于 CPU3 新增对外功能；本功能首个版本为 CPU3 `V1.21.0.0`，配套 CPU2 版本为 `V1.22.0.0`。
- CPU2 `V1.27.0.0` / CPU3 `V1.25.0.0`是协议21历史组合并使用对应历史故障表；协议22未单独发布，协议23首个正式组合为CPU2 `V1.28.0.0` / CPU3 `V1.26.0.0`。
- 本协议卷描述当前软件实现，仍需在实机RS485、PLC、HART和电流回路上验证长帧、CPU2掉线、协议不匹配、AO参数失败回滚、禁用3.40mA、NMS81边界、断环恢复和HART叠加。物理电流精度必须用外部电流表验证，DAC预留字段不能替代台架测量。
