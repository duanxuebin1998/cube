# LTD 共享 Modbus 协议卷

> 最新正式共享契约：`DEVICE_PROTOCOL_VERSION = 30`，首个正式组合为 CPU2 `V1.35.0.0` / CPU3 `V1.35.0.0`；当前开发共享契约为协议31，首个正式固件组合待发布阶段确定；CPU2/CPU3仍按协议版本严格相等判断<br>
> 协议形式：标准 Modbus RTU，0 基 PDU 地址直接索引寄存器数组<br>
> 地址兼容性：本地址表直接替换协议 26 及更早地址表，旧地址不再兼容

## 1. 协议定位

LTD 只保留这一套标准 Modbus RTU 协议。CPU2/CPU3 板间通信和 CPU3 对外 LTD 从站共用共享保持寄存器、共享输入寄存器与命令值；CPU3 本机参数位于同一协议的 `0x7000` 高地址段。

协议实现继续采用项目原有形式：

- `stateformodbus.h` 定义地址宏/枚举；
- `HoldingRegisterArray[]` 与 `InputRegisterArray[]` 保存寄存器值；
- 报文中的 0 基地址直接作为数组索引；
- 参数组表和解析函数负责结构字段与寄存器数组之间的读写；
- 不增加私有功能码，也不增加第二套参数编号。

CPU2 是共享参数、测量状态和命令执行的权威端。CPU3 负责板间轮询、已确认快照、CPU3 本机参数和外部网关。CPU3 对外写共享参数或命令时，必须等待 CPU2 返回合法 FC10 ACK 后才能向主站返回成功；协议28的七个命令前置参数以该ACK确认本次写值，不再追加同步FC03。

协议29不移动任何共享寄存器，也不改变字段宽度；它取消不可达的12-11，把扭力故障调整为18类、模拟输出与自检故障调整为21类，将13-2统一为“震动管频率异常”，并把13-26密度有效上限调整为3000.0 kg/m³。协议29不提供旧故障码别名或翻译。

协议30继续不移动共享寄存器，也不改变字段宽度、字序或命令码；它新增23-1～23-6独立共享故障码，覆盖24 V真实低压、ADC溢出、DMA停止、电源监控启动/恢复失败和掉电位置保存失败。协议29及更早CPU3不能识别这些故障含义，不得与协议30 CPU2混用。

协议31复用调试输入寄存器`0x0116~0x0117`的未使用“重量参数”槽，改为Newhall扭力模块温度IEEE754 float32原始位，高16位在前；双端字段统一命名为`torque_temperature_bits`，寄存器宏统一命名为`REG_DEBUG_TORQUE_TEMPERATURE_BITS`，不保留旧名称别名。CPU3在扭力标定等待页和`STATE_READPARAMETEROVER`读取部件参数结果分页显示该温度，无效时显示`--.--`。地址、字段宽度和调试轮询块长度保持不变。协议30及更早CPU2不会发布该温度，新CPU3不得与其混用。

## 2. RTU 链路与标准帧

### 2.1 默认链路参数

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 物理层 | RS-485，半双工 | 外部 COM 口选择 LTD 协议后使用 |
| 波特率 | 4800 bit/s | 可由 CPU3 端口配置决定 |
| 数据格式 | 8N1 | 8 数据位、无校验、1 停止位 |
| 从站地址 | 1 | CPU3 对外使用拨码地址，合法范围 1~247；非法时回退为 1 |
| CRC | Modbus CRC16 | 帧尾低字节在前、高字节在后 |

实际现场串口参数以 CPU3 当前端口配置为准；更改端口参数前应先完成当前响应事务。

### 2.2 请求与响应

读请求：

```text
[站号][功能码][起始PDU地址Hi][Lo][寄存器数量Hi][Lo][CRC Lo][CRC Hi]
```

读响应：

```text
[站号][功能码][字节数][寄存器数据...][CRC Lo][CRC Hi]
```

FC10 请求：

```text
[站号][10][起始地址Hi][Lo][数量Hi][Lo][字节数][数据...][CRC Lo][CRC Hi]
```

FC10 成功响应回显起始地址和寄存器数量。地址不匹配或 CRC 错误不回包；合法请求中的功能、地址或数据错误返回标准异常帧。

## 3. 功能码与数量限制

| 功能码 | 名称 | 用途 | 单帧限制 |
| --- | --- | --- | --- |
| `0x03` | Read Holding Registers | 读取 CPU2 共享参数、命令回读、能力位或 CPU3 本机参数 | 1~125 个寄存器 |
| `0x04` | Read Input Registers | 读取 CPU2 权威状态和测量快照 | 1~125 个寄存器 |
| `0x10` | Write Multiple Registers | 写完整 32 位共享字段、命令或 CPU3 本机字段 | 共享字段偶数地址、偶数数量，最多 122 个寄存器 |

`FC06`、线圈功能码及其它功能码均不属于本协议，返回 `0x01 Illegal Function`。

CPU3 板间读取大块数据时按 125 个寄存器以内拆帧；密度点表按更小分组轮询，以避免单次事务长期占用 UART5。

## 4. 地址表示方法

### 4.1 报文地址

本协议表中的“PDU 地址”是报文实际发送的 0 基地址。例如读取共享协议兼容号时，报文发送 `0x000E`，不能把 `400015` 或 `400001` 直接填入报文。

### 4.2 3x/4x参考号

为适配 PLC/组态软件，全量表同时给出 6 位参考号：

```text
保持寄存器参考号 = 400001 + PDU地址
输入寄存器参考号 = 300001 + PDU地址
```

示例：

| 字段 | PDU地址 | 参考号 |
| --- | ---: | ---: |
| 共享协议兼容号 | `0x000E` | `400015` |
| 命令入口 | `0x0F00` | `403841` |
| 维护模式状态 | `0x0010` | `300017` |
| CPU3本机首字段 | `0x7000` | `428673` |

不同 PLC 软件可能把第一项显示为 0 或 1。联调时必须先确认软件输入的是 PDU 地址还是 3x/4x参考号。

## 5. 固定功能块

### 5.1 CPU2 共享保持寄存器

CPU2 数组范围为 `HoldingRegisterArray[0x1000]`，合法 PDU 地址为 `0x0000~0x0FFF`。

| PDU范围 | 内容 | 当前已用范围 | 扩展规则 |
| --- | --- | --- | --- |
| `0x0000~0x00FF` | 设备信息、运行策略、协议兼容号 | `0x0000~0x0011` | 后续通用参数在本块空地址追加 |
| `0x0100~0x01FF` | 电机、编码器、重量、零点 | `0x0100~0x0127` | 不移动既有字段 |
| `0x0200~0x02FF` | 液位、罐底、罐高 | `0x0200~0x0221` | 块内追加 |
| `0x0300~0x03FF` | 水位参数 | `0x0300~0x0315` | 块内追加 |
| `0x0400~0x04FF` | 密度、温度、钢带修正 | `0x0400~0x040B` | 块内追加 |
| `0x0500~0x05FF` | 测量、标定、单点参数 | `0x0500~0x0525` | 块内追加 |
| `0x0600~0x06FF` | AO 配置与非持久化仿真开关 | `0x0600~0x061B` | 块内追加 |
| `0x0700~0x07FF` | K1~K4 继电器配置 | `0x0700~0x0767` | 每路固定 26 个寄存器 |
| `0x0800~0x08FF` | Wartsila 与 SI 参数 | `0x0800~0x0813` | 块内追加 |
| `0x0900~0x09FF` | 原参数结构保留字段 | `0x0900~0x0913` | 仅用于原字段，不复用为无关含义 |
| `0x0A00~0x0DFF` | 后续共享参数预留 | 未使用 | 新功能优先按业务另分子块 |
| `0x0E00~0x0EFF` | 参数存储元信息 | `0x0E00~0x0E07` | 只读 |

未分配的保持寄存器读取为 0；对未分配、只读或不完整字段执行 FC10 返回 `0x02` 或 `0x03`，不得用空地址保存临时业务数据。

### 5.2 CPU3 本机保持寄存器

CPU3 本机段不进入 CPU2 数组，由 CPU3 直接读取或事务式保存。

| PDU范围 | 内容 | 备注 |
| --- | --- | --- |
| `0x7000~0x701D` | CPU3版本、语言、数据源、手工输入、显示参数 | 每字段 2 个寄存器 |
| `0x7020~0x7029` | COM1 配置 | 当前对 LTD FC10 只读 |
| `0x7030~0x7039` | COM2 配置 | 当前对 LTD FC10 只读 |
| `0x7040~0x7049` | COM3 配置 | 当前对 LTD FC10 只读 |
| `0x7050~0x7057` | SI 自动 Profile | CPU3 本机持久化 |
| `0x7058~0x706B` | SI 报警限值 | CPU3 本机持久化 |

读取本机段内未分配槽返回 0。FC10 每次只允许写一个完整 32 位本机字段；串口配置首版只读，防止承载请求的端口在响应前改变通信参数。

## 6. 数据类型、字序和工程值

### 6.1 32位字段

除继电器既有 16 位运行标志外，共享标量和 CPU3 本机字段统一占 2 个 16 位寄存器：

```text
地址 A     = 32位值的高16位
地址 A + 1 = 32位值的低16位
```

- `UInt32`：无符号 32 位整数；
- `Int32`：有符号二进制补码；
- `Float32`：IEEE-754 单精度浮点，先高字后低字；
- `Bool`：32 位值，0=否/关闭，1=是/开启；
- `Enum`：32 位枚举，具体取值见全量表。

继电器运行状态块中，报警值是 2 寄存器 `Float32`，随后 8 个既有报警标志各占 1 个 16 位寄存器；全量表会明确标记寄存器数和字序。

### 6.2 缩放与偏移

全量表使用 `S` 表示缩放、`O` 表示原始偏移：

```text
工程值 = (原始值 - O) / S
原始值 = 工程值 × S + O
```

示例：

| 参数 | 原始值 | S | O | 工程值 |
| --- | ---: | ---: | ---: | ---: |
| 0.1 mm 液位 | 12345 | 10 | 0 | 1234.5 mm |
| 0.01 kg/m³ 密度 | 80543 | 100 | 0 | 805.43 kg/m³ |
| 温度 | 22500 | 100 | 20000 | 25.00 ℃ |
| AO 电流 | 2000 | 100 | 0 | 20.00 mA |

浮点字段已经按 IEEE-754 表示工程值，通常 `S=1`、`O=0`。

### 6.3 错误码

Input `0x0004~0x0005` 是CPU2权威的32位内部错误码，高16位为故障类别、低16位为故障子码，屏幕通常按十进制“类别-子码”显示。错误码没有缩放和单位；现场必须按产生该错误的CPU2程序版本选择故障表，不能只按`DEVICE_PROTOCOL_VERSION`跨版本解释历史编号。

## 7. 读取、写入与一致性

### 7.1 CPU2 权威快照

- CPU3 周期读取 CPU2 保持/输入寄存器，并把合法响应写入相同地址的本机缓存。
- CPU3分别维护普通运行态、完整参数、当前连接协议和固定点一致性快照。普通FC04只要求状态、协议兼容且通信故障未锁存；FC03继续要求完整参数快照。
- CPU2 断链、协议不匹配或对应数据域快照未建立时，CPU3 对外共享读写返回 `0x06 Slave Device Busy`，不返回旧值或伪成功。参数刷新期间FC03和普通参数写仍返回Busy；不依赖参数的普通FC04继续可读。命令16和“所需字段均有ACK确认位”的带参命令按下述窄例外处理。
- 固定点代次`0x0030~0x0033`和单点测量/监测结果`0x1100~0x113F`采用前计数、结果、后计数三阶段读取；前后计数一致才提交。`0x1140`起的分布汇总和SI Profile运行态不属于固定点结果门禁。
- 密度点表按汇总头、点数据、汇总头复核，避免跨测量周期拼接。

### 7.2 FC10 共享写入

- 起始地址必须为偶数，数量必须为偶数，且完整覆盖可写的 32 位字段；
- 单帧最多写 122 个寄存器；
- 命令只能单独写 `0x0F00~0x0F01`；
- CPU3 将请求转发给 CPU2，等待 CPU2 的合法 FC10 ACK；
- CPU2拒绝、超时、CRC错误、UART错误或协议不匹配时，CPU3不返回成功；
- 非命令参数获得合法FC10 ACK后，CPU3用本次线序寄存器更新对应保持寄存器和参数解析缓存，使完整参数快照失效并在后台重新读取CPU2完整参数；
- 七个命令前置参数的写入起点仍要求CPU2完整参数快照、协议匹配且通信故障未锁存，但不受普通持久参数的设备状态白名单限制；
- 七字段收到合法FC10 ACK后，只设置本次字段的易失位图，不追加同步FC03。完整参数刷新期间，仅当命令实际消费的字段全部已确认，才允许该命令凭有效运行态快照下发；无参数普通命令不能借用其它字段的确认位；
- 普通FC03/FC04单次失败不清确认位；连续第三次失败触发完整重同步时统一清除。已发出的参数写未取得合法响应时结果不确定，清除全部确认位并请求刷新；普通命令结果不确定时只消费对应字段确认位，不请求参数刷新；恢复出厂例外，仍清除全部确认位并强制完整刷新。TX DMA未启动不清。标准异常`0x01/0x02/0x03/0x04/0x06`是确定失败，不累计物理通信失败；
- 命令ACK后消费对应字段确认位。恢复出厂ACK后立即清除全部确认位并使完整参数快照失效；CPU3等待CPU2默认参数保存完成使`parameter_update_flag`变化后才启动完整刷新，刷新完成前对外参数读取持续返回`0x06`；
- 恢复出厂命令已挂起、正在执行或启动恢复默认参数时，七字段写入返回`0x06`，防止写入已ACK后又被整套默认值覆盖；
- 禁用继电器通道允许逐项写入暂时不满足`HH >= H >= L >= LL`的阈值组合，但本次触及字段仍必须满足枚举、有限值和当前报警源物理范围；切换为启用或修改已启用通道时必须通过完整配置校验；
- 液位罐高和水位罐高变化只复核已启用且分别使用储罐液位、水位报警源的通道；禁用或无关报警源不阻断罐高写入。四路继电器阻尼为预留字段，固定只允许0。

### 7.3 CPU3 本机写入

CPU3 本机段每次只写一个 2 寄存器字段。CPU3先校验范围，再执行本机持久化和写后读回；保存失败返回 `0x04 Slave Device Failure`。COM1~COM3 串口配置当前只读。

## 9. 维护与继电器状态

### 9.1 状态地址

以下字段均属于 CPU2 同一输入寄存器快照，每个字段占 2 个寄存器：

| PDU地址 | 名称 | 语义 | 当前行为 |
| --- | --- | --- | --- |
| `0x0010~0x0011` | 维护模式状态 | 0=关闭，1=开启；非持久化，上电默认关闭 | 已实现，CPU2 权威发布 |
| `0x0012~0x0013` | 继电器实际屏蔽状态 | 0=未屏蔽，1=已屏蔽；表示维护或人工运动造成的最终屏蔽 | 已实现，维护或人工屏蔽任一有效即为 1 |
| `0x0014~0x0015` | K1最终逻辑报警动作 | 0=未报警动作，1=报警动作 | 已实现；屏蔽期间为 0 |
| `0x0016~0x0017` | K2最终逻辑报警动作 | 同上 | 已实现；屏蔽期间为 0 |
| `0x0018~0x0019` | K3最终逻辑报警动作 | 同上 | 已实现；屏蔽期间为 0 |
| `0x001A~0x001B` | K4最终逻辑报警动作 | 同上 | 已实现；屏蔽期间为 0 |
| `0x0034~0x0035` | K1物理触点反馈 | 未来反馈诊断槽 | 保留/不支持，固定 0 |
| `0x0036~0x0037` | K2物理触点反馈 | 未来反馈诊断槽 | 保留/不支持，固定 0 |
| `0x0038~0x0039` | K3物理触点反馈 | 未来反馈诊断槽 | 保留/不支持，固定 0 |
| `0x003A~0x003B` | K4物理触点反馈 | 未来反馈诊断槽 | 保留/不支持，固定 0 |

“最终逻辑报警动作”不是 HH/H/L/LL 条件状态，也不是 NC/NO 触点反馈。CPU2 在维护或人工屏蔽期间继续计算阈值、滞回和锁存，只把最终逻辑动作压为 0，再按 NC/NO 配置驱动输出。现有 HH/H/L/LL 条件状态继续位于继电器运行状态块；没有反馈诊断实现前，任何保留槽的 0 都不能用于证明继电器物理触点动作成功。

维护模式不占用设备状态机，开启后仍可执行测量、移动、标定和取消测量。AO 仅跳过“设备故障时改送故障电流”的分支，固定、仿真、过程、保持最近值、初始值和单一电流修正链保持有效；AD5421 自身诊断不被维护模式屏蔽。

### 9.2 能力位

能力位地址为 `0x0F10~0x0F11`，高字在前。当前 `LTD_CAPABILITY_SUPPORTED_MASK = 0x0000001F`：

| 位 | 名称 | 当前值 |
| ---: | --- | ---: |
| 0 | `MAINTENANCE_MODE` | 1 |
| 1 | `RELAY_ALARM_ACTION_STATUS` | 1 |
| 2 | `RELAY_ALARM_INHIBIT` | 1 |
| 3 | `AO_FAULT_CURRENT_INHIBIT` | 1 |
| 4 | `CLEAR_ALL_RELAY_LATCHED_ALARMS` | 1 |

## 10. 参数存储与升级

共享 Modbus 地址和命令参数运行事务与 CPU2 FRAM 参数结构是独立层次。协议28沿用协议27地址与原结构既有槽：

| 检查项 | 当前值 | 是否改变 |
| --- | --- | --- |
| `DEVICE_PARAM_VERSION` | 3 | 否 |
| `sizeof(DeviceParameters)` | 由当前编译结构决定 | 与重排前相同 |
| magic | `0x4C54444D` (`LTDM`) | 否 |
| CRC范围 | `sensorType` 到 `crc` 前 | 否 |
| FRAM A槽 | `0x0000`，容量 `0x0800` | 否 |
| FRAM B槽 | `0x0800`，容量 `0x0800` | 否 |

因此，从合法旧参数镜像升级时：

1. CPU2 仍按 magic、结构大小、参数存储版本和 CRC 校验 A/B 槽；
2. 任一有效槽可按既有规则加载，现场参数不会因为 Modbus 地址变化被整体清零；
3. 当前正式协议30源码把 `protocolVersion` 归一化为30；CPU2/CPU3按各自编译版本严格相等，协议29及更早程序不得与协议30混搭；
4. AO 单一电流修正值复用原 `SIL/WHG` 保留槽，旧协议 25 及更早镜像在升级时把该槽归零，避免把历史保留值解释为电流修正；
5. 只有原有的 magic、结构大小、参数存储版本、CRC 或 A/B 槽有效性检查失败时，才可能按既有恢复逻辑使用另一槽或恢复出厂默认值；
6. 恢复出厂只在整套默认值覆盖与保存窗口临时拒绝七个命令参数写入，不改变结构、CRC范围或普通状态白名单。

非持久化字段包括命令入口、AO 仿真开关、四路清除锁存报警瞬时写槽、维护/继电器运行状态和全部输入寄存器运行态。

后续若真的修改 `DeviceParameters` 大小、参数存储版本、magic 或 CRC 范围，必须单独设计旧 FRAM 迁移；不能把线地址预留当作存储迁移机制。

## 11. 异常响应

异常帧格式：

```text
[站号][功能码 | 0x80][异常码][CRC Lo][CRC Hi]
```

| 异常码 | 名称 | 典型触发条件 |
| --- | --- | --- |
| `0x01` | Illegal Function | 使用 FC03/FC04/FC10 以外功能码 |
| `0x02` | Illegal Data Address | 地址越界、写只读/未分配地址、字段不完整、CPU3本机字段不存在 |
| `0x03` | Illegal Data Value | 数量/字节数非法、参数越界、命令未实现、命令与其它字段混写、继电器启用时完整配置非法或已启用配置被改为非法 |
| `0x04` | Slave Device Failure | CPU3 本机参数保存或写后读回失败 |
| `0x06` | Slave Device Busy | CPU2对应数据域快照未就绪、协议不匹配、FC03参数刷新中、固定点字段握手未完成、带参命令缺少所需字段确认位、恢复出厂ACK后等待完整参数刷新、恢复出厂覆盖参数、CPU2未返回合法ACK或通信故障 |

CPU2 直连板间从站使用同样的 `0x01/0x02/0x03` 基本校验；CPU3 对外网关额外使用 `0x04/0x06` 表达本机保存失败和下级未就绪。

## 13. 长期维护与代码入口

### 13.1 长期维护规则

1. 新增共享参数或状态时，先选择对应功能块中的空偶数地址；32 位字段固定占两个寄存器。
2. 已发布字段不得移动，也不得把删除字段地址改作无关含义；删除后保留地址并标记为保留/不支持。
3. PDU 地址直接作为 CPU2/CPU3 数组索引；两端同名地址宏/枚举和本地址表共同维护这一套标准 Modbus 映射。
4. 同步修改 CPU2/CPU3 的 `stateformodbus.h`、组表/解析、写权限、CPU3轮询分组、外部网关、上位机映射和本章全量寄存器表。
5. 共享地址、类型、字序、缩放、权限、命令或状态语义变化时提升 `DEVICE_PROTOCOL_VERSION`，并保持 CPU2/CPU3 严格相等检查。
6. 新增轮询分组不得超过 125 个寄存器；FC10 共享写入不得超过 122 个寄存器，且不能拆开 32 位字段。
7. 新增持久化字段时单独评估 `DeviceParameters` 大小、参数存储版本、CRC和旧FRAM迁移；地址块有空位不代表存储结构可无迁移修改。
8. 修改完成后运行双端静态契约、CPU2/CPU3 clean-first 构建、上位机协议测试及 `git diff --check`；真实 UART、掉电、继电器和 AO 环路仍需台架验证。
9. 本目录只维护本 Markdown 协议卷，不再建立可独立漂移的拆分地址表或 PDF 副本。

### 14.6 预留与不支持口径

- 维护模式状态、继电器实际屏蔽状态、K1~K4最终逻辑报警动作均由CPU2真实发布；维护/人工屏蔽期间K1~K4最终逻辑动作返回0，但内部阈值和锁存继续计算。
- K1~K4物理触点反馈地址标记为`reserved/not_supported`，固定0不能证明继电器物理动作成功。
- 命令118/119已实现为退出维护和清除全部继电器锁存报警；能力位0~4均为1，当前掩码为`0x0000001F`。
- 现有HH/H/L/LL条件状态、四路继电器阈值和唯一AO电流修正值使用表内既有地址，不重复建立。

### 14.7 维护要求

新增字段时只能使用对应功能块的空地址或新功能块；已发布地址不得移动或改作无关含义。修改后必须同步CPU2/CPU3地址头、组表与解析、CPU3轮询、外部LTD从站、上位机目录和本表，并提升共享契约兼容号。
