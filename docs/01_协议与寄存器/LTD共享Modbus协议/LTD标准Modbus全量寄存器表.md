# LTD 标准 Modbus 全量寄存器表

更新日期：2026-07-22

适用组合：CPU2 `V1.31.0.0` / CPU3 `V1.30.0.0` / `DEVICE_PROTOCOL_VERSION = 27`。

## 1. 文档定位

本表是 [LTD共享Modbus协议卷](LTD共享Modbus协议卷.md) 第14章的独立查表版，使用同一维护源，覆盖CPU2共享Holding、CPU3本机Holding、普通Input以及200点密度Input。协议语义、异常响应、命令时序、参数存储兼容性和参考帧仍以协议卷正文为准。

故障码必须按产生该错误的CPU2程序版本选择故障表；不得仅按CPU3版本或共享协议号套用当前故障编号。

## 2. 全量寄存器表

本章沿用项目原有的地址宏/枚举和寄存器数组格式，按 PDU 地址给出 3x/4x参考号、参数名称、分组、类型、寄存器数、字序、权限、S、O、单位、范围/枚举、权威端、持久化和支持状态。普通字段逐项列出；200点密度区先列统一字段口径，再列200点逐点地址矩阵。

表中未列出的块内空地址均为预留地址，不代表可写参数。正式联调以 PDU 地址、功能码和寄存器数三者共同确定字段。

### 2.1 查表约定

- Holding参考号：`400001 + PDU地址`；Input参考号：`300001 + PDU地址`。
- 报文必须发送PDU地址，不能把3x/4x参考号直接填入RTU帧。
- 两寄存器字段统一为高16位在前、低16位在后；`Int32`使用二进制补码，`Float32`使用IEEE-754单精度。
- “可写”表示线协议FC10权限；标为“普通页面只读”的兼容字段虽可在线协议写入，但上位机普通参数页不会开放。
- 本表共覆盖1550个已定义字段：CPU2 Holding 164项、CPU3 Holding 44项、普通Input 142项、200点密度Input 1200项。

### 2.6 预留与不支持口径

- 维护模式状态、继电器实际屏蔽状态、K1~K4最终逻辑报警动作均由CPU2真实发布；维护/人工屏蔽期间K1~K4最终逻辑动作返回0，但内部阈值和锁存继续计算。
- K1~K4物理触点反馈地址标记为`reserved/not_supported`，固定0不能证明继电器物理动作成功。
- 命令118/119已实现为退出维护和清除全部继电器锁存报警；能力位0~4均为1，当前掩码为`0x0000001F`。
- 现有HH/H/L/LL条件状态、四路继电器阈值和唯一AO电流修正值使用表内既有地址，不重复建立。

### 2.7 维护要求
