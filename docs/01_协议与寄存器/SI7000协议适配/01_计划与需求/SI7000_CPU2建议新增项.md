# SI7000 适配时 CPU2 建议新增项

## 1. 适配原则

当前更合适的路线不是把 `CPU2` 改造成 `SI7000` 的四种工作模式内核，而是：

- `CPU2` 保留你现有的零点基准体系
- `CPU2` 抽取有价值的通用变量和测量能力
- `CPU3` 负责把这些通用能力转换成 `SI7000` 协议语义

也就是说：

- 内部模型继续是“以零点为基准”
- 对外协议允许是“以罐底为基准”
- 坐标换算放在 `CPU3`
- 时间相关尽量放在 `CPU3`

## 2. 下一步总分类

### 2.1 可以直接复用的现有能力

这些能力不建议重做，直接保留并对外映射：

- 零点基准位置体系
- `sensor_position`
- `cable_length`
- `current_real_height`
- `oil_level`
- `single_point_monitoring.temperature`
- `single_point_monitoring.density`
- `density_distribution.measurement_points`
- `density_distribution.single_density_data[]`
- `CMD_FIND_OIL`
- `CMD_MEASURE_DISTRIBUTED`
- `CMD_CALIBRATE_ZERO`
- `CMD_FORCE_MOVE_UP`
- `CMD_FORCE_MOVE_DOWN`

### 2.2 需要在 CPU2 新增的

重点新增“通用状态变量、通用参数、通用判定能力”，不要新增一整套 `SI7000_MODE_xxx`。

### 2.3 需要在 CPU3 新增的

- 罐底基准坐标换算
- 时间戳和当前时间
- 协议层影子寄存器
- 协议层固定值输出
- 由 `CPU2` 事件生成对外状态位

### 2.4 直接不支持或先返回固定值的

- 保留位
- 当前系统没有等价语义的位
- 缺少真实时间来源时的时间字段

## 3. CPU2 建议新增的变量

建议使用“中性命名”，不要把 `si7000` 协议名直接写进 `CPU2` 内核。

### 3.1 最值得优先新增的状态变量

建议新增到 `MeasurementResult` 关联结构中，或新增一个专门的扩展状态结构。

```c
uint32_t bottom_reference_valid;          // 罐底参考位置是否有效
uint32_t probe_at_liquid_level;           // 探头当前是否处于液位点
uint32_t liquid_stable;                   // 液体是否稳定
uint32_t profile_complete_latched;        // 分布测量完成锁存
uint32_t profile_complete_counter;        // 分布测量完成计数器
uint32_t profile_blocked_by_process;      // 分布测量被工况禁止
uint32_t loading_unloading_active;        // 当前是否处于装卸液过程
uint32_t manual_alarm_inhibit;            // 手动模式下报警抑制
uint32_t manual_level_update_inhibit;     // 手动模式下液位更新抑制
uint32_t profile_temp_deviation_alarm;    // 分布温度偏差报警
uint32_t profile_density_deviation_alarm; // 分布密度偏差报警
```

### 3.2 为什么推荐这批变量

- `bottom_reference_valid`
  - 不是让系统改成罐底基准
  - 只是告诉外部“当前已知罐底参考是否可信”
- `probe_at_liquid_level`
  - 后面可用于 `SI7000` 的 `Probe At Liquid Level`
- `liquid_stable`
  - 可用于限制分布测量/Profile
- `profile_complete_latched`
  - 可用于 `Profile Complete`
- `profile_complete_counter`
  - 方便 `CPU3` 在没有 RTC 的情况下识别“这是一次新的 profile 完成事件”
- `profile_blocked_by_process`
  - 用于表达“装卸液期间禁止做 profile”
- `manual_alarm_inhibit`
  - 对应手动模式“不报警”
- `manual_level_update_inhibit`
  - 对应手动模式“不更新液位”

## 4. CPU2 建议新增的参数

建议新增的是“通用测量和判定参数”，而不是直接照抄协议地址名。

### 4.1 分布测量/Profile 相关参数

```c
uint32_t profile_dwell_time;              // 到底后的停留时间
uint32_t profile_increment;               // 逐点采样间距
uint32_t profile_max_points;              // 最大测点数
uint32_t profile_auto_enable;             // 是否允许自动触发分布测量
uint32_t profile_auto_interval_min;       // 自动触发周期
```

### 4.2 报警阈值参数

```c
int32_t  low_temp_setpoint;               // 低温阈值，建议 0.01°C
int32_t  high_temp_setpoint;              // 高温阈值，建议 0.01°C
uint32_t temp_deviation_setpoint;         // 温度偏差阈值
uint32_t density_deviation_setpoint;      // 密度偏差阈值

uint32_t ll_level_setpoint;               // 低低液位
uint32_t hh_level_setpoint;               // 高高液位
uint32_t low_level_setpoint;              // 低液位
uint32_t high_level_setpoint;             // 高液位
```

### 4.3 手动运行速度参数

```c
uint32_t manual_speed_slow_x100;          // 慢速，单位 0.01m/min
uint32_t manual_speed_medium_x100;        // 中速
uint32_t manual_speed_fast_x100;          // 快速
```

### 4.4 不建议做的事

- 不建议在 `CPU2` 新增 `si7000_profile_*` 这种协议味很重的参数名
- 不建议为了三档速度再新增 6 个独立命令
- 不建议把现有参数强行改成“罐底基准”

## 5. CPU2 建议新增的功能

### 5.1 液位可信判定

建议在 [measure_oilLevel.c](../../../../LTD_MAIN_CPU2/Application/Src/measure_oilLevel.c) 中补：

- `probe_at_liquid_level`
- `liquid_stable`

可以基于：

- 当前液位频率是否在目标附近
- 持续时间是否满足稳定要求
- 是否处于异常频率恢复中

### 5.2 罐底参考建立与失效

建议在回零、到底、重新定位相关流程中维护：

- `bottom_reference_valid = 1`

在以下场景清零：

- 上电未完成重新定位
- 机械异常
- 关键定位流程失败

### 5.3 分布测量前置条件检查

建议在分布测量入口统一检查：

- `liquid_stable`
- `loading_unloading_active`
- `bottom_reference_valid`

如果不满足条件：

- 不执行分布测量
- `profile_blocked_by_process = 1`

### 5.4 分布测量完成锁存

建议在分布测量结束时统一维护：

- `profile_complete_latched = 1`
- `profile_complete_counter++`
- 偏差报警结果

新一次分布测量开始前清除：

- `profile_complete_latched`
- `profile_temp_deviation_alarm`
- `profile_density_deviation_alarm`

### 5.5 手动运行抑制逻辑

建议在手动上/下运行链路中统一维护：

- `manual_alarm_inhibit = 1`
- `manual_level_update_inhibit = 1`

退出手动或回到自动测量流程时清零。

## 6. 时间相关放在哪里

因为 `CPU2` 没有 `RTC`，建议：

- `CPU2` 只提供“事件”
- `CPU3` 负责给事件打时间戳

### 6.1 CPU2 提供的事件

- `profile_complete_latched`
- `profile_complete_counter`
- 其它以后需要打时间戳的完成事件

### 6.2 CPU3 维护的时间字段

- `Current Time`
- `Profile Timestamp`

如果 `CPU3` 也没有真实时钟源：

- 协议层时间字段先返回固定值 `0`
- 不建议长期使用 `HAL_GetTick()` 冒充真实时间

## 7. 坐标基准放在哪里转换

你已经确认：

- `CPU2` 内部继续保留零点基准
- `SI7000` 对外如果需要罐底基准，再由 `CPU3` 换算

建议新增一个统一换算思路：

- `CPU2` 只提供零点基准位置和实高/罐底相关信息
- `CPU3` 做：
  - 探头距罐底位置换算
  - 液位距罐底高度换算
  - Profile 点位的罐底基准换算

## 8. 哪些应由 CPU3 新增

建议新增在 `CPU3` 而不是 `CPU2` 的内容：

- `Profile Timestamp`
- `Current Time`
- 协议层影子寄存器
- 罐底基准坐标换算
- 单位制固定输出
- 固定值/保留值填充

## 9. 哪些可以先固定返回

如果当前系统没有可靠来源，建议先固定返回，不要硬猜：

- 保留位：返回 `0`
- `10002 Lower Level Sensor`：返回 `0`
- `10003 Upper Level Sensor`：返回 `0`
- `10012 Interval Timer`：由 `CPU3` 根据 `40011 Automatic Profile Enable` 影子值合成，`CPU2` 不新增定时器协议状态
- `30007~30010 Profile Timestamp`
  - 由 `CPU3` 在 profile 完成事件后锁存 RTC，RTC 不可读时返回 `0`
- `30011~30013 Current Time`
  - 由 `CPU3` RTC 提供，RTC 不可读时返回 `0`
- `10006 Metric/English`
  - 当前固定返回 `1`

## 10. 最小优先级集合

如果只想先增强最有价值的一批，建议优先做：

### 10.1 CPU2 变量

- `bottom_reference_valid`
- `probe_at_liquid_level`
- `liquid_stable`
- `profile_complete_latched`
- `profile_complete_counter`
- `profile_blocked_by_process`
- `manual_alarm_inhibit`
- `manual_level_update_inhibit`

### 10.2 CPU2 参数

- `profile_dwell_time`
- `profile_increment`
- `profile_max_points`
- `profile_auto_enable`
- `profile_auto_interval_min`
- `low_temp_setpoint`
- `high_temp_setpoint`
- `temp_deviation_setpoint`
- `density_deviation_setpoint`

### 10.3 CPU3 能力

- `Profile Timestamp`
- `Current Time`
- 零点基准到罐底基准的换算

## 11. 推荐修改顺序

1. 先在 `CPU2` 增加中性变量和参数
2. 在液位流程补 `probe_at_liquid_level`、`liquid_stable`
3. 在分布测量补完成锁存、计数器、偏差报警
4. 在回零/到底流程补 `bottom_reference_valid`
5. 在手动运行链路补报警抑制和液位更新抑制
6. 最后由 `CPU3` 统一做协议映射、时间戳和坐标换算
