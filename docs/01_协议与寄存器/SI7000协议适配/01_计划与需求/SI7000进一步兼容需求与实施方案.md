# SI7000 进一步兼容需求与实施方案

日期：2026-07-01

本文根据 2026-07-01 已确认的 SI7000 进一步兼容需求整理。本文只整理需求、方案、影响范围和验证口径，不直接修改固件代码。

## 1. 需求结论

本轮 SI7000 兼容目标从“地址表和基础读写兼容”提升为“按 Scientific Instruments SI7000 profile 行为做独立测量流程兼容”。核心结论如下：

1. SI7000 `Profile` 必须新增独立 CPU2 命令和独立测量流程，不再复用普通分布测量 `CMD_MEASURE_DISTRIBUTED`。
2. SI7000 profile 测量过程按科学仪器方案适配：profile 开始前按探底频次决定是否真实探底；不探底时也必须运行到底部位置采集第 0 点密度。
3. `10001 Bottom Reference` 固定显示“未到底”，即对外始终返回 `0`。
4. `10010 Probe Un-calibrated` 固定显示“可信”，即对外始终返回 `0`。
5. `10002 Lower Level Sensor` / `10003 Upper Level Sensor` 按液位跟随状态合成：液位跟随时下传感器为液体、上传感器为空气；其它状态均显示在液体。
6. 自动 profile 调度需要落地，`40010~40013` 作为 SI7000 独立保持寄存器参与调度。
7. 兼容所有报警限值设置和状态，限值设置尽量复用现有参数或运行态能力；不能安全复用时再做 SI7000 专用配置。
8. `40001`、`40002`、`40003`、`40010`、`40011`、`40012`、`40013` 都作为 SI7000 独立保持寄存器，不再直接复用普通分布测量参数。
9. `30007~30010 Profile Timestamp` 改为 profile 测量开始时间，不再用完成时间。

## 2. 当前实现基线

| 项目 | 当前实现 | 本轮要求 |
| --- | --- | --- |
| SI7000 Profile 线圈 | CPU3 `00004` 写入后下发 `CMD_MEASURE_DISTRIBUTED` | 改为下发新的 SI7000 专用 profile 命令 |
| profile 测量流程 | 复用普通分布测量流程，点阵由现有分布测量结果生成 | 新增 SI7000 独立流程，按底部点 + 后续停点生成点阵 |
| 探底频次 | 已有 Wärtsilä 探底间隔参数和流程可参考 | 新增 SI7000 专用探底频次，不复用 Wärtsilä 参数名 |
| `10001` | 当前按 `bottom_reference_valid` 映射 | 固定 `0`，对外显示未到底 |
| `10010` | 当前按 `zero_point_status` 映射 | 固定 `0`，对外显示位置可信 |
| `10002/10003` | 当前固定 `0` | 按状态合成液体/空气 |
| `40001~40003` | 当前桥接 `spreadTopLimit`、`spreadMeasurementDistance`、`spreadPointHoverTime` | 改为 SI7000 独立保持寄存器 |
| `40010~40013` | 当前为 CPU3 影子回读，不真实调度 | 改为 SI7000 独立保持寄存器并驱动自动 profile 调度 |
| `40014~40023` | 当前为 CPU3 影子回读，并参与部分报警合成 | 尽量复用现有报警/阈值能力，补齐全部报警状态 |
| profile 时间戳 | 当前按完成计数变化锁存完成时刻 | 改为 profile 测量开始时间 |

## 3. 设计原则

- CPU3 继续负责 SI7000 Modbus RTU 地址、功能码、异常响应、缩放、保持寄存器和自动调度。
- CPU2 只新增真实测量所需的通用命令、流程和必要状态，不在 CPU2 中引入 SI7000 地址号、功能码或 Modbus 细节。
- SI7000 专用 profile 与普通分布测量、Wärtsilä 密度测量互相隔离，避免改 SI7000 行为时影响 DSM、Wärtsilä、菜单分布测量或综合测量。
- `40001~40003` 和 `40010~40013` 作为 SI7000 独立保持寄存器处理，避免继续把 SI7000 profile 参数误解释为普通分布测量参数。
- 报警限值优先复用现有通用能力，但复用必须满足单位、方向、阈值含义和持久化语义一致；不一致时保留 SI7000 专用参数。
- 对外协议状态以用户确认口径优先：`Bottom Reference` 和 `Probe Un-calibrated` 固定输出，不再追求与内部真实探底状态完全一致。

## 4. SI7000 Profile 独立测量流程方案

### 4.1 新增命令

建议新增 CPU2/CPU3 共享命令：

| 建议命令 | 建议编号 | 用途 |
| --- | --- | --- |
| `CMD_SI7000_PROFILE` | 建议使用普通命令预留区，例如 `20~22` 中一个空位 | 执行 SI7000 专用 profile 测量 |

CPU3 `si7000_apply_coil_write()` 中 `SI7000_COIL_PROFILE` 不再发送 `CMD_MEASURE_DISTRIBUTED`，改为发送 `CMD_SI7000_PROFILE`。

该变更会改变 CPU2/CPU3 共享命令契约，需要升级 `DEVICE_PROTOCOL_VERSION`，并同步更新 CPU2/CPU3 协议变更记录、SI7000 映射表和 golden frame/契约检查脚本。

### 4.2 测量流程

建议 CPU2 新增独立入口，例如 `CMD_SI7000_ProfileMeasurement()`，流程如下：

1. 收到 `CMD_SI7000_PROFILE`。
2. 进入 SI7000 profile 运行状态，清除上一轮 profile 完成锁存、点阵和报警状态。
3. 锁存 profile 测量开始事件，供 CPU3 输出 `30007~30010`。
4. 根据 SI7000 探底频次计数判断是否需要真实探底。
5. 如果达到探底频次：
   - 先执行真实探底流程。
   - 探底成功后刷新内部底部参考或底部位置。
   - 探底失败按测量失败处理，不生成完成锁存。
6. 如果未达到探底频次：
   - 不执行真实探底。
   - 使用当前已知底部参考、罐高、盲区或专用底部位置参数，运行到底部测量位置。
7. 在底部测量位置等待稳定，采集 `Point 0` 的位置、温度、密度。
8. 按 SI7000 独立保持寄存器继续生成后续停点：
   - `40001 Profile First Point`：底部点之后的首个停点。
   - `40002 Profile Increment`：每点步距。
   - `40003 Profile Dwell Time`：每点停留时间，单位秒。
9. 逐点运行、等待、采集温度和密度，直到达到点数上限、液位边界或其它停止条件。
10. 扫描并生成 profile 报警状态。
11. 写入 `g_measurement.density_distribution`，置位 `profile_complete_latched`，递增 `profile_complete_counter`。
12. 进入 SI7000 profile 完成状态，并按需要回到自动液位跟随或单点监测。

### 4.3 探底频次

建议新增 SI7000 专用参数：

| 参数 | 建议含义 | 范围 | 默认值 |
| --- | --- | --- | --- |
| `si7000_profile_bottom_detect_interval` | SI7000 profile 探底频次，`0` 表示不自动探底，`N` 表示每 N 次 SI7000 profile 前探底一次 | `0~100` | `0` 或按现场要求 |

不建议复用 `wartsila_bottom_detect_interval`，原因是该参数已经是 Wärtsilä 专用语义；SI7000 profile 的点阵和第 0 点含义不同，后续现场参数也可能不同。

### 4.4 底部位置和第 0 点

本轮明确要求：不探底时也必须运行到底部位置读取第 0 点密度。

建议把“真实探底”和“运行到底部测量位置”分开：

| 动作 | 含义 | 是否刷新底部参考 |
| --- | --- | --- |
| 真实探底 | 用扭力或角度等底部检测方式确认罐底 | 是，内部可刷新底部参考 |
| 运行到底部测量位置 | 按已有底部参考或配置位置运行到第 0 点采样位置 | 否，不应改变内部探底可信状态 |

底部测量位置建议优先使用已有罐底参考和盲区参数；如果现场要求底部点偏移，应新增 SI7000 专用底部点偏移参数，不建议把普通分布测量 `spreadBottomLimit` 直接当作 SI7000 Point 0。

## 5. Lower/Upper Level Sensor 输出方案

### 5.1 输出口径

| 状态 | `10002 Lower Level Sensor` | `10003 Upper Level Sensor` | 对外含义 |
| --- | --- | --- | --- |
| 液位跟随状态 | `1` | `0` | 下传感器在液体，上传感器在空气 |
| 其它状态 | `1` | `1` | 两个传感器均显示在液体 |

### 5.2 状态判断

第一版建议在 CPU3 SI7000 映射层根据 CPU2 设备状态合成：

- `STATE_FLOWOIL` 或后续明确的液位跟随状态：按“下液体、上空气”输出。
- 其它状态：按“两者均在液体”输出。

如果后续 CPU2 新增更细状态，例如 `probe_at_liquid_level`、液位稳定、液位跟随有效等，也可以替换成更严格条件。但本轮用户口径已经明确，优先按状态机合成即可。

## 6. 固定状态输出

### 6.1 `10001 Bottom Reference`

用户要求：一直为未到底。

实施口径：

- SI7000 对外 `10001` 固定返回 `0`。
- 内部真实探底状态仍可继续维护，用于测量流程、底部位置和故障判断。
- 文档中必须注明：SI7000 对外状态不再等同 CPU2 内部 `bottom_reference_valid`。

### 6.2 `10010 Probe Un-calibrated`

用户要求：一直为可信。

实施口径：

- SI7000 对外 `10010` 固定返回 `0`。
- 内部 `zero_point_status`、编码器可信状态、探底失败等仍用于本机保护和测量错误处理。
- 文档中必须注明：SI7000 对外始终不提示未校准，PLC 不应再依赖该位判断内部位置可信性。

## 7. 独立保持寄存器方案

### 7.1 必须独立的寄存器

以下地址改为 SI7000 独立保持寄存器，不再直接复用普通分布测量参数：

| 地址 | 名称 | 独立参数含义 | 单位/范围建议 |
| --- | --- | --- | --- |
| `40001` | Profile First Point | 底部点 Point 0 之后的首个停点 | mm，`0~65535` |
| `40002` | Profile Increment | 后续 profile 每点步距 | mm，`1~65535` |
| `40003` | Profile Dwell Time | 每点停留时间 | 秒，建议 `1~3600` |
| `40010` | Automatic Profile Interval | 自动 profile 周期 | 分钟，建议 `0~1440` 或按现场确认 |
| `40011` | Automatic Profile Enable | 自动 profile 使能 | `0/1` |
| `40012` | Automatic Profile Hour | 自动 profile 起始小时 | `0~23` |
| `40013` | Automatic Profile Minute | 自动 profile 起始分钟 | `0~59` |

### 7.2 存储位置建议

推荐将 `40001~40013` 放在 CPU3 本机 SI7000 参数中持久化，原因：

- 这些参数是外部 SI7000 协议配置，CPU3 是协议转换层和自动调度层。
- `40010~40013` 的调度依赖 CPU3 RTC，由 CPU3 持有更自然。
- `40001~40003` 虽然影响 CPU2 测量动作，但仍是 SI7000 profile 专用参数，可由 CPU3 在下发 `CMD_SI7000_PROFILE` 前或随命令上下文同步给 CPU2。

需要注意：如果 CPU2 执行测量时必须读取这些参数，则仍需要建立 CPU2 可见的参数传递机制。可选方案：

1. CPU3 在写 `40001~40003` 时同步写入 CPU2 新增 SI7000 专用参数。
2. CPU3 在触发 `CMD_SI7000_PROFILE` 前同步下发一组 SI7000 profile 参数。
3. 将 `40001~40003` 正式加入 CPU2 `DeviceParameters`，由 CPU2 持久化并执行。

推荐方案是第 3 项，因为测量动作在 CPU2 执行，参数和测量流程同侧更容易保证一致性。但这会改变 CPU2 参数存储布局，需要升级 `DEVICE_PARAM_VERSION`，并明确旧参数升级是否恢复出厂。

## 8. 自动 profile 调度方案

### 8.1 调度责任

建议自动 profile 调度放在 CPU3：

- CPU3 持有 SI7000 外部协议和 `40010~40013`。
- CPU3 已有 RTC 当前时间接口。
- 到点后由 CPU3 向 CPU2 下发 `CMD_SI7000_PROFILE`。

CPU2 只负责收到命令后执行真实测量流程。

### 8.2 调度规则

建议规则如下：

1. `40011 = 0` 时不自动触发 profile。
2. `40011 = 1` 时启用自动 profile。
3. 第一次触发时间为 `40012:40013`。
4. 后续按 `40010` 分钟周期触发；如果 `40010 = 0`，建议解释为“仅每日固定时刻触发一次”或“禁用周期触发”，需在联调前固定口径。
5. CPU3 只在设备空闲、非手动强制动作、无关键故障、未处于当前 profile 测量中时触发。
6. 如果到点时设备忙，记录一次调度跳过或延后，不应强行打断当前测量。
7. `10012 Interval Timer` 建议表示自动 profile 使能且调度器有效，而不是单纯等于 `40011`。

### 8.3 调度状态建议

建议新增 CPU3 本机运行态：

| 状态 | 用途 |
| --- | --- |
| 上次触发时间 | 防止同一分钟重复触发 |
| 下次触发时间 | 便于调试和后续显示 |
| 上次跳过原因 | 设备忙、故障、手动状态、参数非法等 |
| 自动触发计数 | 现场联调统计 |

是否对 PLC 暴露这些诊断状态，需要另行定义扩展寄存器；官方 SI7000 地址表没有预留这些诊断字段。

## 9. 报警限值和状态兼容方案

### 9.1 地址范围

需要兼容的报警限值和状态包括：

| 限值地址 | 状态地址 | 含义 |
| --- | --- | --- |
| `40014` | `10017` | Low Density Alarm |
| `40015` | `10018` | High Density Alarm |
| `40016` | `10019` | Low Temperature Alarm |
| `40017` | `10020` | High Temperature Alarm |
| `40018` | `10021` | LL Level Alarm |
| `40019` | `10022` | HH Level Alarm |
| `40020` | `10023` | Low Level Alarm |
| `40021` | `10024` | High Level Alarm |
| `40022` | `10025` | Profile Temp Deviation Alarm |
| `40023` | `10026` | Profile Density Deviation Alarm |
| `40016/40017` | `10029/10030` | Profile Low/High Temp |
| `40014/40015` | `10031/10032` | Profile Low/High Density |

### 9.2 复用策略

“尽量复用”的建议口径：

| SI7000 限值 | 可复用对象 | 建议 |
| --- | --- | --- |
| 密度低/高 `40014/40015` | 可参考现有 Wärtsilä 密度上下限，但不建议直接共用参数 | 若单位和业务一致，可在 CPU2 执行层复用计算函数；参数仍建议 SI7000 独立 |
| 温度低/高 `40016/40017` | 当前未见完全一致的通用上下限参数 | 建议 SI7000 独立参数 |
| 液位 LL/HH/Low/High `40018~40021` | 可参考 AO 高低报警、继电器报警中的液位阈值能力 | 不建议直接共用 AO 或继电器参数；可复用比较逻辑，不复用参数存储 |
| profile 偏差 `40022/40023` | 当前已有 `profile_temp_deviation_alarm`、`profile_density_deviation_alarm` 状态字段 | 建议新增阈值后在 CPU2 或 CPU3 扫描 profile 点阵生成状态 |

结论：限值“计算逻辑”可以复用，限值“参数”建议保持 SI7000 独立，除非确认某个现有参数与 SI7000 地址完全同义。这样能避免 PLC 修改 SI7000 限值时意外改变 AO、继电器、Wärtsilä 或其它协议行为。

### 9.3 状态生成

建议按两层生成：

1. 当前值报警：
   - CPU3 读取当前密度、温度、液位。
   - 按 `40014~40021` 计算 `10017~10024`。
   - 阈值为 `0` 时建议视为未启用，沿用当前实现口径。
2. Profile 报警：
   - 在 SI7000 profile 完成后扫描有效点阵。
   - 按 `40014/40015` 生成 `10031/10032`。
   - 按 `40016/40017` 生成 `10029/10030`。
   - 按相邻点温度差和密度差与 `40022/40023` 比较，生成 `10025/10026`。

## 10. Profile Timestamp 方案

用户要求：`Profile Timestamp` 改成测量开始时间。

实施口径：

- `30007`：profile 测量开始月份。
- `30008`：profile 测量开始日期。
- `30009`：profile 测量开始小时。
- `30010`：profile 测量开始分钟。

建议由 CPU3 在下发 `CMD_SI7000_PROFILE` 的时刻锁存开始时间，并保存在 SI7000 profile 运行态中。自动 profile 调度触发时也使用同一锁存入口。

如果存在“CPU3 下发命令成功但 CPU2 因忙或错误没有开始测量”的情况，建议：

- 第一版：以下发命令时刻作为 SI7000 profile 开始时间。
- 更严谨版：CPU2 新增 `si7000_profile_started_counter` 或通用 profile start 事件，CPU3 收到该事件后锁存开始时间。

推荐第一版先落地，因为它不新增时间字段到 CPU2；如联调要求严格对应 CPU2 实际开始动作，再升级为事件同步。

## 11. 版本和兼容性影响

| 改动项 | 是否影响 CPU2/CPU3 共享协议 | 是否影响参数存储 | 说明 |
| --- | --- | --- | --- |
| 新增 `CMD_SI7000_PROFILE` | 是 | 否 | 新增共享命令，必须升级 `DEVICE_PROTOCOL_VERSION` |
| CPU3 `00004` 改下发新命令 | 是 | 否 | 命令语义变化，需更新映射表和 golden frame |
| `10001/10010` 固定输出 | 否 | 否 | 只改 CPU3 SI7000 映射行为 |
| `10002/10003` 状态合成 | 否 | 否 | 第一版只按 CPU3 已有状态合成 |
| `40001~40013` 独立保持寄存器 | 视存储位置而定 | 可能 | 若仅 CPU3 持久化，影响 CPU3 本机参数；若 CPU2 执行需持久化，影响 CPU2 参数存储 |
| 自动 profile 调度 | 否 | 可能 | CPU3 调度本身不改共享协议，但参数持久化影响 CPU3 本机参数版本 |
| 报警限值全部兼容 | 视算法位置而定 | 可能 | 若只 CPU3 计算，影响 CPU3；若 CPU2 生成 profile 偏差状态，可能影响共享字段 |
| profile 开始时间戳 | 否或是 | 否 | CPU3 下发时锁存不改协议；若改为 CPU2 start 事件则影响共享协议 |

实施时建议拆成两个提交或两个阶段：

1. 协议映射和 CPU3 独立参数/调度阶段：先完成 `10001/10010/10002/10003`、`40010~40013`、时间戳和当前值报警。
2. CPU2 独立 SI7000 profile 阶段：新增命令、独立流程、Point 0、探底频次、profile 点阵和偏差报警。

## 12. 验证计划

### 12.1 静态检查

- `py tools\check_si7000_modbus_frames.py`
- `py tools\check_si7000_protocol_contract.py`
- 如果新增命令或共享字段，扩展检查脚本覆盖命令号、字段顺序和协议版本。
- 如果改 CPU2 参数存储，增加或更新参数版本检查，并明确升级是否恢复出厂参数。

### 12.2 协议帧验证

| 项目 | 验证点 |
| --- | --- |
| `10001` | 任意状态读取都为 `0` |
| `10010` | 任意状态读取都为 `0` |
| `10002/10003` | 液位跟随时 `10002=1,10003=0`；其它状态 `10002=1,10003=1` |
| `40001~40003` | 写入后可回读，且不改变普通分布测量参数 |
| `40010~40013` | 合法值可写可回读，非法小时/分钟/使能值返回异常 |
| 自动 profile | 到点后下发 SI7000 profile，忙或故障时不误触发 |
| `30007~30010` | 显示 profile 开始时间，而不是完成时间 |
| 报警限值 | 当前值报警、profile 上下限报警、profile 偏差报警均按限值置位和恢复 |

### 12.3 测量流程验证

1. 探底频次为 `0`：执行 profile 时不探底，但运行到底部位置采集 Point 0。
2. 探底频次为 `1`：每次 profile 前探底，然后采集 Point 0。
3. 探底频次为 `N`：前 `N-1` 次不探底，第 `N` 次探底，计数清零。
4. 不探底时不能刷新内部底部参考，只能使用已有参考运行到底部测量位置。
5. 第 0 点必须写入 `30021~30023` 对应的第一组三元组。
6. `40001` 对应 Point 0 之后的首个停点，不能覆盖 Point 0。
7. profile 失败时不置 `10005 Profile Complete`，也不递增完成计数。

## 14. 待实现前确认项

当前需求已经明确大方向，但实现前仍建议确认以下细节：

1. SI7000 探底频次默认值使用 `0` 还是 `1`。
2. 不探底时的“底部位置”使用已有底部参考、罐高/盲区，还是新增 SI7000 底部偏移参数。
3. `40010 = 0` 时，自动 profile 是禁用周期只按每日时刻触发，还是完全不触发。
4. `40014~40023` 是否必须掉电保存。
5. 报警限值参数是否允许只在 CPU3 存储，还是必须让 CPU2 侧也可见。
6. 自动 profile 到点但设备忙时，是跳过本次、延后到空闲立即执行，还是等待下一个周期。
7. profile 完成后是否自动回到液位跟随。
