# SI7000下一轮需求确认表

日期：2026-05-19

本文从 `SI7000下一步工作计划.md` 和 `SI7000说明书需求确认清单.md` 中抽取下一轮真正会影响代码行为、参数存储、PLC 联调或现场动作的确认项。请在“确认结论”列填写选项字母或直接写结论；暂时无法确认的项可以填写“暂缓”，我会按“未确认默认处理”执行。

## 填写说明

- `P0`：下一轮代码修改前必须先确认，否则容易返工或误动硬件流程。
- `P1`：决定兼容深度和现场体验，可在 P0 后确认。
- `P2`：属于扩展能力或优化项，可后续单独排期。
- 如选择“新增参数、扩展寄存器、真实调度、菜单校时”等，会额外涉及版本、参数存储、协议文档和联调测试。

## 建议回复格式

你可以直接按下面格式回复：

```text
P0-01=A
P0-02=A
P0-03=需要转换，40001 是从罐底向上第一个停点，单位 mm
P0-04=A
P0-05=B
P0-06=B
P0-07=A
P0-08=A

P1-01=C
P1-02=C
...
```

如果某项暂时不确定，可以写：

```text
P1-09=暂缓，先保持影子回读
```

## 确认后的开发动作

收到确认后，下一轮按以下顺序落地：

1. 把 P0 结论同步到 `SI7000兼容映射表.md` 和 PLC 联调表。
2. 扩展 `tools/check_si7000_modbus_frames.py`，先补真实状态快照、缩放边界和报警合成测试。
3. 如需要真实状态源，在 CPU2 增加通用状态或 profile 生命周期事件，再由 CPU3 映射到 SI7000。
4. 如需要参数落盘或自动调度，在 CPU3 增加 SI7000 专用参数、默认值、升级兼容和 RTC 调度。
5. 更新 `SI7000下一步工作计划.md`、`SI7000后续需求记录.md`、协议映射表和联调检查表。
