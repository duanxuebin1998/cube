# SI7000官方资料整理与兼容计划

日期：2026-05-16

本文基于 Scientific Instruments 官方公开资料整理 SI7000 测量流程、DCS Modbus 通信协议和当前设备的下一步兼容改动计划。当前目标仍保持“CPU3 做 SI7000 协议转换，CPU2 只补通用变量和通用命令”的方案，不把 SI7000 地址、线圈或功能码语义下沉到 CPU2。

下一轮详细执行计划见：`docs/01_协议与寄存器/SI7000协议适配/01_计划与需求/SI7000下一步工作计划.md`。

## 2. 测量流程整理

### 2.1 Auto 模式

- Auto 是日常运行模式，控制探头定位并跟踪液/气界面。
- SI7000 依赖上下两个液位传感器判断界面：下传感器在液体中、上传感器在气相中时认为探头在液位界面。
- Auto 模式下允许上报报警，自动 profile 调度也可以启动。
- Profile 或 Cal 完成后应回到 Auto。

对当前设备的影响：

- `probe_at_liquid_level` 不能只表示“最近有液位值”，应尽量表示“当前探头确实位于液面附近”。
- `10002 Lower Level Sensor`、`10003 Upper Level Sensor` 是 SI7000 液位判断核心状态，当前固定 0 只能作为第一版兼容，后续需要 CPU2 或硬件提供等价状态。

### 2.2 Cal 模式

- Cal 会驱动探头到罐底，重新建立 bottom reference，然后回到液位界面并切回 Auto。
- 断电后 SI7000 认为探头可能被人工移动，当前探头位置会标记为未校准，必须重新探底后才可信。

对当前设备的影响：

- `10001 Bottom Reference` 应代表罐底参考已建立。
- `10010 Probe Un-calibrated` 应代表位置参考不可信，不能仅按普通错误码合成。
- CPU2 需要明确“探底完成且位置基准可信”的通用状态，CPU3 再映射到 SI7000。

### 2.3 Profile 模式

- Profile 启动后先到罐底并重新建立 bottom reference。
- 在罐底稳定等待后采集第 0 点的位置、温度和密度。
- 随后按 First Point、Increment、Dwell Time 逐点上行采集温度和密度。
- Profile 在达到最大点数或找到液位时结束。
- 结束后分析 profile 数据并生成报警，然后返回 Auto。
- SI7000 DCS 规范中 `40001 Profile First Point` 是从罐底向上后的第一个编程停点；第 0 点始终是罐底点。

对当前设备的影响：

- 当前 `40001` 映射到 `spreadTopLimit` 只是第一版近似，必须确认它是否等同于 SI7000 的“罐底之后第一停点”。
- Profile 时间戳官方语义更接近“首个 profile 点采集时间”，当前 CPU3 按 `profile_complete_counter` 完成时刻锁存，后续建议改为由 CPU2 提供 profile 开始/首点采集事件。
- 新 profile 到达罐底并开始采集时，应清除旧 profile 数据和 `Profile Complete`；当前 CPU3 主要通过“未完成不输出点阵”避免旧数据泄漏，后续可补更明确的生命周期状态。

### 2.4 Manual 模式

- Manual 用于维护，允许 Stop、Up Slow、Up Medium、Up Fast、Down Slow、Down Medium、Down Fast。
- 在 Manual 模式下不报告报警，液位读数不更新。
- 下发方向或速度命令会停止 profile 或液位跟踪，并让系统进入 Manual，直到再次下发 Auto、Cal 或 Profile。

对当前设备的影响：

- 当前三档速度都桥接为 CPU2 统一上/下行命令，后续要确认 PLC 是否要求实际速度差异。
- CPU2 已有部分 manual/report 抑制思路，但需要复核所有报警位和 `30004 Liquid Level` 是否都满足 Manual 期间不更新的要求。

### 2.5 上电流程

- SI7000 以罐底为位置参考，上电后需要重新建立 bottom reference。
- 可配置为上电后自动探底再回液面，也可配置为 Manual 停止状态。

对当前设备的影响：

- 若现场 PLC 按 SI7000 习惯判断 `Probe Uncal`，当前设备上电、探底、找液面之间的状态切换必须清晰。
- 需要确认当前设备上电后是否要模拟 SI7000 的自动探底行为，还是维持现有启动流程，仅通过状态位提示未校准。

## 3. 通信协议整理

### 3.1 串口和站号

| 项目 | SI7000 官方资料要求 |
| --- | --- |
| 物理层 | RS-485 |
| 协议 | Modbus RTU |
| 波特率 | 9600 |
| 数据格式 | 8 data bits、Odd parity、1 stop bit |
| 从站地址 | Device ID 等同 Tank ID，同一总线唯一 |

当前 CPU3 已在选择 `COM_PROTO_SI7000` 时锁定 `9600 8O1`，站号优先复用现有 `SlaveAddress`。后续需确认现场 Tank ID 是否必须独立配置。

### 3.2 支持功能码

| 功能码 | 用途 | 当前适配方向 |
| --- | --- | --- |
| `FC01` | 读线圈，读取模式和手动方向/速度 | CPU3 从影子状态和 CPU2 运行状态合成 |
| `FC02` | 读离散输入，读取状态和报警 | CPU3 从 CPU2 通用状态、阈值和影子参数合成 |
| `FC03` | 读保持寄存器，读取 profile 参数和报警设定 | `40001~40003` 桥接 CPU2 现有分布参数，`40010~40023` 影子回读 |
| `FC04` | 读输入寄存器，读取实时值、当前时间和 profile 数据 | CPU3 做单位缩放、时间锁存和点阵边界保护 |
| `FC05` | 写单线圈，切换模式或手动动作 | CPU3 转为 CPU2 通用命令 |
| `FC06` | 写单保持寄存器，设置 profile/报警参数 | 部分桥接，部分影子保存并做基础值域校验 |

### 3.3 线圈要点

| 地址 | 含义 | 兼容要点 |
| --- | --- | --- |
| `00001` | Manual | 模式线圈互斥；Manual 下报警和液位更新需抑制 |
| `00002` | Calibrate | 对应重新探底并回液面 |
| `00003` | Auto | 对应液位跟踪/找液面 |
| `00004` | Profile | 对应分布/profile 测量 |
| `00009` | Stop | 停止手动动作 |
| `00010~00012` | Up Slow/Medium/Fast | 当前统一桥接上行，速度差异待确认 |
| `00013~00015` | Down Slow/Medium/Fast | 当前统一桥接下行，速度差异待确认 |

### 3.4 离散输入要点

| 地址 | 含义 | 官方语义对当前适配的要求 |
| --- | --- | --- |
| `10001` | Bottom Reference | 罐底参考已建立，位置基准可信 |
| `10002` | Lower Level Sensor | 下液位传感器在液体中 |
| `10003` | Upper Level Sensor | 上液位传感器在液体中 |
| `10004` | Interlock | 最大允许探头位置/上限保护，不宜用所有错误泛化 |
| `10005` | Profile Complete | 新 profile 开始时清除，完成后置位 |
| `10006` | Unit Is Metric | 当前固定公制 |
| `10009` | Reel Alarm | 机械卷筒/驱动异常，建议细分电机或卷筒类错误 |
| `10010` | Probe Un-calibrated | 位置参考不可信 |
| `10012` | Interval Timer | 自动 profile 使能或调度状态 |
| `10013` | Probe At Liquid Level | Auto 且探头在液/气界面 |
| `10017~10024` | 当前密度、温度、液位报警 | 由当前值和 `40014~40021` 阈值合成 |
| `10025~10026` | Profile 温度/密度偏差报警 | 需要按相邻 profile 点偏差阈值实现 |
| `10029~10032` | Profile 温度/密度上下限报警 | 由完成后的 profile 点与阈值合成 |

### 3.6 输入寄存器要点

| 地址 | 含义 | 缩放或时序 |
| --- | --- | --- |
| `30001` | 当前探头位置 | level 类寄存器按 mm 输出 |
| `30002` | 当前温度 | 有符号，单位 `0.01°C` |
| `30003` | 当前密度 | 无符号，单位 `0.01 kg/m3` |
| `30004` | 液位 | 最近有效液位；Manual 或 profile 期间是否保持需确认 |
| `30006` | Profile 点数 | 最近完成 profile 的有效点数 |
| `30007~30010` | Profile 时间戳 | 官方语义更接近首点采集时间 |
| `30011~30013` | 当前时/分/秒 | 应持续变化，可用于主站判断通信活性 |

资料中存在一个兼容性细节：DCS Modbus 地址表只覆盖 `30021~30620`，即 200 个 profile 点；资料文字又提到更高的内部点数，产品页也标注 profile points `250+`。当前代码按 DCS 地址表输出 200 点是合理的第一版，但现场若要求更多点，需要和 PLC 侧另定扩展地址或分页机制。

## 4. 当前实现与官方资料的主要差距

| 优先级 | 差距 | 建议方向 |
| --- | --- | --- |
| P0 | `10002/10003` 上下液位传感器当前没有真实来源 | 确认硬件信号或 CPU2 等价状态，新增通用字段 |
| P0 | `40001` 是否等同现有 `spreadTopLimit` 不确定 | 按“罐底之后第一停点”重新核对分布测量方向和边界 |
| P0 | Profile 时间戳当前锁存在完成时刻 | CPU2 增加 profile 开始/首点采集事件，CPU3 按首点时间锁存 |
| P0 | Profile 点 0 必须是罐底点 | 核对 CPU2 当前点阵第 0 点来源，必要时调整输出快照 |
| P1 | Manual 期间报警和液位更新需要完全抑制 | 补完整状态抑制规则和回归用例 |
| P1 | Interlock/Reel Alarm/Probe Uncal 语义仍偏简化 | CPU2 增加通用故障分类和位置基准状态 |
| P1 | `40010~40013` 自动 profile 调度未实现 | 确认由 CPU3 调度还是 CPU2 调度，再实现通用命令触发 |
| P1 | `40014~40023` 设定点未落盘 | 确认是否掉电保存，优先做 CPU3 SI7000 专用参数 |
| P1 | 当前 RTC 默认时间和长期精度不足 | 增加菜单校时、PLC 校时或 LSE 硬件确认 |
| P2 | 协议诊断和主机帧测试不足 | 增加 CRC、地址、功能码、边界、缩放和报警合成测试 |
| P2 | SI7000 单文件模块较大 | 有 golden frame 后再拆分地址表、缩放、快照、功能码和诊断 |

## 5. 下一步改动计划

### 阶段 0：需求确认

1. 确认 Tank ID 是否等同现有 `SlaveAddress`，是否需要 SI7000 专用地址参数。
2. 确认现场是否有上下液位传感器、顶端限位、卷筒/驱动报警可接入 CPU2。
3. 确认 `40001~40003` 与当前分布测量参数的方向、单位、边界是否一致。
4. 确认 PLC 是否接受密度 `0.01 kg/m3` 的 16 位范围限制。
5. 确认 profile 点数只按 DCS 表 200 点兼容，还是需要扩展到 250+ 或更多。
6. 确认自动 profile 调度、报警阈值和 RTC 校时是否要求掉电保存。

### 阶段 1：验证基线

1. 建立 SI7000 golden frame 测试，覆盖 `FC01/02/03/04/05/06`。
2. 增加 CPU2/CPU3 共享协议静态检查，避免 `SI7000 状态字段` 字段和寄存器偏移漂移。
3. 用官方资料整理一份 PLC 联调检查表，明确每个地址的正常值、边界值和异常响应。

### 阶段 2：CPU2 通用状态补齐

1. 新增或细化 lower/upper level sensor 等价状态。
2. 新增 top/interlock、reel/drive alarm、probe uncal/bottom reference 的通用状态来源。
3. 明确 Manual 期间液位和报警抑制标志。
4. 增加 profile 生命周期事件：开始、到罐底、第 0 点采集、完成、清除旧数据。
5. 如需要三档手动速度，新增通用速度命令或速度参数。

### 阶段 3：CPU3 SI7000 转换层优化

1. 按 CPU2 新状态重映射 `10002/10003/10004/10009/10010/10013`。
2. Profile 快照按官方生命周期处理：新 profile 开始清旧数据，首点采集锁时间戳，完成后置 `10005`。
3. `40010~40023` 做 SI7000 专用参数结构，确认后落盘。
4. 自动 profile 若放在 CPU3，则由 CPU3 RTC 到点后发通用 profile 命令，并记录调度状态。
5. 增加协议诊断计数和最后一次异常摘要，便于现场定位 PLC 帧问题。

### 阶段 4：现场联调

1. 用 PLC 或主机工具验证 `9600 8O1`、站号、CRC 和异常响应。
2. 验证 Auto、Cal、Profile、Manual、Stop、Up/Down 线圈互斥和状态回读。
3. 验证上电、探底、找液面、profile 开始、profile 完成、Manual 抑制等关键时序。
4. 验证当前值、profile 点阵、时间戳、当前时间和报警阈值合成。
5. 输出现场测试记录，决定是否把 P1/P2 优化继续合入。

## 6. 推荐方案结论

当前“CPU3 做协议转换、CPU2 只补通用变量和通用命令”的方案仍是更稳妥的方向。原因是 SI7000 的地址表、功能码、缩放、影子参数和异常响应都是外部协议细节，放在 CPU3 可以避免污染 CPU2 测量核心；CPU2 只需要把真实测量状态、通用命令和生命周期事件表达清楚。

后续真正需要改强的是 CPU2/CPU3 的中性状态契约，而不是把 SI7000 逻辑搬进 CPU2。特别是上下液位传感器、罐底参考、顶端限位、卷筒报警、Manual 抑制、profile 首点事件这几类信息，应作为通用状态暴露给 CPU3，再由 CPU3 生成 SI7000 协议响应。
