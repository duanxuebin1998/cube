# SI7000说明书需求确认清单

日期：2026-05-16

本文根据 SI7000 官方操作手册和 DCS Modbus 资料包整理，需要用户、PLC 侧或现场硬件侧进一步确认的需求。本文只记录待确认口径，不直接修改固件代码。

资料依据：

- `docs/01_协议与寄存器/SI7000协议适配/00_原始资料/SI7000官方操作手册.pdf`
- `docs/01_协议与寄存器/SI7000协议适配/00_原始资料/SI7000官方资料包_含Modbus规范.pdf`
- `docs/01_协议与寄存器/SI7000协议适配/01_计划与需求/SI7000官方资料整理与兼容计划.md`

## 1. 最先需要你确认的结论

下面这些是下一轮代码落地前最关键的确认项，建议先确认 P0，再确认 P1。

| 优先级 | 确认项 | 需要你给出的结论 | 不确认时的默认处理 |
| --- | --- | --- | --- |
| P0 | Tank ID 是否等同当前从站地址 | 使用现有 `SlaveAddress`，还是新增 SI7000 专用 Tank ID | 继续复用 `SlaveAddress` |
| P0 | 上下液位传感器来源 | 现场是否有 Lower/Upper 传感器，CPU2 是否能提供等价状态 | `10002/10003` 继续返回 0 |
| P0 | Profile 参数方向和边界 | `40001` 是否是“罐底之后第一个停点”，是否能映射 `spreadTopLimit` | 保持当前第一版映射，但标记风险 |
| P0 | Profile 第 0 点语义 | 当前分布测量点阵第 0 点是否必须改成罐底点 | 不调整点阵语义，只按当前数据输出 |
| P0 | Profile 时间戳语义 | 时间戳按首点采集时间，还是接受当前完成时间 | 当前按完成时刻锁存 |
| P0 | 密度缩放范围 | PLC 是否接受 `0.01 kg/m3` 且最大 `655.35 kg/m3` | 超范围继续钳位到 `65535` |
| P1 | Manual 模式抑制 | Manual 期间是否必须完全停止报警上报和液位更新 | 按当前已有抑制逻辑，后续再复核 |
| P1 | 自动 profile 调度 | `40010~40013` 是否需要真实触发自动 profile | 继续影子回读，不触发测量 |
| P1 | 报警阈值是否落盘 | `40014~40023` 是否掉电保存 | 继续运行期影子寄存器 |
| P1 | RTC 校时 | 是否需要菜单校时、PLC 校时或 LSE 硬件 | 继续使用 CPU3 LSI RTC 和默认时间 |

## 2. 通信和站号

### 2.1 Tank ID 与 Modbus 从站地址

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | DCS Modbus 规范中 Device ID 等同 Tank ID，且同一 RS485 总线上必须唯一 |
| 关联点位 | Modbus RTU 从站地址 |
| 当前处理 | CPU3 SI7000 层优先使用现有 `SlaveAddress`，无效时使用 SI7000 默认地址 |
| 需要确认 | 现场 PLC 的 Tank ID 是否就是当前设备从站地址；是否要求每个 SI7000 协议口独立配置 Tank ID |
| 可选口径 | A. 复用现有 `SlaveAddress`；B. 新增 CPU3 本机 SI7000 Tank ID 参数；C. 由 PLC 固定只访问一个地址 |
| 建议默认 | A，除非现场明确要求 SI7000 地址独立于其它协议地址 |
| 确认后改动 | 若选 B，需要新增 CPU3 参数、参数默认值、菜单或配置入口、地址校验和文档 |

### 2.2 串口物理层和请求节奏

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | RS485、Modbus RTU、9600、8 data bits、Odd parity、1 stop bit |
| 关联点位 | 全部 SI7000 请求 |
| 当前处理 | 选择 `COM_PROTO_SI7000` 后锁定 `9600 8O1` |
| 需要确认 | PLC 是否完全按 `9600 8O1`；请求间隔是否能满足现场建议的低频轮询 |
| 可选口径 | A. 严格锁定 `9600 8O1`；B. 保留可配置但默认 `9600 8O1`；C. 增加请求频率诊断 |
| 建议默认 | A，同时增加诊断统计，不主动丢弃合法请求 |
| 确认后改动 | 如选 C，CPU3 增加请求计数、CRC 错误、地址不匹配和非法帧统计 |

## 3. 测量流程

### 3.1 上电后的探底和校准

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | SI7000 以上次罐底参考作为位置基准，上电后需要重新建立 bottom reference；也可配置为 Manual 停止 |
| 关联点位 | `10001 Bottom Reference`、`10010 Probe Un-calibrated`、`30001 Current Probe Position` |
| 当前处理 | 当前设备按既有启动流程，不强制模拟 SI7000 上电自动探底；CPU3 仅映射已有状态 |
| 需要确认 | 上电后是否必须自动探底并回液面，还是只提示未校准，等待 PLC 下发 Cal/Auto |
| 可选口径 | A. 维持现有启动流程；B. 上电进入未校准状态，等待 PLC 命令；C. 上电自动执行探底/校准 |
| 建议默认 | B，比 C 更安全，避免上电自动动作带来现场风险 |
| 确认后改动 | 选 B 需要强化 `Probe Un-calibrated` 状态；选 C 需要设计启动互锁、电机动作条件和取消策略 |

### 3.2 Auto 模式和液位界面判断

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | Auto 模式通过 Lower/Upper 两个液位传感器判断探头是否在液/气界面 |
| 关联点位 | `00003 Auto`、`10002`、`10003`、`10013 Probe At Liquid Level`、`30004 Liquid Level` |
| 当前处理 | `10013` 由 CPU2 通用状态合成，`10002/10003` 无可靠来源时返回 0 |
| 需要确认 | 当前设备是否有上下液位传感器；若没有，是否允许用现有液位稳定、找液面状态做等价映射 |
| 可选口径 | A. 有真实硬件，CPU2 发布真实状态；B. 无硬件但允许等价状态；C. 无硬件且不做推测，固定 0 |
| 建议默认 | C，除非现场确认有可靠等价来源 |
| 确认后改动 | 选 A/B 需要 CPU2 新增中性字段，CPU3 再映射到 `10002/10003` |

### 3.3 Calibrate 模式

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | Calibrate 驱动探头到罐底，建立 bottom reference，然后返回液位界面并回 Auto |
| 关联点位 | `00002 Calibrate`、`10001`、`10010`、`10013` |
| 当前处理 | 当前桥接到已有探底/校准类命令，状态位按现有 CPU2 状态合成 |
| 需要确认 | PLC 侧是否要求 Cal 完成后必须自动回到 Auto；失败时是否保持 Manual/Cal 状态还是进入错误状态 |
| 可选口径 | A. 完成后回 Auto；B. 完成后保持当前状态等待 PLC；C. 失败后只置报警不改变模式 |
| 建议默认 | A，贴近说明书 |
| 确认后改动 | 需要 CPU2/CPU3 明确 Cal 开始、完成、失败和回 Auto 的状态转换 |

### 3.4 Manual 模式

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | Manual 下不报告报警，液位不更新；下发 Up/Down/Stop 会停止 profile 或液位跟踪并进入 Manual |
| 关联点位 | `00001`、`00009~00015`、`10017~10032`、`30004` |
| 当前处理 | 三档速度统一桥接到 CPU2 上/下行命令，已有部分 Manual 抑制字段 |
| 需要确认 | PLC 是否要求 Manual 期间所有报警位都不上报；`30004` 是否必须保持进入 Manual 前的最后液位 |
| 可选口径 | A. 严格按说明书抑制报警和液位更新；B. 保留故障类报警；C. 只抑制液位相关报警 |
| 建议默认 | A，但设备安全类故障仍应在本机内部保留，不能影响停机保护 |
| 确认后改动 | CPU2 细化 `manual_alarm_inhibit`、`manual_level_update_inhibit`；CPU3 统一屏蔽对应 SI7000 报警位和液位刷新 |

### 3.5 手动速度档位

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | Manual 支持 Up/Down Slow、Medium、Fast 三档 |
| 关联点位 | `00010~00015` |
| 当前处理 | Slow/Medium/Fast 暂时都桥接为统一上行或下行 |
| 需要确认 | PLC 和现场是否需要真实三档速度差异 |
| 可选口径 | A. 不需要，三档只表示方向；B. 需要三档固定速度；C. 需要三档速度可配置 |
| 建议默认 | A，除非现场明确使用三档维护速度 |
| 确认后改动 | 选 B/C 需要 CPU2 新增通用速度命令或速度参数，CPU3 只做线圈转换 |

## 4. Profile 测量

### 4.1 Profile 点 0 和 First Point 语义

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | Profile 第 0 点始终是罐底点，`40001 Profile First Point` 是罐底之后的第一个编程停点 |
| 关联点位 | `40001`、`30006`、`30021~30023` |
| 当前处理 | `40001` 桥接到 `spreadTopLimit`，profile 点阵来自当前分布测量结果 |
| 需要确认 | 当前分布测量的第一个点是否已经是罐底点；`spreadTopLimit` 是否等同“罐底之后第一停点” |
| 可选口径 | A. 当前点阵已满足，不改；B. 需要 CPU2 调整点阵，第 0 点固定罐底；C. CPU3 输出时重排/补罐底点 |
| 建议默认 | 先确认 CPU2 真实点阵，优先选 B，不建议 CPU3 凭空补点 |
| 确认后改动 | 需要修正 profile 生命周期、点阵输出、`40001` 参数解释和 PLC 联调表 |

### 4.2 Profile 时间戳

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | Profile 时间戳用于标记 profile 数据采集时间，更接近第一个 profile 点采集时刻 |
| 关联点位 | `30007~30010` |
| 当前处理 | CPU3 在 `profile_complete_counter` 变化时锁存完成时刻 |
| 需要确认 | PLC 是否要求严格按首点采集时间，还是接受完成时刻 |
| 可选口径 | A. 接受完成时刻；B. 改为首点采集时刻；C. 同时记录首点和完成时间，SI7000 只输出首点时间 |
| 建议默认 | B，贴近说明书 |
| 确认后改动 | CPU2 增加 profile 首点采集事件或时间戳触发计数，CPU3 按事件锁存 |

### 4.3 新 Profile 开始时清旧数据

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | 新 profile 到罐底并开始采集时，旧 profile 数据和 Profile Complete 应被清除 |
| 关联点位 | `10005`、`30006`、`30021~30620` |
| 当前处理 | CPU3 在未完成时不输出点阵，减少旧数据泄漏，但未完整表达“已清除”生命周期 |
| 需要确认 | PLC 是否依赖新 profile 开始后立即看到 `10005=0` 和点阵清零 |
| 可选口径 | A. 需要严格清除；B. 只要未完成不输出即可；C. 需要数据已读/清除握手 |
| 建议默认 | A，不新增握手，除非 PLC 明确需要 |
| 确认后改动 | CPU2 发布 profile start/clear 事件，CPU3 清除快照并更新 `10005` |

### 4.4 Profile 点数上限

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | DCS Modbus 地址表暴露 `30021~30620`，即 200 个点；资料中另有 250+ 或更高点数描述 |
| 关联点位 | `30006`、`30021~30620` |
| 当前处理 | CPU3 按 200 点地址表输出，超过范围返回 0 |
| 需要确认 | PLC 是否只读取官方 DCS 表 200 点，还是要求 250+ 或更多点 |
| 可选口径 | A. 固定兼容 200 点；B. 扩展私有地址；C. 做分页机制 |
| 建议默认 | A，避免破坏官方地址表 |
| 确认后改动 | 选 B/C 需要新增扩展协议文档、PLC 联调表和地址冲突检查 |

### 4.5 Profile 参数和 Dwell Time

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | `40001` First Point、`40002` Increment、`40003` Dwell Time 控制 profile 停点和停留采样 |
| 关联点位 | `40001~40003` |
| 当前处理 | 分别桥接 `spreadTopLimit`、`spreadMeasurementDistance`、`spreadPointHoverTime` |
| 需要确认 | 单位、方向、上下限、写入后是否立即保存，以及写入时是否需要影响当前正在运行的 profile |
| 可选口径 | A. 完全复用现有参数；B. 新增 SI7000 专用参数再转换；C. 写入仅影响下一次 profile |
| 建议默认 | C，同时优先确认 A 是否成立 |
| 确认后改动 | 可能涉及 CPU2 参数、CPU3 写寄存器、参数保存和运行中互锁 |

## 5. 报警和状态位

### 5.1 Reel Alarm

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | Reel Alarm 表示卷筒、机械驱动或探头运动相关异常 |
| 关联点位 | `10009` |
| 当前处理 | 当前第一版按设备错误简化合成 |
| 需要确认 | 哪些本设备错误码属于 Reel Alarm，哪些不应映射到 `10009` |
| 可选口径 | A. 只映射电机/卷筒/运动类错误；B. 映射所有设备错误；C. 由 PLC 只看本机错误码，不依赖 `10009` |
| 建议默认 | A |
| 确认后改动 | CPU2 增加通用故障分类，CPU3 按分类映射 |

### 5.2 Probe Un-calibrated

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | Probe Un-calibrated 表示位置参考不可信，常见于上电后或探底/校准失败后 |
| 关联点位 | `10010` |
| 当前处理 | 当前按零点状态简化合成 |
| 需要确认 | 哪些状态应判定为未校准：上电未探底、探底失败、罐高未校准、液位未找到、编码器异常 |
| 可选口径 | A. 只看罐底参考；B. 罐底参考加位置/编码器可信；C. 还包括液位/罐高校准状态 |
| 建议默认 | B |
| 确认后改动 | CPU2 增加位置基准可信字段，CPU3 映射 `10010` |

### 5.3 Interlock

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | Interlock 更接近最大允许探头位置、上限位或机械互锁 |
| 关联点位 | `10004` |
| 当前处理 | 第一版语义仍需细化，不能长期泛化为所有错误 |
| 需要确认 | 当前设备是否有顶端限位、最大位置保护、维护互锁或外部联锁输入 |
| 可选口径 | A. 映射顶端/最大位置保护；B. 映射外部互锁输入；C. 无数据源时固定 0 |
| 建议默认 | C，直到硬件来源明确 |
| 确认后改动 | CPU2 增加 top/interlock 通用状态，CPU3 映射 `10004` |

### 5.4 当前值报警和 Profile 报警

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | `10017~10024` 是当前密度/温度/液位报警，`10025/10026` 是 profile 偏差报警，`10029~10032` 是 profile 上下限报警 |
| 关联点位 | `10017~10026`、`10029~10032`、`40014~40023` |
| 当前处理 | 当前值和部分 profile 上下限可由影子阈值合成，偏差算法仍待补 |
| 需要确认 | 阈值是否由 PLC 下发；是否掉电保存；偏差报警按相邻点差值、相对首点、还是相对平均值 |
| 可选口径 | A. PLC 写阈值并掉电保存；B. PLC 写阈值但不保存；C. 阈值来自本机参数；D. 不启用偏差报警 |
| 建议默认 | A 或 B，偏差算法需 PLC 明确 |
| 确认后改动 | CPU3 专用参数、报警合成算法、profile 完成后扫描逻辑和测试用例 |

## 6. 保持寄存器和参数保存

### 6.1 `40010~40013` 自动 Profile

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | SI7000 支持自动 profile 间隔、使能、小时和分钟 |
| 关联点位 | `40010~40013`、`10012` |
| 当前处理 | CPU3 影子保存并回读，未真实调度 profile |
| 需要确认 | 是否需要 CPU3 到点自动发起 profile；自动 profile 与当前测量、Manual、错误状态如何互斥 |
| 可选口径 | A. 不启用真实调度，只回读；B. CPU3 调度，CPU2 执行通用命令；C. CPU2 调度 |
| 建议默认 | B，如果现场确实需要自动 profile |
| 确认后改动 | CPU3 RTC 调度、互斥检查、`10012` 状态、参数落盘和联调测试 |

### 6.2 `40014~40023` 参数落盘

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | 这些寄存器是报警阈值和 profile 偏差阈值 |
| 关联点位 | `40014~40023` |
| 当前处理 | 运行期影子寄存器，掉电不保存 |
| 需要确认 | PLC 写入后是否必须掉电保存；是否允许本机菜单修改同一组阈值 |
| 可选口径 | A. 掉电保存为 CPU3 SI7000 专用参数；B. 只运行期有效；C. 映射到现有报警参数 |
| 建议默认 | A，不建议 C，避免影响其它协议 |
| 确认后改动 | CPU3 参数结构、默认值、升级兼容、写入校验和文档 |

## 7. 时间和校时

### 7.1 当前时间

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | `30011~30013` 当前时分秒可用于主站判断通信活性 |
| 关联点位 | `30011~30013` |
| 当前处理 | CPU3 LSI RTC 输出当前时间，默认初始化时间不代表真实时间 |
| 需要确认 | PLC 是否只要求时间递增，还是要求真实本地时间 |
| 可选口径 | A. 只要求递增；B. 要求本机菜单校时；C. 要求 PLC 远程校时；D. 要求硬件 LSE |
| 建议默认 | A 或 B，远程校时需要额外定义扩展寄存器 |
| 确认后改动 | 菜单校时、PLC 校时入口、LSE 切换或 RTC 失效诊断 |

### 7.2 Profile 时间戳来源

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | Profile 时间戳应对应 profile 数据采集时刻 |
| 关联点位 | `30007~30010` |
| 当前处理 | 完成时刻锁存 |
| 需要确认 | 与第 4.2 项一致：是否必须改为首点采集时刻 |
| 可选口径 | A. 完成时刻；B. 首点采集时刻 |
| 建议默认 | B |
| 确认后改动 | CPU2 profile 生命周期事件，CPU3 锁存策略 |

## 8. PLC 联调和扩展协议

### 8.1 PLC 读取范围和频率

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | DCS 规范定义固定线圈、离散输入、保持寄存器和输入寄存器范围 |
| 关联点位 | 全部地址 |
| 当前处理 | CPU3 对保留地址返回异常或 0，按当前实现处理 |
| 需要确认 | PLC 是否会读取说明书外的地址；是否会批量读取跨越保留区；请求频率是否高于现场建议 |
| 可选口径 | A. PLC 严格按说明书地址读写；B. 允许跨区批量读取，保留地址返回 0；C. 保留地址返回异常 |
| 建议默认 | A/C，保持 Modbus 行为明确 |
| 确认后改动 | 如选 B，需要调整保留地址处理和 golden frame 测试 |

### 8.2 是否需要本设备扩展寄存器

| 项目 | 内容 |
| --- | --- |
| 说明书依据 | 官方地址表没有定义校时、诊断计数、超过 200 点 profile 的扩展读法 |
| 关联点位 | 扩展地址待定 |
| 当前处理 | 不占用官方保留地址做私有扩展 |
| 需要确认 | PLC 是否需要读取协议诊断、远程校时或超过 200 点 profile |
| 可选口径 | A. 不扩展，只做官方兼容；B. 在非冲突地址做本设备扩展；C. 通过本机菜单/调试口处理 |
| 建议默认 | A，扩展必须单独出协议说明 |
| 确认后改动 | 新增扩展地址表、PLC 协议说明、异常响应和测试 |

## 9. 建议你的确认顺序

第一批先确认这些，确认后就能进入下一轮核心代码修改：

1. Tank ID 是否复用 `SlaveAddress`。
2. 是否有真实 Lower/Upper 液位传感器或等价 CPU2 状态。
3. `40001~40003` 是否能复用当前分布测量参数。
4. Profile 第 0 点是否必须为罐底点，当前点阵是否已经满足。
5. Profile 时间戳是否必须改为首点采集时间。
6. 密度 `0.01 kg/m3`、最大 `655.35 kg/m3` 是否可接受。

第二批确认这些，决定兼容深度和现场体验：

1. Manual 期间报警和液位更新是否严格抑制。
2. 三档手动速度是否需要真实速度差异。
3. `40010~40013` 是否真实触发自动 profile。
4. `40014~40023` 是否掉电保存。
5. `10009/10010/10004` 的报警和互锁语义。
6. RTC 是否需要真实时间、菜单校时、PLC 校时或 LSE。

第三批确认这些，决定是否做扩展：

1. Profile 是否需要超过官方 DCS 地址表的 200 点。
2. PLC 是否需要读取诊断计数。
3. PLC 是否会读取说明书以外地址或跨保留区批量读取。
4. 是否需要远程校时或其它本设备扩展寄存器。

## 10. 确认后的落地规则

- 凡是只影响 CPU3 外部协议映射的确认项，优先在 CPU3 SI7000 转换层处理。
- 凡是需要真实硬件状态、测量生命周期或错误分类的确认项，先在 CPU2 增加通用状态，再由 CPU3 映射。
- 凡是新增 CPU2/CPU3 共享字段、命令或语义，都要同步升级 `DEVICE_PROTOCOL_VERSION` 并更新 `docs/01_协议与寄存器/CPU2_CPU3协议变更记录.md`。
- 凡是新增 CPU3 参数或菜单，都要检查默认值、参数存储升级、中文显示字库和版本号。
- 凡是新增或改变 SI7000 地址行为，都要更新 `docs/01_协议与寄存器/SI7000协议适配/02_协议映射/SI7000兼容映射表.md` 和 golden frame 测试。
