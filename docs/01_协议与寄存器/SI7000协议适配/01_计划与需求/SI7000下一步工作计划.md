# SI7000下一步工作计划

日期：2026-05-16

本文是 SI7000 官方资料复核后的下一轮执行计划。计划目标是让当前设备更贴近 SI7000 官方测量流程和 DCS Modbus 语义，同时继续保持架构边界：CPU3 负责 SI7000 协议转换，CPU2 只提供通用状态、通用命令和真实测量生命周期事件。

本计划只定义下一步执行顺序和验收口径，不在本文档变更中直接修改固件代码。

下一轮可填写确认表详见：`docs/01_协议与寄存器/SI7000协议适配/01_计划与需求/SI7000下一轮需求确认表.md`。

说明书待确认需求完整依据详见：`docs/01_协议与寄存器/SI7000协议适配/01_计划与需求/SI7000说明书需求确认清单.md`。

## 1. 当前基线

当前分支已经具备第一版 SI7000 兼容能力：

- CPU3 已接入 SI7000 Modbus RTU 从站，支持 `FC01/FC02/FC03/FC04/FC05/FC06`。
- SI7000 串口参数已按官方资料锁定为 `9600 8O1`。
- CPU3 已具备本地 RTC 当前时间和 profile 时间戳输出能力。
- CPU2/CPU3 共享协议已新增 `SI7000 状态字段`，用于 CPU3 外部协议转换层读取通用状态。
- `40001~40003` 已桥接现有分布测量参数，`40010~40023` 当前为 SI7000 影子寄存器。
- 已记录官方资料差距：上下液位传感器、profile 首点时间戳、profile 第 0 点罐底语义、Manual 抑制、自动 profile 调度、报警语义细分和 RTC 校时。

## 2. 执行原则

- 不把 SI7000 地址、线圈、功能码、异常码和缩放细节放入 CPU2。
- CPU2 新增内容必须是其它协议也能理解的中性能力，例如位置基准可信、上下液位等价状态、顶端限位、卷筒/驱动报警、profile 生命周期事件。
- CPU3 负责把 CPU2 通用状态转换为 SI7000 的 `000xx/100xx/300xx/400xx` 地址语义。
- 每一阶段都先补验证或检查入口，再改代码；涉及共享协议字段时同步升级协议版本和版本文档。
- 未经 PLC 或现场确认的业务口径，只记录为待确认项，不擅自改变现有测量流程。

## 3. 总体路线

```text
需求确认
  -> 协议帧测试和共享协议检查
  -> CPU2 通用状态契约补齐
  -> CPU3 SI7000 映射和生命周期修正
  -> 参数持久化/自动调度/校时能力
  -> PLC 联调和现场验证
  -> 结构收敛和提交
```

## 4. 阶段 0：需求确认和冻结输入

目标：把会影响协议行为、参数存储和硬件动作的口径先确认，避免后续返工。

| 编号 | 事项 | 需要确认的问题 | 产出 |
| --- | --- | --- | --- |
| 0.1 | Tank ID | SI7000 的 Tank ID 是否等同当前 `SlaveAddress`，是否需要 CPU3 专用 SI7000 地址 | 地址策略结论 |
| 0.2 | 上下液位传感器 | 现场是否有下液位/上液位硬件，或 CPU2 是否能提供等价状态 | `10002/10003` 数据源结论 |
| 0.3 | 顶端限位和 Interlock | 是否有最大允许探头位置、上限位、机械互锁信号 | `10004` 数据源结论 |
| 0.4 | 卷筒/驱动报警 | 哪些错误码属于 Reel Alarm，哪些只是普通设备错误 | 错误分类表 |
| 0.5 | Profile 参数 | `40001` 是否等同“罐底之后第一个停点”，与 `spreadTopLimit` 的方向和边界是否一致 | 参数映射表 |
| 0.6 | Profile 点数 | PLC 是否只读取 DCS 表的 200 点，还是要求 250+ 或更多 | 点数兼容策略 |
| 0.7 | 密度缩放 | PLC 是否接受 `0.01 kg/m3` 且 16 位上限 `655.35 kg/m3` | 缩放和钳位策略 |
| 0.8 | 自动 profile | `40010~40013` 是否需要真实调度，调度放 CPU2 还是 CPU3 | 调度责任边界 |
| 0.9 | 报警设定 | `40014~40023` 是否需要掉电保存，阈值是否由 PLC 下发 | 持久化策略 |
| 0.10 | RTC 校时 | 是否需要菜单校时、PLC 远程校时或 LSE 硬件确认 | 时间策略 |

阶段 0 暂停条件：

- `40001~40003` 方向和边界无法确认时，不进入 profile 参数映射改动。
- 密度缩放范围无法确认时，不改变现有 `0.01 kg/m3` 输出和钳位策略。
- 上下液位硬件无法确认时，可以继续做测试和 CPU3 结构优化，但不把 `10002/10003` 从固定 0 改成推测值。

## 5. 阶段 1：验证基线先行

目标：先建立可重复验证入口，防止后续协议改动只靠人工读代码。

| 编号 | 任务 | 影响范围 | 验收标准 |
| --- | --- | --- | --- |
| 1.1 | 建立 SI7000 Modbus golden frame 测试 | CPU3 工具或测试目录 | 覆盖 `FC01/02/03/04/05/06` 正常响应 |
| 1.2 | 增加异常帧测试 | CPU3 协议层 | 覆盖非法功能码、非法地址、非法值、地址不匹配、CRC 错误 |
| 1.3 | 增加缩放边界测试 | CPU3 协议层 | 覆盖位置 mm、温度有符号、密度钳位、profile 点越界 |
| 1.4 | 增加报警合成测试 | CPU3 协议层 | 覆盖 `10017~10024`、`10029~10032` 阈值开关和边界 |
| 1.5 | 增加共享协议静态检查 | `tools` 或现有检查脚本 | 检查 CPU2/CPU3 `SI7000 状态字段` 字段、寄存器偏移和 `DEVICE_PROTOCOL_VERSION` 一致 |
| 1.6 | 整理 PLC 联调表 | `docs` | 每个关键地址都有读写示例、期望值和异常响应 |

当前执行状态：

- 已新增 `tools/check_si7000_modbus_frames.py`，用于检查 SI7000 功能码、地址表常量和主机侧参考帧。
- 已新增 `tools/check_si7000_protocol_contract.py`，用于检查 CPU2/CPU3 `SI7000 状态字段`、`REG_DEVICE_STATUS_*` / `REG_OIL_MEASUREMENT_*` / `REG_HEIGHT_MEASUREMENT_*` / `REG_DENSITY_DIST_*` 和协议版本一致性。
- 已新增 `docs/01_协议与寄存器/SI7000协议适配/04_联调测试/SI7000_PLC联调检查表.md`，用于 PLC/主机侧联调。
- 已新增 `docs/01_协议与寄存器/SI7000协议适配/03_改动记录/CPU2暂存区改动整理.md`，用于逐文件说明 CPU2 暂存区中的协议辅助状态、测量流程和兼容性影响。
- 未确认需求相关的行为变更仍未执行。

阶段 1 已完成基础入口，后续每次改 SI7000 协议层都至少运行：

```text
git diff --check
py tools/check_version_bumped.py
py tools/check_si7000_modbus_frames.py
py tools/check_si7000_protocol_contract.py
cmake --build build/LTD_MAIN_CPU2
cmake --build build/LTD_DISPLAY_CPU3
```

如本轮只改 CPU3 协议测试且不影响 CPU2，可说明 CPU2 构建是否跳过及原因。

## 6. 阶段 2：CPU2 通用状态契约补齐

目标：让 CPU2 发布真实、可复用的测量状态，不暴露 SI7000 专用地址语义。

| 编号 | 任务 | 建议字段或能力 | 验收标准 |
| --- | --- | --- | --- |
| 2.1 | 上下液位等价状态 | lower/upper level sensor equivalent | `10002/10003` 可由真实字段映射，不再长期固定 0 |
| 2.2 | 位置基准可信状态 | bottom reference valid、probe uncal | 探底前后、上电后、校准失败时状态清晰 |
| 2.3 | 顶端限位/互锁状态 | top limit、interlock | `10004` 只表示上限/互锁，不泛化为所有错误 |
| 2.4 | 卷筒/驱动报警分类 | reel alarm category | `10009` 只由机械卷筒、电机或驱动类错误合成 |
| 2.5 | Manual 抑制状态 | manual_alarm_inhibit、manual_level_update_inhibit | Manual 期间报警不上报、液位不更新 |
| 2.6 | Profile 生命周期事件 | start、bottom touched、point0 captured、complete、cleared | CPU3 可按首点采集时间锁存时间戳，按新 profile 清旧数据 |
| 2.7 | 手动速度能力 | slow/medium/fast speed or generic speed command | PLC 要求三档速度时，CPU2 有真实速度入口 |

协议版本判断：

- 如果只修 CPU2 内部状态但不改变共享结构和 CPU3 消费方式，不提升 CPU2/CPU3 共享协议。
- 如果新增 `SI7000 状态字段` 字段、共享寄存器或命令语义，必须同步提升 `DEVICE_PROTOCOL_VERSION`，更新 CPU2/CPU3 版本和 `docs/01_协议与寄存器/CPU2_CPU3协议变更记录.md`。

## 7. 阶段 3：CPU3 SI7000 映射修正

目标：把官方 SI7000 行为尽量收敛到 CPU3 协议转换层。

| 编号 | 任务 | 影响地址 | 验收标准 |
| --- | --- | --- | --- |
| 3.1 | 重映射上下液位传感器 | `10002/10003` | 来自 CPU2 真实或等价状态 |
| 3.2 | 重映射 Interlock/Reel/Uncal | `10004/10009/10010` | 不再用宽泛错误码代替精确语义 |
| 3.3 | 修正 profile 时间戳 | `30007~30010` | 由首点采集事件锁存，而不是完成时刻 |
| 3.4 | 修正 profile 清旧数据时序 | `10005/30006/30021~30620` | 新 profile 开始后清除旧完成态和旧点阵输出 |
| 3.5 | 确认 profile 点 0 语义 | `30021~30023` | 第 0 点为罐底点；`40001` 不被误当成第 0 点 |
| 3.6 | Manual 模式状态转换 | `00001/00009~00015/30004/10017~10032` | 下发手动动作后进入 Manual，停止液位/profile 跟踪，抑制报警和液位更新 |
| 3.7 | 当前时间可靠性 | `30011~30013` | 时间持续变化，失效时有可诊断状态或明确降级策略 |

阶段 3 不处理的事项：

- 不在 CPU3 中猜测没有 CPU2 数据源的硬件状态。
- 不把 SI7000 阈值写入 Wärtsilä 或 DSM 参数。
- 不直接扩展超过 DCS 表的 profile 点地址，除非 PLC 明确要求并给出扩展口径。

## 8. 阶段 4：参数持久化、自动调度和校时

目标：把运行期影子值逐步变成可维护的 SI7000 专用配置能力。

| 编号 | 任务 | 推荐位置 | 验收标准 |
| --- | --- | --- | --- |
| 4.1 | SI7000 专用参数结构 | CPU3 本机参数优先 | `40010~40023` 可按确认口径掉电保存 |
| 4.2 | 自动 profile 调度 | 优先 CPU3 RTC 调度，CPU2 执行通用 profile 命令 | `40010~40013` 能真实触发 profile，`10012` 能反映调度状态 |
| 4.3 | 报警阈值持久化 | CPU3 SI7000 参数 | 当前值和 profile 点报警掉电后仍按上次阈值合成 |
| 4.4 | RTC 校时入口 | 菜单或 PLC 扩展入口 | 现场可设置真实时间，重启后的降级策略清晰 |
| 4.5 | LSE/LSI 策略 | CPU3 时钟模块 | 无 LSE 时明确精度风险；有 LSE 时可切换并验证 |

版本和存储注意：

- 新增 CPU3 本机参数需要检查参数保存、默认值、升级兼容和菜单显示。
- 新增中文菜单或提示时必须同步检查 CPU3 字库。
- 若新增 PLC 校时寄存器，不应与官方 SI7000 保持寄存器冲突，建议作为本设备扩展并在文档中明确。

## 9. 阶段 5：现场联调和验收

目标：用 PLC 或主机工具验证官方协议关键路径。

| 场景 | 验收点 |
| --- | --- |
| 通信基础 | `9600 8O1`、Tank ID、CRC、异常响应、请求间隔 |
| 模式切换 | Manual、Cal、Auto、Profile 线圈互斥和回读一致 |
| 手动移动 | Stop、Up/Down Slow/Medium/Fast 动作、速度、Manual 状态和抑制行为 |
| 探底/校准 | Bottom Reference、Probe Uncal、Interlock 状态正确 |
| 液位跟踪 | Lower/Upper、Probe At Liquid Level、Liquid Level 更新时序正确 |
| Profile | 点 0 罐底、首点时间戳、完成态、点数、点阵越界清零 |
| 自动 profile | `40010~40013` 调度触发、`10012` 状态、完成后回 Auto |
| 报警 | 当前值报警、profile 上下限报警、profile 偏差报警、Manual 抑制 |
| 时间 | `30011~30013` 持续变化，校时后生效 |

现场输出：

- PLC 读写帧记录。
- 关键寄存器截图或日志。
- 本设备 CPU2/CPU3 构建版本和共享协议版本。
- 未确认项和下一轮修正建议。

## 11. 推荐下一轮实际执行顺序

下一轮建议按下面顺序启动，不直接从代码实现开始：

1. 先用现有参考帧脚本和 PLC 联调表跑通真实主机通信，确认 Tank ID、profile 参数、密度缩放、点数和时间策略。
2. 根据联调结论扩展 `tools/check_si7000_modbus_frames.py` 的真实状态快照、缩放边界和报警合成用例。
3. 在 CPU2 增加 profile 生命周期事件和更精确的通用状态字段。
4. 在 CPU3 修正 profile 时间戳、清旧数据时序和 `10002/10003/10004/10009/10010` 映射。
5. 按确认结果决定是否实现 `40010~40023` 持久化、自动调度和校时入口。
6. 做 PLC/主机联调并输出测试记录。
7. 最后再做 SI7000 模块拆分、诊断计数和 `com_manager` 路径收敛。

## 12. 风险和回退策略

| 风险 | 处理方式 |
| --- | --- |
| 现场没有上下液位硬件 | `10002/10003` 保持固定 0 或明确“不支持”，不使用不可靠推测状态 |
| `40001` 与现有分布参数方向不一致 | 新增 SI7000 专用转换或参数，不改坏现有分布测量参数语义 |
| 密度超过 16 位范围 | 保持当前钳位并记录，待 PLC 约定兼容倍率或扩展寄存器 |
| RTC 时间不准 | 保留 LSI 降级说明，优先增加校时入口或确认 LSE |
| 自动调度影响现有测量 | 调度只发通用命令，执行前检查设备状态和互斥条件 |
| 共享协议字段增加引发兼容问题 | 提升协议版本，旧 CPU2/CPU3 严格判定不兼容 |
| 模块拆分引入行为变化 | 先用 golden frame 固定输出，再做等价重构 |
