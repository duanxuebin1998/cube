# SI7000后续需求和优化记录

日期：2026-05-16

本文件记录 SI7000 适配后的后续需求确认项和工程优化项。当前分支只记录，不处理这些需求，不改变 CPU2 测量流程、CPU3 协议映射行为或 CPU2/CPU3 共享协议。

下一轮执行主计划见：`docs/01_协议与寄存器/SI7000协议适配/01_计划与需求/SI7000下一步工作计划.md`。

按说明书拆解的用户确认清单见：`docs/01_协议与寄存器/SI7000协议适配/01_计划与需求/SI7000说明书需求确认清单.md`。

## 处理原则

- 需要 PLC、现场硬件或用户业务口径确认的事项，只记录，不在当前分支实现。
- 不把 SI7000 专用语义下沉到 CPU2；CPU2 只提供通用变量和通用命令。
- 不复用含义不完全一致的 Wärtsilä、DSM 或其它协议参数，避免跨协议副作用。
- 后续实现时先补文档和验证用例，再改代码。

## 优先级建议

| 优先级 | 项目 | 原因 |
| --- | --- | --- |
| P0 | 密度缩放范围、从站地址口径、40001~40003 参数语义、上下液位传感器、profile 首点时间戳 | 直接影响 PLC 读数、profile 数据时序和 SI7000 核心状态是否可信 |
| P1 | `40010~40023` 落盘、RTC 校时、报警语义细分、手动速度档位 | 影响现场体验和长期运行一致性 |
| P2 | 协议诊断计数、主机侧帧测试、模块拆分、兼容分发路径清理 | 提升可维护性和联调定位效率 |

## 官方资料复核补充

资料依据见 `docs/01_协议与寄存器/SI7000协议适配/01_计划与需求/SI7000官方资料整理与兼容计划.md`，已下载：

- `docs/01_协议与寄存器/SI7000协议适配/00_原始资料/SI7000官方操作手册.pdf`
- `docs/01_协议与寄存器/SI7000协议适配/00_原始资料/SI7000官方资料包_含Modbus规范.pdf`

本次复核后新增或提高优先级的确认项：

- SI7000 的上下液位传感器是判断液/气界面的核心状态，`10002/10003` 长期固定 0 只能作为第一版兼容，不能作为最终适配。
- SI7000 profile 的第 0 点应为罐底点，`40001 Profile First Point` 是罐底之后的第一个编程停点；当前 `40001 -> spreadTopLimit` 的语义必须重新确认。
- Profile 时间戳官方语义更接近第一个 profile 点采集时间，当前按完成时刻锁存需要列为后续修正项。
- 新 profile 到罐底并开始采集时应清除上一轮 profile 数据和 `Profile Complete`，当前 CPU3 “未完成不输出点阵”的保护还不是完整生命周期语义。
- Manual 模式下报警不上报、液位不更新；后续需要复核所有报警位和 `30004` 是否严格遵循。
- 下发 Up/Down Slow/Medium/Fast 会停止 profile 或液位跟踪并进入 Manual，直到再次下发 Auto、Cal 或 Profile；当前命令桥接需要覆盖这个状态转换。
- 官方 DCS 地址表暴露 200 个 profile 点，但资料中还出现 250+ 或更高点数描述；当前按 200 点兼容合理，若 PLC 需要更多点需另定扩展方案。
- `30011~30013` 当前时间应持续变化，常被主站用于判断通信有效；如果现场要求真实时间，需要补校时入口或确认 LSE。

## 1. 自动剖面和报警设定落盘

- 关联地址：`40010~40023`
- 当前处理：CPU3 仅保存为 SI7000 影子寄存器，运行期可回读，可用于 `10012` 和报警位合成，掉电后不保留。
- 待确认需求：PLC 写入的自动剖面周期、使能、时分和报警设定点是否必须掉电保存。
- 后续处理边界：确认后再设计 CPU3 本机参数或 CPU2 专用参数，不直接复用 Wärtsilä 或其它协议参数。

## 2. 密度缩放范围

- 关联地址：`30003`、`30021+3n` 剖面密度点
- 当前处理：按协议示例使用 `0.01 kg/m3`；协议 13 后 CPU2/CPU3 内部密度 raw 已统一为 `kg/m3 x100`，SI7000 层不再额外乘 10，超过 16 位时钳位为 `65535`。
- 待确认需求：PLC 侧是否接受 16 位寄存器最高 `655.35 kg/m3` 的范围限制。
- 后续处理边界：如现场密度会超过该范围，需要与 PLC 侧约定兼容倍率或扩展寄存器，不在当前分支擅自改变缩放。

## 3. 手动速度档位

- 关联线圈：Up/Down Slow、Medium、Fast
- 当前处理：三档速度均桥接为 CPU2 现有强制上行或强制下行命令。
- 待确认需求：PLC 是否要求 slow/medium/fast 三档有实际速度差异。
- 后续处理边界：确认需要后，CPU2 需新增通用速度参数或命令；CPU3 仍只负责 SI7000 线圈到通用命令的转换。

## 4. Lower/Upper Level Sensor

- 关联地址：`10002`、`10003`
- 当前处理：当前系统没有可靠同名硬件或状态来源，固定返回 `0`。
- 待确认需求：现场是否存在可接入的下液位/上液位传感器，或 CPU2 是否能提供等价状态。
- 后续处理边界：确认硬件或 CPU2 通用状态后再扩展，不用现有液位稳定状态强行替代上下传感器。

## 5. Interval Timer 语义

- 关联地址：`10012`
- 当前处理：由 `40011 Automatic Profile Enable` 影子值合成，`40011 != 0` 时置位。
- 待确认需求：PLC 侧是否需要“定时器正在计时”“到时触发中”或“自动剖面调度运行中”等更细状态。
- 后续处理边界：如需真实调度状态，应先补充自动剖面调度设计，再由 CPU3 映射到 SI7000。

## 6. CPU3 时钟精度和校时

- 关联地址：`30007~30013`
- 当前处理：CPU3 使用 LSI RTC，提供当前时间和 profile 完成时间戳；已有 `Cpu3Clock_SetDateTime()` 接口，但未接菜单或协议写入。
- 待确认需求：是否要求长期准确时间、LSE 硬件时钟、PLC 远程校时或本机菜单校时。
- 后续处理边界：确认后再定义校时入口；如新增中文菜单，需要同步检查 CPU3 字库。

## 7. 现场协议节奏

- 关联要求：SI7000 协议建议 PLC 请求间隔不小于 1 秒。
- 当前处理：CPU3 作为从站按请求响应，不主动限制 PLC 请求频率。
- 待确认需求：是否需要在 CPU3 侧增加请求频率保护或诊断统计。
- 后续处理边界：如需保护，优先增加统计和告警，不直接丢弃合法请求。

## 8. 从站地址和 Tank ID 口径

- 关联要求：协议描述 `Device ID = Tank ID`，Modbus 从站地址需要同一总线唯一。
- 当前处理：CPU3 SI7000 层优先使用现有 `SlaveAddress`，无效时使用 SI7000 默认地址。
- 待确认需求：现场 PLC 使用的 Tank ID 是否等同于现有 `SlaveAddress`，是否需要独立的 SI7000 Tank ID 参数。
- 后续处理边界：确认不是同一口径后，新增 CPU3 本机 SI7000 地址参数；不复用含义不清的其它设备编号。

## 9. Profile 参数语义

- 关联地址：`40001~40003`
- 当前处理：`40001` 映射 `spreadTopLimit`，`40002` 映射 `spreadMeasurementDistance`，`40003` 映射 `spreadPointHoverTime`。
- 待确认需求：SI7000 的 First Point、Increment、Dwell Time 与当前分布测量参数的方向、单位和边界是否完全一致。
- 后续处理边界：如方向或边界不一致，需要新增 SI7000 专用转换或参数，不直接改变现有分布测量参数语义。

## 10. 报警语义细分

- 关联地址：`10009`、`10010`、`10025`、`10026`、`10029~10032`、`40022~40023`
- 当前处理：Reel Alarm 当前按设备错误简化合成；Probe Un-calibrated 当前按零点状态简化合成；profile 温度/密度偏差报警依赖 CPU2 通用字段，偏差阈值 `40022~40023` 仍为影子寄存器。
- 待确认需求：PLC 是否要求区分卷尺/电机报警、探头未校准、液位/罐高校准状态，以及 profile 偏差阈值算法。
- 后续处理边界：确认算法后，优先在 CPU2 增加通用报警字段或通用偏差结果，CPU3 只做 SI7000 地址映射。

## 11. 液位保持和 profile 数据刷新语义

- 关联地址：`30004`、`30006`、`30021~30620`、`10005`
- 当前处理：profile 完成锁存后输出有效点数和点阵；未完成时输出 0；液位使用当前 CPU2 最近液位值。
- 待确认需求：PLC 是否要求 profile 测量期间 `30004 Liquid Level` 保持上一次液位，或需要明确“profile 数据已读/清除”的握手。
- 后续处理边界：如需握手或清除机制，需要定义独立线圈/寄存器或复用协议已有行为，不能由 CPU3 私自清锁存。

## 12. SI7000 协议诊断计数

- 当前处理：协议异常通过 Modbus 异常响应返回，未保存 CRC 错误、地址不匹配、非法功能、非法地址、非法值等统计。
- 优化建议：增加 CPU3 本地诊断计数和最后一次错误摘要，便于现场判断 PLC 请求格式、站号和频率问题。
- 后续处理边界：优先作为 CPU3 本地诊断或调试信息，不占用 SI7000 协议寄存器，除非 PLC 明确要求读取。

## 13. 主机侧协议帧测试

- 当前处理：当前验证以 CPU2/CPU3 构建、静态检查和文档核对为主。
- 优化建议：增加主机侧 Modbus RTU 帧测试，覆盖 FC01/02/03/04/05/06、CRC、地址不匹配、保留地址异常、密度钳位、温度有符号、profile 点数边界和报警阈值合成。
- 后续处理边界：测试优先放在工具或单元测试目录，不影响固件运行路径。

## 14. CPU3 SI7000 模块结构

- 当前处理：`si7000_modbus_slave.c` 集中包含地址表、缩放、状态刷新、读写处理和异常响应。
- 优化建议：后续可按“地址定义/工程量转换/状态快照/功能码处理/诊断统计”拆分内部结构，降低单文件维护成本。
- 后续处理边界：只做等价重构时不改协议行为；重构前后必须有协议帧测试或 golden frame 对比。

## 15. CPU2/CPU3 共享协议回归检查

- 当前处理：`SI7000 状态字段` 和寄存器偏移已经人工核对，版本检查脚本能检查固件版本是否升级。
- 优化建议：新增脚本检查 CPU2/CPU3 的 `SI7000 状态字段` 字段顺序、`REG_DEVICE_STATUS_*` / `REG_OIL_MEASUREMENT_*` / `REG_HEIGHT_MEASUREMENT_*` / `REG_DENSITY_DIST_*` 偏移和 `DEVICE_PROTOCOL_VERSION` 是否一致。
- 后续处理边界：脚本只做静态检查，不修改代码；协议变更时纳入提交流程。

## 16. CPU3 兼容分发路径取舍

- 当前处理：主循环实际使用 `app_main.c` 的 CPU3 本机参数分发；旧 `com_manager` 兼容路径已统一调用 SI7000 分发，并把枚举改为 `COM_MANAGER_*` 前缀，避免与本机参数枚举混用。
- 优化建议：后续确认是否保留 `com_manager` 兼容路径。如果不再使用，考虑删除或收敛为主分发的薄封装；如果保留，则补齐参数加载和测试。
- 后续处理边界：不在 SI7000 功能合入前做大范围删除，避免影响历史调用方。
