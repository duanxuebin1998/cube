# SI7000 协议兼容映射表

## 1. 方案定位

- 兼容层位置：`CPU3` 外部串口侧
- 当前实现文件：
  - `LTD_DISPLAY_CPU3/Communication/external/si7000_modbus/si7000_modbus_slave.c`
  - `LTD_DISPLAY_CPU3/Communication/external/si7000_modbus/si7000_modbus_slave.h`
- 当前接入方式：
  - `app_main` 主分发路径和 `com_manager` 兼容分发路径均接入 `COM_PROTO_SI7000`
  - 由 `CPU3` 对外模拟 `SI7000 Modbus RTU` 从站
  - 再复用 `CPU3 <-> CPU2` 内部同步数据作为真实数据源

### 1.1 职责边界

| 层级 | 职责 | 不承担的内容 |
| --- | --- | --- |
| `CPU2` | 真实测量、电机动作、液位/密度/profile 数据、通用辅助状态和必要通用命令 | 不理解 SI7000 地址、线圈、功能码、缩放和异常响应 |
| `CPU3` | 串口协议选择、SI7000 Modbus RTU 从站、地址表、单位缩放、影子寄存器、报警合成、命令桥接和时间戳 | 不重写 CPU2 测量流程，不把 SI7000 影子参数误写入非对应 CPU2 参数 |
| `CPU2 <-> CPU3` 共享协议 | 发布通用业务数据和 `SI7000 状态字段` | 不承载 SI7000 寄存器编号或 PLC 专用语义 |

## 2. 当前实现状态

- 已完成：
  - `FC01/FC02/FC03/FC04/FC05/FC06` 基础协议框架
  - 16 个线圈、32 个离散输入、23 个保持寄存器、620 个输入寄存器边界保护
  - CPU3 外部串口协议分发、菜单协议选项和 9600 8O1 串口配置支持
  - `FC05` 关键线圈到 `CPU2` 命令的桥接，模式线圈和动作线圈在影子区内互斥
  - `FC06` 的 `40001~40003` 到 `CPU2` 分布测量参数的真实桥接
  - CPU2/CPU3 共享 `SI7000 状态字段`，供 CPU3 协议转换层生成 SI7000 状态位
  - CPU3 RTC 时间接口，`30011~30013` 当前时间和 `30007~30010` profile 时间戳已接入
  - 位置/液位按内部 `0.1mm` 到协议 `mm` 转换，温度按内部原始值转换为有符号 `0.01°C`
  - 选择 `COM_PROTO_SI7000` 后，CPU3 保存和加载本机串口参数时都会强制该端口为 `9600 8O1`
  - 密度按协议示例输出为 `kg/m3 x100`；协议 13 后 CPU2/CPU3 内部密度 raw 已统一为 `kg/m3 x100`，SI7000 层不再额外乘 10，超出 16 位时钳位到 `65535`
  - `10012` 定时器状态和 `10017~10024`、`10029~10032` 报警位已基于 SI7000 影子设定点合成
  - Profile 完成锁存后才输出 `30006 Number Of Points` 和点阵数据，范围外保持 0，避免 PLC 读到旧点残留
  - 已新增参考帧脚本和共享协议契约脚本，分别保护 SI7000 地址表/异常响应和 CPU2/CPU3 `SI7000 状态字段` 顺序
- 保留限制：
  - `FC05` 慢/中/快三档当前统一桥接到强制上行或强制下行，CPU2 侧尚无独立速度档位参数
  - `40010~40023` 自动 profile 和报警设定点先保留影子回读，未写入 CPU2 参数存储
  - `40011`、`40012`、`40013` 写入时已做基础值域检查，分别限制为使能 `0/1`、小时 `0~23`、分钟 `0~59`
  - `10002/10003` Lower/Upper Level Sensor 当前无内部可靠来源，保持 0
  - 协议密度为 `0.01 kg/m3` 时，常规高密度值可能超过 16 位容量；当前按协议放大并做钳位，仍需 PLC 侧确认实际密度范围

## 3. 串口和协议要求

- 协议：`Modbus RTU`
- 波特率：`9600`
- 格式：`8O1`
- 站号：优先使用现有 `SlaveAddress`，有效范围 `1~247`；无效时使用 SI7000 层默认地址
- 轮询周期：建议 `>= 1s`

当前建议按四类推进：

- 现有命令的可复用部分：
  - `CMD_FIND_OIL`
  - `CMD_MEASURE_DISTRIBUTED`
  - `CMD_CALIBRATE_ZERO`
  - `CMD_FORCE_MOVE_UP`
  - `CMD_FORCE_MOVE_DOWN`

  - `spreadTopLimit`
  - `spreadMeasurementDistance`
  - `spreadPointHoverTime`
  - `wartsila_lower_density_limit`
  - `wartsila_upper_density_limit`

### 4.2 本次在 CPU2 新增/同步的

本次新增的是“中性变量和通用能力”，不是 `SI7000` 模式本身：

- 状态变量：
  - `bottom_reference_valid`
  - `probe_at_liquid_level`
  - `liquid_stable`
  - `profile_complete_latched`
  - `profile_complete_counter`
  - `profile_blocked_by_process`
  - `loading_unloading_active`
  - `manual_alarm_inhibit`
  - `manual_level_update_inhibit`
  - `profile_temp_deviation_alarm`
  - `profile_density_deviation_alarm`
- 参数：
  - 本轮不扩展 CPU2 参数存储布局。
  - `40001~40003` 复用现有 `spreadTopLimit`、`spreadMeasurementDistance`、`spreadPointHoverTime`。
  - 自动 profile、温度/密度/液位报警设定点和手动速度档位仍保留在 SI7000 影子寄存器或后续参数设计中。

### 4.3 本次在 CPU3 落地的

这部分更适合放在协议转换层：

- SI7000 外部 Modbus RTU 从站
- 9600 8O1 串口配置支持
- `Profile Timestamp` 锁存
- `Current Time` 读取
- 协议影子寄存器
- 固定值/保留位填充
- 内部 `0.1mm` 与协议 `mm` 的工程量转换
- 根据 `CPU2` 事件生成协议时间戳

### 4.4 直接不支持或先返回固定值的

在现阶段没有可靠来源时，建议直接固定返回：

- `10002 Lower Level Sensor` -> `0`
- `10003 Upper Level Sensor` -> `0`
- `10012 Interval Timer` -> `40011 Automatic Profile Enable` 影子值
- `10006 Metric/English` -> 固定 `1`
- `10017~10024`、`10029~10032` 阈值报警位 -> 按 `40014~40021` 影子阈值实时合成，阈值为 0 时视为未启用
- 保留位 -> 固定 `0`

### 7.2 点阵寄存器

SI7000 文档要求从 `30021` 开始按 3 个寄存器一组输出 profile 点：

- `30021 + 3n`：位置
- `30022 + 3n`：温度
- `30023 + 3n`：密度

当前实现已接入：

| SI7000 地址模式 | 当前变量来源 | 当前状态 | 说明 |
| --- | --- | --- | --- |
| `30021 + 3n` | `g_measurement.density_distribution.single_density_data[n].temperature_position` | 已接 | 内部 `0.1mm` 转 `mm` |
| `30022 + 3n` | `g_measurement.density_distribution.single_density_data[n].temperature` | 已接 | 内部原始温度按 `raw - 20000` 转有符号 `0.01°C` |

当前上限来源：

- `MAX_MEASUREMENT_POINTS`
- 当前代码按 `SI7000_INPUT_REG_COUNT = 620` 做边界保护
- 只在 `profile_complete_latched` 有效后复制 `30006 Number Of Points` 指定的有效点数，超出有效点数的点阵寄存器保持 0

## 12. 当前保留约束

以下约束和优化项已单独记录到 `docs/01_协议与寄存器/SI7000协议适配/01_计划与需求/SI7000后续需求记录.md`，当前分支只记录，不处理需求实现：

- SI7000 协议描述 `Device ID = Tank ID`，当前优先使用现有 `SlaveAddress`；需确认 Tank ID 是否应独立配置。
- `40001~40003` 当前桥接现有分布测量参数；需确认 First Point、Increment、Dwell Time 与现有方向、单位和边界完全一致。
- `40010~40023` 仍是影子回读，没有真正回写到 `g_deviceParams`；后续需要新增 SI7000 专用参数后再落地。
- 慢/中/快三个手动速度档位当前统一桥接到上行或下行命令，CPU2 暂无三档速度参数。
- `10002/10003` Lower/Upper Level Sensor 没有现成内部可靠来源，当前固定为 0。
- 官方资料明确上下液位传感器是液/气界面判断核心状态，长期兼容需要 CPU2 或硬件提供真实等价状态。
- `40010~40023` 仍是 SI7000 影子寄存器，掉电后不保留；当前只用于回读、定时使能显示和报警位合成。
- 密度已按文档示例输出为 `0.01 kg/m3`，但 16 位寄存器最高只能表达 `655.35 kg/m3`；超过范围时会钳位到 `65535`，需 PLC 侧确认是否接受该限制。
- CPU3 RTC 当前使用 LSI 时钟源，能满足时间显示和时间戳锁存，但长期精度依赖硬件时钟源确认。
- `10009`、`10010`、`10025`、`10026` 及 profile 阈值报警目前是第一版简化/通用字段映射；需确认是否要细分卷尺、电机、校准和 profile 偏差算法。
- 官方 DCS 地址表暴露 200 个 profile 点；资料中另有 250+ 或更高点数描述，若现场 PLC 要求超过 200 点，需要新增扩展方案而不是直接越界输出。
- 官方 profile 语义要求第 0 点为罐底点，`40001` 是罐底之后的第一编程停点；当前 `40001` 桥接现有分布测量参数需继续确认。
- 官方 profile 时间戳更接近首点采集时间；当前按完成时刻锁存，后续需补 CPU2 生命周期事件后修正。
- 后续建议补充主机侧协议帧测试、SI7000 协议诊断计数、共享协议静态一致性检查，并评估 `si7000_modbus_slave.c` 拆分和旧 `com_manager` 兼容路径取舍。
