1. 总体结论

已兼容 协议框架 已支持 SI7000 DCS 表要求的 FC01、FC02、FC03、FC04、FC05、FC06，地址窗口、CRC、异常响应和读写基础边界已落地。
已兼容 串口接入 CPU3 已提供 COM_PROTO_SI7000，选择后按说明书口径锁定 9600 8O1，外部 COM 分发表已接入 SI7000 处理入口。
部分兼容 测量语义 液位、温度、密度、profile 点阵和时间寄存器已能输出，但部分 SI7000 原生生命周期语义仍是近似映射。
待补齐 现场等价状态 上下液位传感器、真实 Interlock、Reel Alarm 分类、Probe Un-calibrated、首点时间戳和自动 profile 调度仍需进一步确认或新增状态来源。

当前方案的方向是正确的：SI7000 的地址、功能码、缩放、影子寄存器和异常响应都集中在 CPU3；CPU2 只暴露通用测量状态、通用参数和通用命令。这能避免把外部协议专用语义下沉到 CPU2 测量核心。

若按“能否让 PLC 按 SI7000 地址表完成基础接入”判断，当前已经可进行第一轮联调；若按“是否完全复刻 SI7000 操作手册中的 Auto、Cal、Profile、Manual 生命周期和报警语义”判断，目前仍是部分兼容。

3. 说明书和 DCS 规范的核心要求

领域 说明书/规范要求 对兼容层的含义
通信 RS-485，Modbus RTU，9600 bps，8 data bits，Odd parity，1 stop bit。Device ID 等同 Tank ID，同一总线唯一。 外部 COM 口选择 SI7000 后必须使用 9600 8O1；站号至少要能复用当前从站地址，若现场要求 Tank ID 独立，需要新增参数。
功能码 FC01 读线圈、FC02 读离散输入、FC03 读保持寄存器、FC04 读输入寄存器、FC05 写单线圈、FC06 写单保持寄存器。 不需要支持 FC10/FC16 等写多寄存器；未支持功能码应返回标准 Modbus 异常。
模式和手动控制 Manual、Cal、Auto、Profile 互斥；手动 Up/Down Slow/Medium/Fast 会中断 profile 或液位跟踪并进入 Manual。 CPU3 可把线圈写入转换为 CPU2 通用命令；读回应以 CPU2 真实状态为准。
Auto Auto 是正常运行模式，探头定位并跟踪液/气界面；Lower sensor 在液中、Upper sensor 在气相时表示在液位界面。 10002、10003 是核心状态，不能长期用无来源固定值替代；10013 应表示探头确实在液面。
Cal Cal 驱动探头到罐底建立 bottom reference，再返回液位界面并回 Auto。断电或维护后可能需要重新校准。 10001、10010 应表达位置基准可信性，而不是泛化错误。
Profile Profile 启动后先到罐底采集 Point 0，再按 First Point、Increment、Dwell Time 逐点采集；完成后返回 Auto。 40001 的语义是“罐底之后第一个停点”；30007~30010 更接近首点采集时间；新 profile 开始应清旧数据和完成标志。
Manual Manual 用于维护；Manual 期间不报告报警，液位读数不更新；系统保持 Manual 直到被切回 Auto、Cal 或 Profile。 需要明确哪些报警在 SI7000 输出层屏蔽、哪些安全故障仍留在本机内部保护；30004 是否保持最后有效液位需确认。
报警 Reel Alarm 表示物理驱动问题；Probe Un-calibrated 表示位置不可信；Deviation Alarm 由 profile 相邻点偏差超过阈值产生。 不能长期把所有错误都映射成 Reel Alarm 或 Interlock；偏差报警应有明确算法来源。
数据范围 DCS 地址表输入寄存器为 30001~30620，profile 点阵从 30021 开始，最多覆盖 200 点；产品资料另提到 250+ profile points。 第一版按 DCS 表输出 200 点是合理的；超过 200 点必须定义扩展地址或分页机制，不能直接越界输出。

5. 按地址区的兼容矩阵

5.1 线圈区 FC01 / FC05

地址 SI7000 含义 当前兼容状态 进一步兼容动作
00001 Manual 已接入 写入后桥接 CMD_MAINTENANCE_MODE；读回由 CPU2 状态推导。 补齐 Manual 期间 SI7000 输出层报警屏蔽和液位保持规则。
00002 Calibrate 部分兼容 当前桥接 CMD_CALIBRATE_ZERO，不是完整“探底后回液面再回 Auto”生命周期。 CPU2 增加 Cal 开始、探底完成、回液面完成、失败状态；CPU3 按状态回读 Cal/Auto。
00003 Auto 已接入 写入桥接 CMD_FIND_OIL，读回 STATE_FLOWOIL。 补真实 Lower/Upper 或等价状态，让 10013 更贴近液/气界面。
00004 Profile 已接入 写入桥接 CMD_MEASURE_DISTRIBUTED，读回分布/密度测量状态。 补 profile 生命周期事件，修正 Point 0 和首点时间戳语义。
00005~00008、00016 Reserved 已保护 FC05 写入返回 Illegal Data Address；读取保持 0。 如现场要求保留位可写回读，需先明确是否破坏官方行为。
00009 Stop 部分兼容 当前用维护模式承担停止和手动态。 建议 CPU2 提供明确 Stop/Abort 通用命令，区分“停动作”和“进入维护”。
00010~00015 Up/Down Slow、Medium、Fast 部分兼容 三档速度统一桥接强制上行/下行；读回时上行/下行固定显示 Medium。 如 PLC 真使用速度档位，CPU2 新增三档速度参数或带速度的手动命令。

5.2 离散输入区 FC02

地址 SI7000 含义 当前兼容状态 进一步兼容动作
10001 Bottom Reference 已接入 来源为 bottom_reference_valid。 复核所有探底成功、fallback、失败和上电状态下该字段是否符合“位置基准可信”。
10002/10003 Lower/Upper Level Sensor 未真实兼容 当前无可靠来源，保持 0。 确认是否有真实硬件；若无，定义 CPU2 等价状态，例如 lower in liquid、upper in vapor。
10004 Interlock 部分兼容 当前按错误码或 profile 流程阻挡合成，语义偏宽。 新增 top reference、最大位置、外部互锁或维护互锁通用状态后重新映射。
10005 Profile Complete 已接入 来源为 profile_complete_latched 和完成态兜底。 补 profile start/clear 事件，确保新 profile 开始时 PLC 立即看到清零。
10006 Metric 已兼容 当前固定公制，返回 1。 若未来支持英制，需要统一全部缩放和 HMI 单位。
10009 Reel Alarm 部分兼容 当前所有设备错误都会置位，尚未限定为卷筒/机械/驱动问题。 CPU2 增加故障分类，CPU3 只把运动、卷筒、电机、限位类故障映射到 Reel Alarm。
10010 Probe Un-calibrated 部分兼容 当前按零点状态合成，未完整覆盖上电未探底、探底失败、编码器位置不可信。 CPU2 增加位置基准可信字段，区分未校准和普通测量错误。
10012 Interval Timer 部分兼容 当前反映 40011 影子使能，不代表真实调度器已启动。 落地自动 profile 调度后改为真实调度状态。
10013 Probe At Liquid Level 已接入 来源为 probe_at_liquid_level。 与 10002/10003 联动复核，确保该位表示当前探头确实在液面，而不是只有历史液位值。
10017~10024 当前值阈值报警 已接入 当前值和 40014~40021 影子阈值合成，阈值为 0 时不启用。 确认阈值是否需掉电保存；Manual 期间是否按说明书屏蔽。
10025/10026 Profile Temp/Density Deviation 部分兼容 已有共享字段，但具体偏差算法仍需明确。 按相邻点差值实现温度/密度偏差扫描，并用 40022/40023 控制阈值。
10029~10032 Profile 上下限报警 已接入 profile 完成锁存后扫描点阵与阈值。 补覆盖用例，确认无效温度、无效密度和超出点数边界不误报警。

5.3 保持寄存器区 FC03 / FC06

地址 SI7000 含义 当前兼容状态 进一步兼容动作
40001 Profile First Point 部分兼容 桥接 spreadTopLimit，但官方语义是罐底之后第一停点。 核对当前分布测量方向和边界；必要时新增 SI7000 profile 起点参数。
40002 Profile Increment 已接入 桥接 spreadMeasurementDistance，mm 与 0.1mm 互转。 确认写入是否只影响下一次 profile，运行中写入是否应拒绝或延后生效。
40003 Profile Dwell Time 已接入 桥接 spreadPointHoverTime。 确认单位为秒，范围与现场稳定时间要求一致。
40004~40009 Reserved 已保护 读取为 0，写入返回 Illegal Data Address。 除非现场 PLC 跨保留区批量写，否则保持当前行为。
40010~40013 Automatic Profile 部分兼容 可写可回读，40011/40012/40013 有基础值域校验，但未真实调度。 若现场需要自动 profile，建议 CPU3 RTC 调度，到点向 CPU2 下发通用 profile 命令。
40014~40023 报警阈值和偏差阈值 部分兼容 当前是运行期影子值，能参与部分报警合成，掉电不保存。 新增 CPU3 SI7000 专用参数存储，不建议复用其他协议阈值，避免跨协议副作用。

5.4 输入寄存器区 FC04

地址 SI7000 含义 当前兼容状态 进一步兼容动作
30001 Current Probe Position 已接入 内部 0.1mm 转 mm，负位置按 0 输出。 确认零点、罐底参考和异常状态下 PLC 是否接受 0 作为无效兜底。
30002 Current Temperature 已接入 内部温度原始值转换为有符号 0.01°C。 补负温度和无效温度帧测试。
30003 Current Density 部分兼容 当前按 16 位无符号输出；密度单位按 0.01 kg/m3 时存在 655.35 kg/m3 上限风险。 现场确认 PLC 是否接受 16 位钳位；如不接受，需要重新约定缩放或扩展寄存器。
30004 Liquid Level 已接入 内部 0.1mm 转 mm，无效液位输出 0。 Manual 和 profile 期间是否必须保持最后液位，需要按说明书补规则。
30006 Number of Points 已接入 仅 profile 完成锁存后输出点数，未完成时为 0。 若 PLC 需要边执行边读逐点递增，需要补 profile 进行中点数发布策略。
30007~30010 Profile Timestamp 部分兼容 当前锁存 profile 完成时刻，说明书更偏向采集时刻或首点时间。 CPU2 发布首点采集事件，CPU3 在该事件锁存时间。
30011~30013 Current Time 已接入 来源为 CPU3 RTC，可作为通信活性辅助判断。 若需要真实时间，补菜单校时、PLC 校时或 LSE 硬件确认。
30021~30620 Profile Point 0~199 部分兼容 已按 200 点 DCS 表输出完成后的点阵，但 Point 0 是否为罐底点仍需核对。 确认或改造 CPU2 点阵生命周期；超过 200 点时另定扩展方案。

6. 关键差距和风险排序

优先级 差距 为什么重要 建议处理方式
P0 10002/10003 上下液位传感器无真实来源 SI7000 用这两个状态判断探头是否处于液/气界面，是 Auto 模式可信液位的核心依据。 先确认硬件是否存在；若没有，定义 CPU2 等价状态并明确局限。
P0 40001 和 Point 0 语义不确定 官方 profile 第 0 点是罐底点，40001 是罐底之后首个停点；错配会导致 PLC 对点位高度解释错误。 核对 CPU2 当前分布测量的起点、方向和点阵来源；必要时改 CPU2 profile 输出。
P0 Profile 时间戳是完成时刻，不是首点采集时刻 说明书语义更接近数据采集时间；长 profile 下完成时刻会偏离首点数据时间。 CPU2 发布 profile 首点采集事件或计数，CPU3 锁存该时刻。
P1 Manual 期间报警和液位更新未严格按 SI7000 屏蔽 说明书明确 Manual 不报告报警、液位不更新；PLC/HMI 可能据此设计操作提示。 CPU2 给出 manual 抑制状态，CPU3 对 SI7000 输出层屏蔽相应报警并保持液位。
P1 Interlock、Reel Alarm、Probe Un-calibrated 语义偏简化 这些状态用于 PLC 安全判断和维修提示，泛化映射会导致误报警或漏判。 CPU2 增加故障分类、位置基准可信、顶端/互锁状态。
P1 40010~40023 未落盘，自动 profile 未调度 PLC 写入后掉电丢失，且自动 profile 使能目前只影响状态位，不会触发测量。 在 CPU3 增加 SI7000 专用参数存储和 RTC 调度器，必要时加菜单或配置页。
P1 手动三档速度未区分 若 PLC/HMI 暴露 Slow、Medium、Fast，现场人员会预期速度不同。 确认现场是否需要；需要时 CPU2 增加带速度档位的手动命令或速度参数。
P2 诊断计数和现场可观测性不足 联调时 CRC 错误、站号不匹配、非法功能码、非法地址等问题需要快速定位。 CPU3 增加 SI7000 诊断计数，必要时通过本机页面或扩展寄存器暴露。

7. 进一步兼容实施方案

版本影响原则：只改 CPU3 外部 SI7000 映射、影子参数或测试脚本时，通常不改变 CPU2/CPU3 共享协议；一旦新增 CPU2 状态字段、命令、参数语义或寄存器映射，必须同步升级 DEVICE_PROTOCOL_VERSION，并更新 CPU2/CPU3 协议变更记录、版本资料和 SI7000 映射文档。

阶段 0：需求确认和联调基线

  • 确认 Tank ID 是否继续复用 SlaveAddress，还是新增 SI7000 专用 Tank ID。
  • 确认现场是否有 Lower/Upper 液位传感器、顶端限位、卷筒/电机故障等硬件来源。
  • 确认 40001~40003 与现有分布测量参数的单位、方向、边界和运行中写入策略。
  • 确认 PLC 是否接受 200 点 DCS 表和密度 16 位范围限制。
  • 用现有 golden frame 脚本和 PLC 主机工具先完成基础通讯接入。

阶段 1：CPU2 通用状态补齐

  • 新增或细化 Lower/Upper 等价状态、Top/Interlock 状态、Reel/Drive 故障分类。
  • 新增位置基准可信字段，覆盖上电未探底、探底成功、探底失败和编码器异常。
  • 明确 Manual 期间液位更新抑制和 SI7000 报警输出屏蔽字段。
  • 补 profile 生命周期事件：start、bottom reached、point0 captured、clear old data、complete、failed。
  • 如需要三档速度，新增通用手动速度命令或参数，不在 CPU3 里硬编码运动速度。

阶段 2：CPU3 SI7000 映射增强

  • 按 CPU2 新状态重映射 10002/10003/10004/10009/10010/10013。
  • Profile 开始时清旧点阵和 10005，首点采集时锁存 30007~30010。
  • 把 40010~40023 做成 CPU3 SI7000 专用参数，支持默认值、值域、FRAM 保存和恢复。
  • 实现自动 profile 调度：RTC 到点、互锁检查、下发 profile 命令、记录调度状态和失败原因。
  • 增加 SI7000 诊断计数：合法帧、CRC 错、地址不匹配、非法功能、非法地址、非法值、最后异常码。

阶段 3：测试、文档和现场闭环

8. 验证计划

验证类别 建议命令或步骤 期望结果
静态协议契约 py tools\check_si7000_protocol_contract.py CPU2/CPU3 的共享字段、寄存器宏和打包/解析顺序一致。
SI7000 地址和参考帧 py tools\check_si7000_modbus_frames.py 地址窗口、功能码、枚举 offset 和参考帧 CRC 与文档一致。
串口参数 选择 COM_PROTO_SI7000 后检查 COM1/COM2/COM3 配置。 实际 UART 为 9600 8O1，且有校验位时 word length 配置不丢数据位。
基础帧联调 PLC 或主机工具读取 FC01、FC02、FC03、FC04，并写 FC05/FC06 合法值和非法值。 合法请求正常响应；保留地址、非法值和未知功能码返回标准异常。
模式生命周期 依次写 Manual、Auto、Cal、Profile、Stop、Up/Down 三档。 模式互斥，手动动作能打断自动行为；读回最终以 CPU2 真实状态为准。
Profile 数据 触发 profile，读取 10005、30006、30007~30010 和 30021~30620。 开始时旧数据清除，完成后点数和点阵有效；点数不超过 200 点 DCS 表。
报警阈值 写入 40014~40023，构造当前值和 profile 点越限场景。 当前值报警、profile 上下限报警和偏差报警按阈值置位，阈值为 0 时不启用。
掉电恢复 在参数落盘阶段写入 40010~40023 后重启。 参数按设计恢复；FRAM 版本迁移、默认值和 CRC 错误回退行为明确。
现场联调建议：先按官方 DCS 地址表做“只读和单点写”联调，不要一开始启用高速轮询。PLC 轮询周期建议不低于 1 秒；若需要更快刷新，应先记录 CPU3 处理耗时、串口负载和 CPU2 轮询影响，再决定是否优化。
