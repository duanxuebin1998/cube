重组方法

  1. 只提取每行时间戳之后的十六进制字节；发送/接收中文标记不参与帧边界判断。
  2. 按时间顺序拼接被串口工具拆行的片段，再用 CRC16/MODBUS 验证请求和响应。
  3. 常规轮询只认站2 02 04 00 00 00 14 F0 36 与 40 字节数据响应。
  4. 点阵读取按请求起始地址与数量配对；五块各读 120 个寄存器，覆盖 30021～30620。
  5. FC01/FC02/FC03 专项查询与原轮询主站发生过穿插，只把结构和 CRC 均成立的响应作为证据。

直接证据

完整请求/响应、CRC 正确，字段可从原始字节直接解码。

交叉验证

两个功能码、两轮过程或点阵与阈值给出一致结果。

时序推断

只能由上位机行为反推，无法证明其程序内部唯一判断条件。

09｜上位机如何判断本轮完成

抓包只能看到总线行为，不能反编译上位机程序。但两轮都出现相同状态序列，且主站在最终状态出现前不读取点阵，最终状态出现后立即切换到五块点阵读取。

1. 命令成功FC05 Profile ON 得到相同回显。
2. 确认进入本轮30014 Profile 位为 1；不能直接使用旧 Complete。
3. 等待旧完成位清零Point0 发布时 30015 Complete 从旧 1 变为 0。
4. 等待新完成组合Profile 清零、Auto 置位、Complete 重新置位。
5. 读取实际结果先读 30006，再按实际点数处理点阵。

10｜本轮可以确认什么，仍不能确认什么

已确认

  • 六个文件是两条累计记录的六个保存节点。
  • 两轮 Profile 的底部、运动时长、停留节奏和最终 30 点高度复现。
  • Point0 是实际底部 345 mm。
  • Profile 时间戳在 Point0 发布时更新。
  • 30014/30015/30016 是 FC01/FC02 打包镜像，且动态态直接成立。
  • 30017～30020 在 6265 个样本中全部为 0。

强交叉证据

  • 40003=20 s 对应底部与最终发布前的停留/处理窗口。
  • 第二轮 P25 相邻密差越过 40023，最终 30016 bit9 置位。
  • 主站依赖最终状态组合后才开始读取点阵。

仍待确认

  • 原上位机内部完成判断的唯一布尔表达式。
  • 30005=1 的厂家私有含义。
  • 30017～30020 在其它故障/功能场景是否使用。
  • 40004～40009 的名称、单位、范围和写权限。
  • 报警非零完成态下 FC02 是否直接返回后半字节 00 02。
