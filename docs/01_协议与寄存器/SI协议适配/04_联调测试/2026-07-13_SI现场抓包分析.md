Modbus 线圈/离散输入按低地址位优先打包，因此 FC01/FC02 数据字节顺序与 16 bit 寄存器显示顺序相反。该结果直接确认了稳态下的三寄存器镜像结构；`16-36-16` 又在第二轮 Profile 下行阶段直接读到 `08 40 -> 30014=0x4008`、`36 00 00 00 -> 30015/30016=0x0036/0x0000`。再结合两轮 FC04 状态变化，`30014/30015` 的字段解释可以视为已确认。

### 7.5 兼容边界

镜像关系已确认，但这些地址在 `020-701 Rev B` 中仍是 Reserved，厂家没有承诺所有固件版本都保持该别名。兼容处理建议如下：

1. 新设计的 PLC/上位机应按官方字段使用 `10005 Profile Complete`，不新增对保留寄存器的依赖；
2. 既有上位机很可能通过 `30014/30015` 的打包镜像判断过程和完成，CUBE 固定返回 0 已属于明确的实机兼容差异；
3. 修改 CUBE 前仍应补齐 Point0、逐点上行、液位稳定和最终完成阶段的 FC01/FC02/FC04 同步读取；下行动态态已经直接一致，但还不能据此替代全阶段逐帧验证；
4. 如需复刻，必须同步更新 SI 映射文档、联调表、golden frame 和协议契约检查，并评估既有 PLC 对保留寄存器固定 0 的反向兼容风险。

结合第 7 节的直接验证，`30014` 是 FC01 `00001~00016` 的打包镜像，其中 `0x0004` 对应 Auto、`0x0008` 对应 Profile；`30015` 是 FC02 `10001~10016` 的打包镜像，其中 `0x0010` 对应 `10005 Profile Complete`，`0x1000` 对应 `10013 Probe At Liquid Level`。据此可以把本轮状态链进一步还原为：

```text
命令前：30014 Auto=1、Stop=1；30015 Complete=1（上一轮结果）
    -> 进入 Profile：30014 Profile=1；30015 Complete 暂时仍为 1
    -> Point0 完成：30015 Complete 由 1 清为 0，本轮状态正式建立
    -> 逐点采样：30014 Profile=1；30015 Complete=0
    -> 最终发布：30014 Profile=0、Auto=1、Stop=1；
                 30015 Complete=1、Probe At Liquid Level=1
    -> 下一轮读取 30006，随后读取点阵
```

这说明上位机不能只在发命令后等待 `Complete=1`，因为命令后到 Point0 之前仍保留上一轮完成位。最可能的实现是先通过 `30014` 的 Profile 位或 `30015` 完成位清零确认“本轮已经进入运行态”，再等待 `30015 bit4` 从 0 变 1，并确认 `30014` 已返回 Auto，最后读取 `30006` 获得本轮实际点数。另一种等价实现是监视 `30014` 的 Profile 位完成 `0 -> 1 -> 0` 全周期，并以 `30015 Complete=1` 作为结果有效门禁。

该镜像关系可以解释本次原上位机为何不读取 FC01/FC02：模式、状态和报警已经由 `30014~30016` 随 FC04 一并返回。下午调试主站在第二轮下行期间插入的 FC01/FC02 已与相邻 FC04 动态值直接一致，但这些地址在官方表中仍属于保留寄存器，抓包也不能证明原上位机程序具体采用了上述哪一组组合条件。标准新实现仍应使用公开的 FC01/FC02 位；若决定让 CUBE 兼容既有上位机，还需补齐 Point0、上行、液位稳定和最终完成阶段的三类功能码同步对照后再实现。

### 16.4 第二主站抢占风险

FC03、FC01、FC02 各发送 3 次，但每种功能码都只有 2 次收到有效响应。三个未响应请求均可由发送时机解释：

- `15:43:00.938` 的 FC03 插入站 1 FC04 响应尚未结束的位置；
- `15:45:17.075` 的 FC01 发出后仅 10 ms，原主站又发送站 1 FC04；
- `15:46:02.795` 的 FC02 直接插入站 3 FC04 响应中间。

成功交互的请求到响应文本时间差为 14～29 ms，但由于抓包仍混有原主站轮询，不能把该范围当作严格设备响应性能。现场专项查询应采用以下任一方式：

1. 暂停原上位机轮询后，再由调试工具独占 RS485 总线；
2. 把 FC01/FC02/FC03 请求加入原主站的统一调度队列；
3. 如需精确测时，使用逻辑分析仪同时记录 A/B 线和 RS485 DE 换向。

不要让两个无仲裁主站同时发送。否则不仅会出现“请求无响应”，还可能破坏原主站正在接收的合法响应，造成误判、重试或数据缺口。
