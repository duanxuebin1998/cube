# SI协议兼容映射表

更新日期：2026-07-16

资料依据：`docs/01_协议与寄存器/SI协议适配/00_原始资料/SI7000_modbus_官方.pdf`，即 SI-7000 DCS Modbus Interface Specification `020-701 Rev B`。本文区分“官方手册口径”和“当前 CUBE 兼容实现”，避免把兼容偏差误写成 SI协议原生行为。

## 0. 资料来源与落地口径

本地 `00_原始资料` 已能确认一部分协议硬约束，但没有找到完整的 `40001~40023` 出厂默认值和非法值总表。2026-07-13 现场抓包结论见 `../04_联调测试/2026-07-13_SI现场抓包分析.md`；抓包用于描述真实 SI 的兼容行为，不提升为官方公开协议契约。后续文档和实现统一按“来源分级”处理：

| 来源分级 | 含义 | 落地规则 |
| --- | --- | --- |
| 官方明确 | 原始 Modbus/DCS 资料直接给出地址、缩放、保留范围或功能语义 | 作为 CPU3 SI 协议层硬约束，脚本和联调必须覆盖 |
| 官方建议 | 手册给出推荐配置，例如每天一次 profile 建议 `40010=1440` | 写入说明和联调建议，不作为唯一合法值 |
| 现场实机抓包 | CRC 正确的真实 SI 请求、响应和完整 Profile 时序 | 作为既有上位机兼容证据；与官方表冲突时同时保留“官方契约”和“实机私有行为”两套口径 |
| CUBE 工程默认 | 本地资料未给默认值，当前代码为安全运行设定的默认值 | 文档必须标注为 CUBE 默认，不写成 SI 出厂默认 |
| 待现场确认 | 手册缺失或与实现目标有冲突的项目 | 进入待确认清单，不提前扩展协议或改变倍率 |

可直接固化的官方硬约束如下：

| 类别 | 官方资料结论 | 当前落地 |
| --- | --- | --- |
| 串口 | `9600` baud、Odd parity、8 data bits、1 stop bit、RTU | 选择 `COM_PROTO_SI` 后 CPU3 外部串口强制为 `9600 8O1` |
| 地址窗口 | 线圈 `00001~00016`、离散输入 `10001~10032`、保持寄存器 `40001~40023`、输入寄存器 `30001~30620` | CPU3 按窗口做边界保护，越界返回 Modbus 异常 |
| 保留地址 | 官方表将 `00005~00008`、`00016`；`10007`、`10011`、`10014~10016`、`10027~10028`；`40004~40009`；`30005`、`30014~30020` 标为 Reserved | 线圈和离散输入保留位仍按公开契约处理；为兼容站2实机，协议18实现 `30014~30016` 状态镜像和 `40004~40009` CPU3本地原始兼容槽；`30017~30020`继续为0。私有字段不提升为官方公开语义 |
| 缩放 | Level 1 count = `1 mm`；Temperature 1 count = `0.01°C`；Density 1 count = `0.01 kg/m3` | CUBE 内部单位在 CPU3 SI 层转换，密度超 16 位时钳位 |
| 自动 profile | `40011=0` 禁用，`40011=1` 启用；每天一次建议 `40010=1440` | 关闭使用 `40011=0`；`40010=0` 拒写；`1440` 作为日周期建议值 |
| Profile 点阵 | DCS 地址表只覆盖 `30021~30620`，即 Point 0~199 共 200 点；有效点之外数据为 0 | 当前 SI协议对外最多 200 点，完成前和有效点外保持 0 |
| 内部点数说明 | 操作手册另提设备内部 profile 最大 500 点 | 不作为当前 DCS Modbus 可读点数；超过 200 点需扩展地址或分页方案 |
| 错误显示值 | 操作手册提到温度/密度超量程显示值 | 外部 Modbus 采用 CUBE 兼容哨兵：温度 `-200.00°C`，密度 `0` |

## 1. 当前基线

| 项目 | 当前结论 |
| --- | --- |
| 协议契约 | 当前整机源码为 `DEVICE_PROTOCOL_VERSION = 21`，正式组合为CPU2 V1.27.0.0 / CPU3 V1.25.0.0；SI地址和生命周期仍沿用协议18。协议19故障码、协议20 AO和协议21固定点代际不改变SI契约或既有SI地址；双端仍须严格配套 |
| 外部协议入口 | CPU3 对外模拟 SI Modbus RTU 从站，CPU2 不承载 SI 地址、功能码或异常码 |
| Profile 命令 | `00004 Profile` 写 ON 后下发 `CMD_SI_PROFILE`；命令成功只进入PREPARING，Point0有效样本才建立新周期并锁存时间 |
| 屏幕 Profile 入口 | CPU3 屏幕“密度分布测量 -> SI Profile”确认后走同一启动入口；时间同样以Point0周期事件为准 |
| Profile 参数 | `40001~40003` 独立存入 CPU2 SI profile 参数，不再复用普通分布测量参数 |
| 自动 profile 与报警阈值 | `40010~40023` 独立存入 CPU3 SI 本机参数，用于 RTC 自动调度和报警合成 |
| 私有兼容槽 | `40004~40009` 为CPU3本地原始 `uint16_t` 槽，默认 `0、50、1000、0、5、1`，支持FC03/FC06和掉电保存，不参与业务控制 |
| CPU3本机参数事务 | `40004~40023`只有FRAM写入和写后读回校验成功才回显FC06；失败返回 `0x06`并恢复整份写前运行态 |
| Profile 时间戳 | `30007~30010` 为CPU3观察到Point0新周期事件时锁存的本机RTC；首次上线/重连无法重建时当前周期四项全0 |
| 液位传感器显示 | `10002` 固定表示下传感器在液体中；`10003` 液位跟随稳定时为空气，其它状态为液体 |
| 探针可信 | `10010 Probe Un-calibrated` 固定输出 `0`，表示探针可信 |
| Point0 和点阵 | Point0输出本轮实际采用的底部参考；Point0建立新周期后活动N从1递增，但 `30021~30620`全0，最终代际复核通过后一次开放完整点阵 |
| 已发布快照隔离 | 普通、国标、每米、间隔和Wärtsilä分布不会清除或改写旧SI的Complete、N、时间、点阵和Profile报警；旧SI终态不得遮住当前非SI动作 |
| 探底失败 fallback | 需要探底但失败时优先沿用可信旧底；没有可信旧底时使用当前位置作为Point0参考继续，不按失败处理、不置Interlock，但该位置不宣称为可靠物理罐底 |
| 无效值 | 温度无效对外输出 `-200.00°C`，密度无效输出 `0`，液位/位置无效和有效点数外仍输出 `0` |
| 现场实机兼容基线 | 站2抓包确认的 `30014~30016` 镜像、真实Point0、Point0时间/周期和递增点数已经实现；最终结果在回液位、稳定、电机停止和点阵代际复核后同代发布。第15节保留抓包当时差异，并附现状后记 |

### 1.1 官方全文复核后的受控偏差

2026-07-02 按官方中文全文译稿复核后，以下项目是当前实现和 SI 原机语义的差异。联调时应把这些差异当成显式验收项，而不是隐含假设。

| 项目 | 官方 SI 语义 | 当前 CUBE 口径 | 风险和联调要求 |
| --- | --- | --- | --- |
| Manual 报警 | Manual mode 下不报告报警，液位读数不更新 | CPU2 本机继电器报警会看 `manual_alarm_inhibit`；CPU3 SI `10017~10026/10029~10032` 仍按阈值合成，未统一按 Manual 清零 | PLC 若要求官方一致，需要验证 Manual 时 SI 报警是否清零；当前应按受控偏差记录 |
| Manual 下自动 Profile | 自动 Profile 到点时，Manual 下不启动 | CPU3 自动调度到点后直接触发 `CMD_SI_PROFILE`，没有 Manual 跳过条件 | 维护模式可能被自动调度打断；建议后续增加 Manual 抑制或现场禁用自动 profile |
| Profile/Cal 完成后回 Auto | Profile 或 Cal 完成后返回 Auto 并跟踪液位 | SI profile采点完成后进入 `RETURNING_LEVEL`并排队 `CMD_FIND_OIL`；回到稳定液位且电机停止后才发布最终Complete并进入液位跟随。`00002 Calibrate` 当前仍桥接 `CMD_CALIBRATE_ZERO`，不是完整 Level Calibration | 回液位前Complete必须保持0；最终组合发布后才把 `30004` 当当前液位。Cal完整语义仍待确认 |
| Probe Un-calibrated | `10010` 表示位置或校准不可信，是判断液位和 profile 可信度的关键状态 | `10010` 固定输出 `0` | `10010=0` 仅表示兼容固定值，不证明底部参考或探针位置真实可靠 |
| Lower/Upper Level Sensor | `10002/10003` 来自真实上下液位传感器 | 当前由 CPU3 根据液位跟随稳定状态合成 | 不能作为真实双传感器安全联锁输入 |
| Interlock/Reel Alarm | `10004` 为高限互锁，`10009` 为卷盘/物理驱动报警 | 当前按 `error_code` 或 `profile_blocked_by_process` 概括合成 | 只能作为概括故障使用，不能区分高限、卷盘、电机和普通测量错误 |
| Profile Timestamp | 更接近首个 profile 点采集时间 | `30007~30010` 在CPU3观察到Point0周期事件时锁存；重启/重连无法重建时为0 | 已与Point0边界对齐；RTC锁存失败或重启恢复场景必须把0当无效编码 |
| 无底部参考时的 profile | 应通过 Cal/Profile 重新建立 bottom reference，保证罐底基准可信 | 探底失败且无可信旧底时使用当前位置作为Point0参考继续，不按失败处理；Point0输出实际采用位置 | 数据可用性优先于官方物理基准；当前位置降级不得对外宣称为可靠探底结果 |
| 报警阈值默认 0 | 阈值是实际设定点，官方资料未给独立 enable 位 | `40014~40023` 默认 0 且 0 是有效阈值 | 默认参数可能触发报警；现场必须下发合理阈值或确认新增 enable 方案 |

## 2. 方案定位

- 兼容层位置：`CPU3` 外部串口侧
- 当前实现文件：
  - `LTD_DISPLAY_CPU3/Communication/external/si_modbus/si_modbus_slave.c`
  - `LTD_DISPLAY_CPU3/Communication/external/si_modbus/si_modbus_slave.h`
- 当前接入方式：
  - `app_main` 主分发路径和 `com_manager` 兼容分发路径均接入 `COM_PROTO_SI`
  - 由 `CPU3` 对外模拟 `SI Modbus RTU` 从站
  - 再复用 `CPU3 <-> CPU2` 内部同步数据作为真实数据源

### 2.1 职责边界

| 层级 | 职责 | 不承担的内容 |
| --- | --- | --- |
| `CPU2` | 真实测量、电机动作、液位/密度/profile 数据、通用辅助状态和必要通用命令 | 不理解 SI 地址、线圈、功能码、缩放和异常响应 |
| `CPU3` | 串口协议选择、SI Modbus RTU 从站、地址表、单位缩放、CPU3 SI 参数、报警合成、自动 profile 调度、命令桥接和时间戳 | 不把 SI Modbus 地址、功能码或异常码下沉到 CPU2 |
| `CPU2 <-> CPU3` 共享协议 | 发布通用业务数据和 SI 状态字段 | 不承载 SI 寄存器编号或 PLC 专用语义 |

  - 位置/液位按内部 `0.1mm` 到协议 `mm` 转换，温度按内部原始值转换为有符号 `0.01°C`
  - 选择 `COM_PROTO_SI` 后，CPU3 保存和加载本机串口参数时都会强制该端口为 `9600 8O1`
  - 密度按协议示例输出为 `kg/m3 x100`；协议 13 后 CPU2/CPU3 内部密度 raw 已统一为 `kg/m3 x100`，SI 层不再额外乘 10，超出 16 位时钳位到 `65535`
  - `40010~40023` 已作为 CPU3 SI 本机参数持久化，并用于自动 profile 调度和报警合成
  - `10012` 定时器状态和 `10017~10026`、`10029~10032` 报警位已基于 CPU3 SI协议设定点合成
  - `10002/10003` 按液位跟随稳定状态合成，`10010` 固定输出可信
  - `30014~30016` 从同一FC01/FC02位图派生，`30017~30020`保持0
  - `40004~40009` 为CPU3本地兼容槽，默认 `0、50、1000、0、5、1`；`40004~40023`支持事务式FC06写、FRAM写后校验、失败整份回滚和V6→V7迁移
  - Point0前保留上一轮结果；Point0后 `30006` 按有效点递增，活动点阵保持0；回液位且候选分块/代际复核通过后一次发布Complete、最终N、点阵和Profile报警
  - CPU3重启/重连不伪造Point0时间；无法重建时 `30007~30010=0`
  - 已发布SI快照与普通、国标、每米、间隔、Wärtsilä分布隔离；旧SI COMPLETE/ABORTED/FAILED终态不遮住当前非SI动作线圈
  - 已新增参考帧脚本和共享协议契约脚本，分别保护 SI协议地址表/异常响应、协议版本、命令号和 CPU2/CPU3 SI协议状态字段顺序
- 保留限制：
  - `FC05` 慢/中/快三档当前统一桥接到强制上行或强制下行，CPU2 侧尚无独立速度档位参数
  - `40010` 禁止写 0，`40011`、`40012`、`40013` 写入时已做基础值域检查，分别限制为使能 `0/1`、小时 `0~23`、分钟 `0~59`
  - SI协议官方手册默认值仍需现场逐项复核；当前代码使用保守默认值
  - 协议密度为 `0.01 kg/m3` 时，常规高密度值可能超过 16 位容量；当前按协议放大并做钳位，该限制已确认可接受

## 4. 串口和协议要求

- 官方接口：`RS485`；若主机侧使用 `RS232`，官方手册要求外接转换器。
- 协议：`Modbus RTU`
- 波特率：`9600`
- 格式：`8O1`
- 站号：官方口径为 `Device ID = Tank ID`，同一总线上每台唯一；当前实现复用现有 `SlaveAddress`，有效范围 `1~247`，无效时使用 SI 层默认地址。
- 轮询周期：建议 `>= 1s`

官方功能码和地址窗口如下：

| 功能码 | 官方用途 | 地址窗口 | 当前支持 |
| --- | --- | --- | --- |
| `FC01` | 读模式、方向和速度线圈 | `00001~00016` | 支持 |
| `FC05` | 写模式、方向和速度线圈 | `00001~00016` | 支持，保留位拒写 |
| `FC02` | 读状态和报警离散输入 | `10001~10032` | 支持 |
| `FC03` | 读 profile 和报警配置保持寄存器 | `40001~40023` | 支持 |
| `FC06` | 写 profile 和报警配置保持寄存器 | `40001~40023` | 支持，保留位和值域非法时返回异常 |
| `FC04` | 读实时测量值、时间和 profile 点阵 | `30001~30620` | 支持 |

官方缩放口径：

| 类别 | 官方量程/缩放 | 当前实现 |
| --- | --- | --- |
| 液位/位置 | 公制下 1 count = `1 mm`，无符号 16 位，`0~65000` 表示 `0~65.000 m` | 内部 `0.1mm` 转 `mm`，负值按 0 输出 |
| 温度 | 有符号 16 位，1 count = `0.01°C` | 内部原始温度按 `raw - 20000` 转有符号 `0.01°C` |
| 密度 | 无符号 16 位，1 count = `0.01 kg/m3`，最高 `655.35 kg/m3` | 内部 `kg/m3 x100` 直接输出，超过 16 位钳位到 `65535` |
| 停留时间 | `40003` dwell time 单位为秒 | 按秒写入 CPU2 SI profile 参数 |

SI协议对外无效值口径：

| 数据 | 内部无效来源 | SI协议对外值 | 说明 |
| --- | --- | --- | --- |
| 温度 | CPU2 温度为 `0`、`9999`、无线温度无效值等 | `-200.00°C`，寄存器值 `-20000`，补码 `0xB1E0` | PLC 按有符号 `0.01°C` 解释 |
| 密度 | `UNVALID_DENSITY = 0` | `0` | 保持现有密度无效值，不改为 `65535` |
| 液位 | `UNVALID_LEVEL` | `0` | 避免 `65535` 被误解为超高液位 |
| 位置 | 负位置或无效位置 | `0` | 对外 0 可解释为底部/未知 |
| profile 有效点外 | 点数之外 | `0` | 保持官方 DCS 点阵口径 |

无效温度和无效密度不参与报警判断，避免 `-200.00°C` 触发低温报警或密度 `0` 触发低密报警。

### 8.2 真实 SI 的 `30014~30016` 私有镜像

这些地址在官方 `020-701 Rev B` 中仍为 Reserved，但现场真实 SI 把 FC01/FC02 状态复制进 FC04 单值窗口，使既有上位机只读一次 `30001~30020` 即可同时获得测量值、模式、完成位和报警。寄存器按 Modbus 大端显示，FC01/FC02 位数据则按低地址位优先传输，因此字节顺序表现为 `04 01 -> 0x0104`、`32 10 -> 0x1032`。

| 地址 | 实机私有含义 | 现场直接证据 | 当前证据强度 | 当前 CUBE |
| --- | --- | --- | --- | --- |
| `30014` | `00001~00016` 打包镜像 | 空闲态 `04 01 -> 0x0104` 独立重复 2 次；Profile 下行态 `08 40 -> 0x4008` 与相邻 FC04 一致 | 稳态和下行动态态均有直接证据 | 已按同一FC01位图派生 |
| `30015` | `10001~10016` 打包镜像 | 空闲态 `32 10 -> 0x1032` 独立重复 2 次；Profile 下行态 `36 00 -> 0x0036` 与相邻 FC04 一致并干净复核 | 稳态和下行动态态均有直接证据 | 已按同一FC02位图派生 |
| `30016` | `10017~10032` 打包镜像 | 同一 FC02 响应的 `00 00` 对应相邻 `30016=0x0000`；第二轮密差越限后最终 `30016=0x0200` | 零值稳态直接证据；非零语义由阈值和点阵交叉验证 | 已按同一FC02位图派生 |

第二轮 Profile 的 Point25 密度为 `441.97 kg/m3`，与 Point24/Point26 的相邻密差分别为 `1.37/1.29 kg/m3`，均超过 `40023=0.80 kg/m3`；最终 `30016=0x0200`。因此 `30016 bit9 -> 10026 Profile Density Deviation` 已获得位序、阈值和点阵三方一致的强证据，但尚缺报警非零时同步 FC02 直接看到后半数据字节 `00 02`。`30014~30016` 属于真实 SI 的未公开别名，不应替代公开 FC01/FC02 契约；若为兼容既有上位机而实现，必须与公开位保持逐帧等价。

## 9. 保持寄存器区 FC03 / FC06

当前 `40001~40003` 已正式绑定到 CPU2 SI profile 执行参数；`40004~40009` 是CPU3本地原始兼容槽；`40010~40023` 是CPU3 SI自动调度和报警参数。三段都支持FC03连续读取；FC06按单寄存器写入。

写入门禁分为两类：`40001~40003` 必须在状态、完整参数和当前连接协议快照均已建立、共享协议版本相等、参数刷新已完成且通信故障未锁存时写 CPU2，只有 CPU2 ACK 成功后才更新 `g_deviceParams` 和 SI 保持寄存器影子；失败返回设备忙 `0x06` 并保留原值。参数写成功或已发起后失败都会立即使CPU2参数快照失效并强制补读四组；补读完成前，与 `40001~40003` 相交的FC03及后续CPU2参数写返回设备忙 `0x06`，`40004~40023`本机参数仍可离线读写。`40004~40023` 只写CPU3本机参数和FRAM，合法写入不依赖CPU2在线状态；FRAM写入或写后读回校验失败时恢复整份写前运行态、尽力恢复旧FRAM镜像，并向FC06返回设备故障 `0x06`，不得留下“运行态已变但掉电未保存”的假成功。

官方语义补充：profile 启动后先到罐底采集Point0；`40001 Profile First Point`是Point1的绝对位置，`40002 Profile Increment`是从该位置开始向液面方向逐点增加的步距，`40003 Profile Dwell Time`是每点停稳后的等待秒数。CPU2不在profile前单独执行 `SearchOilLevel()`，运动候选点按实际采用底部、绝对首点、步距、罐高和200点上限生成；Point0最终输出本轮实际采用的底部参考，Point1固定等于 `40001`，Point2等于 `40001 + 40002`，PointN等于 `40001 + (N-1) * 40002`。即使实际底部位置高于 `40001`，也不跳过 `40001`。逐点采样时若候选点被判定为液面以上点，则停止本轮profile且不把该空气点写入有效点数。采点结束后进入RETURNING_LEVEL；CPU2只有回到稳定液位且电机停止后才提交候选，CPU3再完成点阵分块和代际复核，最终一次发布Complete、N、点阵和Profile报警。自动profile首次在 `40012/40013`指定时刻运行，之后按 `40010`分钟周期重复；如果只需要每天一次，官方建议 `40010=1440`。到点下发失败时不记录本分钟成功状态，CPU3按5s门限节流重试；只有下发成功后才对本分钟去重。关闭自动profile使用 `40011=0`，并拒绝写入 `40010=0`。

### 9.2 写失败反馈和影子一致性

| 写入范围 | CPU2 依赖 | 失败响应 | 影子提交口径 |
| --- | --- | --- | --- |
| `FC05=ON` 的模式/动作线圈 | 依赖 CPU2 命令 ACK | 设备忙 `0x06` | ACK 成功后才更新互斥线圈影子 |
| `FC05=OFF` | 不依赖 CPU2 | 合法请求正常回显 | 只清对应本地影子，不下发停止命令 |
| `FC06 40001~40003` | 依赖 CPU2 参数 ACK | 设备忙 `0x06` | ACK 成功后才更新 `g_deviceParams` 和 `s_holding_regs`，随后立即关闭参数快照并补读四组；补读期间相交FC03/后续CPU2参数写返回忙 |
| `FC06 40004~40009` | CPU3本机兼容槽，不依赖CPU2 | FRAM保存失败返回设备忙 `0x06` | 保存成功后提交；失败恢复写前值 |
| `FC06 40010~40023` | CPU3 本机参数，不依赖 CPU2 | 仅地址/值域非法时返回相应异常 | 合法值写 CPU3 本机参数并按既有 FRAM 机制保存 |

PLC 收到 `0x06` 后应在 CPU2 完整状态快照恢复后重试原目标值，并通过 FC01/FC03 回读确认；不能把异常响应当作命令或 CPU2 参数已经落地。

## 10. 参数复用与独立边界

SI协议适配不再把所有写入都压到既有普通测量参数上，当前按“通用测量基础继续复用、SI 专用 profile/报警参数独立保存”的边界维护。

| 类型 | 字段或参数 | 归属 | 当前结论 |
| --- | --- | --- | --- |
| 通用测量基础 | `oilLevelFrequency`、`tankHeight`、`blindZone`、`oilLevelThreshold`、`oilLevelHysteresisThreshold`、`liquidLevelMeasurementMethod`、`oilLevelHysteresisTime` | CPU2 | 继续作为液位跟随、探底和测量闭环基础，不暴露 SI 寄存器语义 |
| SI profile 执行参数 | `si_profile_first_point`、`si_profile_increment`、`si_profile_dwell_time`、`si_profile_bottom_detect_interval` | CPU2 | 独立持久化；`40001~40003` 直接写入这些参数，探底频次由 CPU2 执行 profile 时消费，按进入 CPU2 SI profile 入口的触发次数计数 |
| SI 自动调度参数 | `si_auto_profile_interval`、`si_auto_profile_enable`、`si_auto_profile_hour`、`si_auto_profile_minute` | CPU3 | 独立持久化；CPU3 RTC 到点后触发 `CMD_SI_PROFILE` |
| SI 报警阈值 | `si_low_density_setpoint` 到 `si_density_deviation_setpoint` | CPU3 | 独立持久化；不复用继电器、AO、Wartsila 或普通密度测量阈值 |
| 不再作为 SI 参数源 | `spreadTopLimit`、`spreadMeasurementDistance`、`spreadPointHoverTime` | CPU2 | 仅保留普通分布测量用途，SI profile 写入不再影响这些参数 |

## 13. 当前保留约束

以下约束和优化项已单独记录到 `docs/01_协议与寄存器/SI协议适配/01_计划与需求/SI协议待确认与后续清单.md`，当前实现只覆盖已确认范围：

- SI协议描述 `Device ID = Tank ID`；当前已确认复用现有 `SlaveAddress`，不新增独立 SI Tank ID 参数。若现场后续要求单独配置 Tank ID，再作为扩展方案处理。
- 慢/中/快三个手动速度档位当前统一桥接到上行或下行命令，CPU2 暂无三档速度参数。
- 官方资料明确上下液位传感器是液/气界面判断核心状态；当前按液位跟随稳定状态合成，未接入真实双传感器硬件。
- 密度已按文档示例输出为 `0.01 kg/m3`，但 16 位寄存器最高只能表达 `655.35 kg/m3`；超过范围时会钳位到 `65535`，该限制已确认可接受。
- CPU3 RTC 优先使用 LSE，启动失败或旧板缺少 LSE 时回退 LSI；回退场景长期精度仍依赖硬件时钟源确认。
- Profile时间戳改由协议18 Point0周期事件触发。CPU3首次上线或重连无法重建事件时不补造当前时间，本周期 `30007~30010=0`。
- `10004 Interlock` 和 `10009 Reel Alarm` 维持当前简化合成，不再细分卷尺、电机、校准等报警来源。
- 官方 DCS 地址表暴露 200 个 profile 点；官方定义章节另提到设备内部最大 profile 点数 500。直接扩到 500 会影响 CPU2/CPU3 共享结构、同步寄存器、内存、循环耗时、脚本和文档；若现场 PLC 要求超过 200 点，应新增扩展地址或分页机制，而不是直接扩大原 DCS 表。
- 官方编程建议可通过监控 `30011~30013` 当前时分秒持续变化来判断通信是否正常；联调时需确认 CPU3 RTC 正常运行。
- SI协议官方手册逐项默认值仍需现场复核；当前代码采用 CPU2 首点 100mm、步距 1000mm、停留 10s、探底频次 1，CPU3 自动周期 60min、默认关闭。报警阈值 `0` 是有效值，不能再作为禁用值。
- 后续建议补充实物主机侧协议帧测试、SI协议诊断计数，并评估 `si_modbus_slave.c` 拆分和旧 `com_manager` 兼容路径取舍。

### 15.1 抓包证据边界

本节只提取站 2 数据，基于三个现场文件：第一轮完整 Profile 文件 `SaveWindows2026_7_13_星期一_12-21-21.TXT`（SHA-256 `4CDC5B3ED1E4CA5687433C6D0146BDC43847409A393497BE5B18683BE994B50F`）、专项查询文件 `SaveWindows2026_7_13_星期一_15-46-44.TXT`（SHA-256 `9472FA6C441AE3EFDB6F5B4E949768FA1ED79A931B33BF91CC1A6B21D7375A3D`）和第二轮仪器处理复测文件 `SaveWindows2026_7_13_星期一_16-36-16.TXT`（SHA-256 `FCBA73B17A836612E66D4B4002523FE3D102E80385BF9780EA3127D61AF94638`）。第三个文件是第二个文件的严格超集。完整解析、帧和时序见 `../04_联调测试/2026-07-13_SI现场抓包分析.md`。

现场主站在完整 Profile 期间只轮询 `FC04 30001~30020`，没有读取 FC01/FC02；最终状态发布后约 1.2 s 开始分块读取点阵。专项抓包再用 FC01/FC02 直接证明稳态镜像关系。由此可以确认既有上位机能够依靠 `30014~30016` 获得公开线圈/离散输入状态，但抓包不能反编译出上位机唯一的完成判断代码。

最符合时序的完成门禁是：先确认本轮已进入 Profile 或 Complete 已清零，再等待 `30015 bit4` 从 0 回到 1，同时确认 `30014` 的 Profile 位清零并返回 Auto，最后读取 `30006` 获得本轮实际点数。不能在发命令后只等待 `Complete=1`，因为真实 SI 在 Point0 完成前仍短暂保留上一轮完成位；也不能等待预期点数，因为本轮最终点数由实测液位决定，事先未知。

### 15.2 现场参数和兼容结论

站 2 实机 `FC03 40001~40023` 两次读回一致：`40001=1000 mm`、`40002=1000 mm`、`40003=20 s`、`40010=1440 min`、`40011=0`、自动时刻 `14:00`；报警阈值依次为 `399.99/500.00 kg/m3`、`-170.00/-150.00°C`、`1620/33799/1650/33650 mm`、`0.40°C` 和 `0.80 kg/m3`。位置平台约 18 s，考虑约 1.2 s 轮询边界后与 `40003=20 s` 一致，停留时间语义没有发现新冲突。

第二轮从 Profile ON 到最终发布为 46 min 45.597 s，底部仍为 345 mm、最终仍为 30 点。探头位置和液位在 `16:35:28.972` 已同为 28514 mm，但又过 20.439 s 才发布最终点数、Auto、Complete、AtLevel 和报警；该“仪器处理/最终结果生成”窗口与 `40003=20 s` 高度吻合，很可能同时包含液位点停留、最终点采样、报警计算和结果发布，不能解释为纯 CPU 运算时间。
