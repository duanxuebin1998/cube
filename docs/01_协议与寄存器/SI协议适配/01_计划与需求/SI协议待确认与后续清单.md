# SI 待确认与后续清单

日期：2026-07-02

本文合并原“说明书需求确认清单”“下一轮需求确认表”和“后续需求记录”的有效内容，作为 SI 后续确认项和优化项的唯一维护入口。已经在 2026-07-01 明确的需求不再作为待确认项重复维护，实施方案见 `SI协议需求与实施总览.md`。

2026-07-02 根据官方中文全文译稿和当前 CPU2/CPU3 实现复核后，新增“官方语义偏差与测量过程风险”清单。该清单不表示必须立即改代码，但联调前必须逐项决定：修正实现、作为受控偏差接受，或由 PLC/现场操作规程规避。

## 2. 当前仍需复核

截至 2026-07-02，本轮 SI协议进一步兼容需求的实现前关键口径已基本确认。后续重点不再是需求口径确认，而是把最新确认项同步到代码实现和联调验证：报警阈值 `0` 不再禁用、负温度阈值写入、温度无效值 `-200.00°C`、密度无效值 `0`、探底频次按触发次数计数，以及官方全文复核后新增的 Manual、Auto、Cal、Profile 生命周期偏差。

本地 `00_原始资料` 能确认串口参数、地址窗口、保留地址、缩放单位、`40011` 启停语义、`40010=1440` 日周期建议、DCS 200 点点阵窗口和有效点外返回 0；没有找到完整的 `40001~40023` 出厂默认值和非法值总表。因此当前代码默认值统一按 CUBE 工程默认记录，不写成 SI 官方出厂默认。

## 3. 2026-07-02 官方全文复核后的问题清单

| 编号 | 官方资料语义 | 当前 CUBE 实现或已确认口径 | 影响 | 建议动作 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| R-01 | Manual mode 下不报告任何报警，液位读数也不更新；系统保持 Manual，直到操作员返回 Auto/Cal/Profile | CPU2 维护/强制动作已有 `manual_alarm_inhibit` 和 `manual_level_update_inhibit`，本机继电器报警会使用该标志；但 CPU3 SI `FC02` 报警位仍在 `si_refresh_discrete_inputs_from_state()` 中按 `40014~40023` 直接合成，未按 Manual 统一清零 | PLC 可能在手动维护或强制移动期间看到 SI 报警置位，并把最后一次 `30004` 液位当成当前液位 | 若追求官方一致，CPU3 SI 层应在 Manual 或手动抑制标志有效时清除 `10017~10026/10029~10032`，并在文档中要求 PLC 只在 `10013=1` 时使用 `30004` 作为当前液位；若接受偏差，必须在 PLC 联调表中判定为受控偏差 | P0 |

| R-04 | `Probe Un-calibrated` 是判断当前位置/液位是否可信的关键状态；断电或维护后可能需要 Cal 重新建立 bottom reference | 已确认 `10010` 固定输出 `0`；探底失败且无旧底时可用当前位置继续 profile，但不刷新底部参考 | 缺少底部参考、零点或位置可信性问题时，外部 SI 主机看不到 `Probe Uncal` 风险；Point0 仍显示位置 `0`，可能被误认为真实罐底样本 | 至少把 `10001 Bottom Reference`、`10010 Probe Un-calibrated`、探底失败 fallback 和 profile complete 的关系重新定义；若不改代码，文档必须提示 `10010=0` 只是兼容固定值，不代表物理校准真实可靠 | P0 |
| R-05 | 上下 level sensor 是 SI 原机判断液/气界面的核心硬件状态 | 当前 `10002/10003` 由 CPU3 按液位跟随稳定状态合成：稳定跟随时下液体上空气，其它状态均液体；没有真实双液位传感器输入 | PLC 如果把 `10002/10003` 当作真实传感器开关，会误判液面、气相或异常状态 | 保持现有合成时，文档和联调必须说明这两个位只能作为兼容显示，不能作为真实双传感器安全联锁；若现场 PLC 强依赖，应补硬件或改映射来源 | P1 |

| R-07 | `30007~30010` 更接近首个 profile 点采集时间；Profile 开始触底后清除旧点阵和完成态 | 当前时间戳在 CPU3 收到/触发 `CMD_SI_PROFILE` 时锁存，早于 CPU2 实际触底和 Point0 采集；完成前 `30006` 和点阵保持 0 | 时间戳不能用于严格计算每点采样时间或首点时间，只能作为命令启动时间；但完成前屏蔽点阵比官方递增输出更保守 | 保留当前口径时，把字段命名为“profile 命令启动时间/测量启动请求时间”；若 PLC 需要首点时间，新增 CPU2 首点事件再锁存 | P1 |
| R-08 | Profile 以真实罐底和稳定停留点为基础；缺少 bottom reference 时应通过 Cal/Profile 重新建立 | 当前探底失败且无旧底部位置时仍使用当前位置作为底部采样目标继续本轮 profile，Point0 对外位置仍为 `0`，本轮可能仍完成 | 可保证 PLC 有一组 profile 数据，但底部坐标和全部点位都可能偏移，数据质量低于官方 SI 语义 | 联调中必须覆盖“无旧底且探底失败”场景；如果现场要求官方一致，应把该场景改成 profile 失败并置位未校准/互锁类状态，不应输出完成态 | P1 |
| R-09 | 官方资料未提供报警独立 enable 位；阈值是设定点 | 当前确认 `40014~40023` 的 `0` 是有效阈值，且默认值也为 `0`；CPU3 会按阈值直接合成报警 | 默认参数下，高密度、高温、高液位或 profile 偏差等报警可能在首次有有效数据后立即置位；这不一定符合现场“默认无报警”习惯 | 必须在现场默认参数表中给出合理阈值，或新增独立报警 enable/disable 方案；不能再把 `0` 当禁用 | P0 |

## 4. 后续优先级清单

| 温度/密度无效值落地 | 温度无效统一 `-200.00°C`，密度无效保持 0 | CPU3 SI协议转换函数、报警过滤和联调脚本 |
| 探底频次边界测试 | 已确认按进入 CPU2 SI profile 入口的触发次数计数，上电第一次必须探底 | CPU2 计数语义、探底失败、命令切换和 profile 失败后的节奏测试 |
