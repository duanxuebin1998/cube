# 水位跟随流程梳理

本文整理当前 CPU2 水位跟随实现，覆盖命令入口、找跟随点、闭环步进、稳定监测、水位值更新和异常恢复逻辑。

## 相关代码

- 命令入口：`LTD_MAIN_CPU2/Application/Src/measure.c`
- 水位测量与跟随：`LTD_MAIN_CPU2/Application/Src/measure_waterLevel.c`
- 水位接口声明：`LTD_MAIN_CPU2/Application/Inc/measure_water_level.h`
- 参数定义：`LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.h`

## 关键参数与单位

水位跟随使用水位电容作为闭环判断依据。参数在设备参数里按 `x1000` 存储，代码通过 `WaterCapRawToFloat(raw)` 转成实际电容值：

```c
return raw / 1000.0f;
```

主要参数如下：

- `water_tank_height`：水位罐高，单位 `0.1mm`。
- `water_level_mode`：水位测量方式，`0` 为慢速找水，非 `0` 为快速状态翻转找点。
- `water_cap_threshold`：水位电容阈值，实际值为寄存器值 `/1000`。
- `water_find_cap_threshold`：水位寻找电容阈值，实际值为寄存器值 `/1000`，用于闭环稳定带。
- `water_lag_cap_threshold`：水位滞后电容阈值，实际值为寄存器值 `/1000`，用于稳定监测时判断水位变化。
- `water_stable_threshold`：快速找点稳定判定的水位波动阈值，单位 `0.1mm`。
- `zero_cap` / `zero_capacitance`：空气区零点电容基准。`zero_cap` 参数存在时，代码会用 `zero_cap / 10.0` 写入 `zero_capacitance`。

## 命令入口

水位跟随命令为 `CMD_FOLLOW_WATER = 8`。`ProcessMeasureCmd()` 收到该命令后调用 `CMD_FollowWaterLevel()`。

入口流程：

1. 调用 `MeasureStart()` 初始化测量流程和电机。
2. 设置设备状态为 `STATE_FOLLOW_WATER_POINT_SEARCHING`，表示正在寻找水位跟随点。
3. 按当前 `water_level_mode` 先找一次水位点。
4. 如果当前位置源不是电机记步，则根据 `position_source_auto_switch` 决定是否自动切换到电机记步。
5. 如果实际发生了“编码轮 -> 电机记步”切换，则重新找一次水位点，避免沿用切换前的位置基准。
6. 进入闭环水位跟随。

入口伪代码：

```text
CMD_FollowWaterLevel()
    MeasureStart()
    state = STATE_FOLLOW_WATER_POINT_SEARCHING

    if water_level_mode == 0:
        SearchWaterLevel()
    else:
        FindWaterLevel_FastByStateFlip_StableExit(0)

    if 当前不是电机记步:
        EnsureMotorPositionSourceBeforeFollow()
        if 已切到电机记步:
            state = STATE_FOLLOW_WATER_POINT_SEARCHING
            重新找水位点

    if water_level_mode == 0:
        FollowWaterLevel()
    else:
        FollowWaterLevel_fast()
```

## 跟随前找点

### 慢速找水

`water_level_mode == 0` 时调用 `SearchWaterLevel()`。

流程：

1. 如果需要回零，先执行 `SearchZero()`。
2. 如果 `zero_capacitance` 为空：
   - `zero_cap == 0` 时，执行 `SearchZero()` 获取零点电容。
   - 否则使用参数 `zero_cap / 10.0` 作为零点电容。
3. 如果当前位置较深，先上行 `100mm` 作为避让。
4. 读取水位状态。如果当前已经在水区，则每次上行 `100mm`，直到退出水面；若接近零点仍在水区，则报 `MEASUREMENT_WATERLEVEL_LOW`。
5. 粗找：连续下行，直到 `check_water_status()` 判断为 `WATER`。
6. 粗找停机后等待 `3000ms`，再次确认仍为 `WATER`。确认成功后只更新临时 `water_value`。
7. 精找：先上行避让，再下行找水。接近粗找位置时分两级降速。
8. 精找成功后更新临时 `water_value`。
9. 最终调用 `WaterLevelSyncFromCable()`，正式更新 `g_measurement.water_measurement.water_level`。

慢速找水最终水位公式：

```text
water_level = water_tank_height - cable_length
```

### 快速状态翻转找点

`water_level_mode != 0` 时调用 `FindWaterLevel_FastByStateFlip_StableExit(stable_win_ms)`。

它不是长期跟随主循环，只负责给闭环跟随找一个初始跟随点。

流程：

1. 确认零点电容。
2. 读取当前水位状态：
   - 当前为 `WATER`：连续上行，直到状态翻转为 `NORMAL`。
   - 当前为 `NORMAL`：连续下行，直到状态翻转为 `WATER`。
3. 每发生一次 `WATER/NORMAL` 翻转，记录一次翻转水位：

```text
lvl_flip = water_tank_height - cable_length
```

4. 第一次翻转只缓存，不更新对外水位。
5. 第二次及以后，用最近两次翻转水位的平均值作为当前水位估计：

```text
lvl_avg = average(last_flip_lvl, lvl_flip)
```

6. 调用 `WaterLevelSetAndLog(lvl_avg)` 更新对外水位。
7. 如果 `stable_win_ms` 窗口内 `lvl_avg` 波动不超过 `water_stable_threshold`，则停机并调用 `AlignToWaterLevel_01mm(lvl_avg)` 对齐到水位附近。

入口首次找点时传入 `stable_win_ms = 0`，因此第二次翻转后基本会立即满足稳定窗口并退出，然后进入闭环跟随。丢失恢复时使用默认 `30000ms` 稳定窗口。

## 闭环步进跟随

慢速和快速模式最终都进入同一个闭环核心 `FollowWaterLevelCore()`，区别只在丢失后的恢复策略：

- `FollowWaterLevel()`：丢失后调用 `SearchWaterLevel()`。
- `FollowWaterLevel_fast()`：丢失后调用 `FindWaterLevel_FastByStateFlip_StableExit(30000)`。

闭环每 `500ms` 读取一次当前水位电容。

### 阈值计算

设：

```text
Z = zero_capacitance
A = water_cap_threshold / 1000.0
B = water_find_cap_threshold / 1000.0
L = water_lag_cap_threshold / 1000.0
```

闭环目标和稳定带：

```text
target_cap = Z + A
th_low     = target_cap - B
th         = target_cap + B
```

判断规则：

- `cap >= th`：探头偏水，电机上行。
- `cap <= th_low`：探头偏空气，电机下行。
- `th_low < cap < th`：进入稳定区，电机保持不动。

### 步长选择

进入偏水或偏空气后，代码按偏差大小选择步长。

偏水时：

```text
diff = cap - th
dir  = MOTOR_DIRECTION_UP
```

偏空气时：

```text
diff = th_low - cap
dir  = MOTOR_DIRECTION_DOWN
```

步长分档：

```text
if diff > 0.6 * A:
    step_mm = 10.0
else if diff > 0.1 * A:
    step_mm = 3.0
else:
    step_mm = 0.2
```

动作执行：

```text
MotorCtrl_MoveAndWait(step_mm, dir, MotorCtrl_GetDefaultSpeedX100())
```

也就是说，当前水位跟随是“读电容 -> 判断方向 -> 走一步 -> 等完成 -> 再读电容”的阻塞式步进闭环，不是连续速度伺服。

### 稳定区处理

当电容进入 `(th_low, th)`：

1. 清零大偏差丢失计数。
2. `stable_count++`。
3. 电机不动作。
4. 只打印当前 `water_level`，不在稳定区内实时刷新水位值。
5. 连续稳定 `WATER_FOLLOW_STABLE_MONITOR_COUNT = 5` 次后，进入稳定监测。

采样周期为 `500ms`，因此连续 5 次稳定约等于 `2.5s`。

### 长时间调节兜底

如果一直在上行/下行调节，超过 `WATER_FOLLOW_ENTER_TIMEOUT_MS = 180000ms` 仍未进入稳定区，代码会强制进入稳定监测。

这表示系统认为已经进入跟随态，但现场可能仍存在调节不到稳定带的问题，需要结合日志确认电容和位置变化。

## 稳定监测

进入 `MonitorWaterFollowChange(target_cap)` 后：

1. 设置设备状态为 `STATE_FOLLOW_WATERING`。
2. 调用一次 `WaterLevelSyncFromCable()`，锁定当前水位显示值。
3. 循环读取水位电容。
4. 计算：

```text
diff = abs(cap - target_cap)
```

5. 如果 `diff > L`，认为水位已经变化，退出稳定监测，返回闭环步进跟随。
6. 如果 `diff <= L`，电机保持不动，只打印进入监测时锁定的水位值。

因此稳定监测阶段不会持续更新水位值，只用电容偏离目标的程度判断是否需要重新开始步进。

## 丢失与恢复

每次步进动作完成后，代码做“大偏差”计数：

```text
if diff > 0.6 * A:
    lost_count++
else:
    lost_count = 0
```

当前实现里 `cap_delta` 会打印，但实际没有参与丢失条件。注释里写的是“大偏差 + 电容几乎不变”，实际代码只按“大偏差”累计。

当 `lost_count >= 5`：

1. 打印“长时间大偏差，重新找水位”。
2. 调用恢复找点：
   - 慢速模式：`SearchWaterLevel()`。
   - 快速模式：`FindWaterLevel_FastByStateFlip_StableExit(30000)`。
3. 恢复成功后清零 `lost_count`，继续闭环跟随。

## 水位值更新时机

对外水位值为：

```text
g_measurement.water_measurement.water_level
```

正式写入路径是 `WaterLevelSetAndLog()` 或 `WaterLevelSyncFromCable()`。

当前会更新水位值的时机：

1. `SearchWaterLevel()` 精找成功后的最终记录阶段。
2. `FindWaterLevel_FastByStateFlip_StableExit()` 第二次及以后状态翻转后，用最近两次翻转水位平均值更新。
3. `MonitorWaterFollowChange()` 入口，进入稳定监测时同步一次当前缆长对应的水位。
4. 水位标定完成后，修正 `water_tank_height` 并同步一次。

当前不会更新水位值的时机：

- 闭环每次步进移动完成后不更新。代码中 `UpdateWaterLevelIfValid()` 已注释。
- 闭环稳定区内不更新。代码中 `WaterLevelSyncFromCable()` 已注释。
- 稳定监测循环内不更新，只打印进入监测时锁定的值。

这意味着水位跟随长期运行时，`water_level` 更像“最近一次找点/进入稳定监测时的水位快照”，不是每一步运动后的实时水位。

## 命令切换与错误处理

水位跟随循环中多处调用 `CHECK_COMMAND_SWITCH()`。如果有新命令或取消命令，流程会通过 `STATE_SWITCH` 退出当前测量/跟随。

底层读电容、电机运动、丢步检测、停机、位置源切换等失败时，会通过 `CHECK_ERROR()` 或 `SET_ERROR()` 进入统一错误处理路径。

慢速找水的粗找和精找有重试日志：

- 粗找最多 `WATER_ROUGH_RETRY_MAX = 3` 次。
- 精找最多 `WATER_PRECISE_RETRY_MAX = 3` 次。

闭环跟随本身没有外层次数上限，正常情况下会持续运行，直到命令切换、取消或错误退出。

## 参数示例

如果现场配置为：

```text
water_cap_threshold = 7.0
water_find_cap_threshold = 0.2
water_lag_cap_threshold = 0.3
```

对应寄存器值应为：

```text
7000, 200, 300
```

设零点电容为 `Z`：

```text
target_cap = Z + 7.0
th_low     = Z + 6.8
th         = Z + 7.2
```

闭环：

- `cap >= Z + 7.2`：上行。
- `cap <= Z + 6.8`：下行。
- `Z + 6.8 < cap < Z + 7.2`：保持。

步长：

- 偏差 `> 4.2`：走 `10.0mm`。
- 偏差 `> 0.7`：走 `3.0mm`。
- 偏差 `<= 0.7`：走 `0.2mm`。

稳定监测：

- `abs(cap - (Z + 7.0)) <= 0.3`：继续不动。
- `abs(cap - (Z + 7.0)) > 0.3`：返回闭环步进。

这个参数组合下，稳定监测带宽 `0.3` 大于闭环寻找带宽 `0.2`。因此存在 `Z+6.7 ~ Z+6.8` 和 `Z+7.2 ~ Z+7.3` 两段区域：稳定监测会认为仍可保持，但闭环若运行到这里已经会触发下行或上行。现场表现可能是进入稳定监测后小幅水位变化响应偏迟。

## 当前流程要点

- 跟随前一定先找水位点，必要时切换到电机记步后再重新找点。
- 闭环靠电容双阈值判断方向，动作方式是小步进阻塞移动。
- 连续稳定约 `2.5s` 后进入稳定监测，稳定监测期间电机不动。
- 稳定监测只用电容偏差判断是否回到闭环，不持续刷新 `water_level`。
- 大偏差连续 5 次会重新找水位。
- 当前 `water_level` 不是实时连续刷新值，主要在找点完成、快速翻转估计、进入稳定监测和标定后更新。
