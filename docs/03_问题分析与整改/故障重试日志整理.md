# 错误重试、报警与最终报错日志整理

更新时间：2026-06-03

本文整理当前 CPU2 程序中与错误重试、重试成功、错误报警、最终报错、通信异常相关的主要串口打印信息，便于现场只搜索 `错误` 进行故障链路排查。普通调试信息，例如速度刷新、正常液位频率、正常扭力值等，不在本文重点范围内。

## 统一日志口径

CPU2 新增统一错误日志入口：

- `LTD_MAIN_CPU2/Services/Utilities/error_log.h`
- `LTD_MAIN_CPU2/Services/Utilities/error_log.c`

统一格式示例：

说明：统一错误日志字段之间使用制表符分隔，便于串口日志导入表格或按列查看。

```text
错误	阶段：错误重试	模块：传感器	操作：读取液位	原因：通信超时	尝试：2/3	错误码：0x000D0003	错误名：传感器通信超时
错误	阶段：重试成功	模块：传感器	操作：读取液位	原因：恢复成功	尝试：2/3
错误	阶段：错误报警	模块：电机	操作：驱动状态检查	原因：TMC5130驱动器错误	处理：停止电机	详情：全局状态：0x00000002,驱动状态：0x...
错误	阶段：最终报错	模块：电机	操作：错误出口	原因：TMC5130驱动器错误	错误码：0x000B0002	错误名：电机未知反馈	处理：停止测量	详情：文件：...,行号：...,函数：...
```

重试打印策略：

- 最大重试次数小于等于 3 时，每次重试都打印。
- 最大重试次数大于 3 时，只打印第 1 次和最后 1 次重试，避免传感器/无线通信长时间超时时刷屏。
- 如果中间某次恢复成功，仍会打印 `阶段：重试成功`，保留恢复发生的具体尝试次数。
当前阶段定义：

- `错误重试`：失败后仍会继续尝试。
- `重试成功`：前面发生过失败，后续尝试成功。
- `错误报警`：不是最终报错，但现场需要关注，通常会继续尝试或停止电机。
- `最终报错`：最终错误出口，由 `fault_manager` 统一打印。

固定模块名：

```text
电机、编码器、传感器、扭力、参数、通信、测量、系统、未知
```

## 打印出口

- CPU2 的 `printf` 通过 `LTD_MAIN_CPU2/Core/Src/usart.c` 中的 `__io_putchar()` 走 `USART1` 阻塞发送。
- CPU3 的 `printf` 通过 `LTD_DISPLAY_CPU3/Core/Src/usart.c` 中的 `__io_putchar()` 走 `USART1` 阻塞发送。
- 本轮统一主要覆盖 CPU2，CPU3 只记录现状，后续单独整理显示端/通信端错误日志。

## 最终报错出口

来源文件：

- `LTD_MAIN_CPU2/Application/Inc/fault_manager.h`
- `LTD_MAIN_CPU2/Application/Src/fault_manager.c`

当前口径：

- `CHECK_ERROR(...)` 和 `SET_ERROR(...)` 最终通过 `FaultManager_ReportErrorExit()` 打印 `阶段：最终报错`。
- 业务过程尽量不直接调用 `ErrorLog_Report()`，避免同一个错误码重复打印最终报错。
- `NO_ERROR` 和 `STATE_SWITCH` 不打印最终报错。
- 详情字段包含：`文件`、`行号`、`函数`。

示例：

```text
错误	阶段：最终报错	模块：测量	操作：错误出口	原因：搜索失败	错误码：0x000F0004	错误名：零点重复失败	处理：停止测量	详情：文件：measure_zero.c,行号：...,函数：...
```

### TMC5130 初始化写寄存器

触发路径：

- `tmc5130_initWrite()` 初始化阶段写 TMC5130 寄存器。
- 每个寄存器最多尝试 `TMC5130_INIT_WRITE_RETRY_MAX` 次。

当前打印：

```text
错误	阶段：错误重试	模块：电机	操作：驱动初始化	原因：通信失败	尝试：attempt/TMC5130_INIT_WRITE_RETRY_MAX	错误码：0x000B0002	错误名：TMC通信错误

TMC5130初始化写寄存器恢复 | 地址：0x.. | 写入值=0x........ | 尝试：attempt/TMC5130_INIT_WRITE_RETRY_MAX
```

注意：

- 初始化失败时现在会逐次打印重试，方便定位具体寄存器地址和值。
- 如果 SPI 长时间异常，初始化阶段日志量会比以前更大。

触发路径：

## 自动恢复与空闲错误兜底

来源文件：

- `LTD_MAIN_CPU2/Application/Src/app_main.c`
- `LTD_MAIN_CPU2/Application/Src/fault_recovery.c`
- `LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.c`

普通提示：

```text
自动恢复	命令切换，取消恢复
自动恢复	配置关闭，停止自动恢复
自动恢复	测量重跑次数达到上限%lu次，停止自动重跑，错误码=0x%08lX
```

当前错误日志：

```text
错误	阶段：错误报警	模块：系统	操作：自动恢复	原因：进入自动恢复	处理：继续尝试
错误	阶段：错误重试	模块：系统	操作：自动恢复	原因：自动恢复失败	尝试：1/1	错误码：check_ret	错误名：ErrorLog_GetCodeName(check_ret)
错误	阶段：重试成功	模块：系统	操作：自动恢复	原因：恢复成功	尝试：s_fault_recovery.command_retry_count/retry_limit
错误	阶段：错误报警	模块：系统	操作：自动恢复	原因：自动恢复失败	处理：停止测量
```

说明：

- 自动恢复只对允许恢复的测量命令生效。
- `fault_auto_recovery_retry_limit` 控制恢复确认成功后的原命令自动重跑次数：`0` 关闭，`1~10` 为最大次数，默认 `3`，大于 `10` 按默认值恢复。
- 命令切换属于用户主动打断，只打印普通提示，不进入 `ErrorLog_*` 错误日志。
- 恢复检查失败时保持原错误状态。
- 恢复检查失败的尝试数仍按 `1/1` 记录，因为每个周期只做一次恢复确认。
- 恢复成功后重新执行完整测量命令，重跑次数使用 `s_fault_recovery.command_retry_count/retry_limit` 记录。
- 到达自动重跑上限后保留错误态并停止继续重跑。

## 维护注意事项

- 每个新增 `ErrorLog_*` 调用前保留一行中文注释，注释内容写出实际打印字段。
- 错误重试和重试成功保留在业务路径；最终报错交给 `fault_manager` 统一出口。
- ISR 或 ISR 直接调用链里不要直接新增 `printf` 或 `ErrorLog_*`，需要延迟到主循环打印。
- 修改含中文的 CPU2 源码时注意编码：GBK 文件按 GBK/936 读写，UTF-8 文档按 UTF-8 维护。
- 提交前同时检查工作区和暂存区，避免工作区已修复但暂存区仍保留旧乱码。
