1. 总体结论

电机程序的核心分层比较清晰：业务命令和测量流程调用 MotorCtrl_* 上层接口；MotorControl 内部再分为运动 API、驱动参数/健康检查、位置模型、丢步检测和尺带拟合；最底层由 TMC5130.c 负责 SPI 寄存器访问和步进驱动器控制，AS5145.c 与 encoder.c 负责外部编码轮采集与位置换算。

2026-06-13 当前 MAIN 工作区在第一轮结构优化基础上继续收敛点动和位置模式：MotorMotionTargetPlan 统一相对/绝对目标规划，MotorMotion_CheckReadyForProtectedMotion()、MotorMotion_CheckCommandAbortWithSpeedScope()、MotorMotion_WaitMoveStartObservation()、MotorMotion_CheckJogRuntimeGuards()、MotorMotion_CheckAbortRefreshAndHealth() 和 MotorMotion_CheckStoppedAndRefresh() 收敛入口门控、命令切换、正式运动启动观察、Jog 单轮运行保护、等待循环公共运行检查和停稳后刷新收尾；第三轮策略评估结论是继续保留正式位置模式和 Jog 点动速度模式各自执行策略，不用 Jog 默认替换 MotorCtrl_MoveToPosition()。台架验证仍以《电机运动函数台架验证记录.md》为准，本文不宣称本轮实物验证已经完成。

正常业务运动

CMD_MoveUp()、CMD_MoveDown()、液位/密度/罐底等测量流程主要走 MotorCtrl_MoveAndWait() 或 MotorCtrl_MoveToPosition()，入口目标先由 MotorMotionTargetPlan 统一规划，执行仍走正式位置目标模式；临时速度由 MotorMotionSpeedScope 统一恢复。

调试和强制运动

A、B、BE、BJ/BJP、C/D/E/M/N 等串口调试路径会部分绕开正式测量初始化或保护检测。MotorCtrl_MoveBlockingNoDetectForceDebug() 只绕过编码器首帧门控；BJ/BJP 调用 Jog 接口验证主动位置反馈和提前减速方案。

位置源

系统支持编码轮记步和电机记步两套位置源。编码轮模式由 encoder_get_cable_length_01mm() 换算尺带长度；电机记步模式由 TMC5130_XACTUAL、卷筒模型和切换基准推算业务位置。

关键安全边界

运动前统一经过 MotorDriver_CheckMotionReady() 和 MotorDriver_CheckHealth()；运行中持续调用 MotorDriver_SyncPositionOrCheckHealth()、MotorCtrl_PollRuntimePosition()、MotorCtrl_CheckLostStepAutoTiming() 等接口。Jog 路径还会通过当前有效位置源判断剩余距离、减速距离和越界风险。

11. 保护、恢复和易错点

电机相关改动最容易出问题的地方不是单个函数，而是绕开了已有边界：运动前门控、命令切换打断、TMC5130 掉电/复位恢复、编码器首帧有效门控、位置源切换回滚和 FRAM 持久化。

风险点涉及函数检查建议
未初始化或 24V 功率级未建立时下发运动MotorDriver_CheckMotionReady()、MotorDriver_CheckHealth()、stpr_checkDriverPowerReady()新增运动入口必须经过 MotorControl 上层门控，除非明确是受控低检测测试。
命令切换时电机未停稳CHECK_COMMAND_SWITCH_AND_STOP、MotorDriver_StopIfCommandSwitchRequested()、MotorDriver_StopAndMarkStopped()长循环和等待循环要持续检查命令切换，返回 STATE_SWITCH 前先停机。
异常返回时临时速度未恢复MotorMotionSpeedScope、MotorMotion_ReturnWithSpeedScope()、MotorMotion_CheckErrorWithSpeedScope()新增带临时速度的运动路径必须通过 scope 收尾；若提前调用故障处理，也要先恢复默认速度。
编码轮未首帧有效导致位置盲区Encoder_IsReady()、AS5145_HasValidSample()、MotorDriver_CheckMotionReady()普通运动不能绕过首帧门控；强制调试路径要在文档和日志中明确。
主动位置反馈使用了错误位置源MotorCtrl_RefreshPositionFromActiveSource()、MotorCtrl_SnapshotSensorPositionMm()、MotorMotion_RefreshActivePositionMm()Jog、绝对位置和密度流程都应按当前记步源刷新位置；切换位置源后要重新确认快照来源。
Jog 速度模式接近目标时过冲MotorMotion_CalcJogSlowdownDistanceMm()、MotorMotion_CalcJogStopDistanceMm()、MotorMotion_StopJogAndRestore()调整速度、加减速或卷筒模型后，必须复核减速距离、最终停机距离和越界阈值。
未经 A/B 数据替换正式绝对位置策略MotorCtrl_MoveToPosition()、MotorCtrl_JogMoveToPosition()、MotorMotion_JogMoveToTargetInternal()第三轮策略评估结论是暂不替换默认路径；只有补齐同目标、同速度、同起点对比和故障注入后，才允许进入可回退实验。
TMC5130 单帧异常 XACTUAL 污染位置MotorPosition_FilterXactualGlitch()、MotorPosition_TryUpdateDrumStateFromXactual()读取异常时二次确认，不要直接更新缓存和 FRAM。
位置源切换失败留下半更新状态MotorCtrl_SwitchPositionSourceToMotor()、MotorPosition_RollbackPositionSourceSwitch()切换失败必须回滚旧模式、旧局部周长、基准和错误码。
调试无检测运动误用于正式流程MotorCtrl_MoveBlockingNoDetect()、MotorCtrl_MoveBlockingNoDetectForceDebug()正式测量流程优先使用 MotorCtrl_MoveAndWait() 或 MotorCtrl_MoveToPosition()。

阅读结论

核心层次已经形成

公开入口由 MotorCtrl_* 承担，目标计算由 MotorMotionTargetPlan 和两个 Build 函数统一，执行策略再分成正式位置、Jog 速度、ticks 和无检测四类。

点动和位置模式不应硬合并

二者共享“当前位置信息、目标位置、方向、剩余距离”的规划结果，但驱动下发方式不同。正式模式走 MoveNoWait 和到位等待；Jog 模式走速度模式、减速距离和主动停机。

后续优化重点在拆小循环

MotorMotion_JogMoveToTargetInternal 仍是最长函数，后续可把“启动前准备、循环判定、减速切换、停机出口”继续拆出，降低评审和台架定位成本。

MotorCtrl_JogMoveAndWait Jog 相对 运行前检查 -> 刷新当前位置 -> 相对目标规划 -> JogMoveToTargetInternal 需要用速度点动完成相对距离运动时使用。 目标规划和正式距离共用，但执行策略完全不同。
MotorCtrl_JogMoveToPosition Jog 绝对 目标范围检查 -> 刷新当前位置 -> 绝对目标规划 -> JogMoveToTargetInternal 长距离或需要更平滑减速的绝对位置运动实验入口。 以有效位置源闭环判断剩余距离，越界或位置异常直接退出。
MotorCtrl_MoveByTicksAndWait ticks ticks 参数 -> 临时速度 -> 等待 XACTUAL 变化 -> 等待目标 ticks 校准、位置源切换和底层 ticks 验证。 不经过 MotorMotionTargetPlan，评审时不要把它归入位置规划链路。
MotorCtrl_MoveBlockingNoDetect
MotorCtrl_MoveBlockingNoDetectForceDebug		 无检测 距离转 ticks -> 下发运动 -> 守护等待 -> 驱动同步 编码器不可用或调试强制运动。 可以忽略编码器就绪，但不应忽略驱动健康、命令切换和超时。

MotorCtrl_SlowStop		 停机 命令切换保护 -> 停机命令 -> 同步/状态清理 外部命令、异常处理或调试停机。 停机动作要和显示活动态、速度恢复、驱动状态保持一致。

共享目标规划层

本轮优化后，正式模式和 Jog 模式的共同部分被压缩到 MotorMotionTargetPlan。 该结构只回答“从哪里开始、到哪里结束、朝哪个方向、还有多少距离、是否已经到位”，不决定使用位置模式还是速度模式。

字段 含义 由谁填充 被谁消费
start_mm 规划时的当前有效位置。 相对规划使用入口传入 start；绝对规划使用 current。 正式模式用于运动后位移差核对；Jog 用于启动前目标确认。
target_mm 最终目标绝对位置。 相对规划按方向加减距离；绝对规划直接使用 target。 正式等待和 Jog 循环都用它判断到位、越界和停机。
distance_mm 需要执行的正数距离。 相对规划等于 move；绝对规划等于 fabs(target-current)。 正式模式下发 MoveNoWait；Jog 用于启动目标。
dir 向上或向下运动方向。 相对规划沿用入口参数；绝对规划按 delta 正负选择。 显示状态、剩余距离、越界判断和驱动方向。
already_reached 目标已经在允许误差内，无需运动。 相对距离小于等于 0 或绝对目标误差内。 绝对入口直接返回成功；相对入口通常在入口参数处提前返回。

相对规划

  1. 入口先校验 move_mm > 0 和方向合法。
  2. 调用 MotorMotion_RefreshActivePositionMm 获取当前有效位置。
  3. MotorMotion_BuildRelativeTargetPlan 检查位置快照有效性。
  4. 按方向得到 target_mm，再用 MotorMotion_CheckAbsoluteTargetRange 检查目标范围。
  5. 正式距离和 Jog 相对入口各自选择自己的执行策略。

绝对规划

  1. 入口先调用 MotorMotion_CheckAbsoluteTargetRange 检查目标 mm。
  2. 刷新当前有效位置，异常快照返回 MEASUREMENT_POSITION_ERROR。
  3. MotorMotion_BuildAbsoluteTargetPlan 计算 delta、方向和剩余距离。
  4. 误差小于 eps 时设置 already_reached 并返回成功。
  5. 正式绝对入口分轮调用 MoveAndWait，Jog 绝对入口进入 Jog 内核。
分层边界： 目标规划层不接触 TMC5130 寄存器、不下发速度、不等待停机。这样后续无论正式模式还是 Jog 模式调整执行策略，都不需要重复修改方向和目标范围判断。

正式位置模式链路

MotorCtrl_MoveAndWait(mm, dir, speed)

  1. 参数层：距离小于等于 0 直接成功，方向非法返回 PARAM_ERROR。
  2. 运行前：MotorMotion_CheckReadyForProtectedMotion(false, false)，允许后续等待过程中再做健康轮询。
  3. 速度域：MotorMotion_BeginSpeedScope 记录并应用临时速度。
  4. 目标规划：刷新有效位置，调用 MotorMotion_BuildRelativeTargetPlan 得到 start、target 和 distance。
  5. 执行：调用 MotorCtrl_MoveNoWait(distance, dir, 0U) 下发正式位置模式。
  6. 观察：设置活动显示态，调用 MotorMotion_WaitMoveStartObservation 避免刚下发未启动的误判。
  7. 等待：MotorMotion_WaitUntilStopWithTarget 按目标位置、误差和方向等待到位/停机。
  8. 收尾：刷新位置、计算实际位移差、做丢步判断、同步驱动、清活动态、恢复速度。

MotorCtrl_MoveToPosition(target, speed)

  1. 先检查目标绝对位置是否在 0 ~ tankHeight 范围。
  2. 检查驱动运动就绪，进入临时速度域。
  3. 最多循环 10 次，每轮先检查命令切换，再刷新当前有效位置。
  4. 调用 MotorMotion_BuildAbsoluteTargetPlan 计算剩余距离和方向。
  5. 如果已经到位，恢复速度后返回成功。
  6. 如果未到位，将过小距离抬到 EPS_MM * 2，再调用 MotorCtrl_MoveAndWait。
  7. 每一轮都重新取当前位置，抵消位置更新滞后和累计误差。

Jog 点动速度模式链路

Jog 模式不是“正式位置模式的另一层包装”，它是使用目标规划结果驱动速度模式的另一套执行策略。 关键差异是：它不会一次性把 XTARGET 作为最终控制目标，而是在循环中根据有效位置源持续计算剩余距离，接近目标时主动减速和停机。

Jog 相对入口

  1. MotorCtrl_JogMoveAndWait 校验距离和方向。
  2. MotorMotion_CheckReadyForProtectedMotion(false, true) 运行前检查驱动健康。
  3. 刷新当前有效位置。
  4. 复用 MotorMotion_BuildRelativeTargetPlan 得到目标。
  5. 调用 MotorMotion_JogMoveToTargetInternal。

Jog 绝对入口

  1. MotorCtrl_JogMoveToPosition 先检查绝对目标范围。
  2. 运行前检查和当前位置刷新。
  3. 复用 MotorMotion_BuildAbsoluteTargetPlan，误差使用 MOTOR_JOG_POSITION_EPS_MM。
  4. 已到位直接成功。
  5. 未到位进入 MotorMotion_JogMoveToTargetInternal。

14. 问题点与整改建议

当前分支以结构收敛为主，未改变默认运动策略。以下问题不是本次新增 bug，而是后续评审和台架验证需要优先收敛的风险点。

问题点影响源码依据建议
默认绝对位置策略是否替换为 Jog 证据不足 Jog 更依赖主动位置反馈和减速模型，直接替换可能改变正式业务到位、过冲和错误收尾语义。 MotorCtrl_MoveToPosition()
MotorCtrl_JogMoveToPosition()		 先完成同目标、同速度、同起点 A/B 对比，再考虑可回退实验开关。
台架 200mm 下限尚未定义为产品边界 测试规程限制和固件边界不一致时，现场容易误以为代码已经保护 200mm。 MotorMotion_CheckAbsoluteTargetRange() 当前使用 0..tankHeight 本分支保持为台架限制；若要固化，另开分支评估兼容、参数化和显示/协议文档。
T15/T16 故障注入未覆盖当前分支 本地构建和结构脚本不能证明编码器首帧缺失、TMC/24V 异常时的真实停机表现。 MotorMotion_CheckReadyForProtectedMotion()
MotorMotion_CheckAbortRefreshAndHealth()		 按剩余台架验证规程补测，记录返回码、日志、停止位置和是否恢复重跑。
无检测路径容易被误用 该路径缺少完整目标窗口、撞底、丢步和主动位置闭环，不适合作为正式测量运动。 MotorMotion_MoveBlockingNoDetectInternal() 文档和测试命令继续标注“受控调试/特定罐底流程”，必要时加运行权限或日志提示。
位置源切换失败会影响后续所有位置判断 电机记步基准、局部周长或 FRAM 快照污染后，后续目标规划会基于错误位置。 MotorCtrl_SwitchPositionSourceToMotor()
MotorPosition_RollbackPositionSourceSwitch()		 继续保留失败回滚；台架验证 YM 时记录旧模式、新模式、实测周长和回滚结果。

优先整改顺序：先补 T15/T16 和 A/B 对比数据；再决策 200mm 下限是否产品化；最后才进入默认运动策略替换或无检测权限收紧。

命令切换打断 正式运动、ticks、无检测、Jog 和停机等待均保留命令切换检查。 台架回归时记录返回码、停机时机和速度恢复。
