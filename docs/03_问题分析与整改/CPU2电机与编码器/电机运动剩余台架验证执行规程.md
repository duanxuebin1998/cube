# 电机运动剩余台架验证执行规程

更新日期：2026-06-12

## 1. 目的和边界

本文用于补齐当前计划中仍未覆盖的外部验证项：

- T15：编码器首帧缺失。
- T16：TMC5130、驱动或 24V 故障。
- `200mm` 台架下限是否需要固化为固件目标边界。
- 正式位置模式与 Jog 速度模式 A/B 对比。

本文只给出台架人工执行规程和记录格式，不通过 Codex 远程制造硬件故障，不自动下发危险运动命令，不把未执行项写成通过。

## 2. 通用安全前提

执行前必须满足：

- 现场人员在设备旁，能立即急停、断电或拔掉驱动供电。
- 传感器位置保持在 `200mm <= 当前位置 <= 1000mm`。
- 先记录 `YS`、`YC` 输出，确认位置源、驱动静止状态、`VACTUAL=0`、错误码和当前高度。
- 串口为 `COM12 / 115200 / GBK`，完整保存命令、返回码和日志。
- 当前固件来自 `D:\CUBE\.worktrees\motor-motion-structure`，并记录分支、提交号、是否有未提交 diff。
- 每个动作前确认目标位置不会越过机械上限 `1000mm` 或下限 `200mm`。

建议每个场景前后执行：

```text
YS
YC
```

记录字段：

```text
日期：
操作者：
分支/提交：
是否有未提交 diff：
固件版本：
位置源：
起点：
目标：
终点：
返回码：
device_state / error_code：
关键日志：
结论：通过 / 失败 / 未覆盖
```

## 3. T15 编码器首帧缺失

### 3.1 目标

验证普通正式运动不能在编码器首帧不可用时先下发运动；强制路径只能绕过编码器首帧，不能绕过驱动初始化和健康检查。

### 3.2 人工准备

任选一种可恢复方式制造首帧缺失：

- 断开或遮挡编码器采样，使 `Encoder_IsReady()` 或 `AS5145_HasValidSample()` 不能成立。
- 若有调试固件或调试器入口，可清除首帧有效标志，但不得绕过驱动健康状态。

恢复条件：

- 编码器接线和采样恢复后，`YS` 能重新显示有效位置。
- 若需要复位设备，复位后必须重新记录 `YS` 和 `YC`。

### 3.3 正式路径步骤

建议选择当前附近小距离，避免触碰 `200mm/1000mm` 限位：

```text
1. 记录 YS 和 YC。
2. 制造编码器首帧缺失。
3. 执行正式上行或下行小距离命令，例如 CMD_MOVE_UP / CMD_MOVE_DOWN，距离 20mm。
4. 观察是否拒绝运动。
5. 恢复编码器。
6. 再执行 YS / YC，确认驱动静止且位置未发生危险变化。
```

通过条件：

- 正式路径返回运动就绪或编码器未就绪相关错误。
- 驱动不进入持续运动状态。
- 不能出现绕过首帧后继续正式测量运动的情况。

失败条件：

- 首帧缺失时正式路径仍下发持续运动。
- 出现无法命令切换停机、无法急停或位置越过安全范围。

### 3.4 强制路径步骤

```text
1. 记录 YS 和 YC。
2. 制造编码器首帧缺失。
3. 执行 CMD_FORCE_MOVE_UP 或 CMD_FORCE_MOVE_DOWN，小距离 20mm。
4. 观察返回码、驱动健康检查日志和终点。
5. 恢复编码器并执行 YS / YC。
```

通过条件：

- 强制路径允许绕过编码器首帧。
- 仍必须执行 TMC 初始化、驱动通信和 24V 健康检查。
- 运动距离受控，终点仍在 `200mm~1000mm` 内。

## 4. T16 TMC5130、驱动或 24V 故障

### 4.1 目标

验证正式运动在 TMC5130 通信异常、驱动状态异常或 24V 功率级异常时不会继续运行，并返回驱动健康相关错误。

### 4.2 故障注入方式

任选一种可恢复方式：

- 人工断开或关闭 24V 驱动功率级。
- 人工制造 TMC5130 SPI 通信异常。
- 人工触发驱动故障状态，例如过温、欠压或驱动状态异常。

不建议：

- 不在电机运行高速阶段直接拔插关键线束。
- 不让传感器接近 `200mm` 或 `1000mm` 后再制造故障。
- 不在无人值守状态执行。

### 4.3 正式运动步骤

```text
1. 记录 YS 和 YC，确认当前静止。
2. 制造 TMC/驱动/24V 故障。
3. 执行 CMD_MOVE_UP 或 CMD_MOVE_DOWN，小距离 20mm。
4. 记录返回码、错误日志、device_state 和 error_code。
5. 执行 YC，确认驱动没有持续运动。
6. 恢复硬件故障。
7. 复位或重新初始化后执行 YS / YC。
```

通过条件：

- 返回驱动健康、TMC 通信、功率级未就绪或初始化相关错误。
- 电机不进入危险持续运动。
- 故障恢复后可重新读到静态驱动状态。

失败条件：

- 故障存在时仍继续正式运动。
- 错误码与日志显示正常完成。
- 恢复后状态无法清理，或者必须通过非预期手段才能停机。

## 5. `200mm` 台架下限决策验证

### 5.1 当前事实

当前固件目标范围仍按 `0~tankHeight` 判定。`200mm` 是本次台架安全限制，尚未确认是否应固化成固件边界。

### 5.2 决策选项

| 选项 | 含义 | 影响 |
| --- | --- | --- |
| 只作为台架限制 | 固件仍允许 `0~tankHeight` 内目标，台架测试不下发低于 `200mm` 的目标 | 不改变固件行为，文档继续标注测试限制 |
| 固化为产品边界 | 固件目标范围新增下限 `200mm` 或参数化下限 | 属于 CPU2 行为变化，需要版本升级、参数/协议影响评估和完整回归 |
| 做成可配置参数 | 下限由参数决定，现场可配置 | 涉及参数语义和存储兼容性，需评估 `DEVICE_PARAM_VERSION` |

### 5.3 建议结论

在没有产品需求确认前，建议保持 `200mm` 为台架限制，不改固件默认目标范围。

若决定固化为固件边界，必须先新增需求和版本测试方案，再进入代码实现。

## 6. 正式位置模式与 Jog 速度模式 A/B 对比

### 6.1 目标

验证是否有足够数据支持用 Jog 速度反馈策略替换或影响默认 `MotorCtrl_MoveToPosition()`。当前结论是不替换默认策略；本节用于后续采集证据。

### 6.2 测试矩阵

建议每组同起点、同目标、同速度分别执行正式位置模式和 `BJP`：

| 目标位置 | 方向 | 速度 | 位置源 | 备注 |
| --- | --- | --- | --- | --- |
| `250mm` | 下行 | `0.3m/min`、`1.0m/min` | 编码轮记步 | 接近台架下限，需现场确认安全 |
| `500mm` | 上行/下行 | `0.3m/min`、`1.0m/min` | 编码轮记步 | 中间安全点 |
| `700mm` | 上行/下行 | `0.3m/min`、`1.0m/min` | 编码轮记步 | 覆盖已验证区域 |
| `950mm` | 上行 | `0.3m/min`、`1.0m/min` | 编码轮记步 | 接近高位限制，需保守距离 |

如需覆盖电机记步模式，先执行位置源切换验证，再重复同一目标矩阵。

### 6.3 单组步骤

```text
1. 执行 YS / YC，记录起点。
2. 用正式位置模式执行目标位置，例如 CMD_RUN_TO_POSITION。
3. 记录终点、误差、耗时、返回码和关键日志。
4. 回到同一起点附近，或选择对称目标重新建立可比起点。
5. 用 BJP<目标>,<速度> 执行同一目标。
6. 记录终点、误差、耗时、是否提前停机、返回码和关键日志。
7. 比较两种模式的偏差、过冲、耗时和异常表现。
```

### 6.4 判定

不能只凭单次 `BJP650,1.0` 或 20mm 小行程数据替换默认策略。

进入代码实验前至少需要：

- 同方向、同目标、同速度的正式/Jog 对比数据。
- 多速度覆盖。
- 长距离覆盖。
- 命令切换和故障路径覆盖。
- 明确对生产节拍的影响。
