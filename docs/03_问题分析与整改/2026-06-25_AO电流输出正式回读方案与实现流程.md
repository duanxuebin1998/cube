# AO电流输出正式回读方案与实现流程

## 1. 结论

当前 AO 电流输出只保留正式回读方案：

- AD5421 初始化必须写控制寄存器并回读 `READCONTROL` 校验。
- 电流写入后通过 `READFAULT` 读取芯片故障寄存器确认状态。
- 当前 PCB 上 AD5421 第 7 脚 `FAULT` 未接入 MCU PB8，PB8 悬空，因此固件不再把 PB8 作为 AD5421 故障来源。
- 临时引入的旧式只写调试入口已删除，串口 AO 测试指令也改为正式回读路径。

现场判定口径：如果串口日志中 `formal init=0x00000000` 且每次写入日志 `write=0x00000000 diag=0x00000000 fault=0x0000 flags=0x00000000`，说明控制寄存器回读、故障寄存器回读和 DAC 写入流程均通过。实际电流仍需在 `P420PW_WAIBU` 或 `P420PW_NEIBU` 到 `P420-` 的负载回路上实测确认。

## 2. 硬件边界

### 2.1 电流环接线

原理图第 4 页显示 AD5421 输出经过 HART/保护网络接到外部回路：

- `VCC-24` 分到 `P420PW_NEIBU` 和 `P420PW_WAIBU` 两路正端。
- AD5421 `LOOP-` 侧接到 `P420-` 回流负端。
- 验证电流输出时，负载电阻或电流表应接在某一路 `P420PW_*` 正端与 `P420-` 之间，不应接在 `P420PW_NEIBU` 和 `P420PW_WAIBU` 之间。

### 2.2 PB8/FAULT

原理图和 PCB 实物确认：

- CPU2 MCU 页 PB8 标为 `FAULT`。
- AD5421 页第 7 脚 `FAULT` 是短悬线，没有和 MCU 侧 PB8 网络形成连接。
- 当前 PCB 上 PB8 悬空，不代表 AD5421 故障状态。

因此当前正式方案只使用 SPI 读取 `READFAULT` 寄存器，不合并 PB8。历史 `AD5421_FAULT_FLAG_PIN` 位保留为兼容运行态字段，但在诊断中清零，避免悬空脚污染 `driver_fault_flags`。

## 3. AD5421 底层流程

### 3.1 SPI 访问

文件：`LTD_MAIN_CPU2/BSP/Peripherals/src/ad5421.c`

- `AD5421_WriteReg(reg, value)`：片选拉低，SPI3 发送 3 字节写帧，失败置 `AD5421_FAULT_FLAG_SPI_WRITE` 并返回通信错误。
- `AD5421_ReadRegChecked(reg, value)`：先发送读命令帧，再用 `NOOPAD5421` 哑帧收回 3 字节数据；失败置 `AD5421_FAULT_FLAG_SPI_READ`。
- 所有 AD5421 SPI 阻塞访问使用 `AD5421_SPI_TIMEOUT_MS = 10ms`，不使用 `HAL_MAX_DELAY`。

### 3.2 初始化回读

`Ad5421Init()` 的正式顺序：

1. 清 `ad5421_fault_flags` 和 `ad5421_fault_register`。
2. `ResetAD5421()` 软件复位，并延时 1ms。
3. `WriteControlRegister(CUR_SPIOFF_READBACK_COMMAND)` 写控制寄存器。
4. `WriteControlRegister()` 立即读取 `READCONTROL`，要求回读值与写入值一致。
5. 写入初始电流 `g_deviceParams.InitialCurrent_mA`。
6. 延时 10ms。
7. 调用 `AD5421_PollDiagnostics()` 读取 `READFAULT`。

控制寄存器值使用：

- `CUR_SPIOFF_COMMAND = 0x1000`：关闭 SPI 看门狗。
- `CUR_AUTO_FAULT_READBACK_OFF_COMMAND = 0x0800`：禁止自动 fault 回读，允许专用寄存器回读。
- `CUR_SPIOFF_READBACK_COMMAND = 0x1800`。

如果 `READCONTROL` 读失败，返回 `AD5421_INIT_ERROR`；如果回读值不一致，返回 `AD5421_READBACK_ERROR`。

### 3.3 电流换算与写入

`AD5421_SetCurrentX100(mA_x100)` 将参数单位从 0.01mA 转为 float mA，并进入 `AD5421_SetCurrent()`：

1. 将输入钳位到 AD5421 硬件允许范围 `3.2mA..24.0mA`。
2. 按 `(mA - 3.2) / (24.0 - 3.2)` 换算到 16 位 DAC。
3. 通过 `WRITEDAC` 写入 AD5421。
4. 写失败返回 `AD5421_WRITE_CURRENT_ERROR`。

注意：DAC 写入本身没有 DAC 数据寄存器回读校验；正式链路依靠初始化控制寄存器回读、写返回值、周期 `READFAULT` 和外部电流实测共同闭环。

### 3.4 故障诊断

`AD5421_PollDiagnostics()` 只做两件事：

1. 读取 `READFAULT`，更新 `ad5421_fault_register`。
2. 若 `READFAULT != 0`，置 `AD5421_FAULT_FLAG_STATUS` 并返回 `AD5421_READFAULT_ERROR`。

它不会读取 PB8，也不会因为 PB8 高电平报 `AD5421_FAULT_PIN_ERROR`。

## 4. AO 服务流程

文件：`LTD_MAIN_CPU2/Services/AoOutput/ao_output.c`

### 4.1 初始化入口

`App_Init()` 在参数、HART、称重、Modbus、继电器初始化后调用 `AoOutput_Init()`。若 AO 初始化失败，启动阶段记录错误码，并由后续统一错误流程处理。

`AoOutput_Init()`：

1. 标记 AO 服务已初始化。
2. 如果 `AoOutputEnable == 0`，发布禁用运行态，不访问 AD5421。
3. 如果 AO 使能，调用 `AoOutput_EnsureDriverReady()`。
4. 驱动就绪后进入一次 `AoOutput_Update()`。

### 4.2 周期刷新入口

TIM4 中断现在只与继电器同节拍提出 AO 刷新请求：TIM4_IRQHandler() 先调用 RelayOutput_Update()，再调用 AoOutput_RequestTimerRefreshFromTim4Isr() 置位请求并挂起 PendSV。主循环里的周期 AO 刷新已移除，避免主循环阻塞时 AO 长时间不更新；部分测量流程保留主动刷新入口，作为测量过程中的额外安全点。

PendSV_Handler() 以最低优先级调用 AoOutput_ProcessPendingTimerRefresh()，在延后上下文中执行正式 AD5421 写入、控制/故障回读和运行态更新。TIM4 中断不访问 AD5421、不做 SPI、不打印、不调用 FaultManager_SetErrorState()；PendSV 中若检测到错误，只写入 AO 运行态和 g_measurement.device_status.error_code，后续由系统全局错误兜底统一处理。AO 服务和 AD5421 驱动均增加重入保护，避免串口测试、测量流程与 PendSV 同时访问 SPI。PendSV_IRQn 优先级设置为 15，TIM4_IRQn 保持原优先级 0，SysTick 优先级调到 4，保证 PendSV 中的 HAL SPI 超时计数仍可推进。
刷新顺序：

1. AO 未初始化：直接返回。
2. AO 未使能：清驱动就绪、诊断节流和写入重试状态，发布禁用运行态。
3. AO 使能：`AoOutput_EnsureDriverReady()` 确保 AD5421 初始化成功。
4. `AoOutput_PollDiagnosticsThrottled()` 按 1000ms 节流读取 `READFAULT`。
5. 诊断正常后，按优先级选择目标电流。
6. 判断是否需要写入 AD5421：目标变化立即写；目标不变则 1000ms 周期刷新；上次写失败则按周期重试。
7. 更新 `AoOutputRuntime`，供 Modbus/CPU3/HART 查看。

### 4.3 目标电流优先级

`AoOutput_SelectTarget()` 的输出优先级：

1. 系统存在真实错误码且不是 `STATE_SWITCH`：输出 `FaultCurrent_mA`，来源 `AO_OUTPUT_SOURCE_FAULT`。
2. 设备处于调试模式：输出 `DebugCurrent_mA`，来源 `AO_OUTPUT_SOURCE_DEBUG`。
3. 液位有效：按液位线性映射 `CurrentRangeStart_mA..CurrentRangeEnd_mA`，来源 `AO_OUTPUT_SOURCE_LEVEL`。
4. 液位输出后，如果继电器高高/高报警有效，覆盖为 `AOHighCurrent_mA`；如果低低/低报警有效，覆盖为 `AOLowCurrent_mA`。
5. 没有有效液位：输出 `InitialCurrent_mA`，来源 `AO_OUTPUT_SOURCE_INIT`。

业务正常量程参数会先限制在 `4.00mA..20.00mA`；硬件输出、故障、调试和报警电流最终限制在 `3.20mA..24.00mA`。

## 5. 串口验证指令

文件：`LTD_MAIN_CPU2/Application/Src/test.c`

当前保留命令：

- `AO400`：正式回读路径输出 4.00mA。
- `AO1200`：正式回读路径输出 12.00mA。
- `AO2000`：正式回读路径输出 20.00mA。
- `AO2200`：正式回读路径输出 22.00mA。
- `AOS`：依次输出 4.00mA、12.00mA、20.00mA、22.00mA，每点保持 5s，每 500ms 刷新一次。

AO 测试指令执行期间会调用 `AoOutput_SuspendTimerRefresh()` 暂停 TIM4 请求和 PendSV 延后刷新，避免测试点电流被运行态目标电流覆盖；退出测试命令前调用 `AoOutput_ResumeTimerRefresh()` 恢复。继电器刷新不受影响。

每个点的流程：

1. 调用 `Ad5421Init()`，完成控制寄存器写入和 `READCONTROL` 回读。
2. 打印 `AO FORMAL formal init=... fault=... flags=... current_x100=...`。
3. 初始化成功后循环写 `AD5421_SetCurrentX100()`。
4. 每次写入成功后调用 `AD5421_PollDiagnostics()` 读取 `READFAULT`。
5. 打印 `write/diag/fault/flags/elapsed`。

正常日志示例：

```text
AO FORMAL	formal init=0x00000000	fault=0x0000	flags=0x00000000	current_x100=400
AO FORMAL	write current=4.00mA	write=0x00000000	diag=0x00000000	fault=0x0000	flags=0x00000000	elapsed=0ms
```

如果 `formal init` 非 0，优先看控制寄存器回读打印；如果 `diag` 非 0，优先看 `fault` 原始值；如果软件全部为 0 但外部没有电流，优先检查负载回路、接线端子、外部 24V 和电流表位置。

## 6. 运行态与对外读取

`AoOutputRuntime` 通过 CPU2 Modbus 输入寄存器发布：

- `target_mA_x100`：当前目标电流。
- `last_sent_mA_x100`：最近成功写入 AD5421 的电流。
- `source`：目标电流来源。
- `driver_fault_flags`：AD5421 驱动故障标志。
- `driver_fault_register`：最近一次 `READFAULT` 原始值。
- `last_error_code`：最近一次 AO 更新错误码。
- `update_counter`、`last_update_tick`、`last_sent_tick`：刷新和写入时间信息。

HART Command 2/3 读取 `AoOutput_GetCurrent_mA()` 和 `AoOutput_GetPercentOfRange()`，返回的是 AO 服务运行态目标电流，不会额外访问 AD5421。

## 7. 错误码口径

当前 AD5421 相关错误码：

| 错误码 | 含义 | 当前触发来源 |
| --- | --- | --- |
| `AD5421_INIT_ERROR` / `0x00130005` | 初始化或控制寄存器读写失败 | `WriteControlRegister()` 写/读 SPI 失败 |
| `AD5421_WRITE_CURRENT_ERROR` / `0x00130006` | 写 DAC 电流失败 | `AD5421_SetDacRaw()` 写 `WRITEDAC` 失败 |
| `AD5421_FAULT_PIN_ERROR` / `0x00130007` | 历史故障脚报警 | 当前 PCB 不再触发，PB8 悬空不用作诊断 |
| `AD5421_READFAULT_ERROR` / `0x00130008` | 故障寄存器异常 | `READFAULT` 非 0 或读取失败 |
| `AD5421_READBACK_ERROR` / `0x00130009` | 控制寄存器回读失败 | `READCONTROL` 与写入控制字不一致 |

## 8. 当前遗留风险

1. `AD5421_FAULT_PIN_ERROR` 错误码仍保留在 CPU2/CPU3 枚举和显示中，主要用于兼容历史协议；当前硬件版本不应触发。
2. CubeMX 仍配置 PB8 为 `AD5421_FAULT` 输入，但驱动不再读取该引脚；后续如果重新生成代码，需要确认不会把 PB8 诊断逻辑加回来。
3. SPI3 的 PB4/PB5 标签历史上存在 MISO/MOSI 命名混淆；当前 HAL 复用和实测电流输出已证明主路径可用，但调示波器或改 CubeMX 时必须按实际信号判断。
4. DAC 写入没有寄存器回读，最终电流闭环仍依赖外部回路实测；调试时必须接负载或电流表。
5. 文档中早期“FAULT/LDAC 待确认”的分析已被后续实物确认更新：FAULT 未接 PB8，LDAC 固定到 COM，不应再作为当前主因。
