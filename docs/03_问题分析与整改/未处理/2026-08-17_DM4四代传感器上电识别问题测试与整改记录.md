# DM4四代传感器上电识别问题测试与整改记录

日期：2026-08-17

当前状态：上电识别问题已取得实机闭环证据；R01、R67、编号0身份提交和FRAM保存均成功。命令15已实机确认R07 NaN会打印通信包并按无效值跳过；流程继续后又发现R05同样返回NaN，CPU2现对V4水位电容采用相同的非致命处理，等待目标板复测闭环。

## 1. 结论

本次“DM4四代传感器上电无法识别”不是单一故障，而是三个问题依次暴露：

1. CPU2使用广播地址`0x00`发送R01后，旧校验要求应答地址必须等于请求地址，错误拒绝了地址`0x01`传感器返回的合法应答。
2. R01修正后，CPU2使用地址`0x01`读取R67。无线桥先返回参数码`0xFF`，真实传感器稍后才返回合法R67应答，CPU2因先收到无线桥应答而报告远端内部故障。
3. V4请求临时改为广播后，R67通信和帧校验成功，但传感器返回未初始化编号`0`。旧CPU2把`value <= 0`判为格式错误；用户确认编号`0`是合法的未初始化状态后，CPU2改为只拒绝负数。

当前源码已实现：V4交互请求临时统一使用广播地址、广播应答允许携带设备自身地址、R67编号`0`作为合法编号处理。最终实机日志确认CPU2已经把该传感器识别为`MULTIPARAM_V4_SENSOR`、提交`sensorID=0`并成功保存到FRAM A/B。

识别成功后出现的`CMD_ReadPartParams`错误不再属于“上电无法识别”问题。新增通信包日志先后证明R07和R05的应答帧均校验通过，但数据域都是`00 00 C0 7F`，按小端IEEE-754解释为安静NaN。NaN表示当前没有可用测量值，不应伪装为0，也不应在命令15这种部件诊断读取中触发全局错误；正式测量链仍拒绝发布该值。

## 4. 测试过程和问题推进

### 4.1 第一阶段：R01已有应答，但CPU2仍报告协议识别失败

初始抓包可见：

```text
TX  00 52 00 00 00 00 01 53
RX  01 D2 00 00 80 40 01 94
```

请求地址`0x00`是广播地址，传感器使用自身地址`0x01`应答。应答的功能码、数据、参数码和校验均合法。旧CPU2仍按普通定向事务执行`reply[0] == request[0]`，把该帧判为`SENSOR_RESP_FORMAT_ERROR`。

处理后，公共R01采用广播应答地址策略：只有请求地址为`0x00`时，允许应答携带传感器自身地址；成功后记录应答地址，保留后续恢复定向通信的能力。

### 4.2 第二阶段：增加探测原始包打印

为区分“未收到”“坏帧”“远端错误”和“合法帧被业务值域拒绝”，自动识别阶段增加统一探测日志：

```text
探测包  协议=<V4/V3/DSM>  操作=<命令>  方向=<TX/RX>
        长度=<实际长度>  HEX=<实际字节>  结果=<错误码>  阶段=<校验阶段>
```

覆盖范围包括：

- V4主动帧监听前后结果；
- V4 R01、R67及通信方式切换事务；
- V3 R22每次尝试的TX/RX；
- DSM `Cv`、`CV`、`CN`每次尝试的TX/RX。

日志只打印实际接收长度，超时使用长度0，不把清零缓冲区伪装成收到的应答。

### 4.3 第三阶段：R67定向请求被无线桥抢先应答

R01修正后，CPU2锁定地址`0x01`并发送：

```text
TX       01 52 00 00 00 00 43 96
桥接应答 01 D2 00 00 00 00 FF D2
传感器答 01 D2 00 00 00 00 43 16
```

CPU2的8字节事务先收到参数码`0xFF`的帧，因此返回`0x000D0026`，即传感器远端内部故障。总线日志随后出现参数码`0x43`的真实传感器应答，说明传感器并非没有响应。

参考无线主机旧源码可见，本地应答器使用地址`0x01`，只实现少量本机参数，对未知参数返回`0xFF`。这与现场“先收到`FF`、后收到真实R67”的顺序一致。该源码位于`old/WirelessHost_V4.1_init/`，本次没有修改无线桥固件。

### 4.4 第四阶段：V4请求临时改为广播

为避开无线桥对地址`0x01`的本地抢答，CPU2临时启用：

```c
#define MULTIPARAM_V4_TEMP_FORCE_BROADCAST_TX 1U
```

所有V4交互请求，包括R01、R67、普通参数读写、通信方式和功能控制，暂时使用地址`0x00`。广播请求的合法应答可以返回设备自身地址。现场复测结果为：

```text
R01 TX  00 52 00 00 00 00 01 53
R01 RX  01 D2 00 00 80 40 01 94  结果=0x00000000  阶段=校验通过

R67 TX  00 52 00 00 00 00 43 95
R67 RX  01 D2 00 00 00 00 43 16  结果=0x00000000  阶段=校验通过
```

该结果证明广播兼容已经避开无线桥`0xFF`应答，R67的通信层、功能码、参数码和校验均通过。

### 4.5 第五阶段：R67编号0被业务值域拒绝

R67应答数据区为`00 00 00 00`。通信层返回成功后，旧`MULTIPARAM_V4_ReadSensorID()`执行：

```c
if (value <= 0) {
    return SENSOR_RESP_FORMAT_ERROR;
}
```

因此现场仍报告：

```text
R67读取=0x000D001B
错误名：传感器响应格式异常
```

用户随后确认：未初始化传感器的编号均为`0`，编号`0`需要作为正常编号处理。CPU2据此改为只拒绝负数：

```c
if (value < 0) {
    return SENSOR_RESP_FORMAT_ERROR;
}
```

编号`0`现在会写入输出参数，并由`Sensor_CompleteV4Detection()`提交为当前V4传感器身份；负数仍不会被无符号转换成伪编号。

### 4.6 第六阶段：上电识别闭环，命令15暴露后续读取问题

最终目标板日志给出以下连续证据：

```text
R01 RX  01 D2 00 00 80 40 01 94  结果=0x00000000  阶段=校验通过
R67 RX  01 D2 00 00 00 00 43 16  结果=0x00000000  阶段=校验通过
[参数][写入][成功] 传感器类型: 12 -> 15
[参数][写入][成功] 传感器编号: 2513331 -> 0
[参数][保存][成功] 位置=FRAM A/B
识别成功：多参数V4传感器 | 通信=交互 | 地址=0 | 编号=0
```

至此，上电识别问题已经现场闭环。随后执行命令15时出现：

```text
执行读取部件参数指令
错误码：0x000D001B
错误名：传感器响应格式异常
详情：文件：sensor.c,行号：1631,函数：CMD_ReadPartParams
```

源码追踪表明，`sensor.c:1631`只传播下层返回码。部件参数读取会依次读取姿态角、密度/温度/频率和水位电容，任一V4帧错误或业务值域错误均可能返回该错误码。当前修改复用V4事务诊断缓存，在上述三个失败出口打印最近一组`TX`和`RX`，并包含实际接收长度、HEX、错误码、帧/业务校验阶段、耗时和UART状态。正常的每秒参数刷新不打印这些包，避免持续刷屏。

### 4.7 第七阶段：R07返回NaN，命令15误置全局错误

新增事务日志取得了直接证据：

```text
通信包 协议=V4 场景=读取部件参数 操作=读取密度/温度/频率 指令=R07
方向=TX 长度=8 HEX=00 52 00 00 00 00 07 59
方向=RX 长度=8 HEX=01 D2 00 00 C0 7F 07 19
结果=0x000D001B 阶段=帧校验通过，业务校验失败
```

应答地址、功能码、参数码和校验和均通过。数据域按协议小端顺序还原为`0x7FC00000`，即IEEE-754安静NaN。原实现的通用浮点读取把所有非有限值都映射为`SENSOR_RESP_FORMAT_ERROR`，命令15随后通过`SET_ERROR`进入全局错误态。

本轮将NaN单独映射为`SENSOR_DATA_STALE`，正负无穷和其他格式/值域错误仍保持原错误处理。命令15读取V4密度组合量时遇到`SENSOR_DATA_STALE`会继续打印最近一次TX/RX，提示该项当前无有效值，然后继续读取其他部件参数；正式测量链不会把NaN发布为密度，也不会用0替代。

### 4.8 第八阶段：R07降级通过后，R05返回同类NaN

目标板复测证明第七阶段修改已经生效：R07返回NaN时错误码由格式错误变为`0x000D0024`，命令15打印“跳过本项且不置错误状态”后继续执行。随后水位电容R05暴露同类数据：

```text
通信包 协议=V4 场景=读取部件参数 操作=读取水位电容 指令=R05
方向=TX 长度=8 HEX=00 52 00 00 00 00 05 57
方向=RX 长度=8 HEX=01 D2 00 00 C0 7F 05 17
结果=0x000D0024 阶段=帧校验通过，业务校验失败
```

R05数据域同样为`0x7FC00000`。通用浮点层已经正确返回`SENSOR_DATA_STALE`，但命令15的水位电容分支仍把该返回码作为最终错误传播。本轮只在V4部件参数诊断场景降级该返回码：保留TX/RX证据，打印水位电容当前无有效值，继续后续RSSI和参数汇总；不写0，也不覆盖已有有效水位电容快照。其他传感器类型、通信错误、坏帧、无穷和有限值越界仍保持原错误处理。

## 5. 根因和竞争解释

| 解释 | 证据 | 结论 |
| --- | --- | --- |
| 蓝牙未连接或信号过弱 | 多次链路检查成功，RSSI最低样本为`-53 dB`；R01/R67可以往返 | 排除为本次直接原因 |
| 传感器完全无响应 | R01和R67均有合法应答 | 排除 |
| R01应答地址错误 | 请求为广播，设备返回自身地址符合用户确认的协议规则 | 是CPU2旧校验问题，不是设备坏帧 |
| R67远端内部故障 | `0xFF`帧后仍出现参数码`0x43`的真实应答 | `0xFF`来自无线桥本地抢答的可能性高，与参考源码一致 |
| R67编号损坏 | 数据值稳定为`0`，用户确认这是未初始化编号 | 不是坏帧；是CPU2旧值域与产品定义冲突 |
| R07应答帧损坏 | 地址、功能码、参数码和校验和均通过 | 排除；失败来自数据域NaN的业务解释 |
| R07 NaN是密度0 | IEEE-754原始值为`0x7FC00000` | 排除；NaN只表示当前无可用值，不可参与测量计算 |
| R05是坏帧或水位电容0 | 应答校验通过，原始值同样为`0x7FC00000` | 排除；属于当前水位电容无有效值，不得写成0 |
| 设备发生重启 | 日志中两次出现`00 Welcome` | 只能确认观测点见到启动提示；与R67失败没有建立直接因果关系，继续作为观察项 |

## 9. 风险、回退和后续动作

- 临时广播发送不仅影响读参数，也影响写参数、通信方式和功能控制命令。多设备总线上会出现响应冲突或多台设备同时执行命令，只允许在单应答设备链路使用。
- 无线桥地址抢答问题解决后，将`MULTIPARAM_V4_TEMP_FORCE_BROADCAST_TX`改为`0U`即可恢复锁定地址发送；恢复前必须重新验证R01广播探测和后续定向R67。
- 多台未初始化传感器的编号都为0，编号不能作为唯一身份区分。当前产品决定只要求把0作为合法编号，本次没有自动生成编号或写回传感器。
- 两次`00 Welcome`需要在后续长时间测试中观察是否伴随传感器或无线模块复位；当前证据不足以归因。
- 上电识别和R07 NaN非致命处理已经现场闭环；当前文件暂保留在“未处理”目录，是因为R05 NaN非致命处理尚未取得目标板复测证据。复测确认命令15可以完成后，应将识别记录移动到`../已闭环/`并同步索引。

## 11. 2026-08-18主动流通信质量监测

### 11.1 需求和实现口径

本轮在既有V4主动帧诊断上增加通信质量闭环：按16位帧序号统计确认丢包率，通过`V4G`打印质量和最近一次异常包，连续3个主动包异常后进入统一错误状态。实现没有新增CPU2/CPU3共享错误码，而是保留导致阈值命中的具体既有错误码；共享协议仍为34。

| 项目 | 实现 |
| --- | --- |
| 丢包率 | `lost_frames / (valid_frames + lost_frames)`；`lost_frames`只由已确认的正向序号缺口累计 |
| 异常范围 | 完整候选帧CRC/格式/地址/协议错误、重复帧、乱序帧、序号缺口；1500 ms无有效主动帧按3个连续异常触发 |
| 不直接算包异常 | DMA短接收、重同步字节、UART错误和接收恢复错误保留独立计数，避免把分片事件误当成完整包 |
| 连续性恢复 | 有效且序号连续的新帧将当前连续异常归零；已产生的待上报故障不撤销 |
| 最近异常包 | 保存错误码、接收Tick、长度和最多122字节；无线补零候选可完整保留，纯超时长度为0 |
| 故障上下文 | PendSV和UART中断只记录；`App_MainLoop()`取走待上报错误码并调用统一故障管理，已有全局故障不被覆盖 |
| 串口命令 | `V4G`增加质量汇总与异常HEX；`V4C`同时清累计质量、当前连续异常、待上报故障和异常包 |
