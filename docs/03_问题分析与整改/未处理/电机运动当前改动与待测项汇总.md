## 3. 代码改动点

### 3.1 统一目标规划

新增 `MotorMotionTargetPlan`，集中保存：

- 起点 `start_mm`。
- 绝对目标 `target_mm`。
- 剩余距离 `distance_mm`。
- 方向 `dir`。
- 是否已经到位 `already_reached`。

新增 `MotorMotion_BuildRelativeTargetPlan()`：

- 供 `MotorCtrl_MoveAndWait()` 和 `MotorCtrl_JogMoveAndWait()` 共用相对距离目标规划。
- 保留原有方向、距离和目标边界语义。

新增 `MotorMotion_BuildAbsoluteTargetPlan()`：

- 供 `MotorCtrl_MoveToPosition()` 和 `MotorCtrl_JogMoveToPosition()` 共用绝对位置目标规划。
- 保留原有位置范围判断和已到位短路行为。

### 3.2 收敛运行前门控和命令切换

新增 `MotorMotion_CheckReadyForProtectedMotion()`：

- 统一检查电机运行前的基础就绪条件。
- 调用方仍明确传入是否忽略编码器就绪、是否执行驱动健康检查，避免降低原路径保护强度。

新增 `MotorMotion_CheckCommandAbortWithSpeedScope()`：

- 统一正式距离运动中“命令切换打断并恢复临时速度”的处理。
- 保留命令切换时停止运动并返回错误的原语义。

新增 `MotorMotion_WaitMoveStartObservation()`：

- 抽出 `MotorCtrl_MoveAndWait()` 目标下发后的启动观察窗口。
- 保留原有 `100` 次、每次 `10ms` 的观察节奏。

### 3.3 收敛 Jog 运行保护

新增 `MotorMotion_CheckJogRuntimeGuards()`：

- 集中处理 Jog 循环内运行健康检查、撞底检查、丢步检查、运动状态判断和超时判断。
- Jog 的提前减速、提前停机、慢停恢复和策略状态机仍保留在 `MotorMotion_JogMoveToTargetInternal()`，避免把调速策略隐藏到通用 helper 中。

### 3.4 收敛等待循环公共检查

新增 `MotorMotion_CheckAbortRefreshAndHealth()`：

- 用于 ticks 起步等待、强制无检测阻塞等待、通用停机等待等路径。
- 收敛命令切换、运行中速度刷新、TMC 同步和驱动健康检查。
- 调用方仍决定速度恢复、无检测日志、撞底/丢步/目标判断等路径专属逻辑。

新增 `MotorMotion_CheckStoppedAndRefresh()`：

- 用于通用停机等待、正式到位等待和停止命令等待。
- 收敛停稳后的最终位置同步和活动状态清理。
- 若最终位置同步失败，保留原始错误码，不清活动状态。

### 3.5 保留两套执行策略

当前分支没有把默认 `MotorCtrl_MoveToPosition()` 改成 Jog 路径：

- 正式位置模式仍通过分段 `MotorCtrl_MoveAndWait()` 执行，保持既有对外行为。
- Jog 速度模式继续作为 `MotorCtrl_JogMoveAndWait()`、`MotorCtrl_JogMoveToPosition()` 和串口 `BJ/BJP` 调试入口。
- 第三轮评估结论是：在没有完成 T15/T16、正式/Jog A/B 对比和 `200mm` 下限决策前，不做默认行为替换。

## 5. 当前待测项

### 5.1 T15：编码器首帧缺失故障注入

目的：

- 验证编码器首帧缺失、位置源不可用或初始同步异常时，当前运动入口能正确拒绝或进入预期错误路径。
- 覆盖当前本地构建无法证明的传感器异常边界。

建议步骤：

1. 使用 COM12，`115200`，GBK。
2. 按《电机运动剩余台架验证执行规程.md》设置安全范围。
3. 人工制造编码器首帧缺失或位置源不可用条件。
4. 执行正式位置模式和 Jog 入口各一组低速短行程命令。
5. 记录返回码、串口日志、是否停机、是否出现错误恢复重跑。

通过条件：

- 不发生失控运动。
- 不突破 `200mm` 到 `1000mm` 台架安全范围。
- 错误码和日志能解释失败原因。
- 故障清除后可按既有流程恢复。

### 5.2 T16：TMC/24V 故障注入

目的：

- 验证 TMC 通信、驱动健康或 24V 功率级故障时，新增公共健康检查没有降低保护强度。
- 覆盖正式、Jog、ticks、停机等待和无检测路径对健康异常的处理差异。

建议步骤：

1. 在传感器位置 `200mm` 到 `1000mm` 范围内选择中间位置。
2. 低速执行正式位置模式短距离运动，并在运动中制造 TMC 或 24V 异常。
3. 低速执行 Jog 运动，并在运动中制造相同异常。
4. 必要时覆盖 ticks 或无检测路径，但无检测路径只允许短距离、低速、可人工断电条件。
5. 记录停止时机、错误码、串口日志和恢复动作。

通过条件：

- 正式和 Jog 路径均能及时停机或返回错误。
- 无检测路径不得被误判为可替代正常保护路径。
- 故障恢复不会自动重复执行危险运动。

### 5.3 `200mm` 下限决策

当前用户给出的台架安全限制：

- 传感器位置不要高于 `1000mm`。
- 传感器位置不要低于 `200mm`。

待决策项：

| 方案 | 说明 | 影响 |
| --- | --- | --- |
| 仅作为台架测试限制 | 代码保持产品原范围，测试规程限制命令目标 | 风险最低，不引入产品行为变化 |
| 升级为产品硬边界 | 将 `200mm` 写入正式位置范围 | 需要确认真实设备行程、客户场景和历史兼容性 |
| 参数化下限 | 通过参数或配置区分台架和产品 | 需要额外参数定义、存储、协议和显示侧同步评估 |

当前建议：

- 本分支不把 `200mm` 写入代码。
- 在台架规程中强制限制命令目标。
- 等产品需求确认后再决定是否另开分支做边界参数化或硬边界改动。

### 5.4 正式位置模式与 Jog 模式 A/B 对比

目的：

- 判断是否有证据支持未来把默认绝对位置运动替换为 Jog 反馈式速度模式。
- 当前分支只完成结构统一，不做默认策略替换。

建议测试矩阵：

| 目标位置 | 速度建议 | 覆盖重点 |
| --- | --- | --- |
| `250mm` | 低速 `0.3`，常规 `1.0` | 靠近下限但不低于 `200mm` |
| `500mm` | 低速 `0.3`，常规 `1.0` | 中间位置重复性 |
| `700mm` | 低速 `0.3`，常规 `1.0` | 中高位重复性 |
| `950mm` | 低速 `0.3`，常规 `1.0` | 靠近上限但不高于 `1000mm` |

每组记录：

- 起点、目标、最终 `sensor_position`。
- 正式模式耗时、最大偏差、是否丢步、是否有异常日志。
- Jog 模式耗时、减速点、停止点、慢停恢复情况。
- 两种模式在相同目标下的最终误差和稳定性。

进入策略替换的最低条件：

- T15/T16 均通过。
- A/B 对比显示 Jog 在目标精度、异常处理和恢复行为上不差于正式位置模式。
- 对外命令语义、返回码、超时和日志差异已整理并确认可接受。
- 有可回退开关或明确回退提交点。
