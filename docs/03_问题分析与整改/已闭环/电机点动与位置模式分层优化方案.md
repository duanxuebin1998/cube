# 电机点动与位置模式分层优化方案

更新日期：2026-06-12

> 当前复核（2026-07-08）：状态：已闭环（方案落地）。`1a1b8e30` 已将目标规划、ready/health 门禁、启动观察、Jog 运行保护和停稳同步 helper 合入 `motor_ctrl_motion_api.c`；T15/T16、A/B 对比和 200mm 决策仍由未处理目录中的验证规程跟踪。

## 1. 目标

当前电机运动函数同时存在正式位置模式和 Jog 点动速度模式。两套模式的目标计算、目标越界检查和位置快照校验有重复，但执行策略不同：

- 正式位置模式：下发 TMC5130 位置目标，等待驱动到位或按目标位置停止。
- Jog 点动速度模式：下发速度运动，运行中按当前有效位置反馈计算剩余距离、减速和提前停机。

本轮优化目标是统一目标规划和入口边界，不合并两套执行策略，降低重复代码和误用风险。

## 2. 当前入口分层

| 分层 | 公开入口 | 允许用途 |
| --- | --- | --- |
| 正式相对距离运动 | `MotorCtrl_MoveAndWait()` | 测量流程、手动上/下行、液位/水位/密度/瓦锡兰流程 |
| 正式绝对位置运动 | `MotorCtrl_MoveToPosition()` | 单点测量、固定点监测、测后回固定点 |
| Jog 相对点动 | `MotorCtrl_JogMoveAndWait()` | `BJ+/-` 串口台架验证，验证速度模式和主动位置反馈 |
| Jog 绝对点动 | `MotorCtrl_JogMoveToPosition()` | `BJP` 串口台架验证，验证目标位置点动和越界保护 |
| ticks 内部运动 | `MotorCtrl_MoveByTicksAndWait()` | 位置源切换、局部周长标定和卷筒模型内部操作 |
| 强制/无检测运动 | `MotorCtrl_MoveBlockingNoDetect*()` | 受控维护和强制调试，不能替代正式业务运动 |

## 3. 指定优化方案

本轮采用“目标规划统一，执行策略分离”的方案。

### 3.1 新增目标规划结构

`MotorMotionTargetPlan` 只保存一次运动入口需要的目标信息：

- `start_mm`：规划起点。
- `target_mm`：绝对目标位置。
- `distance_mm`：本次需要移动的正距离。
- `dir`：统一方向。
- `already_reached`：当前位置已经在目标窗口内。

### 3.2 新增目标规划 helper

| Helper | 调用方 | 职责 |
| --- | --- | --- |
| `MotorMotion_BuildRelativeTargetPlan()` | `MotorCtrl_MoveAndWait()`、`MotorCtrl_JogMoveAndWait()` | 按当前位置、相对距离和方向生成绝对目标，并统一检查方向、位置快照和目标范围 |
| `MotorMotion_BuildAbsoluteTargetPlan()` | `MotorCtrl_MoveToPosition()`、`MotorCtrl_JogMoveToPosition()` | 按当前位置和绝对目标生成方向、剩余距离和到位状态，并统一检查位置快照和目标范围 |

这两个 helper 不下发运动、不等待停机、不切换速度，只做入口目标规划。

### 3.3 保留执行策略差异

| 执行策略 | 保留原因 |
| --- | --- |
| 正式位置模式 | 正式流程需要 TMC5130 位置目标、运动前门控、起步观察、到位等待、最终偏差判断和丢步处理 |
| Jog 速度模式 | BJ/BJP 需要验证速度模式、主动位置反馈、减速距离和提前停机；停机依据不同，不能直接替代正式模式 |

### 3.4 收敛入口边界和启动观察

本轮第二步继续收敛入口边界，但仍不合并执行策略：

| Helper | 调用方 | 职责 |
| --- | --- | --- |
| `MotorMotion_CheckReadyForProtectedMotion()` | 正式距离运动、Jog 入口、Jog 内部执行、无检测运动 | 统一运行前就绪门控；是否绕过编码器首帧、是否执行健康检查由调用方显式选择 |
| `MotorMotion_CheckCommandAbortWithSpeedScope()` | `MotorCtrl_MoveAndWait()` 和启动观察 helper | 命令切换打断时先恢复本次临时速度，再把错误返回给调用方 |
| `MotorMotion_WaitMoveStartObservation()` | `MotorCtrl_MoveAndWait()` | 抽出正式位置模式下发目标后的 100 次、10ms 启动观察窗口，保持原有速度刷新、位置轮询和活动状态刷新顺序 |

### 3.5 收敛 Jog 单轮运行保护

Jog 状态机继续保留剩余距离计算、慢速切换、提前停机和慢停收尾；本轮只把每轮末尾的公共运行保护集中为 helper：

| Helper | 调用方 | 职责 |
| --- | --- | --- |
| `MotorMotion_CheckJogRuntimeGuards()` | `MotorMotion_JogMoveToTargetInternal()` | 集中检查运行健康、撞底、丢步、驱动运动状态、起步宽限超时和最大运行超时；不计算剩余距离、不切换速度、不下发停机 |

### 3.6 第二轮等待循环收敛

第二轮不合并为统一大循环，只收敛等待循环中完全同构的机械动作：

| Helper | 调用方 | 职责 |
| --- | --- | --- |
| `MotorMotion_CheckAbortRefreshAndHealth()` | `MotorMotion_WaitTicksStartChanged()`、`MotorMotion_MoveBlockingNoDetectInternal()`、`MotorMotion_WaitStopAbortable()` | 集中执行命令切换停机检查、运行中速度刷新和 TMC 同步/健康检查；不做速度恢复、不做撞底/丢步、不做目标判断、不清活动状态 |
| `MotorMotion_CheckStoppedAndRefresh()` | `MotorMotion_WaitStopAbortable()`、`MotorMotion_WaitUntilStopWithTarget()`、`MotorMotion_WaitStoppedAfterStopCommand()` | 集中执行确认停稳后的最终位置同步和活动状态清理；同步失败时保留原始错误码且不清活动状态 |

`MotorMotion_WaitUntilStopWithTarget()` 暂不纳入该 helper 主体，因为它还承担正式位置模式的目标停机、撞底、驱动健康错误归因和超时日志。

## 4. 本轮代码改动

修改文件：

```text
LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_motion_api.c
tools/check_motor_motion_target_plan.py
```

主要改动：

- 新增 `MotorMotionTargetPlan`。
- 新增 `MotorMotion_BuildRelativeTargetPlan()`。
- 新增 `MotorMotion_BuildAbsoluteTargetPlan()`。
- `MotorCtrl_MoveAndWait()` 复用相对目标规划 helper。
- `MotorCtrl_JogMoveAndWait()` 复用相对目标规划 helper。
- `MotorCtrl_MoveToPosition()` 复用绝对目标规划 helper。
- `MotorCtrl_JogMoveToPosition()` 复用绝对目标规划 helper。
- 新增 `MotorMotion_CheckReadyForProtectedMotion()`，收敛运行前门控，但不改变各入口是否检查健康、是否允许强制调试的选择。
- 新增 `MotorMotion_CheckCommandAbortWithSpeedScope()`，收敛带临时速度恢复的命令切换打断。
- 新增 `MotorMotion_WaitMoveStartObservation()`，收敛 `MotorCtrl_MoveAndWait()` 的启动观察窗口。
- 新增 `MotorMotion_CheckJogRuntimeGuards()`，收敛 Jog 循环末尾的运行健康、撞底、丢步、运动状态和超时检查；错误仍由上层 `MotorMotion_StopJogAndRestore()` 慢停并恢复速度。
- 新增 `MotorMotion_CheckAbortRefreshAndHealth()`，第二轮第一刀先收敛 ticks 起步等待、无检测阻塞等待和通用停机等待中的命令切换、速度刷新和 TMC 同步/健康检查。
- 新增 `MotorMotion_CheckStoppedAndRefresh()`，第二轮第二刀收敛通用停机等待、正式到位等待和停止命令等待在停稳后的最终位置同步和活动状态清理。
- 新增 `tools/check_motor_motion_target_plan.py`，用于检查四个入口是否持续共用目标规划 helper。

## 6. 后续优化边界

下一轮如果继续收敛等待循环，建议保持以下边界：

- 不把 Jog 速度模式直接改成正式业务入口。
- 不把正式位置模式和 Jog 速度模式合成一个大函数。
- `MoveNoWait()` 继续视为低层目标下发能力，正式业务优先使用带等待和保护的入口。
- 强制/无检测运动继续保留维护边界，不能静默替代正式测量流程。
- 不把 `MotorMotion_WaitUntilStopWithTarget()` 的目标停机、撞底、健康错误归因和超时日志塞进通用 helper。

## 7. 第三轮策略评估结论

第三轮已完成现有代码和台架记录审计，结论是不在当前分支替换默认 `MotorCtrl_MoveToPosition()` 策略。

保留当前分层：

| 入口 | 当前定位 | 第三轮结论 |
| --- | --- | --- |
| `MotorCtrl_MoveToPosition()` | 正式业务绝对位置入口 | 继续通过主动位置刷新、目标规划和 `MotorCtrl_MoveAndWait()` 分段执行 |
| `MotorCtrl_JogMoveToPosition()` | `BJP` 调试和提前减速方案验证入口 | 继续保留为速度模式验证路径，不直接承担正式业务默认入口 |
| `MotorMotionTargetPlan` | 两类入口共用目标规划 | 继续复用，不向下合并执行策略 |

当前台架记录只覆盖 `T04`、`T07`、`T08`、`T09`、`T10` 等有限场景，主要是 `1.0m/min` 和小行程数据；T15/T16 人工故障注入、低于 `200mm` 台架下限策略、多速度长距离 A/B 对比尚未完成。因此第三轮退出状态是“评估完成，代码实验暂缓”。

后续如果要继续实验，只允许默认关闭、可回退的台架入口或内部开关，并按同目标、同速度、同起点对比正式位置模式和 Jog 速度模式的终点偏差、耗时、过冲、返回码和关键日志。
