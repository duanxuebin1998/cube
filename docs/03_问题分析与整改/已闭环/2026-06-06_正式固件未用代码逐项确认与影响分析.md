# 正式固件未用代码逐项确认与影响分析

日期：2026-06-06

本文记录 CPU2/CPU3 正式固件源码中未用代码的梳理结果、用户逐项确认结论、删除影响和后续验证方法。当前已按用户确认删除项执行源码删除；确认保留项和仅记录项不处理。本次删除改变 CPU2/CPU3 构建产物，固件 build 版本分别升级到 CPU2 `V1.12.0.1`、CPU3 `V1.10.0.1`。

## 1. 分析边界

本次只覆盖当前正式固件工程：

- `LTD_MAIN_CPU2/`：CPU2 主控测量板固件。
- `LTD_DISPLAY_CPU3/`：CPU3 显示通讯板固件。

不纳入本次删除判断的范围：

- `old/` 历史归档。
- `WirelessHost_V4.1_init/` 历史/独立验证工程。
- 文档、CI、构建脚本和 PDF 导出物。

判断依据：

- CPU2 `CMakeLists.txt` 会编译 `Core/Src`、`Application/Src`、`Services`、`BSP/Peripherals/src`、HAL 和启动文件。
- CPU3 `CMakeLists.txt` 会编译 `Core/Src`、`Application`、`Communication`、HAL 和启动文件。
- 当前构建使用 `-ffunction-sections`、`-fdata-sections` 和链接选项 `-Wl,--gc-sections`，未被引用的函数/数据会被链接器丢弃。
- 已用 `arm-none-eabi-nm` 对比对象文件和最终 ELF 中的符号，并用 `rg` 检查源码引用。
- CPU2/CPU3 构建目录当前可用，`cmake --build` 返回 `ninja: no work to do.`，说明现有 map/ELF 与当前源码时间戳一致。

## 3. 确认删除项影响分析

### 3.1 CPU3 `com_manager.c/.h`

删除内容：

- `LTD_DISPLAY_CPU3/Communication/common/com_manager.c`
- `LTD_DISPLAY_CPU3/Communication/common/com_manager.h`
- `g_com_manager_config`
- `COM_InitAllFromParams()`
- `COM_ApplyConfigToUart()`
- `COM_DispatchProtocol()`
- 文件内部静态函数 `COM_GetUartHandle()`、`COM_EnableRxDMAAndIdle()`

当前状态：

- 该文件进入 CPU3 CMake 编译范围，但没有符号进入最终 ELF。
- 源码中只存在头文件声明、文件内部自调用和历史文档引用。
- 当前 CPU3 外部协议主分发走 `Application/app_main.c` 相关路径。

删除影响：

- 不影响当前 CPU3 外部 COM 口协议处理主路径。
- 不影响当前 SI、DSM、Wartsila 的实际主分发逻辑。
- 会移除旧 `com_manager` 兼容分发路径，后续不能再把它作为备用协议入口。
- SI 文档中曾提到“旧 `com_manager` 兼容路径取舍”，源码删除后应在后续文档整理中把该项标记为已删除或已收敛到主分发。

风险等级：低到中。

风险说明：

- 当前固件运行风险低，因为最终 ELF 中没有该模块。
- 文档一致性风险中等，因为已有 SI协议适配文档提过该兼容路径。

验证方法：

- CPU3 构建通过。
- `rg "com_manager|COM_DispatchProtocol|COM_InitAllFromParams"` 确认源码引用已清零或只剩历史文档。
- 运行 `py tools\check_si_modbus_frames.py`。
- 运行 `py tools\check_si_protocol_contract.py`。
