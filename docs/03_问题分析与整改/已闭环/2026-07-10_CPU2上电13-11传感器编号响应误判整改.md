# CPU2 上电 13-11 传感器编号响应误判整改

日期：2026-07-10

适用版本：CPU2 `V1.21.6.0`；CPU3 `V1.20.0.0`；`DEVICE_PROTOCOL_VERSION` 保持 `14`。

## 1. 问题现象

设备首次烧写或冷启动时，DSM 一代传感器可能上报 `13-11`。该错误对应 `SENSOR_RESP_FORMAT_ERROR`，现场容易误判为传感器编号损坏或通信帧格式异常。

## 2. 根因

CPU2 使用 `CN` 指令读取 DSM 一代振动管编号。正常响应通常以 `N` 开头，例如 `N2009924H`；传感器处于低电压状态时也可能以 `E` 或 `e` 开头，但后续仍携带同一编号数字。

原 `Read_VibrationTube_ID()` 只允许首字符为 `N`。因此 `E/e` 低电压响应虽然通信、校验和编号数字均有效，仍会在前缀判断处返回 `SENSOR_RESP_FORMAT_ERROR`，最终表现为上电 `13-11`。

## 3. 整改内容

- `Read_VibrationTube_ID()` 去除前导空白后接受 `N`、`E`、`e` 三种前缀。
- `E/e` 仅作为低电压提示，不再直接判为编号格式错误；响应文本继续复制到调用方。
- `Sensor_ParseDsmTextId()` 继续从文本中提取全部数字，`N2009924H`、`E2009924H` 和 `e2009924H` 均得到传感器编号 `2009924`。
- `Sensor_ParseDsmTextId()` 在每次十进制累加前检查 `UINT32_MAX` 边界；`N4294967295H` 可解析为 `0xFFFFFFFF`，`N4294967296H` 和更长数字串返回 `SENSOR_RESP_FORMAT_ERROR`，不再因无符号回绕保存伪编号。
- 没有任何数字、其它首字母、通信失败或后续 `DSM_EnableDensityMode()` 失败时仍按原错误出口处理，不放宽真正的异常响应。
- `CD/CB/CL` 等其它 DSM 指令不复用该前缀兼容规则，避免扩大协议接受范围。

## 4. 影响与兼容性

- 只修改 CPU2 对 DSM `CN` 文本响应的兼容解析，不改变 CPU2/CPU3 共享寄存器、命令、状态字段或参数语义。
- `DEVICE_PROTOCOL_VERSION` 保持 `14`。
- CPU2 `DEVICE_PARAM_VERSION` 保持 `3`，`DeviceParameters` 结构和 `struct_size` 不变，升级不会因本次修复恢复出厂参数。
- 正常 `N` 响应路径保持不变；`E/e` 路径从误报格式错误改为继续识别编号并切换密度模式。
- 传感器编号存储类型仍为 `uint32_t`；本次只补十进制解析溢出拒绝，不改变字段宽度、持久化布局或对外协议语义。

## 6. 现场复测

| 场景 | 步骤 | 预期结果 |
| --- | --- | --- |
| 正常编号响应 | 冷启动并抓取 `CN` 原始响应，确认首字符为 `N` | 正确识别传感器编号，不报 `13-11`，随后进入密度模式 |
| 低电压大写响应 | 构造或复现 `E<编号>` 原始响应，保留真实 BCC/结束符 | 打印低电压响应但继续提取编号，不报 `13-11` |
| 低电压小写响应 | 构造或复现 `e<编号>` 原始响应 | 与大写 `E` 行为一致，识别到相同编号 |
| 无数字响应 | 构造 `E`、`e` 或 `N` 后不含数字的响应 | 仍返回 `SENSOR_RESP_FORMAT_ERROR`，不保存伪编号 |
| 其它首字母 | 构造 `X2009924H` | 返回 `SENSOR_RESP_FORMAT_ERROR`，不扩大接受范围 |
| 最大有效编号 | 构造 `N4294967295H`，保留合法 BCC/结束符 | 解析为 `0xFFFFFFFF`，不报格式错误 |
| 编号十进制溢出 | 构造 `N4294967296H` 和超长 `E999999999999999999H` | 返回 `SENSOR_RESP_FORMAT_ERROR`，不写入回绕后的伪编号，不进入密度模式 |
| 首次烧写冷启动 | 清除运行环境后首次烧写并连续冷启动至少 10 次 | 不再因 `CN` 的 `E/e` 低电压前缀误报 `13-11`；真实通信/格式错误仍可上报 |

## 7. 未验证风险

- 本地静态契约不能替代真实 DSM 传感器的低电压原始帧、BCC、串口时序和电源恢复过程。
- 发布后仍需保留至少一次真实 `E/e` 原始帧和冷启动日志作为硬件闭环证据。
