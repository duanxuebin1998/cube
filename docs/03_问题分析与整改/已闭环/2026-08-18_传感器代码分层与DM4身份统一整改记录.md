# 传感器代码分层与DM4身份统一整改记录

日期：2026-08-18
状态：代码整改已闭环，待实机回归与版本提交

## 1. 结论

CPU2传感器代码已完成身份、运行时、驱动、探测、维护诊断、UART6所有权和DM4 V4协议实现的分层整理。上层业务统一使用`SensorService_*`，不再直接判断DSM、V3、DM4 V4或DM4 Safe协议类型。

DM4普通协议和Safe协议继续表示同一物理传感器，持久化类型固定为`DM4_SENSOR=14`。V4是当前普通运行协议；Safe仅保留驱动选择位置，未设计的Safe进入、退出和异常回退流程没有在本轮开放。普通上电识别不探测Safe，也不发送Safe `HELLO`。

本轮直接替换旧高层接口，没有保留`SAFE_SENSOR=14`、`MULTIPARAM_V4_SENSOR=15`或旧`sensor.[ch]`兼容层。

## 2. 已确认需求

| 项目 | 确认结果 |
| --- | --- |
| DM4与Safe关系 | 同一物理传感器；进入安全模式后才使用Safe协议 |
| 上电识别 | 只按V4识别DM4，不识别独立Safe类型 |
| 物理链路 | DSM、V3、DM4均经过无线滑环 |
| 旧高层接口 | 直接替换，不保留兼容包装 |
| 当前持久化类型 | 12=DSM，13=多参数V3，14=DM4 |
| 旧类型15 | 仅为协议32至34历史值，升级时定向迁移为14 |
| Safe模式切换 | 尚未设计，只保留驱动选择位置，不提供公共切换入口 |

## 3. 完成的六个阶段

### 3.1 统一身份与服务入口

- CPU2和CPU3共享协议版本升级为35，DM4持久化类型统一为14。
- CPU2加载旧FRAM参数时把历史类型15定向迁移为14，参数结构大小、CRC范围和FRAM A/B布局不变。
- 测量、故障恢复、电机保护、维护命令和应用测试统一改用`sensor_service.h`。
- 删除旧`sensor.h`和`sensor.c`，不保留旧函数名包装。

### 3.2 建立运行时和驱动表

| 文件 | 职责 |
| --- | --- |
| `sensor_runtime.[ch]` | 保存本次识别结果，提交物理身份，按当前DM4协议模式取得驱动 |
| `sensor_driver.h` | 定义`SensorDriverOps`和能力位，不包含具体协议头 |
| `sensor_driver_registry.[ch]` | 注册DSM、V3、DM4 V4和预留DM4 Safe驱动，集中处理可选能力 |
| `sensor_service.[ch]` | 向上层提供稳定业务接口，通过驱动表调用协议实现 |

水位、陀螺仪、磁零点、主动上报、供电电压和密度分析等能力均通过能力位和可选函数指针表达。V4水位与磁零点互斥、只允许在密度模式启用、启用后保持开启的既有适配集中在V4驱动适配层。

### 3.3 拆分上电探测

`sensor_detector.c`只负责以下探测顺序和身份提交：

1. 蓝牙查询前监听V4主动帧。
2. 检查CH9141无线链路。
3. 透传恢复后再次监听V4主动帧。
4. 使用R01区分V3和V4；V4再读取R67，编号0按未初始化的合法编号处理。
5. V3候选读取编号。
6. 回退DSM组合版本和CN编号。

探测过程不建立Safe会话。候选全部失败时仍按原有优先级保留具体错误码和原始通信包诊断。

### 3.4 拆分部件维护诊断

部件参数读取、周期刷新、电机、编码器、称重、传感器参数和无线RSSI维护流程移到`Application/Src/part_diagnostics.c`。`measure.c`只保留命令调度，`fault_recovery.c`通过`PartDiagnostics_CheckAll()`执行维护复查。

共享的传感器超时与无线链路归因逻辑移到`sensor_comm_diagnostics.[ch]`，避免服务层和维护命令各自维护一套错误判断。

### 3.5 建立UART6所有权

`sensor_uart6_owner.[ch]`为UART6定义非抢占所有权和同所有者嵌套计数：

| 所有者 | 使用场景 |
| --- | --- |
| `CH9141_AT` | 无线模块AT命令、异步等待和强制恢复 |
| `DSM` | DSM文本命令事务 |
| `MULTIPARAM_V3` | V3固定8字节事务 |
| `DM4_V4_ACTIVE` | V4 Receive-to-IDLE主动流和恢复中断 |
| `DM4_V4_INTERACTIVE` | V4 8字节交互事务和通信模式切换 |
| `DM4_SAFE` | DM4 Safe请求响应和周期接收 |

不同所有者冲突时立即返回忙或模式未就绪，不启动DMA。V4主动接收停止后释放所有权；主动帧抢占交互切换时，通过原子所有权转换恢复主动接收。USART6接收、错误、定时恢复和异步终止回调只分派给`DM4_V4_ACTIVE`，不再默认进入V4回调。

### 3.6 拆分DM4 V4实现

原约2445行的`multiparam_v4_communication.c`已拆分为以下实现单元，公开头文件和上层调用不变：

| 文件 | 当前行数 | 职责 |
| --- | ---: | --- |
| `multiparam_v4_communication.c` | 96 | 公共状态、初始化和反初始化 |
| `multiparam_v4_codec.c` | 346 | 主动帧解析、无线50字节零填充还原、8字节帧编解码与校验 |
| `multiparam_v4_active_stream.c` | 731 | 主动DMA、ISR到PendSV、流重同步、快照发布和15 ms窗口时间戳 |
| `multiparam_v4_interactive.c` | 874 | 参数读写、模式切换、功能开关和主动/交互转换 |
| `multiparam_v4_diagnostics.c` | 378 | 探测包、事务包、通信质量、异常帧和错误日志 |
| `multiparam_v4_internal.h` | 内部头 | 模块间私有常量、状态和内部函数契约 |

V4主动帧72字节、无线滑环在偏移50插入50个零的122字节兼容、P0至P14参数、连续3帧异常报警、15 ms半双工保护和临时广播发包策略均保持不变。

## 5. 共享协议与兼容性

- CPU2和CPU3的`DEVICE_PROTOCOL_VERSION`均为35。
- `DeviceParameters.sensorType`地址、32位宽度、字段偏移和默认值不变。
- `DEVICE_PARAM_VERSION`继续为3，不触发整套参数恢复出厂。
- CPU3协议35只接受14作为DM4并显示“DM4传感器”，不保留15的运行期别名。
- 协议34及更早程序对14和15的解释不同，禁止与协议35混用；降级前必须人工确认传感器类型。
