## 维护规则

- 新增问题分析文档优先放入 [未处理/](未处理/)，待代码、验证或决策闭环后再移动到 [已闭环/](已闭环/)。
- 问题分析文档应包含现象、影响范围、根因、整改方案、验证方法、未验证风险和后续动作。
- 如果同一问题已经进入版本发布，文档中应引用对应的版本改动与测试方案。
- HTML 主要作为流程化阅读或历史分析页保留；长期维护的问题结论应补 Markdown 或在 README 中标明对应维护源。
- 移动文档后同步更新本目录 README 和 [问题专题索引.md](问题专题索引.md)。
