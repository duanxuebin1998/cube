# 故障代码表权威来源判定

更新日期：2026-07-14

本文记录CPU2/CPU3故障码资料的权威边界。正式故障项目维护在 `docs/00_构建与版本/故障码/LTD故障代码统一表.xlsx`，完整枚举、调用点、链路、编号迁移和治理记录维护在 `docs/00_构建与版本/故障码/LTD内部技术与治理资料.xlsx`；二者职责不同，不是两份并行的正式故障代码表。

## 结论

- CPU2共享定义以 `LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.h` 的 `ErrorCode` 为准。当前共65项，其中2项为非故障状态，实际共享故障码63项。
- CPU3同步CPU2的65项定义，并额外定义本机故障 `CPU2_COMM_TIMEOUT = 0x00140007`；不得据此要求CPU2增加无产生场景的枚举。
- `当前程序故障代码清单.md` 是当前源码的可检索Markdown清单。
- `LTD故障代码统一表.xlsx` 是唯一正式故障项目工作簿；当前页收录63个共享故障和1个CPU3本机故障。
- “历史故障代码_CPU2V1.24.0.0”冻结CPU2 V1.24.0.0开发基线，不随当前枚举删除或重编号改写。
- “一代计量仪历史故障代码”独立保存一代设备资料，只按一代主控程序版本查询。
- `LTD内部技术与治理资料.xlsx` 保存65项CPU2枚举定义、1项CPU3本机故障、调用点、链路复查、分类规则和协议16到17的编号迁移。
- 如果工作簿和源码冲突，以对应产生端源码为准；共享码按CPU2枚举维护，CPU3本机码按CPU3枚举和实际产生链路维护。

## 判定依据

| 对象 | 判定 |
| --- | --- |
| CPU2 `ErrorCode` | 故障码产生和上报的定义源；当前65项包含2个非故障状态和63个共享故障 |
| CPU2 `ErrorLog_GetCodeName/ReasonByCode` | 当前63个共享故障的统一日志名称和原因 |
| CPU3 `ErrorCode` | 同步CPU2的65项定义，并额外定义本机 `CPU2_COMM_TIMEOUT` |
| CPU3 `Display_GetErrorReasonByCode` | 显示当前共享故障和20-7本机故障原因 |
| 正式工作簿 | 保存当前64个故障项目、两代历史代码、中文说明、处理方法、设备参数和测量结果 |
| 内部技术工作簿 | 保存完整枚举、调用点、链路、分类、迁移和治理证据 |

## 维护顺序

1. 先判断错误码是CPU2共享故障、非故障状态，还是CPU3本机故障。
2. 共享故障先修改CPU2 `ErrorCode`，再同步CPU2日志名称和原因。
3. 同步CPU3 `ErrorCode`、显示原因和本机故障产生/恢复链路。
4. 更新当前Markdown清单、正式工作簿、内部技术工作簿和协议兼容记录。
5. 按CPU2程序版本归档新历史表；不得回写旧快照，也不得复用旧编号。
6. 数值、责任域或显示解释变化时，评估 `DEVICE_PROTOCOL_VERSION` 和两端固件版本。

## 当前处理

- 共享协议17采用二代编号方案：11～18优先延续一代类别加10，20～22作为二代新增责任域；10、16、19保留代际对应类别但当前无故障。
- 当前Markdown、正式工作簿和内部技术工作簿已按65项CPU2定义、63项共享故障和1项CPU3本机故障维护。
- 正式工作簿64个故障项目中，使用中61项、保留3项；12项停用码只保留在CPU2 V1.24.0.0历史表，旧编号不复用。
- CPU2共享故障按CPU2程序版本选表；CPU3本机20-7按CPU3程序版本确认；共享协议版本只用于两端配套判断。
- 一代历史页不计入当前故障项目统计，旧设备必须先确认代际。
