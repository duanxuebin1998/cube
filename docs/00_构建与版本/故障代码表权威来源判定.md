# 故障代码表权威来源判定

更新日期：2026-07-10

本文用于记录 CPU2/CPU3 两份历史 `LTD故障代码表.xlsx` 的合并结果，避免后续继续出现两个故障代码表。当前正式表格入口已经统一为 `docs/00_构建与版本/故障码/LTD故障代码统一表.xlsx`。

## 结论

- 73 项 CPU2/CPU3 共享故障码的最终依据是 `LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.h` 中的 `ErrorCode`。
- CPU3 本机扩展码的最终依据是 `LTD_DISPLAY_CPU3/Application/system_param/system_parameter.h` 中的 `ErrorCode`，不得据此要求 CPU2 增加无产生场景的枚举。
- `docs/00_构建与版本/故障码/当前程序故障代码清单.md` 是当前源码的可检索 Markdown 清单，分别列出 73 项共享码和 CPU3 本机扩展码。
- `docs/00_构建与版本/故障码/LTD故障代码统一表.xlsx` 是唯一表格维护入口，包含 73 项共享总表、CPU3 本机故障码和分类/链路/辅助资料。
- 历史 CPU2 分表的故障代码总表已并入统一表；历史 CPU3 分表只作为合并来源，不再作为故障码定义或显示辅助的维护入口。
- 如果 Excel 表和源码冲突，以对应产生端源码为准；共享码按 CPU2 枚举维护，CPU3 本机码按 CPU3 枚举和显示产生链路维护。

## 判定依据

| 对象 | 判定 |
| --- | --- |
| CPU2 `ErrorCode` 枚举 | 故障码产生和上报的源头，包含当前 73 项，包括 `NO_ERROR`、`STATE_SWITCH` 和 5 个 `AD5421_*` 错误码 |
| CPU2 `ErrorLog_GetCodeName/ReasonByCode` | 当前覆盖 CPU2 `ErrorCode` 枚举中的故障码，用于日志名称和原因口径 |
| CPU3 `ErrorCode` 枚举 | 同步 CPU2 的 73 项共享码，额外保留兼容别名和 `CPU2_COMM_TIMEOUT` 等 CPU3 本机扩展码 |
| CPU3 `Display_GetErrorReasonByCode` | 用于屏幕显示原因，覆盖故障态错误码；`NO_ERROR`、`STATE_SWITCH` 不作为故障原因显示 |
| Markdown 当前清单 | 共享码由 CPU2 `ErrorCode` 整理，CPU3 本机扩展码由 CPU3 `ErrorCode` 和产生链路整理 |
| 统一 Excel | “故障代码总表”保存 73 项共享码；“CPU3本机故障码”单独保存 CPU3 单侧产生的扩展码 |
| 分类规则和链路复查页 | 记录当前分类口径、源码使用统计、CPU2 日志覆盖、CPU3 显示覆盖、预留/历史保留和第 3 阶段调用点评审候选 |
| 旧表差异页 | 记录历史 CPU3 表中的旧口径条目，例如 `MOTOR_OVERCURRENT`、`ENCODER_DATA_LOST`、`MEASUREMENT_ZERO_CALIB_TIMEOUT`，明确不作为当前故障码定义 |

## 维护顺序

1. 先判断错误码是 CPU2/CPU3 共享码还是 CPU3 本机扩展码。
2. 共享码检查 CPU2 `ErrorCode`，并同步 CPU2 日志名称和原因。
3. 检查 CPU3 `ErrorCode` 是同步共享码还是新增本机扩展码。
4. 检查 CPU3 `Display_GetErrorReasonByCode()` 和本机故障产生点。
5. 更新 Markdown 清单，再更新统一 Excel 的共享总表或“CPU3本机故障码”工作表。
6. 如果错误码调用点、语义、显示或协议映射发生变化，同步复核兼容性影响和版本测试资料。

## 当前处理

- 统一表已补齐 5 个 `AD5421_*` 错误码，并在“整理说明”中记录权威来源和两份旧表的合并原因。
- Markdown 当前清单已按当前源码列出 73 项共享码和 `CPU2_COMM_TIMEOUT` CPU3 本机扩展码。
- 统一表已补充“分类规则”“链路复查”“治理摘要”三个工作表；当前标注运行使用 54 项、非故障状态 2 项、预留/历史保留 17 项，并列出 8 个第 3 阶段调用点评审候选。
- CPU3 本机故障码、显示、设备参数、测量结果、保持寄存器和 `param_meta` 辅助资料已合并进统一表；后续只维护统一表，不再维护 CPU2/CPU3 两份分表。
