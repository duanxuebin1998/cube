# 文档库使用指南

更新日期：2026-06-27

本文面向实际查资料的人，解决“我该先看哪份、哪份能改、哪份只是附件”的问题。维护规则和迁移记录见 `文档库治理清单.md`、`文档库迁移映射表.md`。

## 文件类型优先级

| 文件类型 | 定位 | 维护原则 |
| --- | --- | --- |
| `.md` | 可维护正文 | 优先修改；应写清依据、版本、验证和未确认项 |
| `.html` | 流程图、结构图或阅读版 | 当前保留为阅读入口；长期内容应回链 Markdown 或源码依据 |
| `.xlsx` | 参数表、寄存器表、故障码表、状态矩阵 | 只有被 README 标为维护表时才直接改；否则先补 Markdown 说明 |
| `.docx` | 现场确认稿、菜单稿、历史源文档 | 不直接覆盖为正文；需要可维护内容时补 Markdown 摘要 |
| `.pdf` | 外部资料、导出件、图纸、历史阅读版 | 默认不修改；同名 Markdown 存在时以 Markdown 为准 |
| `.DAT`、`.txt`、`.zip` | 原始日志或外部包 | 保留原始证据，不手工改正文 |

## 常见判断

| 情况 | 以谁为准 |
| --- | --- |
| Markdown 和 PDF 同名 | Markdown 是维护正文，PDF 是历史导出或外发阅读件 |
| Markdown 和 HTML 同主题 | Markdown 写维护口径；HTML 用于流程图、图形化阅读或历史展示 |
| Word 和 Markdown 同主题 | Markdown 是维护正文，Word 是确认稿或导出版 |
| Excel 和源码冲突 | 源码为准；Excel 必须补说明或同步修正 |
| CPU2/CPU3 故障代码表冲突 | 已合并为 `00_构建与版本/故障码/LTD故障代码统一表.xlsx`；定义仍以 CPU2 `ErrorCode` 为准 |
| 外部资料和项目解释冲突 | 外部资料是输入，项目解释必须写清当前代码如何采用或偏离 |

## 维护动作顺序

1. 先确认资料属于哪个业务域，不按文件格式直接归档。
2. 如果已有同主题 Markdown，优先更新 Markdown，再决定是否需要同步导出版。
3. 如果只有 PDF、DOCX 或 XLSX，先在对应 README 标明用途、维护状态和权威性。
4. 如果移动或重命名文件，按 `新增资料落位检查表.md` 搜索旧路径引用，再更新 README、迁移映射表和相关文档。
5. 资料迁移、目录整理或链接修改后可运行 `py tools\check_docs.py`；它只检查仓库文档结构和 `docs/` 内相对链接，不参与 skill 版本文档生成。
6. 修改文档后运行 `git diff --check`；需要验证本地文档站时，在 `docs-site/` 运行 `npm run check`，构建结果不提交。

## 人工索引不改变生成规则

`版本总览.md`、`附件与源文件清单.md`、`新增资料落位检查表.md`、`流程排查入口.md`、`问题专题索引.md` 和 SIL `资料用途矩阵.md` 都是人工查找或复核入口。后续版本提交时，仍按既有 skill 规则新增 `版本改动与测试/` 文档、同步 `CHANGELOG.md` 和必要的流程资料；这些索引可以提交后补，不应成为版本生成或提交门禁。
