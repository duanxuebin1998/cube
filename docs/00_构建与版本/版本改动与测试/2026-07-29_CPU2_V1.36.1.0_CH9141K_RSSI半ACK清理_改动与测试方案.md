# CPU2 V1.36.1.0 CH9141K RSSI半ACK清理改动与测试方案

## 1. 文档目的和适用版本

本文用于复核CPU2在读取CH9141K连接状态时，`AT+RSSI=ON`已被模块执行但ACK只返回部分字符后，异步RSSI上报未关闭并污染后续DSM透传响应的问题。

- 修改前版本：CPU2 `V1.36.0.0`
- 修改后版本：CPU2 `V1.36.1.0`
- CPU3版本：保持`V1.36.0.0`
- 适用硬件：CPU2 UART6连接CH9141K主机模块，CH9141K透传连接DSM传感器

## 4. 详细改动

### 4.1 RSSI开启尝试与清理责任绑定

- 源码位置：`wireless_pairing.c`的`WirelessPairing_ReadConnectionStatus()`和`WirelessPairing_PrintConnectionStatus()`。
- 改前问题：只有完整收到`AT+RSSI=ON`的成功ACK后才设置`rssi_started`。现场出现模块已执行命令但仅返回`O`时，程序跳过`AT+RSSI=OFF`，异步`RSSI:-35dB\r\n`进入后续DSM `Cl`接收缓冲区。
- 具体改法：改用`rssi_enable_attempted`，在发送`AT+RSSI=ON`之前置位；凡尝试过开启RSSI，无论ACK是否完整都执行关闭清理。
- 必查边界：完整ACK、半ACK、零字节超时、明确ERR、命令切换以及异步RSSI等待超时。
- 通过标准：半ACK后仍能观察到关闭RSSI动作，后续DSM帧不包含`RSSI:`文本。

### 4.2 OFF和EXIT不确定时执行有界强制恢复

- 源码位置：`ch9141_at.c/.h`的`CH9141_AT_RecoverRssiQuery()`及两个RSSI查询收尾路径。
- 改前问题：普通`AT+RSSI=OFF`或`AT+EXIT`收不到完整ACK时，无法确认模块是否仍在RSSI上报或AT模式，后续透传命令可能无响应或收到异步文本。
- 具体改法：新增仅供主循环调用的有界恢复接口；停止UART6 DMA、清除硬件错误，阻塞发送原始`AT+RSSI=OFF\r\n`与`AT+EXIT\r\n`，每步排空接收数据，最后中止并清理UART。
- 必查边界：OFF短ACK、EXIT短ACK、UART FE/ORE/NE、DMA忙、清理期间收到命令切换、模块已提前回到透传模式。
- 通过标准：恢复动作在有限时间内结束；UART6不保留错误或忙状态；下一条DSM命令能够收到自身协议响应。

### 4.3 RSSI阶段状态切换向上传递

- 源码位置：`WirelessPairing_ReadConnectionStatus()`。
- 改前问题：RSSI阶段的`STATE_SWITCH`可能被改写为`NO_ERROR`，使上层继续当前读取流程。
- 具体改法：RSSI读取或关闭阶段返回`STATE_SWITCH`时原样向上传递，同时完成强制清理。
- 必查边界：开启前切换、等待异步RSSI时切换、关闭RSSI时切换和退出AT时切换。
- 通过标准：上层收到`STATE_SWITCH`且不进入故障出口；UART6恢复透传可用状态。

## 5. 异常闭环

```text
进入AT -> 查询连接/MAC -> 发送RSSI=ON前标记必须清理
  -> 完整ACK：等待异步RSSI
  -> 半ACK/超时/切换：进入收尾
收尾 -> 普通RSSI=OFF
  -> 成功：普通AT+EXIT
  -> 失败：强制RSSI=OFF + AT+EXIT，跳过重复普通EXIT
普通AT+EXIT失败 -> 再执行一次有界强制清理
最终排空UART6 -> 返回业务结果或STATE_SWITCH
```

## 9. 风险与未验证项

- CH9141K在半ACK条件下是否可靠接受紧随其后的OFF和EXIT，需要真实模块抓包确认。
- 强制恢复使用阻塞HAL发送，只允许在主循环调用；不得从ISR或ISR直接调用链进入。
- 如果CH9141K或远端DSM硬件已掉电、复位或死机，清理AT状态不能代替硬件恢复。
- 尚未执行真实半ACK、UART FE/DMA故障以及恢复后首条DSM `Cl`台架测试。
