# 2026-06-03 CPU2 V1.10.0.0 CPU3 V1.9.0.0 启动安全与串口调试状态改动与测试方案

## 版本变化

- CPU2：`V1.9.1.0 -> V1.10.0.0`
- CPU3：`V1.8.0.0 -> V1.9.0.0`
- CPU2/CPU3 共享 `DEVICE_PROTOCOL_VERSION`：`5u -> 6u`
- 升级原因：新增 CPU2/CPU3 共享设备状态 `STATE_DEBUG_MODE = 0x0033`，复用原 `reserved2` 参数槽控制故障自动恢复重跑次数，同时合并 CPU2 启动安全、编码器首帧门控、B/BE 诊断打印、电机日志收敛和空载扭力有符号参数同步。

## 协议版本与兼容性

- 本次不新增保持寄存器或输入寄存器地址。
- 本次不改变 `MeasurementResult` 和 CPU2/CPU3 内部 Modbus 打包顺序；`DeviceParameters` 原 `reserved2` 字段语义替换为 `fault_auto_recovery_retry_limit`，后续字段地址不移动。
- 共享 `DeviceState` 新增 `STATE_DEBUG_MODE = 0x0033`，CPU2 发布后由 CPU3 设备状态页显示“调试模式中”。
- 故障自动恢复重跑上限参数语义为：`0` 关闭自动恢复重跑，`1~10` 为最多自动重跑次数，默认 `3`；旧协议存储升级到协议版本 6 时由 CPU2 补默认值。
- `empty_weight` 空载扭力保持原保持寄存器地址和 2 word 长度不变，32 位内容按 `int32_t` 有符号值解释，负值按二进制补码传输。
- CPU2/CPU3 必须同为协议版本 6；旧 CPU3 不识别 `STATE_DEBUG_MODE`，应由协议版本不匹配检查拦截。
- CPU3 外部 DSM 状态转换层将内部 `STATE_DEBUG_MODE` 映射为既有维护模式状态，避免外部 DSM 主站收到未知内部状态值。

## 详细改动

### CPU2 启动安全和编码器门控

- GPIO 默认电平改为电机驱动禁用，SPI 片选默认为空闲高电平，并同步 `.ioc`。
- 新增 `MotorCtrl_BootSafeStop()`，在 SPI2 初始化完成后、`App_Init()` 前执行早期安全停机。
- 早期安全停机会保持驱动禁用，写 `VMAX=0`，读取 `XACTUAL` 后写入 `XTARGET`，并切回位置模式。
- AS5145 采集链路新增首帧有效标志和最近有效帧 tick，成功解析完整 SSI 帧后才置位。
- `Start_Encoder_Collection_TIM()` 启动定时器后立即触发一次 SSI 读取，缩短启动位置盲区。
- `Initialize_Encoder()` 等待编码器首帧有效；编码轮记步模式下等待失败会置编码器错误。
- 普通运动入口统一调用运动就绪检查，在写 `VMAX/XTARGET/RAMPMODE` 前确认驱动和位置源就绪。
- 强制上行、强制下行和强制找零只绕过编码器首帧门控，不绕过驱动初始化和上电安全停机检查。
- `App_Init()` 调整初始化顺序，编码器启动后再保留 1 秒外设稳定延时，电机初始化失败或编码器未就绪时拦截上电默认命令。

### CPU2 串口调试状态

- `DEVICE_PROTOCOL_VERSION` 从 `5u` 升级到 `6u`。
- `DeviceState` 新增 `STATE_DEBUG_MODE = 0x0033`。
- `process_command()` 新增串口调试显示状态快照 helper。
- `SC/A/C/D/E/L/M/N/T*/Y*` 等不走正式测量状态机的调试指令执行期间临时发布 `STATE_DEBUG_MODE`。
- 调试指令正常返回或命令切换退出时，仅当当前仍是调试模式才恢复进入前状态，避免覆盖故障态或其他业务态。
- `F/H/J` 保持原逻辑，因为它们调用正式测量流程，应显示探底、零点测量、液位测量和液位跟随等业务状态。
- 正式命令映射、无线滑环 `SP*` 和演示 `X` 保持各自现有状态语义。

### CPU2 B/BE 诊断

- `B/BE` 进入诊断时保存原 `device_state`/`error_code`，并切换为 `STATE_DEBUG_MODE`。
- 诊断期间清除临时错误时仍回到调试模式，不再短暂显示待机或错误态。
- 诊断退出时恢复进入前业务状态和错误码快照，避免影响正常测量流程。
- `BE` 编码器闭环轮询周期由 20ms 调整为 10ms，只影响 B/BE 诊断流程，用于更早触发编码器目标停机。
- 将 B/BE 打印统一整理为中文阶段名和中文字段，包含保护行程、编码器到位触发、停稳结果、触发偏差、停稳偏差和通信检查。
- 串口命令入口打印改为 `串口B指令 命令参数`，避免与 B/BE 内部详细启动日志重复。
- 按现场反馈撤回 B/BE 专用 10 倍加减速度调整；当前 B/BE 不读写 TMC5130 `A1/AMAX/D1/DMAX`，继续使用正常程序斜坡配置。

### CPU2 电机日志

- 电机初始化日志改为单条 `电机初始化完成` 摘要，合并初始化方式、速度、尺带长度、卷筒周长、`VMAX`、电流档位和等效微步速度。
- 底层 TMC5130 电流写入和速度换算不再重复打印，避免启动和停止恢复流程刷屏。
- 手动速度/电流设置保留单条中文结果打印。
- 急停、慢停、可选速度和临时速度恢复改走静默路径，只更新参数和寄存器，不打印用户操作日志。

### CPU2 故障自动恢复次数参数

- 新增 `fault_auto_recovery_retry_limit`，复用原 `reserved2` 保持寄存器地址和结构体位置。
- CPU2 自动恢复确认成功后，按该参数限制自动重跑原命令次数；参数为 `0` 时不进入自动恢复重跑。
- 参数大于 `10` 时按默认 `3` 处理，并在参数加载归一化时写回默认值。
- 恢复确认的部件参数读取仍按 1 秒节流执行，不纳入业务命令重跑计数。

### CPU2/CPU3 空载扭力有符号处理

- CPU2 参数结构体中的 `empty_weight` 按 `int32_t` 保存，获取空载扭力、参数打印和内部保持寄存器打包都保留负值语义。
- CPU3 参数结构体和参数同步逻辑同步按 `int32_t` 处理 `empty_weight`，避免负值在参数表中被解释为无符号大数。
- `HOLDREGISTER_DEVICEPARAM_EMPTY_WEIGHT` 地址和长度不变，仍占 2 个 word；外部读写工具需要按有符号 32 位解释该字段。
- 满载扭力、上限扭力和下限扭力仍按原无符号语义处理，不跟随本次空载扭力语义调整。

### CPU3 显示和外部状态

- `DEVICE_PROTOCOL_VERSION` 从 `5u` 升级到 `6u`。
- `DeviceState` 新增 `STATE_DEBUG_MODE = 0x0033`。
- 设备状态表新增 `STATE_DEBUG_MODE`，中文显示“调试模式中”，英文显示 `Debug Mode`。
- 参数页将原 `reserved2` 显示为“自动恢复次数”，范围 `0~10`，写入同一内部保持寄存器地址。
- 字库已有“调试模式中”和“自动恢复次数”所需汉字，无需新增点阵。
- 内部 `STATE_DEBUG_MODE` 对外翻译为既有 `STATE_MAINTENANCEMODE`，避免 DSM 外部状态寄存器出现未知 `0x0033`。

### 文档和工具

- 追加协议版本 6 记录，说明共享状态语义、寄存器布局影响和兼容要求。
- 新增 CPU3 参数菜单与故障自动恢复次数说明，整理菜单入口、保持寄存器、参数范围和联调检查。
- 新增 CPU2 串口调试指令与打印信息梳理文档。
- 更新串口 B 指令 HTML 流程说明。
- 新增 SI协议兼容性与指令映射整理。
- 新增重启后电机继续运行导致丢步问题分析文档和 PDF。
- 补充 SIL 功能安全认证准备资料、CPU2 编码规范、偏离记录模板、整改检查表和 Markdown 转 PDF 工具。

## 影响范围

- 影响 CPU2 上电、软件复位、看门狗复位和调试重启后的电机默认安全态。
- 影响 CPU2 编码轮记步模式下普通运动和上电默认命令的启动前置条件。
- 影响 CPU2 串口调试指令执行期间的设备状态显示。
- 影响 CPU2 串口 `B/BE` 的现场打印、错误状态恢复和编码器停机轮询。
- 影响 CPU2 电机初始化、手动速度/电流设置、急停/慢停和临时速度恢复的打印量。
- 影响 CPU2 故障自动恢复成功后的原命令自动重跑次数。
- 影响 CPU2/CPU3 空载扭力参数的保存、同步、读取、打印和菜单参数缓存显示。
- 影响 CPU3 设备状态页对 `STATE_DEBUG_MODE` 的显示。
- 影响 CPU3 参数页对故障自动恢复次数的显示和写入。
- 影响 CPU3 外部 DSM 状态转换层对内部调试状态的兜底映射。
- 不影响 CPU2/CPU3 共享寄存器地址、后续参数地址和外部寄存器地址。
- 不影响正式测量命令的 `current_command` 管理、测量流程状态和电机业务状态。

## 风险和注意事项

- `DRV_ENN` 默认禁用会取消电机保持电流；机械结构如果不能自锁，需要台架确认失电/复位瞬间不会产生危险位移。
- 编码器首帧等待超时时间有限；如果现场编码器稳定时间更长，可能出现编码器超时错误。
- 强制调试运动仍可能产生实际运动，必须由人工确认现场安全条件。
- `B/BE` 会在退出时恢复进入前错误状态；如果执行前系统已有错误，退出后仍会保留原错误。
- `B/BE` 运行期间产生的临时错误不会作为系统最终错误保留，现场排查需要依赖串口打印和运动现象。
- 当前 B/BE 不再修改加减速度；若 BE 停稳偏差仍超出现场允许范围，后续应优先评估提前停机或速度参数，而不是临时放大斜坡寄存器。
- `fault_auto_recovery_retry_limit=0` 会关闭自动恢复重跑，现场如果依赖原 3 次自动重跑，需要确认参数页未被误写为 0。
- 外部工具或 PLC 如果直接把 `empty_weight` 两个保持寄存器拼成无符号 32 位数，负空载扭力仍会显示为大正数，需要同步更新解释口径。
- 打印文案改为中文后，依赖英文关键字解析串口日志的外部脚本需要同步更新。

## 测试点

### 1. 运行中 CPU2 复位

步骤：
1. 让电机执行长距离运动。
2. 在运动过程中触发 CPU2 软件复位、看门狗复位或调试重启。
3. 观察 GPIO 初始化后电机是否继续执行复位前旧目标。

预期结果：
- GPIO 初始化后 `DRV_ENN` 保持禁用。
- `MotorCtrl_BootSafeStop()` 打印安全停机结果。
- 电机不再沿用复位前旧 `XTARGET/VMAX` 继续运行。

通过标准：
- 复位盲区内不出现持续旧运动。
- 编码器计数和实际位置偏差不再因旧运动继续扩大。

### 2. 编码器首帧门控

步骤：
1. 保持编码器正常连接，上电启动 CPU2。
2. 断开编码器或制造首帧无效场景，再次上电启动。
3. 分别下发普通上/下行或绝对位置运动命令。

预期结果：
- 编码器正常时能收到首帧有效 SSI 数据，普通运动命令可执行。
- 编码轮记步模式下首帧未就绪时设置编码器错误，普通运动命令在写 TMC5130 运动寄存器前被拦截。

通过标准：
- 正常场景不出现编码器超时。
- 异常场景电机不启动，错误码为编码器相关错误。

### 3. 上电默认命令拦截

步骤：
1. 配置 `powerOnDefaultCommand` 为非 `CMD_NONE`。
2. 分别制造电机初始化失败、编码器首帧未就绪和正常启动三种场景。

预期结果：
- 电机初始化失败时默认命令被拦截。
- 编码轮记步模式下编码器首帧未就绪时默认命令被拦截。
- 正常启动时默认命令按原流程转换为测量命令。

通过标准：
- 异常场景不产生自动运动。
- 正常场景不影响既有默认命令功能。

### 4. 串口调试指令显示调试模式

步骤：
1. CPU2 烧录 `V1.10.0.0`，CPU3 烧录 `V1.9.0.0`。
2. 在待机状态下分别下发 `SC`、`A0`、`A+`、`A-`、`C`、`D`、`E`、`L`、`M`、`N`、`TS`、`YC`。
3. 在 CPU3 设备状态页观察状态文本。
4. 在命令结束、命令切换或停止后继续观察状态是否恢复。

预期结果：
- 指令执行期间 CPU3 显示“调试模式中”。
- 指令退出后恢复进入调试指令前的业务状态。
- 如果指令执行中产生真实故障，恢复逻辑不覆盖故障状态。

通过标准：
- 目标调试指令执行期间不再显示“液位跟随中”等旧业务状态。
- 调试指令退出后不把设备强制留在调试模式。

### 5. B/BE 诊断状态隔离和打印

步骤：
1. 在待机状态下下发 `B100`，观察 CPU3 状态和串口日志。
2. 在待机状态下下发 `BE100`，观察 CPU3 状态和串口日志。
3. 在液位跟随或其他业务状态中打断并下发 `B100` 或 `BE100`。
4. 中途切换新命令，让 B/BE 提前退出。

预期结果：
- B/BE 运行期间显示“调试模式中”。
- B/BE 内部临时错误清除后不短暂回到待机。
- B/BE 退出后恢复进入前状态和错误码快照。
- 串口打印使用 `B电机测试`、`BE编码器测试`、`B下行`、`B上行回零`、`BE下行`、`BE上行` 等中文阶段名。
- BE 编码器到位打印包含触发位置、目标位置、触发偏差、停稳位置和停稳偏差。
- B/BE 不打印 `B/BE快速加减速`，也不读写 `A1/AMAX/D1/DMAX`。

通过标准：
- 串口调试过程不会把诊断错误遗留给正常测量流程。
- 现场不会再看到 B/BE 运行时仍停留在被打断前的“液位跟随中”状态。
- 编码器计数变化与打印的当前位置、目标位置一致。

### 6. 正式测量流程状态保持

步骤：
1. 下发 `F`，观察探底流程状态。
2. 下发 `H`，观察零点测量流程状态。
3. 下发 `J`，观察液位测量和液位跟随流程状态。
4. 下发正式命令映射对应的业务命令，观察 `current_command` 和设备状态。

预期结果：
- `F/H/J` 仍显示各自业务流程状态，不显示调试模式。
- 正式命令仍由主循环状态机处理，不受串口调试模式 helper 影响。

通过标准：
- 正式业务流程状态、错误恢复和命令切换行为与改动前一致。

### 7. CPU3 显示和外部协议兜底

步骤：
1. CPU2 发布 `STATE_DEBUG_MODE` 时观察 CPU3 设备状态页。
2. 读取 DSM 外部输入寄存器 `INPUTREGISTER_SYSTEMSTATE`。
3. 检查 SI 和 Wartsila 轮询不出现异常响应。

预期结果：
- CPU3 设备状态页显示“调试模式中”。
- DSM 外部状态寄存器不返回未知 `0x0033`，而是按维护模式兜底。
- SI/Wartsila 仍按既有默认状态映射和异常处理运行。

通过标准：
- CPU3 本机显示可见内部调试模式。
- 外部协议主站不因新增内部状态发生未知状态异常。

### 8. 电机日志收敛

步骤：
1. 上电启动并观察电机初始化日志。
2. 手动设置电机速度和电流。
3. 执行急停、慢停和一次临时速度运动。

预期结果：
- 初始化只输出单条 `电机初始化完成` 摘要。
- 手动速度/电流设置输出单条中文结果。
- 急停、慢停和临时速度恢复不额外刷出用户操作日志。

通过标准：
- 现场日志能保留关键参数，又不会因内部恢复路径重复刷屏。

### 9. 故障自动恢复次数参数

步骤：
1. 将 `fault_auto_recovery_retry_limit` 设置为 `0`，制造一次可恢复测量故障。
2. 将参数设置为 `1`，制造“恢复确认成功，但原命令再次失败”的场景。
3. 将参数设置为 `3`，重复制造失败并观察自动重跑次数。
4. 通过内部 Modbus 或异常参数写入大于 `10` 的值，重启后观察启动打印和寄存器值。

预期结果：
- 参数为 `0` 时，CPU2 不进入自动恢复重跑，后续交由普通错误态兜底。
- 参数为 `1` 时，恢复确认成功后最多只自动重跑原命令 1 次，再失败则停止继续重跑。
- 参数为 `3` 时保持原默认最多 3 次重跑行为。
- 参数大于 `10` 时归一化为默认 `3`，不会按异常大值持续重跑。

通过标准：
- 自动重跑次数与参数一致，且达到上限后保持错误态并停止继续重入测量。
- CPU3 参数页显示“自动恢复次数”，范围限制为 `0~10`，写入后 CPU2 读取值一致。

### 10. 空载扭力有符号参数

步骤：
1. 通过空载扭力流程或内部 Modbus 将 `empty_weight` 写为负值，例如 `-500`。
2. 读取 `HOLDREGISTER_DEVICEPARAM_EMPTY_WEIGHT` 对应两个保持寄存器，确认原始 32 位补码值不被破坏。
3. 在 CPU2 参数打印、CPU3 参数缓存或参数页中观察空载扭力显示。
