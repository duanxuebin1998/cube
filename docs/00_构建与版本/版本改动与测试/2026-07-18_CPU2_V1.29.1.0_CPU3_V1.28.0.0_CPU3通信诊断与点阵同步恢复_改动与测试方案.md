## 4. 逐项实现说明

### 4.1 CPU2六种分布测量统一原子发布

- 源码位置：`measure_density.c`的`DensityProfile_Begin`、`DensityProfile_PublishResult`及四种分布测量出口；`measure.c`的Wartsila和综合测量入口。
- 改前问题：各测量模式分别写点阵、来源、锁存和完成计数，CPU3在完成边沿可能读到新计数与旧来源或半更新点阵；综合测量来源还可能与实际模式不一致。
- 具体改法：测量开始先清旧锁存；候选数据、来源和锁存写完后使用内存屏障，并在短临界区最后递增完成计数；综合测量通过实际参数映射来源。
- 必查边界：普通、国标、每米、间隔、Wartsila和综合六种模式；首次测量、连续两轮、空点、最大点数、命令切换和中断并发读取。
- 通过标准：CPU3观察到完成计数变化时，点数、来源、锁存和全部点阵字段属于同一代；契约脚本和CPU2 clean-first构建通过。

### 4.2 CPU3点阵分块同步和20-13自动恢复

- 源码位置：`cpu2_communicate.c`的`CPU2_ProfileStart`、`CPU2_ProfileSyncPoll`、`CPU2_ProfileObservePublicHeader`、`CPU2_ProfileCommitCandidate`及相关失败/恢复函数。
- 改前问题：同步过程中进展计时、会话变化和完整失败代际处理不完整，可能重复读取旧块、在重试间隙穿插普通轮询，或20-13后无法对同一完成代际自动恢复。
- 具体改法：每块成功后刷新进展时间；单块失败按100/300/1000ms重试当前阶段，三次耗尽后等待500ms并从`HEADER_BEFORE`开启下一整轮，最多三轮；任一时刻20秒无进展则直接终止并发布20-13。会话或key变化立即作废候选并从头开始；同步任务活动时独占CPU2轮询槽；完整失败记录代际和会话，2秒后自动重试，同代成功后清20-13。
- 用户可见状态门禁：CPU2先发布六种分布完成态时，CPU3在完整同代点阵提交前把完成态临时映射回对应测量中态；候选完整提交后才恢复原始完成态，真实CPU2故障仍优先于本机20-13。
- 必查边界：普通、国标、每米、区间、Wartsila、综合和SI来源；单帧失败、单块三次失败、整轮三次失败、20秒无进展、完成计数回绕、CPU2重启、会话改变、代际在同步中变化、20-13同代恢复和真实CPU2故障同时存在。
- 通过标准：只发布前后key一致的完整候选；提交前对外不出现“完成态+旧/部分点阵”组合；失败不发布部分点阵；CPU2真实故障不被20-13遮盖；CPU3契约和clean-first构建通过。

### 4.3 USART1异步通信诊断日志

- 源码位置：新增`cpu3_debug_log.c/.h`，以及`app_main.c`、`usart.c`、`dma.c`、`stm32f4xx_it.c/.h`的初始化、DMA和回调接入。
- 改前问题：阻塞式逐字节打印会占用主循环并改变CPU2轮询和外部协议响应时序；发送统计把准备发送、进入pending和真实发送完成混为同一口径。
- 具体改法：使用4KB环形队列和USART1 TX DMA；日志调用只格式化并入队，队列满时丢弃日志并累计；DMA完成后续发下一段；WARN/错误事件和HardFault紧急轮询输出保留；发送统计按提交、排队、DMA启动、完成和失败分层。
- 必查边界：队列空/满/回绕、DMA启动失败、回调续发、ISR与主循环并发、INFO周期摘要、DEBUG长帧、HardFault和调试口未连接。
- 通过标准：日志压力不阻塞业务；ISR不直接格式化打印；CPU3构建、ISR边界和通信契约通过。

### 4.4 外部COM发送完成时序和中断优先级

- 源码位置：`app_main.c`的`HAL_UART_TxCpltCallback`，`usart.c`、`dma.c`和`LTD_DISPLAY_CPU3.ioc`的NVIC配置。
- 改前问题：COM1/2/3发送完成中断各执行18000次忙等待，且与UART5同为抢占优先级0；外部COM活动可能阻塞UART5切回接收，导致CPU2响应前缀丢失、CRC或FE/NE错误。
- 具体改法：TC回调直接释放方向并恢复接收DMA；UART5及其DMA保持0，COM1/2/3及其DMA改为1，USART1调试口及其DMA保持5；源码和`.ioc`同时更新。
- 必查边界：最后停止位、DE释放、pending续发、协议切换ACK、COM1/2/3同时负载、UART5最大205字节响应和DMA/UART错误恢复。
- 通过标准：HAL的`DMA_NORMAL -> UART TC -> TxCpltCallback`链路成立，删除忙等待后不截断末字节；CPU3构建和静态优先级检查通过。现场波形若证明需要尾保持，只能采用TIM5微秒级非阻塞方案。

### 4.5 协议适配层日志与失败分类

- 源码位置：DSM、Wartsila、LTD/SI调用链、`my_crc.c`、`device_param_sync.c`和`cpu2_communicate.c/.h`。
- 改前问题：地址不匹配、CRC失败、处理失败、发送受理和真实完成的日志口径不一致，现场难以区分协议忽略、业务失败和底层UART/DMA故障。
- 具体改法：统一模块、方向、功能码、地址、长度和失败原因字段；地址不匹配不计业务失败；CPU2健康快照提供超时、CRC、地址、功能码、长度、UART和TX DMA分类；中断只记录待处理标志。
- 必查边界：合法帧、短帧、坏CRC、错误地址/功能码、无响应命令、pending覆盖、写参数ACK失败和通信恢复。
- 通过标准：DSM、Wartsila、SI、LTD和外部新鲜度契约均通过，日志口径不改变协议返回和业务状态机。

### 4.6 正式文档交付物

- 源码位置：AO逻辑PDF、全工程问题总账HTML阅读版和两个索引。
- 改前问题：AO逻辑缺少便于外发的固定版式材料；全工程问题总账只有Markdown阅读入口，长文档浏览和打印不便。
- 具体改法：纳入现有AO逻辑PDF；生成无外部资源的独立HTML阅读版并保留Markdown为权威源；索引同时提供Markdown和HTML入口。
- 必查边界：中文编码、内部相对链接、离线打开、目录锚点、打印样式和源文档权威边界。
- 通过标准：HTML结构与源报告问题数量一致，Markdown链接检查无缺失；PDF按用户“全部提交”的授权纳入，不重新生成或改写。
