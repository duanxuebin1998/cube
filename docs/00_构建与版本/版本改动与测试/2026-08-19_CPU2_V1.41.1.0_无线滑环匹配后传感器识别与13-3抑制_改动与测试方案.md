# CPU2 V1.41.1.0 无线滑环匹配后传感器识别与 13-3 抑制改动与测试方案

## 版本与兼容性

- CPU2：`V1.41.0.0 -> V1.41.1.0`，PATCH 修复。
- CPU3：保持 `V1.40.1.0`。
- `DEVICE_PROTOCOL_VERSION` 保持 34；不新增或移动共享寄存器、命令、状态和字段，CPU3 无需修改。
- CPU2 `DEVICE_PARAM_VERSION` 保持 3；参数结构、`struct_size`、CRC 范围和 FRAM 布局不变，升级不恢复出厂参数。
- 无线滑环旧 RSSI 接口继续保留；正式命令 117 使用带传感器识别校验的新接口。

## 改动点

### 1. 匹配后重新识别传感器

- 源码位置：`LTD_MAIN_CPU2/Application/Src/measure.c` 的 `ProcessMeasureCmd`；`LTD_MAIN_CPU2/Services/Sensor/Wireless/wireless_pairing.c/.h` 的 RSSI 匹配入口。调用链为 `命令117 -> RSSI扫描/连接保存 -> SensorService_Detect -> 最终成功状态`。
- 改前问题：无线连接成功后直接发布匹配成功，可能继续使用 FRAM 中旧的传感器类型；测量命令检测状态无效时也可能仅依据旧结果继续执行。
- 具体改法：增加 `WirelessPairing_RunByRssiWithValidator`；命令117在连接保存后调用 `SensorService_Detect`，识别失败则将匹配结果改为失败。需要传感器的测量命令在检测状态无效时主动重新识别，`STATE_SWITCH` 保持取消语义，其它失败设置错误并拒绝测量。
- 必查边界：扫描无候选、连接失败、复位后断链、DSM/V3/V4识别、识别超时、命令切换和重复匹配。
- 通过标准：只有链路正常且识别有效时命令117显示成功并发布目标信息；识别失败不进入测量流程。

### 2. 识别阶段抑制预期的 V4 异步故障上报

- 源码位置：`multiparam_v4_communication.h`、`multiparam_v4_diagnostics.c` 的识别探测模式；`sensor_detector.c` 的 `Sensor_ProbeV4Active`。调用链为 `V4主动探测 -> 预期超时统计 -> 质量故障上报门禁`。
- 改前问题：DSM传感器对V4主动帧保持静默时，连续超时达到阈值会触发全局异步 `13-3`，随后DSM识别成功但屏幕曾短暂显示故障。
- 具体改法：主动探测前开启识别模式；仍记录探测包、超时和质量统计，但不排队全局异步质量故障。成功、超时、命令切换和启动失败均关闭模式并清理质量锁存与连续计数。
- 必查边界：真实V4有效帧、非V4静默、连续超时、异常帧、启动失败、命令切换、中断并发和下一次正常测量。
- 通过标准：非V4识别期间可见探测超时日志，但不出现短暂 `13-3` 屏显；正常测量阶段仍保留连续异常故障上报能力。
