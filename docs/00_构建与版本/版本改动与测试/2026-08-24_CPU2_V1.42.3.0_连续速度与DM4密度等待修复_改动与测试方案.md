## 4. 逐项改动清单

### 4.1 连续速度运动状态与启动失败识别

- 源码位置：`Services/MotorControl/motor_ctrl_internal.h`的`MotorDriverRuntime`和`MOTOR_CONTINUOUS_VELOCITY_START_GRACE_MS`；`motor_ctrl_motion_api.c`的`MotorCtrl_StartVelocity()`、`MotorCtrl_StartFineVelocity()`和`MotorMotion_SetVelocityActiveState()`；`motor_ctrl_position_model.c`的`MotorCtrl_PollRuntimePosition()`。
- 改前问题：连续速度模式没有有效位置目标，沿用位置模式的目标到位判断可能把实际仍在执行的速度命令判为停止并清除方向；驱动未真正起动时也可能静默丢失命令。
- 具体改法：增加连续速度标志和首次启动节拍；连续速度使用`MotorDriver_ReadStoppingState()`读取`VZERO/VACTUAL`，启动500 ms内允许硬件状态建立，窗口后仍未运动则安全停止并返回`MOTOR_STEP_ERROR`；重复同方向调速保留首次启动节拍。
- 必查边界：上下行、精细速度、启动瞬间VZERO、500 ms边界、同方向调速、换向、手动停机、命令切换、驱动通信失败和实际失速。
- 通过标准：有效连续速度命令保持方向和运行态；500 ms后无实际运动时返回`MOTOR_STEP_ERROR`且驱动停止；停止或错误收尾后所有连续速度状态清零。

### 4.2 正式运动和维护调试状态统一

- 源码位置：`motor_ctrl_motion_api.c`的`MotorMotion_SetActiveState()`、`MotorMotion_ClearActiveState()`；`motor_ctrl_driver_param.c`的初始化、速度设置和停止收尾；`Application/Src/service_debug/service_debug_motor.c`的原始运动、点动、重启和退出路径。
- 改前问题：正式接口和维护调试直接分散写入`motor_state`、`motion_command_active`和`motion_wait_active`，新增连续速度状态后容易出现只清理部分字段的残留。
- 具体改法：把运动状态设置和清理函数提升为MotorControl内部公共接口；正式速度入口和维护点动调用专用连续速度设置，初始化、命令切换、手动停止、重启和退出统一清理全部运动字段。
- 必查边界：维护A/B/BE命令、正式速度入口、重启重试、停止确认、异常退出和命令切换。
- 通过标准：任一停止或恢复出口均将显示、命令、等待、连续速度和启动节拍状态复位；再次启动不继承旧方向或旧节拍。

### 4.3 油位位置边界检查使用实时位置

- 源码位置：`Application/Src/measurement/oil_level/oil_level_position.c`的`OilLevel_UpdatePositionAndCheckBounds()`；调用链为油位闭环到`MotorCtrl_PollRuntimePosition()`再到位置发布和边界保护。
- 改前问题：函数直接消费`g_measurement.debug_data.sensor_position`，后台位置刷新延迟或驱动健康异常时可能继续使用过期位置判断油位边界。
- 具体改法：发布位置和执行上下界检查前先轮询运行位置；轮询失败时原样返回错误，不继续发布或判断边界。
- 必查边界：正常连续速度、位置源为编码轮或电机记步、驱动读失败、碰撞/丢步、命令切换和上下边界临界值。
- 通过标准：边界判断使用本轮同步后的实时位置；驱动或位置同步失败时立即退出并保留错误码。

### 4.4 DM4 V4密度模式R04为0的等待语义

- 源码位置：`Services/Sensor/Protocols/Dm4/V4/multiparam_v4_measurement.c`的`MULTIPARAM_V4_IsDensityNotScanned()`、`MULTIPARAM_V4_ReadInteractiveDensity()`和`MULTIPARAM_V4_MeasurementReadDensity()`；上层消费为`SensorService_ReadDensity()`及既有密度等待循环。
- 改前问题：传感器进入密度模式但尚未完成首次扫频时会返回`R04=0`；旧解码把0作为格式错误，导致上层在可以继续等待的阶段提前退出。
- 具体改法：密度模式检测原始R04是否为0；主动快照和交互读取均把频率和密度归零并返回`NO_ERROR`，由上层密度为0或频率无效分支继续轮询；非0值仍执行符号、绝对值、上限和`INT32_MIN`检查。
- 必查边界：R04为0、正值、负值、`INT32_MIN`、超过6600 Hz，R07/R06为有限值或NaN，主动/交互模式以及液位模式。
- 通过标准：密度模式R04为0时不返回格式错误且输出频率0、密度0；液位模式0、`INT32_MIN`和越界频率仍被拒绝；非零密度数据保持既有值和符号语义。

### 4.5 正式协议资料同步

- 资料位置：`多参数传感器通信协议V4.0.md`及同名20页PDF。
- 改前问题：资料只说明0为无效编码，不能表达真实传感器首次扫频阶段和CPU2等待行为。
- 具体改法：明确密度模式0表示尚未扫到有效密度，CPU2把频率和密度归零后继续轮询；液位模式0和`INT32_MIN`边界保持原定义。
- 必查边界：Markdown/PDF语义一致、R04模式前提、负值快扫标志、页面裁切、表格跨页和中文字体。
- 通过标准：两份资料包含相同规则；PDF 20页无裁切、重叠、黑块或乱码。

## 5. 跨模块数据流和异常闭环

- 电机链路：油位或维护入口 -> `MotorCtrl_StartVelocity/StartFineVelocity` -> 连续速度运行态 -> 主循环/油位位置轮询 -> `VZERO/VACTUAL`实际运动判断 -> 正常保持、停止清理或`MOTOR_STEP_ERROR`。
- DM4链路：V4主动快照或交互R04/R07/R06 -> 密度模式与原始R04判断 -> 未扫描时输出0/0 -> `SensorService_ReadDensity()` -> 普通密度、Wartsila或SI等待循环继续；协议错误仍从原错误出口返回。
- 本次不改变CPU2/CPU3共享寄存器、CPU3消费逻辑、参数持久化或外部LTD共享区，因此CPU3和共享协议版本不升级。

## 6. 可执行测试矩阵

### T01 连续速度正常启动与保持

- 关联改动点：4.1、4.2。
- 前置条件：CPU2 V1.42.3.0目标板、电机空载、驱动诊断正常，可读取VZERO/VACTUAL和电机状态。
- 步骤：分别执行上行、下行和精细速度命令；在0、100、500、1000 ms读取方向、VACTUAL和运行态；同方向修改速度后再次读取。
- 预期与通过标准：方向始终与命令一致；实际运动期间运行态不因位置目标状态被清零；同方向调速不重启500 ms窗口。
- 执行状态：未执行，缺少本轮目标板和电机台架。

### T02 连续速度启动失败和停止清理

- 关联改动点：4.1、4.2。
- 前置条件：可通过禁用驱动、机械阻挡或故障注入使VACTUAL持续为0，并可观察错误码和驱动使能。
- 步骤：下发连续速度命令并保持无运动超过500 ms；记录返回码和状态；解除故障后重新启动并执行手动停止、命令切换和维护退出。
- 预期与通过标准：观察窗口内不误报；窗口后返回`MOTOR_STEP_ERROR`并安全停止；各停止出口清零全部运动状态，解除故障后可重新启动。
- 执行状态：未执行，缺少可控电机故障注入环境。

### T03 油位位置实时刷新和边界错误传播

- 关联改动点：4.3。
- 前置条件：油位闭环可运行，可模拟上下边界和TMC寄存器读取失败。
- 步骤：连续运动中改变位置跨越边界；分别在边界前后读取发布位置；注入驱动读取失败并观察测量返回。
- 预期与通过标准：边界使用本轮实时位置；读取失败时不继续发布旧位置并原样返回底层错误。
- 执行状态：未执行，缺少油位和驱动故障台架。

### T04 DM4密度模式未扫描到有效密度

- 关联改动点：4.4、4.5。
- 前置条件：真实DM4 V4或可控串口仿真，密度模式下依次提供R04=0和有效非零频率，R07/R06为有限值。
- 步骤：在主动和交互方式分别输入R04=0；记录CPU2输出和测量循环；随后输入有效正频率和带负号的快扫完成频率。
- 预期与通过标准：R04=0时返回`NO_ERROR`、频率0、密度0且继续轮询；有效正/负频率按绝对值恢复测量，负号快扫标志保留。
- 执行状态：未执行，缺少真实DM4和RS485仿真输入。

### T05 DM4异常编码回归

- 预期与通过标准：所有无效编码继续返回既有格式错误或数据陈旧错误，不被“未扫描”分支放行。
