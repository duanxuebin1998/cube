# CPU3 V1.40.1.0 OLED恢复与确认页按键修正改动与测试方案

## 1. 文档目的和适用版本

本文记录CPU3 OLED硬恢复失败闭环和命令确认页按键计数修正的最终实现、兼容边界、已执行验证及目标板缺口。适用版本组合为CPU2 `V1.40.1.0`、CPU3 `V1.40.1.0`。

## 4. 详细改动

### 4.1 清零完整SSD1325 GDDRAM

- 源码位置：`hgs.c`的`OLED_InitializeAndFill`、`OLED_SetRamWindow`、`OLED_SetVisibleWindow`和`OLED_WriteFillData`。
- 改前问题：初始化写入可见窗口后直接循环80行填充，窗口仅覆盖64行并发生回绕；控制器完整80行GDDRAM未被确定性清零，异常恢复后可能保留不可见行历史数据。
- 具体改法：硬复位和初始化后先把窗口设为列`0x00~0x3F`、行`0x00~0x4F`，连续写入80×64字节，再把窗口恢复为可见行`0x0C~0x4B`，最后发送开屏命令；普通`OLED_Clear`仍只清64行可见区。
- 必查边界：完整窗口起止行、每行64字节、80行乘积5120字节、可见窗口恢复、填充中途SPI失败和非零填充值。
- 通过标准：逻辑分析仪可见完整窗口命令和5120字节填充；恢复后首个普通绘制仍落在`0x0C~0x4B`，滚动或反复恢复不重新出现残留像素。

### 4.2 复位释放等待与底层错误传播

- 源码位置：`hgs.c`的`OLED_ResetPin`、`OLED_InitializeAndFill`、`OLED_Clear`、`OLED_RecoverAndClear`、`all_screen`及`hgs.h`接口声明。
- 改前问题：NREST拉高后立即发送命令；清屏和恢复接口返回`void`，调用层无法区分成功与SPI/HAL失败，可能继续绘制并把不完整帧当作完成。
- 具体改法：NREST释放后固定等待1 ms；初始化、窗口、填充和开屏逐步返回首个非`HAL_OK`结果，三个公开接口改为返回`HAL_StatusTypeDef`。
- 必查边界：复位低电平200 ms/10 ms路径、释放等待、初始化命令失败、窗口命令失败、填充中途失败、开屏失败和普通可见区清屏失败。
- 通过标准：任一步失败均原样返回且OLED SPI错误计数增加；显示层不继续本帧绘制，也不推进成功帧序号。

### 4.3 有界恢复与失败帧终止

- 源码位置：`display.c`的`Display_RequestRecovery`、`Display_PerformRecovery`、`Display_ClearBeforeDraw`、`Display_PrepareForForegroundDraw`、`Display_DrawStatusFull`和`RefreshScreen`。
- 改前问题：恢复调用结果不可见，状态页、菜单页或前景页可能在恢复失败后继续写屏；持续故障时每帧都可能重新硬复位，反复占用SPI和主循环。
- 具体改法：每轮恢复最多连续尝试3次；每次失败终止当前帧并更新时间和错误计数，达到上限后取消逐帧请求。恢复成功清零计数；60秒周期、SPI新错误或息屏唤醒显式请求可重置计数并开启新一轮。
- 必查边界：首试成功、前两次失败后成功、连续3次失败、第4帧不硬复位、60秒后再试、错误计数变化再试、息屏唤醒再试和节拍回绕。
- 通过标准：失败帧没有后续绘制或完成提交；单轮最多3次硬复位，达到上限后不逐帧重试，新触发条件到来后只开启一轮新的有界尝试。

### 4.4 命令确认页按键计数修正

- 源码位置：`display_tankopera.c`的`ifsendcmd`，调用链为参数/命令选择或输入完成 -> 首次确认进入页面 -> 页面内再次确认 -> `dtm_suretofunc`。
- 改前问题：首次按键进入确认页时`timesure`由0增到1；下一次确认旧条件`timesure > 1`仍不执行，只增到2，用户必须第三次确认才真正下发。
- 具体改法：执行条件改为`timesure != 0`。进入页面的首次按键仍只显示确认页；页面出现后的下一次确认立即清零计数并执行原目标函数。
- 必查边界：无参命令、带参命令、参数写入、维护模式、清继电器锁存、返回取消、确认与返回交替、密码页和需要额外保护确认的高风险操作。
- 通过标准：首次确认只进入页面且不下发，第二次确认下发一次；返回键仍需页面内确认且不误下发，既有额外保护确认链不被绕过。

## 5. 跨模块数据流和异常出口

正常恢复链为显示刷新请求 -> `Display_ShouldRecoverBeforeDraw` -> `Display_PerformRecovery` -> `OLED_RecoverAndClear` -> 完整GDDRAM清零 -> 当前页重绘 -> `Display_FinishFrame`。任一底层步骤失败时在`Display_PerformRecovery`返回`false`，当前帧直接退出，不调用页面绘制或完成提交。

命令确认链为菜单选择/参数输入 -> `ifsendcmd`显示确认页并把`timesure`置1 -> 下一次确认调用`dtm_suretofunc`一次。该变化只影响CPU3本地按键状态，不改变下发给CPU2的命令号、参数值或通信格式。

## 9. 风险与未验证项

- 未在真实SSD1325上确认完整80行GDDRAM清零和重新显示后的残影；逻辑分析仪和面板观察仍是发布前必要证据。
- 未注入SPI超时、DMA/HAL错误或连续失败，三次上限、错误计数确认和60秒新轮次只有代码与构建证据。
- 未测真实按键抖动、长按/短按交替、快速连按和CPU2下发日志；确认页修正需台架证明不会重复下发或绕过高风险保护。
- 未执行目标板烧写、RS485、FRAM、长期运行、现场或SIL验证。静态检查和构建不替代真实设备证据。
