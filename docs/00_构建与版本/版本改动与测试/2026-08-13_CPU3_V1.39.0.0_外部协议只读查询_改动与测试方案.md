# CPU3 V1.39.0.0 外部协议只读查询改动与测试方案

## 1. 文档目的和适用版本

本文记录CPU3外部COM当前协议只读查询、上位机兼容扫描及其提交范围。适用CPU2 `V1.39.2.0`、CPU3 `V1.39.0.0`；提交前基线为CPU3 `V1.38.2.0`。

## 2. 版本与兼容性

- CPU2：保持`V1.39.2.0`。
- CPU3：`V1.38.2.0 -> V1.39.0.0`，新增对外管理命令，按MINOR升级。
- `DEVICE_PROTOCOL_VERSION`：保持33；不改变CPU2/CPU3共享协议。
- CPU3 `CPU3_PARAM_VERSION`：保持`0x0007`；结构、CRC和FRAM布局不变，升级不清参数。
- 既有切换目标`0/1/2/3/5`及`0x00` ACK不变；新增`0xFF`查询和`0x01`查询响应。
- 旧固件可能返回`0xC6/0x03`或超时；新版上位机只对该站号候选回退原业务协议指纹。

## 4. 详细改动

### 4.1 CPU3只读查询响应

- 源码位置：`ProtocolSwitchFrame_Process`；调用链为外部COM收帧到`cpu3_port_process`再到管理帧解析。
- 改前问题：上位机确定串口参数和站号后无法直接读取当前协议，只能依次尝试各业务协议指纹，扫描时间长且旧、新设备混接难以区分。
- 具体改法：请求`[站号] 46 4C 54 44 FF CRC`返回`[站号] 46 01 [当前协议原始值] CRC`；CRC通过后在目标协议合法性判断前处理`0xFF`。
- 必查边界：地址、长度、Magic、CRC错误；协议值0至5、保留值4和未知值；请求本地回显及与切换ACK粘包。
- 通过标准：返回正确Golden Frame和`HANDLED`，目标协议输出不变，不产生切换pending。

### 4.2 查询与串口参数保持

- 源码位置：`cpu3_port_process`向管理帧传入`cfg->protocol`，仅当结果为`ACCEPTED`时调用`cpu3_stage_protocol_switch`。
- 改前问题：管理入口没有当前运行态协议输入，也没有明确的只读分支。
- 具体改法：查询只读取当前端口配置；不调用协议保存、FRAM写入、UART重初始化或默认串口参数应用。
- 必查边界：三路COM分别查询、发送忙/pending、查询后立即发送业务帧、连续重复查询。
- 通过标准：查询前后协议、站号、波特率、数据位、校验位和停止位一致；屏幕配置仍按目标协议应用默认串口参数。

### 4.3 上位机扫描和旧固件回退

- 源码位置：上位机`Cpu3ProtocolSwitchCodec`与`Cpu3ConnectionAssistantService.DiscoverDevicesAsync`。
- 改前问题：每个候选均需遍历业务协议指纹，上位机难以快速确认当前协议。
- 具体改法：先用现有只读业务帧确定物理串口参数和站号，再最多两次发送查询；合法已知协议形成强匹配，保留/未知值只记录地址；`0xC6/0x03`或两次超时才回退旧指纹。
- 必查边界：首次超时第二次成功、新旧固件混接、无候选站号、回显/噪声/粘包、未知协议原始值。
- 通过标准：新固件不执行业务指纹遍历；旧固件仅对自身候选回退；未知值不自动连接。

## 5. Golden Frame

站号1查询请求：`01 46 4C 54 44 FF AC 05`。

| 当前协议 | 响应 |
| --- | --- |
| DSM 0 | `01 46 01 00 E1 9D` |
| Wartsila 1 | `01 46 01 01 20 5D` |
| LTD 2 | `01 46 01 02 60 5C` |
| LH 3 | `01 46 01 03 A1 9C` |
| 保留 4 | `01 46 01 04 E0 5E` |
| SI 5 | `01 46 01 05 21 9E` |
| 未知 FE | `01 46 01 FE 60 1D` |
