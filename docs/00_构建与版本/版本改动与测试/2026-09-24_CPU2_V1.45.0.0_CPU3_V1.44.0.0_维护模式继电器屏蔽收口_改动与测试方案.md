# CPU2 V1.45.0.0 / CPU3 V1.44.0.0 维护模式继电器屏蔽收口改动与测试方案

## 1. 版本与兼容性

- CPU2：`V1.44.2.0 -> V1.45.0.0`（MINOR）。
- CPU3：`V1.43.1.0 -> V1.44.0.0`（MINOR）。
- `DEVICE_PROTOCOL_VERSION` 从 37 提升到 38。协议 38 将继电器最终动作屏蔽收口为只由维护模式控制；协议 37 中 `manual_alarm_inhibit` 的人工运动语义不再有效。
- CPU2 和 CPU3 继续按协议版本严格相等判断，协议 37/38 混用会被兼容门禁拦截，必须成套升级和回退。
- CPU2 `DEVICE_PARAM_VERSION` 保持 3，CPU3 `CPU3_PARAM_VERSION` 保持 `0x0007`。共享寄存器地址、字段宽度、`DeviceParameters` 结构大小、CRC 范围和 FRAM 布局不变，升级不恢复出厂、不清除或迁移现场参数。

## 3. 详细改动

### 3.1 人工运动不再改变报警屏蔽

- 源码位置：`LTD_MAIN_CPU2/Application/Src/measurement/measure_maintenance_commands.c`。
- 改前问题：普通上行、下行、强制上行和强制下行在所有入口及退出路径置位、清零 `manual_alarm_inhibit`，导致未进入维护模式时人工运动也关闭继电器最终动作。
- 具体改法：删除四类命令对 `manual_alarm_inhibit` 的全部写入；保留 `manual_level_update_inhibit` 的既有置位和对称清零，后者仅作兼容状态发布且当前无业务消费者。
- 通过标准：人工运动、命令切换、取消和错误退出都不改变继电器屏蔽；维护状态也不被人工运动命令隐式进入或退出。

### 3.2 继电器只认维护模式

- 源码位置：`LTD_MAIN_CPU2/Services/Relay/relay_output.c`。
- 改前问题：继电器快照同时读取 `maintenance_mode_active` 与 `manual_alarm_inhibit`，任一为 1 就关闭最终逻辑动作。
- 具体改法：从继电器测量快照删除 `manual_alarm_inhibit`，`alarm_inhibited` 只由 `maintenance_mode_active` 计算；屏蔽期间仍执行条件、滞回和锁存计算，只压制最终动作。
- 通过标准：命令 109 后 K1 至 K4 最终动作均为 0，命令 118 后下一刷新周期恢复按实时条件或锁存判定；未进入维护时人工/强制运动不再自动关闭动作。

### 3.3 协议 38 双端语义

- `manual_alarm_inhibit` 保留原共享字段和输入寄存器 `0x000E~0x000F`，CPU2 固定发布 0，CPU3 继续解析但不作业务门禁。
- `maintenance_mode_active` 继续由命令 109/118 控制；`relay_alarm_inhibit_effective` 和 K1 至 K4 最终逻辑动作只由该维护状态决定。
- `manual_level_update_inhibit` 继续在人工/强制运动期间发布，当前无业务消费者，不冻结液位且不参与继电器屏蔽。
- 双端 `DEVICE_PROTOCOL_VERSION=38`，字段注释、协议资料和界面说明同步更新；协议严格相等门禁保持不变。
