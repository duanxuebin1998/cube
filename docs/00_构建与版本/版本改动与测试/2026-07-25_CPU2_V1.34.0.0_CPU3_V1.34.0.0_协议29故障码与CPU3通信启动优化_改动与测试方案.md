# CPU2 V1.34.0.0 / CPU3 V1.34.0.0 协议29故障码与CPU3通信启动优化改动与测试方案

## 1. 文档目的和适用版本

本文记录协议29故障码治理、CPU3远程协议切换语义、启动非阻塞保护和OLED字库补充的最终实现、兼容边界、验证结果与台架缺口。适用固件组合：

- CPU2：`V1.34.0.0`
- CPU3：`V1.34.0.0`
- CPU2/CPU3共享协议：`DEVICE_PROTOCOL_VERSION = 29`
- CPU2参数存储：`DEVICE_PARAM_VERSION = 3`
- CPU3本机参数存储：V7 / `0x0007`

本次是二代计量仪配套升级。CPU2、CPU3必须使用相同共享协议，不考虑协议28旧故障码的运行期兼容、别名、翻译或规避。

## 2. 版本、协议和参数存储兼容性

| 项目 | 改前 | 改后 | 兼容结论 |
| --- | --- | --- | --- |
| CPU2固件 | `V1.33.0.0` | `V1.34.0.0` | 功能级变更，升MINOR |
| CPU3固件 | `V1.33.0.0` | `V1.34.0.0` | 功能级变更，升MINOR |
| 共享协议 | 28 | 29 | 故障编号语义不兼容，双端必须严格配套 |

协议29不新增共享寄存器，不移动参数字段，不改变CPU2 `DeviceParameters`结构、FRAM A/B槽、magic、元信息和CRC范围。升级本身不触发恢复出厂或清除现场通信参数。

## 3. 已确认需求和实现边界

### 3.1 故障码

- 取消实际不可达的12-11，不保留预留项、兼容别名或运行时翻译。
- 13-2名称统一为“震动管频率异常”，CPU2日志、CPU3显示和正式资料使用同一文字。
- 13-26密度有效上限从2000.0 kg/m³调整为3000.0 kg/m³；3000.0合法，大于3000.0故障。
- 18类改为扭力检测故障，21类改为模拟输出与自检故障；只交换类别分区数字，各具体故障语义不变。
- 12-6、15-16、21-5为已确认预留项，继续冻结保留，不因当前无调用点删除。
- 二代计量仪不考虑协议28旧故障码兼容或规避；协议28历史文档保持冻结，用于追溯而不是解释协议29设备。

### 3.2 CPU3远程协议切换

- 远程统一切换帧`0x46`只修改目标COM口的协议类型，保留该端口当前波特率、校验、数据位、停止位和地址等物理串口参数。
- 屏幕通信参数配置仍按目标协议默认模板更新物理串口参数；远程切换与屏幕配置语义明确分离。
- 切换ACK必须使用旧协议和旧串口参数完整发送；发送完成中断只登记待应用状态，FRAM保存和UART重初始化在主循环执行。
- 目标协议持久化读回失败时恢复旧端口配置；只影响目标端口，不回滚或重初始化其它端口。
- 切换成功或回滚后均按最终配置恢复RS485接收方向和RX DMA；目标口重初始化失败进入既有完整重初始化队列。

### 3.3 CPU3启动和显示

- 删除首屏前两个固定1000 ms延时。
- `App_Init()`末尾原固定`HAL_Delay(1000)`改为1000 ms非阻塞外部COM保护窗口。
- 保护期继续运行`Display_Task()`、CPU2轮询、调试和启动日志。
- 保护期暂停COM1/COM2/COM3外部UART恢复、远程协议切换应用、UART参数重配、SI周期任务以及外部协议帧处理；CPU2板间UART5恢复继续运行，窗口结束后恢复原有外部任务顺序。
- CPU2轮询和显示不因外部COM保护额外延迟；CPU2同步请求原有最长等待边界不在本次重构。
- OLED字库新增“震”字14×16点阵，用于13-2“震动管频率异常”；不复用“振”字。

## 4. 最小实现分析

本次没有增加新的故障码翻译层、旧协议兼容表、参数迁移器、后台任务框架或新的持久化字段。故障码修改直接落在现有共享枚举、错误文本、阈值判断和显示字库；远程协议切换复用现有端口配置结构和FRAM保存接口；启动保护只增加RAM截止时间和主循环门禁。

以下行为明确保持不变：

- 12-6、15-16、21-5预留语义与编号；
- CPU2/CPU3共享寄存器地址、字段缩放、字序和参数结构；
- CPU3屏幕配置按协议默认串口模板的行为；
- 普通UART重配仍等待三路端口收发空闲；
- 外部COM单帧pending缓存、CPU2同步轮询和SI业务算法；
- 一代设备及协议28历史资料。
