# CPU2 V1.42.7.0 V4密度无效值处理改动与测试方案

## 1. 版本与兼容性

- CPU2：`V1.42.6.0 -> V1.42.7.0`（PATCH）。
- CPU3：保持`V1.40.1.0`。
- `DEVICE_PROTOCOL_VERSION`保持35，`DEVICE_PARAM_VERSION`保持3；共享寄存器、帧格式、FRAM布局和现场参数不变，不恢复出厂参数。

## 2. 改动范围

源码位置：`LTD_MAIN_CPU2/Services/Sensor/Protocols/Dm4/V4/multiparam_v4_measurement.c`。

- R04通过统一解码判断无效频率；原始值0、`INT32_MIN`、解码失败或超出频率上限时输出频率0。
- R07通过原始寄存器读取；`NaN`、无穷、负值和超范围值输出密度0。R04无效时密度也输出0。
- R06通过原始寄存器读取；非有限或超范围值输出`NaN`。
- 底层UART、应答、地址、BCC/CRC、模式错误继续返回错误；主动帧过期或R02参数未更新继续返回`SENSOR_DATA_STALE`。
- 交互模式与主动上报模式使用同一套R04/R07/R06归一化语义。

## 3. 测试用例

### TC-V4-01 正常密度读取

- 前置条件：V4传感器处于密度模式，R04、R06、R07均为有效值。
- 操作：分别执行交互读取和主动帧读取。
- 预期：返回`NO_ERROR`，频率、温度、密度与原始值一致。

### TC-V4-02 R04无效

- 输入：R04分别设置为0、`INT32_MIN`和超出上限的值。
- 预期：通信帧校验通过，返回`NO_ERROR`，频率为0，密度为0，不返回格式错误。

### TC-V4-03 R07无效

- 输入：R07分别设置为`NaN`、`+Inf`、负值和超范围值。
- 预期：通信帧校验通过，返回`NO_ERROR`，密度为0；有效R04和R06保持原值。

### TC-V4-04 R06无效

- 输入：R06分别设置为`NaN`、无穷和超范围值。
- 预期：通信帧校验通过，返回`NO_ERROR`，温度为`NaN`；频率和密度不被连带清零。

### TC-V4-05 通信错误边界

- 输入：制造超时、短帧、错误功能码、错误地址和BCC/CRC错误。
- 预期：继续返回对应通信错误，不被无效值归一化逻辑吞掉。

### TC-V4-06 主动帧新鲜度

- 输入：主动帧超过1500 ms未更新，或R02温度/密度新数据位未置位。
- 预期：保持返回`SENSOR_DATA_STALE`；本版本不改变等待和统一恢复策略。

## 4. 回归范围与风险

- 回归V4交互读取、主动帧读取、DM4密度模式切换，以及SI/Wartsila既有密度0处理。
- V4液位、取水电容、磁零点和陀螺读取逻辑未在本版本改变。
- `SensorService_ReadDensity()`在成功返回后会把温度写入RAW；R06为`NaN`时需在目标板确认上层日志和调试数据不会产生异常整数。

- 未执行：目标板烧写、真实V4传感器异常值注入、无线主动帧超时、R06为`NaN`时的完整业务链路、RS485/台架/现场/SIL验证。
