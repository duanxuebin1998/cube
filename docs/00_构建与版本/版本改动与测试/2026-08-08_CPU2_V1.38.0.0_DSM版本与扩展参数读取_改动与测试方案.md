# CPU2 V1.38.0.0 DSM版本与扩展参数读取改动与测试方案

## 1. 文档目的和适用范围

本文记录CPU2 DSM传感器维护串口适配的最终提交范围、兼容边界和可执行验证方法。适用固件为CPU2 `V1.38.0.0`，CPU3保持`V1.37.0.0`。

本次只修改CUBE CPU2库，不修改DSM CPU1程序。用户已确认以下产品语义继续保持：测水电容小于30.0 pF映射为99999.9 pF是特殊处理，`zero_cap`继续保留；DSM一代采用磁零点，本次不在读取部件参数流程增加`Ch`倾角读取。

## 2. 版本、协议和参数存储兼容性

| 项目 | 修改前 | 提交版本 | 结论 |
| --- | --- | --- | --- |
| CPU2 | V1.37.0.0 | V1.38.0.0 | 新增版本识别、CK/CM参数和有效位，升MINOR |
| CPU3 | V1.37.0.0 | V1.37.0.0 | 无源码和行为修改 |
| `DEVICE_PROTOCOL_VERSION` | 32 | 32 | 不改变CPU2/CPU3共享字段、命令或寄存器 |
| `DEVICE_PARAM_VERSION` | 3 | 3 | 不改变`DeviceParameters`和FRAM布局 |
| CPU3本机参数版本 | `0x0007` | `0x0007` | 不涉及 |

兼容规则：

- `DsmSessionContext`、供电电压有效位和密度分析有效位仅位于CPU2 RAM，不写入FRAM，不触发参数迁移、恢复出厂或清除现场参数。
- V1/V2等不支持`Cv`的设备表现为无响应超时；只有同时读到`CV`前缀07时才归类为`CV07-ambiguous`并继续使用。
- V3同样可能使用07前缀，但支持`Cv`。因此BCC、帧格式或UART错误不得按旧设备兼容成功，必须保留原错误码。
- `Cv/CV/CK/CM`扩展不改变既有`CN/CL/CB/CD/Cb/Cd/Ch/Cl`线上格式和公开接口。

## 4. 详细改动点

### 4.1 DSM CPU1/CPU0版本上下文

- 源码位置：`dsm_sensor_communication.c`的`UART6_SendWithPolicy()`、`DSM_ReadVersionContext()`和`DSM_GetSessionContext()`；调用链为`Sensor_ProbeDsmSensor() -> DSM_ReadVersionContext() -> Cv/CV`。
- 改前问题：CPU2没有CPU1维护线信息，无法区分V3、V4、V5、V6，也无法明确处理V1/V2不支持`Cv`的历史兼容情况。
- 具体改法：`Cv`先静默探测一次，成功后解析五字节CPU1版本；随后使用正常重试策略读取`CV`组合版本。结果写入RAM会话上下文及独立valid标志，探测阶段输出版本分类。版本读取失败仍继续既有`CN`探测。
- 必查边界：V1/V2无`Cv`、V3及以上合法版本、V5.00歧义版本、非法数字、坏BCC、短帧、UART错误、命令切换及`CV`失败。
- 通过标准：合法版本得到对应profile；`Cv`超时且`CV=07xxx`得到`CV07-ambiguous`；其它`Cv`错误原样返回且不阻断后续`CN`兼容探测；`STATE_SWITCH`立即向上传递。

### 4.2 收紧07前缀兼容回退

- 源码位置：`DSM_ReadVersionContext()`的`cpu1_ret`处理。
- 改前问题：仅凭`CV`前缀07会把V3的BCC、格式或UART错误也转换成成功，降低诊断可信度。
- 具体改法：兼容条件收紧为`cpu1_ret == SENSOR_DEVICE_COMM_TIMEOUT`且组合前缀严格等于`07`；其它错误将profile置为unknown并返回原错误码。
- 必查边界：超时、BCC错误、格式错误、UART FE/NE/ORE、前缀07和非07的组合。
- 通过标准：只有“超时+07”返回兼容成功；任何非超时错误都不得被前缀07吞掉。

### 4.3 CK供电电压和CM密度分析参数

- 源码位置：`DSM_FRAME_SUPPLY_VOLTAGE`、`DSM_FRAME_DENSITY_ANALYSIS`、`Read_Sensor_Voltage()`和`DSM_ReadDensityAnalysis()`。
- 改前问题：现有部件参数流程没有读取DSM供电电压、22.5度周期平方、45度周期平方和动态黏度；CM正常帧和统一错误帧都可能以A开头，不能仅凭首字节决定长度。
- 具体改法：CK按11字节读取；CM在第18、19字节已经是CRLF时按19字节错误帧结束，否则继续接收27字节正常帧。三个CM字段全部校验并解析成功后一次性发布，CK和CM分别维护有效位。
- 必查边界：CM正常A前缀、E前缀、19字节错误帧、坏分隔符、正负整数周期平方、动态黏度小数、坏BCC、短帧和输出空指针。
- 通过标准：只有完整合法帧设置有效位；失败时对应有效位为0，不发布混合新旧字段；其它DSM数据保持原值和原接口。

### 4.4 读取部件参数的降级和部分成功输出

- 源码位置：`sensor.c`的`Sensor_ReadPartParamsInternal()`。
- 改前问题：扩展诊断读取如果直接复用主错误出口会阻断核心参数和故障恢复；CK、CM只有同时成功时才输出，部分成功数据不可见。
- 具体改法：仅DSM类型执行CK/CM；通信超时继续走蓝牙链路诊断，`STATE_SWITCH`立即返回，其它失败记录错误码但继续水位电容和RSSI等既有流程。CK和CM成功结果分别输出。
- 必查边界：CK成功/CM失败、CK失败/CM成功、两者失败、两者成功、命令切换、蓝牙链路异常以及非DSM传感器。
- 通过标准：任一扩展项失败不阻断核心参数和故障恢复；另一项成功数据仍可见；非DSM类型不发送CK/CM。

### 4.5 低电压诊断口径

- 源码位置：`DSM_LogLowVoltageFrame()`及版本/编号响应处理。
- 改前问题：大小写响应混用可能产生假低压日志，影响现场判断。
- 具体改法：统一错误日志入口只对协议规定的 uppercase `E`低压响应打印低压提示；编号解析仍接受协议允许的`N/E/e`前缀并提取数字。
- 必查边界：`N`、`E`、`e`编号帧及不含数字的错误文字。
- 通过标准：合法编号不因前缀丢失；非低压响应不打印低压提示；无数字和溢出编号仍返回格式错误。

## 5. 数据流和异常闭环

版本链路：`DSM传感器探测 -> Cv单次静默探测 -> CV三次正常读取 -> RAM版本上下文/profile -> 版本诊断日志 -> CN既有身份探测`。

扩展参数链路：`读取部件参数 -> CK/CM定长事务 -> 长度/BCC/CRLF/字段校验 -> 局部变量 -> 全部字段成功后设置有效位 -> 分项日志 -> 继续水位电容/RSSI和故障恢复`。

异常出口：命令切换立即返回；超时可进入蓝牙透明链路诊断；BCC、格式、UART和远端错误保留具体错误码；扩展诊断失败不覆盖核心参数结果。

## 8. 复杂场景验证

### 8.1 旧版兼容

1. 冷启动V1/V2设备并记录`Cv`实际无响应时长。
2. 确认随后`CV`和`CN`完成，profile为`CV07-ambiguous`。
3. 连续重复十轮，确认没有把版本探测超时升级为整机故障，也没有三轮无意义`Cv`错误日志。

### 8.2 V3错误不被兼容掩盖

1. 连接可正常返回`Cv/CV`的V3设备。
2. 分别注入坏BCC、短帧和UART错误，同时保留`CV`前缀07。
3. 确认返回码分别对应BCC、格式和UART错误，profile为unknown；随后CN仍可用于身份探测。

### 8.3 CK/CM部分成功

1. 依次执行“CK成功/CM失败”和“CK失败/CM成功”。
2. 检查成功项的valid、数值和日志，失败项valid必须为0。
3. 确认水位电容、RSSI和故障恢复仍继续执行，命令切换能中断当前流程。
