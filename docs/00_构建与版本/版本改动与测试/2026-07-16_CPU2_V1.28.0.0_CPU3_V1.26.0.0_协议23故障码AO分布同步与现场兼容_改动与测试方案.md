## 1. 文档目的和提交状态

本文记录CPU2 V1.28.0.0、CPU3 V1.26.0.0与共享协议23的发布范围、兼容性、代码改动、可执行测试、已执行验证和残余风险。协议22未形成独立发布组合，其故障码重排与协议23的AO语义、通信快照、分布同步和外部协议修复统一随本版本发布。

本文件随本次提交纳入，提交哈希以Git记录为准。本次只创建本地提交，不自动推送。PDF、本机`tools/`、`docs/00_程序流程导航/`、`docs-site/`和`outputs/`不进入Git提交。

### 2.1 CPU2 AO旧值迁移

- 原13个AO持久化槽和寄存器地址不移动，`fault_mode`、`error_level`、`power_on_current_mA_x100`只改变协议23解释。
- 旧最小/最大故障模式迁移为“输出故障电流”，并把对应最小/最大电流固化到故障电流；旧最近有效模式迁移为“保持上次有效过程电流”；无法可靠继承的旧实际值/设定值模式回退到输出故障电流。
- 原错误等级槽固定归一化为0；原上电电流作为非跟随电流保留，超出3.40～22.60mA时补默认4.00mA。
- 升级前建议记录AO配置；升级后核对工作模式、电流模式、输出源、0%/100%量程、阻尼、故障动作、故障电流、非跟随电流和仿真电流。其它现场参数不清除。

## 4. 详细改动点

### 4.1 协议22故障码重排随协议23发布

- 源码位置：双端`Services/ParamStorage/system_parameter.h`和`Application/system_param/system_parameter.h`故障枚举；正式与内部故障码工作簿。
- 改前问题：二代旧版本历史编号永久占位，导致现行电机、位置、测量、AD5421和系统类编号存在不必要空洞，且按CPU2版本查询历史表的规则未完整落地。
- 具体改法：一代同义故障优先沿用子码，一代无同义项时使用最低可用子码，重排32项共享故障；CPU2 V1.27.0.0 / CPU3 V1.25.0.0 / 协议21完整归档，不反向改写。
- 必查边界：双端129项共享码一致且无重复；2项CPU3本机码不并入共享数量；历史页数量、名称和编号保持不变。
- 通过标准：源码、当前清单和工作簿现行页一致；协议21日志按历史页解释；协议23设备显示现行编号。

### 4.2 AO故障动作与非跟随状态

- 源码位置：CPU2 `AoOutput_SelectTarget()`、`AoOutput_SelectFaultCurrent()`、运行缓存和参数迁移；CPU3 `param_meta[]`、`menu_ao_fault()`、`menu_ao_runtime()`。
- 改前问题：搜索、待机、其它测量或过程数据无效可能被当成设备故障；五种故障模式和错误等级难以对应真实产品动作；上电电流只在启动期使用。
- 具体改法：故障动作收敛为输出故障电流或保持上次有效过程电流；仅明确`STATE_ERROR`且错误码有效时进入故障动作。液位/空高/水位只在匹配命令和跟随状态下换算过程电流，其余非故障状态输出非跟随电流。
- 必查边界：禁用、固定、仿真、待机、搜索、三种跟随、命令切换、过程无效、故障缓存为空、输出源/量程/模式切换和驱动错误。
- 通过标准：非故障状态不输出故障电流；保持无历史时回退非跟随电流；缓存只由成功下发的正常过程目标更新。

### 4.3 CPU3 AO菜单和运行页

- 源码位置：`display_tankopera.c/.h`的AO五组菜单、名称、编辑门禁和运行页；`display.c`字库。
- 改前问题：菜单仍暴露旧五种故障模式和错误等级，运行页缺少当前输出状态及输出电流说明，新增文字存在缺字风险。
- 具体改法：故障组只显示故障动作、故障电流、非跟随电流；运行页显示输出状态、输入值、比例和最近成功下发电流。新增“站、普”，并按参考点阵修正“尼、组、跑、锁、隔、策、亮”。
- 必查边界：中英文短名、4行页面、禁用状态参数预配置、通信不可用时N/A、物理返回键、字库索引和28字节点阵。
- 通过标准：菜单宽度和字库检查通过；运行页不把最近下发值描述成DAC回读或物理环路实测值。

### 4.4 协议优先探测与快照门禁

- 源码位置：CPU3 `CPU2_CommIsProtocolCompatible()`、`CPU2_CommIsProtocolMismatch()`、`PollingInputData()`和状态页显示。
- 改前问题：旧CPU2可能在当前扩展地址返回非法地址，公共组成功又清除失败计数，设备永久停在通讯尝试中；显示直接比较缓存值会把未知状态误报为版本不匹配。
- 具体改法：上电和恢复先独立读取稳定的协议版本地址；未知时只探测，确认不匹配后只保留版本心跳并关闭业务快照；真实连续失败仍在第10次置`20-7`。
- 必查边界：完全断线、CRC错误、合法Modbus异常、协议21/22/23、协议0、探测后再断线和协议23恢复上线。
- 通过标准：未知、不匹配和通信超时三种状态可区分；旧协议不访问协议23扩展区；协议23完整重同步后才开放命令和外部读取。

### 4.5 分布结果非阻塞同代同步

- 源码位置：CPU3 `CPU2_PollFixedPointSnapshotHandshake()`及分布候选、分块、重试和发布状态机；本机故障`CPU2_PROFILE_SYNC_FAILED`。
- 改前问题：同步固定读取200点且可长时间阻塞；失败可能一直保持测量中；完成头、点阵和来源跨帧读取时可能混代。
- 具体改法：先读头部实际点数`N`，只拉`N×12`个寄存器；每帧最多8点、间隔至少50ms；单块100/300/1000ms重试，整轮最多3轮且总上限15秒；前后头一致后一次发布。
- 必查边界：1/5/8/9/100/200点、块失败恢复、三轮失败、头部变化、通信断线、完成锁存清零、立即开始下一次测量和CPU2重启计数复用。
- 通过标准：只发布完整同代点阵；正常作废直接取消旧同步；最终失败退出测量中并显示`20-13`。

### 4.6 会话代际与SI投影作废

- 源码位置：CPU3通信会话代际和`si_update_profile_projection()`。
- 改前问题：CPU2重启后完成计数可能与旧计数相同，CPU3或SI投影可能把旧点阵当成新结果；短暂断线未被SI轮询观察时旧投影仍可能保留。
- 具体改法：快照失效时清除中央分布发布缓存并递增本机会话代际；SI比较代际并清除旧点阵、Complete和时间；同步中的候选遇会话变化从头读取。
- 必查边界：CPU2重启、计数回退、断线后快速恢复、SI轮询未命中短断线和新测量清锁存。
- 通过标准：新会话不会复用旧发布键；SI首次观察新代际时立即重建，不暴露旧点阵。

### 4.7 Wärtsilä FC10现场特例

- 源码位置：`CPU3_ExternalWartsilaWriteShapeIsValid()`及Wärtsilä协议资料。
- 改前问题：标准Modbus严检要求`byteCount=2×quantity`，会拒绝现场主机使用的`byteCount=quantity`帧并返回异常03。
- 具体改法：同时接受现场和标准byteCount，但PDU长度始终严格等于`6+2×quantity`，数据偏移和16位寄存器解析不变。
- 必查边界：现场/标准单寄存器、最大数量、短帧、超长帧、非法byteCount、地址`0x81/0x01`和CRC。
- 通过标准：两种合法格式成功；截短、超长和非法格式仍被拒绝；DSM、LTD和内部Modbus不跟随放宽。

### 4.8 CH9141K上电残包有界重试

- 源码位置：CPU2 `CH9141_AT_EnterSoftwareMode()`。
- 改前问题：上电偶发收到非空但非`OK/ERR`的残包时，原逻辑等待超时并直接报蓝牙主机无响应；仅单独`%`有特殊重试。
- 具体改法：仅上电首次窗口、响应非空且没有`OK/ERR`时，记录错误重试，恢复透明模式和UART6、重新等待空闲并完整重试一次；成功记录恢复，失败沿用原出口。
- 必查边界：空响应、明确ERR、STATE_SWITCH、单独`%`、其它残包、重试成功/失败和运行期普通AT。
- 通过标准：只有目标上电残包路径新增一次重试；不无限延长启动，不掩盖持续硬件故障。

### 4.9 正式资料和工作簿

- 源码位置：`docs/00_构建与版本/故障码/`两份工作簿、当前清单、协议记录、AO/外部协议/菜单资料。
- 改前问题：现行表原因描述过于按类别套话，协议23首版和历史查询口径尚未形成发布闭环。
- 具体改法：逐项重写131项面向普通人员的原因，保留内部技术证据；同步协议23正式版本、历史页、菜单树、现场特例和测试边界。
- 必查边界：公式错误、重复/空原因、合并单元格、换行、行高、历史页不改、内部与外发资料边界。
- 通过标准：两份工作簿内容和视觉检查通过；正式表无空项、无重复原因和公式错误；历史页保持冻结。
