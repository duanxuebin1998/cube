# CPU3 V1.41.0.0 LED 面板指示灯初始化改动与测试方案

## 1. 版本与目的

- CPU2：保持 `V1.42.10.0`。
- CPU3：`V1.40.1.0 -> V1.41.0.0`（MINOR）。
- 目的：初始化 LED 面板的两个指示灯并暂时保持常亮，为后续状态指示逻辑建立稳定的 GPIO 基线。

## 2. 协议版本与兼容性

- `DEVICE_PROTOCOL_VERSION` 保持 35；CPU2/CPU3 共享寄存器、命令、状态和字段不变。
- CPU3 `CPU3_PARAM_VERSION` 保持 `0x0007`；参数布局、FRAM 数据和启动加载逻辑不变，升级不清除现场参数。
- 本次只新增 PF0/PF10 GPIO 输出初始化，不改变串口、SPI、OLED 刷新、菜单和对外协议行为。

## 3. 本次修改

### 3.1 LED 引脚定义与低电平常亮

- 源码位置：`LTD_DISPLAY_CPU3/Core/Inc/main.h` 的 GPIO 宏，以及 `LTD_DISPLAY_CPU3/Core/Src/gpio.c` 的 `MX_GPIO_Init()`。
- 改前问题：CPU3 未定义或初始化 LED 面板的两个控制引脚，固件无法保证上电后的指示灯状态。
- 具体改法：定义 `WLED1=PF10`、`WLED2=PF0`；GPIOF 时钟启用后先把两引脚写为 `GPIO_PIN_RESET`，再配置为低速推挽输出、无上下拉，使其按当前低有效假设保持常亮。
- 必查边界：冷上电、软件复位、看门狗复位、两灯同时驱动、OLED 刷新和 SPI 通信期间的电平保持；还需核对面板实物是否存在引脚互换或硬件改线。
- 通过标准：PF10 和 PF0 初始化后均持续为低电平，两只指示灯从 CPU3 初始化完成后持续点亮，且 OLED、按键和通信功能无新增异常。

### 3.2 CubeMX 配置同步

- 源码位置：`LTD_DISPLAY_CPU3/LTD_DISPLAY_CPU3.ioc` 的 `PF0`、`PF10` 和 `Mcu.Pin*` 配置。
- 改前问题：只修改生成源码会在后续 CubeMX 重新生成时丢失 LED 初始化。
- 具体改法：把 PF0 标记为 `WLED2`、PF10 标记为 `WLED1`，均设置为 `GPIO_Output`，初始状态为 `GPIO_PIN_RESET`，并把引脚总数由 54 更新为 56。
- 必查边界：重新打开 `.ioc` 时无引脚冲突；重新生成后宏、输出电平和 GPIO 模式与当前源码一致；PF0 不再作为 I2C2，PF10 不再作为 ADC3 使用。
- 通过标准：CubeMX 能正常载入工程且不报告 PF0/PF10 冲突，重新生成的 `main.h` 与 `gpio.c` 保留相同配置。
