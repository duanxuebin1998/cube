# CPU3 V1.38.1.1 显示字库索引与只读存储优化改动与测试方案

## 1. 文档目的和适用版本

本文用于复核和验证CPU3显示字库索引整理、只读存储迁移、接口只读约束及自动检查增强。适用CPU3版本为`V1.38.1.1`，基线为`V1.38.1.0`；CPU2保持`V1.39.1.0`。

## 2. 版本与兼容性

- CPU3：`V1.38.1.0 -> V1.38.1.1`（BUILD）。
- CPU2：保持`V1.39.1.0`。
- 共享协议：`DEVICE_PROTOCOL_VERSION=33`，不变。
- 参数存储：CPU2 `DEVICE_PARAM_VERSION=3`、CPU3 `CPU3_PARAM_VERSION=0x0007`，均不变；参数结构、字段偏移、CRC和FRAM布局不变，升级不会恢复出厂或清除现场参数。
- 显示兼容性：页面文案和493个保留字形不变；删除的是7个重复索引及其重复点阵，运行时继续命中原先首次出现的同字符字形。

本次不更新程序流程图：改动不改变页面入口、菜单结构、显示文案、状态机、刷新时序、通信链路或异常出口，只整理字库数据组织、存储属性和防错接口。

## 4. 详细改动

### 4.1 删除重复字库索引和点阵

- 源码位置：`display.c`的`StockMap`、`WordStock`和`WordStock2`。
- 改前问题：500项索引中有7项字符重复，人工维护时难以确认索引与点阵是否严格对应，重复数据也占用固件空间。
- 具体改法：保留每个重复字符第一次出现的位置和点阵，删除后续重复项；剩余493项按全局0～492连续编号，分段为252项和241项。
- 必查边界：中文UTF-8键必须完整；索引与点阵数量相等；每项必须恰有28字节；两张表均不得超过255项；保留字形必须与修改前首次命中点阵一致。
- 通过标准：检查器报告493/493一致、无重复、分段252/241；修改前后逐字节比较493/493一致。

### 4.2 字库迁移到只读存储

- 源码位置：`display.c`的字库数组及`display.h`、`hgs.c`、`hgs.h`的绘制接口。
- 改前问题：固定字库数组未声明为`const`，链接器将其计入可写数据段，占用启动复制空间和SRAM，并允许误写。
- 具体改法：字库数组和下层字模缓冲入参增加`const`；`OledDisplayLineWords`改为`const void *`并在实现内按只读字节访问，调用点不再移除字符串常量的只读属性。最终链接结果的`data`由基线37972字节降至20996字节，减少16976字节。
- 必查边界：字符串常量、栈上格式化缓冲、参数表名称和字库数组均可正常传入；函数不得写入输入缓冲；ASCII与中文分支的坐标推进不变。
- 通过标准：编译无类型错误；42处目标强转清零；链接后字库进入只读段，SRAM占用相对旧布局明显下降。

### 4.3 增加编译期与脚本防错门禁

- 源码位置：`display.c`的6条`_Static_assert`及`font_check.py`。
- 改前问题：字符、点阵、注释索引和分表容量依赖人工同步，缺项、重复、错位或越过8位索引容量可能直到运行时才暴露。
- 具体改法：编译期校验UTF-8索引长度、两张表的28字节对齐、总数量一致和单表255上限；脚本解析实际字节和注释，检查连续全局索引、重复、缺字并输出候选未用字。
- 必查边界：空表、少/多一个字节、跳号、重复字符、分表256项和显示字符串缺字均应失败；候选未用字只报告，不自动删除。
- 通过标准：当前源码全部检查通过；人为破坏任一强约束时编译或脚本以非零退出码失败。

### 4.4 保留候选未用字

- 源码位置：`font_check.py`的使用统计输出。
- 改前问题：静态字面量扫描无法覆盖运行时拼接、间接引用、历史兼容页面和现场配置，直接删除“未扫描到”的字可能造成真机缺字。
- 具体改法：117个候选未用字保留在字库中，检查器仅输出字符及索引，后续有完整运行覆盖证据后再单独评估。
- 必查边界：不得把“当前源码字面量未命中”等同于“产品不会显示”。
- 通过标准：候选列表可复核且不会导致检查失败，缺字列表必须为0。
