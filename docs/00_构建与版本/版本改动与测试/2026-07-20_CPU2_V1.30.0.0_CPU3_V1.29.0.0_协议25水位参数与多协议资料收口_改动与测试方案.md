# CPU2 V1.30.0.0 / CPU3 V1.29.0.0 协议25水位参数与多协议资料收口改动与测试方案

日期：2026-07-20

本文记录CPU2 V1.30.0.0、CPU3 V1.29.0.0与共享协议25的提交范围、兼容性、参数迁移、代码和资料改动、已执行验证及未验证风险。本文件随本次提交纳入，提交哈希以Git记录为准；本任务只创建本地提交，不自动推送。

## 1. 版本、协议和参数存储

| 项目 | 旧值 | 新值 | 影响 |
| --- | --- | --- | --- |
| CPU2固件 | V1.29.1.0 | V1.30.0.0 | MINOR；新增共享水位参数语义并调整出厂默认值 |
| CPU3固件 | V1.28.0.0 | V1.29.0.0 | MINOR；新增菜单项/快捷入口并收紧Wärtsilä FC10外部行为 |
| 共享协议 | 24 | 25 | 原`reserved3`槽位定义为水位滞后时间预留参数，双端严格相等 |
| CPU2参数存储 | 3 | 3 | 结构大小、元信息和CRC范围不变，不清参数 |
| CPU3本机参数 | 0x0007 | 0x0007 | 本机FRAM布局不变 |

### 参数存储兼容性

- `DeviceParameters`没有新增字节、移动字段或改变CRC范围，只把原`reserved3`槽位改名为`water_level_hysteresis_time_s`。
- 协议24及更早版本升级到协议25时，CPU2在运行期迁移入口把该槽强制归零，避免历史保留值被解释为有效秒数。
- 新参数范围为0～3600s、默认0s；当前不进入水位控制算法，因此升级后不会改变现有水位状态机时序。
- `DEVICE_PARAM_VERSION=3`不变，升级不会因本次改动恢复出厂或清除其它现场参数。
- 降级到协议24及更早程序时，该槽重新成为保留值；降级前仍建议导出并记录整机参数。

## 3. 详细改动

### 3.1 协议25水位滞后时间预留参数

- 源码位置：双端`system_parameter.h`、`stateformodbus.h`、`dataanalysis_modbus.c`和CPU3`device_param_sync.c`。
- 改前问题：共享结构中存在无业务含义的`reserved3`，Word需求需要一个可配置但暂不启用算法的水位滞后时间字段。
- 具体改法：保持32位槽位和寄存器地址不变，双端统一重命名；范围0～3600s，默认0s，保留旧宏别名；共享协议升至25。
- 必查边界：0、1、3600、3601，协议24旧存储升级，协议24/25交叉固件，参数写失败和补读。
- 通过标准：双端协议均为25；0～3600可读写并持久化；越界值归零/拒绝符合入口约定；旧保留值不会直接生效。

### 3.2 CPU2默认值与运行期归一化对齐

- 源码位置：`LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.c`的协议迁移、归一化和`RestoreFactoryParamsConfig()`。
- 改前问题：液位固定频率、水位滞后电容阈值和SI首点与已确认Word口径不一致，恢复默认和旧值补默认路径也不一致。
- 具体改法：固定频率5500改为5200；水位滞后电容30.000pF改为15.000pF；SI首点1000改为5000；运行期0值补默认与恢复出厂使用同一数值。
- 必查边界：已有非零现场值保留、0值补默认、恢复出厂、协议升级、参数打印倍率。
- 通过标准：已有合法非零值不被覆盖；对应0值按新默认补齐；恢复默认、打印和正式文档一致。

### 3.3 CPU3菜单、长按和共享快捷入口

- 源码位置：`display_tankopera.c/.h`、`exit.h`和CPU3参数元数据。
- 改前问题：菜单排序与Word不一致，罐底编码器修正参数只能从单一路径进入，长按约1.5s短于文档口径，水位菜单缺少协议25预留项。
- 具体改法：长按计数15改为30；新增按显式操作号数组构建菜单的入口；罐底、Wärtsilä和SI Profile复用编码器修正项；水位菜单使用11项显式数组，顺序固定为水位方式、罐高、盲区、跳变/跟随/寻找/滞后电容阈值、稳定距离、修正值、最大下行距离、零点电容、滞后时间，协议25新增项保持在末尾。
- 必查边界：4行分页、返回父级、多入口写同一寄存器、长按释放保护、中文短名和英文短名宽度。
- 通过标准：三处入口显示顺序与正式菜单树一致；多入口读写同一参数；长按约3s；无缺字、越界或错误返回路径。

### 3.4 Wärtsilä FC10现场格式唯一口径

- 源码位置：`external_read_freshness.h`的`CPU3_ExternalWartsilaWriteShapeIsValid()`及Wärtsilä协议资料/工具catalog。
- 改前问题：旧实现同时接受现场`byteCount=quantity`和标准`byteCount=2*quantity`，与本轮确认的莆田主机唯一口径不一致。
- 具体改法：FC10仅接受`byteCount=quantity`，数据区仍严格为`2*quantity`，PDU长度为`6+2*quantity`；标准格式和异常长度返回`0x03`且不下发CPU2。FC03响应保持标准字节数。
- 必查边界：现场格式、标准格式、0数量、超上限、截短、超长、命令区和参数区、CPU2 ACK失败。
- 通过标准：现场格式进入原业务链；标准/畸形格式无副作用并返回`0x03`；FC03读响应不受影响。

### 3.5 Word、Markdown和OPML菜单资料对齐

- 改前问题：Word和程序在默认值、AO项目、参数位置、长按时间、罐底/Wärtsilä/SI菜单入口上存在偏差。
