# CPU3 V1.15.1.0 串口协议默认值与手动参数覆盖改动与测试方案

## 版本变化

- CPU2：保持 `V1.16.0.1`。
- CPU3：`V1.15.0.2 -> V1.15.1.0`。
- 升级级别：CPU3 `patch`。
- 升级原因：修复 CPU3 串口参数会被协议持续覆盖的问题，同时调整 COM 配置菜单顺序。

## 协议版本与兼容性

- `DEVICE_PROTOCOL_VERSION` 保持 `10`。
- 不新增 CPU2/CPU3 共享寄存器、命令码、输入寄存器尾段或共享结构字段。
- CPU2 `DEVICE_PARAM_VERSION` 保持 `3`，`DeviceParameters` 结构大小不变，不会因本次升级触发 CPU2 参数恢复出厂。
- CPU3 本机参数存储版本保持 `0x0004`，`Cpu3CommAndDisplayParams` 布局不变，旧 FRAM 中合法串口配置继续加载。
- 旧版本行为为“写任意串口字段或加载 FRAM 后按协议持续归一化”；新版本行为为“只有修改协议字段时带出默认串口参数，后续物理参数允许单独覆盖”。

## 本次修改

- 将 CPU3 COM1/COM2/COM3 串口配置处理拆分为协议默认模板和合法值兜底两类逻辑。
- 修改协议字段时自动带出默认串口参数：
  - DSM / Wartsila：`4800 8N1`。
  - LTD：`115200 8N1`。
  - SI：`9600 8O1`。
- 修改波特率、数据位、校验、停止位时，只检查并修正非法值，不再因为当前协议覆盖用户设置。
- 上电从 FRAM 加载 CPU3 本机参数时，只修正非法串口字段，保留合法的人工串口配置。
- COM1/COM2/COM3 配置菜单顺序改为“协议、波特率、数据位、校验、停止位”。
- 更新 SI协议枚举注释，明确是“切换协议时带出默认值”，不是持续强制收敛。

## 影响范围

- 影响 CPU3 本机 FRAM 通信参数加载、保存和运行期 UART 重配置。
- 影响 CPU3 屏幕菜单中 COM1/COM2/COM3 配置项显示顺序。
- 影响现场通过屏幕菜单修改外部 COM 口协议和物理串口参数的行为。
- 不影响 CPU2 测量流程、CPU2 参数存储、内部 CPU2/CPU3 Modbus 地址和外部协议寄存器映射。

## 测试点

### 1. 协议切换带出默认值

准备条件：
- CPU3 能进入参数配置菜单。
- COM1/COM2/COM3 至少任选一路验证，建议三路都覆盖。

步骤：
1. 进入 `通信设置 -> COMx配置`。
2. 修改协议为 DSM 或 Wartsila。
3. 返回 COMx 配置页查看波特率、数据位、校验和停止位。
4. 依次修改协议为 LTD、SI，重复查看。

预期结果：
- DSM / Wartsila 自动带出 `4800 8N1`。
- LTD 自动带出 `115200 8N1`。
- SI 自动带出 `9600 8O1`。

通过标准：
- 协议字段保存后，当前端口物理串口参数与默认模板一致。
- 串口重初始化不会导致主循环卡死或外部 COM DMA 接收异常。

### 2. 物理串口参数可单独覆盖

准备条件：
- 已将某一路 COM 协议设置为 SI 或 Wartsila。

步骤：
1. 单独修改该端口波特率，例如从 `9600` 改为 `19200`。
2. 单独修改校验或停止位。
3. 返回菜单重新进入该 COM 配置页查看当前值。
4. 重启 CPU3 后再次进入该 COM 配置页查看当前值。

预期结果：
- 单独修改的波特率、校验和停止位不会被协议自动改回默认值。
- 重启后 FRAM 中合法配置继续保留。

通过标准：
- “协议 + 非默认物理参数”的组合能够保存、显示和重启保持。

### 3. 非法值兜底

准备条件：
- 可通过调试方式构造非法 FRAM 值，或后续上位机写入测试支持 CPU3 本机保持寄存器。

步骤：
1. 构造非法波特率、数据位、校验或停止位。
2. 重启 CPU3 或触发本机参数写入。
3. 查看 COM 配置页和 UART 初始化状态。

预期结果：
- 非法字段按当前协议默认模板修正。
- 合法字段不被额外覆盖。

通过标准：
- 无非法配置导致 UART 初始化异常。
- 修正范围只限非法字段。

## 回归范围

- COM1/COM2/COM3 外部协议收发：DSM、Wartsila、LTD、SI 至少覆盖当前现场常用端口。
- CPU3 菜单返回路径：进入 COM 配置、修改协议、修改物理参数、返回上级菜单。
- CPU3 上电加载 FRAM：确认本机参数 CRC 有效时不恢复默认值，不重复覆盖合法串口参数。
- CPU3 主循环安全点重配：确认外部 COM 正在收发时仍按原逻辑延后重配。

## 未验证风险

- 未做实物联调；需要在 OLED 实机菜单上确认三路 COM 的菜单顺序、协议切换默认值、手动覆盖和重启保持。
- 需要现场确认上位机或 PLC 是否依赖旧版“SI 始终强制 9600 8O1”的行为；新版本允许人工覆盖，应在升级说明中提示。
- 如果外部 COM 持续有报文流量，串口重配置仍会等待安全点执行，现场可能需要停止主站轮询后再确认新参数立即生效。

- 本次只改变 CPU3 本机参数写入后的串口配置策略和菜单排序，现有流程图中的“菜单写入 CPU3 本机参数、主循环安全点重配 UART”流程仍成立。
- 因此程序流程图无需更新。
