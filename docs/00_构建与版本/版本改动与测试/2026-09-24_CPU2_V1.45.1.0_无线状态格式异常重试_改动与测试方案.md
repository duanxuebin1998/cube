## 3. 详细改动

### 3.1 格式异常按完整只读事务重试

- 源码位置：`wireless_pairing.c` 的 `WirelessPairing_UpdateConnectionStatusSnapshot()`；调用链为 `PartDiagnostics_ReadAllInternal -> PartDiagnostics_UpdateWirelessRssi -> WirelessPairing_UpdateConnectionStatusSnapshot -> WirelessPairing_ReadConnectionStatus`。
- 改前问题：`BLEMODE`、`BLESTA`、`CCADD` 或异步 RSSI 任一格式异常都会在第一次查询后返回 `WIRELESS_RESP_FORMAT_ERROR`，周期刷新随后进入最终故障并停止测量。
- 具体改法：增加 `WIRELESS_STATUS_QUERY_MAX_ATTEMPTS=3` 和 `WIRELESS_STATUS_QUERY_RETRY_DELAY_MS=300`；仅当执行返回值为格式错误，或执行安全完成但快照错误码为格式错误时，记录重试并在可被命令切换取消的 300 ms 等待后重做整个读取函数。
- 必查边界：首次成功、第二/三次恢复、明确未连接、非格式执行错误、重试等待期间命令切换、计数上限；不在同一 AT 会话中重发当前命令。
- 通过标准：格式异常最多调用 3 次完整事务；每次尝试均经既有路径关闭 RSSI、退出 AT 并完成透明交接；非格式结果和不安全执行错误不进入下一次查询。

### 3.2 连续格式异常安全降级

- 源码位置：`wireless_pairing.c` 的重试耗尽出口及 `WirelessPairing_ResetConnectionStatus()`。
- 改前问题：单次格式异常既停止整条部件参数刷新，又可能被上层描述成 UART6 透明交接失败，无法区分诊断内容无效与共享串口不安全。
- 具体改法：连续 3 次格式异常且每轮执行返回仍证明收尾安全时，清空连接、MAC、RSSI 等有效标志，保留 `WIRELESS_RESP_FORMAT_ERROR`，发布无效快照、记录告警并返回 `NO_ERROR`；其它部件诊断继续刷新。
- 必查边界：三次快照不能混合前次字段；明确未连接不按格式异常重试；清理、退出 AT、透明交接及等待错误均原样返回，不允许降级掩盖。
- 通过标准：安全耗尽后 CPU3 只看到同一代无效无线快照，上层不进入最终故障；任何无法证明 UART6 安全的错误仍阻断后续访问。

### 3.3 上层失败日志收口

- 源码位置：`part_diagnostics.c` 的 `PartDiagnostics_ReadAllInternal()`。
- 改前问题：所有无线状态刷新非零返回统一打印“蓝牙状态刷新失败，UART6透明传输未确认”，即使错误只是内容格式异常且透明交接已经成功。
- 具体改法：安全格式异常由快照层内部重试或降级并返回成功；上层非零路径改写为“无线状态查询收尾失败”，只描述真正传播到调用方的执行、清理或交接错误。
- 必查边界：`STATE_SWITCH` 仍正常退出、不打印最终故障；安全降级不进入该日志；其它非零返回继续阻断。
- 通过标准：格式异常不会被误报为交接失败，真实不安全错误仍保留具体错误码并停止后续 UART6 访问。

## 4. 数据流与异常闭环

```text
每 5 秒无线状态刷新
  -> 完整读取 BLEMODE/BLESTA/CCADD/RSSI
  -> RSSI OFF、AT EXIT、UART6 透明交接
  -> 成功或明确业务状态：发布快照并返回
  -> 非格式执行/收尾错误：发布本次状态并立即返回错误
  -> 格式错误且收尾安全：等待 300 ms 后重做完整事务，最多 3 次
  -> 三次均为格式错误且收尾安全：发布统一无效快照、告警、继续其它部件诊断
  -> 等待期间命令切换：返回 STATE_SWITCH，不进入最终故障
```
