# CPU2 V1.42.8.0 V4帧间隔与负频率提示改动与测试方案

## 1. 版本和适用范围

- CPU2：`V1.42.7.0 -> V1.42.8.0`（PATCH）。
- CPU3：保持`V1.40.1.0`。
- 适用链路：CPU2 DM4 多参数传感器 V4 交互读写、主动转交互窗口、密度/液位前台频率读取。

## 2. 协议和参数存储兼容性

- `DEVICE_PROTOCOL_VERSION`保持35；不改变CPU2/CPU3共享寄存器、共享命令、共享状态或共享字段。
- DM4 V4帧格式和命令语义保持兼容；所有8字节V4请求新增CPU2侧事务间最小30 ms门禁。
- CPU2 `DEVICE_PARAM_VERSION`保持3；`DeviceParameters`大小、字段偏移、元信息和CRC范围不变。
- 升级不会恢复出厂参数、不清除现场参数；无需参数迁移。

## 3. 本次提交范围

### 3.1 V4事务帧间隔

- 源码位置：`LTD_MAIN_CPU2/Services/Sensor/Protocols/Dm4/V4/multiparam_v4_internal.h` 的 `MULTIPARAM_V4_INTER_FRAME_GAP_MS`；`multiparam_v4_interactive.c` 的 `MULTIPARAM_V4_WaitInterFrameGap`、`MULTIPARAM_V4_MarkTransactionEnd` 和 `MULTIPARAM_V4_TransceiveOnceInternal`。
- 改前问题：连续V4事务可能在上一笔事务收尾后立即进入下一次发送，无法保证总线静默时间。
- 具体改法：事务成功、业务校验失败、异常帧和超时返回前后统一记录退出 tick；下一次发送前以 `HAL_GetTick() - last_exit_tick >= 30` 检查，不满足时每次延时1 ms；主动转交互还必须同时满足主动帧15～100 ms窗口。
- 必查边界：首次事务无历史tick、有效应答、业务校验失败、短帧、UART错误、无响应超时、命令切换请求、主动帧窗口过早/过晚、tick回绕。
- 通过标准：相邻V4事务TX时间戳差值满足上一笔事务退出后至少30 ms；错误或超时后下一次V4 TX也满足同一门禁；不产生永久等待。

### 3.2 负频率提示

- 源码位置：`LTD_MAIN_CPU2/Services/Sensor/Protocols/Dm4/V4/multiparam_v4_measurement.c` 的 `MULTIPARAM_V4_PrintNegativeFrequencyWarning` 及密度/液位读取入口。
- 改前问题：前台读到负频率时没有明确提示当前频率可能不稳定，现场容易把该值当作可信频率。
- 具体改法：密度交互读取、密度主动快照读取、液位交互读取和液位主动快照读取在消费R04前台值时，检测负值并打印原始有符号频率；不改变既有返回码、原始值保留、绝对值发布和无效值归一化。
- 必查边界：`0`、正值、普通负值、`INT32_MIN`、超量程值、密度模式和液位模式、交互和主动两条路径。
- 通过标准：负值出现一条明确提示并包含原始值；返回码和业务归一化结果与改动前保持一致；`INT32_MIN`不执行未定义的绝对值转换。
