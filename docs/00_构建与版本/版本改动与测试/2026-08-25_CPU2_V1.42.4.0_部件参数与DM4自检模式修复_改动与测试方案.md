## 4. 逐项改动清单

### 4.1 命令15统一准备密度模式

- 源码位置：`part_diagnostics.c`的`PartDiagnostics_PrepareDensityMode()`和`PartDiagnostics_ReadAllInternal()`；调用链为命令15 -> 识别传感器 -> 切换密度模式 -> `SensorService_ReadDensity()`。
- 改前问题：旧逻辑只对V3/LTD执行密度模式切换。DM4 V4或DSM若继承上一液位测量状态，命令15直接读取密度，V4在R02业务校验阶段返回`0x000D002F`并停止测量。
- 具体改法：所有已识别传感器在读取密度前统一调用`SensorService_EnableDensityMode()`；非V3成功后立即读取，V3继续执行原有3000 ms稳定等待；模式切换错误和命令切换`STATE_SWITCH`沿既有出口返回。
- 必查边界：V4从液位模式进入、V4已处于密度模式、DSM、V3稳定等待、切换失败、等待期间命令切换和未知传感器类型。
- 通过标准：V4或DSM处于液位模式时执行命令15，先完成密度模式切换再读取密度，不再因残留模式返回`0x000D002F`；V3等待时序和中断行为不变。

### 4.2 DM4诊断测试显式准备密度模式

- 源码位置：`service_debug_command.c`的`Sensor_CommCheckAndLog()`和`SensorWireless_CommTest()`；消费链路为诊断入口 -> DM4模式切换 -> 密度/温度/频率读取 -> 结果计数与日志。
- 改前问题：两处DM4诊断路径直接读取密度，残留液位模式会被计为通信失败，无法区分模式前置缺失与真实通信错误。
- 具体改法：读取前调用`SensorService_EnableDensityMode()`并单独记录切换结果；切换失败时保留底层错误和失败计数，不再发送后续密度读取。
- 必查边界：切换成功、切换超时、帧校验失败、业务校验失败、已处于密度模式、无线识别后首次读取和连续多次诊断。
- 通过标准：模式切换与密度读取分别形成可观察日志；切换失败只计一次对应失败且不继续读密度；成功时输出频率、密度和温度。

## 5. 数据流和异常闭环

- 命令15：命令分发 -> `PartDiagnostics_ReadAllInternal()` -> 传感器识别 -> `SensorService_EnableDensityMode()` -> V3可中断稳定等待 -> `SensorService_ReadDensity()` -> 成功打印或既有故障上报。
- DM4自检：调试入口 -> `SensorService_EnableDensityMode()` -> 独立打印/记录切换结果 -> 成功后读取密度 -> 输出数据或记录底层错误。
- 本次不修改V4底层R02模式校验，因为该校验能正确识别调用方前置缺失；修复位于发起密度读取的业务入口。
