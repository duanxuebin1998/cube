# CPU2 V1.39.2.0 固定频率液位闭环与低液位保护改动与测试方案

## 1. 文档目的和适用版本

本文用于复核和验证方法5固定频率液位搜索、持续跟随、低液位保护以及`LF`串口调试入口。适用CPU2版本为`V1.39.2.0`，基线为`V1.39.1.0`；CPU3保持`V1.38.2.0`。

## 2. 版本、协议与参数存储兼容性

- CPU2：`V1.39.1.0 -> V1.39.2.0`（PATCH）。
- CPU3：保持`V1.38.2.0`。
- 共享协议：提交基线`DEVICE_PROTOCOL_VERSION=33`，不变；工作区中的协议34并行改动不属于本提交。
- CPU2参数存储：`DEVICE_PARAM_VERSION=3 -> 3`，不变。
- `DeviceParameters`、`struct_size`、字段偏移、magic、CRC范围和FRAM A/B地址均不变化，升级不会恢复出厂或清除现场参数。
- 既有`oilLevelFrequency`、`oilLevelThreshold`和`oilLevelHysteresisThreshold`字段的地址、宽度和持久化语义不变；方法5分别把后两者按x10换算为首次搜索死区和持续跟随死区。
- `LF=<目标>[,<死区>]`覆盖值仅对本次搜索有效，返回前恢复公开`follow_frequency`，不修改`DeviceParameters`、不写FRAM。

## 4. 详细改动

### 4.1 生产方法5使用已知目标频率直接闭环

- 源码位置：`measure_oilLevel.c`的`OilLevel_TryRunDirectSearchMethod()`、`FrequencyLevel_RunFixedClosedLoop()`、`FrequencyLevel_RunClosedLoopConfigured()`；调用链为`SearchOilLevel() -> 方法5直接分流 -> 固定频率闭环`。
- 改前问题：固定频率入口与串口调试入口各自维护闭环，生产逻辑仍容易与需要`air_frequency/oil_frequency`的相对频率路径混淆，后续安全修正可能只覆盖其中一条路径。
- 具体改法：方法5直接校验并使用`oilLevelFrequency`，以局部目标调用统一闭环；不进入`SearchOil()`/`SearchAir()`，不学习或依赖`oil_frequency`，也不执行命中液体后的固定下行100 mm。
- 必查边界：目标为0、1、6500、6501 Hz；方法0/1/4原端点路径；重复找液、找液后进入跟随以及命令切换。
- 通过标准：方法5目标合法时不调用端点粗找即可进入闭环；目标0返回参数缺失，目标大于6500返回参数越界；方法0/1/4行为保持原路径。

### 4.2 搜索与跟随使用不同死区并按频差调速

- 源码位置：`FrequencyLevel_GetCompatThresholdHz()`、`FrequencyLevel_GetDeadband()`、`FrequencyLevel_ComputeSpeedX100()`和`FrequencyLevel_RunClosedLoopConfigured()`。
- 改前问题：首次找液和持续跟随的阈值语义没有在统一闭环入口明确分开，调试入口还重复实现了另一套方向、速度和稳定计数。
- 具体改法：首次搜索使用`oilLevelThreshold`，持续跟随使用`oilLevelHysteresisThreshold`，原始值均按x10四舍五入换算为整数Hz；0或换算为0时使用15 Hz。`current_frequency > target + deadband`时下行，`current_frequency < target - deadband`时上行，死区内停机。速度从`0.10 m/min`起，按超出死区的频差比例增加，并受电机默认速度上限约束。
- 必查边界：两种阈值为0、低于0.5 Hz、恰好等于死区上下沿、超出上下沿1 Hz、大频差、默认速度低于最小速度以及运行中反向。
- 通过标准：方向与频差符号一致；死区边界不启动运动；运动速度不低于0.10 m/min、不高于有效默认上限；反向前先停止原方向。

### 4.3 稳定判定和结果发布

- 源码位置：`FrequencyLevel_RunClosedLoopConfigured()`的死区分支和`FrequencyLevel_RecordCurrentPosition()`。
- 改前问题：独立`LF`实现和生产方法5的稳定计数、结果发布及AO样本出口重复，二者可能产生不同结果。
- 具体改法：生产方法5和`LF`均使用同一闭环；连续3次进入死区后记录当前液位、同步密度分布液位及AO过程样本。首次搜索随后返回，持续跟随保持长循环并继续监测。
- 必查边界：稳定样本1/2/3次、死区内外交替、稳定后再次离开、记录时位置边界以及AO更新失败。
- 通过标准：少于3次不发布稳定结果；第3次才置`probe_at_liquid_level`和`liquid_stable`；离开死区会清稳定计数和稳定标志。

### 4.4 盲区停机和只上行撤回

- 源码位置：`FrequencyLevel_CheckMotionGuards()`、`FrequencyLevel_ReadCurrentWithGuards()`和`FrequencyLevel_HandleLowLimit()`。
- 改前问题：检测到液体后继续下行100 mm可能在低液位工况触底；旧盲区等待的方向条件也没有与方法5目标死区统一。
- 具体改法：方法5运动前、读数前和运动后检查`blindZone`。首次搜索到达盲区立即停机并返回`MEASUREMENT_OILLEVEL_LOW`；持续跟随到达盲区后停机等待，仅当`current_frequency < target - deadband`时允许上行撤回，等待期间不下行、不发布液位。
- 必查边界：位置恰好等于盲区、盲区上方一个位置单位、下行越界、跟随等待期间频率位于死区/高于上沿/低于下沿、命令切换和频率读取失败。
- 通过标准：首次搜索不在盲区继续下行；跟随等待时仅低于目标死区下沿能恢复上行闭环；命令切换和传感器错误及时返回。

### 4.5 位置、称重、丢步和超时保护

- 源码位置：`FrequencyLevel_ValidateFixedConfig()`和`FrequencyLevel_CheckMotionGuards()`；调用链覆盖方法5和`LF`。
- 改前问题：原独立调试闭环与生产闭环的保护检查顺序、参数校验和错误出口重复，存在一条路径遗漏称重上下限或位置轮询的风险。
- 具体改法：启动前校验`tankHeight > 1000`、`blindZone < tankHeight - 1000`、`full_weight`、`bottom_weight_threshold`和`zero_weight_threshold_ratio`关系；运行时上行使用`full_weight × (100 + zero_weight_threshold_ratio) / 100`作为最大称重保护，下行使用`bottom_weight_threshold`作为最小称重保护，并保留称重通信、`CheckWeightCollision()`、丢步、罐高上限、命令切换和600秒首次搜索超时。
- 必查边界：零满载、称重上下限相等/反转、32位溢出、罐高小于等于100 mm安全余量、位置上下限、称重通信超时、丢步和600秒边界。
- 通过标准：配置非法时不启动电机；运动中的任一保护失败都会使AO过程样本失效、尝试慢停并返回对应错误码。

### 4.6 `LF`串口调试复用生产闭环

- 源码位置：`fixed_frequency_level_search.c`的`FixedFrequencyLevelSearch_PrintCurrentConfig()`和`FixedFrequencyLevelSearch_Run()`，以及`measure_oilLevel.h`新增生产闭环入口。
- 改前问题：`LF`维护约400行独立电机闭环，与生产方法5重复；`LF?`文档声称打印位置、称重和速度限制，但当前输出只包含目标和两个死区。
- 具体改法：删除独立闭环，`LF`解析本次目标/搜索死区后调用`OilLevel_RunFixedFrequencySearch()`；`LF?`明确打印`target`、`search_deadband`和`follow_deadband`。覆盖值不写参数，退出后恢复原`follow_frequency`。
- 必查边界：`LF`、`LF?`、`LF=1`、`LF=6500,1`、非法尾随字符、0/6501、运行中`STOP`、返回成功/错误/打断以及生产目标恢复。
- 通过标准：严格解析测试全部通过；`LF?`不调用`MeasureStart()`且不启动电机；`LF`输出最终真实错误码，调试结束恢复`STATE_DEBUG_MODE`和原目标。

## 5. 数据流和异常闭环

生产方法5的数据流为：`oilLevelFrequency -> FrequencyLevel_ValidateFixedConfig() -> FrequencyLevel_RunClosedLoopConfigured() -> DSM_Get_LevelMode_Frequence() -> 频差/方向/速度 -> 电机速度模式 -> 位置与称重保护 -> 连续3次稳定 -> 液位/密度液位/AO样本`。首次搜索和持续跟随分别选择搜索死区与跟随死区；`LF`仅在最前端临时替换本轮目标和搜索死区，后续复用同一数据流。

所有异常出口通过`FrequencyLevel_StopAndReturn()`使AO过程样本失效并尝试慢停。首次搜索超时、位置/称重越界、称重通信、传感器、电机和丢步错误返回具体错误码；命令切换返回`STATE_SWITCH`，不转换成设备故障。

## 8. 复杂场景分步验证

### 8.1 低液位首次搜索不触底

1. 将液面设置在接近盲区的位置，确认罐底仍有可观察安全余量。
2. 配置方法5、有效目标频率和搜索死区，记录起始位置。
3. 发起找液位并同步记录频率、位置、称重和电机方向。
4. 如果频率始终要求下行，让位置到达`blindZone`。
5. 确认CPU2先停机，再返回`MEASUREMENT_OILLEVEL_LOW`；之后不得出现额外100 mm下行。

### 8.2 低液位持续跟随撤回

1. 先在安全位置让方法5进入稳定跟随。
2. 缓慢降低液面，使探头跟随至`blindZone`并停机。
3. 依次让当前频率位于死区内、高于上沿和低于下沿。
4. 前两种频率下保持停机；低于下沿时只允许上行撤回。
5. 撤回安全区后恢复正常闭环，期间`probe_at_liquid_level`和`liquid_stable`保持0，重新稳定后才置1。

### 8.3 串口覆盖值恢复

1. 记录生产`oilLevelFrequency`和当前`follow_frequency`。
2. 发送`LF=<不同目标>,<死区>`，观察启动打印。
3. 稳定结束、保护退出和`STOP`打断三种出口分别执行一次。
4. 每次退出后查询运行态，确认`follow_frequency`恢复为进入调试前的值，设备参数及FRAM未变化。
