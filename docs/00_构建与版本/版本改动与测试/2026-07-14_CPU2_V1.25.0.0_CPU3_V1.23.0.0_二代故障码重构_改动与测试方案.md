# CPU2 V1.25.0.0 / CPU3 V1.23.0.0 二代故障码重构改动与测试方案

## 1. 文档目的和适用版本

本文记录二代计量仪故障码重新分类、删减、重编号及双端同步改动，供代码复核、版本配套、台架故障注入和历史日志查询使用。

适用版本：

- CPU2：V1.25.0.0。
- CPU3：V1.23.0.0。
- CPU2/CPU3共享协议：17。
- CPU2参数存储版本：3。
- CPU3本机参数存储版本：0x0006。

本文件随本次提交纳入，提交哈希以Git记录为准。

## 2. 版本、协议和参数存储兼容性

| 项目 | 变更前 | 变更后 | 兼容结论 |
| --- | --- | --- | --- |
| CPU2固件 | V1.24.0.0 | V1.25.0.0 | 新增一套完整的二代故障码解释，提升次版本 |
| CPU3固件 | V1.22.0.0 | V1.23.0.0 | 同步共享枚举、类别显示和具体原因，提升次版本 |
| 共享协议 | 15 | 17 | 协议16仅为类别13、14互换的开发过渡，未单独发布；协议17与16及更早编号不兼容 |
| CPU2参数存储 | 3 | 3 | 不变 |
| CPU3本机参数存储 | 0x0006 | 0x0006 | 不变 |

参数存储兼容性：

- CPU2的 `DeviceParameters` 字段、结构大小、`struct_size`、`magic`、FRAM A/B区地址、元信息和CRC覆盖范围均未改变。
- 从CPU2 V1.24.0.0升级到V1.25.0.0不会恢复出厂参数，不会清除现场数据，不需要重新下发设备参数。
- CPU3本机FRAM结构和版本均未改变，不触发本机参数迁移或清除。
- 本次属于故障码共享语义的功能级不兼容变化，使用共享协议版本严格拦截，不满足软件主版本升级条件，因此CPU2、CPU3均提升MINOR，不升级MAJOR。

配套规则：

- CPU2和CPU3必须同时使用共享协议17，不能把协议17的一端与协议16及更早版本交叉烧写。
- CPU2产生的共享故障按CPU2程序版本选择故障码表，不能仅凭共享协议版本查询历史表。
- CPU3本机故障 `20-7` 按CPU3程序版本确认，不并入CPU2共享故障数量。

## 4. 详细改动

### 4.1 按二代责任域重建共享故障码目录

- 源码位置：CPU2、CPU3的 `system_parameter.h` 中 `ErrorCode`。
- 改前问题：协议15仍以早期九类责任域组织故障码，与一代类别延续关系、二代新增责任域和现场处理方式不完全一致；同一责任模块内存在跳号、泛化码和低价值重复码。
- 具体改法：同步建立协议17枚举。CPU2包含2项非故障状态和63项共享故障；CPU3同步这些定义，并额外保留1项本机故障。现行有故障项的类别为11电机驱动、12编码器、13传感器与密度、14零点与位置检测、15测量过程、17参数与存储、18模拟输出与自检、20设备通信链路、21扭力检测、22系统与软件。
- 必查边界：枚举值唯一；CPU2、CPU3共享名称和值完全一致；CPU3本机码不进入CPU2；类别号和子码均按十进制显示；历史编号不得复用。
- 通过标准：目录契约报告CPU2枚举65项、CPU3枚举66项；共享定义和值一致；正式表64项。

### 4.2 停用12项低价值故障码并冻结历史编号

- 源码位置：双端 `ErrorCode`、CPU2 `error_log.c/.h`、CPU3 `display.c`、AO运行期判断和密度测量依赖说明。
- 改前问题：部分故障没有独立产生点、已被具体故障替代，或只能表达无法直接定位的泛化现象；继续保留会增加现场误判。
- 具体改法：从当前枚举和映射移出电机设置失败、电机复位失败、滑环校验错误、滑环丢包、传感器温度异常、传感器电压异常、密度不稳定、密度范围无效、AD5421故障管脚报警、未知故障、地址读取错误和电源波动共12项。
- 必查边界：全仓运行源码不得再引用这些符号；旧编号只允许出现在历史表和迁移说明；不得把旧值分配给新含义。
- 通过标准：故障码目录契约对12个符号执行运行引用扫描并全部通过；CPU2、CPU3 clean-first构建无未定义符号。

### 4.3 保留3项已确认的兼容编号

- 源码位置：双端 `ErrorCode` 和正式工作簿。
- 改前问题：治理阶段曾计划保留15项未启用码，数量过多且缺少明确产品决策。
- 具体改法：仅保留 `12-6 编码器上电值变化`、`15-16 实高偏差过大`、`21-5 扭力传感器饱和`；其余未启用项按停用或使用中状态处理。
- 必查边界：保留码当前设备不得主动产生；代码调用点扫描必须为0；正式表必须明确“保留”。
- 通过标准：正式表统计为61项使用中、3项保留；契约脚本只接受上述3个保留枚举。

### 4.4 同步CPU2错误日志名称、原因和责任模块

- 源码位置：`ErrorLog_GetModuleByCode()`、`ErrorLog_GetReasonByCode()`、`ErrorLog_GetCodeName()`。
- 改前问题：故障码高16位类别变化后，旧责任模块兜底会把位置故障归为通信、模拟输出归入旧16类，并可能显示已删除故障名称。
- 具体改法：按协议17类别更新责任模块和兜底原因；逐项保留现行故障的中文名称和具体原因；删除已停用枚举分支。
- 必查边界：直接映射和类别兜底均需覆盖；具体错误不能被上层泛化；未知值仍使用统一未知文本；不改变日志打印时序和故障恢复逻辑。
- 通过标准：名称/原因覆盖检查无缺项；传感器、参数/测量、TMC5130和AD5421专项契约通过。

### 4.5 同步CPU3类别、具体原因和本机通信故障

- 源码位置：CPU3 `system_parameter.h` 和 `Display_GetErrorReasonByCode()`。
- 改前问题：CPU3仍按旧类别解释共享故障；主控通信超时曾使用13-12开发编号，不能与协议17当前设备通信责任域一致。
- 具体改法：同步协议17共享值；把CPU3本机 `CPU2_COMM_TIMEOUT` 调整为 `0x00140007`，屏幕显示 `20-7`；更新全部具体原因和类别兜底。
- 必查边界：本机通信故障只由CPU3产生；连续失败门槛和解除条件不变；128×64屏幕仍使用“类别-子码”两部分十进制显示；中文必须有字库。
- 通过标准：CPU3本机通信故障契约、具体原因可见性检查和字库检查通过，缺字0个。

### 4.6 清理被停用枚举的邻接引用

- 源码位置：`AoOutput_IsRuntimeDriverError()` 和 `measure_density.c` 文件说明。
- 改前问题：AO判断仍引用已停用的AD5421故障管脚码，密度测量依赖说明仍列出已停用的密度不稳定和未知故障。
- 具体改法：删除这些引用，仅保留仍可产生的具体故障。
- 必查边界：不得改变AO实际故障检测条件以外的运行逻辑；不得改变密度测量步骤、返回值或状态切换。
- 通过标准：AO和密度模块正常编译；最终差异中没有测量流程、状态机或恢复条件改动。

### 4.7 建立当前表、历史表和代际兼容口径

- 资料位置：正式工作簿、内部治理工作簿、当前程序清单、权威来源判定和协议记录。
- 改前问题：一代、二代、旧CPU2版本和内部治理信息混在同一阅读层，现场容易按错误版本解释故障。
- 具体改法：正式表面向正常查阅，使用中文参数名和故障原因；内部工作簿保存枚举、调用点和迁移信息；CPU2 V1.24.0.0历史表及一代计量仪历史表独立冻结。共享故障按CPU2程序版本选表，CPU3本机码按CPU3程序版本确认。
- 必查边界：正式表不出现内部枚举名、十六进制迁移细节和治理过程；历史表不得被当前编号回写；工作簿合并单元格、边框、列宽和换行不得破坏。
- 通过标准：正式工作簿6张工作表无公式错误，视觉检查无截断；当前数量、使用状态和版本说明与源码一致。

### 4.8 发布协议17并同步固件版本

- 源码位置：双端版本头、双端 `DEVICE_PROTOCOL_VERSION`、`CHANGELOG.md` 和协议变更记录。
- 改前问题：协议16只是开发过渡，若按独立正式版本描述，会造成现场寻找不存在的发布固件；此前错误地把协议不兼容等同于软件主版本升级。
- 具体改法：正式发布直接使用协议17；CPU2从V1.24.0.0升到V1.25.0.0，CPU3从V1.22.0.0升到V1.23.0.0；明确参数存储兼容、不清参。
- 必查边界：协议版本必须双端严格相等；固件版本和共享协议版本分别判断；发布资料不得出现V2.0.0.0或协议16独立发布结论。
- 通过标准：版本头、协议记录、CHANGELOG、工作簿和本文件版本一致；版本门禁通过。

## 5. 数据流和异常闭环

共享故障链路：

`CPU2具体错误源 -> ErrorCode -> g_measurement.device_status.error_code -> 32位状态寄存器 -> CPU3状态快照 -> 十进制类别-子码及中文原因`

CPU3本机故障链路：

`CPU2通信连续失败 -> CPU2_COMM_TIMEOUT(20-7) -> CPU3本机STATE_ERROR -> 屏幕显示 -> 合法完整状态响应解除锁存`

本次只改变故障码数值、名称、责任域和显示解释，不改变错误产生条件、重试次数、最终置错入口、电机停机、自动恢复白名单、命令调度、测量步骤或寄存器地址。
