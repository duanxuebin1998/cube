## 4. 详细改动

### 4.1 CPU2建立独立SI Profile生命周期

- 源码位置：`system_parameter.h`中的`SiProfilePhase`、`SiProfileRuntime`和`MeasurementResult.si_profile_runtime`；`measure_density.c`中的SI Profile流程；`measure.c`中的命令分发和回液位完成处理。
- 改前问题：上位机无法区分命令已下发、Point0已建立、有效点递增、采点结束、回液位和最终发布；预期点数在测量前未知，不能靠固定点数判定完成。
- 具体改法：增加`PREPARING/MEASURING/RETURNING_LEVEL/COMPLETE/ABORTED/FAILED`阶段、周期计数和有效点进度；Point0有效样本写入时建立新周期并令进度从1开始，后续点逐步增加。
- 必查边界：Point0前取消、Point0后取消、采点失败、命令覆盖、1点和200点上限、液面以上候选不计入有效点。
- 通过标准：CPU3读取的周期号只在Point0建立时改变；活动阶段点数单调不减；失败或取消不发布本轮最终Complete。

### 4.2 回液位后发布最终Complete组合

- 源码位置：`measure_density.c`的候选形成逻辑、`measure.c`的`RETURNING_LEVEL`处理、CPU2分布结果完成计数和来源字段。
- 改前问题：采点结束即发布会使上位机在探头尚未回到液位时看到Complete，且最终点数、点阵、液位和动作状态可能来自不同阶段。
- 具体改法：采点成功后只形成SI候选并排队找液位；液位稳定且电机停止后再锁存`profile_complete_latched`、完成计数、来源、最终点数和点阵。
- 必查边界：回液位失败、回液位中插入其它命令、无有效点、普通分布结果覆盖、重复完成轮询。
- 通过标准：回液位前Complete保持0；回液位后Auto、Stop、Complete、最终N和点阵属于同一SI周期。

### 4.3 CPU3不可变发布快照和代际复核

- 源码位置：`cpu2_communicate.c`中的候选头读取、分块点阵读取和前后代际复核；`si_modbus_slave.c`中的`SiProfileProjection`及最终发布判断。
- 改前问题：200点点阵跨多帧读取，期间CPU2结果变化可能产生混代数据；旧SI结果还可能被普通分布或Wärtsilä结果覆盖。
- 具体改法：点阵拉取前后分别读取完成计数、周期号、来源、阶段和点数；只有两次键值完全一致且来源为SI时才发布；已发布快照独立保存。
- 必查边界：任一分块超时、头部变化、来源变化、点数越界、CPU3重启后的旧快照恢复。
- 通过标准：失败时不发布部分点阵；发布后非SI分布不改变SI Complete、N、时间、点阵和Profile报警。

### 4.4 站2输入寄存器兼容

- 源码位置：`si_modbus_slave.c`的FC04映射和`30014~30020`构造逻辑。
- 改前问题：现场抓包证明站2在官方保留区返回状态镜像，原实现与真实上位机读取口径不一致。
- 具体改法：`30014~30016`分别镜像FC01模式/动作、FC02状态和FC02报警；`30017~30020`保持0。
- 必查边界：Manual/Auto/Profile切换、上/下/停止、报警变化、跨地址连续读取。
- 通过标准：同一CPU3快照下镜像位与对应FC01/FC02一致，保留四项始终为0。

### 4.5 站2保持寄存器兼容和CPU3 FRAM V7

- 源码位置：`cpu3_comm_display_params.h/c`的`si_compat_holding[6]`、V6/V7结构和迁移；`si_modbus_slave.c`的FC03/FC06处理。
- 改前问题：`40004~40009`现场可读写但无已确认业务含义；旧实现不能保留这些值。
- 具体改法：增加六个CPU3本地原始兼容槽，按现场默认值初始化并允许原值读写；字段不参与测量、报警或控制。CPU3存储从V6升级为V7，正常迁移保留V6既有SI参数和三路串口配置。
- 必查边界：V6正常迁移、合法Wärtsilä 4800 8N1/8N2串口值、重复保存、写后读回失败和掉电重启。
- 通过标准：正常迁移后V7 CRC有效；`40004~40009`重启保持；失败返回`0x06`且运行态回滚。迁移写失败破坏旧镜像的风险见R18-01。

### 4.6 Point0时间戳、渐进点数和最终点阵投影

- 源码位置：`si_modbus_slave.c`中的`si_update_profile_projection()`、时间戳锁存和FC04点阵映射。
- 改前问题：液位和最终点数只能测完后确定，无法提前给出预期点数；命令触发时间也不等于Point0采样时间。
- 具体改法：CPU3观察CPU2周期号边沿后锁存RTC；活动阶段只发布渐进N且点阵保持0；最终候选通过代际复核并回液位完成后再发布点阵和Complete。
- 必查边界：RTC读取失败、CPU2重启、CPU3重启、周期号回绕、完成计数不变或跨代。
- 通过标准：Point0前保留上一轮；Point0后时间更新且N从1增加；最终发布前有效点阵仍为0。

### 4.7 自动Profile调度

- 源码位置：`si_modbus_slave.c`中的调度配置刷新、分钟锚点和命令重试；CPU3本机`40010~40013`参数。
- 改前问题：需要从首次时间按周期连续跨天调度，并在命令失败时重试而不是误记本分钟成功。
- 具体改法：按RTC绝对分钟建立RAM锚点，周期命中时启动SI Profile；CPU2拒绝或通信失败后按5秒节流重试，只有成功才锁存本分钟。
- 必查边界：`40010=0`非法、`40011=0`关闭、小时/分钟边界、午夜、61/1000分钟周期、CPU3重启。
- 通过标准：连续运行时非整日周期跨午夜不重置；CPU3重启相位丢失风险见R18-03。

### 4.8 写命令ACK、快照门禁和协议18拦截

- 源码位置：`cpu2_communicate.c`的可用性、参数补读和失败计数；`si_modbus_slave.c`的FC05/FC06写路径；双端`DEVICE_PROTOCOL_VERSION`。
- 改前问题：CPU2离线、协议不匹配或参数快照未完成时，不能把本地影子当作真实ACK结果。
- 具体改法：`FC05=ON`及`40001~40003`写入必须等待CPU2合法ACK；失败返回`0x06`并保留影子，参数写后关闭快照并补读。CPU3本地`40004~40023`不依赖CPU2在线，但FRAM失败同样返回`0x06`。
- 必查边界：协议17/18混搭、CPU2十次失败门限、ACK超时、坏帧、参数补读窗口和多端口连续写。
- 通过标准：不兼容组合不开放普通写；ACK失败不提交请求值；补读完成前相交读取返回忙。

## 5. 跨CPU数据流

1. PLC、CPU3菜单或自动调度触发`CMD_SI_PROFILE`。
2. CPU2进入`PREPARING`，Point0前保留上一轮已发布结果。
3. CPU2取得Point0有效样本后递增`cycle_counter`，设置`MEASURING`和`progress_points=1`。
4. CPU3周期轮询生命周期尾组；观察到新周期后锁存RTC，活动期对外只发布渐进点数。
5. CPU2逐点采样并递增进度，遇到液面以上候选、罐高或200点上限后结束采点。
6. CPU2进入`RETURNING_LEVEL`并排队找液位；液位稳定且电机停止后形成SI Complete候选。
7. CPU3读取候选头、分块点阵、再次读取候选头；只有代际一致才一次发布最终快照。
8. PLC读取FC01/FC02/FC04取得Auto、Stop、Complete、最终N、时间和点阵。
