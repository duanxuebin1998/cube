# CPU2 V1.42.6.0 Debug/Release双构建改动与测试方案

## 1. 文档目的和适用版本

本文记录CPU2 V1.42.6.0相对V1.42.5.1的Debug/Release双构建、产物命名、USART1调试命令接收差异、兼容性、验证证据和未验证边界。本次仅修改CPU2固件构建行为，不修改CPU3固件功能，不推送远端。

## 2. 版本、协议和参数存储兼容性

- CPU2：`V1.42.5.1 -> V1.42.6.0`，PATCH。
- CPU3：保持`V1.40.1.0`。
- `DEVICE_PROTOCOL_VERSION`保持35；CPU2/CPU3共享寄存器、共享命令、共享状态和共享字段不变。
- CPU2 `DEVICE_PARAM_VERSION`保持3，CPU3 `CPU3_PARAM_VERSION`保持`0x0007`；`DeviceParameters`结构、元信息、CRC范围和FRAM布局不变，升级不恢复出厂、不清除现场参数。
- Debug固件保留USART1调试命令接收；Release固件关闭USART1 RX DMA、IDLE中断和USART1恢复轮询。USART1发送能力、CPU2测量控制、传感器通信及对外业务协议不变。

## 4. 逐项改动清单

### 4.1 CMake构建变体与产物命名

- `CPU2_BUILD_VARIANT`仅接受`debug`或`release`，默认值为`debug`，输入不区分大小写。
- Debug注入`CPU2_USART1_COMMAND_RX_ENABLED=1`；Release注入`CPU2_USART1_COMMAND_RX_ENABLED=0`。
- 固定产物分别为`LTD_MAIN_CPU2_DEBUG.hex/.bin`和`LTD_MAIN_CPU2_RELEASE.hex/.bin`；版本HEX分别为`LTD_MAIN_CPU2_V1.42.6.0_DEBUG.hex`和`LTD_MAIN_CPU2_V1.42.6.0_RELEASE.hex`。
- 非法变体必须在CMake配置阶段失败，避免静默生成语义不明的固件。

### 4.2 USART1调试命令接收差异

- Debug沿用原行为：启动USART1 RX DMA，使用IDLE中断收帧，并参与TIM4恢复轮询。
- Release在USART1初始化后关闭IDLE中断、停止RX DMA、关闭USART1 IRQ，并在恢复轮询中跳过USART1。
- Release不改变USART1初始化和发送路径；串口输出仍可用于既有运行日志，禁止把Release解释为完全关闭USART1外设。

### 4.3 编辑器和CI入口

- VS Code为Debug和Release分别提供配置、编译、普通连接烧写、复位连接烧写及组合任务，烧写路径与变体产物名一致。
- GitHub Actions矩阵增加`cpu2-release`，CPU2两种变体使用独立构建目录，避免缓存和产物覆盖；CPU3仍执行Debug构建。

## 6. 回归范围、风险与验证边界

- 回归范围：CPU2 CMake配置、固件命名、USART1调试命令接收、VS Code任务和CI矩阵。
- 主要风险：Release仍初始化USART1并保留发送能力；若现场把“Release关闭调试串口”理解为引脚无活动，需要另行确认产品要求。关闭USART1 IRQ后若未来在Release发送路径依赖该IRQ，也需补充目标板回归。
- 隔离验证用于排除当前主工作区未纳入提交的DM4改动；构建通过不能替代目标板USART1 DMA、IDLE中断和发送路径验证。
- 本次不验证真实DM4/DSM传感器、RS485、无线滑环、目标板、台架、现场或SIL场景。
