# CPU2 V1.8.1.0 串口 B/BE 低检测重试改动与测试方案

## 版本变化

- CPU2：V1.8.0.0 -> V1.8.1.0
- CPU3：未变化，保持 V1.6.0.0
- 升级级别：patch

## 协议版本/兼容性

- 本次只调整 CPU2 串口调试指令 B/BE 的内部执行流程。
- 不修改 Modbus、SI7000、CPU2/CPU3 共享寄存器映射、参数存储布局或 `DEVICE_PROTOCOL_VERSION`。
- 命令格式保持兼容：`B<mm>`、`BE<mm>`、`B<mm>S`、`BE<mm>S`、`B<mm>,1`、`BE<mm>,1`。

## 详细改动点

- `process_command()` 中 B/BE 分支前置到通用 `MeasureStart()` 之前，避免调试指令被测量初始化、扭力、电机健康检查或历史错误码拦截。
- B/BE 使用专用低检测路径：初始化阶段只尽量写 TMC5130 基础配置，运动阶段直接写 `RAMPMODE`、`VMAX`、`XTARGET`，不读取业务错误状态。
- B/BE 电机运行函数改为直接写 TMC5130 `RAMPMODE`、`VMAX`、`XTARGET` 等寄存器；不再根据 `stpr_moveBy()`、`stpr_moveTo()`、`stpr_setVelocity()`、`stpr_setPos()` 返回错误码决定流程。
- B 指令不检测编码器、扭力、电机过热、驱动告警等业务错误；只管下发往返运动并等待电机停转。
- BE 指令进入后固定记录起始编码点和下行目标点，循环过程中不重新计算；下行结束后记录上行起点，上行始终回到最初起始点。
- BE 单段运动下发后，到达固定编码目标或检测到 `RAMPSTAT.VZERO` 电机停转即结束本阶段；不读取编码器错误码或其它全局错误码。
- 电机停转判断使用二次确认：第一次读到 `RAMPSTAT.VZERO` 后延时 200ms，再次读取仍为 `VZERO` 才认为停稳，避免换向瞬间速度为 0 被误判。
- BE 不重复启动编码器采集定时器；定时器由上电初始化启动，BE 只读取当前编码器计数和最近一次编码器错误。
- S 后缀通信检查和 `SC` 通信测试的传感器参数读取按 `sensorType` 区分 DSM 一代和 LTD/V2 传感器，每次只发一次读命令；DSM 一代只读频率/密度/温度，LTD/V2 只读密度，不切液位模式、不读液位频率。S 后缀调用前后恢复 `device_state` 和 `error_code`，不参与退出条件或错误状态。
- 每段新运动下发前，上一段只等待 `TMC5130_RAMPSTAT.VZERO`，不依赖拟合目标对应的 `POSREACHED`。
- 更新 HTML 文档：`LTD_MAIN_CPU2/docs/01_电机与编码器/串口B指令详细执行过程.html`。

## 影响范围

- 影响 CPU2 串口调试命令 B/BE。
- 不影响正式业务测量命令、CPU3 显示、SI7000 转换、参数存储和 Modbus 寄存器映射。
- B/BE 调试过程会主动清理自身路径中产生的全局错误码，避免进入业务错误状态。

## 需要重点测试的点

### 1. B 指令基础往返

准备条件：设备可通过串口发送调试命令，电机可安全往返。

步骤：
1. 下发 `B100`。
2. 观察日志中 B DOWN 和 B UP 循环执行。
3. 确认每段运动完成后才下发下一段。

预期结果：
- B 指令持续循环，不因扭力异常、驱动健康检查或历史错误码退出。
- 每段运动之间有停稳二次确认。

通过标准：
- 无异常退出。
- 日志持续打印 loop done。

### 2. B 指令运行期下发失败重试

准备条件：可模拟 TMC5130 通信短暂失败或在安全条件下断开/恢复驱动通信。

步骤：
1. 下发 `B100`。
2. 制造一次运动命令下发失败。
3. 恢复通信。

预期结果：
- 日志打印 command failed 或 raw init failed。
- 流程不停机退出，恢复后继续当前阶段。

通过标准：
- 不进入业务错误状态。
- 恢复后 B 往返继续运行。

### 3. BE 编码器闭环目标

准备条件：编码器采集正常，编码轮周长参数有效。

步骤：
1. 下发 `BE100`。
2. 观察下行使用进入 BE 时固定的目标、上行回进入 BE 时固定的原点。
3. 检查日志中的 current/target 编码值和 mm 换算。

预期结果：
- 下行满足 `current >= target` 或电机停转后结束本阶段。
- 上行满足 `current <= origin` 或电机停转后结束本阶段。
- 每次停止后等待 `VZERO` 二次确认再进入下一段。
- 起始点和下行终止点在 BE 循环期间保持不变。

通过标准：
- 编码器目标日志符合方向判断。
- 循环持续运行。

### 4. BE 不受编码器/扭力错误码影响

准备条件：可模拟编码器超时、OCF/COF/LIN 等异常，或临时断开编码器信号。

步骤：
1. 下发 `BE100`。
2. 制造编码器异常或扭力通信超时。
3. 观察 BE 是否继续按编码值或停转推进。

预期结果：
- BE 不读取编码器错误码，不因编码器错误码退出。
- 若编码器读数未到目标但电机停转，本阶段结束并进入下一阶段。

通过标准：
- B/BE 不因编码器或扭力错误码退出。
- BE 只按编码值到达或电机停转推进阶段。

### 5. S 后缀通信结果只打印

准备条件：传感器通信可正常或可模拟失败。

步骤：
1. 分别在 DSM 一代和 LTD/V2 传感器配置下下发 `B100S` 和 `BE100S`。
2. 分别观察下行/上行后的通信日志。
3. 模拟一次传感器通信失败。

预期结果：
- 通信成功/失败均只打印，且打印项符合当前 `sensorType`。
- 每次 S 后缀检查只发一次读命令：DSM 一代读取频率/密度/温度，LTD/V2 读取密度；不切液位模式，不读取液位频率。
- `device_state` 和 `error_code` 不因 S 后缀改变。
- B/BE 不因通信失败退出。

通过标准：
- 无错误状态残留。
- 循环继续。

### 6. 命令切换退出

准备条件：B/BE 正在运行。

步骤：
1. 下发 `B100` 或 `BE100`。
2. 再下发新的有效命令。

预期结果：
- 当前 B/BE 测试打印命令切换提示。
- 停止当前测试并关闭驱动。

通过标准：
- 能从 B/BE 退回命令处理流程。
- 不把运行期错误码带入后续状态。

## 回归范围

- 串口 A/C/D/E 等其它调试命令仍走原通用 `MeasureStart()` 路径。
- 正式业务命令仍由主循环执行，不被 B/BE 改动影响。
- CPU2 构建输出版本应为 V1.8.1.0。
