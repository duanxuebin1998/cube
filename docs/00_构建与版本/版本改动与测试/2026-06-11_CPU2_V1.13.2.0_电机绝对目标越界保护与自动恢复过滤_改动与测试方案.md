# CPU2 V1.13.2.0 电机绝对目标越界保护与自动恢复过滤改动与测试方案

日期：2026-06-11

## 版本变化

| 项目 | 旧版本 | 新版本 | 说明 |
| --- | --- | --- | --- |
| CPU2 固件版本 | `V1.13.1.0` | `V1.13.2.0` | 修复电机绝对目标越界保护和参数错误自动恢复 |
| CPU3 固件版本 | `V1.12.1.0` | `V1.12.1.0` | 未修改 CPU3 |
| `DEVICE_PROTOCOL_VERSION` | `7` | `7` | 不改变 CPU2/CPU3 共享协议 |

本次属于 CPU2 电机运动和故障恢复边界修复，按 patch 升级 CPU2 固件版本。

## 协议版本/兼容性

- 不新增 CPU2/CPU3 共享命令、状态、输入寄存器、保持寄存器、结构体或设备参数字段。
- 不改变 BJ/BJP 本地串口测试命令的命令格式，只修正绝对目标越界时的返回和停止行为。
- 电机目标越界继续使用已有 `PARAM_RANGE_ERROR` (`0x00110003`)，不新增错误码。
- `MEASUREMENT_POSITION_ERROR` 仍用于位置快照无效、位置读取失败等测量位置问题，不再承担绝对目标超出罐高的参数错误含义。

## 参数存储兼容性

- CPU2 `DEVICE_PARAM_VERSION`: `3 -> 3`。
- `DeviceParameters` 结构大小：不变。
- 升级是否清参数：否；从 V1.13.1.0 升级到 V1.13.2.0 不会因参数存储版本或结构大小触发恢复出厂。
- 现场动作：正常升级即可。若设备 FRAM A/B 分区本身 CRC 或元信息损坏，仍按既有参数加载异常流程恢复出厂。

## 详细改动点

| 模块 | 改动 |
| --- | --- |
| `motor_ctrl_motion_api.c` | 新增 `MotorMotionSpeedScope`，集中处理运动速度切换和退出恢复 |
| `motor_ctrl_motion_api.c` | `MotorCtrl_MoveByTicksAndWait()` 拆分起步等待和到位等待助手，减少重复状态判断 |
| `motor_ctrl_motion_api.c` | `MotorCtrl_MoveAndWait()` 删除不可达重试框架，改为单路径正式运动 |
| `motor_ctrl_motion_api.c` | 新增 `MotorMotion_CheckAbsoluteTargetRange()`，统一检查目标是否小于 0 或大于罐高 |
| `motor_ctrl_motion_api.c` | 正式绝对目标、相对运动换算目标、点动绝对目标和点动相对目标均进入同一目标范围检查 |
| `motor_ctrl_motion_api.c` | 新增 `MotorMotion_RefreshJogPositionChecked()`，集中处理点动位置刷新、快照有效性和越界检查 |
| `fault_recovery.c` | 新增不可恢复错误过滤，参数类确定性错误不再自动重跑 |
| 文档 | 新增优化计划、台架验证记录、本次改动点 HTML，并更新电机与编码器索引 |

## 影响范围

| 范围 | 影响 |
| --- | --- |
| 正式运动 | `MotorCtrl_MoveAndWait()` 对目标越界更早返回 `PARAM_RANGE_ERROR`，不启动电机 |
| 绝对目标运动 | `MotorCtrl_MoveToPosition()` 入口即检查目标范围 |
| 点动运动 | `MotorCtrl_JogMoveAndWait()` / `MotorCtrl_JogMoveToPosition()` 统一复用目标范围检查 |
| 故障恢复 | 参数超限、参数地址溢出、参数错误不再进入自动恢复重试 |
| 协议和参数 | 无共享协议、参数存储、CPU3 显示改动 |

## 回归范围

- 正式运动、点动运动、编码器 tick 运动的启动等待、到位等待、停止和命令切换。
- 绝对目标和相对距离换算目标的边界值：0、罐高、罐高外、负值。
- 自动故障恢复对参数类错误和驱动类错误的区分。
- 串口中文错误打印、错误码名称和返回码。

## 未验证风险

- T15/T16 尚未在本轮台架覆盖，后续如验证大负距离和长时间软停止，应继续保持传感器位置不低于 200mm、不高于 1000mm。
- 本次通用目标范围仍按 0 到罐高判断，没有把 200mm 台架机械下限固化为软件硬限位；200mm 约束仍需要测试人员和现场工装共同保证。
