# CPU2 V1.36.2.0 液位标定AO归一化与近期资料收口改动与测试方案

## 1. 文档目的和适用版本

本文用于复核CPU2液位标定写入新罐高后，AO储罐液位源的高低端点仍可能保留旧量程的问题，并固化本次一并提交的近期正式文档、Office/PDF附件和硬件原理图资料边界。

- 修改前版本：CPU2 `V1.36.1.0`
- 修改后版本：CPU2 `V1.36.2.0`
- CPU3版本：保持`V1.36.0.0`
- CPU2/CPU3共享协议：`DEVICE_PROTOCOL_VERSION = 31`，不变
- CPU2参数存储：`DEVICE_PARAM_VERSION = 3`，不变

## 2. 协议与参数存储兼容性

- 不新增、删除或移动CPU2/CPU3共享寄存器，不改变字段宽度、字序、缩放、命令值、状态值或双方消费语义；CPU3无需升版。
- `DeviceParameters`结构大小、字段偏移、`struct_size`、magic、CRC范围、FRAM A/B地址和单槽容量均不变。
- 升级不会因版本变化恢复出厂或清除现场参数；如果FRAM原本存在CRC错误或双槽损坏，仍按既有异常路径处理。
- 本次只在罐高提交后复用已有AO归一化函数，将储罐液位源端点约束到新动态上限；AO寄存器地址、单位、默认值和持久化格式不变。

## 4. 详细改动

### 4.1 液位标定提交新罐高后归一化AO端点

- 源码位置：`LTD_MAIN_CPU2/Application/Src/measure_oilLevel.c`的`CorrectOilLevelProcess()`；调用现有`normalize_ao_params_after_write()`。
- 调用链：液位标定完成 -> 校验并写入`g_deviceParams.tankHeight` -> AO端点归一化 -> 清理未变化命令参数 -> 刷新当前位置。
- 改前问题：液位标定改变罐高后，没有在同一提交点刷新AO动态范围。储罐液位源的历史高低端点可能超过新罐高，导致后续参数写严格校验失败，或继续按不再适用的端点参与换算。
- 具体改法：罐高成功写入后立即调用已有AO归一化函数；返回值按现有接口丢弃，因为该函数直接把运行态参数收敛到合法范围，当前流程后续仍沿用既有保存和位置刷新边界。
- 必查边界：罐高增大、缩小、不变；AO禁用/启用；储罐液位、传感器位置、水位、固定和仿真来源；端点合法、超过新上限、上下限倒置；后续FC10同值写和无关参数写；FRAM保存失败与掉电恢复。
- 通过标准：新罐高写入后AO端点均满足当前动态范围；合法后续参数写不再被旧量程阻塞；其它AO来源和共享协议字段不发生变化。

### 4.2 正式文档、故障码与协议口径收口

- 改前问题：多轮已完成的协议、故障、参数、菜单、DSM分析和代码规模资料仍分散在工作区，当前版本口径停留在CPU2 V1.36.1.0。
- 具体改法：统一当前基线为CPU2 V1.36.2.0 / CPU3 V1.36.0.0 / 协议31；历史首发版本和历史故障页保持原值；正式Markdown、相关PDF、工作簿及README索引同步纳入。
- 必查边界：历史版本不得被批量改写；协议31首个正式组合仍为双端V1.36.0.0；V1.36.1.0 RSSI修复记录保持历史事实；静态资料不得写成台架或现场验证。
