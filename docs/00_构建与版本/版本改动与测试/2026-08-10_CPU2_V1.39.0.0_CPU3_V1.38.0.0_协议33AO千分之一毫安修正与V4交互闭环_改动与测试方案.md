# CPU2 V1.39.0.0 / CPU3 V1.38.0.0 协议33 AO千分之一毫安修正与V4交互闭环改动与测试方案

## 1. 文档目的与适用范围

本文用于复核和验证2026-08-10工作区中准备一次性提交的全部合规改动。固件主线为AO电流修正分辨率由`0.01 mA`提升到`0.001 mA`，并补齐多参数V4交互方式的业务读取闭环；同一提交还收口协议、菜单、版本、仓库治理、正式资料和硬件原理说明。

适用组合：

- CPU2：`V1.38.0.0 -> V1.39.0.0`。
- CPU3：`V1.37.0.0 -> V1.38.0.0`。
- CPU2/CPU3共享协议：`32 -> 33`。
- 本文件随本次提交纳入，提交哈希以Git记录为准。

## 2. 版本、协议与参数存储兼容性

| 项目 | 改前 | 改后 | 兼容结论 |
| --- | --- | --- | --- |
| CPU2固件 | V1.38.0.0 | V1.39.0.0 | AO最终输出链路和V4交互读取均改变，升MINOR |
| CPU3固件 | V1.37.0.0 | V1.38.0.0 | 共享倍率、菜单和LTD/LH映射改变，升MINOR |
| `DEVICE_PROTOCOL_VERSION` | 32 | 33 | AO修正、目标、实发值的线值倍率改变，双端必须严格相等 |
| CPU2 `DEVICE_PARAM_VERSION` | 3 | 3 | 结构大小、地址、元信息和CRC范围不变 |
| CPU3 `CPU3_PARAM_VERSION` | 0x0007 | 0x0007 | CPU3本机FRAM布局不变 |

参数存储迁移规则：

1. `DeviceParameters.ao_output.current_correction_mA_x1000`原位复用旧修正槽，字段仍为有符号32位，结构大小和偏移不变。
2. FRAM中`protocolVersion`为26～32时，旧值按`mA x100`解释并乘10迁移到`mA x1000`。例如旧值`-25`迁移为`-250`，物理含义仍是`-0.250 mA`。
3. 协议25及更早或版本未知时，该槽可能不是电流修正语义，迁移时归零，不推测旧含义。
4. 迁移或加载后若修正值不在`-1000～+1000`，归一化为默认值0。
5. 升级不会恢复出厂参数，不清除AO其它配置或其它现场参数。现场升级前仍建议导出参数快照，升级后核对AO修正、工作模式、输出源、固定电流、0%/100%端点和故障动作。
6. 降级到协议32及更早前必须把修正值换回旧倍率或归零；否则旧固件会把`1000`解释为`10.00 mA`并因越界归一化，不能保证保持原修正量。

## 4. 详细改动点

### 4.1 AO修正和最终目标统一为`mA x1000`

- 源码位置：`LTD_MAIN_CPU2/Services/AoOutput/ao_output.c`、`ao_output.h`的`AoOutput_ApplyCurrentCorrection()`、`AoOutput_UpdateInternal()`和`AoOutputRuntime`；链路为参数配置→基础电流→修正→硬件钳位→AD5421→共享运行态。
- 改前问题：修正值和最终目标以`0.01 mA`为最小线值单位，无法表达现场要求的`0.001 mA`修正步进。
- 具体改法：基础AO配置继续为`x100`，最终值按`base_mA_x100 * 10 + correction_mA_x1000`合成；目标、实发、写入尝试和恢复目标统一为`x1000`，物理钳位改为`3200～24000`。
- 必查边界：`-1000/0/+1000`修正、3.200/24.000 mA钳位、固定/过程/保持/故障/仿真来源、禁用态、重复目标刷新和失败重试。
- 通过标准：每个`0.001 mA`修正增量均能改变最终整数目标；禁用态始终为3.400 mA且不叠加修正；运行态和驱动接收同一目标。

### 4.2 AD5421整数DAC换算及初始化/恢复链路

- 源码位置：`LTD_MAIN_CPU2/BSP/Peripherals/src/ad5421.c`、`inc/ad5421.h`的`AD5421_SetCurrentX1000()`、`AD5421_InitCurrentX1000()`和`AD5421_RecoverCurrentX1000()`。
- 改前问题：旧`x100`接口转成float后换算DAC，既不能接收千分之一毫安目标，也可能在浮点舍入中吞掉最小修正步进。
- 具体改法：用`((offset_x1000 * 65535) + span/2) / span`执行64位整数四舍五入；3.2～24.0 mA对应DAC 0～65535；初始化和故障恢复复用同一`x1000`启动序列，旧`x100`接口乘10后转调。
- 必查边界：低于3.200、高于24.000、端点、相邻1 µA目标、乘法溢出、复位/控制寄存器回读/SPI/故障诊断失败。
- 通过标准：端点分别映射0和65535；所有合法输入不溢出；初始化、正常写入和恢复使用相同整数目标；旧接口行为保持原物理含义。

### 4.3 AO旧参数倍率迁移和加载归一化

- 源码位置：`LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.c`、`.h`的`migrate_ao_current_correction_scale_runtime()`和`normalize_ao_params_runtime()`。
- 改前问题：同一32位槽从`x100`变为`x1000`后，直接读取会把旧物理修正缩小10倍；更老协议中该槽含义不确定。
- 具体改法：协议26～32乘10，协议25及更早或未知版本归零，之后按`-1000～+1000`校验；默认值和参数打印同步为`0.001 mA`。
- 必查边界：旧值`-100/0/+100`、越界值、未知协议、已经是协议33、A/B分区加载和迁移后写回。
- 通过标准：协议26～32升级前后物理修正不变；更老或未知版本不误解释预留槽；其它参数字节不被清除。

### 4.4 协议33双端共享字段同步

- 源码位置：CPU2/CPU3 `stateformodbus.h`、`system_parameter.h`、双方`dataanalysis_modbus.c`和CPU3 `device_param_sync.c`。
- 改前问题：只修改CPU2内部单位会导致CPU3、LTD和外部主机仍按`x100`解释，显示和写入放大或缩小10倍。
- 具体改法：共享协议升33；AO修正操作号、保持寄存器别名、运行态目标/实发别名及结构成员统一命名为`X1000`，地址和字段宽度保持不变。
- 必查边界：协议32/33混搭、FC03/FC04读值、FC06/FC10写修正、负数二补码、快照未建立和CPU2断线。
- 通过标准：协议版本不相等时严格门禁；协议33组合读写同一32位原始值；无地址偏移或相邻字段错位。

### 4.5 CPU3菜单与AO运行页三位小数

- 源码位置：`LTD_DISPLAY_CPU3/Application/display/display_tankopera.c`、`.h`和`system_parameter.c`参数元数据。
- 改前问题：菜单步进、范围和运行页只显示两位小数，无法录入或观察`0.001 mA`修正。
- 具体改法：电流修正菜单单位倍率改为3位小数、范围`-1.000～+1.000 mA`；运行页最近实发值用`%lu.%03lu mA`显示。
- 必查边界：负值、零、正值、三位小数补零、最大字符长度、N/A、通信断线、非法来源。
- 通过标准：`-1`显示/编辑为`-0.001 mA`，`1000`为`1.000 mA`，运行值`3400`显示`3.400 mA`，无乱码或越界覆盖。

### 4.6 LTD与LH外部协议倍率同步

- 源码位置：CPU3 `lh_modbus_slave.c`、`lh_register_map.h`及LTD共享Modbus资料。
- 改前问题：LH `0x0018～0x0019`和LTD共享参数若仍按`x100`解释，会与CPU2协议33不一致。
- 具体改法：地址不变，将修正字段口径改为有符号`mA x1000`并按`-1000～+1000`校验；同步协议卷、全量寄存器表和LH手册。
- 必查边界：FC03读取、FC10写入、`0xFFFFFC18`（-1000）、`0x000003E8`（+1000）、越界拒绝、协议不匹配和断线忙异常。
- 通过标准：合法端点读写一致，越界写不进入CPU2参数，地址`0x001A`后的固定电流等字段保持原倍率和位置。

### 4.7 V4交互方式R02状态核对与核心测量

- 源码位置：`multiparam_v4_communication.c/.h`的`MULTIPARAM_V4_ReadOperatingState()`，`multiparam_v4_measurement.c/.h`的交互密度、液位、水电容和姿态读取函数。
- 改前问题：交互方式仍绕过或零散复用主动快照逻辑，读取R04等核心值前没有统一核对R02模式和异常位，可能把错误模式或异常测量解释为有效值。
- 具体改法：统一解码R02的测量模式、功能状态和异常位；密度读取R04/R07/R06，液位读取R04，水电容读取R05，姿态读取R11/R12，并更新相应运行测量快照。
- 必查边界：密度/液位模式不符、R02非法枚举、水位/姿态异常位、通信超时、状态切换、NaN/Inf、负频率和超范围值。
- 通过标准：模式或异常位不满足时返回明确错误且不发布无效结果；合法交互值进入与主动方式相同的业务消费路径。

### 4.8 V4主动快照边界与公共入口收敛

- 源码位置：`multiparam_v4_measurement.c`主动读取分支及`Services/Sensor/sensor.c`的`Sensor_ReadLevelFrequency()`、`Read_Density()`、`Sensor_ReadWaterCapacitance()`、`Sensor_ReadGyroAngle()`。
- 改前问题：主动快照缺少部分频率、密度、温度范围复核；公共入口重复判断通信方式，容易使主动/交互路径行为分叉。
- 具体改法：主动密度快照增加有限值和上下限检查；公共传感器入口只识别类型15并转调V4测量层，由测量层选择主动或交互方式。
- 必查边界：主动帧陈旧、范围端点、通信方式切换、命令切换、非V4传感器和空输出指针。
- 通过标准：主动和交互方式共享一致的业务错误出口；越界快照不被发布；V3/DSM等其它传感器路径不变。

### 4.9 V4交互附加调试结果节流刷新

- 源码位置：`MULTIPARAM_V4_MeasurementRefreshInteractiveDebugData()`和`MULTIPARAM_V4_ReadFloatParamOnce()`。
- 改前问题：协议32已向CPU3/LTD暴露磁零点电压、动力黏度、运动黏度和供电电压，但交互方式没有稳定刷新这四项。
- 具体改法：仅在类型15且参数65为交互方式时，每500 ms最多读取一次R03/R08/R09/R10；逐项成功即更新对应值，记录首个失败，状态切换立即退出。
- 必查边界：500 ms边界、部分成功、首项失败后后项成功、`STATE_SWITCH`、主动方式和非V4类型。
- 通过标准：交互方式四项结果可持续刷新；单项失败不擦除其它成功结果；主动方式不额外发交互查询。

## 5. 跨CPU数据流与异常闭环

AO链路：

`CPU3/LTD/LH写入x1000修正 -> CPU2 Holding参数镜像 -> FRAM原槽保存 -> AO基础x100电流乘10 -> 叠加有符号x1000修正 -> 3.200～24.000 mA钳位 -> AD5421整数DAC -> CPU2 x1000运行态 -> CPU3/LTD三位小数显示`

V4交互链路：

`业务测量入口 -> V4测量层识别交互方式 -> R02模式/异常位 -> R04等核心参数 -> 有限值/范围检查 -> 业务测量快照 -> 500 ms节流读取R03/R08/R09/R10 -> CPU2调试Input -> CPU3原子快照 -> LTD FC04`

异常出口：协议不匹配或快照不新鲜时CPU3/LTD返回忙/不可用；V4状态切换返回`STATE_SWITCH`；通信错误保留具体错误码；越界或非有限值不发布；AD5421写入/诊断错误进入既有恢复链路并保留`x1000`恢复目标。
