## 3. 详细改动点

### 3.1 多参数V3/V4识别路由

- 公共识别入口先读取R01版本，根据返回的代际选择后续寄存器，不再用错误寄存器判断类型。
- R01为V3时读取R22物理编号；R01为V4时读取R67物理编号。
- V3和V4只有在通信成功且识别号大于0时才确认传感器类型；0或负值不能作为有效身份。
- DSM继续使用既有CN编号识别，但同样要求编号为正值，避免“通信返回成功但身份无效”被误判为已识别。

### 3.2 主动V4识别期间的临时交互方式

- 已处于主动方式的V4传感器在身份读取前临时进入交互方式，以便执行R01/R67查询。
- 无论识别成功、身份无效或后续查询失败，退出识别分支前都应尝试恢复主动方式。
- 恢复失败必须保留为可观测错误，不得把传感器留在交互方式后仍宣称主动识别完成。
- 普通`DetectSensorType()`只负责普通V3/V4/DSM识别，不发送安全协议HELLO；安全HELLO、配置摘要、身份和新鲜度确认由独立安全测量流程完成。

### 3.3 故障名称同步

- 同步修正49项故障名称，覆盖CPU2 `ErrorCodeString()`日志、CPU3 OLED故障显示、当前故障代码清单和`LTD故障代码统一表.xlsx`。
- 故障码数值、类别、屏幕编号和使用状态不改变；协议30新增6个23类故障，协议31～33未改变这些故障码的数值或解释。
- CPU3本机`20-7`和`20-13`继续由CPU3本机定义，不改变CPU2共享枚举。

### 3.4 本机同步但不提交：任务上下文快照脚本

- 移除误插入的文件元数据块及反引号，避免脚本出现语法错误、无效转义告警和无法执行。
