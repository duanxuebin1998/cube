## 3. 详细改动

### 3.1 固化继电器报警配置的一字节对齐

- 源码位置：`LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.h` 的 `RelayAlarmConfig`；数据链路为 `DeviceParameters.relayAlarm -> relay_output.c 配置快照 -> 报警计算`。
- 改前问题：父结构使用一字节打包，但 `RelayAlarmConfig` 类型自身仍按自然对齐声明。编译器在通过该类型访问嵌套成员时可能假定四字节对齐，Release 优化下读取非对齐浮点原始位存在生成不安全装载指令并触发 HardFault 的风险。
- 具体改法：在 `RelayAlarmConfig` 定义外单独使用 `#pragma pack(push, 1)` 与 `#pragma pack(pop)`，使类型本身的对齐要求固定为 1，同时不改变 13 个 `uint32_t` 字段的顺序和大小。
- 必查边界：两个继电器通道、首末字段、零值与 IEEE754 浮点原始位、CPU2 Debug/Release 编译、旧 FRAM 数据读取、结构嵌套和数组步长。
- 通过标准：`sizeof(RelayAlarmConfig)=52`、`_Alignof(RelayAlarmConfig)=1`；ARM 固件可编译，旧参数位置和值不变，目标板读取配置时不再依赖四字节对齐假设。

### 3.2 增加持久化布局编译期门禁

- 源码位置：同一头文件中 `DeviceParameters` 定义后的 `_Static_assert`。
- 改前问题：继电器子结构的大小、对齐、父结构偏移和总大小缺少就地约束，后续修改可能在代码评审时漏掉持久化兼容性变化。
- 具体改法：增加 52 字节大小和 1 字节对齐断言；在 ARM/Thumb 构建中增加 `relayAlarm` 偏移 458 和父结构总大小 682 的断言。
- 必查边界：主机 ABI 与 ARM ABI 不同，因此父结构偏移和总大小只在固件目标宏下断言；子结构大小和对齐在全部编译环境检查。
- 通过标准：当前 ARM 工具链通过全部断言；任一受保护值变化时编译直接失败，要求开发者先评估协议和参数存储版本。
