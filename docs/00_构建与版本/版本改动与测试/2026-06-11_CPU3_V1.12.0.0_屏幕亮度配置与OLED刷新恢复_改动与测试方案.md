# CPU3 V1.12.0.0 屏幕亮度配置与 OLED 刷新恢复改动与测试方案

日期：2026-06-11

## 1. 版本

- CPU2：保持 V1.13.0.1
- CPU3：V1.11.2.0 -> V1.12.0.0

## 2. 兼容性

- `DEVICE_PROTOCOL_VERSION` 保持 7。
- 不改变 CPU2/CPU3 共享命令码、状态码、输入寄存器、CPU2 设备参数字段或 CPU2 `DeviceParameters` 结构。
- CPU2 `DEVICE_PARAM_VERSION` 保持 3，从 CPU2 V1.13.0.1 升级时不会因本次 CPU3 改动触发 CPU2 参数恢复出厂。
- CPU3 本地显示/通信参数结构新增屏幕亮度字段，`CPU3_PARAM_VERSION` 从 `0x0003` 升至 `0x0004`。
- 从 CPU3 本地参数 V3 升级时，保留原有液位、水位、密度、温度、COM 和显示配置，把屏幕亮度补为默认“中低”挡并写回 V4。
- CPU3 本地参数魔术字异常、版本既不是 V3 也不是 V4、或存储读取失败时，按默认显示/通信参数重建并写回。
- 新增 `HOLDREGISTER_CPU3_BRIGHTNESS` 使用 CPU3 本地保持寄存器预留地址 `CPU3_BASE + 0x1C`，不占用新的 CPU2/CPU3 共享协议字段。

## 3. 改动内容

### 3.1 屏幕亮度配置

- 在 `显示设置 -> 显示基础` 中新增“屏幕亮度”菜单项。
- 亮度支持五挡：`低`、`中低`、`中`、`中高`、`高`。
- 默认值为 `中低`，对应旧版固定 OLED 对比度，尽量保持升级后的观感不突变。
- 菜单保存后立即调用 OLED 亮度接口应用到当前屏幕。
- CPU3 本地保持寄存器新增亮度字段，便于调试或工具读取当前配置。

### 3.2 OLED 初始化和恢复

- OLED 初始化命令集中维护，避免初始化流程里重复散落关键寄存器配置。
- OLED 对比度通过统一接口写入 SSD1325 `0x81` 命令，初始化、清屏恢复、屏幕重开和静电花屏恢复都使用当前配置值。
- 清屏恢复流程不再固定写死亮度，避免用户调暗或调亮后恢复动作把亮度打回旧值。
- 恢复当前页面时优先走主循环刷新路径，减少恢复时页面状态和 OLED 写屏时序互相覆盖。

### 3.3 刷新边界和状态页显示

- 中断里只设置刷新请求，不直接执行 OLED 绘制。
- 主循环统一消费刷新请求并执行实际页面绘制，降低 SPI 写屏占用中断和页面变量竞争风险。
- 状态页从菜单、配置页等非状态页面返回时强制全屏重绘，避免局部刷新只覆盖数值区导致页面标题、单位或旧字符残留。
- 状态页正常数据刷新时只刷新变化区域，减少整页擦除造成的一闪一闪。
- 数据变化后，变化值和单位反显高亮 0.5 秒；高亮到期后自动请求一次局部刷新恢复普通显示。

### 3.4 屏幕健康诊断资料

- OLED 驱动增加影子缓冲、刷新序号和 SPI 错误计数，作为后续识别花屏、总线异常和恢复效果的基础。
- CPU3 屏幕驱动与刷新问题分析文档补充静电花屏后的恢复策略、软件一致性校验思路和实物排查建议。
- 新增 OLED 刷新中断边界和亮度配置检查脚本，提交前可自动检查关键约束是否被破坏。

## 4. 影响范围

- 影响 CPU3 OLED 初始化、亮度配置、静电恢复、菜单刷新、状态页刷新和状态页数据变化提示。
- 影响 CPU3 本地 FRAM 中显示/通信参数结构和版本号。
- 不影响 CPU2 运动控制、液位/水位算法、CPU2 参数存储、外部协议地址或 CPU2/CPU3 共享协议版本。
- 外部或调试工具如果直接读取 CPU3 本地保持寄存器，可读取新增亮度字段；既有字段地址不变。

## 5. 重点测试

| 测试项 | 步骤 | 预期结果 |
| --- | --- | --- |
| 亮度菜单 | 进入 `显示设置 -> 显示基础 -> 屏幕亮度`，依次选择五个挡位并保存 | 屏幕亮度立即变化，重启后保持上次保存值 |
| V3 参数升级 | 使用旧版 CPU3 本地参数存储后升级到 V1.12.0.0 | 旧显示/通信配置保留，亮度补默认“中低”，FRAM 写回 V4 |
| 默认参数重建 | 模拟 CPU3 本地参数魔术字或版本异常 | CPU3 使用默认显示/通信配置启动，亮度为“中低” |
| OLED 初始化 | 上电、屏幕重开、执行清屏恢复 | OLED 对比度均使用当前亮度配置，不回退到固定值 |
| 菜单返回状态页 | 从菜单或配置页返回状态页 | 状态页先全屏重绘，不出现乱码、旧字符或单位残留 |
| 状态页局部刷新 | CPU2 数据持续刷新但页面不切换 | 只刷新变化值区域，整页闪烁明显减少 |
| 数据变化高亮 | 让液位、水位、密度、温度等状态值发生变化 | 变化值和单位反显约 0.5 秒后恢复普通显示 |
| 静电花屏恢复 | 触发屏幕恢复入口或模拟恢复请求 | 当前页面重新绘制，亮度配置不丢失 |

## 7. 实物回归范围

- 状态页长时间刷新观察：液位、水位、密度、温度、位置、扭力等字段变化时不整页频繁闪烁。
- 菜单进入和退出观察：菜单页、编辑页、状态页之间切换不残留旧文字。
- 静电干扰后观察：花屏后执行恢复动作，确认恢复到当前页面且亮度不丢失。
- 不同亮度挡位在现场光照下观察：最低挡仍可读，最高挡不过亮且不会明显加剧残影。
- 断电重启观察：亮度配置可持久化，旧配置升级后不丢失 COM 和显示相关设置。

## 8. 未验证风险

- 影子缓冲和刷新序号只能辅助软件侧一致性检查，无法直接证明 OLED 玻璃实际像素完全正确；真正花屏识别仍需结合硬件读回能力、外部采样或恢复策略验证。
- 数据变化高亮依赖 `HAL_GetTick()` 计时，实物上需确认 0.5 秒提示既明显又不会影响用户读数。
- 静电花屏根因仍偏硬件抗扰和屏幕模组状态保持能力，软件恢复可以降低现场影响，但不能替代 ESD、防护、接地和排线可靠性整改。
