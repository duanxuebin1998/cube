# 2026-06-04 CPU2 V1.11.0.0 BE 编码器速度 m/min、加速度倍率与连续换向重启改动与测试方案

## 版本变化

- CPU2：`V1.10.0.0 -> V1.11.0.0`
- CPU3：未变化，保持 `V1.9.0.0`
- `DEVICE_PROTOCOL_VERSION`：不变，保持 `6u`

## 协议版本/兼容性

- 本次调整 CPU2 串口 `BE<mm>` 编码器闭环往返调试流程，并同步调整普通运动入口和自动恢复中的 TMC5130 掉电/复位重初始化逻辑。
- 不修改 CPU2/CPU3 共享命令、共享状态、共享参数语义、寄存器映射、参数存储布局或外部协议地址。
- 旧命令 `BE<mm>`、`BE<mm>S`、`BE<mm>,1` 保持兼容，其中 `BE<mm>,1` 仍表示开启运动中传感器通信。
- 新增参数：`BE<mm>,<速度m/min>,<加速度倍率>`。
- 速度单位为 `m/min`，解析后转成 `0.01m/min`，再复用既有 `MotorDriver_ComputeUniformVelocityFromLength()` 换算 TMC5130 `VMAX`；速度 `0` 或省略时沿用当前速度配置。`0` 或非法加速度倍率按 `1` 处理，加速度倍率按 `1~20` 限幅。
- 开启运动中传感器通信可继续使用 `S`，也可在速度/加速度后追加第三个 `,1`，例如 `BE50,1.5,3,1`。若需要 1.00m/min，请使用带加速度参数的 `BE50,1.0,1` 或 `BE50,1,3`，避免和旧式 `BE50,1` 兼容写法冲突。

## 问题现象和日志结论

- 现场日志 `G:\SAVE2026_06_04_8-54-35.DAT` 中，`BE300` 的下行目标为约 `300.01mm`，但多轮在约 `271mm` 先打印 `保护行程停稳`。
- `BE150` 长时间运行时，上行回原点偏差逐轮变大，后段已增长到约 `83.33mm`。
- 现场要求改为类似点动的长距离连续运行：到编码器目标只打印位置并立即反向，不在到位点减速停机；异常或超时不退出测试，而是在固定区间内重启当前阶段。

## 本次修改

- `BE` 下行使用 `TMC5130_MODE_VELPOS`，上行使用 `TMC5130_MODE_VELNEG`，直接进入速度模式连续运行。
- 到编码器目标后打印 `编码器到位换向`，输出当前位置、目标和偏差；不写 `VMAX=0`，不等待停稳，上层立即下发下一段反向运动。
- 新增速度 m/min 参数：非 0 时按线速度设置临时换算 `VMAX`，为 `0` 时沿用当前速度配置，限幅范围复用既有 `MOTOR_LINEAR_SPEED_MIN_X100`/`MOTOR_LINEAR_SPEED_MAX_X100`。
- 新增加速度倍率：进入 BE 时读取当前 `A1/AMAX/D1/DMAX` 作为 1 档，按倍率临时写入，命令切换退出时恢复。
- 命令切换退出时，命令切换检查先等待电机停稳并对齐 `XTARGET=XACTUAL`、切回 `TMC5130_MODE_POSITION`；退出恢复阶段调用 `MotorCtrl_Init()` 重新初始化电机配置，初始化成功后恢复进入 BE 前的斜坡参数。
- `MotorCtrl_Init()` 非首次初始化也完整重写 TMC5130 寄存器；非首次不恢复 FRAM 中的 `XACTUAL/XTARGET`，也不恢复位置源，由 `stpr_initStepper()` 重建默认位置寄存器。
- 运行期 TMC5130 掉电/复位只让当前初始化有效性失效，不清掉已初始化标志；后续自动恢复或 BE 重启仍按非首次初始化刷新配置，避免误恢复 FRAM 位置和位置源。
- 运行过程中 TMC5130 掉电/复位导致驱动初始化状态失效后，下一次运动入口先尝试 `MotorCtrl_Init()` 自动重新初始化；初始化成功后继续原业务重试，避免后续运动直接报 `电机被禁止`。
- 自动恢复轮询除检查保存的错误码外，也检查当前驱动初始化/上电安全状态；驱动状态失效时先 `MotorCtrl_Init()`，错误态停机不再反复慢停已经失效的驱动。
- `MotorCtrl_Init()` 初始化期等待 `DRV_STATUS.CS_ACTUAL` 实际电流建立；刚恢复 24V 时不会因单次 `CS_ACTUAL=0` 立刻失败。
- 回零点粗找/精找遇到电机驱动类错误时，直接退出本轮命令交给自动恢复，不再在回零内部继续下发退让运动。
- 传感器通信从下行后/上行后的停机点读取，改为运动中按周期读取；通信异常只打印，不改变 BE 流程。
- 初始 `origin_encoder` 和 `down_target_encoder` 固定，后续往返、超时和重启都不重新计算区间。
- 单段按距离和有效线速度估算超时时间；超时未到目标时打印 `到位超时重启`，先初始化电机并重新应用 BE 加速度倍率，再重新下发当前方向。
- 如果启动宽限时间后检测到提前停稳但编码器未到目标，打印 `提前停稳重启`，先初始化电机并重新应用 BE 加速度倍率，再继续重试。

## 影响范围

- 影响 CPU2 串口 `BE` 编码器往返诊断，以及普通电机运动入口在 TMC5130 掉电/复位后的自动重新初始化行为。
- 不影响 CPU3 显示协议、Modbus 寄存器映射和外部协议地址。
- `B` 调试运动仍保持位置模式下行/回零逻辑。

## 测试点

### 1. 旧命令兼容

步骤：
1. 分别下发 `BE50`、`BE50S`、`BE50,1`。
2. 观察开始日志中的速度、速度x100、加速度倍率和运动中传感器通信标志。

预期结果：
- `BE50` 使用当前速度配置换算值，命令参数速度x100 为 `0`，加速度倍率 `1`，不开启传感器通信。
- `BE50S` 和 `BE50,1` 开启运动中传感器通信。

通过标准：
- 旧命令仍可进入连续往返。
- 不出现参数解析错误。

### 2. 速度 m/min 和加速度倍率

步骤：
1. 下发 `BE50,1.5,3`。
2. 观察 `串口B指令` 和 `BE编码器测试` 开始日志。
3. 检查 `加速度设置` 中 `A1/AMAX/D1/DMAX` 是否按 3 倍写入或被上限截断。

预期结果：
- 串口命令日志打印 `速度=1.50m/min`、`速度x100=150`。
- BE 开始日志打印有效线速度，并按该速度通过现有换算函数写入 `TMC5130_VMAX`。
- 加速度倍率打印为 `3`。
- 到位后打印 `编码器到位换向`，随后立即进入反向阶段。

通过标准：
- 不打印 `停稳结果`。
- 不在到位点等待停稳。

### 3. 运动中传感器通信

步骤：
1. 下发 `BE150,0,1,1` 或 `BE150,0,1S`。
2. 观察传感器日志出现的时机。

预期结果：
- 传感器读取发生在 `BE下行` 或 `BE上行` 运动过程中。
- 不再只在 `BE下行后` 或 `BE上行后` 读取。

通过标准：
- 传感器通信异常只打印，不退出 BE。

### 4. 固定区间连续往返

步骤：
1. 下发 `BE150,0,1`。
2. 连续运行不少于 1000 轮或现场允许的等效时长。
3. 对比前 10 轮、中间轮次和后 10 轮的固定原点、固定下行目标和往返当前值。

预期结果：
- 固定原点和固定下行目标不变化。
- 到位后立即换向。
- 上行回原点偏差不再持续向同一方向累积。

通过标准：
- 区间上下限稳定。
- 不因提前停稳或超时改变目标区间。

### 5. 超时和提前停稳重启

步骤：
1. 使用现场可控方式制造编码器目标迟迟不到或电机提前停稳。
2. 观察 `到位超时重启` 或 `提前停稳重启` 日志。

预期结果：
- 当前阶段先完成 `MotorCtrl_Init()` 和 BE 加速度倍率重写，再重新下发同一方向速度运动。
- 固定原点和固定目标保持不变。
- BE 不因该异常退出。

通过标准：
- 只在命令切换时退出 BE。
- 异常重启后仍继续追同一个编码器目标，固定原点和固定目标不重新计算。

### 6. 命令切换退出

步骤：
1. 运行 `BE150,1.5,3`。
2. 在下行或上行阶段下发新串口命令，例如 `A+300`。

预期结果：
- 打印 `A/B/BE检测到命令切换请求`。
- 当前 BE 测试退出，并恢复进入 BE 前的加速度寄存器。
- 退出恢复日志打印 `电机已重新初始化` 和 `模式=位置模式`。
- 初始化完成后打印 `BE加速度已恢复`，恢复进入 BE 前的 `A1/AMAX/D1/DMAX`。
- 后续新命令可继续执行。

通过标准：
- 命令切换无卡死、无错误状态泄漏。
- 下一条位置模式运动不会沿用 BE 的速度模式。
- `I` 回零命令能在 BE 退出后继续进入 `执行回零点指令` 和 `零点测量    开始`。
- `电机初始化完成 | 方式=刷新配置` 后，TMC5130 已重新写入整套寄存器，FRAM 持久化位置和位置源不会在非首次初始化中恢复。

### 7. 运行中电机断电恢复

步骤：
1. 执行 `I` 回零点或其它带业务重试的测量流程。
2. 在电机运动过程中断开 TMC5130/电机 24V，再恢复供电。
3. 观察首次故障后的下一次业务重试日志。

预期结果：
- 运行期能打印 TMC5130 复位或通信异常。
- 下一次运动入口打印 `电机运动准备 | 驱动未初始化或安全停机状态失效，尝试重新初始化`。
- 自动恢复轮询如果读到驱动初始化状态失效，也会先执行 `MotorCtrl_Init()`，不会只持续打印 `停止电机 | 电机被禁止`。
- 运行期重新初始化走 `刷新配置` 分支，不恢复 FRAM 持久化位置和位置源。
- 如果 TMC5130 reset 已清除但 `CS_ACTUAL=0`，初始化期打印 `TMC5130初始化等待电流建立` 并等待实际电流建立。
- 回零点粗找/精找遇到电机驱动类错误时，打印 `退出本轮命令等待自动恢复`，不继续执行退让运动。
- 重新初始化成功后继续原业务重试，不再直接卡在 `电机被禁止`。

通过标准：
- 24V 恢复后可通过自动 `MotorCtrl_Init()` 重新下发 TMC5130 配置。
- 故障恢复等待期间不会持续刷 `错误报警 | 模块：电机 | 操作：停止电机 | 原因：电机被禁止`。
- 24V 刚恢复时允许短暂等待电流建立，超过等待窗口才继续按 `MOTOR_DISABLED` 进入恢复等待。
- 若 24V 尚未恢复，初始化失败返回真实错误码，流程仍按原错误重试或最终报错处理。
