## 3. 逐项改动和通过标准

### B1. 固定基准与位置窗口

- 源码：`measure_tank_height.c`的`Bottom_PrepareWeightSearchWindow`、`check_bottom_status`及`SearchBottom`。
- 改前：任意位置越过固定绝对重量可能误判，噪声可能掩盖真正触底。
- 改法：预计底部前300mm建窗口；入口使用已有低通stable_weight冻结基准。当前值<=基准-减重量才为候选；首次建基准返回正常。入口当前值>500、候选下限>500且当前值>候选下限，否则失败。粗找及两次精找共用基准；可选回零后、首次上提前准备配置。
- 必查：阈值0、INT32_MAX、当前值500/501、入口已卸载、窗口前后、历史底部有效/无效、重入时清旧状态。
- 通过：窗口外不发布候选，异常入口不启动下行，不把入口卸载误记为成功。

### B2. 分段减速与释放距离

- 源码：`Bottom_ApplyWeightApproachSpeedLimit`、`Bottom_ReleaseWeightCandidate`、`SearchBottomRough/Precise`。
- 改前：过早长距离低速，且按制动后位置记录或固定上提不能可靠离底。
- 改法：300mm内0.50m/min、30mm内0.10m/min；精找以此前触发位置作参考。触发立即记录制动前尺带位置，释放上提补偿实际过行程并额外200mm，允许单侧5mm短行程，不补额外微动。
- 必查：300/30mm边界、长制动过行程、上提不足/超过、最大下行边界、命令取消、丢步。机械刹车性能不能由模拟验证。
- 通过：长距离保持原正常速度，触发位置不含刹车过行程，释放目标与触发位置对应。

### B3. 新帧恢复与重复定位

- 源码：`Weight_MarkFrameReceived/GetFrameSequence`、`Bottom_WaitForWeightRecovery`、`SearchBottom`。
- 改前：上提后可能拿到触底旧缓存，引起12-3或放行假恢复。
- 改法：上提后记序号，每20ms检查，1000ms内新有效帧需同时高于500和候选下限。新低值继续等，旧高值也不能放行；两次精找位置相差<=10mm才取平均作为结果。
- 必查：新旧高低帧、持续低值、断联、真实故障、取消、序号及tick回绕、两次位置差10/10.1mm。
- 通过：旧缓存不决定恢复；超时按真实通信/释放错误返回，不继续精找；超差不发布底部有效。

### B4. 通用下行保护与错误优先级

- 源码：`CheckWeightCollision`、`FrequencyLevel_CheckMotionGuards`、`CMD_MeasureBottom`。
- 改前：普通运动复用探底绝对阈值；改为减重量后该比较失去意义；重试或参考罐高兜底可能吞掉真实故障。
- 改法：通用下行当前值<=500或相对变轻>full_weight*lower_ratio/100触发碰撞。通信先检查，仍保留忽略区与停止态，上行规则不变。专用探底先候选后通用碰撞。仅未找到罐底业务错误允许原重试；真实故障不得兜底，参考值兜底时bottom_reference_valid=0。
- 必查：501/500/499/0/负数、当前等于稳定值、相对阈值等于/超过、忽略区临界、停机/上提、通信与低重量同时发生、候选与低重量同时发生。
- 通过：持续低重量即使相对变化为0也报碰撞；通信错误优先；合法触底候选不被提前改为普通碰撞；停止后由调用方执行原故障处理。

### B5. 编码器修正与SI首点

- 源码：`ApplyBottomEncoderCorrection`和`measure_density_si.c`中的`SiProfile_ResolveReleasedPoint0FromCable/SelectPoint0Position/BuildPoints`。
- 改前：修正坐标后底部参考或SI释放偏移不一致；默认100mm首点可能不高于新200mm释放位置。
- 改法：修正同步底部尺带参考；称重释放200mm、陀螺100mm，实际释放位置为Point0。40001必须高于Point0且不超罐高，非法计划置点数0并返回MEASUREMENT_DENSITY_PLAN_INVALID。
- 必查：首次探底、已有参考、清参考重探、修正开关、SI首点等于/低于Point0、超高、无效罐高、取消和陀螺回归。
- 通过：坐标一致，不静默更改PLC首点，非法计划不进入下行测量。

### B6. 参数、协议与界面

- 源码：双端`system_parameter.c/h`、CPU3`display_tankopera.h`、CPU2`hostcommu_modbus.c`。
- 改前：既有参数为绝对重量，不能在双板混配时按同一数值解释。
- 改法：名称“探底扭力阈值”及短名“扭力阈值”不变，0x0216改为减重量；双端协议37，FC10超过INT32_MAX返回03，忙时仍06；0x0908预留不可写，参数存储布局不变。
- 必查：FC10起始0x0216/数量2，数据0、500、0x7FFFFFFF、0x80000000；半字段写、0x0908写、重启读回、36/37混配、菜单与ACK。
- 通过：合法整字段写保留原ACK及保存机制，非法值返回03且不覆盖；忙态返回06；混配不执行命令。主机测试只覆盖真实声明与权限帮助函数，不证明真实总线FC10或FRAM。

## 4. 数据流和可执行测试

CPU3菜单或外部LTD写原0x0216 -> CPU2值域/忙态校验 -> 现有保存和镜像 -> 探底窗口冻结基准 -> 粗候选快停 -> 上提及新帧恢复 -> 两次精找 -> 位置一致性 -> 编码器修正和罐高/有效位 -> CPU3显示或SI Point0消费。取消和真实通信/运动错误沿原链退出，不得改成参考值成功。

台架前置：两块板配套版本，备份参数；称重模式、可靠零点/罐高和安全最大下行范围；可调悬挂负载、可控触底平面、急停与独立位移记录；日志同步记录当前/稳定称重、帧号、尺带长度、速度、触发/停机/释放位置及故障码。先空载限行程验证保护，后扩大测试，不从构建通过直接进入无人值守运行。

开放问题及未验证项：

1. 固定频率入口`FrequencyLevel_ValidateParameters`仍比较`bottom_weight_threshold`与绝对`zero_weight_limit`，与减重量新含义不一致。本次按此前决定保留，不把它描述为已解决。可能拒绝某些减重量配置，发布到使用定频方式的设备前需要独立确认并处理。
