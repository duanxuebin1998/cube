# CPU3 V1.45.0.0 设备状态页俄文显示改动与测试方案

## 1. 文档目的和适用版本

本方案对应 MAIN 分支的 CPU3 `V1.45.0.0` 固件，CPU2 配套版本保持 `V1.45.1.0`。目标是在 CPU3 设备状态页增加可持久化的俄文显示，同时保持配置菜单和调试页面的现有中英文布局，避免因 OLED 宽度限制使用含义不清的俄文缩写。

本次只改变 CPU3 显示、语言参数和本机 FRAM 存储版本，不改变 CPU2 程序、CPU2/CPU3 共享寄存器、共享命令、共享状态、错误码数值或外部协议帧格式。

## 2. 版本、协议和参数存储兼容性

| 项目 | 改前 | 改后 | 说明 |
| --- | --- | --- | --- |
| CPU2 程序 | `V1.45.1.0` | `V1.45.1.0` | 本次不修改 CPU2 |
| CPU3 程序 | `V1.44.0.0` | `V1.45.0.0` | 新增语言能力，MINOR 升版 |
| 共享协议 | `DEVICE_PROTOCOL_VERSION=38` | `38` | 共享地址、宽度、命令、状态和语义不变 |
| CPU2 参数存储 | `DEVICE_PARAM_VERSION=3` | `3` | 结构、CRC 和 FRAM 布局不变 |
| CPU3 本机参数存储 | `CPU3_PARAM_VERSION=0x0007` | `0x0008` | 参数负载布局不变；新增语言编号由存储版本隔离 |
| CPU3 本机语言参数 | `0=中文，1=英文` | `0=中文，1=英文，2=俄文` | 地址仍为本机 Holding `0x7002` |

`0x7002` 只属于 CPU3 本机参数区，不进入 CPU2/CPU3 共享契约，因此共享协议保持 38。V7 镜像升级到 V8 时保留合法的显示、SI、COM1/COM2/COM3 和六个兼容槽参数，将本机版本字段更新为当前 CPU3 版本；非法语言值回退英文，非法 COM 协议、波特率、数据位、校验位或停止位按对应协议 profile 修正。原中文和英文编号不变。

降级限制：V8 固件写入本机 FRAM 后，回退到只识别 V7 的旧 CPU3 固件会把该镜像判为未知版本并恢复 CPU3 本机默认参数。降级前必须记录本机显示、SI 和三路串口设置，回退后重新核对或下发。

## 4. 详细改动清单

### 4.1 统一语言编号和页面文本域

- **源码位置**：`Application/display/display_language.h/.c` 的 `LANGUAGE_TYPE`、`DisplayLanguage_Normalize()`、`DisplayLanguage_Resolve()`、`DisplayLanguage_GetLegacyColumn()` 和两个文本选择接口；`display_tankopera.c` 的 `setlanguage()`、`set_display_language()`；`system_parameter.c` 的 `COM_NUM_PARA_LANG` 元数据。调用链为“FRAM/菜单或寄存器值 -> 统一归一化 -> 按文本域选择语言 -> 页面绘制”。
- **改前问题**：语言值实际被多处当作中英二维数组下标；若只把语言值扩展为 2，普通菜单会越界或出现中、英、俄混排，也没有为后续语言保留统一入口。
- **具体改法**：固定 `0=中文、1=英文、2=俄文`，增加 `LANGUAGE_COUNT`；非法原始值统一回退英文。普通页面解析为 `DISPLAY_TEXT_DOMAIN_LEGACY`，所有非中文语言使用英文列；设备状态页解析为 `DISPLAY_TEXT_DOMAIN_STATUS`，可选中、英、俄三套文字。Language 菜单新增 `Russian`，合法上限统一使用 `LANGUAGE_COUNT-1`。
- **必查边界**：检查 `0/1/2`、负值、`LANGUAGE_COUNT`、大整数、英文或俄文文本为空时的回退、普通二维表索引始终为 `0/1`；显示任务串行消费语言值，本点不涉及中断并发写页面。
- **通过标准**：写入 0、1、2 后状态页分别显示中、英、俄文；选择俄文时所有普通菜单仍为英文；非法值不会成为数组下标，合法 CRC 镜像中的非法值加载后为英文。

### 4.2 设备状态页俄文布局和翻译

- **源码位置**：`display.c` 的 `state_display_table`、`GetStateString()`、`Display_DrawRussianStatusText()`、`Display_GetRussianStatusSlotLabel()`、`Display_BuildStatusSnapshot()`、`Display_DrawRussianStatusSlots()` 和 `EquipFirstPower()`；消费链路为“CPU2 状态快照 -> 结果上下文/状态槽 -> 俄文映射与分行 -> OLED”。
- **改前问题**：设备状态页只有中英文，直接套用原多字段布局会使完整俄文标签和值互相遮挡；长状态若依靠随意缩写或静默截断会失去工业含义，启动通信提示也总在加载语言前绘制。
- **具体改法**：为设备状态集中增加俄文映射；长状态最多两行、每行 16 个紧凑字形，优先按空格均衡分行且不滚动。俄文过程量改为单字段分页，状态、上下文或语言变化时重建快照并重置分页。维护/模拟徽标和电机图标允许被正文覆盖。“无线滑环匹配”按滑环通信配对显示为 `Сопряжение с токосъёмником`；启动通信提示使用已保存语言。
- **必查边界**：检查 0、16、17、32 个字形，有空格/无空格、切换状态/上下文/语言、状态槽为空或满 6 项、维护/模拟/电机图标区域、液位低于盲区、RSSI/MAC 无数据和无线滑环匹配；超过 32 个字形的新文案不得无提示截断，必须重新评审翻译或布局。
- **通过标准**：全部 71 个状态均有唯一非空俄文映射；现有长状态最多两行且无滚动、乱码、含义不清缩写或残留；俄文参数页每页只显示一个完整标签和值，启动首帧按保存语言显示。

### 4.3 故障显示规则

- **源码位置**：`display.c` 的 `Display_ShouldShowErrorReason()`、`Display_BuildStatusSnapshot()`、`GetStateString()`、`DIS_Equipment()` 和 `Display_ShowErrorReasonPage()`；数据链为“共享错误码 -> 语言/协议判定 -> 状态标题与故障代码”。
- **改前问题**：现有故障原因表只有中文语义；俄文模式若继续进入原因页会显示非俄文内容或诱导新增未经确认的故障翻译，与“只显示代码”的产品决定冲突。
- **具体改法**：中文和英文保留现有故障原因路径；俄文快照不构建原因字段，错误态标题下只把单个 `uint32_t error_code` 拆为 `类型-位置` 代码显示。协议不兼容提示继续拥有更高优先级。
- **必查边界**：逐一注入多个不同已知错误码、零错误码、未知错误码、CPU2 通信故障、协议不匹配、结果页与故障详情页切换，以及从俄文切回中英文后的原因显示；错误码数值和共享协议均不得变化。
- **通过标准**：俄文错误态只出现可追溯的数字代码且没有原因文本；中文和英文原原因显示保持；协议不匹配时不展示可能不可信的普通故障内容。

### 4.4 西里尔字库和许可

- **源码位置**：`font_cyrillic.c/.h` 的 `s_cyrillic_font`、`FontCyrillic_GetGlyph()`；`display.c` 的 `Display_DecodeGlyph()`、`matchingwordstock()`；`font_check.py` 的西里尔字形、状态与显示契约检查；许可入口为 `THIRD_PARTY_NOTICES.md`。
- **改前问题**：原字库没有西里尔字形，UTF-8 俄文会落入缺字或中文字模查找路径；也缺少字形来源、许可和提交前自动覆盖检查。
- **具体改法**：加入俄语 33 个大小写字母（含 `Ё/ё`）共 66 个 `8x14` 点阵；统一 UTF-8 解码器按码点选择 ASCII、西里尔、度数符号或原中文字模，未知字形显示问号。记录 DejaVu 字形来源和许可，并扩展检查器验证字形、字符串、状态映射、分行和许可。
- **必查边界**：`А/Я/а/я/Ё/ё`、非法或不完整 UTF-8、未收录码点、空白/重复字形、原 ASCII/中文索引、反显和 64 列边界；字体查找为只读表，不涉及重入或动态分配。
- **通过标准**：66 个字形数量、非空、非重复和映射全部通过；所有俄文源码字符串缺字为 0；非法输入稳定显示问号且不会死循环或越界；第三方声明可追溯到字形来源和许可。

### 4.5 语言持久化、迁移和启动时序

- **源码位置**：`cpu3_comm_display_params.h/.c` 的 `CPU3_PARAM_VERSION`、`Cpu3ParamStorageV7`、`Cpu3_Params_LoadFromFRAM()`、`Cpu3_Params_SaveToFRAM()`、`Cpu3_Params_RestoreStorageV7()`、`Cpu3Local_WriteValueChecked()`；`app_main.c` 的 `App_Init()`；`display_tankopera.c` 的 `set_display_language()`。
- **改前问题**：V7 的语言字段虽占同一字节，但其发布语义只有 0/1，无法让旧固件可靠识别新增值 2；启动页在 FRAM 语言加载前绘制会短暂显示中文；保存或迁移写入失败若仍切换运行态或记录成功会造成界面与 FRAM 不一致。
- **具体改法**：本机存储版本升为 V8，保留参数负载布局和 CRC 范围；用固定 V7 结构校验、迁移，并用静态断言锁定布局。V3 至 V7 迁移和 V8 加载后统一归一化语言；V7 转写 V8 失败时尝试恢复原完整 V7 镜像。`App_Init()` 调整为 OLED/RTC 初始化、FRAM 加载、再绘制首屏。菜单和本机寄存器均以保存及回读成功为提交点，失败恢复旧结构和显示运行态，不触发成功后动作。
- **必查边界**：V3/V4/V5/V6/V7/V8 有效镜像、CRC/魔术字/版本损坏、语言 0/1/2/非法值、首次写失败、恢复旧镜像失败、连续失败、写入中掉电、重启保持和降级到只识别 V7 的旧固件；FRAM 真实掉电原子性需目标板故障注入确认。
- **通过标准**：有效 V7 中除本机版本字段更新外的合法显示、SI、三路串口和兼容槽保持后写为 V8，非法语言和 COM 字段按上述规则修正；保存失败不显示成功且运行态保持旧值；V8 选择俄文后掉电重启仍为 2，首屏直接使用俄文；损坏镜像恢复默认中文；降级限制在发布资料中明确可见。

## 5. 跨模块数据流和异常闭环

1. 上电后 `DisplayInit()` 只建立 OLED 和页面运行态，不提前选择最终启动文案。
2. `Cpu3_Params_LoadFromFRAM()` 读取 V8，或从 V3 至 V7 迁移；语言值经统一入口归一化。
3. `DisplayAubonLogo()` 读取已经生效的语言，俄文时绘制俄文启动通信提示。
4. 用户进入 Language 菜单选择 Russian，显示层调用受检参数写入接口。
5. FRAM 保存并读回校验成功后才切换页面语言；失败时恢复旧参数和旧显示，界面保留返回或重试能力。
6. 状态页按状态、错误、协议和语言变化或 2 秒节拍更新快照；俄文路径选择静态双行状态和单参数分页。
7. 俄文故障路径读取同一错误码，但跳过原因文案，只显示代码；中文和英文继续走原原因显示。
