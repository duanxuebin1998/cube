# CPU2 V1.41.0.0 DM4 V4调试与通信质量监测改动与测试方案

## 1. 文档目的和适用版本

本文记录CPU2 `V1.40.1.0 -> V1.41.0.0`的DM4 V4通信改动、验证证据和未验证风险。事实范围以本次最终暂存区为准；本文随本次提交纳入，提交哈希以Git记录为准。

## 2. 版本和兼容性

| 项目 | 结果 |
| --- | --- |
| CPU2固件 | `V1.40.1.0 -> V1.41.0.0`（MINOR） |
| CPU3固件 | 保持`V1.40.1.0` |
| CPU2/CPU3共享协议 | `DEVICE_PROTOCOL_VERSION=34`，保持不变 |
| CPU2参数存储 | `DEVICE_PARAM_VERSION=3`，保持不变 |
| `DeviceParameters` | 结构大小、字段偏移、`struct_size`和CRC范围不变 |
| 现场参数 | 升级不恢复出厂、不清除FRAM参数 |
| 传感器协议 | DM4 V4主动帧72字节；交互请求临时使用广播地址`0x00` |

本次只改变CPU2到传感器及CPU2调试串口行为，不改变CPU2/CPU3共享字段或CPU3对外LTD共享区，因此不提升`DEVICE_PROTOCOL_VERSION`。

## 3. 提交范围

- CPU2应用：V4测量适配、主循环服务、串口解析、调试命令和综合测试。

## 4. 详细改动

### 4.1 V4上电识别和无线滑环兼容

- 源码位置：`multiparam_v4_communication.c`的请求构造、应答校验和`MULTIPARAM_V4_ReadSensorID`；`sensor.c`的V4探测和身份提交。
- 改前问题：广播R01收到地址`0x01`的合法应答仍被地址相等校验拒绝；定向R67被无线滑环本地`0xFF`应答抢先；编号0被当成格式错误。
- 具体改法：V4交互请求暂时统一发往`0x00`；广播应答接受设备自身地址；R67只拒绝负数，允许未初始化编号0；每次探测打印实际TX/RX和校验阶段。
- 必查边界：单设备广播、多设备广播冲突、0/正数/负数编号、超时、短帧、地址错、功能码错、参数码错和BCC错。
- 通过标准：R01和R67帧校验通过，编号0提交成功，FRAM A/B保存成功；非法帧仍返回原具体错误码。

### 4.2 72字节主动帧和无线滑环插零兼容

- 源码位置：`multiparam_v4_communication.c`的主动DMA、流缓冲、候选帧解析和快照发布；`multiparam_v4_measurement.c`的业务快照消费。
- 改前问题：传感器直连帧正常，经无线滑环后可能在帧中出现连续零字节，固定偏移解析失败；主动帧新增P13和P14后旧长度和字段数不足。
- 具体改法：主动帧固定长度调整为72字节，解包P0至P14；候选解析在不改变有效载荷顺序的前提下兼容现场连续零字节，并保留原始异常包供诊断。
- 必查边界：直连72字节帧、插零帧、全零区、截断、粘包、多个候选帧、CRC错、固定字段错和缓冲区满。
- 通过标准：直连与插零样本得到相同P0至P14结果；坏帧不刷新最新有效快照。

### 4.3 主动/交互半双工切换保护

- 源码位置：`multiparam_v4_communication.c`的主动帧结束记录、交互事务和参数65切换；`test.c`的`V4I/V4A`命令。
- 改前问题：主动帧发送期间下发交互切换命令可能与传感器上发冲突。
- 具体改法：记录完整主动帧结束时刻；切入交互前等待至少15 ms静默窗口，窗口中收到新主动帧则重新计算；交互结束后按目标模式恢复常驻接收。
- 必查边界：刚收到完整帧、持续主动上报、等待中UART错误、命令取消、切换超时和首帧恢复。
- 通过标准：交互TX不早于最近完整主动帧结束15 ms；失败后UART6保持可恢复状态。

### 4.4 主动帧通信质量和三连异常故障

- 源码位置：`multiparam_v4_communication.c/.h`的诊断结构、序号统计、异常保存和质量故障领取；`app_main.c`的主循环错误上报；`test.c`的`V4G/V4C`。
- 改前问题：只能看到单帧解析结果，无法量化丢包，也无法在连续通信异常时形成统一错误。
- 具体改法：按16位主动帧序号统计有效包、预计包、缺口和丢包率；分别统计CRC、格式、地址、重复、乱序、UART和恢复异常；保存上一异常包；连续3次异常或主动流1500 ms无有效帧时上报质量错误。
- 必查边界：正常递增、序号回绕、重复、乱序、序号复位、单次坏帧、连续3次坏帧、1500 ms超时、计数饱和和`V4C`清零。
- 通过标准：`V4G`打印可复算的丢包率和上一异常包；连续1至2次异常不报最终质量错误，连续第3次产生约定错误；`V4C`不破坏当前接收和最近有效快照。

### 4.5 模式和附加功能控制

- 源码位置：`multiparam_v4_communication.c`的模式/功能确认；`multiparam_v4_measurement.c`和`sensor.c`的读取前使能；`test.c`的`V4D/V4S/V4L/V4M/V4O`。
- 改前问题：水位和磁零点上电默认关闭，读取前未统一使能；两项只能在密度模式使用且互斥，进入液位模式必须关闭。
- 具体改法：读取前按R02状态确保目标功能开启；水位与磁零点互斥，开启一项前关闭另一项；进入液位模式自动关闭附加功能；功能阶段结束后保持当前开启状态。
- 必查边界：密度/液位切换、重复开启、重复关闭、两项互斥、R02读后清除位、命令取消和远端错误。
- 通过标准：不会通过盲目翻转把已开启功能关闭；液位模式最终无附加功能；水位与磁零点不同时开启。

### 4.6 无效测量值和通信包诊断

- 源码位置：`multiparam_v4_communication.c`的浮点读取；`multiparam_v4_measurement.c`的值域检查；`sensor.c`的命令15失败处理；DSM/V3通信文件的探测日志。
- 改前问题：帧校验成功但数据为`0x7FC00000` NaN时被当成协议格式错误并置全局故障；失败日志没有实际通信包。
- 具体改法：NaN返回`SENSOR_DATA_STALE`，正负无穷和真正格式错误仍报错；命令15对V4姿态、密度组合量、水位电容和磁零点的陈旧值打印最近TX/RX后跳过，不写0、不覆盖有效快照；V4/V3/DSM探测统一打印实际长度和HEX。
- 必查边界：NaN、正负无穷、有限越界、无响应、短帧、UART错误、已有有效快照和连续刷新。
- 通过标准：NaN不进入全局通信错误，正式测量不发布NaN或伪0；真正通信与协议错误仍保留具体错误码。

### 4.7 V4串口调试命令

- 源码位置：`serial_command_parser.c`、`serial_command.c`和`test.c`。
- 改前问题：现场无法独立控制V4通信方式、模式和附加功能，也无法打印主动帧、参数原值和质量统计。
- 具体改法：新增`V4?`、`V4P`、`V4I`、`V4A`、`V4D`、`V4S`、`V4L=0|1`、`V4M=0|1`、`V4O`、`V4R=<0..25|65..159>`、`V4F`、`V4G`和`V4C`，严格匹配完整命令。
- 必查边界：合法首尾参数、26至64保留区、160越界、额外尾随字符、错误模式和无快照状态。
- 通过标准：合法命令进入测试分发且打印明确ACK/结果；非法格式不访问传感器。

## 8. 风险和未验证项

- 广播请求要求总线上只有一台同协议设备；多设备同时应答行为未验证。
- 无线滑环插零兼容依据现场样本实现，长期噪声、粘包和不同插零位置仍需压力测试。
- 连续3包异常和1500 ms超时需要目标板故障注入，构建不能证明实时错误时序。
- Safe协议模式切换尚未设计，本版本不自动进入Safe模式，也不据此声明SIL闭环。
- 未执行最终版本真实烧录、长线、现场长期运行和完整回归。
