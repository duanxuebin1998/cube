# 2026-05-23 CPU2 V1.9.0.0 / CPU3 V1.7.0.0 无线滑环最近匹配正式命令与 MAC 显示改动与测试方案

## 版本变化

- CPU2：`V1.8.1.0 -> V1.9.0.0`
- CPU3：`V1.6.0.0 -> V1.7.0.0`
- 说明：无线滑环分支中的 `V1.8.0.0` / CPU3 `V1.6.0.0` 是阶段性开发口径；合并到 MAIN 后，因 MAIN 已使用协议版本 4，最终以协议版本 5、CPU3 V1.7.0.0 发布。

## 协议版本与兼容性

- `DEVICE_PROTOCOL_VERSION`：`4 -> 5`。
- 新增共享命令 `CMD_PAIR_NEAREST_WIRELESS_SLIPRING = 117`。
- 在 CPU2->CPU3 输入寄存器末尾追加运行态 `WirelessPairingStatus`，用于发布匹配结果、从机 MAC、失败错误码和更新计数。
- CPU2 V1.9.0.0 与 CPU3 V1.7.0.0 配套使用；旧 CPU2 不识别命令 117，协议版本不匹配时 CPU3 按现有机制提示不兼容。
- 不新增保持寄存器地址，不改变 `command` 寄存器宽度；MAC 仅作为运行态输入寄存器状态发布，不新增无线滑环 MAC、名称或 RSSI 持久化参数。
- 固定点样机模式复用现有 `single_point_monitoring` 测量数据字段，不新增 CPU2/CPU3 协议字段。

## 详细改动

### CPU2 无线滑环匹配基础能力

- 新增 `ch9141_at.c/.h`，封装 UART6 上的 CH9141K AT 指令收发、空闲等待、响应收集和结果判定。
- 软件 AT 入口按 CH9141K 协议发送 `AT...`，不使用裸 `AT`；旧 `CH9141EVT.c` 初始化路径同步修正，避免后续误用。
- AT 指令统一追加 `\r\n`，按独立控制行识别 `OK`、`ERR`、`LINK OK`、`PAIR ERR`、`SCAN END` 和 RSSI 上报，避免候选名称或数据内容误触发响应结束。
- 默认隐藏正常成功的逐条 AT 收发明细，仅在失败时打印底层 AT 结果和原始响应；连接密码字段在日志中脱敏。
- RSSI 异步上报必须等到具体数值才判定完成，只收到 `RSSI` 标题时继续等待；发送新 AT 命令前短暂清理 UART6 残留，降低异步尾包污染后续查询的概率。
- 新增 `wireless_pairing.c/.h`，实现 CH9141K 主机模式确认、扫描候选解析、RSSI 近距离选择、名称字段选择、连接、默认连接保存、模块复位和透传链路探测。
- `SPR` 按 RSSI 近距离规则自动匹配：最强 RSSI 不低于 `-55 dB`，多候选时领先第二名不少于 `8 dB`；多候选缺少可比较的第二 RSSI 时拒绝自动匹配。
- `SPN=<name>` 只接受扫描结果里显式 `NAME:`、`NAME=`、`PNAME:`、`PNAME=` 字段，避免数字编号误命中 MAC、RSSI 或电压文本。
- `SPC` 只读查询 `BLEMODE`、`BLESTA`、`CCADD`；RSSI 读取按 `AT+RSSI=ON,<周期>` 先 ACK、再等待异步上报、最后关闭上报处理。
- 扫描候选 MAC 统一转为大写，并修正 `MAC:D1...` 被误截成 `AC:D1...` 的边界问题。
- `BLEMODE` / `BLESTA` 解析只接受协议合法枚举值，并跳过前序残留异步行，避免 `-35dB` 被当成模式或状态。
- 新增 CPU2 串口调试命令 `SPS`、`SPR`、`SPN=<name>`、`SPC`，分别用于扫描打印、RSSI 最近匹配、名称匹配和当前连接状态查询。

### CPU2 辅助调试和样机模式

- `process_command()` 串口调试提示统一为中文字段格式，覆盖 `B/BE`、`A`、`N`、`TFIT`、`Y` 等调试命令，便于现场日志检索。
- 增强 `BE<mm>` 编码器闭环往返测试日志，打印命令切换上下文、运动下发、下行/上行退出原因、错误码/错误名、当前/目标/原点编码器值、电机状态和待执行命令。
- `BE/B` 的 `S` 通信检查按 `g_deviceParams.sensorType` 分支：DSM 一代读取密度帧和供电电压，LTD/V2 切换密度模式后读取温度、密度和扫频均值，未知类型只打印提示并跳过。
- 新增固定点监测样机宏 `ENABLE_SINGLE_POINT_MONITORING_PROTOTYPE`，默认启用；固定点监测移动到设定位置后不读取真实密度传感器，改为每 500 ms 刷新虚拟温度和水密度，密度、标密、计重密度均固定为 `999.5kg/m3`。
- 当 `ENABLE_SINGLE_POINT_MONITORING_PROTOTYPE` 设为 `0U` 时，固定点监测恢复原有 `EnableDensityMode()` 和 `SinglePoint_ReadSensor()` 真实传感器通信流程。

### CPU2/CPU3 正式命令和显示

- CPU2/CPU3 `CommandType` 同步新增 `CMD_PAIR_NEAREST_WIRELESS_SLIPRING = 117`。
- CPU2 `ProcessMeasureCmd()` 在 `MeasureStart()` 前处理无线滑环正式命令，不依赖电机初始化，直接复用 `WirelessPairing_RunByRssi()`。
- CPU2/CPU3 新增设备状态 `STATE_WIRELESS_PAIRING = 0x0032` 和 `STATE_WIRELESS_PAIRING_OVER = 0x8032`。
- CPU2 在匹配开始、成功、失败时发布 `WirelessPairingStatus`；成功时把 `AA:BB:CC:DD:EE:FF` 拆成 `mac_high/mac_mid/mac_low` 三段数值。
- 匹配失败时 CPU2 将 `device_status.error_code` 置为失败错误码，并将 `device_status.device_state` 置为 `STATE_ERROR`；CPU3 按现有故障页显示错误码。
- CPU3 维护/调试菜单新增“匹配无线滑环”入口，通过现有 `send_cpu2_command()` 写入 CPU2 `command` 寄存器。
- CPU3 菜单操作码 `COM_NUM_PAIR_NEAREST_WIRELESS_SLIPRING = 1000` 使用显式编号，不插入既有连续枚举区间，避免改变已有菜单和参数操作码数值。
- CPU3 正常轮询新增的 `WirelessPairingStatus` 输入寄存器区间，避免匹配结果和 MAC 状态未刷新。
- CPU3 下发匹配命令后退出罐上操作菜单覆盖页；收到 CPU2 发布的匹配中/完成设备状态后，由普通设备状态页显示“无线滑环匹配中/完成”，完成状态下显示两行 MAC。

### 文档

- 合并无线滑环 RSSI/名称匹配、固定点样机模式、正式命令和 MAC 显示为本测试方案。
- 新增《无线滑环最近匹配正式命令需求》。
- 更新《CPU2_CPU3协议变更记录》，将协议版本 4 定义为无线滑环最近匹配正式命令和匹配结果/MAC 运行态状态。
- 更新 CPU2 无线滑环设备端匹配执行记录和 `CHANGELOG.md`，统一为本次提交的最终版本口径。

## 影响范围

- 影响 CPU2 UART6 无线滑环维护调试流程；匹配动作会临时中断 UART6 透传，必须在维护或停测状态执行。
- 影响 CPU2/CPU3 共享命令枚举、协议版本和输入寄存器总长度；新增字段追加在既有输入寄存器末尾。
- 影响 CPU3 维护/调试菜单和普通设备状态页；匹配完成状态下额外显示从机 MAC。
- 不改变现有保持寄存器地址、`command` 寄存器写入方式和 CH9141K 默认连接保存位置。
- 不提供 CPU3 扫描候选列表、RSSI 明细、名称显示或手动选择候选；详细阶段仍通过 CPU2 串口日志定位。
- `ENABLE_SINGLE_POINT_MONITORING_PROTOTYPE=1U` 时，固定点监测显示虚拟样本数据，不代表真实传感器测量值。

## 测试点

### 1. CPU3 菜单触发最近匹配和 MAC 显示

准备条件：
- CPU2 V1.9.0.0 与 CPU3 V1.7.0.0 配套运行。
- CH9141K 主机模块接在 CPU2 UART6。
- 只打开目标无线滑环从机，或让目标从机明显靠近主机。

步骤：
1. 在 CPU3 维护/调试菜单选择“匹配无线滑环”。
2. 观察 CPU2 串口日志。
3. 等待扫描、RSSI 选择、连接、保存默认连接、复位和透传探测完成。

预期结果：
- CPU3 写入命令 117，并退出罐上操作菜单覆盖页。
- CPU2 打印正式命令触发日志，并执行与 `SPR` 相同的 RSSI 最近匹配流程。
- CPU2 发布 `STATE_WIRELESS_PAIRING` 时，CPU3 设备状态页显示“无线滑环匹配中”。
- 匹配成功后主机和从机透传探测正常。
- CPU2 发布 `STATE_WIRELESS_PAIRING_OVER`、成功结果和从机 MAC。
- CPU3 设备状态页显示“无线滑环匹配完成”，并以 `AA:BB:CC` / `DD:EE:FF` 两行显示从机 MAC。

通过标准：
- 不需要电机初始化也能执行匹配。
- 屏幕显示的 MAC 与 CPU2 日志里的目标 MAC 一致。
- 匹配完成后 UART6 恢复透传，设备可继续通信。

### 2. 多候选拒绝误配

准备条件：
- 同时打开多个 CH9141K 从机。
- 目标从机与其他从机 RSSI 差值不足。

步骤：
1. 通过 CPU3 菜单触发“匹配无线滑环”。
2. 观察 CPU2 RSSI 选择日志和 CPU3 错误显示。

预期结果：
- CPU2 打印候选数量和 RSSI 差值不足原因。
- 不静默保存错误的默认连接。
- 匹配失败后复位 CH9141K 并恢复 UART6 透传。
- CPU2 将设备状态置为 `STATE_ERROR`，并发布对应错误码。
- CPU3 按现有故障页显示对应错误码。

通过标准：
- 多候选条件不满足时拒绝自动匹配，不发生静默误配。

### 3. CPU2 调试串口扫描和匹配回归

准备条件：
- CPU2 调试串口可用。
- 至少一个 CH9141K 从机上电。

步骤：
1. 发送 `SPS\r\n`，观察扫描候选。
2. 发送 `SPR\r\n`，观察近距离匹配流程。
3. 若扫描输出包含名称字段，发送 `SPN=<name>\r\n`。
4. 匹配成功后发送 `SPC\r\n`。

预期结果：
- `SPS` 输出候选数量、序号、MAC、RSSI；扫描完成后复位 CH9141K 并恢复透传。
- `SPR` 满足阈值和差值条件时连接并保存默认连接；不满足时拒绝。
- `SPN=<name>` 只匹配显式名称字段，重复或未找到时拒绝。
- `SPC` 只读查询连接状态，不扫描、不断开、不保存默认连接；已连接时打印 MAC，RSSI 异步上报成功时打印 RSSI。

通过标准：
- CPU3 正式命令和 CPU2 `SPR` 复用同一底层流程，原调试入口不回归。
- `SPC` 前后连接关系不变化。

### 4. 固定点监测样机模式

准备条件：
- `ENABLE_SINGLE_POINT_MONITORING_PROTOTYPE` 保持默认 `1U`。
- CPU3 或调试端可观察固定点监测显示数据。

步骤：
1. 触发固定点监测命令。
2. 等待电机移动到 `singlePointMonitoringPosition`。
3. 观察 CPU2 调试串口和 CPU3 固定点监测显示。

预期结果：
- CPU2 打印样机模式已启用，并提示不与真实密度传感器通信。
- CPU2 不执行 `EnableDensityMode()` 和 `SinglePoint_ReadSensor()` 真实传感器读取流程。
- 每 500 ms 打印一次虚拟位置、温度、`999.5kg/m3` 水密度、标密、VCF20 和计重密度。
- CPU3 显示的固定点温度/密度来自虚拟样本字段，密度类字段按水密度显示。

通过标准：
- 固定点监测状态可持续刷新虚拟数据。
- UART6 无真实密度传感器查询帧。

### 5. 关闭固定点样机模式回归

准备条件：
- 临时将 `ENABLE_SINGLE_POINT_MONITORING_PROTOTYPE` 设为 `0U` 后重新编译。
- 真实密度传感器链路可用。

步骤：
1. 触发固定点监测命令。
2. 观察固定点监测到位后的传感器通信流程。

预期结果：
- 固定点监测到位后执行原有 `EnableDensityMode()`。
- 后续通过 `SinglePoint_ReadSensor()` 读取真实密度传感器。
- 不打印样机模式虚拟样本日志。

通过标准：
- 原有固定点监测真实传感器流程可编译并保持可回归。

### 6. BE 编码器闭环测试退出诊断

准备条件：
- 调试串口连接 CPU2 USART1。
- 编码器和电机驱动按现场方式接入。

步骤：
1. 发送 `BE100\r\n`。
2. 观察首次运动下发日志。
3. 如果运行一下就停止，记录 `BE编码器测试退出` 和返回提示日志。

预期结果：
- 运动下发时打印保护距离、速度、当前编码器和目标编码器。
- 命令切换、编码器目标未达、电机提前停止、轮询失败、停止失败或下行/上行阶段退出时，打印错误码、错误名、当前编码器、目标编码器和原点编码器。

通过标准：
- `BE` 不再静默退出，现场可根据日志判断退出原因。

### 7. BE/B S 通信检查按传感器类型分流

准备条件：
- 已通过上电识别或 `SC` 确认 `g_deviceParams.sensorType`。
- 分别准备 DSM 一代和 LTD/V2 两类传感器现场条件。

步骤：
1. DSM 一代条件下发送 `BE100S\r\n` 或 `B100S\r\n`。
2. LTD/V2 条件下发送 `BE100S\r\n` 或 `B100S\r\n`。
3. 观察 `BE传感器通信` 日志中的类型、项目、错误码和失败次数。

预期结果：
- DSM 一代只发送 DSM 一代密度模式/密度帧/供电电压相关命令。
- LTD/V2 发送 LTD/V2 密度模式、温度、密度和扫频均值读取命令。
- 未知 `sensorType` 时不尝试协议帧，打印跳过提示。
- 传感器通信失败只累计打印，不改变 BE/B 的电机运动退出判断。

通过标准：
- DSM 一代不会再收到 LTD/V2 的 R 参数帧。
- LTD/V2 保留温度、密度和扫频均值通信诊断能力。

### 8. 版本兼容提示

准备条件：
- 使用 CPU3 V1.7.0.0 与旧 CPU2 组合，或模拟 CPU2 协议版本不是 4。

步骤：
1. 启动 CPU3 并读取 CPU2 协议版本。
2. 观察设备状态页或协议兼容提示。

预期结果：
- CPU3 识别协议不匹配。
- 不建议继续通过菜单下发新增命令。

通过标准：
- 旧 CPU2 不被误判为支持命令 117。

## 未验证风险

- CH9141K 实际 `AT+SCAN=ON` 输出是否包含名称字段仍需台架确认；如果不包含，`SPN=<name>` 将按设计拒绝匹配。
- CH9141K 规格书未提供当前已连接远端名称查询命令，`SPC` 的从机名称依赖 CPU2 本次运行期最近一次成功匹配缓存；断电重启或缓存未命中时名称会显示未知。
- RSSI 受天线方向、遮挡、舱内反射影响，现场阈值 `-55 dB` 和差值 `8 dB` 需要实测校准。
- CPU3 仅显示最终成功 MAC 或失败错误码，不显示扫描候选、RSSI、名称或失败阶段明细；现场仍需通过 CPU2 串口日志定位具体失败阶段。
- 固定点样机模式默认启用，发布真实测量固件前必须确认 `ENABLE_SINGLE_POINT_MONITORING_PROTOTYPE` 已按目标版本要求设置。
- 虚拟温度和 `999.5kg/m3` 水密度只用于样机固定点展示，不用于现场计量验收。
- `BE/B` 的 `S` 通信检查依赖已识别的 `sensorType`；若上电识别失败或参数未更新，会按未知类型跳过通信内容，需先执行传感器识别或完整通信测试。
