## 4. 详细改动

### 4.1 CPU2固定频率找液位调试闭环

- 源码位置：`fixed_frequency_level_search.c`的`FixedLevel_BuildConfig()`、`FixedLevel_CheckGuards()`和`FixedFrequencyLevelSearch_Run()`；入口链路为`串口收帧 -> SerialCommandParser_Parse -> Test_ProcessSerialCommand -> MeasureStart -> LF闭环`。
- 改前问题：CPU2没有可由串口独立执行并观测的固定频率找液位调试闭环，现场无法用一次性命令验证频率方向、速度和安全保护。
- 具体改法：新增`LF`、`LF=<frequency>`、`LF=<frequency>,<deadband>`和只读`LF?`。默认目标来自`oilLevelFrequency`，默认死区由`oilLevelThreshold`按现有迁移倍率换算；频率高于目标时下行、低于目标时上行，速度从0.10 m/min起按频差增加并受当前默认最大速度限制。连续3次进入死区后记录当前位置；每次稳定确认间隔1秒，运动采样间隔200毫秒，总超时10分钟。
- 必查边界：目标/死区0、1、6500、6501；罐高小于顶部100.0 mm余量；盲区与上限交叉；扭力上下限相等；方向切换；电机意外停止；STOP/新命令；位置、扭力、传感器通信、丢步和超时。
- 通过标准：非法语法返回`INVALID_FORMAT`且不启动电机；`LF?`不调用`MeasureStart()`；运行中每个异常出口慢停并输出明确错误；找到液位时电机已停止，当前位置写入液位结果，临时覆盖不写FRAM。

### 4.2 区间密度点规划容量保护

- 源码位置：`measure_density.c`的`BuildPoints_Interval_Exact()`和`Density_MeasureByMode_Exact()`。
- 改前问题：`int8_t i`在128～200点时回绕为负数，可能负索引写出`points01[200]`；超过200点被静默钳位，调用方无法区分非法配置。
- 具体改法：点数和索引改为`uint32_t`；调用方传入实际数组容量；入口先把`*out_n`清零，再拒绝0点、超过200点和超过容量；删除静默钳位，端点修正只在容量门禁通过后执行。
- 必查边界：0、1、2、3、127、128、129、199、200、201和`UINT32_MAX`；升序/降序；上下端点相等、越罐高、低于盲区；输出数组前后canary。
- 通过标准：1～200点首尾和单调性正确；非法点数返回`MEASUREMENT_DENSITY_PLAN_INVALID`，`out_n=0`，输出区和canary不变。

### 4.3 区间测量失败禁止发布

- 源码位置：`measure_density.c`的`CMD_MeasureDensitySpread_Interval()`。
- 改前问题：区间测量返回错误后虽记录故障，仍继续打印、发布临时结构并进入`STATE_INTERVAL_DENSITY_OVER`，可能对CPU3形成“完成态+空或部分点阵”。
- 具体改法：非`NO_ERROR`时打印错误、`SET_ERROR()`后立即返回；不调用`DensityProfile_PublishResult()`，不进入完成态。`STATE_SWITCH`仍作为正常取消直接返回。
- 必查边界：规划失败、移动失败、单点读取失败、中途命令切换、成功完整点阵、上一代快照保留。
- 通过标准：失败时完成代次不增加、来源和点数不提交、状态不进入完成；成功时仍只在完整点阵写入后递增完成代次。

### 4.4 LTD/V2远端失败和恢复原因

- 源码位置：`ltd_sensor_communication.c`的`DSM_V2_CheckReply()`、`DSM_V2_SwitchMode()`、`DSM_V2_Read_FloatParam()`和`DSM_V2_Read_IntParamInternal()`。
- 改前问题：应答第7字节`0xFF`只打印原始帧后返回成功，随后可能解析无效`rx[2..5]`并更新模式或参数；重试恢复统一记录“通信失败”，丢失真实失败类型。
- 具体改法：在功能码检查后把`0xFF`映射为现有`SENSOR_REMOTE_INTERNAL_ERROR`；失败进入既有有限重试，只有完整成功帧才解析和提交；恢复日志用最后一次错误码映射实际原因。
- 必查边界：模式、浮点、整数读取各返回`0xFF`；前两次失败第三次成功；三次失败；功能码错、参数码错、坏CRC、短帧和命令切换。
- 通过标准：失败帧不更新输出、模式、valid或完成态；最终失败保留`SENSOR_REMOTE_INTERNAL_ERROR`；恢复日志与最后一次错误一致。

### 4.5 CPU3 LH FC01读线圈兼容

- 源码位置：`lh_modbus_slave.h`的功能码和最大数量定义；`lh_modbus_slave.c`的`lh_handle_read_coils()`与`lh_modbus_process()`；`.cproject`补充LH包含路径。
- 改前问题：LH主机读取命令线圈时收到非法功能异常，不能按手册完成线圈区探测。
- 具体改法：接受8字节FC01请求；数量范围1～2000且`start+count`不超过`LH_COIL_COUNT`时，按Modbus位打包格式返回全0位图。线圈仍只作为命令写入口，不把历史命令、当前状态或锁存结果映射成1。
- 必查边界：起始0/16/17，数量0/1/8/9/17/2000/2001，`start+count`边界，坏CRC、错地址和长度非8。
- 通过标准：合法范围响应功能码0x01、字节数为`ceil(count/8)`、所有位为0且CRC正确；数量非法返回0x03，地址越界返回0x02；不改变CPU2命令、RAM、FRAM或硬件。

### 4.6 正式资料同步

- 文档位置：CPU2串口调试协议卷、LH索引/Word手册、需求审批方案、故障码复核和版本资料。
- 改前问题：LF版本仍写“待发布”；审批方案把已进入工作区的C-10/C-31写为“尚未修改固件”；故障码复核仍引用未提交的`measure_density.c`。

## 5. 关键数据流

```text
LF串口命令
  -> 严格语法校验
  -> LF?只读配置 / LF运行MeasureStart
  -> 构建单次配置，不写参数
  -> EnableLevelMode
  -> 位置/扭力/通信/丢步守护
  -> 读取频率并按误差调方向和速度
  -> 连续3次进入死区
  -> 慢停、记录液位并返回FOUND

LTD/V2应答
  -> 帧形/功能码检查
  -> rx[6]==0xFF：远端内部失败
  -> 有限重试
     -> 成功：只提交完整候选值
     -> 耗尽：返回具体错误，不发布完成

LH FC01
  -> 地址/CRC/长度检查
  -> 数量与线圈范围检查
  -> 生成全0位图
  -> 追加CRC并响应
```

## 9. 风险与未验证项

1. LF属于真实运动调试入口，构建和解析测试不能证明方向、制动距离、扭力阈值、位置源新鲜度或机械安全；首次台架必须空载、限速并具备独立急停。
2. LF读取频率、位置和扭力的时序依赖真实传感器和电机状态，10分钟超时、方向切换及命令切换需要实机长场景验证。
3. 区间点规划已消除窄索引，但尚未用canary或内存工具覆盖128～200点，也未验证200点长流程的栈余量和时长。
4. `0xFF`语义按现有证据只映射为粗粒度远端内部失败，不猜测更具体原因；真实设备或golden frame仍需确认。
5. LH FC01返回全0是兼容探测口径，不是线圈状态回读；主机不得据此判断历史命令、当前状态或执行结果。
6. 静态契约、DOCX渲染和clean-first构建不能替代交叉烧写、RS485压力、传感器故障注入或机械长稳。
