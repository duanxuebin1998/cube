# CPU2 V1.42.10.0 SI 分布测量修复改动与测试方案

## 1. 版本与目的

- CPU2：`V1.42.9.0 -> V1.42.10.0`（PATCH）。
- CPU3：保持 `V1.40.1.0`。
- 目的：修复 SI 分布测量探底后 Point0 重复下行，以及密度模式切换后未等待稳定便读取零值并误判空气的问题；保持单点等待 5 分钟后的既有回退行为，不让单点未稳定取消整次 profile。

## 2. 协议版本与兼容性

- `DEVICE_PROTOCOL_VERSION` 保持 35；CPU2/CPU3 共享寄存器、共享命令、共享状态、SI 对外寄存器地址和数据语义不变，CPU3 固件无需随本次改动升级。
- CPU2 `DEVICE_PARAM_VERSION` 保持 3；`DeviceParameters` 结构、字段偏移、CRC 范围和 FRAM 布局不变，升级不恢复出厂、不清除现场参数。
- SI 参数 `40001~40003` 的配置含义不变。本次只调整 CPU2 内部 Point0 定位、密度模式切换与读数判定时序。

## 3. 本次修改

### 3.1 探底后 Point0

- 源码位置：`measure_density_si.c` 的 `SiProfile_ResolveReleasedPoint0FromCable()`、`SiProfile_CaptureSharedBottomReference()`、`SiProfile_SelectPoint0Position()`、`SiProfile_RunPoints01mmWithDwell()` 和 `CMD_SiProfile()`；调用链为 `CMD_SiProfile -> SearchBottom -> SiProfile_SelectPoint0Position -> SiProfile_BuildPoints -> SiProfile_RunPoints01mmWithDwell`。
- 改前问题：`SearchBottom()` 返回前已上提 100 mm，但 SI 随后仍把原罐底作为 Point0 运动目标，导致探头再次下行并存在触底风险；复用旧底时也直接使用罐底位置。
- 具体改法：新增 1000 个 0.1 mm 单位的释放偏移。新探底成功时直接保存当前实际位置为 Point0，并向逐点执行函数传入“Point0 已到达”；复用可信旧底时按底部解析位置加 100 mm 生成 Point0。仅“本轮探底成功”跳过第 0 点运动，其它兜底路径仍按目标位置运动。
- 必查边界：当前实际位置为负时压到 0；底部加 100 mm 超过 `INT32_MAX` 时钳位；探底失败但有旧底、探底失败且无旧底、本轮按周期跳过探底、Point0 后命令切换均需复核。底部参考存储格式和罐高计算不变。
- 通过标准：探底成功日志中的 Point0 等于 `SearchBottom()` 返回后的实际位置；进入候选点 0 时出现“无需再移动”日志且无新的下行 Jog 命令；复用旧底时 Point0 等于解析底部位置加 100.0 mm；候选点 0 的上报位置等于实际位置。

### 3.2 密度模式与稳定等待

- 源码位置：`measure_density_si.c` 的 `SiProfile_RunPoints01mmWithDwell()` 和 `SiProfile_ReadPointAndClassify()`；调用链为 `到点 -> SensorService_EnableDensityMode -> AbortableDelay_CommandSwitch(dwell) -> SiProfile_ReadPointAndClassify -> SensorService_ReadDensity`。
- 改前问题：逐点流程先执行 `40003` 停留，读数函数随后才切换 D 模式并立即读取 R6/R7/R17/R18。传感器刚切模式时返回 0，旧逻辑先执行空气判断，密度 0 被立即当作液面以上点，Point0 即终止时最终得到 0 个有效点。
- 具体改法：把 D 模式切换移到每点停留之前，停留窗口同时作为模式稳定时间；读数函数不再重复切模式。读取后先检查频率、密度、温度是否有限以及频率、密度是否大于 0，无效时重置稳定窗口并延时 200 ms 后重读，空气判断只接收合法正值样本。
- 必查边界：`40003=1s` 与 `3600s`、命令在切模式/停留/重读期间切换、D 模式命令失败、读寄存器通信或帧错误、0、负数、NaN、Inf、低于空气密度阈值的合法正值以及重新出现合法样本均需复核。
- 通过标准：抓包顺序必须为 D 模式命令在前、完整 `40003` 停留在中、首次 R6/R7/R17/R18 读取在后；0/NaN/Inf/非正值不产生“判定为液面以上”日志；通信错误仍返回原错误码；合法低密度正值仍能结束扫描。

### 3.3 五分钟超时

- 源码位置：`measure_density_si.c` 的 `SiProfile_ReadPointAndClassify()` 五分钟超时分支，以及其调用方 `SiProfile_RunPoints01mmWithDwell()`、`CMD_SiProfile()`。
- 改前问题：本轮讨论中的中间方案曾考虑把五分钟未稳定统一返回 `SENSOR_DATA_STALE`，这会进入 `SiProfile_HandleFailure()` 并清除本周期候选，导致前面已经得到的有效点也无法发布。
- 具体改法：保留原有三个超时出口，不加入新的 stale 分支。有最后液体样本时填充 `timeout_last_liquid` 并返回成功；没有有效频率或当前频率无效时返回 `SONIC_FREQ_ABNORMAL`；否则填充 `density_timeout_zero` 空气点并返回成功。
- 必查边界：Point0 全程频率为 0、后续点先有合法液体样本再持续无效、有合法频率但密度持续为 0、临近五分钟发生命令切换、读数通信错误均需分别验证。超时判断使用无符号 tick 差值，保持既有回绕处理方式。
- 通过标准：有最后液体样本时该点加入候选且 profile 继续；有有效频率但密度不稳定时只结束后续扫描，已获得候选点保留；没有有效频率时仍出现原频率异常；源码和静态契约中不存在 `SENSOR_DATA_STALE` 触发的整次 profile 失败分支。

## 7. 复杂场景与回归范围

### 7.1 Point0 后长时间未稳定

1. 让 Point0 和 Point1 正常得到稳定液体样本，确认活动进度为 2。
2. Point2 先返回一次合法液体值，再持续返回 0 直至 5 分钟。
3. 确认 Point2 使用最后液体样本，活动进度增加到 3，随后继续 Point3。
4. 在后续提供合法空气样本，确认扫描结束、回液位后最终 N 至少为 3，Point0~Point2 均保留。

通过标准：五分钟未稳定不清除前序点，不产生“密度测量无有效点”，最终 Complete、N 和点阵来自同一 cycle。

### 7.2 回归范围

- SI 自动/手动 Profile 触发、Point0 cycle/progress、空气点结束、回液位后 Complete 发布和命令切换取消。
- 普通单点、普通分布、国标分布和 Wartsila 密度流程未修改；至少执行一次冒烟测试，确认其 D 模式时序和返回码未受 SI 私有函数调整影响。
- 普通探底形成的共享底部参考、SI 周期探底计数、罐高上限、200 点上限和 `40001~40003` 参数读写。
- CPU2/CPU3 协议 35 握手和 CPU3 V1.40.1.0 对 SI Profile 状态、N、点阵的读取。
