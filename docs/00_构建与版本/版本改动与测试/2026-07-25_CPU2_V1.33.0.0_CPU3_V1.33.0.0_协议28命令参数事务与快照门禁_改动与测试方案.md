# CPU2 V1.33.0.0 / CPU3 V1.33.0.0 协议28命令参数事务与快照门禁改动与测试方案

## 1. 文档目的和适用版本

本文记录协议28的最终实现、提交范围、兼容性、验证结果和台架测试方法。适用固件组合：

- CPU2：`V1.33.0.0`
- CPU3：`V1.33.0.0`
- CPU2/CPU3共享协议：`DEVICE_PROTOCOL_VERSION = 28`
- CPU2参数存储：`DEVICE_PARAM_VERSION = 3`
- CPU3本机参数存储：V7 / `0x0007`

本次只落实已确认的S-01～S-03：拆开运行态与固定点门禁、修正LTD FC04门禁、区分普通命令失败与参数写失败。S-04～S-06不在本次实现范围内，不增加数据域失败计数器、参数代次整体确认或新的全局恢复状态机。

## 2. 版本、协议和参数存储兼容性

| 项目 | 改前 | 改后 | 兼容结论 |
| --- | --- | --- | --- |
| CPU2固件 | `V1.32.0.0` | `V1.33.0.0` | 功能级变更，升MINOR |
| CPU3固件 | `V1.32.0.0` | `V1.33.0.0` | 功能级变更，升MINOR |

| CPU3本机参数存储 | `0x0007` | `0x0007` | 仅新增RAM确认状态，不改变FRAM |

协议28不新增、不删除、不移动共享寄存器，不改变字段类型、宽度、字序、缩放、命令值、设备状态或故障码。变化集中在以下运行期契约：

1. 七个命令前置参数从单一共享运行值拆为pending/active快照。
2. CPU3用合法FC10 ACK确认本次字段值和命令资格。
3. CPU3普通运行态、完整参数、固定点结果分别门禁。
4. 普通命令结果不确定不再扩大为整套参数失效。

CPU2 `DeviceParameters`、`struct_size`、magic、元信息、CRC覆盖范围、FRAM A/B地址和单槽容量均不变。协议28的字段代次、pending/active快照和CPU3确认位图都只存在RAM。升级不会因本次改动恢复出厂或清除现场参数。

## 3. 用户决定和明确边界

- 只处理S-01～S-03，S-04～S-06保持现状。
- 恢复出厂命令ACK成功或响应结果不确定时，继续立即关闭参数读取资格并进入全量刷新流程。
- 屏幕与上位机可交错写同一命令参数；不增加端口所有权锁、来源ID、租约或事务号，以命令到达前最后一次CPU2 ACK成功值作为本次命令值。
- 原有命令打断、自中断白名单、重复命令处理、取消语义、单命令槽和CPU2业务状态机不改变。
- 本次不增加自动重发。CPU3仍以CPU2合法ACK作为写成功依据。

## 5. 详细改动

### 5.1 七个命令前置参数建立pending/active快照

- 源码位置：CPU2 `system_parameter.c/.h`、`measure.c`及各测量入口；链路为FC10参数写入 → pending更新/字段代次 → 命令接收时原子绑定active → 命令执行或自动恢复读取active。
- 改前问题：命令执行期间若屏幕或上位机再次修改同一参数，正在执行或恢复的命令可能读取后写值；多个控制端交错时无法固定本次命令参数。
- 具体改法：为七个32位字段维护pending和active。参数ACK成功后更新pending；主循环真正接受命令时一次性获取所需字段到active；本次命令和自动恢复始终读取active，后续写入只影响下一条命令。
- 必查边界：写参数后未发命令、命令等待期间二次写、命令执行中二次写、命令被拒绝、取消、重复命令、自动恢复、CPU2重启。
- 通过标准：本次命令使用启动时绑定值；执行期间后写值不改变本次动作，并成为下一条命令的候选值。

### 5.2 活动态只放开命令相关参数

- 源码位置：CPU2 `hostcommu_modbus.c`、`system_parameter.c/.h`，CPU3 `display_tankopera.c`、`device_param_sync.c`及外部协议写入口。
- 改前问题：统一持久参数写门禁会在测量或运动状态拒绝命令所需的前置参数，导致“先下参数、再下命令”固定返回设备忙。
- 具体改法：只把七个命令前置参数识别为运行态可写；普通持久配置仍执行原有状态、命令队列和故障恢复门禁。CPU2继续保留最终裁决。
- 必查边界：待机、各活动态、完成态、错误态、自动恢复期、普通参数、七字段边界、跨字段FC10。
- 通过标准：活动态可写七字段并获得合法ACK；普通配置在原禁止状态仍返回`0x06`，不得提前改运行态或请求保存。

### 5.3 CPU3逐字段ACK确认和命令资格消费

- 源码位置：CPU3 `cpu2_communicate.c/.h`、`device_param_sync.c/.h`、`param_float32.h`；调用链为外部/屏幕FC10 → CPU2合法ACK → 局部镜像提交和确认位设置 → 命令门禁 → 命令ACK后消费。
- 改前问题：参数写ACK后立即关闭整套参数快照，紧接着的命令会被CPU3本地门禁拦截；命令失败又可能把无关参数全部标记失效。
- 具体改法：七字段写入以合法FC10 ACK直接确认本次值，更新CPU3局部镜像并设置字段位。参数全量补读仍在后台进行；刷新期间只有所需字段全部确认的带参命令可下发。命令ACK或响应结果不确定后只消费该命令实际使用的位。
- 必查边界：单字段和连续多字段写、半字段/奇数地址、参数写标准异常、命令标准异常、命令超时、坏帧、TX DMA未启动、另一命令消费不同字段。
- 通过标准：参数ACK后相应带参命令可立即下发；不相关字段资格不被误清；非法范围和标准异常不能形成确认资格。

### 5.4 S-01：运行态和固定点门禁拆分

- 源码位置：CPU3 `cpu2_communicate.c/.h`、`external_read_freshness.h`。
- 改前问题：普通运行态有效性依赖固定点三步握手，固定点尚未同步时设备状态、错误码、液位等无关数据也返回`0x06`。
- 具体改法：`CPU2_CommHasRuntimeSnapshot()`只要求状态快照、当前连接协议快照、无通信故障且协议严格匹配；新增`CPU2_CommHasFixedPointSnapshot()`，固定点字段单独检查固定点快照。
- 必查边界：首次上电、通信恢复、协议不匹配、固定点同步中、固定点同步失败、普通状态刷新成功。
- 通过标准：普通运行态可在固定点未完成时读取；固定点派生字段仍保持Busy，旧会话固定点结果不得发布。

### 5.5 S-02：LTD FC04按字段选择门禁

- 源码位置：CPU3 `ltd_modbus_slave.c`、`external_read_freshness.h`，并同步DSM、SI、Wärtsilä固定点字段分类。
- 改前问题：LTD FC04依赖完整参数快照，参数写后补读期间全部输入寄存器返回`0x06`；固定点快照又会阻塞无关运行字段。
- 具体改法：LTD FC04普通字段使用运行态门禁；固定点代次`0x0030～0x0033`和单点结果`0x1100～0x113F`额外检查固定点快照；`0x1140`起分布汇总不归入固定点门禁。LTD FC03继续使用完整参数门禁。
- 必查边界：每个区间首末地址、跨普通/固定点范围读取、数量0、越界、参数刷新中、固定点同步中、协议不匹配。
- 通过标准：参数刷新期间普通FC04仍可读；固定点字段未就绪返回`0x06`；FC03在完整参数快照未建立时仍返回`0x06`。

### 5.6 S-03：普通命令失败与参数写失败分类

- 源码位置：CPU3 `cpu2_communicate.c`的请求分类、失败收口和恢复出厂特例。
- 改前问题：测量、移动、取消等普通命令超时或响应不确定时，整套CPU2参数被标记无效，造成所有外部FC03和后续普通命令等待全量补读。
- 具体改法：参数写结果不确定继续调用全量参数刷新；普通命令只消费对应参数确认位，不关闭整套参数快照；恢复出厂保持立即关闭参数读取并等待`parameter_update_flag`变化后全量补读。
- 必查边界：TX DMA启动失败、已发送后超时、UART错误、短帧/坏CRC、标准Modbus异常、恢复出厂ACK成功、恢复出厂响应不确定。
- 通过标准：普通命令失败后无关参数读取仍可用；本命令资格被清除；参数写不确定和恢复出厂继续触发全量刷新。

### 5.7 标准异常和发送启动边界

- 源码位置：CPU3 `cpu2_communicate.c`的`CPU2_CombinatePackage_SendWire()`和失败完成函数。
- 改前问题：如果未区分“请求未发出”“物理响应不确定”“CPU2明确返回标准异常”，可能误消费确认资格或误累计CPU2物理通信失败。
- 具体改法：HAL TX DMA未启动时直接返回，不消费命令参数资格；CPU2标准Modbus异常按确定业务失败返回，不累计物理通信失败；已发出后超时、UART错误或不可验证响应才走响应不确定分支。
- 必查边界：DMA busy/error、异常码`0x01/0x02/0x03/0x06`、响应长度错误、CRC错误、正常ACK。
- 通过标准：未发送请求可原样重试；标准异常不触发全局通信失效；不确定响应不自动重发。

### 5.8 继电器报警配置校验

- 源码位置：CPU2 `relay_alarm_config.c/.h`、`relay_output.c`、参数加载/写入入口。
- 改前问题：禁用通道无法逐步配置，已启用通道可能被单字段写破坏阈值关系；历史NaN/Inf或越界值缺少一致归一化。
- 具体改法：禁用通道允许逐项写入；从禁用切换到启用时执行完整范围和顺序校验。已启用通道的单字段写必须保持完整配置合法。历史非法浮点逐字段归零；只有顺序冲突时保留原值并禁用通道。阻尼预留字段只接受0。
- 必查边界：四通道、正负阈值、罐高相关上限、NaN、Inf、单字段越界、顺序冲突、禁用后重配、启用动作。
- 通过标准：合法配置可逐步建立并启用；任何启用态非法配置均不生效；存储结构、地址和CRC不改变。

## 6. 跨CPU数据流和异常闭环

正常带参命令链路：

1. 屏幕或外部主站写入命令前置参数。
2. CPU3把FC10转发CPU2，等待合法ACK。
3. CPU2更新pending和字段代次；CPU3提交局部镜像、设置字段确认位并安排后台参数补读。
4. 主站或屏幕下发命令。
5. CPU3检查运行态和该命令所需字段确认位后转发。
6. CPU2按原业务门禁决定是否接受；接受时原子绑定active快照。
7. CPU3收到命令ACK后消费该命令对应确认位。
8. CPU2执行及自动恢复使用active；后续参数写只影响下一条命令。

异常闭环：

- 参数写未发送：返回失败，不设置确认位，不消费已有资格。
- 参数写已发送但结果不确定：关闭完整参数快照并立即请求全量补读。
- 普通命令未发送：返回失败，保留确认资格，可由上层重新发起。
- 普通命令已发送但结果不确定：不自动重发，只消费该命令对应资格，避免重复动作。
- CPU2标准异常：作为确定失败返回，不累计物理通信失败。
- 恢复出厂：继续关闭完整参数快照，等待CPU2持久化代次变化后全量补读。
