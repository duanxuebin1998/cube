# CPU2 V1.35.0.0 / CPU3 V1.35.0.0 协议30编码器与掉电恢复改动与测试方案

日期：2026-07-28

## 1. 文档目的和适用版本

本文记录协议30首个正式固件组合的实现范围、兼容边界、可执行测试、已完成验证和未验证风险，供代码复核、台架验证和发布追溯使用。

| 项目 | 旧值 | 新值 |
| --- | --- | --- |
| CPU2固件 | `V1.34.0.0` | `V1.35.0.0` |
| CPU3固件 | `V1.34.0.0` | `V1.35.0.0` |
| CPU2/CPU3共享协议 | `DEVICE_PROTOCOL_VERSION=29` | `DEVICE_PROTOCOL_VERSION=30` |
| CPU2参数存储 | `DEVICE_PARAM_VERSION=3` | 保持3 |
| CPU3本机参数存储 | `CPU3_PARAM_VERSION=0x0007` | 保持`0x0007` |
| 编码器独立位置记录 | V1 | 只写V2，兼容读取V1 |

CPU2和CPU3必须严格使用协议30配套。协议29及更早CPU3不能解释23-1～23-6新故障码，不得与协议30 CPU2混用。

## 2. 参数存储兼容性

- `DeviceParameters`字段、大小、`struct_size`、magic、CRC范围、参数FRAM A/B地址和单槽容量均未变化。
- 从CPU2 V1.34.0.0升级到V1.35.0.0不会因本次改动恢复出厂或清除现场参数。
- CPU3本机参数结构和V7迁移路径未变化，不重建CPU3本机显示/通信参数。
- 编码器位置属于独立记录，不属于`DeviceParameters`。新程序写V2记录，启动时可读取合法V1记录并在后续成功保存时迁移为V2。
- 未发布的中间格式不保留兼容路径；V2即本轮正式发布格式。
- 编码器A/B都无效时不把0当作可信绝对位置，也不自动移动；允许操作者执行明确回零或标定零点重建位置。

## 4. 详细改动清单

### 4.1 编码器连续异常锁存

- 源码位置：`BSP/Peripherals/src/AS5145.c`的采样完成路径；`Services/Encoder/encoder.c`的`Update_Encoder_Count()`、`Encoder_BeginNewProcess()`和锁存状态接口。
- 改前问题：单帧异常、正常帧恢复和故障管理清码边界混在采样链路中，可能出现瞬态误报、正常帧自动清除或测量中途丢失故障证据。
- 具体改法：SPI5中断只解析并投递结果；任意错误类型组成的连续3帧异常即锁存，正常帧只中断连续计数，不清除已锁存故障。新的顶层正式测量或回零流程调用`Encoder_BeginNewProcess()`获得清锁存资格。
- 必查边界：异常类型相同/不同、两帧异常后一帧正常、第三帧锁存、通信恢复、取消命令、内部重试和新正式流程。
- 通过标准：前两帧不进入最终锁存；第三个连续异常帧发布稳定故障快照并禁止运动；正常帧和取消命令不清锁存；新正式流程可按入口规则清除并重新判定。

### 4.2 ISR只投递，PendSV处理延后工作

- 源码位置：`BSP/Peripherals/src/AS5145.c`、`Core/Src/stm32f4xx_it.c`、`Services/Encoder/encoder.c`。
- 改前问题：在SPI DMA回调等中断链路直接执行FRAM访问、日志或复杂状态处理会扩大中断占用，并与主循环参数保存争用SPI4。
- 具体改法：中断只保存采样/事件、置待处理标志并触发PendSV；PendSV处理编码器事件及受限的持久化请求，不在SPI5中断直接写FRAM或打印。
- 必查边界：事件重入、PendSV已有待处理项、紧急保存与普通保存同时到达、AO/UART延后任务排队。
- 通过标准：SPI5 ISR调用链无FRAM写、`printf`和`ErrorLog_*`；事件不会因重复触发丢失；真实最坏PendSV时长由台架测量。

### 4.3 SPI4 FRAM单所有者和有限超时

- 源码位置：`BSP/Peripherals/inc/mb85rs2m.h`、`BSP/Peripherals/src/mb85rs2m.c`及参数、编码器、电机位置调用点。
- 改前问题：旧接口使用`HAL_MAX_DELAY`且忽略HAL状态，并发访问时可能互相打断、死等或把半写数据当成功。
- 具体改法：FRAM接口增加地址/长度检查、忙状态、有限超时和状态返回；调用方只在取得所有权后执行事务并检查结果。
- 必查边界：零长度、越过256 KiB、SPI忙、HAL超时、写使能失败、参数保存与编码器保存并发。
- 通过标准：非法范围在拉低片选前返回；任何HAL阶段失败向上传播；无`HAL_MAX_DELAY`；并发请求不会交叉片选或覆盖同一事务。

### 4.4 编码器A/B V2位置记录和V1迁移

- 源码位置：`Services/Encoder/encoder.c`中的`EncoderPersistRecordV2`、A/B地址、加载和提交逻辑。
- 改前问题：单记录或无提交标记的记录在掉电中断写入时可能留下CRC、代次和内容不一致，启动时难以区分最后完整记录。
- 具体改法：V2记录包含magic、版本、generation、位置、原因、CRC和最终commit marker；先写非提交内容、读回验证，再写提交标记并复核。启动从A/B合法记录中选择新代次，兼容读取V1。
- 必查边界：A有效/B坏、B有效/A坏、同代次、代次回绕、CRC坏、提交标记缺失、写到任一阶段断电、V1首次升级。
- 通过标准：仅完整提交且CRC正确的记录可被采用；单槽损坏可由另一槽恢复；A/B都无效时位置保持不可信；V1合法记录可加载且后续写成V2。

### 4.5 256 counts周期保存

- 源码位置：`Services/Encoder/encoder.c`的`ENCODER_PERSIST_THRESHOLD_COUNTS=256`和延后保存处理。
- 改前问题：只在流程结束或固定时机保存会扩大突然掉电时的位置丢失量。
- 具体改法：可信位置相对最近成功持久化位置累计变化达到256 counts时投递普通保存；保存失败有限重试，不在编码器采样中断同步写。
- 必查边界：正转/反转、跨0点、恰好255/256 counts、高速连续越阈值、FRAM忙和连续失败。
- 通过标准：255 counts不投递，达到或越过256 counts投递；失败不更新“最近成功位置”；最大速度下队列峰值和写入负载需台架通过。

### 4.6 24 V低压检测、恢复和运动门禁

- 源码位置：`Core/Src/adc.c`、`Core/Src/stm32f4xx_it.c`、`Services/power_monitor.c/.h`和运动入口。
- 改前问题：没有可信的早期低压信号时，软件可能继续运动或在供电下降阶段执行普通FRAM写。
- 具体改法：PC2进入ADC1 DMA周期采样；低于换算20 V阈值立即锁存23-1、禁止运动和普通FRAM写并投递紧急保存。恢复到22 V以上连续稳定100 ms后解除低压活动态和普通写门禁；电机仍需新的正式流程重新开放。
- 必查边界：19.99/20.00 V、21 V滞回区、21.99/22.00 V、恢复99/100 ms、恢复期间再次跌落、启动即低压。
- 通过标准：阈值和滞回按宏定义生效；低压首个有效判定后运动禁止；22 V以上不足100 ms不恢复；真实阈值和响应时间需台架校准。

### 4.7 ADC/DMA异常局部恢复

- 源码位置：`Services/power_monitor.c`的`PowerMonitor_TickFromISR()`、`PowerMonitor_ProcessDeferred()`和`PowerMonitor_BeginNewProcess()`。
- 改前问题：DMA停止或ADC OVR会使内存中保留陈旧“电压正常”值；永久要求整机重启影响可用性，直接在ISR重配外设又扩大中断风险。
- 具体改法：每1 ms检查DMA运行和ADC OVR；异常立即锁存对应23-2或23-3并禁止运动，主循环最多执行3次ADC/DMA局部恢复。成功后保留故障快照但允许新的正式流程重新确认监控链路；连续3次失败升级为23-5并保持禁止。
- 必查边界：单次OVR、DMA停止、重启首次成功、第三次成功、三次均失败、恢复后采样仍低压、恢复中收到命令。
- 通过标准：异常检测后不继续相信旧采样；恢复动作不在ISR执行；三次失败报告23-5；恢复成功且电压正常时只由新的正式流程开放运动。

### 4.8 紧急位置保存和可信位置自动布防

- 源码位置：`Services/power_monitor.c`的`PowerMonitor_ArmEmergencyPersistence()`、`PowerMonitor_TickFromISR()`；`Services/Encoder/encoder.c`的紧急保存请求和回执。
- 改前问题：启动时A/B都无效则不布防；后续回零或人工修正建立可信位置后若不重新布防，下一次低压只停机而不保存位置。
- 具体改法：布防函数自身检查可信位置；1 ms Tick发现“尚未布防且位置已可信”时自动布防，覆盖启动恢复、回零和人工修正。真实低压紧急保存总计最多3次，避免PendSV无限重投。
- 必查边界：新设备A/B无效、回零后、标零后、低压已发生时才建立可信位置、连续三次失败和掉电回执不一致。
- 通过标准：位置不可信不投递错误位置；位置一旦可信无需重启即可布防；低压时最多3次尝试；失败或下次启动回执不一致报告23-6。

### 4.9 位置不可信时的命令边界

- 源码位置：`Application/Src/measure.c`、`Application/Src/measure_zero.c`、`Services/Encoder/encoder.c/.h`。
- 改前问题：统一以“位置不可信”拦截全部命令会导致无法执行用于重建位置的回零和标定零点，形成无法自恢复的闭环。
- 具体改法：依赖绝对位置的运动和测量继续被拦截；`CMD_BACK_ZERO`和`CMD_CALIBRATE_ZERO`使用专用准入，允许通过机械零点重建可信位置。
- 必查边界：A/B都无效的新设备、单槽有效、已有锁存故障、回零取消、回零失败、标零失败。
- 通过标准：位置不可信时普通测量不启动电机；回零和标定零点可进入；只有成功建立并持久化的位置变为可信。

### 4.10 标定零点持久化失败传播

- 源码位置：`Services/Encoder/encoder.c`的`set_encoder_zero()`和`Application/Src/measure_zero.c`调用处。
- 改前问题：标零FRAM失败若仍返回成功并继续首圈周长标定，运行态看似完成但重启后位置丢失。
- 具体改法：`set_encoder_zero()`返回实际持久化错误；调用方在失败时停止后续标定并进入统一错误处理。
- 必查边界：A槽失败/B槽成功、A/B都失败、读回不一致、成功保存和断电重启。
- 通过标准：未确认持久化时不继续首圈标定、不报告标零成功；成功时位置可信且可触发紧急保存布防。

### 4.11 参数Modbus成功响应边界

- 源码位置：`Services/ParamStorage/system_parameter.c/.h`和共享Modbus参数写入入口。
- 改前问题：参数先更新RAM后延迟保存，如果把FC10成功解释为“FRAM已落盘”，上位机会误判持久化完成。
- 具体改法：保持最小兼容方案：合法写入更新RAM并响应成功，主循环延迟保存；连续3次持久化失败清待处理并发布存储错误，读回可确认当前RAM值。
- 必查边界：单次保存失败后恢复、连续三次失败、掉电发生在响应后保存前、连续多次写同字段。
- 通过标准：协议成功仅代表RAM接受；错误状态能暴露最终保存失败；不修改既有FC10时序和ACK格式。

### 4.12 协议30故障码和CPU3显示

- 源码位置：CPU2 `fault_manager.h`、`error_log.c`；CPU3 `system_parameter.h`、`display.c`；正式故障码工作簿和当前清单。
- 改前问题：复用电荷泵欠压会混淆真实低压、监控链路异常和保存失败，也无法给出不同恢复动作。
- 具体改法：新增23-1～23-6独立共享故障，CPU2发布完整码，CPU3按同值显示对应原因；共享寄存器地址、宽度和字序不变。
- 必查边界：两端枚举一致、名称/原因覆盖、优先级升级、未知旧CPU3、OLED四行空间和字库。
- 通过标准：双端数值一致且唯一；协议30 CPU3可显示六种原因；协议29及更早组合被严格版本门禁阻止；真实OLED需台架确认。

## 5. 跨模块异常闭环

正常路径：ADC/DMA持续采样24 V，编码器采样更新可信位置；累计256 counts时投递普通保存；正式流程开始前同时检查编码器和电源监控门禁。

真实低压路径：ADC看门狗或周期检查发现低于20 V，立即禁止运动和普通FRAM写，投递紧急位置保存；PendSV/延后处理完成最多3次A/B提交；22 V以上稳定100 ms后恢复普通写，新的正式流程再决定是否开放运动。

监控异常路径：1 ms检查发现OVR或DMA停止，立即禁止运动并投递主循环恢复；恢复成功后重新使用新样本判断低压，三次失败报告23-5并保持禁止。

位置重建路径：A/B都无效时位置不可信，普通测量被拦截；操作者执行回零或标定零点，成功保存后位置可信；Tick自动重新布防紧急保存，无需整机重启。
