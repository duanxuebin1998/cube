# CPU2 V1.11.0.1 BSP 外设驱动目录整理改动与测试方案

## 版本变化

- CPU2: V1.11.0.0 -> V1.11.0.1
- CPU3: 未变化，保持 V1.9.0.0
- `DEVICE_PROTOCOL_VERSION`: 不变

## 协议版本与兼容性

- 本次不修改 CPU2/CPU3 共享命令、共享状态、共享参数语义、寄存器映射或共享结构体契约。
- 外设驱动文件内容保持不变，仅调整目录位置；头文件名、函数名、宏定义和上层 include 方式保持兼容。
- 固件版本升级为 build 级别，仅用于追踪本次构建组织调整。

## 详细改动

- 将 CPU2 项目外设驱动从 `LTD_MAIN_CPU2/Drivers/Peripherals` 迁移到 `LTD_MAIN_CPU2/BSP/Peripherals`。
- 迁移范围包括 TMC5130、AS5145、CH9141EVT、MB85RS2M 和 AD5421 的 `inc`、`src` 文件。
- 更新 `LTD_MAIN_CPU2/CMakeLists.txt`，从 `BSP/Peripherals/src` 收集源码，并将 `BSP/Peripherals/inc` 加入 include path。
- 同步更新 CPU2 文档中引用旧 `Drivers/Peripherals` 路径的位置。

## 影响范围

- 影响 CPU2 构建组织和源码目录归属。
- 不影响 CPU2 运行逻辑、外设初始化参数、Modbus/HART/传感器协议行为、参数存储格式或 CPU3 显示行为。
- `Drivers/` 目录后续主要保留 CubeMX/CubeIDE 带入的 HAL/CMSIS 内容，项目板级外设驱动归入 `BSP/`。

## 重点测试点

1. 构建系统能找到迁移后的外设驱动源码。
2. 上层仍能通过原头文件名 include 外设驱动。
3. 旧路径在源码和构建脚本中不再作为活动引用残留。
4. 构建产物版本号更新为 `V1.11.0.1`。

## 测试步骤与预期结果

### 1. 旧路径残留检查

准备条件：
- 工作目录为 `D:\CUBE`。

步骤：
- 搜索 `Drivers/Peripherals` 旧路径。

预期结果：
- 源码、CMake 和 CubeIDE 配置中无旧路径活动引用。
- `Debug/`、`Release/` 下历史构建产物如仍含旧路径，不作为源码问题，后续 clean/rebuild 会重建。
- CHANGELOG、版本改动方案等迁移说明文本可以保留旧路径作为对照记录。

### 2. CPU2 构建检查

准备条件：
- 已存在 `build\LTD_MAIN_CPU2` 构建目录。

步骤：
- 运行 `cmake --build build\LTD_MAIN_CPU2`。

预期结果：
- 构建成功。
- 构建日志出现 `BSP/Peripherals/src/*.c` 编译项。
- 输出 `LTD_MAIN_CPU2_V1.11.0.1.hex`。

### 3. 提交前检查

步骤：
- 运行 `git diff --cached --check`。
- 运行 `py tools\check_version_bumped.py`。

预期结果：
- 暂存区无空白错误。
- 版本检查通过。
