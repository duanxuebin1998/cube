### 1.1 新参数

| 字段 / 菜单 | 寄存器 | 类型、单位 | 范围 | 默认值 |
| --- | --- | --- | --- | --- |
| liquidLevelReferenceRefreshEnable / 定时矫正 | 0x0904～0x0905 | UInt32，高字在前；开关 | 0 关闭，1 开启 | 0 |
| liquidLevelReferenceRefreshIntervalMin / 矫正周期 | 0x0906～0x0907 | UInt32，高字在前；分钟 | 60～10080 | 1440 |

两个字段分别位于结构偏移 132、136。周期及开关属于已有液位参数组，沿用跟随期间禁止修改参数的约束，不新增运行中改参入口。开关使用既有确认页；周期使用数值编辑。刷新结果只更新 RAM，不每轮写 FRAM。

对外统一称为“液位定时矫正”。参数全称分别为“液位定时矫正开关”和“液位定时矫正周期”；列表短名为“定时矫正”和“矫正周期”。内部字段、函数及文件标识保留 `ReferenceRefresh`，本次命名修订不改变算法、寄存器、单位、范围、默认值或参数存储布局，合入同一次提交，不另升版本。

### 1.2 参数存储兼容性

协议 33/34/35 的合法旧参数载入后，新字段补为关闭和 1440 分钟，不能把原保留区内容当成开关或周期。既有参数及 AO 千分之一毫安单位保留；协议 36 合法字段保持原值。结构长度、CRC 位置与存储版本均不变。本次没有新增“某个旧固件升级必清参数”的规则；原有 CRC 损坏、格式非法等恢复机制仍按既有逻辑执行。

现场升级前导出参数并记录固件/协议、AO 配置、液位方式和跟随目标。成对升级后回读参数，确认旧参数保留、新参数默认为关闭，再由操作者明确开启。仅更新一块 CPU 的协议版本不一致组合应被兼容检查拦截。回滚也必须成对处理并复核参数，不把新版保留字段语义假定为旧版支持。

## 3. 逐项改动

### 3.1 进入跟随、计时与退出

- 源码位置：`oil_level_follow.c` 调用 `OilLevelReferenceRefresh_EnterFollow/LeaveFollow`；`oil_level_reference_refresh.c` 的 `RefreshPollWindow`、`OilLevelReferenceRefresh_Poll`；`oil_level_refresh_policy.c` 的 `OilLevelRefresh_InitSchedule/PollReady/Begin`。
- 改前问题：长期跟随没有统一的周期基准刷新调度，无法按配置完成复测和恢复闭环。
- 具体改法：开启后从首次稳定、停止且无故障的窗口开始计时；到期置待执行标志，等安全稳定窗口执行。成功后重新计周期。同一配置正常退出/重新进入保留应执行信息与连续失败计数；实际故障或配置变化按入口逻辑重建调度。普通停止不是故障，也不是持续检测丢步的理由。
- 必查边界：开关关闭、周期两端、未稳定、切换状态、取消、重新进入、配置变更、计时回绕。
- 通过标准：未到期不启动；到期不打断不稳定运动；取消后无输出冻结遗留；正常长时间停止不因刷新新增丢步报警。

### 3.2 油中与空气采样

- 源码位置：`oil_level_reference_refresh.c` 的 `RefreshFrequencyRound`、`RefreshSeekPhase`、`RefreshMoveEndpoint`、`RefreshAverage`、`OilLevelReferenceRefresh_Read`。
- 改前问题：缺少长期运行期间重新测量油中/空气基准的流程；不能直接拿可能已异常的实际跟随目标判断介质侧。
- 具体改法：使用配置的安全中间频率 `oilLevelFrequency`（默认 5200）分辨油中/空气。先找油，严格小于阈值后停止并再下行 100 mm；取 10 次读数，每次后等待 2 秒，排序去掉最高和最低各 2 个，余下 6 个取四舍五入平均。再找空气，严格大于阈值后停止并再上行 100 mm，同样采样。频率 0 按未稳定处理，停机、重置运动判据并在预算内等待，不计入有效样本；传输/帧错误按原错误返回。
- 必查边界：等于安全阈值、频率 0、1、6500、越界值；持续未稳定；停止到运动的阶段切换；端点移动和运动超时。
- 通过标准：油、空气采样顺序固定；相等不误判跨界；无效读数不污染平均；碰撞、位置越界和真实通信错误不会被候选重采掩盖。

### 3.3 候选基准与重新定位

- 源码位置：`oil_level_refresh_policy.c` 的 `OilLevelRefresh_BuildFrequencyCandidate`；`oil_level_reference_refresh.c` 的 `RefreshLocate/RefreshPublish`；步进及连续搜索入口、`oil_level_runtime.c` 的 `OilLevelRuntime_CommitReference`。
- 改前问题：若直接覆盖旧基准，候选失败时无法保证继续使用完整有效的一组参考数据。
- 具体改法：新油/空气频率均须在 1～6500、空气大于油、差值大于 400；目标须严格位于油频率加 200 与空气频率减 200 之间。方式 0/4 使用中点，方式 1/5 保持原固定跟随频率，但也刷新两侧基准并检查其可用性。通过后下行 100 mm，按原步进或连续算法重新找液位，完成安全检查后才同时发布新参考和液位。
- 必查边界：差值 400、401、402；目标恰在两侧 200 边界；固定目标在新有效区间外；重新定位中断。
- 通过标准：边界相等拒绝；差值 401 的整数中点不能满足严格间隔时拒绝；任何未完成候选均不作为成功基准发布。

### 3.4 输出保持、安全检测与时间预算

- 源码位置：`oil_level_runtime.c/.h` 的输出保持入口；`OilLevelReferenceRefresh_Check/Delay`、`RefreshCheckSafety`；`motor_ctrl_motion_api.c` 的 `MotorCtrl_MoveAndWaitUntil`；对应 `motor_ctrl.h` 声明。
- 改前问题：探头离开液面会使内部位置偏离当前液位；采样停机与运动阶段若共用错误的检测状态，会误判丢步或丢失限时控制。
- 具体改法：频率刷新期间保留最后有效液位及其发布状态，依赖该液位的输出继续消费保持值；实际探头位置、限位/碰撞检查与其他测量量并不全部冻结。主动停机采样只执行适用的位置和碰撞检查；运动阶段在命令成功后启用相应丢步监控，阶段入口清理历史窗口。新限时移动 API 使用可选截止检查，原公共 API 的调用语义保持不变。候选采样预算 180 秒、整轮及保持预算 300 秒、恢复预算最多 120 秒且包含在整轮预算内。
- 必查边界：停止、运动命令失败、命令后堵转、通信等待跨截止时刻、慢停、取消、故障输出策略。
- 通过标准：离液面期间外发液位不随探头位置跳动；运动堵转不因驱动状态变化漏检；故障退出执行原安全/无效化路径。预算为检查点协作式约束，不宣称墙钟严格不超过 300 秒。

### 3.5 失败恢复与重试

- 源码位置：`RefreshFrequencyRound`、`OilLevelRefresh_StartRollback/DeferAfterRecovery/CancelActive`。
- 改前问题：新增刷新必须有明确恢复条件，不能盲目重用已经被有效数据否定的旧目标，也不能无限重试或一直保持旧输出。
- 具体改法：采样阶段最多 3 组候选，共享 180 秒预算；特定安全/通信错误直接退出，不当作普通候选无效重试。新有效油/空气对已证明旧目标不满足严格 200 间隔时，记住旧目标被否定，不允许后续失败将其重新当作恢复依据。仅在旧基准仍有效且有预算时，按旧目标重新寻找真实液位；不是返回旧机械位置。前两次整轮失败在成功恢复后等 5 分钟再试，连续第三次整轮失败退出故障。无法恢复或恢复失败立即退出；有具体错误时优先保留具体错误。
- 必查边界：第一次有效候选否定旧目标后第二次采样失败；旧基准无效；恢复前预算不足；第 2/3 次整轮失败；取消不增加失败计数。
- 通过标准：不发布失败候选；不使用已否定旧基准继续跟随；成功恢复释放输出保持；达到失败上限有明确故障而非永久重试。

### 3.6 密度方式 2 复核

- 源码位置：`oil_level_density.c` 调用 `OilLevelReferenceRefresh_DensitySample`。
- 改前问题：密度找液位也需要周期复核，但无需为了复核另找空气和油中频率。
- 具体改法：方式 2 保持原闭环，不主动离开液位、不冻结输出、不改变目标密度。触发当次不计数，随后连续 3 次稳定、驱动停止且密度/频率/温度为有效有限值的读取完成复核；按已确认口径，重复缓存也计数，不引入数据新旧门禁。不稳定/无效时清连续计数。复核窗口 300 秒；到期仍不稳定或运动中则失败退出，稳定但未完成按 5 分钟延期和连续 3 次失败限制处理。方式 3 不接入。
- 必查边界：相同缓存重复 3 次；中间一次不稳定或非有限值；到期瞬间仍运动；切换方式；正常 1 秒读取节奏。
- 通过标准：触发读数不算第 1 次；完整连续 3 次后成功；不新增空气搜索、目标密度改写或人为输出冻结。正常额外等待约 3 秒加读取耗时，不保证传感器阻塞时仍为 3 秒。

### 3.7 参数链路与界面

- 必查边界：0/1/2，周期 59/60/10080/10081；取消确认；双端协议不一致；掉电后回读；全量参数同步和部件参数读取。

## 4. 数据流与异常闭环

CPU3 液位菜单/标准 Modbus 写入 → 已有参数状态门禁 → CPU2 参数校验及存储 → 双端同步和回读 → 进入液位跟随 → 首个稳定窗口起计时 → 到期等待安全窗口。

频率方式：保持外发液位 → 找油与采样 → 找空气与采样 → 检查新目标 → 原算法重找液位 → 一次发布并恢复跟随。失败则先判断具体错误、旧基准可用性和时间；允许恢复时按旧目标重找液位，成功恢复后延期或达到第 3 次失败上限；不能恢复则终止并报告故障。

密度方式：原闭环继续 → 触发读数排除 → 连续 3 次合格读取 → 完成并重新计时；中途不合格清计数，超时依稳定状态决定延期或故障。两条路径均不周期写 FRAM。
