## 4. 详细改动

### 4.1 按距离和生效速度计算单次目标运动等待预算

- 源码位置：`LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_motion_api.c`的`MotorCtrl_MoveAndWait()`；调用链为`MotorMotion_BeginSpeedScope -> MotorMotion_BuildRelativeTargetPlan -> MotorCtrl_MoveNoWait -> MotorMotion_WaitUntilStopWithTarget`。
- 改前问题：所有普通阻塞目标运动统一使用固定`3600000 ms`上限；同一目标运动在低速度或长距离条件下，即使仍按计划运行，也可能在1小时后返回`MOTOR_RUN_TIMEOUT`。
- 具体改法：临时速度生效并完成目标规划后读取当前线速度设定，计算`理论时间(ms) = 计划距离(mm) × 60 ÷ 生效线速度(m/min)`；允许时间取`max(3600000 ms, 理论时间 × 2 + 60000 ms)`并在启动运动前固化，本次运动进展不重置该预算。
- 必查边界：距离小于等于0的原提前返回；0.10～6.00 m/min速度限幅；允许时间恰好落在1小时下限两侧；最大合法行程；`uint32_t`换算；HAL Tick回绕；命令切换、位置刷新、碰撞和驱动健康错误先于超时退出。
- 通过标准：短距离仍至少保留1小时预算；长距离或低速度按公式获得更长预算；预算只计算一次并传给目标等待函数；其它保护顺序和返回码不变。

### 4.2 超时日志区分实际时间和允许时间

- 源码位置：`MotorMotion_WaitUntilStopWithTarget()`的超时判断和`ErrorLog_WarnDetail()`调用。
- 改前问题：日志只输出固定超时常量，无法区分现场实际等待时长与本次允许运行预算。
- 具体改法：每轮以`HAL_GetTick() - startTick`计算已运行时间；超过本次`max_wait_ms`后，结构化日志和普通打印同时输出当前位置、目标位置、已运行毫秒数和允许毫秒数，仍返回`MOTOR_RUN_TIMEOUT`。
- 必查边界：Tick正常递增与单次回绕；日志缓冲区长度；目标到位、驱动停止、命令切换、碰撞和健康错误不得误报为运行超时。
- 通过标准：真实超时日志能同时看到“已运行”和“允许”两个值，且错误码和停机出口保持原语义。
