## 命名规则

- 项目自有 Markdown 文档优先使用中文业务名，必要时加日期：`YYYY-MM-DD_主题_文档类型.md`。
- 版本改动与测试方案使用：`YYYY-MM-DD_CPU2_Vx_CPU3_Vy_主题_改动与测试方案.md`。
- `版本改动与测试/` 是后续版本提交和 skill 生成新方案的输出区；新增方案后可先提交版本资料，`版本总览.md` 和人工索引允许后补。
- 第三方芯片、协议、工具和供应商资料可保留英文或原厂文件名，但必须放入对应业务目录的 `00_原始资料/`、`00_外部资料/` 或芯片手册目录。
- HTML 页面当前作为流程图、结构图或历史阅读页保留；长期维护结论应回到 Markdown 或源码依据。
- PDF、DOCX、XLSX 默认视为外部资料、导出件、测试附件或维护表；是否可改必须看所在 README。

## 入口页职责

- `docs/README.md` 和各一级目录 `README.md` 只回答“先看哪里、按什么边界维护”，不承载完整历史表、长清单或全文复盘。
- 历史版本、附件清单、新增资料落位、流程排查、问题专题和 SIL 外部资料等长列表，分别放入 `版本总览.md`、`附件与源文件清单.md`、`新增资料落位检查表.md`、`流程排查入口.md`、`问题专题索引.md` 和 `资料用途矩阵.md`。
- `assets/` 这类支撑资源目录只存放 HTML 页面使用的 CSS、JS 或图形脚本，不作为业务资料入口；新增业务说明不能放入资源目录。
- 如果某个 README 超过 60 行，后续优先判断是否应拆出专题索引或清单页；拆分后的索引仍是人工查找入口，不改变 skill 生成版本文档规则。
