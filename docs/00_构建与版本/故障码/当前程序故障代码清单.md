# 当前程序故障代码清单

更新日期：2026-07-14

本文记录当前源码中的故障码定义、屏幕编号和兼容性口径。正式中文说明、处理方法、设备参数和测量结果以 `LTD故障代码统一表.xlsx` 为准；内部调用点、完整码和编号迁移保存在 `LTD内部技术与治理资料.xlsx`。

## 当前口径

- CPU2 `ErrorCode` 共65项，其中2项是非故障状态，实际共享故障码63项。
- CPU3同步CPU2的65项定义，并额外定义本机故障 `CPU2_COMM_TIMEOUT = 0x00140007`，屏幕显示 `20-7`。
- 正式工作簿收录64个故障项目：63个共享故障码和1个CPU3本机故障码；其中使用中61项、保留3项。
- 屏幕使用十进制“类别代码-故障码”，例如 `13-3`；不显示十六进制完整码。
- CPU2和CPU3的 `DEVICE_PROTOCOL_VERSION` 均为17。本版重新分类并调整子码，协议16及更早版本不能按当前编号直接解释。
- 故障状态寄存器地址和宽度不变，仍传递32位故障码；参数存储结构和 `DEVICE_PARAM_VERSION` 不变。
- 现场按CPU2程序版本选择共享故障码表；共享协议版本只用于CPU2与CPU3配套兼容判断。

## 按CPU2程序版本归档

- “历史故障代码_CPU2V1.24.0.0”工作表冻结CPU2 V1.24.0.0开发基线，保留75个共享故障码和当时的CPU3本机故障记录，不随后续重编号改写。
- 当前“故障代码”工作表对应CPU2 `V1.25.0.0`故障码基线；配套CPU3版本为 `V1.23.0.0`。
- CPU3本机 `20-7` 不属于CPU2共享故障码选表范围，应按CPU3程序版本单独确认。
- 历史编号不得复用于新的故障含义。

## 一代计量仪历史资料

- “一代计量仪历史故障代码”工作表归档资料版本v1.0（2026-05-23），包含106项两段式故障代码和1项特殊通信代码 `1F1-0～500`。
- 一代设备先确认设备代际，再按一代计量仪主控程序版本和表内说明查表；不得与二代当前表混用。
- 二代类别优先采用一代类别加10：11电机、12编码器、13传感器、14位置检测、15测量过程、17参数与存储、18模拟输出与自检。10、16、19保留代际对应类别但当前不分配故障码；20～22为二代新增责任域。

## 保留编号

以下3项保留现有含义，不在当前流程主动产生；启用前必须补齐调用点和验证。

`ENCODER_POWERON_CHANGE`（12-6）、`MEASUREMENT_HEIGHT_DEVIATION`（15-16）、`WEIGHT_SENSOR_SATURATION`（21-5）。

## 移出当前枚举

以下12项只保留在CPU2 V1.24.0.0历史表，新程序不再定义，旧编号不复用：

`MOTOR_FAIL_SETTING`、`MOTOR_RESET_FAIL`、`SLIPRING_BCC_ERROR`、`SLIPRING_PACKET_LOSS`、`SENSOR_TEMPERATURE_ERROR`、`SENSOR_VOLTAGE_ERROR`、`DENSITY_UNSTABLE`、`MEASUREMENT_DENSITY_RANGE_INVALID`、`AD5421_FAULT_PIN_ERROR`、`OTHER_UNKNOWN_ERROR`、`OTHER_ADDRESS_READ_ERROR`、`OTHER_POWER_FLUCTUATION`。

## 维护要求

1. 新增或调整共享故障码时，同时修改CPU2枚举、CPU2日志、CPU3枚举、CPU3显示、正式工作簿和内部技术工作簿。
2. 只有CPU3本机产生且不属于CPU2共享枚举的故障，才使用CPU3本机扩展码。
3. 具体底层错误已经取得时，不得在上层改写成通用失败码。
4. 新编号不得复用历史值；迁移关系追加到内部工作簿“编号迁移”表。
5. 共享故障码取值或解释变化时，同步提升 `DEVICE_PROTOCOL_VERSION` 并记录兼容影响。
6. 修改CPU3中文显示后运行字库检查；修改源码后运行故障码契约检查和CPU2/CPU3构建。
7. 一代和CPU2历史页只按核验过的历史资料追加或勘误，不按当前源码反向改写。
