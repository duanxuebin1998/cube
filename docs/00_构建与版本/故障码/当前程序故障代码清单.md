# 当前程序故障代码清单

更新日期：2026-07-16

本文记录当前开发源码中的故障码定义、屏幕编号、一代对照和版本兼容口径。正式中文说明、可能原因和现场处理方法以 `LTD故障代码统一表.xlsx` 为准；完整调用点、拆分来源和编号迁移以 `LTD内部技术与治理资料.xlsx` 为准。

## 当前口径

- CPU2 `ErrorCode` 共131项，其中2项为非故障状态、129项为CPU2/CPU3共享故障。
- CPU3共133项定义：同步CPU2的131项，并额外保留2个本机故障：`CPU2_COMM_TIMEOUT = 0x00140007`（屏幕显示 `20-7`）和 `CPU2_PROFILE_SYNC_FAILED = 0x0014000D`（屏幕显示 `20-13`）。
- 正式工作簿当前页共131个故障项目：129个共享故障和2个CPU3本机故障；其中使用中128项、保留3项。
- 屏幕使用十进制“类别代码-故障码”，例如 `13-3`；正式工作簿不使用十六进制编号作为现场查询入口。
- 当前源码的 `DEVICE_PROTOCOL_VERSION` 为25。协议25沿用协议22重排、协议23正式发布的现行故障编号，故障项目数量、故障寄存器地址、宽度和32位传递方式不变。
- CPU2 `V1.30.0.0`、CPU3 `V1.29.0.0`是协议25首个正式组合，使用现行页；协议23/24组合使用相同现行编号，CPU2 V1.27.0.0、CPU3 V1.25.0.0的协议21组合必须查询CPU2 V1.27.0.0历史页，协议22未单独发布。
- CPU2 `DEVICE_PARAM_VERSION` 仍为3，`DeviceParameters` 结构、大小和校验范围未变；本次故障码拆分不会清除现场参数。
- 现场查询CPU2产生的共享故障时，先确认设备代际，再按CPU2程序版本选择故障表；`DEVICE_PROTOCOL_VERSION` 只用于CPU2与CPU3严格配套判断。CPU3本机 `20-7`、`20-13` 按CPU3程序版本确认。

## 一代与二代的编号关系

- 二代优先采用“一代类别加10、同含义保留子码”，例如一代 `3-3` 传感器无响应对应二代 `13-3` 传感器通信超时。
- 只有责任域、现场现象和处理方式一致时才沿用一代子码；一代一个大类被拆成多个可定位故障时，二代新增子码并在表中保留一代来源。
- 二代新增责任域使用20设备通信链路、21扭力检测、22系统与软件。10、16、19只保留代际类别位置，当前不分配故障码。
- 一代已有编号不得改作完全不同的二代含义；二代新增项目从不占用一代既有含义的最低可用子码开始安排。

## 维护要求

1. 新增、拆分或调整共享故障码时，同步修改CPU2枚举和产生路径、CPU2日志名称和原因、CPU3枚举和显示、正式工作簿、内部技术工作簿及协议记录。
2. 具体故障已经能够判断时，不得再压缩成一个跨责任域或跨处理方式的通用码；同一代码允许覆盖的多个触发点必须具有相同现场含义和处理方式。
3. 新编号优先保持一代对照，但不得为了编号相似把不同责任域或不同处理方法合在一起。
4. 二代历史、保留和取消项目保留在对应CPU2版本页；后续版本可以复用相同编号，迁移关系追加到内部工作簿“编号迁移”表，现场不得脱离CPU2程序版本解释。
5. 共享故障码取值或解释变化时，同步提升 `DEVICE_PROTOCOL_VERSION`；现场选表仍按CPU2程序版本，不按共享协议版本替代。
6. 修改CPU3中文显示后检查字库；修改源码后运行故障码契约、相关专项检查和CPU2/CPU3构建。
7. 一代、CPU2 V1.24.0.0、CPU2 V1.25.0.0～V1.26.0.0和CPU2 V1.27.0.0历史页只按核验过的历史资料追加说明或勘误，不按当前源码反向改写。
