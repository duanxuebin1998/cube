# 当前程序故障代码清单

更新日期：2026-07-01

本文按当前源码整理 CPU2/CPU3 程序使用的故障代码，便于在 Git diff、现场日志和协议资料中直接检索。故障码定义权威来源仍是 CPU2 `ErrorCode` 枚举；CPU2 Excel 表是表格维护入口，CPU3 Excel 表只作为显示、保持寄存器和 `param_meta` 辅助资料。

## 整理依据

| 对象 | 路径 | 口径 |
| --- | --- | --- |
| CPU2 故障码定义 | `LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.h` 的 `ErrorCode` | 最终定义来源 |
| CPU2 日志名称和原因 | `LTD_MAIN_CPU2/Services/Utilities/error_log.c` 的 `ErrorLog_GetCodeName()` / `ErrorLog_GetReasonByCode()` | 串口日志和最终报错原因 |
| CPU3 兼容枚举 | `LTD_DISPLAY_CPU3/Application/system_param/system_parameter.h` 的 `ErrorCode` | 与 CPU2 保持一致；额外保留 `SENSOR_COMM_TIMEOUT` 兼容别名 |
| CPU3 屏幕显示 | `LTD_DISPLAY_CPU3/Application/display/display.c` 的 `Display_GetErrorReasonByCode()` | 状态页和故障详情显示文案 |
| CPU2 表格 | `docs/00_构建与版本/故障码/CPU2/LTD故障代码表.xlsx` | 当前 73 项，与 CPU2 `ErrorCode` 一致 |
| CPU3 表格 | `docs/00_构建与版本/故障码/CPU3/LTD故障代码表.xlsx` | 辅助资料，不作为定义源 |

## 当前结论

- 当前 CPU2 `ErrorCode` 共 73 项，含 `NO_ERROR` 和 `STATE_SWITCH` 两个非故障状态。
- CPU2 `LTD故障代码表.xlsx` 的总表也是 73 项，和当前 CPU2 `ErrorCode` 无缺失、无多余。
- CPU3 `ErrorCode` 与 CPU2 保持同值同步，`SENSOR_COMM_TIMEOUT = SENSOR_DEVICE_COMM_TIMEOUT` 只是兼容别名，不新增独立故障码。
- `AD5421_*` 5 项当前归入 `0x00130000 - 0x0013FFFF` 其他错误区间。
- 当前错误码格式为 `0x00TT000N`，其中 `TT` 是类型代码，`N` 是子代码；存在跳号时按源码保留，不补写历史未使用码。

## 类别速查

| 类型代码 | 区间 | 当前项数 | 说明 |
| --- | --- | ---: | --- |
| `0x00` | `0x00000000 - 0x00000001` | 2 | 正常状态和状态切换，非故障 |
| `0x0B` | `0x000B0000 - 0x000BFFFF` | 10 | 电机类故障 |
| `0x0C` | `0x000C0000 - 0x000CFFFF` | 10 | 编码器类故障 |
| `0x0D` | `0x000D0000 - 0x000DFFFF` | 15 | 传感器、密度、无线滑环和蓝牙链路故障 |
| `0x0F` | `0x000F0000 - 0x000FFFFF` | 15 | 测量过程故障 |
| `0x11` | `0x00110000 - 0x0011FFFF` | 6 | 参数存储和参数调用故障 |
| `0x12` | `0x00120000 - 0x0012FFFF` | 6 | 扭力类故障 |
| `0x13` | `0x00130000 - 0x0013FFFF` | 9 | 其他系统错误和 AD5421 错误 |

## 上报和显示路径

| 场景 | 当前路径 |
| --- | --- |
| CPU2 内部故障状态 | 业务代码写入 `g_measurement.device_status.error_code`，最终报错优先走 `fault_manager` 统一出口 |
| CPU2 到 CPU3 共享寄存器 | CPU2 写 `REG_DEVICE_STATUS_ERROR_CODE`，CPU3 在内部 Modbus 轮询中读取到 `g_measurement.device_status.error_code` |
| CPU3 屏幕状态页 | `Display_GetErrorReasonByCode(error_code)` 把错误码转成屏幕故障原因 |
| DSM 外部协议 | `INPUTREGISTER_ERRORNUM` 写入 32 位 `g_measurement.device_status.error_code` |
| SI协议 | `10004 Interlock` 当前由 `error_code != NO_ERROR` 或 `profile_blocked_by_process` 合成；`10009 Reel Alarm` 当前由 `error_code != NO_ERROR` 合成 |
| AO/AD5421 运行态 | `REG_AO_OUTPUT_RUNTIME_LAST_ERROR_CODE` 上报 AO 输出最近错误码，系统故障仍以 `device_status.error_code` 为主 |

## 维护检查项

新增、删除或改写故障码时，按下面顺序检查：

1. CPU2 `ErrorCode` 是否新增或改值。
2. CPU2 `ErrorLog_GetCodeName()` 是否有名称覆盖。
3. CPU2 `ErrorLog_GetReasonByCode()` 是否有原因覆盖；没有具体覆盖时是否允许走大类兜底。
4. CPU3 `ErrorCode` 是否同步，是否需要保留兼容别名。
5. CPU3 `Display_GetErrorReasonByCode()` 是否覆盖屏幕显示文案。
6. CPU2 `LTD故障代码表.xlsx` 是否同步；必要时再同步 CPU3 辅助表。
7. 如果改变共享协议字段、错误码语义或外部协议映射，检查 `DEVICE_PROTOCOL_VERSION`、协议变更记录和版本改动与测试方案。
