# 故障码资料入口

更新日期：2026-07-27

本目录统一维护二代计量仪CPU2/CPU3故障码的正式资料、内部技术资料和历史表。协议19故障码没有形成独立固件，随共享协议21在CPU2 `V1.27.0.0`、CPU3 `V1.25.0.0`组合中发布。协议22也未单独发布，其重排编号随协议23组合首次正式发布。最新正式协议30对应CPU2/CPU3 `V1.35.0.0`组合，在协议29取消12-11、交换18/21故障类别并提高13-26密度上限的基础上，新增6个23类整机供电与电源监控故障。

| 文件 | 用途 |
| --- | --- |
| `LTD故障代码统一表.xlsx` | 正式工作簿，当前页按协议30开发口径维护，并包含CPU2 V1.27.0.0、V1.25.0.0～V1.26.0.0、V1.24.0.0及一代历史页、设备参数和测量结果 |
| `LTD内部技术与治理资料.xlsx` | 内部维护工作簿，保存完整码、内部标识、调用点、链路复查、分类规则、治理摘要、一代对照和分阶段编号迁移 |

| `故障码整体治理执行、当前进度与窗口交接计划.md` | 本轮长期计划执行情况、当前进度、剩余发布和台架工作 |

当前正式工作簿开发页收录136个故障项目：134个CPU2/CPU3共享故障码和2个CPU3本机故障码；使用中132项、保留4项。`NO_ERROR`、`STATE_SWITCH` 两个非故障状态只保存在源码、当前清单和内部技术资料中。

现场查询顺序为：先确认一代或二代，再按CPU2程序版本选择共享故障表。CPU3本机 `20-7`、`20-13` 单独按CPU3程序版本确认。`DEVICE_PROTOCOL_VERSION` 用于判断CPU2与CPU3能否配套运行，不替代现场选表所需的CPU2程序版本。

历史页分四层维护：

- `历史故障代码_CPU2V1.27.0.0` 保存CPU2 V1.27.0.0、CPU3 V1.25.0.0、共享协议21使用的130个故障项目。
- `历史故障代码_CPU2V1.25.0.0-V1.26.0.0` 保存该CPU2版本范围的64个历史故障项目，包含当前开发版拆分前的10个通用码。
- `历史故障代码_CPU2V1.24.0.0` 保存更早开发基线，包含协议17阶段已停用的12项。
- `一代计量仪历史故障代码` 归档一代资料版本v1.0（2026-05-23），只用于一代设备。

二代编号优先采用“一代类别加10、相同含义保留子码”。责任域或现场处理方式不同必须拆分；一代没有直接同义项时，从不占用一代既有含义的最低可用子码开始安排。二代不同CPU2程序版本允许复用相同编号，历史页内容保持不变，现场必须按CPU2程序版本解释。

当前有故障码的类别为11电机驱动、12编码器、13传感器与密度、14零点与位置检测、15测量过程、17参数与存储、18扭力检测、20设备通信链路、21模拟输出与自检、22系统与软件、23整机供电与电源监控。10、16、19保留代际类别位置但当前不分配故障码。协议30新增共享故障码数值和解释，CPU2/CPU3必须配套升级；正式发布版本号待发布阶段统一处理。
