## 当前治理结论

- `LTD_MAIN_CPU2/docs/` 和 `LTD_DISPLAY_CPU3/docs/` 已不再作为文档保存位置。
- 使用者入口是 `docs/README.md`，维护者入口是 `docs/00_构建与版本/文档库治理清单.md`。
- CPU2/CPU3 单侧资料不再按子项目目录查找，而是按整机业务域进入。
- `版本总览.md`、`附件与源文件清单.md`、`流程排查入口.md`、`问题专题索引.md` 和 SIL `资料用途矩阵.md` 是人工查找索引，不改变 skill 生成版本文档的路径和规则。
- `docs-site/` 只作为本机预览工具；同步源应只有 `docs/`，不要手工维护 `docs-site/src/content/docs/` 下的同步结果，也不要把 `docs-site/` 加入 Git 跟踪。
- 旧 `site/` 工作区副本已删除，不再作为内容维护入口，也不作为发布目标。
- 旧路径复查已完成：`LTD_MAIN_CPU2/docs`、`LTD_DISPLAY_CPU3/docs`、`/html/cpu2/`、`/html/cpu3/`、`8128` 和旧静态站脚本关键词只保留在治理、迁移或索引说明中，没有作为活文档入口继续指向旧目录。
