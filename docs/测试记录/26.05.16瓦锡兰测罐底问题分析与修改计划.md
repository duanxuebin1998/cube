# 26.05.16 瓦锡兰测罐底问题分析与修改计划

## 资料范围

- 测试记录：`docs/测试记录/26.05.16测试记录-瓦锡兰测罐底.docx`
- 串口打印：`docs/测试记录/ReceivedTofile-COM3-2026_5_15_22-38-49.DAT`
- 串口文件编码：GBK
- 关联源码：`LTD_MAIN_CPU2` 为主，少量涉及 `LTD_DISPLAY_CPU3` 故障显示

## 总体结论

本次记录里的问题大部分存在。其中风险最高的是“标定零点失败后已经清零点”和“罐底编码器修正偏差很大仍强制修正”。这两项会直接导致后续罐高测量出现 1027.6 mm 这类明显异常值，并可能把编码器位置强行改到 1500.0 mm 对应位置。

另外，瓦锡兰密度测量后的固定点回位、探底、再切回固定点监测，是当前代码设计行为，不是日志误判。但当前日志没有把“本次为什么探底/为什么不探底/探底后为什么又监测”讲清楚，且探底频率计数、点位舍弃、密度模式稳定等待、打印节流都需要调整。

| 12 | 罐底修正偏差过大仍执行 | 存在，风险高 | DAT 54746 行实高偏差 472.4 mm 仍执行修正。`ApplyBottomEncoderCorrection()` 只有在 `maxTankHeightDeviation != 0` 时才做偏差拦截，参数为 0 时等同关闭保护。 |

| 14 | 液氮中间报 18-3 | 存在 | DAT 656、7231 行最终报错 `0x00120003`，错误名“检测到碰撞”，来自 `motor_ctrl_motion_api.c:1001 MotorMotion_WaitUntilStopWithTarget`。根因是下行过程中称重碰撞检测触发。 |

## 修改计划

### 阶段 1：先修正高风险状态提交问题

1. 修改 `LTD_MAIN_CPU2/Application/Src/measure_zero.c`
   - 把标定零点改成“两阶段提交”。
   - 粗找、精找、脱离零点、零点电容或辅助通道检查全部成功后，才执行 `set_encoder_zero()` 和电机/编码轮基准重置。
   - 如果零点电容只是 DSM 一代辅助数据，应明确降级为告警或跳过，不能在已经清零后返回最终错误。
   - 若必须保留零点电容为强校验，则失败时不得改零点，并打印“零点未提交”。

2. 修改 `LTD_MAIN_CPU2/Application/Src/measure_tank_height.c`
   - `ApplyBottomEncoderCorrection()` 增加硬保护：实高偏差超过安全阈值时无条件跳过，不允许用 `maxTankHeightDeviation = 0` 关闭保护。
   - 建议默认硬阈值先按 50.0 mm，现场可再确认是否改为参数。
   - 只有本次 `SearchBottom()` 成功且零点状态有效时才允许编码器修正。
   - 修正日志增加“跳过/执行原因”和公式：`目标尺带 = 采用罐高 - 探头距差`。

3. 验证
   - 人为让 `read_zero_capacitance()` 返回 `0x000D000D`，确认零点未被清除。
   - 构造实高偏差 472.4 mm 场景，确认编码器修正被跳过。
   - 运行 CPU2 构建。

### 阶段 2：梳理瓦锡兰测后探底和固定点监测流程

1. 修改 `LTD_MAIN_CPU2/Application/Src/measure.c`
   - 给 `bottom_detect_count` 增加上次频率快照；当 `wartsila_bottom_detect_interval` 改变时重置计数。
   - 每次瓦锡兰测量结束打印：`探底频率=N，本次计数=x/N，本次是否探底=是/否`。
   - 把 `Wartsila_MoveToMonitorPositionOnly()` 日志改为“回固定点等待探底”或“回固定点监测”，避免误解成找液位。
   - 探底完成后切回 `CMD_MONITOR_SINGLE` 前，明确打印“探底完成，切回固定点密度监测”。

2. 行为需要确认
   - 若现场不希望瓦锡兰密度测量后自动探底，应把 `wartsila_bottom_detect_interval` 设为 0，或改成默认不探底。
   - 若只希望每 N 次探底，不希望每次都回固定点，应拆分为两个参数：`测后回固定点` 和 `测后探底频率`。

3. 验证
   - 分别设置探底频率 0、1、2、3，连续运行 5 次，确认探底次数和日志完全一致。

### 阶段 3：修正分布测点选择和结果说明

1. 修改 `LTD_MAIN_CPU2/Application/Src/wartsila_density_measurement.c`
   - 起始点移动到 400 mm 后增加到位确认；如果偏差超限，重试一次或返回明确错误。
   - 首点采样前打印：`目标首点=400.0mm，实际首点=xxx.xmm，偏差=xxx.xmm`。
   - 最高点因距液面小于限制被舍弃时，打印被舍弃点的位置、液位、间距、限制。
   - 结果表增加“原始点数、舍弃点数、有效点数”。

2. 验证
   - 复测液位约 660 mm 场景，应清楚看到 600 mm 点被舍弃，最终只保留 400/500 两点。
   - 复测液位约 700 mm 场景，应清楚看到 400/500/600 三点都保留。

### 阶段 4：处理密度模式瞬态报错和单点日志

1. 修改 `LTD_MAIN_CPU2/Application/Src/measure_density.c`
   - `EnableDensityMode()` 后增加短稳定窗口，前几次密度 0 不立即按错误打印。
   - `0x000D0004` 的打印改为节流：首次、达到阈值、最终失败才打印；恢复时打印一次。
   - `单点读数` 增加当前位置：`位置=xxx.xmm`。
   - 固定点监测循环增加输出频率限制，避免每 200 ms 全量打印。

2. 验证
   - 密度模式刚开启时不再立刻刷 `13-4`。
   - 传感器确实长时间密度为 0 时仍能最终报警。
   - 单点检测串口行能直接看到位置。

### 阶段 5：读取部件参数的 13-13 处理

1. 修改 `LTD_MAIN_CPU2/Services/Sensor/sensor.c`
   - `Sensor_ReadPartParamsInternal()` 读取密度/温度前先进入密度模式并等待稳定。
   - 密度读取失败时，不应丢弃已经读到的位置、称重、电机状态等数据；建议返回“部分成功”日志，并只在关键项失败时置最终错误。
   - 对不支持的辅助通道继续打印跳过，不进入最终报错。

2. 验证
   - 连续执行读取部件参数 10 次，确认不再出现连续 `13-13`。
   - 如果传感器确实返回设备内部错误，应保留原始错误码和响应内容，便于判断硬件原因。

### 阶段 6：称重碰撞 18-3 的边界优化

1. 修改 `LTD_MAIN_CPU2/Services/Weight/weight.c` 或调用侧
   - 区分普通移动、固定点回位、找底流程中的称重保护语义。
   - 普通下行移动接近罐底时触发低于触底阈值，可以先停止并返回“到达保护区/疑似触底”，不要全部显示为“碰撞”。
   - 最终是否仍用 `0x00120003` 需要和现场安全策略确认。若仍保留该错误码，日志必须写清楚“触底阈值触发”。

2. 验证
   - 液氮场景复测，确认 18-3 不再在正常探底或固定点移动中误导显示。

### 阶段 7：打印节流和日志可读性

1. 对以下高频打印增加节流或条件编译
   - `CheckWeightCollision()` 的正常态打印。
   - `motorMoveUpToPositionOrAir()` 的循环检测打印。
   - `SinglePoint_ReadSensor()` 的每次采样打印。
   - `MotorCtrl_MoveToPosition()` 运动中打印。

2. 建议日志分级
   - 默认现场日志：阶段开始、阶段完成、关键参数、错误、恢复。
   - 调试日志：50 ms/80 ms 运动明细，需要宏或参数打开。

3. 验证
   - 同样流程串口日志行数明显下降。
   - 上位机不再出现“下行一会才打印”的明显滞后。

## 建议执行顺序

1. 先做阶段 1，避免继续产生错误零点和错误编码器修正。
2. 再做阶段 2、3，解决瓦锡兰探底频率和点位选择疑问。
3. 再做阶段 4、5，减少密度模式瞬态报错和 13-13。
4. 最后做阶段 6、7，优化告警语义和现场打印体验。

## 需要现场确认的问题

1. 瓦锡兰密度测量后，是否默认必须探底；如果不是，建议默认 `wartsila_bottom_detect_interval = 0`。
2. `bottom_encoder_correction_tank_height` 是现场期望罐高，还是只用于某一次校准；如果只用于校准，修正完成后是否需要自动清零或显示“已应用”。
3. `maxTankHeightDeviation = 0` 当前等同关闭偏差保护，是否允许现场这样配置；建议不允许关闭硬保护。
4. CPU3 或上位机显示的 `3-13` 是否来自另一个日志源；当前 DAT 未找到该码，需要用原始 `0xXXXXXXXX` 对照确认。
