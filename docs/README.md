## 命名原则

- 项目自有文档优先使用中文文件名，便于按业务场景查找。
- `CPU2`、`CPU3`、`SI7000`、`DSM`、`UART6`、`LNG`、`TMC5130A` 等协议、模块、芯片或产品名保留英文。
- `README.md`、`CHANGELOG.md`、`LICENSE`、脚本和工具文件名保留项目约定命名。

## 归档规则

- 原始供应商资料、现场日志、外部协议说明和图纸优先放入对应业务目录的 `00_原始资料/`，不直接修改原始文件。
- 可持续维护的项目说明优先使用 Markdown；PDF、docx、html 可作为导出、外部输入或阅读版保留。
- 同一事项如果经历“需求 -> 实现 -> 问题 -> 测试”，分别在对应目录保留入口，并在文档中互相引用。
- 涉及协议语义、参数范围、固件行为、显示行为或功能安全边界的文档改动，要同步检查相关 README、CHANGELOG、协议记录和版本改动与测试方案。
