# CUBE 文档库入口

更新日期：2026-08-04

这个目录是整机级资料入口。查资料时先按“你要解决的问题”进入对应目录，不要先按 PDF、Word、Excel 或 HTML 文件类型找。

## 先看这几份

| 文档 | 用途 |
| --- | --- |
| `00_程序流程导航/index.html` | CPU2/CPU3 程序流程统一入口，按整机业务链路跳转到 CPU2 和 CPU3 详细流程页 |

## 文件和命名口径

| 要判断的问题 | 看哪里 |
| --- | --- |
| `.md`、`.html`、`.xlsx`、`.docx`、`.pdf` 分别能不能改 | `00_构建与版本/文档库使用指南.md` |
| DOCX、XLSX、PDF、DAT、ZIP 是否仍作为源文件维护 | `00_构建与版本/附件与源文件清单.md` |
| 新文档怎么命名、原厂资料怎么归档 | `00_构建与版本/文档库治理清单.md`、`00_构建与版本/新增资料落位检查表.md` |

## 维护提醒

- 修改协议、参数、显示、版本或安全边界时，同步检查对应 README、协议记录、版本改动与测试方案和测试记录。
- 移动或重命名文件前先按 `00_构建与版本/新增资料落位检查表.md` 搜索旧路径引用，移动后更新迁移映射表。
- 资料迁移、目录整理或链接修改后可先运行 `py tools\check_docs.py` 做本地快速自检；需要定位时再分别运行 `py tools\check_docs_structure.py` 或 `py tools\check_markdown_links.py`。
- 默认不生成、不检查、不同步 PDF；除非明确需要交付 PDF。
- `docs/` 是唯一正式文档源；CPU2/CPU3 子项目文档已并入本目录，`docs-site/` 只作为本地预览工具保留，不纳入 Git 跟踪；需要预览或校验时在 `docs-site/` 运行 `npm run check`。
