# 任务上下文连续性与工程搜索说明

## 目的

本说明约束本机预览站如何在跨页阅读时保持任务角色、业务链路、核心流程、固件基线和验证范围，并定义工程语义搜索的分类边界。

`docs/` 仍是唯一正式资料源。URL、上下文条和搜索工作台只保存定位条件，不保存业务结论，也不替代正式流程、验证资料、运行台账、批次或基线。

## 可分享 URL 契约

任务上下文只保存在 URL 查询参数中，不使用 `localStorage`、`sessionStorage` 或其他浏览器私有状态。

| 参数 | 含义 | 稳定值示例 | 来源边界 |
| --- | --- | --- | --- |
| `role` | 当前任务角色 | `field`、`development`、`test`、`delivery` | 首页四类首选入口 |
| `route` | 业务链路 ID | `fault`、`external`、`param` | `业务链路清单.json` |
| `flow` | 核心流程键 | `cpu2_07`、`cpu3_03` | `流程证据清单.json` |
| `baseline` | 当前核对的固件基线 | `V1.22.0.0`、`V1.22.0.0_V1.21.0.0` | 流程证据或版本事件 |
| `scope` | 当前现象、证据或验证范围的稳定 ID | `symptom-fault`、`ev-fault-code-governance` | 正式登记清单或派生稳定键 |

工程搜索另外使用 `q` 保存检索词，使用 `kind` 保存事实类型。上述参数可以出现在同一个 URL 中，因此搜索结果和任务上下文可以一起复制、分享和复现。

示例：

```text
/start/search-workbench/?q=FaultManager&kind=symbol&role=development&flow=cpu2_07&baseline=V1.22.0.0
```

无效角色、越界路径和不符合稳定 ID 格式的上下文字段必须被忽略，不能据此生成业务判断。

## 深层页面连续性

从四类首页入口进入后，预览站在每个站内深层页面显示统一任务上下文条：

1. 显示当前任务角色和所在证据生命周期阶段。
2. 显示 URL 已提供的业务链路、核心流程、固件基线和验证范围。
3. 提供返回当前角色首选入口的路径。
4. 提供该角色的推荐下一步：现场进入现象搜索，开发进入验证矩阵，测试进入真实运行台账，交付进入基线与退化门禁。
5. 站内链接继续携带已有上下文；外部链接、下载链接和纯页内锚点不改写。
6. 可复制当前完整 URL，也可清除上下文字段回到普通阅读模式。

上下文条只说明“正在查什么”，不说明“已经通过”“已经关闭”或“可以发布”。

## 六类工程语义搜索

`/start/search-workbench/` 按以下六类事实组织检索结果：

| 事实类型 | 派生来源 | 进入后的默认角色 |
| --- | --- | --- |
| 现场现象 | `流程排查入口.md` 中显式登记的问题模式 | 现场排查 |
| 源码符号 | `流程证据清单.json` 中登记的函数、状态、命令、寄存器和异常出口 | 开发变更 |
| 核心流程 | 业务链路清单与流程证据清单共同覆盖的 18 个流程 | 现场排查 |
| 验证证据 | `验证证据登记清单.json` 中的稳定证据身份 | 交付决策 |
| 版本基线 | 正式版本资料、流程关系和可解析 Git 事件 | 交付决策 |
| 验证状态 | 验证新鲜度和执行队列中的失败、过期、待执行、未记录及专项缺口 | 测试执行 |

本页适合按工程实体和状态缩小范围；右上角全文搜索继续用于查任意文件正文。两者并存，不用新的搜索索引替代 Pagefind，也不把搜索结果写回正式资料。

## 自动检查

本机预览站使用以下命令检查上下文和搜索契约：

```powershell
cd docs-site
npm run check:task-context
```

检查已经接入 `npm run check`，失败关闭以下问题：

- 首页角色入口没有写入对应 `role` 参数。
- 四类角色缺少首选入口或推荐下一步。
- 深层页面没有加载统一上下文脚本。
- 工程搜索缺少任一事实类型、事实类型为空或泄漏未展开结构对象。
- 搜索词、事实类型和任务上下文不能在同一 URL 中保持。
- 上下文实现依赖浏览器私有存储。

自动检查只证明定位条件可复现、跨页路径连续和搜索分类完整，不证明搜索命中的资料仍然新鲜，也不证明任何验证结果、批次结论或交付决定成立。
