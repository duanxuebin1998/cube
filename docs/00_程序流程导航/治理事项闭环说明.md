# 治理事项闭环说明

更新日期：2026-07-12

## 目的

本说明把责任治理队列从“发现问题并给出下一步”推进为可审计关闭链。每个治理项必须能够回溯：机器发现了什么、谁正式接手、采取了哪项正式动作、哪一个权威事实最终清零。治理清单不保存测试结果、批次正文、基线快照或流程关系副本。

## 单一关闭链

1. **发现事实**：本机预览站从流程证据、当前源码影响、专项证据、真实运行、验证批次和交付基线派生当前事实，并生成稳定 `gov-*` 治理身份和事实指纹。
2. **责任接手**：责任人在 `治理事项处置清单.json` 中追加 `claimed` 事件，绑定责任、正式说明、完整 Git revision 和当前事实指纹。
3. **正式动作**：进入执行时追加 `in-progress`；外部条件未满足时追加 `waiting-external`。动作只引用原有正式身份与资料，不复制工作包、运行、批次或基线内容。
4. **机器清零**：只有权威事实已经消失后才能追加 `closed`。关闭事件必须引用真正改变事实的正式动作；派生页面没有手工完成开关。

同类事实再次出现时，原关闭事件继续保留，派生队列显示为“重新出现”；责任人必须为新一轮事实指纹追加新的 `claimed` 事件，不能覆盖旧历史。

## 生命周期

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| `unclaimed` | 机器事实存在，但尚无正式接手事件 | 仅由当前事实派生，不写入清单 |
| `claimed` | 责任已明确接手 | 必须绑定当前事实指纹、责任、说明和 revision |
| `in-progress` | 已进入正式动作 | 至少引用一项动作身份或正式资料 |
| `waiting-external` | 等待台架、设备、现场、外部团队或干净工作区 | 必须说明等待边界，不按日期自动失败或关闭 |
| `closed` | 权威机器事实已经清零 | 事实仍存在时禁止关闭；必须引用满足关闭契约的正式动作 |
| `reopened` | 已关闭的同类事实重新出现 | 仅由当前事实与历史关闭事件共同派生，不直接写入清单 |

## 六类关闭契约

| 治理类型 | 权威事实来源 | 允许的正式关闭动作 |
| --- | --- | --- |
| `stale-review` | `流程证据清单.json` 的 `reviewedAt` | `flow-review`：重新核对正式流程页并更新核对日期 |
| `unmapped-source` | 当前 Git 工作区的流程影响分析 | `flow-mapping` 或 `flow-adjudication`：补入正式映射，或以正式说明确认不属于核心流程 |
| `missing-specific-evidence` | 专项证据覆盖关系 | `evidence-registration`：登记稳定证据身份并建立流程专项关系 |
| `no-real-run` | `验证运行登记清单.json` | `validation-run`：追加真实运行 ID 与原始记录 |
| `no-validation-batch` | `验证批次登记清单.json` | `validation-batch`：创建稳定批次并冻结范围 |
| `no-delivery-baseline` | `交付证据基线清单.json` | `delivery-baseline`：在满足保存条件后创建并显式选择基线 |

动作引用只保存 `kind`、稳定 ID 和 `docs/` 正式资料路径。运行结果仍由运行台账维护，批次状态仍由批次事件维护，基线生命周期仍由基线清单维护，流程关系仍由流程证据清单维护。

## 操作方式

先重新同步本机预览，使 `/data/governance-queue.json` 与当前工作区一致，再执行 dry-run：

```powershell
py tools\manage_governance_item.py transition `
  --id gov-no-run-ev-flow-cpu2-05 `
  --state claimed `
  --recorded-at 2026-07-12T14:00:00+08:00 `
  --owner-id validation `
  --owner "测试执行负责人" `
  --decision-revision <40位revision> `
  --explanation "docs/00_程序流程导航/治理事项闭环说明.md" `
  --dry-run
```

进入执行或关闭时使用相同命令追加事件，并按 `kind:id:path` 增加动作引用。例如真实运行清零后关闭：

```powershell
py tools\manage_governance_item.py transition `
  --id gov-no-run-ev-flow-cpu2-05 `
  --state closed `
  --recorded-at 2026-07-12T18:00:00+08:00 `
  --owner-id validation `
  --owner "测试执行负责人" `
  --decision-revision <40位revision> `
  --explanation "docs/00_程序流程导航/治理事项闭环说明.md" `
  --action "validation-run:run-cpu2-05-wl-a01-20260712:docs/00_程序流程导航/验证运行台账说明.md" `
  --dry-run
```

去掉 `--dry-run` 后工具才会原子追加。工具不会生成治理身份、运行结果、批次、基线或 Git revision，也不会在机器事实仍存在时接受关闭。

## 自动门禁

- `py tools\check_governance_items.py` 校验正式清单的 schema、稳定身份、追加顺序、合法状态转换、责任、说明、revision、事实指纹和动作引用。
- `docs-site/scripts/check-governance-queue.mjs` 在重新同步后把正式处置事件与当前机器事实对账：活动事件丢失当前事实、事实指纹漂移、关闭动作类型错误或派生生命周期不一致时失败关闭。
- `/start/governance-queue/` 同时展示治理身份、接手状态、事件数量、关闭信号和处理入口，但不提供手工完成按钮。

## 结论边界

治理项关闭只表示对应机器事实已按契约清零。它不自动说明用例通过、批次被接受、交付被批准或固件可以发布；这些结论仍由各自的正式运行、批次和交付决策证据承担。
