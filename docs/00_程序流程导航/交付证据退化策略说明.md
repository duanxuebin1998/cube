# 交付证据退化策略说明

## 目的

交付证据退化策略把显式基线对比转成可审计的治理结论，区分“必须阻断”“需要解释”“仅记录”三类变化。策略不计算风险分数，不从标题、日期、页面文案或数量趋势猜测质量结论。

## 正式来源

- `交付证据退化策略.json` 定义策略版本、失败关闭边界和规则。
- `交付证据退化例外清单.json` 记录绑定规则、基线和当前 Git revision 的例外或解释。
- `交付证据基线清单.json` 继续负责显式选择历史比较对象。
- `docs-site/public/data/current-delivery-regression.json`、`delivery-baseline-trend.json` 与 `delivery-baseline-lifecycle.json` 是本机派生结果，不是正式批准记录。

## 三类结论

1. **必须阻断**：只覆盖可以由机器字段证明的治理退化，例如新增严格待复核流程、新增未投影流程、通过证据退化为失败，以及交付就绪状态从可决策退化为不可决策。
2. **需要解释**：覆盖新增未映射源码、验证队列增长、高优先执行项增长和专项证据缺口增长。数量变化本身不代表质量升降，但必须说明变化原因和后续动作。
3. **仅记录**：记录受影响流程、结构化结果和固件基线变化，不自动触发风险结论。

没有显式选择基线时，门禁状态必须为“未评估”，不得用当前值与零比较，也不得把“没有命中规则”显示为通过。

## 例外与解释

例外记录必须同时绑定：

- 唯一 `id`；
- 已存在的 `ruleId`；
- 当前选择的 `baselineId`；
- 完整 40 位 `currentGitRevision`；
- `action`：阻断规则只能使用 `waive`，解释规则只能使用 `acknowledge`；
- 明确的 `owner`、`explanation` 和至少一条 `evidencePaths`。

Git revision 或所选基线变化后，旧记录自动失效。例外只改变自动门禁处置，不表示测试通过、现场确认或交付批准。

## 稀疏趋势

- 趋势点只来自清单中明确登记、通过校验且当前生命周期状态为 `current` 或 `superseded` 的正式基线。
- `retired` 和 `audit-only` 不参与默认趋势，但完整责任链继续保留在生命周期快照中。
- 同一 Git revision 的重复登记合并为一个点，不制造重复进展。
- 不按日期补点，不插值，不使用当前脏工作区作为趋势点。
- 数量趋势只描述机器事实，不解释为质量、可靠性或安全性趋势。

## 检查方式

只校验正式策略、例外和基线结构：

```powershell
py tools\check_delivery_evidence_regression.py
```

同步本机站点后校验当前门禁结果，并核对 Python 与站点使用同一判定：

```powershell
py tools\check_delivery_evidence_regression.py --comparison docs-site\public\data\current-delivery-comparison.json --result docs-site\public\data\current-delivery-regression.json --trend docs-site\public\data\delivery-baseline-trend.json --lifecycle docs-site\public\data\delivery-baseline-lifecycle.json
```

命中未豁免的阻断规则时返回非零；只有“需要解释”时保持成功退出，但结果状态明确为 `explanation-required`。
