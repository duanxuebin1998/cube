2. 按业务链路跳转

这些路线把“显示端/外部协议入口 -> CPU3 内部通信 -> CPU2 测量执行 -> 状态回读”串起来，避免在两个 CPU 的目录之间硬切。

液位测量与跟随链路

从 CPU3 菜单或外部协议发起找液位/液位跟随，CPU2 执行找液位、闭环跟随和状态上报，CPU3 再显示或对外响应。

查看链路菜单参数与指令下发CPU2 内部通信与轮询
水位测量与跟随链路

水位链路与液位类似，但传感模式、阈值和盲区策略不同，建议从命令入口一路跟到 CPU2 水位详细流程。

查看链路菜单参数与指令下发CPU2 内部通信与轮询
密度、单点和分布测量链路

密度链路同时涉及 CPU2 测量算法、分布点回读和 CPU3 的 Wartsila/SI7000 协议适配。

查看链路Wartsila 与 SI7000 协议适配CPU2 内部通信与轮询
读取部件参数、RSSI 与 AO 运行态链路

读取部件参数由 CPU3 菜单下发，CPU2 周期刷新传感器快照并查询 CH9141K 当前连接 RSSI；协议 10 起返回 RSSI，协议 11 起在 RSSI 后追加 AO 运行态，CPU3 轮询尾部输入寄存器后在状态页显示。

查看链路菜单参数与指令下发CPU2 内部通信与轮询
AO 模拟电流输出与 HART 链路

AO 输出由 CPU3 菜单参数使能，CPU2 根据液位/故障/调试状态刷新 AoOutput 运行态，AD5421 输出电流，HART 和 CPU3 状态页读取同一运行数据。

查看链路菜单参数与指令下发参数存储与系统配置
参数修改、保存和同步链路

CPU3 菜单和外部协议都可能修改参数，必须区分 CPU3 本机参数、CPU2 设备参数和共享寄存器缓存。

查看链路菜单参数与指令下发本机参数、FRAM、时钟与外设恢复
故障、恢复和状态展示链路

CPU2 是主要故障产生和恢复位置，CPU3 负责轮询状态、显示提示，并在外部协议里反馈故障结果。

查看链路电机与位置模型故障管理与恢复
外部协议到 CPU2 测量链路

外部 COM 先在 CPU3 分发，协议层只做映射和缓存，真正测量动作仍由 CPU2 命令入口完成。

查看链路外部 COM 协议分发与 RS485 发送DSM 协议与命令映射

6. 维护规则

单页继续按源码单独整理

每个功能页仍需要独立阅读源码、单独画业务级 SVG，不用统一模板批量凑图。

跨页只表达业务关系

统一入口和跨 CPU 链路页不替代详细流程图，只说明上下游、触发源和结果去向。

重新生成后恢复导航

如果 CPU2/CPU3 流程 HTML 被重新生成，执行 py tools/update_flow_navigation.py 恢复统一入口和页面关联导航。
