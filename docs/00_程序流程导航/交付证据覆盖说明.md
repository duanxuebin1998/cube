# 交付证据覆盖说明

## 目的

交付证据覆盖用于回答四个问题：一份正式验证资料是否具有稳定身份、它与哪些核心流程相关、这些流程进入哪些业务链路，以及已选交付基线实际携带了哪些证据关系。

覆盖关系只描述“资料声明覆盖什么”，不表示测试已经执行、结果仍然新鲜或交付已经批准。

## 单一来源边界

覆盖图谱坚持身份、关系、结果分离：

| 事实 | 唯一正式来源 | 说明 |
| --- | --- | --- |
| 证据身份 | `验证证据登记清单.json` | 保存稳定 `id`、当前路径、历史别名、资料类型和声明验证层 |
| 流程与资料关系 | `流程证据清单.json` | `defaultValidationPaths` 表示共享资料，页面 `validationPaths` 表示专项关系 |
| 链路与流程关系 | `业务链路清单.json` | 由八条业务链路的正式步骤和闭环角色定义 |
| 执行结果 | 正式 Markdown 内的 `cube-validation-result` | 保存状态、执行日期、固件基线、环境和结果摘要 |
| 基线选择 | `交付证据基线清单.json` | 只有唯一 `current` 基线参与历史覆盖评估 |
| 缺口责任与处置状态 | `交付证据缺口处置清单.json` | 保存稳定缺口 ID、负责人、正式说明和追加式状态历史 |

身份登记清单不得复制流程或链路关系。覆盖工具通过稳定 ID 与正式路径连接上述来源，并要求登记路径精确覆盖流程证据清单当前引用的全部资料。

## 稳定身份契约

每份被流程证据清单引用的 Markdown 必须在 `验证证据登记清单.json` 中登记一次：

- `id`：以 `ev-` 开头的稳定小写标识；资料重命名时保持不变；
- `path`：`docs/` 下当前正式 Markdown 路径；
- `documentKind`：`validation-plan` 或 `governance-record`；
- `declaredLayers`：资料明确规定的验证层，可选 `automatic`、`bench`、`device`、`field`；
- `aliases`：可选的历史正式路径，只用于旧基线回溯，不重新建立流程关系。

同一 ID、当前路径或别名不得重复。未知 schema、未知资料类型、未知验证层、路径越界或资料不存在时失败关闭。

## 覆盖判定

### 核心流程

- 页面有至少一个 `validationPaths` 时为“有专项证据关系”。
- 页面没有 `validationPaths` 时为“缺专项证据”。
- `defaultValidationPaths` 只作为共享基线，不得替代页面专项关系。

### 业务链路

业务链路的流程集合从 `业务链路清单.json` 自动取得。链路中任一核心流程缺少专项证据时，该链路保持“存在缺口”；不因链路内其它流程拥有多份资料而抵消。

### 已选基线

没有显式 `current` 基线时，基线覆盖状态必须为 `not-evaluated`。有基线时只读取该基线快照中的 `affectedPages` 和 `formalEvidence`：

- 正式资料路径通过当前路径或 `aliases` 解析为稳定证据 ID；
- 只统计被正式证据明确列出的受影响流程；
- 未登记路径和未覆盖受影响流程继续显式保留。

## 验证层含义

- `automatic`：资料定义构建、静态检查、脚本或主机测试范围；
- `bench`：资料定义台架连接、激励、观测或联调范围；
- `device`：资料定义整机、实机或真实外设验证范围；
- `field`：资料定义 PLC、RS485、现场设备或现场条件确认范围。

`declaredLayers` 只说明资料定义了哪些层，不代表这些层已经执行或通过。真实状态继续由验证结果元数据和证据新鲜度页面判断。

## 当前覆盖事实

当前 17 份被引用资料均已获得稳定身份。18 个核心流程全部具备至少一份专项关系，八条业务链路均无专项关系缺口。

此前的 `cpu2_05`、`cpu2_10`、`cpu2_12`、`cpu3_02`、`cpu3_06` 五个缺口已经由 `验证工作包/` 中的正式资料建立专项关系，并在 `交付证据缺口处置清单.json` 中保留完整 `new → claimed → in-progress → closed` 历史。

这表示资料身份、流程关系和缺口处置已经闭环，不表示五份工作包已经执行或通过。它们的 `cube-validation-result` 当前仍为 `pending`，必须继续进入验证执行队列。

## 检查方式

检查正式身份、路径和覆盖关系：

```powershell
py tools\check_delivery_evidence_coverage.py
```

同步本机站点后核对 Python 与 Node 生成结果：

```powershell
py tools\check_delivery_evidence_coverage.py --snapshot docs-site\public\data\delivery-evidence-coverage.json
```

该检查已接入 `py tools\check_docs.py` 和站点 `npm run check`。机器快照是本机派生视图，正式资料和关系仍只维护在 `docs/`。
