3.1 水位命令入口与模式选择

本图把三条水位正式指令放在同一张业务图中：找水位只执行一次完整搜索；水位跟随先按模式寻找跟随点，再检查位置源；水位标定根据进入前是否跟随态决定是否先找水位。

命令分派Application/Src/measure.c:129-158：CMD_FIND_WATER、CMD_FOLLOW_WATER 分别进入找水位和跟随处理。
水位包装函数Application/Src/measure.c:513-567：命令函数内部再次 MeasureStart()，跟随模式由 water_level_mode 选择。
维护关注公共入口和命令函数内均执行测量准备，调试时要注意过程标志、电机和扭力初始化被重复清理。

3.2 完整找水位 SearchWaterLevel

完整找水位不是一条直线：先处理回零和零点电容，再根据当前是否已经在水中做上行避让，之后粗找、精找各自最多 3 次重试，命令切换要直接透传。

准备和避让Application/Src/measure_waterLevel.c:270-358：自动回零、零点电容恢复、初始上行 100mm、若当前在水中则上行离开。
重试策略Application/Src/measure_waterLevel.c:360-445：粗找和精找均按 3 次重试处理，粗找失败返回最后一次错误。
结果同步Application/Src/measure_waterLevel.c:452-458：最终用 WaterLevelSyncFromCable() 将尺带长度换算为水位。

3.3 粗找与精找水位边界

粗找负责快速找到第一次 WATER 并确认停稳后仍接触水位；精找负责从空气侧重新低速下行，按距粗定位点的距离降速，提高边界定位精度。

粗找Application/Src/measure_waterLevel.c:528-579：连续下行直到 WATER，慢停后等待 3000ms 再确认；确认失败上行 100mm 并返回水位低。
精找Application/Src/measure_waterLevel.c:585-674：若开始时仍在水中先低速上行离水，再下行；距粗定位点 <100mm 和 <10mm 时降速。
边界风险源码中走过头保护块被注释，精找主要依赖电容翻转、丢步检测和命令切换退出。

3.4 电容阈值与水位状态判断

水位状态判断的核心公式是：接触水位阈值 = 空气/零点电容 + water_cap_threshold / 1000.0。只有当前电容 cap 大于这个阈值时才认为 WATER，否则认为 NORMAL。

阈值公式Application/Src/measure_waterLevel.c:705-742：th = zero + WaterCapRawToFloat(water_cap_threshold)，WaterCapRawToFloat(raw)=raw/1000.0。
零点来源Application/Src/measure_waterLevel.c:680-698：读取零点电容时会写入 zero_cap=10*cap 并保存参数。
单位说明阈值参数不是直接电容值，进入公式前要除以 1000；zero_cap 保存时又按 10 倍存储，调试手算要分清。

3.5 快速状态翻转找跟随点

快速模式通过 WATER/NORMAL 两侧翻转位置求平均来得到水位点。第一次翻转只缓存，从第二次翻转开始计算平均值；稳定窗口为 0 时，形成可用平均点后会很快退出。

入口准备Application/Src/measure_waterLevel.c:804-848：准备零点电容、打印阈值，并读取初始 WATER/NORMAL 状态。
翻转逻辑Application/Src/measure_waterLevel.c:852-945：水中上行找 NORMAL，空气中下行找 WATER；从第二次翻转开始取两次边界平均。
稳定退出Application/Src/measure_waterLevel.c:947-988：稳定窗口内波动小于阈值且时间满足后慢停并对准平均水位。

3.6 水位跟随闭环

跟随闭环按目标电容窗口判断“偏水、偏空气、稳定带”。偏水上行，偏空气下行，偏差越大步长越大；连续大偏差触发重新找水位，稳定后进入专门的水位变化监视循环。

闭环阈值Application/Src/measure_waterLevel.c:1121-1125：target=zero+water_cap_threshold/1000，th_low=target-band，th=target+band。
动作决策Application/Src/measure_waterLevel.c:1152-1223：高于上限上行、低于下限下行，按 0.6/0.1 阈值比例选择 10mm、3mm、0.2mm。
恢复机制Application/Src/measure_waterLevel.c:1230-1297：180s 未进入稳定监视也会转入监视；连续大偏差达到 5 次后按策略重新找水位。

3.7 稳定监视与水位变化唤醒

闭环进入稳定带并连续计数后，会进入稳定监视循环。该循环只判断当前电容是否偏离目标值超过滞后阈值；超过后返回主闭环重新调节，没有超过则持续等待。

状态切换Application/Src/measure_waterLevel.c:1034-1047：进入监视时置 STATE_FOLLOW_WATERING，并同步一次水位。
变化判断Application/Src/measure_waterLevel.c:1049-1064：|cap-target_cap| > water_lag_cap_threshold/1000 时认为水位变化。
维护关注Application/Src/measure_waterLevel.c:1189-1190 稳定带内的 WaterLevelSyncFromCable() 被注释，稳定期间水位值不会连续刷新。

3.8 水位标定与罐高修正

水位标定通过当前尺带长度和用户输入的真实水位反推 water_tank_height。若标定命令是在水位跟随态触发，修正后恢复跟随；否则先找水位再修正，完成后置标定完成。

标定入口Application/Src/measure_waterLevel.c:1352-1409：检查 calibrateWaterLevel、区分是否恢复跟随、必要时先找水位。
修正公式Application/Src/measure_waterLevel.c:1319-1350：water_tank_height = cable_length + calibrateWaterLevel，不再加入固定 0.1mm 偏置。
异常边界新罐高必须满足 0 < height <= 5000000；calibrateWaterLevel=0 被视为参数错误。

5. 问题点与维护建议

  • 跟随丢失阈值不一致。
    WATER_FOLLOW_LOST_COUNT_MAX 定义为 20，但闭环中实际判断是 lost_count >= 5。现场看到更频繁重新找水位时，应先核对这个硬编码。
  • 重复 MeasureStart 可能清过程状态。
    水位命令先经过公共入口测量准备，命令函数内部又执行一次。若后续把水位流程接入更多临时状态，要注意被重复初始化。
  • 稳定带内水位值不会连续刷新。
    FollowWaterLevelCore() 稳定带分支中 WaterLevelSyncFromCable() 被注释，稳定监视入口只同步一次，显示/上报可能保留旧水位。
  • 快速模式 stable_win_ms=0 时稳定等待很短。
    跟随入口调用快速找点时传入 0，形成第二次翻转平均后会快速满足退出条件，适合找初始跟随点，但不是长时间稳定确认。
  • 零点电容和阈值单位容易混淆。
    water_cap_threshold 进入公式前除以 1000；zero_cap 保存时按 10 倍电容存储，调试手算必须统一单位。
  • calibrateWaterLevel=0 被视为无效。
    水位真实值为 0 的标定场景无法表达，若现场需要以零水位校准，需要调整参数语义或单独命令。
  • 精找走过头保护被注释。
    当前精找主要依赖电容状态翻转、丢步检测和命令切换，若电容状态失真，错误出口可能不够直观。
