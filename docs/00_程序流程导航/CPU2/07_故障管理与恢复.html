1. 整理范围

本页不是按函数名堆叠，而是按故障业务链路整理：错误从业务函数进入，先统一停机和最终报警，再在命令结束后登记自动恢复上下文，最后由主循环空闲分支周期性检查并重跑原业务命令。

故障入口CHECK_ERROR、SET_ERROR、CHECK_COMMAND_SWITCH、AbortableDelay_CommandSwitch
故障落地FaultManager_ReportErrorExit、FaultManager_HandleCheckError、FaultManager_SetErrorState、HandleError
自动恢复FaultRecovery_UpdateAfterCommand、FaultRecovery_Poll、FaultRecovery_Cancel
日志输出ErrorLog_Retry、ErrorLog_Recover、ErrorLog_ReportDetail、ErrorLog_Warn
Application/Inc/fault_manager.h:96-164 错误宏定义了返回、置错和命令切换的公共出口。 Application/Src/fault_manager.c:33-128 FaultManager 负责最终报警、慢停和设备错误态。 Application/Src/fault_recovery.c:230-459 故障恢复负责登记上下文、轮询检查和触发重跑命令。 Application/Src/app_main.c:174-223 主循环决定新命令优先、空闲时轮询自动恢复。

2. 总体业务流程图

这张图按真实业务时序画：错误入口不是直接进入重试，而是先完成统一错误处理；自动恢复只在命令结束后登记，重试动作由主循环空闲分支触发。

3. 错误宏与命令切换入口

故障管理最容易误解的地方在宏语义：CHECK_ERROR 会把非 NO_ERROR 返回码直接送入 FaultManager_HandleCheckError；SET_ERROR 明确跳过 STATE_SWITCH；CHECK_COMMAND_SWITCH 只处理命令切换并返回 STATE_SWITCH。

Application/Inc/fault_manager.h:96-123 CHECK_ERROR 先检查 ret，再检查全局 error_code，最后检查命令切换。Application/Inc/fault_manager.h:141-152 SET_ERROR 对 STATE_SWITCH 和 NO_ERROR 不处理，只对真实故障置设备错误态。Application/Inc/fault_manager.h:154-164 CHECK_COMMAND_SWITCH 发现切换或 ret==STATE_SWITCH 时 HandleError 并返回 STATE_SWITCH。

4. FaultManager 故障落地流程

FaultManager 的目标是把“某个业务点失败”落成可追踪的错误：保留文件、行号、函数，过滤正常和状态切换，避免短时间重复最终报警，并执行安全停机。

Application/Src/fault_manager.c:33-60 ReportErrorExit 过滤 NO_ERROR/STATE_SWITCH，调用 ErrorLog_TakeRecentReport 去重，再输出最终报警。Application/Src/fault_manager.c:66-100 HandleCheckError 返回错误码；SetErrorState 额外写 device_state/error_code/zero_point_status。Application/Src/fault_manager.c:105-128 HandleError 在驱动有效时慢停，慢停失败只记录告警。

5. 命令结束后的自动恢复判定

FaultRecovery_UpdateAfterCommand 是自动恢复的入口，但它不直接执行恢复动作。它判断当前命令和错误是否允许恢复，记录上下文后等待主循环空闲时轮询。

Application/Src/fault_recovery.c:290-335 UpdateAfterCommand 处理重试结果、上限、真实错误和上下文清理。Application/Src/fault_recovery.c:230-282 Start 会排除无错误、STATE_SWITCH、不可恢复参数错误、关闭恢复和非白名单命令。

6. 主循环恢复轮询流程

FaultRecovery_Poll 是等待期真正干活的函数：它恢复原错误态、按 1 秒节流做电机和传感器检查；检查通过后只返回“应该重跑原命令”，不直接执行业务命令。

Application/Src/fault_recovery.c:361-459 Poll 的 active、1 秒节流、电机初始化、传感器检查、上限判断和 retry_command 逻辑。Application/Src/fault_recovery.c:150-161 RestoreErrorStatus 在等待恢复时持续保持原故障状态。

7. 主循环接入关系

新命令优先级高于恢复。串口原始命令或正式命令到来都会取消正在等待的自动恢复；只有没有新命令时，才轮询恢复并可能把原命令送回统一执行入口。

Application/Src/app_main.c:186-193 完整串口帧到来时先取消自动恢复，再由 SerialCommand_ProcessReady() 复制并处理定长收帧缓存。Application/Src/app_main.c:194-203 正式命令到来时取消自动恢复，清 CMD_NONE 后执行命令。Application/Src/app_main.c:204-227 空闲分支轮询 FaultRecovery_Poll，若 should_retry_command 为真则调用 App_ExecuteMeasureCommand。

8. 错误日志流程

日志不是单一 printf。代码把重试、恢复成功、最终报警、普通告警分成不同阶段；最终报警还有 200ms 同码去重，重试日志也有打印节流。

Services/Utilities/error_log.c:17-63 重试日志打印策略和最终报警去重窗口。Services/Utilities/error_log.c:100-405 错误码到模块、原因、名称的映射。Services/Utilities/error_log.c:410-542 Retry、Recover、ReportDetail、Warn 的实际输出路径。

9. 可中断延时流程

长等待不能一次性阻塞，否则命令切换不及时。AbortableDelay_CommandSwitch 把等待切成小片，每片结束都检查有效命令切换。

Services/Utilities/abortable_delay.c:13-38 step_ms 为 0 时使用 50ms；循环 HAL_Delay 后检查 HasEffectiveCommandSwitchRequest。

10. 自动恢复准入规则

自动恢复并不是所有错误都重跑。参数类错误直接排除，现场参数可关闭恢复，命令还必须在白名单中；恢复前只做电机/传感器可用性检查，原业务条件是否真的恢复要靠重跑原命令验证。

Application/Src/fault_recovery.c:62-71 PARAM_RANGE_ERROR、PARAM_ADDRESS_OVERFLOW、PARAM_ERROR 被判定为不可自动恢复。Application/Src/fault_recovery.c:80-89 fault_auto_recovery_retry_limit 为 0 关闭恢复，超过最大值回默认值。Application/Src/fault_recovery.c:99-126 可恢复命令白名单包含回零、找液位、水位跟随、密度和校准等命令。

11. 已整理问题点与优化建议

高CHECK_ERROR 不排除 STATE_SWITCH

宏只判断 ret != NO_ERROR，因此如果调用点把 STATE_SWITCH 传给 CHECK_ERROR，会进入 FaultManager_HandleCheckError 并执行 HandleError；虽然最终报警会过滤 STATE_SWITCH，但仍会走停机路径。

Application/Inc/fault_manager.h:96-123；Application/Src/fault_manager.c:66-78
中SET_ERROR 会忽略 STATE_SWITCH

SET_ERROR 明确跳过 STATE_SWITCH；如果调用方期望状态切换立即退出，必须在 SET_ERROR 前后单独 return 或使用 CHECK_COMMAND_SWITCH。

Application/Inc/fault_manager.h:141-152
中fault_info_init 会清掉 error_code

初始化函数先慢停再把 error_code 清为 NO_ERROR；如果在测量开始处调用，会覆盖上一次可见故障，需要确认上位机/显示侧是否已经读取。

Application/Src/fault_manager.c:165-168
中最终报警 200ms 同码去重可能隐藏重复故障频次

同一错误码在 200ms 窗口内只打印一次最终报警，能抑制刷屏，但调试瞬态重复故障时需要结合阶段日志或计数。

Services/Utilities/error_log.c:31-63；Application/Src/fault_manager.c:42-45
中自动恢复依赖全局 error_code

UpdateAfterCommand 从 g_measurement.device_status.error_code 取故障；如果某条业务路径只返回错误而没有正确落到全局错误状态，恢复模块可能看不到。

Application/Src/fault_recovery.c:290-327
中恢复检查不等于业务条件恢复

Poll 只确认电机初始化和传感器参数刷新，之后让主循环重跑原命令；原先导致失败的液位、扭力或边界条件仍可能在重跑中再次失败。

Application/Src/fault_recovery.c:400-458
低新命令会取消恢复

串口命令或正式命令进入时会取消正在等待的恢复，这是优先级设计；现场误操作可能导致自动恢复未完成。

Application/Src/app_main.c:174-199；Application/Src/fault_recovery.c:343-355
低驱动未初始化时 HandleError 不慢停

HandleError 在电机驱动状态无效时只打印一次提示并返回，真正的驱动重初始化依赖自动恢复 Poll。

Application/Src/fault_manager.c:105-116；Application/Src/fault_recovery.c:395-418
