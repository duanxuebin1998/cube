3. 关键规则与公式

液位频率有效范围

hz != 0 && hz <= 6500 才写入输出；每轮 3 次读取失败后进入一次模式恢复，最多 3 轮。

LTD 密度频率换算

先读 R17 的 45 度扫频均方值 v45，当 v45 > 0 时：freq = sqrt(1000000000000.0 / v45)。

固定校正

密度校正：density += (densityCorrection - 100000) / 100；温度校正：temp += (temperatureCorrection - 1000) / 10。

无线 RSSI 选择

最强 RSSI 必须不低于 -55 dB，多个候选时最强与第二强差值必须不小于 8 dB。

Services/Sensor/sensor.c:477-526 液位频率无效重试和恢复次数。Services/Sensor/ltd_sensor_communication.c:602-625 LTD 频率由 R17/R18 均方根参数读取。Services/Sensor/wireless_pairing.c:1242-1306 RSSI 强度阈值和候选差值判断。

4. 已整理问题点与优化建议

  • 读取部件参数发生双重 MeasureStart普通入口 ProcessMeasureCmd 已经执行 MeasureStart，CMD_ReadPartParams 内部 update_command_state=1 又执行一次，电机/扭力初始化和清状态可能重复。
  • 无线配对正式入口忽略返回值CMD_PAIR_NEAREST_WIRELESS_SLIPRING 直接丢弃 WirelessPairing_RunByRssi 返回值，虽然内部会发布状态，但主入口没有统一 SET_ERROR 闭环。
  • LTD rx[6]==0xFF 被视为 NO_ERRORDSM_V2_CheckReply 遇到参数字节 0xFF 只打印原始帧后返回 NO_ERROR，可能把设备异常帧当作正常响应。
  • LTD 部件参数读密度失败会清频率并继续Sensor_ReadPartParamsInternal 对 LTD 密度/频率失败不退出，只把 frequency 置 0，现场需要确认这是降级策略还是掩盖故障。
  • 水位电容小于 30pF 被改写为 99999.9Read_Water_Capacitance 对低值做哨兵替换，没有同步专用状态位，后续水位算法容易把通信正常但数值异常混在一起。
  • 液位频率恢复会移动探头 1mm无效频率恢复在电机停止时会调用 MotorCtrl_MoveAndWait 上行 1mm，再切密度/液位模式；应在文档和测试中明确这是业务动作。
  • CH9141 AT 与透传/固定帧共用 UART6配对流程频繁 HAL_UART_DMAStop/HAL_UART_Abort，若与测量链路并发或状态未切换干净，会影响传感器透传。
  • 名称配对依赖扫描行是否带 NAME 字段扫描结果没有名称字段时 SPN 直接失败；维护界面需要提示固件/模块扫描格式限制。
  • 固定校正常量命名不直观densityCorrection 以 100000 为基准并按 /100 换算，temperatureCorrection 以 1000 为基准并按 /10 换算；建议参数说明直接写工程单位。
  • Read_Density_text 和多处 Adapter 仍是测试/占位性质这些函数返回固定值或 TODO 读取，文档中已标为不参与主链路；后续应清理或隔离测试入口。
