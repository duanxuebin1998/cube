1. 系统边界与阅读顺序

命令入口分两层：USART1 中断只完成定长收帧，主循环复制完整帧后由 SerialCommand_Process() 严格分类；正式 CommandType 命令统一进入 ProcessMeasureCmd()，再决定是否执行公共准备和业务分发。

外部入口
USART1 完整 ASCII 帧、g_deviceParams.command 正式命令、上电默认命令、故障恢复重试命令。
核心处理
SerialCommand_RxByteFromIsr()、SerialCommand_ProcessReady()、SerialCommandParser_Parse()、ProcessMeasureCmd()、CMD_CancelMeasurement()。
输出结果
严格校验后输出 ACK/ERR，或写入正式命令缓存、返回只读查询、进入合法测试命令，再由总入口分发液位、水位、密度、回零、标定和维护动作。
阅读重点
先看 ISR 为什么只收帧，再看主循环如何拒绝尾随垃圾和超长帧，最后看 STOP、查询、测试与正式命令如何分流。

2. 功能域业务总览 SVG

总入口的核心不是某一个测量动作，而是把多种来源的命令统一变成“可被主循环执行的一次业务动作”。

3.1 串口 ASCII 严格收帧与命令分流

USART1 中断只形成完整帧或超长事件；主循环复制帧、取消待恢复动作并严格解析。正式命令只写 g_deviceParams.command，查询只读，测试命令必须全文合法，非法输入只返回 ERR。

源码依据Application/Src/serial_command_parser.c 负责定长收帧和严格语法；Application/Src/serial_command.c 负责 ACK/ERR、正式命令、STOP、查询和测试分流；Application/Src/test.c 对测试命令再次门禁。
状态回写正式命令只写 g_deviceParams.command；STOP 写取消命令；查询只读；非法输入不调用 MeasureStart()，也不执行电机或参数动作。
边界正文最多 63 字节，支持 CRLF/LF；超长整帧丢弃并在主循环报告；接收器只有一个待处理帧槽，上位机应等待 ACK/ERR 后再发送下一条。

3.2 正式命令总分发流程

ProcessMeasureCmd() 对取消和无线配对做直通处理；其它命令先统一执行 MeasureStart()，成功后再进入 switch 分发。

源码依据Application/Src/measure.c:92-291：取消命令、无线配对命令、公共准备、switch(command) 分发和保留/未知兜底。
异常出口公共准备返回非 NO_ERROR 后调用 SET_ERROR(start_ret)，宏会写故障状态并从当前函数返回。
已整理问题点CMD_NONE、保留命令和未知命令也会先执行公共准备，可能产生电机/扭力初始化和状态标志清理副作用。

3.3 公共测量准备 MeasureStart 流程

公共准备负责把正式命令执行前的基础状态拉齐，但它也会清掉一批业务辅助标志，因此哪些命令需要调用、哪些命令不该调用，需要边界清晰。

源码依据Application/Src/measure.c:450-474：故障信息初始化、电机初始化、扭力初始化、清错误码和多类协议/密度辅助标志。
关键副作用会清 error_code、液位稳定/探头到液面标志、密度 profile 阻塞与偏差报警、手动报警/液位更新抑制等状态。
已整理问题点总入口已调用一次公共准备，但部分业务函数内部又再次调用 MeasureStart()，会重复初始化并二次清状态。

3.4 命令分发矩阵流程

分发矩阵按业务域而不是源码顺序阅读：总入口只负责分派，真正测量闭环在后续液位、水位、密度、回零等页面展开。

源码依据Application/Src/measure.c:115-291：从 CMD_NONE 到 default 的全部 case；各业务函数在液位、水位、密度、回零、标定页面继续展开。
状态边界总入口不负责业务完成态细节，完成态通常由被调用函数写入，例如液位、水位、密度或维护动作自己的状态。
已整理问题点部分 case 只是打印或调用外部函数，没有统一“命令已拒绝/已完成”的状态约定，协议层排查时容易只看到命令消失。

3.5 特殊命令、未知命令和异常出口流程

这张图把总入口里的特殊出口集中起来。它们不属于普通测量闭环，但会影响故障恢复、错误码、命令缓存和上层状态。

源码依据Application/Src/measure.c:94-100 特殊直通；Application/Src/measure.c:298-324 取消测量；Application/Src/measure.c:280-291 保留/未知命令兜底。

5. 问题点与优化建议

  • 未知/保留命令不应先做公共准备：当前会先初始化电机和扭力，再打印“不支持”。建议把非法命令识别前移，在 MeasureStart() 前直接拒绝并设置明确错误/响应。
  • 取消命令会清掉原错误码：CMD_CancelMeasurement() 先清 error_code，慢停失败也只打印。建议保留取消前故障快照，慢停失败至少写告警或错误日志。
  • 公共准备重复调用：总入口调用 MeasureStart() 后，部分业务函数内部又调用一次，可能重复初始化电机/扭力并清辅助标志。建议明确“只由总入口准备”或“由业务函数自准备”的单一责任。
  • 无线配对结果未传播：WirelessPairing_RunByRssi() 返回值被忽略，总入口无法把失败转换成统一错误状态。
  • 串口待处理帧只有一个槽位：new_command_ready 未清除时中断入口会忽略后续字节；上位机连续无等待发送多条命令时可能丢帧。现场工具应等待每条 ACK/ERR 后再发送下一条，后续如需突发输入再评估环形队列。
