# 验证批次与里程碑决策说明

验证运行台账回答“某个用例是否真实执行过”，验证批次回答“这一轮验证准备证明什么、范围是否完整、能否进入里程碑决策”。正式来源是 `验证批次登记清单.json`；当前清单为空，表示尚未建立真实批次，不表示验证已完成。

## 批次边界

| 层级 | 稳定身份 | 正式来源 | 责任 |
| --- | --- | --- | --- |
| 工作包 | `ev-wp-*` | `验证工作包/` | 定义用例、验证层、步骤和通过标准 |
| 运行 | `run-*` | `验证运行登记清单.json` | 记录一次真实执行及原始记录完整性 |
| 批次 | `batch-*` | `验证批次登记清单.json` | 冻结本轮范围、基线、责任、时间窗口和退出条件 |
| 里程碑结论 | 批次关闭事件 | 批次追加式事件链 | 明确接受、拒绝或带例外接受，不自动批准发布 |

批次只引用稳定工作包用例和运行 ID，不复制测试正文、原始记录或业务链路关系。

## 批次生命周期

```text
planned → running → decision-ready → closed
              ↕
       waiting-external

planned / running / waiting-external → cancelled
decision-ready → running
```

- `planned`：范围、基线、责任、窗口和退出条件已经冻结，尚未开始执行。
- `running`：正在执行批次范围内的用例。
- `waiting-external`：等待台架、实机、现场、人员或其他外部条件；等待不会按日期自动变成失败。
- `decision-ready`：所有范围用例都有明确运行，当前结果不再是 `partial` 或 `blocked`；失败可以进入拒绝决策，但不能伪装成接受。
- `closed`：追加明确的 `accepted`、`rejected` 或 `accepted-with-exceptions` 结论，并冻结本次结论所引用的运行集合。
- `cancelled`：批次停止，不再参与当前决策；历史仍保留。

## 关闭规则

1. `decision-ready` 和 `closed` 事件必须为批次范围内每个用例各引用一次运行，不能用同一用例重复运行替代其他用例。
2. 被引用运行必须早于或等于事件时间，并与批次范围、固件基线一致。
3. `accepted` 要求本次决策引用的所有运行均为 `passed`。
4. `rejected` 至少包含一个 `failed`。
5. `accepted-with-exceptions` 至少包含一个非通过结果，并必须引用 `docs/` 下的正式例外说明；PDF 不进入本契约。
6. 批次关闭只表示这轮验证形成了明确结论，仍不能替交付负责人批准发布、现场放行或功能安全结论。

## 管理方式

创建前先使用 `--dry-run` 核对范围：

```powershell
py tools\manage_validation_batch.py create `
  --id batch-cpu2-water-level-202607 `
  --label "CPU2 水位测量台架验证批次" `
  --milestone-kind bench-campaign `
  --milestone-reference "CPU2 水位测量台架闭环" `
  --owner "测试负责人" `
  --created-at 2026-07-12T15:00:00+08:00 `
  --scope-revision 6dad8cd634a2cf576a77b78bf4b12fe14d60103e `
  --cpu2 V1.22.0.0 --cpu3 V1.21.0.0 `
  --window-start 2026-07-12 --window-end 2026-07-19 `
  --case ev-wp-cpu2-05-water-level:WL-B01 `
  --case ev-wp-cpu2-05-water-level:WL-B02 `
  --exit-criterion "两个台架用例都有明确运行结果" `
  --explanation docs/05_测试记录/批次计划说明.md `
  --decision-revision 6dad8cd634a2cf576a77b78bf4b12fe14d60103e `
  --dry-run
```

状态推进使用 `transition`，运行 ID 必须显式提供：

```powershell
py tools\manage_validation_batch.py transition `
  --id batch-cpu2-water-level-202607 `
  --state decision-ready `
  --recorded-at 2026-07-19T16:00:00+08:00 `
  --owner "测试负责人" `
  --decision-revision 6dad8cd634a2cf576a77b78bf4b12fe14d60103e `
  --explanation docs/05_测试记录/批次结论说明.md `
  --run-id run-cpu2-05-wl-b01-20260712-01 `
  --run-id run-cpu2-05-wl-b02-20260712-01 `
  --dry-run
```

去掉 `--dry-run` 后工具才会原子追加。所有批次关系和状态由以下检查统一核对：

```powershell
py tools\check_validation_batches.py
py tools\check_docs.py
```
