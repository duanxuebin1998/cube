# 流程图网站嵌入格式规范

更新日期：2026-07-11

本文约束 `docs/00_程序流程导航/` 下程序流程 HTML 的页面结构、内联 SVG、响应式展示和网站嵌入方式。目标是在不改变节点、分支、异常出口、源码证据和业务结论的前提下，让同一份流程文档既可独立打开，也可由本地文档站安全嵌入。

## 1. 文档源与维护边界

- `docs/` 是唯一正式文档源。流程正文、图题、SVG、源码证据和链接都只在 `docs/00_程序流程导航/` 中维护。
- `docs-site/` 只是从 `docs/` 同步生成的本机预览工具，不是业务资料来源，不手工维护其生成内容，也不纳入 Git 跟踪。
- 旧 `site/` 已淘汰，不恢复为维护入口或发布目标。
- 纯格式优化不得改变流程业务语义。若业务流程确有变化，应先依据源码和需求更新节点、分支、异常出口与证据，再进行格式整理。
- 流程图继续使用 HTML 中的内联 SVG。不要把正式流程图转换为 PNG，也不要改为依赖浏览器运行时渲染的 Mermaid；前者会损失缩放、检索和可访问性，后者会引入脚本依赖及布局漂移。

## 2. 独立页与站内嵌入契约

每个流程 HTML 同时承担两种展示方式：

| 展示方式 | 保留内容 | 约束 |
| --- | --- | --- |
| 独立页 | 完整 HTML、页面标题、导览、正文、共享样式和可选交互脚本 | 关闭 JavaScript 后仍可阅读全部核心流程 |
| 站内嵌入 | 嵌入标记之间的正文、所需样式和静态链接 | 不重复独立页首屏与顶部导航，不执行源页脚本，不污染文档站全局样式 |

独立页至少满足以下要求：

- 使用 HTML5 文档结构，并设置 `lang="zh-CN"`。
- `<head>` 中声明 `<meta charset="utf-8">`、移动端 viewport 和与正文一致的 `<title>`。
- `<body>` 增加 `cube-flow-page` 类；页面标识应稳定、页面内唯一，不用临时序号代替业务可读名称。
- 在原有页面样式之后加载统一增强样式。目录根页面使用 `assets/网站嵌入增强.css`，CPU2/CPU3 子目录页面使用 `../assets/网站嵌入增强.css`。
- `body` 的最后一个元素统一加载 `assets/网站嵌入增强.js`；CPU2/CPU3 子目录页面使用 `../assets/网站嵌入增强.js`。该脚本只增强流程图和表格的滚动、焦点与操作提示，不生成业务正文。
- 首屏、顶部导航和只服务独立页的工具栏放在嵌入区域之外；核心流程正文放在嵌入区域之内。
- 可选脚本放在正文之后并使用渐进增强原则，不负责生成唯一可见的业务内容。

建议骨架如下，类名可在保留既有结构的前提下组合使用：

```html
<!doctype html>
<html lang="zh-CN">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>流程页标题</title>
    <link rel="stylesheet" href="../assets/网站嵌入增强.css">
  </head>
  <body class="cube-flow-page">
    <div class="wrap">
      <header class="hero">独立页标题与摘要</header>
      <nav class="topnav" aria-label="页内导航">独立页导航</nav>

      <!-- CUBE_EMBED_START -->
      <main>
        核心流程正文
      </main>
      <!-- CUBE_EMBED_END -->
    </div>

    <script src="assets/流程文档交互.js" defer></script>
  </body>
</html>
```

示例中的资源相对路径应按文件所在目录调整，不得为迁就预览站改成 `docs-site/` 内路径。

## 3. 嵌入边界标记

嵌入边界使用以下精确标记名，每页只保留一对：

```html
<!-- CUBE_EMBED_START -->
<!-- CUBE_EMBED_END -->
```

维护要求：

- 起始标记放在首屏、顶部导航之后，结束标记放在独立页脚本和仅用于独立页的控件之前。
- 两个标记必须按开始、结束的顺序出现，且不能放进 `<style>`、`<script>` 或 `<svg>` 内。
- 标记之间必须包含不依赖脚本即可阅读的核心正文；不要把唯一的流程标题、图题、图例或证据留在标记之外。
- 同步工具取第一对完整标记之间的内容。缺少完整标记时可兼容回退到 `<body>` 正文，但这只用于旧页面，不是新页面允许省略标记的理由。
- 同步工具会剥离源页脚本；因此嵌入正文不能依赖脚本生成、展开或恢复关键内容。

站内同步后的正文根容器由展示层统一生成：

```html
<div class="cube-html-inline__body cube-flow-page cube-flow-embedded"
     role="region"
     aria-label="原始 HTML 正文">
  嵌入正文
</div>
```

外层仍由 `.cube-html-inline` 承担普通 HTML 嵌入布局。同步工具可为避免语义嵌套而把嵌入片段中的 `main` 转为 `div`、把顶层 `h1` 降为 `h2`；正式源中的标题层级仍应在独立页内自洽。

## 4. 单张流程图的结构

每张流程图统一使用 `figure + figcaption + viewport + inline SVG`。既有业务类名可以保留，同时补充统一类名：

```html
<figure class="flow-card cube-flow-figure">
  <figcaption id="cpu2-start-caption">
    CPU2 启动与主循环
  </figcaption>

  <div class="svg-flow-wrap cube-flow__viewport"
       data-flow-width="standard"
       role="region"
       aria-labelledby="cpu2-start-caption"
       tabindex="0">
    <svg viewBox="0 0 1180 760"
         role="img"
         aria-labelledby="cpu2-start-title cpu2-start-desc">
      <title id="cpu2-start-title">CPU2 启动与主循环</title>
      <desc id="cpu2-start-desc">使用已核实的现有图题或说明描述流程范围。</desc>
      <!-- 原有节点、连线、文字、标记和定义 -->
    </svg>
  </div>
</figure>
```

结构要求：

- `figure` 只包裹一张图及其直接说明；图后的源码证据、问题项和长篇解释继续放在正文语义结构中。
- `figcaption` 必须可见，名称与图中业务范围一致。已有标题和说明不得因格式迁移被删减。
- viewport 负责横向滚动，使用 `tabindex="0"` 让键盘用户可聚焦，并用 `role="region"`、`aria-labelledby` 关联可见图题、用 `aria-describedby` 关联 SVG 的作者摘要。站内嵌入只对实测存在横向溢出的 viewport 显示操作提示并提供 `←` / `→` 滚动，无溢出时移除提示和额外 Tab 停靠点；可见的 CSS 提示不得混入区域名称，键盘说明通过追加的独立 `aria-describedby` 节点提供；宽度变化后必须重新计算可读起点。
- `data-flow-width` 只放在 viewport 上，取值为 `compact`、`standard` 或 `wide`；不得把该属性放在 SVG 节点上。
- SVG 必须保留有效 `viewBox`，不得用固定像素宽高破坏等比缩放。
- SVG 视觉画布保留 `<title>` 和 `<desc>`，但使用 `aria-hidden="true"`、`focusable="false"` 从辅助技术树中隔离；可访问名称、作者摘要和滚动操作说明统一由外层 viewport 暴露，避免图题、摘要和 SVG 节点文字重复朗读。SVG 根不得再保留 `role`、`aria-label`、`aria-labelledby`、`aria-describedby` 或 `tabindex`。同一元素的属性名不得重复；页面内所有 `id` 唯一，`aria-labelledby`、`aria-describedby`、`href`、`clip-path`、`marker-end` 等引用必须有效。
- `<desc>` 是作者摘要而不是图题副本；归一化后不得为空，也不得与直接 `<title>` 或所属 `<figcaption>` 完全相同。摘要需概述入口、关键判断和结果，`py tools/check_flow_docs.py` 对此执行门禁。
- 格式迁移补写 `<title>` 或 `<desc>` 时，只能复用已经存在的 `aria-label`、`figcaption` 或已核实说明，不根据文件名猜测业务语义。缺少可靠说明时应由维护者依据源码补齐。

## 5. 响应式与最小可读宽度

复杂流程图在窄屏上不应被强制压缩到容器宽度。正确策略是“外层自适应、图形保留最小可读宽度、viewport 横向滚动”：

| 宽度等级 | 默认最小宽度 | 适用情况 |
| --- | ---: | --- |
| `compact` | `44rem` | 节点较少、分支简单的流程 |
| `standard` | `58rem` | 常规业务流程 |
| `wide` | `70rem` | 节点密集、跨 CPU 或多泳道流程 |

- 等级依据节点密度、分支数量和实测可读性选择，不只依据 `viewBox` 的数值大小机械判断。
- 桌面端允许 SVG 在卡片中等比填充；当容器小于最小宽度时，只在 viewport 内出现横向滚动，不让整页产生横向滚动。
- 不通过移动端媒体查询继续缩小 SVG 内文字。流程节点正文、分支标签和图例在常见缩放下应保持可辨认。
- viewport 聚焦时应有完整、清晰且向内绘制的焦点环，不能被流程卡片的圆角或 `overflow` 裁掉；滚动条应可见但不抢夺内容视觉层级。Windows 高对比度模式下焦点环、卡片边框、滚动提示、滚动条，以及 SVG 节点填充、文字、连线和箭头都应回退到系统色。
- 表格同样在自身容器内横向滚动。不得用截断列、缩写业务字段或缩小到不可读字号的方式适配窄屏。
- 表格统一使用 `cube-flow-table > cube-flow-table__hint + cube-flow-table__viewport > table`。viewport 使用 `tabindex="0"`、`role="region"`，通过 `aria-labelledby` 关联可见 `caption`，通过 `aria-describedby` 关联“横向滚动，键盘 ← → 查看完整表格”提示；`caption` 和提示都必须有页面内唯一 ID。
- 屏幕样式保持表格不小于 `42rem`，通用单元格、首列和末列分别保留至少 `7rem`、`10rem` 和 `14rem` 的可读宽度。容器不足时只让 `cube-flow-table__viewport` 横向滚动；在 `900px` 以下显示操作提示，不得把四列以上表格强压到逐字断行。
- 打印样式可取消屏幕最小宽度并隐藏独立页导航，但不得裁掉流程节点或异常出口。

### 打印与分页

- 默认打印页保持打印机所选纸张尺寸，使用 `12mm` 页边距；标记为 `data-flow-width="wide"` 的流程所在章节使用命名横向页面。浏览器不支持命名页面时必须回退为在当前纸张内完整缩放，不能横向裁切。
- 章节本身允许跨页，避免长章节因整体 `break-inside: avoid` 产生大段空白。标题、图题、紧邻流程的说明、单张流程图、短卡片和表格行分别使用防拆规则；跨页表格重复表头。
- 打印时取消 SVG 的屏幕最小宽度，同时限制最大页内高度并保持 `object-fit: contain`。普通页面流程图最高 `230mm`，横向页面流程图最高 `160mm`，以给图题和页边距保留空间。
- 正文基准字号不得低于 `10pt`，HTML 图题、辅助标签和表格不得低于 `9pt`。边框、连线和正文使用即使关闭背景图形仍可辨认的深色，不依赖浅色填充表达唯一语义。
- SVG 节点文字使用作者坐标，实际纸面字号仍会随整图缩放。若打印预览中节点文字过小，应在正式源中拆分过密流程或重新排布节点，不能用打印 CSS 强制放大文字而造成节点溢出或分支标签重叠。
- 顶部导航、搜索、筛选、展开/收起按钮和横向滚动提示不进入打印结果；关闭状态的 `details` 内容在打印模式下展开，避免脚本或交互状态造成正文缺失。
- 命名横向页面的支持程度取决于打印引擎。Chrome/Edge 等主流浏览器仍应在打印预览中人工抽查至少一张纵向长图、一张横向宽图和一张跨页表格；静态检查不能证明实体打印机驱动的缩放结果。

## 6. CSS 作用域与视觉主题

- 统一视觉令牌定义在 `.cube-flow-page` 下，页面规则以 `.cube-flow-page ...` 为作用域；独立页根规则可使用 `body.cube-flow-page`。
- 新增页面样式不得使用无作用域的 `:root`、`body`、`h1`、`section`、`table` 等选择器影响宿主页面。旧页面中的全局规则由同步工具在嵌入时隔离，但新代码不应继续扩大兼容负担。
- 站内同步时，源页 `<link>` 引入的本地 CSS 和内联 `<style>` 都应经过结构化 CSS 解析并限定到 `.cube-html-inline__body.cube-flow-page.cube-flow-embedded`。`@media`、`@supports` 内的普通规则继续作用域；`@keyframes`、`@font-face`、`@page`、`@property` 和 `@counter-style` 等描述型 at-rule 不改写选择器。
- 业务页保留节点语义类，例如开始/结束、动作、判断、异常和状态；颜色只是辅助提示，不能成为区分分支或状态的唯一方式。
- 配色、字体、圆角、阴影、间距和焦点样式由共享增强样式统一控制。流程正文不要复制整套色板，以便后续调整设计语言时只改视觉层，不批量重写业务 HTML。
- 为兼容既有内联样式，共享增强层可以在明确的流程容器内使用必要的高优先级覆盖；不得把覆盖扩散到文档站其他内容。
- 同时支持 `prefers-reduced-motion: reduce`、`forced-colors: active` 和打印模式。装饰性动画不能影响流程理解或操作，高对比度模式不能只靠作者色维持焦点与边界辨识。

## 7. 脚本的渐进增强

- 搜索、筛选、全部展开/收起等功能可以由脚本增强，但标题、图题、流程 SVG、图例、证据和普通链接必须在脚本关闭时仍可见、可达。
- 脚本使用稳定的 `data-*` 钩子，不依赖颜色、视觉顺序或自动生成类名定位业务内容。
- 不用脚本注入正式流程节点，不在脚本字符串中维护唯一的业务说明，也不在页面加载后替换 SVG 为另一份流程。
- 统一增强脚本只让实测存在横向溢出的流程图和表格进入 Tab 顺序，使用 `←` / `→` 按容器宽度分段滚动；到达边界、存在修饰键或事件来自内部子元素时不得吞掉浏览器默认按键。表格初始位置必须保持第一列，流程图初始位置优先对准入口节点。
- 宽度变化时保留已有相对阅读位置；从无溢出重新进入溢出时，表格回到第一列，流程图回到入口。操作提示及 `aria-describedby` 必须随实测溢出同步，不能出现“提示可滚动但方向键无效”的状态。
- 独立页脚本建议使用 `defer`，并在找不到可选控件时安全退出，不产生阻断正文的异常。
- 站内嵌入会移除脚本，并隐藏没有静态回退意义的独立页工具控件；任何依赖这些控件才能看到的内容都不符合嵌入契约。

## 8. UTF-8 与最小改动

- HTML、Markdown、CSS 和 JavaScript 统一使用 UTF-8；HTML 必须显式声明 `<meta charset="utf-8">`。
- 修改前确认原文件编码和换行风格，写回后进行严格 UTF-8 解码检查，并检查中文标题、图题、节点文字和源码路径没有乱码。
- 纯格式迁移应采用最小编辑：不重排整份 HTML，不格式化 SVG 路径数据，不重命名业务 ID，不改变节点文字、路径 `d`、分支标签、标记引用或源码证据。
- 对已有用户改动的流程页只追加结构与展示属性，不覆盖、不还原业务内容，也不改变暂存区状态。

## 9. 验证清单

### 单页检查

- [ ] 独立打开时标题、导航、全部流程、证据和链接可读。
- [ ] 页面只有一对有效的 `CUBE_EMBED_START/END` 标记，核心正文完整位于标记之间。
- [ ] 每张图都是 `figure + figcaption + viewport + inline SVG`，图题可见。
- [ ] 每个 SVG 都有有效 `viewBox`、`<title>` 和作者摘要 `<desc>`；视觉 SVG 从辅助技术树隔离，可访问名称与说明由外层 viewport 统一提供。
- [ ] viewport 可用键盘聚焦和横向滚动，窄屏不压缩流程文字，也不让整页横向溢出。
- [ ] 每张表格都有可见 `caption`，位于带提示、可聚焦且正确关联 ARIA 的独立横向滚动容器中；400% 等效窄视口下不逐字断行。
- [ ] 统一增强脚本是 `body` 的最后一个元素；流程图和表格在真实焦点下都能用 `←` / `→` 滚动，并在边界处保留默认按键行为。
- [ ] 页面内 ID 唯一，全部 SVG 与 ARIA 引用有效。
- [ ] 关闭 JavaScript 后核心内容仍完整；打印时没有节点、分支或异常出口被裁切。
- [ ] 打印预览中长章节可自然分页，标题/说明不孤立在页尾，宽图进入横向页，表格跨页时重复表头且行不被拆开。
- [ ] 打印正文不小于 `10pt`，图题、辅助标签和表格不小于 `9pt`；关闭“背景图形”后文字、边框、连线和状态标签仍可辨认。

### 批量格式迁移检查

- [ ] 迁移前后 HTML 文件数、SVG 数量、`viewBox`、节点文字、路径数据和业务链接保持一致；任何差异都有明确业务依据。
- [ ] 所有页面均链接统一增强样式，并带有 `cube-flow-page` 标记。
- [ ] 没有新增 PNG 流程图或运行时 Mermaid 依赖。
- [ ] 所有目标文件可按 UTF-8 严格解码，中文抽查无乱码，`git diff --check` 通过。
- [ ] 只修改本次目标文件，没有改写 CPU2/CPU3 README 或其他用户改动，暂存区状态保持不变。

### 文档站检查

- [ ] 在仓库根运行 `py tools\check_flow_docs.py`，正式源的嵌入边界、SVG 结构、ID 与引用契约全部通过。
- [ ] 嵌入页不重复独立页首屏、顶部导航和脚本控件。

## 10. 维护原则

新增或修改流程页时，先保证业务内容可追溯，再套用本规范的结构契约。业务变化更新对应 HTML/SVG、跨页导航和必要索引；仅设计语言变化时优先修改共享增强样式，不逐页复制视觉规则。提交前还应按仓库文档治理要求检查 `docs/README.md`、本目录 README 及相关 CPU2/CPU3 流程入口是否仍可追溯。

## 11. 长期质量目标

- 正式源门禁必须位于仓库 `tools/`，不依赖被忽略的本机预览目录；任何环境都能检查 32 个页面及后续新增页面。
- 站内构建必须记录源文件 SHA-256，并逐页比较最终 DOM 的 figure、SVG、section 和 table 数量；源变化、正文被代码化或结构缺失时检查必须失败。
- 文件链接、页内 fragment、HTML ID、ARIA 与 SVG 引用保持零失效，不能通过剥离 fragment 或宽泛白名单掩盖问题。
- 移动端不主动缩小 SVG 文字，滚动提示、焦点环和滚动条达到清晰可辨；打印输出逐步建立横向页面和最小字号门禁。
- 本地预览同步逐步改为单次、增量、原子且可恢复：未变化文件不重写，失败时保留上一份成功预览。
