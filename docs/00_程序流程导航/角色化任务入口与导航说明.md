# 角色化任务入口与导航说明

## 目的

本说明约束本机预览站的入口层和侧栏分组。目标不是新增业务关系，而是让使用者先按当前任务进入，再复用已有流程、证据、运行、批次和基线页面继续调查。

`docs/` 仍是唯一正式资料源；`docs-site/` 只负责派生展示、检索和路径校验。

## 四类首选入口

| 任务角色 | 首页唯一首选入口 | 第二步关键事实 | 典型完成边界 |
| --- | --- | --- | --- |
| 现场排查 | `/start/troubleshooting/` | 当前变更风险、系统流程地图 | 现象已归类，关联业务链路、核心流程和历史证据可追溯 |
| 开发变更 | `/start/change-impact/` | 变更验证矩阵、验证执行队列 | 源码改动已投影到候选流程、关键语义和分层验证范围 |
| 测试执行 | `/start/validation-queue/` | 验证工作包、真实运行台账、验证批次 | 执行优先级明确，真实运行和批次范围使用稳定身份登记 |
| 交付决策 | `/start/delivery-readiness/` | 当前变更、真实运行、验证批次、交付基线 | 机器可见事实已汇总，未验证边界保持显式，最终判断仍由负责人完成 |

首页不得再次平铺上述内页的所有子页面。系统流程地图作为整机理解入口保留，工程语义搜索用于按现象、符号、流程、证据、版本和验证状态缩小范围，完整索引作为已知文件名或专家检索入口保留；三者都不替代四类任务首选入口。

四个首选入口必须分别写入 `role=field`、`role=development`、`role=test`、`role=delivery`。后续页面按 `任务上下文连续性与工程搜索说明.md` 继续保持任务角色和已知工程范围。

## 两次选择规则

四类任务从首页到关键事实最多经过两次选择：

1. 第一次选择从首页进入该角色唯一首选页。
2. 第二次选择从首选页进入流程、矩阵、工作包、运行、批次或基线等关键事实。

本规则不要求删除深层页面，也不要求把正文复制到首页。首选页只负责承接任务和指向已有事实页面。

## 侧栏生命周期分组

治理页面按证据生命周期组织：

1. `影响与判断`：交付就绪、当前变更和流程治理状态。
2. `覆盖与计划`：证据覆盖、缺口处置、验证工作包和验证矩阵。
3. `执行与结论`：执行队列、证据新鲜度、真实运行和验证批次。
4. `基线与追溯`：交付基线、退化门禁、版本时间轴和历史差异。
5. `规则与迁移`：文档库治理、资料落位和迁移说明。

完整索引继续独立保留，不把专家入口与日常任务入口混在同一层级。

## 自动检查

本机预览站使用以下命令校验角色入口和两次选择规则：

```powershell
cd docs-site
npm run check:task-paths
npm run check:task-context
```

该检查已经接入 `npm run check`，失败关闭以下问题：

- 首页角色入口不是四个。
- 同一角色不存在唯一首选入口。
- 首选入口与本说明不一致。
- 首选页缺少约定的第二步关键事实入口。
- 首页重新出现已淘汰的八条平铺路径或三组重复入口。

自动检查只证明导航契约成立，不证明测试通过、批次关闭、发布安全或现场放行。
