# 交付证据基线生命周期说明

## 目的

生命周期用于明确一份正式交付证据基线当前承担什么角色、由谁作出该决定，以及决定可以回溯到哪份正式说明和 Git revision。生命周期只记录治理决策，不根据文件顺序、日期、固件版本或使用次数自动变化。

## 状态

| 状态 | 含义 | 参与当前对比 | 参与默认趋势 |
| --- | --- | --- | --- |
| `current` | 当前唯一选中的比较基线 | 是 | 是 |
| `superseded` | 已被另一份基线显式替代 | 否 | 是 |
| `retired` | 已停用，不再作为当前治理依据 | 否 | 否 |
| `audit-only` | 只保留审计关系，尚未选用或已转为审计保留 | 否 | 否 |

清单最多只能存在一个 `current` 基线，且必须与 `selectedBaselineId` 一致。没有 `selectedBaselineId` 时不得保留 `current` 状态。

## 事件契约

每个基线保存按发生顺序排列的 `lifecycle` 事件数组，最后一个事件决定当前状态。事件不得覆盖或删除，且必须包含：

- `state`：上述四种状态之一；
- `owner`：对本次保存、选择、替代或停用负责的人；
- `explanationPath`：`docs/` 下真实存在的正式说明；
- `decisionRevision`：作出决定时绑定的完整 40 位小写 Git revision；
- `supersededBy`：只在 `superseded` 事件中填写，并指向另一份已登记基线。

首个事件只能是 `current` 或 `audit-only`。同一基线不得连续追加相同状态。已停用基线不能直接恢复为 `current`；如确需重新评估，应先显式转为 `audit-only`，再执行选择，以保留完整决策链。

## 操作

保存并选中一份新基线：

```powershell
py tools\save_delivery_evidence_baseline.py --id <基线-id> --label "<说明>" --owner "<负责人>" --explanation "docs/<正式说明>.md" --select
```

保存但只用于审计时省略 `--select`。此时初始状态为 `audit-only`。

显式选择、停用或转为仅审计：

```powershell
py tools\manage_delivery_evidence_baseline.py select --id <基线-id> --owner "<负责人>" --explanation "docs/<正式说明>.md" --decision-revision <40位revision>
py tools\manage_delivery_evidence_baseline.py retire --id <基线-id> --owner "<负责人>" --explanation "docs/<正式说明>.md" --decision-revision <40位revision>
py tools\manage_delivery_evidence_baseline.py audit-only --id <基线-id> --owner "<负责人>" --explanation "docs/<正式说明>.md" --decision-revision <40位revision>
```

选择新基线时，旧 `current` 基线会自动追加 `superseded` 事件并通过 `supersededBy` 指向新基线。所有写操作都先验证完整清单；`--dry-run` 可用于只检查下一状态。

## 派生视图与可信边界

- `docs-site/public/data/delivery-baseline-lifecycle.json` 汇总所有基线的当前状态、责任人、说明、决策 revision 和事件数。
- 默认趋势只读取当前状态为 `current` 或 `superseded` 的基线；`retired` 和 `audit-only` 仍保留在生命周期快照中。
- 同一 Git revision 的趋势事实继续合并，别名或迁移记录不会制造重复趋势点。
- Python 工具与站点同步器必须生成完全相同的生命周期和趋势结果；未知 schema、缺失责任字段或选择状态不一致时失败关闭。

生命周期状态不代表测试通过、实机确认、现场批准或安全结论。正式测试正文和决策理由仍以 `docs/` 中被引用的资料为准。
