# 交付证据基线说明

## 目的

交付证据基线用于保存某个明确 Git revision 对应的机器可读交付事实，供后续工作区比较新增影响、已关闭缺口、新出现的未映射源码和正式证据状态变化。

基线只保存关系、状态、路径和版本事实，不复制测试正文，也不表示交付批准、实机通过或现场结论。

## 正式来源

- `交付证据基线清单.json` 是基线选择入口。
- 基线文件统一放在 `交付证据基线/` 目录。
- `docs-site/public/data/current-delivery-evidence.json` 是本机派生快照，不是正式基线。
- 清单使用 `schemaVersion: 2`，每个基线保存不可覆盖的生命周期事件链；状态和责任契约见 `交付证据基线生命周期说明.md`。
- 只有清单中 `selectedBaselineId` 明确指向且生命周期状态为 `current` 的基线才参与站内历史比较；不得按提交时间、文件名或版本标题自动选择。

## 保存条件

保存基线前必须同时满足：

1. 当前证据快照的 `schemaVersion` 为工具明确支持的版本。
2. 快照记录完整 40 位 Git revision。
3. 快照声明工作区干净，确保后续可以从 Git revision 复现。
4. 基线标识、说明、负责人和正式说明路径由操作者明确提供，不使用当前时间自动命名。
5. 生命周期决定绑定完整 40 位 `decisionRevision`；默认使用快照 Git revision。

执行示例：

```powershell
py tools\save_delivery_evidence_baseline.py --id cpu2-v1.22.0.0-cpu3-v1.21.0.0 --label "CPU2 V1.22.0.0 / CPU3 V1.21.0.0 交付基线" --owner "<负责人>" --explanation "docs/<正式说明>.md" --select
```

如果当前工作区有未提交修改，工具必须拒绝保存。应先完成正式提交并重新生成本机证据快照，再显式保存基线。

## 兼容与迁移

- 当前基线清单使用 `schemaVersion: 2`；基线封装和交付证据快照使用 `schemaVersion: 1`。
- 同一 schema 内可以增加不会改变既有字段语义的可选字段。
- 删除字段、改变字段类型或改变状态含义时必须提升 schema 版本，并在校验器和站点同步器中增加显式迁移分支。
- 遇到未知 schema 时直接失败，不自动猜测、降级或从页面文案恢复历史事实。

## 对比口径

站点只比较机器可读字段：

- 受影响流程的新增与移除；
- 当前验证队列项的新增、持续与关闭；
- 未映射固件源码的新增与消除；
- 正式证据状态的显式变化；
- 已登记数量指标的差值。

数量减少不自动解释为风险降低，数量增加也不自动解释为风险升高。最终交付判断仍由负责人结合正式资料、硬件验证和现场条件完成。

历史对比进入自动处置前，还必须遵循 `交付证据退化策略.json` 和 `交付证据退化策略说明.md`。没有显式基线时退化门禁保持“未评估”；策略例外必须精确绑定规则、基线和当前 Git revision。

基线内的正式资料路径通过 `验证证据登记清单.json` 解析为稳定证据 ID。资料重命名后应保留 ID 并登记旧路径别名；未登记路径不得静默丢弃，必须在交付证据覆盖快照中显式显示。详细口径见 `交付证据覆盖说明.md`。
