# 知识治理趋势说明

更新日期：2026-07-12

## 目的

本说明把流程核对窗口、治理事项生命周期、验证批次关闭和交付基线生命周期组合为稀疏的月度治理视图。这张视图用于安排文档复核、测试资源和现场验证，不用于证明测试通过、质量改善或允许交付。

## 权威边界

- `知识治理月度快照清单.json` 是月度历史的唯一正式源；`docs-site/` 只读取清单并生成浏览视图。
- 快照只能绑定完整的 40 位 Git revision，且记录时目标范围必须工作区干净。
- 同一月只保留一个快照；新月份只能追加，不覆盖历史点。
- 快照仅保存稳定治理身份、事实指纹、责任组、生命周期状态、流程页键、已关闭批次身份和基线生命周期身份；不复制测试步骤、观测、结论或异常正文。

## 月度视图回答的问题

1. **流程核对是否超窗**：仅按 `流程证据清单.json` 中的 `reviewedAt` 和明示策略窗口计算。
2. **问题是否反复或跨版本未清零**：只比较不同正式月份中相同的 `gov-*` 身份和 SHA-256 事实指纹。
3. **外部等待是否长期存在**：只统计连续月度快照中仍为 `waiting-external` 的治理身份。
4. **批次和基线是否形成长期节奏**：只使用正式批次的 `closed` 身份和基线的明示生命周期状态。
5. **责任和业务投影在哪里**：当前事实和历史高频项按责任组归集，并用稳定流程页键反查 `业务链路清单.json`。无流程页键的全局事项保持为“未投影”，不猜测业务归属。

## 禁止的推断

- 不统计页面访问量、文件修改时间、标题关键词或卡片颜色。
- 不将告警数量、关闭数量或基线数量换算为综合分数。
- 不把“本月没有快照”显示为“没有问题”，也不把“没有重开事件”显示为“系统稳定”。
- 不使用脏工作区、非正式预览产物或自然语言描述伪造历史点。

## 记录流程

1. 保持目标工作区干净，运行文档与站点全量门禁。
2. 重新同步本机预览，确认 `governance-queue.json`、`validation-batches.json` 和 `delivery-baseline-lifecycle.json` 与当前 revision 一致。
3. 使用 `manage_knowledge_governance_snapshot.py` 生成当月快照，并引用一份 `docs/` 下的正式说明。
4. 重新运行全量门禁；确认月度视图仅新增一个稀疏点，且跨版本持续项、重开项和等待外部项投影正确。

```powershell
py tools\manage_knowledge_governance_snapshot.py `
  --recorded-at 2026-08-01T10:00:00+08:00 `
  --explanation "docs/00_程序流程导航/知识治理趋势说明.md" `
  --dry-run
```

去掉 `--dry-run` 后工具才会原子追加。工具不会替责任人创建治理事件、验证运行、批次结论或交付批准。
