CPU3 RTC 真实时间兼容电路修改方案

结合当前 CPU3 原理图、SI 寄存器需求和 STM32F429 RTC 资源整理。整理日期：2026-06-13。

1. 结论

要让 30007~30010 锁存 profile 完成时刻、30011~30013 输出当前时分秒，并且在外接 RTC、LSE+备份电池、PLC/菜单校时后都输出真实时间，硬件必须提供一个“不断电或可恢复”的真实时间来源。

推荐量产方案

优先 使用 STM32F429 内部 RTC，加 32.768 kHz LSE 晶体和 VBAT 备份电池/超级电容。

优点是 BOM 少、固件接口简单、CPU3 现有 Cpu3Clock_GetDateTime() 可以直接承接。

当前图纸限制

必须改 当前 CPU3 图纸中 VBAT 直接接 3V3，断主电后不保时。

PC15/OSC32_OUT 当前接到 WLED1，不能同时作为 LSE 晶振脚。

备选方案

可选 如果不方便释放 PC15，就外接 I2C RTC，并新增 RTC 芯片电池域。

PLC/菜单校时只负责设置时间，不能替代断电保时硬件。

3. 推荐改法：LSE + VBAT 备份

这一路径最适合新板修订。核心动作是释放 PC14/PC15 给 LSE，重做 VBAT 为独立备份电源域，并保留 PLC/菜单校时作为设置时间入口。

3.1 必改网络

网络 修改要求 说明
VBAT 断开当前 VBAT 到 3V3 的直接硬连接，改为电池/超级电容备份域。 建议用跳帽或 0 欧电阻做选配：无电池版本可短接到 3V3，有电池版本不得让主 3V3 反向充 CR2032。
PC14/OSC32_IN 接 32.768 kHz 晶体一端，旁路负载电容到地。 走线短、远离 RS485、DC/DC、电机/继电器、OLED SPI 等快速或强干扰网络。
PC15/OSC32_OUT 从 WLED1 断开，接 32.768 kHz 晶体另一端，旁路负载电容到地。 这是当前原理图的主要冲突点。LSE 使用后，PC15 不能再接显示接口或 LED 负载。
WLED1 改到其他背光控制方式：并到 WLED2、固定上拉供电，或移到一个确认空闲 GPIO 通过三极管/MOS 管驱动。 不建议 MCU 管脚直接承受背光电流。若需要亮度控制，应单独用驱动管并预留限流。
PDR_ON 保持接 3V3。 不要为节省器件改成悬空或其他状态，否则会影响备份域可用性。

3.2 建议器件和布局

  • 晶体：32.768 kHz、低 ESR、低负载电容型号，优先选 CL=6 pF 或 CL=7 pF 的表晶，便于降低负载电容和启动风险。
  • 负载电容：先按晶体 CL 和 PCB 寄生电容估算，建议预留 6.8 pF、8.2 pF、10 pF 调试档位，不要照搬 HSE 的 22 pF。
  • 电容材质：LSE 负载电容用 C0G/NP0，小封装、靠近 MCU；VBAT 去耦至少放 100 nF 靠近管脚。
  • 电池：CR2032 正极接 VBAT、负极接 GND；非充电电池不得接充电通路。超级电容方案需串限流电阻/二极管，并保证 VBAT 不超过器件允许范围。
  • 测试点：可以给 VBAT 预留测试点；不建议在 PC14/PC15 晶振线上挂长测试点或跨板走线。
如果只把 VBAT 加电池，但仍使用当前 LSI 作为 RTC 时钟，断电后时间可能能继续走，但精度仍受 LSI 影响；如果只加 LSE 但 VBAT 仍并到 3V3，掉电后仍会丢时间。真实时间要求两部分一起闭环。

4. 备选改法：外接 RTC 芯片

如果当前 PCB 版本不方便释放 PC15/WLED1，外接 RTC 是更少动 MCU 晶振脚的方案。它需要新增 RTC 芯片、电池域和两根通信线。

引脚/网络 连接建议 注意事项
RTC_VCC 接 CPU3 3V3，旁边放 100 nF。 与 CPU3 逻辑电平一致。
RTC_VBAT 接 CR2032 或超级电容备份。 按所选 RTC 芯片手册处理充电/非充电配置。
SCL/SDA 接 CPU3 两个确认空闲的 GPIO 或 I2C 复用脚，外拉 2.2 kΩ~4.7 kΩ 到 3V3。 当前 CPU3 固件未启用 I2C。若选非 I2C 复用脚，可用软件 I2C，但要评估实时性和抗干扰。
INT/SQW 可不接；如需 1 Hz 校准或闹钟唤醒，可接一个空闲 GPIO。 当前 SI 时间寄存器不强制需要中断。
GND 接 CPU3 数字地。 远离 RS485 浪涌回流和 DC/DC 大电流回路。

4.1 当前图纸下的引脚选择原则

  • 不要占用 PB8/PB9/PB12，它们当前是 COM 口模式选择输出。
  • 不要占用 PF1~PF4，它们当前是按键输入。
  • 不要占用 PE11~PE14，它们当前是 FRAM 的 SPI4。
  • 不要占用 PC6/PC7、PD5/PD6、PD8/PD9，它们当前是外部通信串口。
  • 图纸上可见的未命名 GPIO 需要结合 PCB 走线、连接器和装配版本再定稿；若只是新板修订，可优先从未接网络中挑两根并做软件 I2C。
外接 RTC 方案可以保留 PC15/WLED1，但固件需要新增 RTC 芯片读写、掉电后启动读取、PLC/菜单校时写 RTC、通信异常时的时间有效性判定。

5. PLC/菜单校时的电路含义

PLC/菜单校时本质是“写入时间”，不是“保持时间”。电路要按现场期望分两档处理：

只要求上电后校时 可不改硬件；PLC 或菜单设置时间后，CPU3 在不断电期间输出真实时间。缺点是掉电后必须重新校时，LSI 长时间运行会漂移。
要求断电后仍真实 必须改硬件：采用 LSE+VBAT 或外接 RTC+电池。PLC/菜单校时只负责首次设置或现场校准。
要求长期精度 优先 LSE 晶体或温补外接 RTC。内部 LSI 只能作为兜底，不能作为长期真实时间基准。

6. SI 寄存器输出关系

寄存器 输出内容 硬件/固件条件
30007 Profile 完成时刻：月 CPU2 完成 profile 并递增完成计数后，CPU3 读取当前真实时间并锁存。下一次 profile 完成前保持该次完成时刻。
30008 Profile 完成时刻：日
30009 Profile 完成时刻：时
30010 Profile 完成时刻：分
30011 当前时间：时 每次刷新输入寄存器时读取 CPU3 当前真实时间。时间源可以是 LSE RTC、外接 RTC 同步后的本机时钟，或 PLC/菜单校时后的运行时钟。
30012 当前时间：分
30013 当前时间：秒
不建议把这些时间寄存器反向耦合到 CPU2 测量调度。它们应保持“协议展示/时间戳”用途，自动 profile 调度若后续要做，需要单独设计互斥条件、掉电恢复和安全边界。

7. 推荐落地顺序

  1. 硬件评审先确认 WLED1 是否必须由 MCU 控制。如果不是必须，优先释放 PC15。
  2. 新板修订采用 PC14/PC15 + 32.768 kHz LSE + VBAT，同时把 VBAT 从当前 3V3 直连改为可选备份电源域。
  3. 如果 WLED1 不能释放，改走外接 RTC，先定两根不冲突的 CPU3 GPIO/I2C 线，再更新 .ioc 和驱动。
  4. 固件把 Cpu3Clock 抽象成统一时间源：LSE RTC、外接 RTC 同步、PLC/菜单校时都通过同一接口输出给 SI。
  5. 联调时验证：断主电再上电，30011~30013 不回到默认时间；完成一次 profile 后，30007~30010 保持完成时刻，不随当前时间滚动。
