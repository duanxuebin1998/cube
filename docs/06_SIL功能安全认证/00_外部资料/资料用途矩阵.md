# SIL 外部资料用途矩阵

更新日期：2026-06-30

本文按 SIL 准备工作场景说明外部资料的用途、优先级和获取状态。它只作为阅读顺序和资料定位入口，不替代正式采购标准、认证机构要求或公司受控质量体系文件。

## 使用边界

- 外部 PDF、厂商包和案例资料只作为输入资料；CUBE 自身认证计划、架构决策、偏离记录和整改清单以本目录 Markdown 为维护正文。
- IEC、MISRA、厂商 FMEDA/FMEA、工具资质包等受版权、采购或 NDA 限制的资料，只记录获取路径和使用场景，不绕过访问控制。
- 新增外部资料时优先更新各子目录 README；本文可后补，不影响固件版本提交和 skill 生成版本文档。

## 优先级说明

| 优先级 | 含义 |
| --- | --- |
| 必读 | 当前 SIL2 准备、软件生命周期、编码整改或证据包设计的基础输入 |
| 重点参考 | 与 CPU2/STM32 安全机制、诊断、测试策略强相关，需要在方案设计时查阅 |
| 选读 | 用于补充背景、案例对照或沟通准备 |
| 采购/NDA | 只能记录官方获取路径，正式引用前需采购、授权或签署 NDA |

## 后续维护建议

- 每新增一份外部资料，先在所在子目录 README 补来源、用途、本地状态和版权/授权限制。
- 如果资料直接影响 CUBE 架构或编码规则，再同步到 `../CUBE功能安全认证详细工作计划.md`、`../CPU2编码规范.md` 或安全模块清单。
- 不把外部资料结论写成已经认证完成；所有认证结论必须来自项目证据包和认证机构确认。
