# 传感器安全通信相关标准适用矩阵

更新日期：2026-07-03

本文用于把“重新设计传感器通信协议以满足 SIL 认证要求”涉及的标准、适用边界和 CUBE 证据包落点整理到文档库中。它只作为工程选型和认证沟通入口，不替代官方完整标准、认证机构评估计划或公司受控质量体系文件。

## 结论先行

- SIL 认证对象不是单个通信协议，而是某个安全功能及其完整实现链路。传感器通信只是在安全功能链路中的输入通道或诊断通道。
- 自研传感器协议如果承载安全相关数据，应按 black channel 思路设计安全通信层：底层 UART、RS485、CAN、Modbus、SPI、I2C 或无线链路均视为不可信，安全性由两端安全层和系统诊断闭环证明。
- CUBE 当前资料路线以 IEC 61508 / GB/T 20438 为基础；若传感器信号进入联锁、停机、限位、防溢、防干转、防失控等安全功能，应同步评估 IEC 61784-3、IEC 62280、行业标准和网络安全标准。
- 若目标是 SIL 2，优先选用有功能安全资料、FMEDA/FMEA、失效率数据和安全手册的传感器或安全输入模块；若目标上升到 SIL 3，不建议只靠普通传感器加自研协议闭环。

## 传感器通信标准选型路径

1. 先定义安全功能，而不是先定义帧格式。示例：传感器超限、断线、失效或数据过期时，CPU2 必须在规定时间内进入安全状态。
2. 判断传感器数据是否参与安全功能。
   - 不参与安全功能：按普通通信协议、诊断和稳定性要求处理，不声明该链路满足 SIL。
   - 参与安全功能：进入安全生命周期，编写 SRS，分配 SIL，定义安全状态和故障反应。
3. 判断通信方案是否已有安全 profile 或认证组件。
   - 有：优先采用供应商安全手册、证书、FMEDA/FMEA 和限制条件，减少自研证明负担。
   - 无：按 black channel 自研安全层，并提前让认证机构确认评估路线。
4. 判断行业场景。
   - 过程工业 SIS：补充 IEC 61511 / GB/T 21109。
   - 机械安全：补充 IEC 62061 或 ISO 13849-1。
   - 网络化或无线：补充 IEC 62443，并把安全与网络安全的威胁边界分开写。
   - EMC 可能导致危险失效：补充 IEC 61000-1-2、IEC 61326-3-1 或 IEC 61000-6-7。

## 自研安全通信层最低证据要求

| 风险 | 协议层建议措施 | 验证证据 |
| --- | --- | --- |
| 数据损坏 | Safety CRC 覆盖源/目的、功能 ID、版本、序列号、长度、负载和常量种子 | CRC 篡改、单 bit、多 bit、截断、粘包和半包测试 |
| 丢帧或超时 | 周期计数、超时窗口、最大数据年龄 | 丢帧、连续丢帧、长延迟、总线阻塞注入测试 |
| 重复或重放 | 单调序列号、会话计数、上电随机数或安全启动计数 | 重放旧帧、重复当前帧、上电后旧帧注入测试 |
| 乱序 | 序列窗口和方向性检查 | 乱序帧、跨传感器交换帧测试 |
| 伪装或地址错误 | 源 ID、目的 ID、传感器 ID、功能 ID 纳入 CRC | 地址替换、传感器 ID 替换、错误节点响应测试 |
| 版本或配置不匹配 | 协议版本、安全参数版本、量程/单位/比例因子版本 | 版本不一致、参数缺失、单位错误和比例因子错误测试 |
| 数据越界或冻结 | 物理范围、变化率、诊断位、数据新鲜度检查 | 边界值、异常跳变、长期不变、诊断状态未更新测试 |
| 通信恢复误判 | 错误锁存、恢复确认窗口、证明测试或人工复位策略 | 单帧恢复、抖动恢复、掉电重启后恢复测试 |
