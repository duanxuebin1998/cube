# IEC 61784-3 传感器通信与功能安全手册（工程版）

更新时间：2026-07-03

## 1. 标准定义

`IEC 61784-3` 的完整名称为：
**Industrial communication networks - Profiles - Part 3: Functional safety fieldbuses**。

核心目标是定义工业现场总线/工业网络中的**安全功能通信**（functional safety）的一致性配置和协议映射，通常用于承载具有安全意义的数据（safety relevant messages）。

授权获取和正式引用时，优先确认 `IEC 61784-3:2021+AMD1:2024 CSV` 是否作为项目受控版本。若认证机构指定其他版本或行业 profile，以认证机构评估计划为准。

## 2. 与项目的关系

- 如果通信仅用于普通测量数据、状态上报、参数查询，不直接参与紧急停机、联锁、限位防护等安全动作，通常不要求直接按 `61784-3` 进行协议实现。
- 如果该通信链路直接影响安全功能（例如：
  - 紧急停机触发链路
  - 安全联锁闭锁
  - 高低液位/超限防护闭环信号
  - 任何用于 SIL/PL 安全需求分配的传感器回路），则需按安全通信规范评估并与项目 SIL 架构一致实施。

## 3. 判定逻辑（建议用于本项目评审）

在做需求评审时按以下三步判断是否需要 `IEC 61784-3`：

1. 该信号是否是安全功能的输入或输出？
   - 是 → 进入下一步
   - 否 → 一般使用现有通信规范即可
2. 项目是否按 IEC 61508 等功能安全生命周期进行安全等级分配（SIL 目标已确认）？
   - 是 → 按安全等级选用对应的安全通信方案
   - 否 → 先完成安全等级和安全场景分解，再确定是否适配
3. 传感器厂商或总线设备是否提供对应 `IEC 61784-3` 安全通信特性（安全诊断、冗余校验、错误约束机制）与认证能力？
   - 是 → 评估选型符合性、证据链、测试闭环
   - 否 → 不能直接把普通通信当作安全通道使用

## 4. 工程实施要点

1. **边界定义**：把“安全相关信号”与“非安全信号”分离。
2. **协议匹配**：确认总线是否支持安全协议 profile（如厂商提供的 safety profile）。
3. **证据链**：安全功能通信必须有：
   - 安全需求（SRS）链接
   - 架构图中通信链路标注
   - 测试记录（异常注入、通信中断、CRC/序列号/报文一致性等）
   - 配置与版本变更记录
4. **变更控制**：通信参数和安全相关固件参数必须进入配置项变更流程（与 SIL 证据包一致）。

## 5. 与本项目的结论化建议

- 当前项目若涉及 LNG 计量、液位测量、故障保护等场景，建议先确认“哪些传感器通道属于安全相关回路”。
- 对于**普通监测型传感器通信**，优先执行现有协议兼容、链路稳定性、故障检测即可。
- 对于**安全相关回路**，除功能安全软件开发流程（IEC 61508-3）外，还要校验 `61784-3` 对应安全通信能力是否被满足。
