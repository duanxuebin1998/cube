二、做 SIL 认证时的正确用法

  1. 先定义项目安全范围，不要先套库。 明确 LNG 计量仪哪些功能是安全相关功能，例如电机运动安全停机、上电默认安全态、故障恢复边界、参数保护、通信命令误触发防护等。 输出物应是安全功能清单、危险场景、SIL 目标来源和 CPU2/CPU3 安全相关范围。
  2. 用 STM32F4 Safety Manual 反查硬件和软件约束。 把 Safety Manual 中的使用假设、时钟/Flash/RAM/复位/中断/外设限制转成项目约束。 对 CPU2 的 STM32F429ZGTx，要逐项确认实际硬件设计、初始化默认电平和故障处理是否满足这些假设。
  3. 用 FMEA/FMEDA 资料做项目级分析输入。 ST 的 FMEA/FMEDA 只能提供芯片级参考和假设，不能直接变成整机指标。 项目需要结合主控板、电机驱动、编码器、传感器供电、通信接口、本安边界和软件诊断策略重新计算或评审。
  4. 决定是否采用 X-CUBE-STL 自检库。 如果采用，需要定义自检项、运行阶段、调度周期、运行耗时、失败处理、错误上报、看门狗关系和对实时测量流程的影响。 如果不采用，也要说明用什么等效诊断或为什么不需要该诊断。
  5. 把 ST 文档要求落到工程文档和代码门禁。 将约束同步到 CPU2编码规范.md、CPU2安全相关模块清单.md、整改检查表、版本改动与测试方案和后续测试记录。 代码层面要形成可审计的安全状态机、启动安全、故障处理、参数校验和构建范围控制。
  6. 生成认证证据，而不是只保存资料。 每条安全要求都应能追溯到设计、代码、测试、评审和偏离记录。 ST 资料作为外部证据输入，项目自己的验证报告才是证明本产品满足要求的核心。

五、不要这样用

  • 风险 不要把 X-CUBE-STL 当成“装上就满足 SIL2”的库。SIL 是系统级结论，不是单个库的结论。
  • 风险 不要直接把 ST 的 FMEDA 指标复制到项目报告。必须检查硬件电路、诊断配置、运行条件和失效假设。
  • 风险 不要把包内示例源码直接混进 CPU2 安全发布构建。需要先做许可证、版本锁定、构建范围和测试影响评审。
  • 风险 不要只做 MISRA 整改而不做需求、设计、测试和变更控制。SIL 认证看完整生命周期证据。
  • 风险 不要忽略 ST Safety Manual 的使用假设。任何不满足的假设都需要项目级缓解措施或偏离说明。

八、按当前 CPU2 安全功能分离代码

当前安全功能定义： CPU2 是安全功能板，安全功能应定义为“液位测量结果输出 4-20mA”和“液位测量结果驱动四路继电器 HH/H/L/LL 液位报警信号”。 因此，安全边界不是整个 CPU2 所有功能，而是从液位有效性判断、阈值判断、4-20mA 输出、继电器报警输出、输出反馈和故障降级组成的一条闭环链路。
分层 应归入安全功能代码 当前工程对应位置 分离要求
S0 安全输出核心 液位有效性、液位新鲜度、量程换算、4-20mA 输出、四路继电器 HH/H/L/LL 报警输出、故障电流、输出反馈确认。 建议新建 LTD_MAIN_CPU2/Safety/Output/，现有 AD5421 在 BSP/Peripherals/src/ad5421.c，继电器 GPIO 在 Core/Src/gpio.c。 非安全代码不得直接调用 AD5421_SetCurrent() 或 HAL_GPIO_WritePin(RELAYx)，只能通过安全输出 API 请求。
S0 故障和降级 传感器失效、液位无效、AD5421 fault、继电器反馈不一致、STL 自检失败、参数 CRC 失败后的安全动作。 Application/Src/fault_manager.c、Application/Src/app_main.c。 故障后进入明确的安全输出状态：4-20mA 输出故障电流，继电器进入约定的报警/失电安全状态，错误锁存到统一故障入口。
S1 液位测量输入 液位寻找、跟随、位置计算、频率读取、传感器模式切换、编码器/电机位置源。 Application/Src/measure_oilLevel.c、Services/Sensor/、Services/Encoder/、Services/MotorControl/。 这些模块可作为安全功能输入，但必须输出“液位值 + 有效标志 + 时间戳 + 质量状态”，不能让安全输出层直接读一堆全局变量后自行猜测。
S1 安全参数 液位 HH/H/L/LL 报警阈值、继电器通道配置、4-20mA 量程、故障电流、报警滞回、无效液位策略。 Services/ParamStorage/system_parameter.h 中已有 AlarmHighDO、AlarmLowDO、AlarmHighAO、AlarmLowAO、FaultCurrent_mA 等字段。 参数写入必须做范围、单位、互斥关系和 CRC 校验；参数异常时不能继续使用旧的不可信值驱动安全输出。
S2 通信和显示 Modbus/HART/CPU3 显示、安全状态查询、参数配置入口。 Services/Modbus/、Services/Hart/。 通信只能请求参数或读取状态，不能绕过安全输出层直接改变继电器或电流输出。HART 通信和 AD5421 输出驱动要拆开。
S3 非安全/调试 测试命令、现场调试串口、密度测量、水位跟随、无线配对、日志打印、人工观察流程。 Application/Src/test.c、部分临时串口命令、非液位安全输出相关测量流程。 安全发布构建必须排除或用编译开关禁用。非安全功能可以存在，但不得作为安全动作依据。

安全发布构建必须改显式源码清单

当前 LTD_MAIN_CPU2/CMakeLists.txt 使用 file(GLOB ... Application/Src/*.c) 和 file(GLOB_RECURSE ... Services/*.c) 自动收集源码。 对 SIL 准备来说，这不能作为安全发布基线，因为 Application/Src/test.c、临时调试命令或新加的非安全文件可能自动进入固件。

构建集合 说明 处理原则
CPU2_SAFETY_SOURCES 安全输出核心、故障处理、液位输入快照、STL wrapper、必要底层驱动。 显式列出，每次发布评审；静态分析和单元测试优先覆盖。
CPU2_SUPPORT_SOURCES 传感器、编码器、电机、参数、通信中会影响安全输入或参数的支撑模块。 允许进入安全发布，但必须受安全 API 和参数校验约束。
CPU2_NONSAFETY_SOURCES 密度、水位、无线、日志、普通协议功能等不属于液位安全输出的模块。 可以编译进普通固件，但不能直接写安全输出；进入安全发布前要有影响分析。
CPU2_DEBUG_SOURCES test.c 和串口调试硬件直控入口。 安全发布构建排除，或由 CPU2_ENABLE_DEBUG_COMMANDS=0 强制禁用。

九、X-CUBE-STL 自检库引入方案

X-CUBE-STL 的作用是给 STM32 内核、Flash、RAM 等提供诊断测试模块。它不能替代液位测量、AD5421、继电器和传感器本身的诊断。 在当前项目中，它应作为 Safety/Diagnostics 的一个输入：STL 通过则允许安全输出进入正常模式，STL 失败则进入故障电流和报警安全态。

步骤 动作 当前项目注意点
1. 固定包版本 只引入 STM32_Safety_STL/Inc、Src/stl_util.c、定制后的 stl_user_param.c 和 Lib/STL_Lib.a。 不要复制整个示例工程；把许可证、发布说明和 Safety Manual 作为受控外部资料保留。
2. 定制 Flash/RAM 地址 以 stl_user_param_template.c 为模板生成项目自己的 stl_user_param.c。 CPU2 是 STM32F429ZGTx，模板中 STM32F429xx 的 Flash 结束地址为 0x081FFFFF，还要结合当前 linker script 核对实际使用范围。
3. 修改 linker script 为 STL RAM backup buffer 增加 backup_buffer_section，并保证 RAM 自检范围避开该区。 否则 RAM 测试会破坏 STL 备份区或业务数据，认证时也无法解释 RAM 测试范围。
4. 建 wrapper 新建 Safety/Diagnostics/safety_stl.c，只在 wrapper 内调用 STL_SCH_* API。 业务代码不直接调用 STL；所有 STL 结果统一映射到安全故障码和故障输出策略。
5. 启动自检 在允许正常 4-20mA 和继电器输出前，运行 CPU 核心测试、Flash 配置测试和必要 RAM 启动测试。 自检未通过时不进入正常安全输出，直接输出故障电流并置报警状态。
6. 运行时分片自检 在 App_MainLoop() 或安全监督 50ms 周期中调度短耗时测试，RAM/Flash 用 subset 分片。 必须实测每个 STL 调用耗时，不能影响液位更新、继电器报警输出、AD5421 写入和看门狗窗口。
7. 失败处理和证据 STL 返回 STL_FAILED、STL_ERROR 或 API 返回 STL_KO 时，锁存安全故障。 记录测试项、返回状态、时间戳、固件版本；验证故障注入时会进入故障电流和继电器安全态。

推荐调度策略

测试项 建议阶段 通过后允许什么 失败动作
CPU TM 启动必测，运行时周期复测。 允许安全监督进入正常周期。 锁存 STL 故障，4-20mA 输出故障电流，继电器进入安全报警态。
Flash TM 启动时覆盖安全代码区，运行时按 section 分片。 允许继续使用当前固件安全逻辑。 认为程序存储完整性异常，禁止正常安全输出。
RAM TM 启动和运行时按 subset 分片。 允许使用安全状态对象和运行时变量。 认为运行数据存储异常，输出故障电流并报警。
用户自检 通过 STL user test 或 safety wrapper 调度。 AD5421 fault/status、继电器 NC/NO 反馈、参数 CRC、液位输入新鲜度均正常时允许正常输出。 按对应诊断项进入故障或报警状态。

引入前必须先补的项目诊断

  • AD5421：初始化后读取 AD5421_FAULT 引脚和 READFAULT 状态；每次电流输出变化后做写后确认或状态确认。
  • 继电器：明确 HH/H/L/LL 液位报警对应继电器通道、失电安全态、NO/NC 反馈输入和反馈超时。
  • 液位输入：明确无效液位、超时未更新、手动/强制动作期间报警抑制的安全策略。
