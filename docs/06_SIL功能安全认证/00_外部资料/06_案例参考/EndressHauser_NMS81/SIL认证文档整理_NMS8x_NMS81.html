1. 先看结论

SIL 2 NMS8x 设备硬件安全完整性等级为 SIL 2。单通道 HFT=0 时可用于最高 SIL 2 应用。
SC 3 系统能力 Systematic Capability 为 SC 3。它说明系统性失效控制过程可支持到相应等级。
SIL 3 证书说在 HFT=1 的架构下可用于最高 SIL 3 应用。常见理解是需要冗余架构，不是单台设备自动变成 SIL 3。
2028-06-29 TÜV 证书有效期到 2028-06-29。项目采购、投运、审查前应再次核对证书状态。
这两份文件说明了什么： E+H Proservo NMS8x 这类液位计已经通过第三方功能安全评估；只要选型、安装、配置、锁定、proof test、维护和修改都符合安全手册，它可以作为 SIS 中的传感器/输入设备参与实现 SIL 保护功能。
这两份文件不能替代什么： 不能替代我们项目自己的 HAZOP、LOPA、SRS、安全回路设计、PFDavg 计算、proof test 周期设定、调试验证记录、运行维护记录，也不能直接证明整条安全仪表功能已经达到 SIL 2 或 SIL 3。

证书的边界

  • 证书只对“与被测产品相同的产品”有效。订货选项、硬件版本、固件版本、铭牌 SIL 标识都要核对。
  • 证书覆盖的是设备能力，不是我们现场安全功能的完整认证。完整 SIF 还包含逻辑单元、执行机构、供电、布线、旁路、操作规程和维护规程。
  • 证书要求考虑操作手册和安全手册，因此安全手册中的 proof test、锁定、维修和修改要求应纳入项目文件。

脚注和适用条件

脚注 第5页含义 项目影响
1) 有效订单码和订单码排除项由 E+H 订货系统维护。 不要只凭型号名称判断，必须核对完整订单码和厂家订货系统确认。
2) FIT = Failure In Time，即每 10^9 小时的失效次数。 换算到每小时失效率时，196 FIT = 196E-9 /h = 1.96E-7 /h。
3) 数值适用于平均环境温度最高 +40 °C；若长期接近 +60 °C，需应用 2.1 的系数。 高温现场不能直接套用表中失效率，PFDavg/PFH 计算可能需要乘以温度系数。
4) PTC = Proof Test Coverage。 PTC 是定期验证覆盖率，不是在线诊断覆盖率。
5) 所有诊断功能至少在诊断测试间隔内执行一次。 这说明设备内部诊断不是实时连续每毫秒都完整执行，而是有最大诊断周期。
6) 故障响应时间是从错误识别到错误响应之间的最大时间。 做 SIF 响应时间验证时，应把它作为传感器/设备响应的一部分纳入总响应时间。

第5页最重要的项目结论

  • 第 5 页给出了完整的失效率和 PFDavg/PFH 摘要，是做初步 SIL 计算时非常关键的一页。
  • MIN、MAX、RANGE 三种安全功能在该页列出的 FMEDA 数值相同：λDU 196 FIT、λDD 6095 FIT、λS 2551 FIT、SFF 97%。
  • 单通道 1 年 proof test 周期下，声明页给出 PFDavg = 9.06E-4；但硬件安全完整性勾选仍是 HFT=0 时 SIL 2 capable。
  • 如果目标是 SIL 3，不能只引用 PFDavg 数值，必须采用 HFT ≥ 1 的多通道架构，并处理 β/βD 共因失效。
  • 高温工况要特别注意脚注 3：长期接近 +60 °C 时，失效率计算可能要应用 2.1 系数。
  • 第 5 页的硬件日期是 2016-11-28 后，第 9 页文字是 2016-11-23 后；正式资料包建议把这个差异列为厂家确认项。

4.11 SIL确认和锁定

手册要求配置必须满足两个概念：

  • Locking concept：配置完成后锁定设备，符合 IEC 61511-1:2016 11.6.3 对参数保护的要求。

Expert mode 下锁定顺序

  1. 完成配置，并遵守手册中的参数要求。
  2. 启动调试检查：Diagnostics -> Device check -> Commissioning check = Start。液位与参考位置距离至少 500 mm。

  6. 执行功能测试：MAX/MIN 监测至少到达一个超过或低于开关点的液位/电流；范围监测建议覆盖整个测量范围的 5 个值。

  8. 再次输入锁定码 7452 设置写保护，并确认 Locking status = SIL locked。

4.12 Proof testing 定期验证

Proof test 的目的是按周期验证安全功能可用性和检测随机设备失效，尤其是危险未检测失效 λDU。周期由操作方制定。测试必须验证设备与所有 SIS 组件的交互，而不是只看仪表显示。

单通道架构下手册给出的 PFDavg 关系式：
PFDavg = 1/2 * PTC * λDU * T1 + λDD * MTTR + 1/2 * (1 - PTC) * λDU * LT
安全功能 测试序列 手册表格中的 PTC 小节末尾文字 说明
液位测量 A - Approach the level 99% PTC = 0.99 通过真实接近液位测试，覆盖率最高，推荐作为强验证。
液位测量 B - Simulation of the level 91% 文字写“detects 91%”，但又写 PTC = 0.88 文档内部不一致，正式计算前应向 E+H 或认证机构确认。
液位测量 C - Simulation of the level and single-point verification of the level 97% 文字写 PTC = 0.95 文档内部不一致，正式计算前应确认采用值。
电流输入测量 D - Feed in real currents 99% PTC = 0.99 输入真实电流进行测试。

Proof test 通用要求

  • 测试期间必须采取替代监测措施保证过程安全。
  • 所有盖板密封和电缆入口密封也要检查。
  • 如果任一测试判据不满足，设备不得继续作为 SIS 的一部分使用。
  • Proof test 只覆盖随机设备失效，不覆盖系统性失效。介质属性、工况、挂料、腐蚀等系统性原因必须另行评估。
  • 模拟量测试建议使用精度优于 ±0.1 mA 的测量设备。
  • 数字输出测试建议使用精度优于 ±0.1 Ω 的电阻测量设备。
  • 数字继电器自监测时，闭合判据通常为小于 1 Ω，打开判据为大于 1 MΩ。

Logic unit 逻辑单元 接收输入并执行安全逻辑的设备，例如安全 PLC 或限值信号变送器。 必须识别 NMS81 的超限、开路、失败电流、故障码映射。
Actuator 执行机构 执行安全动作的最终元件，例如切断阀、泵停机、断电接触器。 整条 SIF 的 PFDavg 往往由执行机构贡献较大，不能只看仪表证书。
Safe state 安全状态 过程风险被降低到可接受水平的状态。 例如停止进料、关闭阀门、停泵、报警并联锁。必须在 SRS 中定义。
Fail-safe mode 故障安全模式 设备检测到故障后输出可被下游识别的故障状态。 NMS81 对模拟量可输出 ≤3.6 mA 或 ≥21.0 mA，对数字量打开继电器触点。
MAX monitoring 高限监测 超过上限时触发安全功能。 典型为溢流保护。
MIN monitoring 低限监测 低于下限时触发安全功能。 典型为泵干运行保护。
Range monitoring 范围监测 监测测量值是否在允许范围内。 proof test 通常要求覆盖范围的 5 个点。
HH/H/L/LL alarm 高高/高/低/低低报警 不同严重程度或位置的限值报警。 数字输出配置时要把有效范围放在 HH、H、L、LL 限值之间。
WHG German Water Resources Act context 在 E+H 菜单中常与 SIL 锁定/确认放在一起出现的保护相关功能标识。 本手册菜单项写作 SIL/WHG confirmation 和 Deactivate SIL/WHG。

5.3 失效、诊断和可靠性术语

术语 含义 对输出信号的影响 项目影响
λ 失效率的符号，lambda。单位通常与时间相关，例如 1/h。 不同 λ 类别决定 PFDavg、诊断覆盖和 SIL 计算。 FMEDA 报告通常给出各类 λ。
λSD Safe Detected，安全已检测失效。失效本身不会导致危险，且可被检测。 使输出进入故障安全模式。 会造成停机或报警，但不是危险未检测失效。
λSU Safe Undetected，安全未检测失效。失效本身不危险，但设备不能检测。 仍在定义误差范围内，测量不确定性可能超出规格。 可能影响可用性或测量质量，但不直接计入危险失效。
λDD Dangerous Detected，危险已检测失效。失效有危险潜力，但可被设备诊断检测。 使输出进入故障安全模式。 计入 PFDavg 公式中的 λDD * MTTR，修复时间很关键。
λDU Dangerous Undetected，危险未检测失效。失效有危险潜力且不能被设备检测。 可能输出错误但看似正常，例如仍在 4-20 mA 范围内或继电器仍闭合。 这是 proof test 和 PFDavg 计算中最关键的失效率。
Dangerous undetected failure 危险未检测失效。 本手册定义为输出偏离真实值超过 2%，但仍在 4-20 mA 范围内或继电器仍闭合。 逻辑单元不会自动发现，所以需要 proof test。
FMEDA Failure Modes, Effects and Diagnostic Analysis，失效模式、影响和诊断分析。 定义设备错误范围和失效分类。 产品 SIL 证书背后的核心分析资料之一。
Diagnostic coverage 诊断覆盖率。 表示诊断能发现多少相关失效。 在线诊断和 proof test 覆盖率共同影响 PFDavg。
MTBF Mean Time Between Failures，平均故障间隔时间。 手册给出 29 年。 不能直接拿 MTBF 证明 SIL，要看危险失效率和 PFDavg。
MTTR Mean Time To Repair，平均修复时间。 出现在 PFDavg 公式中。 维修响应慢会增加不可用性。SRS 或维护计划应设定 MTTR 假设。
Useful lifetime 有效寿命。 失效率只在有效寿命内适用。 超过寿命应替换、评估或由厂家/操作方措施支持延寿。
Systematic failure 系统性失效，来自设计、规格、软件、配置、工况误用、维护错误等非随机原因。 Proof test 不覆盖所有系统性失效。 需要通过流程、审查、验证、培训和变更管理控制。
Random hardware failure 随机硬件失效。 元器件随机失效造成。 FMEDA、λ、PFDavg 主要处理这一类。

6. 参数和计算指标详解

先抓住主线： SIL 计算不是看一个单独参数，而是看一条 SIF 在给定架构、给定 proof test 周期、给定维修时间、给定诊断能力下，平均有多大概率在需要动作时失效。 诊断覆盖率、proof test 覆盖率、失效率、MTTR、HFT、β/βD 都是在描述这件事的不同侧面。

6.1 最容易混淆的三个“覆盖/能力”指标

指标 中文名称 它回答的问题 发生在什么时候 不要和什么混用
DC Diagnostic Coverage，在线诊断覆盖率 设备运行中，内部诊断能自动发现多少危险失效？ 在线运行期间，故障发生后由设备诊断发现。 不要和 PTC 混用。DC 是在线诊断，PTC 是定期人工/程序测试。
PTC Proof Test Coverage，定期验证测试覆盖率 一次 proof test 能发现多少平时没被诊断出来的危险未检测失效？ 按 T1 周期执行 proof test 时。 不要把 PTC 当成设备日常自诊断能力。测试不做，PTC 就不会发挥作用。
SFF Safe Failure Fraction，安全失效分数 所有相关失效中，有多少属于安全失效或危险但可检测失效？ FMEDA 结果中用于硬件架构约束判断。 不要把 SFF 当成 PFDavg。SFF 高不代表整条 SIF 的 PFDavg 一定达标。
SC Systematic Capability，系统能力 厂家流程能控制到什么等级的系统性失效风险？ 产品开发、验证、变更和管理过程。 不要把 SC 3 理解成硬件随机失效自动达到 SIL 3。

6.2 诊断覆盖率 DC 的具体含义

诊断覆盖率通常指设备在线运行时，内部诊断能发现的危险失效比例。对 SIL 计算最有用的是 危险失效诊断覆盖率，也就是危险失效中有多少会变成 λDD，而不是隐藏成 λDU。

危险失效诊断覆盖率 DC ≈ λDD / (λDD + λDU)
如果 DC 较高 如果 DC 较低 项目上的直接影响
更多危险故障会被设备发现，并输出故障安全状态，例如 ≤3.6 mA、≥21.0 mA 或继电器打开。 更多危险故障可能潜伏，输出看起来正常，但真实测量已经错误。 DC 越高，通常 λDU 越少，PFDavg 更容易降低；但诊断触发也可能带来更多报警或停车，需要在可用性上平衡。
在这份 NMS81 安全手册中： 失效分类表把 λDD 解释为设备内部诊断可检测的危险失效；proof test 章节写的“diagnostic coverages”实际是在讲具体 proof test 序列的 PTC。阅读时要把在线 DC 和定期 PTC 分开。

6.3 PTC 的具体含义

PTC 是某个 proof test 序列对危险未检测失效的发现能力。它不是设备日常自动诊断，而是“按规程做了这次测试以后，能把多少潜伏危险故障暴露出来”。

PTC 数值 直观理解 剩余风险
PTC = 0.99 该测试理论上能发现 99% 的相关危险未检测失效。 仍有 1% 的危险未检测失效可能测试也发现不了，需要用 (1 - PTC) 项计入计算。
PTC = 0.90 该测试能发现 90%，覆盖较低。 剩余 10% 会对长期 PFDavg 贡献更大，可能需要更短测试周期或更强测试方法。
PTC 未确认 不能正式用于 SIL 计算。 应向厂家/认证机构确认，或在初步估算中保守取较低值并写明假设。

NMS81 手册中 proof test 覆盖率的读取方式

测试序列 测试对象 手册表格值 小节末尾值 建议处理
A - 真实接近液位 液位测量 99% 0.99 一致，可作为该序列的依据。
B - 模拟液位 液位测量 91% 文字同时出现 91% 和 PTC = 0.88 正式计算前确认。初步保守估算可取 0.88，并标注“待厂家确认”。
C - 模拟液位 + 单点真实验证 液位测量 97% 0.95 正式计算前确认。初步保守估算可取 0.95，并标注“待厂家确认”。
D - 输入真实电流 电流输入测量 99% 0.99 一致，可作为该序列的依据。

6.4 PFDavg 公式每一项是什么意思

NMS81 手册给出单通道架构的关系式：

PFDavg = 1/2 * PTC * λDU * T1 + λDD * MTTR + 1/2 * (1 - PTC) * λDU * LT
公式项 中文解释 怎样降低这一项
1/2 * PTC * λDU * T1 能被 proof test 发现的危险未检测失效，在两次测试之间逐渐累积。平均来看，潜伏时间按半个测试周期估算。 降低 λDU、提高 PTC、缩短 T1、选择更充分的 proof test。
λDD * MTTR 危险已检测失效虽然被发现了，但从发现到修复期间仍有不可用时间。 提高维修响应能力、备件可用性、报警处理速度，降低 MTTR。
1/2 * (1 - PTC) * λDU * LT proof test 也发现不了的危险未检测失效，可能跨过多次测试一直潜伏，按寿命 LT 计入。 选择覆盖率更高的 proof test，补充真实点验证，缩短设备有效寿命假设或增加更强的诊断/测试。
关键直觉： T1 越长，第一项越大；PTC 越低，第三项越大；MTTR 越长，第二项越大。做 SIL 设计时，不只是“设备通过 SIL 2”，还要把测试周期、维修能力和测试覆盖率一起写进 SRS 和运维计划。

6.7 一个简化算例，帮助理解各参数影响

下面是假设数字，只用于理解公式，不代表 NMS81 的实际失效率。

假设：λDU = 1.0E-7 /h，λDD = 2.0E-7 /h，T1 = 8760 h，MTTR = 8 h，LT = 87600 h，PTC = 0.99
第一项 = 1/2 * 0.99 * 1.0E-7 * 8760 = 4.34E-4
第二项 = 2.0E-7 * 8 = 1.60E-6
第三项 = 1/2 * 0.01 * 1.0E-7 * 87600 = 4.38E-5
PFDavg ≈ 4.78E-4
调整项 会发生什么 工程含义
T1 从 1 年改为 2 年 第一项大约翻倍。 延长 proof test 周期会直接增加潜伏危险失效暴露时间。
PTC 从 0.99 降到 0.90 第三项会显著增加。 测试覆盖率低时，即使按期测试，也可能留下更多检测不到的危险故障。
MTTR 从 8 h 变成 72 h 第二项增加 9 倍。 诊断发现了故障但修得慢，安全功能仍然长期不可用。
λDU 降低 第一项和第三项都降低。 选择更可靠、诊断更强或架构更好的传感器子系统会改善 PFDavg。

6.9 常见错误判断

  • 把 DC 当 PTC：在线诊断覆盖率再高，也不能替代定期 proof test；proof test 覆盖率再高，也不能说明设备日常能自动发现故障。
  • 拿 MTBF 直接证明 SIL：MTBF 是总体可靠性指标，SIL 更关心危险失效、诊断、测试周期和平均按需失效概率。
  • 只看传感器证书：一条 SIF 还包括逻辑单元和执行机构，执行机构通常是 PFDavg 的大头。
  • 随意延长 proof test 周期：T1 是计算输入，不是现场习惯值。延长 T1 后必须重算 PFDavg。
  • 忽略 β：冗余不是简单把 PFDavg 除以设备数量，共同原因失效会让多台设备一起失效。
  • 把 SC 3 当 SIL 3：SC 是系统性能力，不是硬件随机失效概率。

7. 从零开始做 SIL，该怎么理解和推进

先区分两种“做 SIL 认证”： 如果我们是项目业主/系统集成方，通常是做某条安全仪表功能的 SIL 目标确认、设计验证和生命周期资料包；如果我们是仪表制造商，才是按 IEC 61508 对自己的产品做第三方产品认证。两条路线工作量差别很大。

6.1 如果我们是在项目里使用 NMS81 做安全回路

  1. 识别危险：组织 HAZOP，找出如罐溢流、泵干运行、误收料、超压等危险场景。
  2. 确定目标 SIL：通过 LOPA 或风险矩阵确定每条 SIF 需要 SIL 1、SIL 2 还是 SIL 3。
  3. 写 SRS：把每条 SIF 写成可测试需求，例如“液位达到 HH 时，X 秒内关闭进料阀并报警”。
  4. 选设备：确认 NMS81 订货码 590=LA SIL、固件、硬件日期、输出类型和证书有效性；同时确认逻辑单元和执行机构的 SIL 资料。
  5. 设计回路：确定 1oo1、1oo2、2oo3 等架构，画回路图、接线图、因果表、旁路逻辑。
  6. 计算 PFDavg：使用传感器、逻辑单元、执行机构的失效率、诊断覆盖、proof test 周期和 MTTR 计算整条 SIF 是否满足目标 SIL。
  7. 配置和锁定：按安全手册配置 NMS81，执行 commissioning check、功能测试、SIL/WHG confirmation、SIL locked。
  8. 验证整条 SIF：做 FAT/SAT 或现场联动测试，确认输入、逻辑、输出、执行机构动作、报警、复位、旁路都符合 SRS。
  9. 建立运维制度：规定 proof test 周期、测试步骤、记录模板、维修后检查、人员授权、变更审批。
  10. 归档证据：把证书、安全手册、SRS、计算、图纸、参数记录、测试记录、培训记录、MOC 放入 SIL 资料包。

6.2 如果我们是要给自己的产品做 IEC 61508 第三方认证

  1. 定义产品和安全功能：明确产品边界、输入输出、安全状态、诊断、需求模式、目标 SIL。
  2. 建立功能安全管理体系：安全计划、角色独立性、配置管理、变更管理、供应商管理、问题闭环。
  3. 编写安全需求：硬件安全需求、软件安全需求、接口需求、环境限制、误用限制。
  4. 硬件分析：做 FMEDA，给出 λSD、λSU、λDD、λDU、SFF、DC、HFT、PFDavg/PFH。
  5. 软件过程证据：需求到设计到代码到测试的追溯，静态分析，单元测试，集成测试，故障注入，版本控制。
  6. 系统性能力证据：证明开发流程可控制系统性失效，例如评审、验证、确认、工具合格性、人员能力。
  7. 安全手册：写清允许型号、环境、参数、安装、调试、诊断、proof test、维修和修改限制。
  8. 独立评估：把资料提交 TÜV、exida、SIRA 等认证机构审查，回答问题并整改。
  9. 证书维护：产品变更、固件升级、元器件替代、现场问题都要按认证机构认可的变更流程处理。

7.3 这两份 E+H 文件对我们的借鉴

  • 证书文字非常短，真正落地要求都在安全手册里。因此项目不能只收集证书，还要把安全手册转成现场可执行规程。
  • 证书把“硬件 SIL”“系统能力 SC”“架构 HFT”分开写，这三个概念不能混用。
  • 安全手册要求配置确认、锁定和 proof test，这说明 SIL 不是买回来就结束，而是生命周期管理。
  • 手册明确限制用户修改 SIL 设备，这意味着现场改硬件、改固件、改安全参数都必须走 MOC 和厂家确认。

9. 深度梳理和落地细节

这一章按现场实施来讲： 前面章节已经解释证书、手册和术语；这一章把它们翻译成项目团队真正要做的判断、表格、记录和审查点。 重点不是背术语，而是知道每个参数要填在哪里、由谁确认、如何影响 SIL 结论。

9.1 把 SIL 项目拆成三层

层级 核心问题 本项目中 NMS81 文件能提供什么 还必须由项目自己完成什么
产品层 这台仪表本身有没有功能安全能力？ TÜV 证书、SIL 2、SC 3、HFT 条件、认证安全功能、安全手册。 确认采购型号和现场设备与证书覆盖范围一致。
回路层 这条 SIF 作为一条完整安全回路能达到目标 SIL 吗？ NMS81 可作为传感器子系统或输入测量环节的一部分。 把传感器、逻辑单元、执行机构、供电、接线、旁路和复位一起设计和计算。
生命周期层 投运后还能持续保持 SIL 能力吗？ 手册规定 SIL 锁定、proof test、维修、修改和人员要求。 建立运维制度、测试计划、人员授权、MOC、记录归档和定期复评。

9.2 一条 SIF 应该怎么写清楚

SIF 不是一句“液位高高联锁”。为了能做 SIL 计算和验收，至少要写清下面这些内容。

SIF字段 要写什么 以 NMS81 高高液位保护为例 为什么重要
SIF 名称 唯一名称和 TAG。 TK-101 HH Level Trip。 后续图纸、参数、测试记录都要对应同一条功能。
危险场景 什么事件会导致什么后果。 进料阀未关闭导致储罐溢流。 SIL 目标来自风险，不来自设备证书。
触发条件 测量值达到什么限值触发。 NMS81 液位达到 HH alarm value。 决定参数、测试点和验收判据。
安全状态 触发后系统必须达到什么状态。 关闭进料阀 XV-101，停止进料泵 P-101，触发声光报警。 “报警”通常不是安全状态本身，必须有降低风险的动作。
响应时间 从危险条件出现到安全动作完成的最大时间。 例如 10 s 内阀门到达关闭位置。 NMS81 手册说系统反应时间在 Expert mode 中用户可配置，但整条回路还要加 PLC 扫描和阀门动作时间。
目标 SIL LOPA 或风险评估得出的 SIL 1/2/3。 例如 SIL 2。 目标 SIL 是计算判据。
传感器子系统 传感器型号、架构和输出。 NMS81，4-20 mA 输出或数字继电器输出，1oo1 或 1oo2。 影响 HFT、PFDavg、β 和 proof test。
逻辑单元 安全 PLC 或限值信号变送器，输入处理规则。 识别 4-20 mA 正常值、≤3.6 mA、≥21.0 mA，或识别继电器开路。 如果 PLC 没按手册识别失败电流，设备诊断输出就不能转化为安全动作。
执行机构 阀门、泵、接触器等最终元件和动作方向。 气关阀、弹簧复位阀、泵停机接触器。 最终元件常是 PFDavg 主要贡献者。
旁路和抑制 谁能旁路、何时旁路、旁路多久、旁路期间替代措施。 proof test 或维护时需要临时旁路，但必须审批和记录。 旁路管理失控会让 SIL 形同虚设。
复位策略 自动复位还是人工复位，复位条件。 高高液位联锁动作后，液位恢复且现场确认后人工复位。 防止危险未消除就恢复运行。
proof test 测试周期、测试方法、测试点、通过判据。 序列 A 或 C；记录液位点、电流、继电器电阻和动作结果。 PTC 和 T1 直接进入 PFDavg 计算。

9.3 NMS81 在安全回路里的角色

角色 NMS81做什么 安全边界 容易出错的地方

报警限值 HH/H/L/LL 是否与 SRS、因果表、PLC 程序一致？ 现场动作点与风险分析不一致。 SRS、因果表、DCS/PLC 变量表、NMS81 参数表。
输出映射 Tank level 或 AIO value mA 是否映射到正确的模拟/数字输出？ PLC 监控了错误信号，安全功能不动作或误动作。 接线图、I/O 清单、参数截图、回路测试记录。
SIL/WHG 启用 安全输出是否设置 Used for SIL/WHG = Enabled？ 输出未纳入 SIL 安全配置。 配置截图和 SIL confirmation 记录。
错误处理 Error on event 是否为 Any error？Output out of range 是否为 Alarm？ 某些故障不进入安全输出。 SIL 自动预设参数记录。
仿真状态 测试后 Simulation distance on 和 Current output simulation 是否关闭？ 设备可能停留在仿真状态，真实过程不再被正确监测。 测试结束检查记录、SIL locked 状态。

9.9 SIL 锁定和解锁的细化流程

动作 什么时候做 风险 控制措施
锁定 SIL 完成配置、commissioning check 和功能测试后。 如果未锁定，安全参数可能被误改。 确认 Locking status = SIL locked，可选启用 WP 硬件写保护。
解锁 SIL 需要修改配置、执行某些 proof test 或维修操作时。 手册说明解锁会停用诊断功能，设备可能不能执行安全功能。 解锁前审批，设置替代监测，记录开始/结束时间和操作人。
使用锁定码 7452 SIL/WHG confirmation 或 Deactivate SIL/WHG。 锁定码泄露会导致未经授权参数修改。 纳入密码/权限管理，不在无控制的操作规程中随意公开。
重新锁定 测试、维护或修改完成后。 忘记重新锁定会留下长期风险。 把“确认 SIL locked”设为工作票关闭条件。

9.10 Proof test 选择建议

目标 优先选择 原因 代价
最高覆盖率验证液位安全功能 序列 A，真实接近液位。 PTC 99%，最接近真实工况，能验证测量链和输出链。 可能需要改变罐内真实液位，受生产条件限制。
无法改变真实液位，但要验证液位输出逻辑 序列 C。 结合单点真实测量和模拟测试，比纯模拟更强。 PTC 文档值不一致，需确认；仍可能不能发现所有校准问题。
只能做模拟验证 序列 B。 实施方便。 覆盖率较低且文档值不一致；对校准错误覆盖有限。
验证电流输入安全功能 序列 D，输入真实电流。 PTC 99%，直接验证电流输入链路。 需要电流源或外部设备仿真能力。

9.11 Proof test 详细记录模板

记录字段 建议填写内容 示例/说明
测试依据 安全手册文件号、版本、章节和测试序列。 FY01100G/00/EN/01.23-00，5.3.1 Test sequence A。
测试对象 TAG、序列号、订单码、固件版本、输出端子。 确保测试记录不会和另一台设备混淆。
测试前状态 SIL locked 状态、WP 开关、当前液位、报警状态、旁路状态。 说明测试前系统是否处于可控状态。
替代保护 人工监护、备用仪表、临时液位巡检、停止进料、工艺隔离等。 手册明确要求 proof test 期间保证过程安全。
测试设备 万用表、电流表、电流源、电阻表、校准证书编号。 模拟量建议优于 ±0.1 mA；电阻测量建议优于 ±0.1 Ω。
测试点 每个液位/电流点的设定值、实际值、期望输出、实际输出。 范围监测通常至少 5 个点。
联锁结果 PLC 输入状态、逻辑动作、阀门/泵动作、报警显示。 只测仪表输出不够，最好验证到逻辑单元和最终元件。
测试后恢复 仿真关闭、SIL 重新锁定、旁路解除、工艺恢复、报警复位。 这是 proof test 最容易遗漏的部分。
结论 通过/失败、偏差、整改、复测结果。 失败时设备不得继续作为 SIS 部件使用，必须处理后复测。

9.12 维修和更换后的重新验证

维修类型 手册倾向要求 项目建议
I/O 模块、主板、电子盒、SD 卡等电子相关部件 目视检查并执行 proof test 序列 A 或 B。 优先做能覆盖实际安全功能的测试；更换 I/O 后必须重新做回路测试。
伺服传感模块、测量鼓、钢丝、displacer 等测量链部件 目视检查、重新校准、重复 commissioning check。 这类维修会影响测量基准，建议重新执行功能测试和参数核对。
盖板、O-ring、窗口盖、外壳过滤器等机械/密封部件 目视检查，必要时任意液位测量检查。 除功能外，还要确认防爆/防护等级/密封状态未受影响。
无法排除设备错误的缺陷件 送回 E+H 故障分析，并注明“Used as SIL device in protective system”。 把返回单、故障分析、整改措施归入 SIL 资料包。

10. 待确认项和风险提示

文档内部 PTC 不一致： proof test 总表写 B=91%、C=97%；B 小节末尾又写 PTC = 0.88，C 小节末尾写 PTC = 0.95。正式 PFDavg 计算前，建议向 E+H 或 TÜV 确认应采用哪个值，并把确认邮件/文件归档。
证书和手册适用范围不同： 证书覆盖 NMS8x [x=0,1,3]，但本安全手册是 NMS81。若项目用 NMS80 或 NMS83，应找对应安全手册。
精度表述需要按功能区分： 证书写液位安全检测精度 ±2%，电流测量精度 ±1%；安全手册中危险未检测失效和 proof test 失败判据多处使用 ±2%。项目应按实际使用的安全功能和信号链确认验收判据。
不要把 HART/Modbus 当安全信号： 手册把安全相关信号限定为模拟 4-20 mA 或数字继电器。通信可用于信息和配置，但不应作为本证书/手册下的安全输出依据。
不要忽略生命周期： SIL 的核心不是一次性认证文件，而是从需求、设计、调试、验证、运维、proof test、维修、变更到退役的全过程控制。

  3. proof test B/C 的 PTC 到底采用表格值还是小节末尾值？

  5. 是否能提供 FMEDA 摘要、SIL declaration、Safety Manual 最新版、证书官网记录链接？
