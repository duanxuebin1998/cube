## 对 SIL 认证的帮助

### 1. 明确证书不能直接套用到整机

NMS81 资料最重要的提醒是：产品证书只说明某个设备在规定型号、版本、配置、输出和生命周期条件下可用于安全仪表功能。整条 SIF 是否达到目标 SIL，还要由项目自己的 HAZOP/LOPA、SRS、回路架构、PFDavg 计算、调试验证和运维制度共同证明。

对 CUBE 来说，后续资料包必须区分：

- 产品或模块的能力证明：例如 MCU、诊断库、继电器、电流输出、传感器、执行机构的安全资料。
- 项目安全功能证明：例如某条液位/罐底/电机保护 SIF 的触发条件、动作、响应时间、失效率计算、测试和维护记录。
- 软件系统能力证明：编码规范、需求追踪、评审、静态分析、单元测试、集成测试、变更控制和偏离记录。

### 2. 给出了可借鉴的安全手册结构

NMS81 安全手册的结构可以作为 CUBE 后续 `软件架构设计.md` 和安全手册草稿的模板：

| 安全手册要素 | NMS81 做法 | CUBE 应补齐的对应内容 |
| --- | --- | --- |
| 适用范围 | 规定订货选项、固件版本、硬件生产日期和 SIL 铭牌标识 | 规定 CPU2/CPU3 版本、硬件版本、编译配置、禁用调试模块、可发布构建条件 |
| 安全功能 | 分为液位安全检测和电流输入安全测量 | 明确 CUBE 实际申请的安全功能，不能把普通测量、显示、通信全部默认列入安全功能 |
| 安全相关信号 | 只承认 4-20 mA 或数字继电器输出，HART/Modbus 仅作信息用途 | 明确安全相关输出优先落在继电器、故障电流或专用停机输出；Modbus/CPU3 显示默认只作诊断和维护信息 |
| 使用限制 | 规定工况、EMC、输出误差、下游逻辑单元处理要求 | 规定传感器工况、通信中断、参数损坏、电机异常、继电器开路/短路、供电异常时的处理 |
| 配置锁定 | SIL 确认后写保护，解锁会降低安全能力 | 安全参数应有确认、校验、锁定、变更审批和解锁期间替代监测要求 |
| proof test | 不同测试序列给出 PTC，按周期验证安全功能 | 建立 CUBE 安全功能 proof test 计划、步骤、记录模板和 PFDavg 输入参数 |
| 生命周期 | 规定人员资质、安装、调试、维护、维修、修改 | 建立 CUBE 安全发布、维修后复测、现场变更和版本影响评估流程 |

## 对 CUBE 程序架构设计的启发

### 1. 先写 SRS，再写代码和接口

NMS81 把安全功能写成明确的检测对象、输出信号和下游逻辑单元责任。CUBE 后续也应先把每条安全功能写成 SRS 条目，再决定软件模块怎么实现。

每条 SIF 至少应包含：

| 字段 | 说明 |
| --- | --- |
| 安全功能名称 | 例如高高液位保护、低低液位保护、电机异常停机、罐底下行保护 |
| 输入来源 | 传感器、编码器、电机驱动状态、参数、继电器反馈、外部命令 |
| 触发条件 | 阈值、持续时间、滤波、边界、无效值判定 |
| 安全动作 | 停机、断开继电器、输出故障电流、禁止继续测量、报警 |
| 安全状态 | 电机无运动、继电器故障态、输出失败电流、参数写入禁止等 |
| 响应时间 | 传感器采样、CPU2 判断、输出动作、下游执行机构动作的总时间 |
| 允许旁路 | 是否允许、谁授权、多久、如何记录、旁路期间替代措施 |
| proof test | 测试周期、步骤、合格判据、失败处理 |

### 2. 安全相关输出要和信息通道隔离

NMS81 明确 HART、Modbus 等通信只用于信息目的，安全相关措施只围绕 4-20 mA 或继电器输出。CUBE 架构也应避免把普通通信、屏幕显示或调试命令作为安全功能的唯一依据。

建议的 CUBE 边界：

| 层级 | 建议定位 | 设计要求 |
| --- | --- | --- |
| CPU2 安全监督层 | 安全核心 | 统一判断安全状态、停机、故障输出、看门狗健康、参数有效性 |
| 电机和测量执行层 | 安全相关 | 所有运动入口先经过安全前置检查，停止失败必须升级为安全故障 |
| 参数存储层 | 安全相关 | 安全参数必须范围检查、CRC、默认值策略、版本化和写保护 |
| 继电器/电流输出层 | 安全相关输出候选 | 输出故障态必须有明确定义，最好支持启动自检和定期 proof test |
| CPU3 显示和外部 Modbus | 支撑/诊断 | 可展示安全状态和记录，不应直接绕过 CPU2 安全监督层 |
| 调试命令和测试模块 | 非安全 | 安全发布版隔离或禁用，不能进入正式安全路径 |

### 3. 启动阶段先进入安全态

NMS81 上电后先进入诊断阶段，数字继电器打开，模拟输出进入失败电流，通信暂不可用。CUBE 也应把启动阶段设计成“先安全、再使能”：

- 上电初始化期间继电器和电机输出保持安全态。
- 参数、传感器、编码器、电机驱动和通信状态检查完成前，不允许执行运动命令。
- 看门狗喂狗不应掩盖主循环卡死或安全监督失效。
- 启动自检失败要进入可追踪的故障状态，而不是继续运行默认测量流程。

### 4. 参数配置需要确认、锁定和变更控制

NMS81 的 SIL 模式通过确认序列和写保护锁定安全相关参数。CUBE 后续应把安全相关参数从普通配置中分离出来：

- 建立 `安全相关参数清单.md`，标明参数来源、单位、范围、默认值、是否允许现场修改。
- CPU2 对 Modbus/CPU3 写入安全参数执行白名单、范围检查、互斥条件检查和 CRC 持久化。
- 参数变更后要求重新确认相关安全功能，必要时重新 proof test。
- 安全发布版记录参数快照、软件版本和协议版本，作为现场追溯证据。

### 5. 在线诊断和 proof test 是两件事

NMS81 资料把在线诊断、proof test 覆盖率和 PFDavg 计算分开。CUBE 架构也应分清：

- 在线诊断：运行时发现传感器异常、编码器跳变、参数 CRC 失败、电机驱动异常、通信超时、继电器异常等。
- proof test：按周期主动验证安全功能能否按 SRS 动作，尤其是平时诊断发现不了的潜伏危险失效。

建议新增或补齐：

- 安全功能 proof test 规程和记录模板。
- 继电器输出测试、故障电流测试、停机确认测试、参数损坏注入测试。
- 故障注入测试：传感器无响应、编码器异常、FRAM CRC 错、Modbus 非法写入、电机停止失败。

### 6. 当前 CUBE 目标改为参考 NMS81 的 SIL 2 路线

NMS81 证书和安全手册的关键参考点是：单通道 HFT=0 时可用于最高 SIL 2 应用；HFT=1 冗余架构才讨论 SIL 3。CUBE 当前需求调整为不做 SIL 3，按 NMS81 单通道思路做 SIL 2 能力准备。

CUBE 当前架构重点应放在：

- 明确单通道安全功能边界、输入、输出、安全状态和响应时间。
- 建立 4-20 mA 故障电流、继电器报警、参数锁定、proof test 和维修后复测规则。
- 通过 PFDavg/PFH 计算、FMEDA/FMEA、诊断覆盖和测试证据证明目标 SIL 2。
- 将 SIL 3 冗余架构、HFT 和共因失效专项作为未来扩展，不作为当前需求。

## 关键注意事项

- NMS81 的 PDF 是主来源，HTML 是中文整理和学习导读；正式引用应优先引用安全手册、证书和厂家/认证机构最新确认。
- NMS81 手册中的 proof test 覆盖率在总表和部分分节说明中存在不一致风险，正式 PFDavg 计算前应向 E+H 或认证机构确认采用哪个 PTC。
- CUBE 如果是“作为项目系统的一部分使用”，重点是 SIF 级别的设计验证和运维证据；如果是“给自己的产品做 IEC 61508 产品认证”，则需要完整的软件安全生命周期、工具确认、第三方评估和产品安全手册。
- 本次整理只新增文档和归档外部资料，不改变固件行为，因此不触发 CPU2/CPU3 固件版本升级。
