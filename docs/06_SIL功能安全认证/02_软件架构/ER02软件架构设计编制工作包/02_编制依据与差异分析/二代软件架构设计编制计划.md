## 2. 编制目标

1. 形成覆盖 CPU1/DM4、CPU2、CPU3 和 CPU4 的二代软件整体架构。
2. 明确每颗处理器的职责、分层结构、模块关系、外部接口、功能分类、调度负载和状态转移。
3. 明确 CPU2 的业务数据与动作权威端地位，以及 CPU3 快照、普通写 ACK、长事务完成确认和外部协议网关边界。
4. 把 CPU1 无源码、CPU4 证据不完整、真实硬件和 SIL 证据未闭环等限制写入正式文档。
5. 为后续 CPU2 软件详细设计提供稳定的模块、接口和状态上位基线。

## 6. 证据与声明规则

- `源码已核对`：当前 CPU2、CPU3 或 CPU4 工作树存在直接代码证据。
- `协议/资料已核对`：正式协议、CG01、硬件分析或批准资料提供合同或边界。
- `目标设计`：为二代架构规定的职责或状态，仍需对应端实现和验证。
- `待确认`：源代码、接线、版本、SRS、FTTI 或批准资料不足。
- `未验证`：没有目标板、台架、长线、故障注入、现场或认证证据。

文档完成不等于通过 SIL；Word/Visio 结构检查、静态源代码核对和主机构建不能替代整机验证。

1. ER02 的处理器边界、模块分层、接口方向和数据权威端完成评审。
