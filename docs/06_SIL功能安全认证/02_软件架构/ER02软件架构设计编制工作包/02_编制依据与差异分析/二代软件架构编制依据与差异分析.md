## 4. 二代关键架构关系

| 链路 | 当前二代口径 | 证据状态 |
| --- | --- | --- |
| CPU1 ↔ 蓝牙透传 ↔ CPU2 | CPU1 在 DSM、LTD、DM4 中三选一，均向 CPU2 传输原始数据和计算结果；DSM、LTD 和 DM4 非安全协议均为非安全通信。DM4 安全协议用于 SIL 配置时，仅逻辑端点 `CPU1（DM4）↔ CPU2` 构成安全通信链路；蓝牙两端只承担透明传输，不设置 CPU 节点或安全处理端点 | DSM/LTD 的 CPU2 源码已核对；DM4 安全和非安全协议正在添加，最终字段、映射和联调证据待冻结；真实蓝牙链路待验证 |
| CPUW → CPU2 | 非安全链路。CPUW UCA1 与 CPU2 UART4 名义配置为 19200 8N1；CPUW 每轮扭力采样后主动发送包含末尾 BCC 在内共 22 字节的 `CC 03 83` 全量帧，前 21 字节异或得到第 22 字节 BCC。CPU2 被动接收并校验长度、帧头和 BCC，消费 0 基索引 15～18（帧内第 16～19 字节）的温度原始位及 19～20（第 20～21 字节）的原始扭力，计算 `current_weight = empty_weight - raw_weight` 后再调用 `Weight_Update`。1000 ms 无合法帧时置 `WEIGHT_COMM_TIMEOUT` 并进入统一错误处理；电机驱动有效时调用慢停流程，错误进入 CPU2 共享状态并由 CPU3 轮询同步 | CPUW 与 CPU2 双端源码已核对；CPUW 侧 8N1 依赖外设复位默认位，CPU2 侧为显式配置；当前 CPU2 未发现 UART4 查询发送路径；`0x83` 无独立诊断码，CPUW 诊断状态上报闭环和硬件联调未在本文证明 |
| CPU2 ↔ CPU3 | 非安全链路。本 V0.2 冻结基线为 UART5/RS485、115200 8N1、共享 Modbus 协议 31；CPU2 为业务数据和动作权威端，CPU3 读取已确认快照；普通参数写以 CPU2 合法 ACK 作为该次写成功门禁并使相关快照失效，恢复出厂等长事务的 ACK 仅表示受理，最终完成必须依据 CPU2 后续状态/结果及重新同步 | 双端源码已核对；最终工作树已进入协议 32，后续版本吸收前需单独复核差异 |
| CPU3 ↔ 工程师站/外部系统 | 非安全链路。所有外部数字协议均归 CPU3；当前 COM1/COM2/COM3 可配置 DSM、Wartsila、LTD、LH、SI，CPU3 负责协议转换、DMA 收发、异常响应和端口恢复 | CPU3 源码已核对；真实设备联调未在本文证明 |
| CPU2 ↔ AO/HART/继电器/电机/编码器/FRAM | CPU2 直接控制或采集，故障由统一故障出口和安全动作处理 | CPU2 源码已核对；目标板和故障注入待验证 |
| 外部实时温度计 → CPU4 → CPU3 → 上位机 | 未来非安全扩展路径，不经过 CPU2；CPU3 负责向上位机转发 | 产品用途、方向和非安全属性已确认；处理器、接线、供电、接口协议和字段映射待设计 |

## 5. 一代与二代主要差异

| 主题 | 一代 ER02 | 二代设计 |
| --- | --- | --- |
| 处理器组织 | 一代编号和职责仅作为旧文档参考 | 当前不存在 CPU0；CPU1、CPU2、CPU3 和 CPUW 为需描述的处理器关系，CPU4 仅保留 `外部实时温度计→CPU4→CPU3→上位机` 的未来非安全扩展位置 |
| 传感器 | CPU1 采集/冗余计算的旧实现描述 | CPU1 在 DSM、LTD、DM4 中三选一；三种配置均传输原始数据和计算结果；DM4 安全和非安全协议正在添加 |
| 安全通信 | 旧稿安全/非安全对象和处理器边界与当前产品不一致 | DSM、LTD 和 DM4 非安全协议均为非安全通信；SIL 配置使用 DM4 安全协议时，仅 `CPU1（DM4）↔ CPU2` 为安全通信链路 |
| 扭力处理 | 未形成当前 CPUW 双端调用链说明 | 新增每台必装的 CPUW（扭力）；以 `D:\CSS_workspace\newhall` 和 CPU2 UART4/Weight 源码描述主动推送、校验、消费、超时及非安全自诊断责任，同时标明独立诊断状态上报闭环缺口 |
| CPU2 调度 | 旧状态模式和功能表 | 当前 50 ms 协作式主循环、命令邮箱、同步测量、后台服务、故障恢复和中断/PendSV 边界 |
| CPU2/CPU3 通信 | 旧文档按安全/非安全模式描述单向或双向 | 协议 31 双端实现；读取使用一致快照；普通参数写等待 CPU2 合法 ACK，失败后不得伪成功；恢复出厂等长事务不能仅凭 ACK 对外宣布完成 |
| CPU3 对外通信 | 数字信号、密度温度模块的简单串口描述 | 三路可配置多协议网关、协议切换、DMA 队列、UART 恢复、SI 周期调度 |
| 数据一致性 | 未明确快照代际和写后失效 | CPU2 权威端；CPU3 状态/参数/固定点快照、协议匹配、失效和重同步分离 |
| 无线链路 | 旧文档可能把无线端作为处理器描述 | 无线主机/无线从机不再设置 CPU，只保留蓝牙透明传输及必要链路管理 |
| CPU4 | 旧编号或旧无线工程映射 | 当前未实现，但目标路径已固定为 `外部实时温度计 → CPU4 → CPU3 → 上位机`；CPU3、CPU4 均非安全相关，具体接口仍待设计 |
| SIL 声明 | 安全/非安全功能分类较直接 | 只把 DM4 安全协议配置下的 CPU1↔CPU2 端到端通信标为安全链路；不把文档、在编协议、静态检查或单端代码写成 SIL 通过 |

## 6. 待确认与不得越界事项

1. DM4 安全协议和非安全协议的物理参数、帧格式、命令、数据项、错误处理、安全机制、协议版本和兼容矩阵仍需随在编协议冻结；DM4 两种协议及 SIL 选型不再作为待确认项。
2. CPU2 现有 `SAFE_SENSOR` 候选代码与 DM4 最终安全协议的源码映射、版本和完整调用链仍需核对；这属于实现映射，不是产品安全边界待决策。
3. CPU4 的具体处理器、接线、供电、实时温度计输入接口、CPU4→CPU3 协议和上位机字段映射尚未设计；既定数据方向和非安全分类不再作为待确认项。
4. CPUW 的独立诊断状态码、有效帧承载、CPU2 消费和故障映射、向 CPU3 发布方式尚未闭环；CPUW 当前主动推送方向已由双端源码确定。
5. CPUW 的正式版本号、发布方式及其与 CPU2 固件的兼容矩阵仍待建立。
6. 蓝牙透明链路的硬件型号、配对策略、断链恢复和真实设备证据仍需在正式架构中分层记录，但无线两端不再作为 CPU。
7. `CG01 V1.3` 和 ER02 V0.1 中把 DM4 与 CPU1 并列、把无线工程映射为 CPU4 或把无线两端设置为处理器的描述不能直接作为实现事实；本轮状态模型以已同步的 CG01 V1.2、ER02 V0.2 和确认基线为准。
8. 整机 1 s 响应目标、FTTI、安全输出值和锁存/恢复策略仍以批准 SRS 为准；本文不凭旧文档或静态源码重新批准这些数值。
9. CPU2/CPU3 构建、主机测试、Word 渲染和 Visio 检查不等于蓝牙、CPUW、RS485 长线、FRAM 掉电、AO/HART、继电器、电机、目标板、现场、故障注入或 SIL 验证通过。
