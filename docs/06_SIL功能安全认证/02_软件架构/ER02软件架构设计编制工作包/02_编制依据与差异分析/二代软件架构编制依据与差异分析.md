## 4. 二代关键架构关系

| 链路 | 当前二代口径 | 证据状态 |
| --- | --- | --- |
| CPU1/DM4 ↔ CPU2 | CPU2 UART6/RS485，9600 bps；安全协议 V1 规定身份、会话、序号、CRC32C、采样计数、数据年龄、状态、诊断和配置摘要；保留旧协议探测/回退边界 | CPU2 设备侧源码已核对；DM4 端待实现/验证 |
| CPU2 ↔ CPU3 | UART5/RS485，115200 8N1，共享 Modbus 协议 31；CPU2 为业务数据和动作权威端，CPU3 读取已确认快照；普通参数写以 CPU2 合法 ACK 作为该次写成功门禁并使相关快照失效，恢复出厂等长事务的 ACK 仅表示受理，最终完成必须依据 CPU2 后续状态/结果及重新同步 | 双端源码已核对 |
| CPU3 ↔ 工程师站/外部系统 | COM1/COM2/COM3 可配置 DSM、Wartsila、LTD、LH、SI；CPU3 负责协议转换、DMA 收发、异常响应和端口恢复 | CPU3 源码已核对；真实设备联调未在本文证明 |
| CPU2 ↔ AO/HART/继电器/电机/编码器/FRAM | CPU2 直接控制或采集，故障由统一故障出口和安全动作处理 | CPU2 源码已核对；目标板和故障注入待验证 |
| CPU4 无线桥接 | 当前源码把 USART2 接收数据转发到 USART3，并对部分 8 字节管理命令向 USART2 返回本机响应；实际产品链路位置待硬件/接线确认 | 局部源码已核对，产品归属待确认 |

## 5. 一代与二代主要差异

| 主题 | 一代 ER02 | 二代设计 |
| --- | --- | --- |
| 处理器组织 | CPU0、CPU1、CPU2、CPU3，正文重点为 CPU1/CPU2/CPU3 | CPU1/DM4、CPU2、CPU3、CPU4；不沿用 CPU0 事实 |
| 传感器 | CPU1 采集/冗余计算的旧实现描述 | DM4 四板多参数硬件 + 安全协议合同；传感器端代码缺失须显式隔离 |
| CPU2 调度 | 旧状态模式和功能表 | 当前 50 ms 协作式主循环、命令邮箱、同步测量、后台服务、故障恢复和中断/PendSV 边界 |
| CPU2/CPU3 通信 | 旧文档按安全/非安全模式描述单向或双向 | 协议 31 双端实现；读取使用一致快照；普通参数写等待 CPU2 合法 ACK，失败后不得伪成功；恢复出厂等长事务不能仅凭 ACK 对外宣布完成 |
| CPU3 对外通信 | 数字信号、密度温度模块的简单串口描述 | 三路可配置多协议网关、协议切换、DMA 队列、UART 恢复、SI 周期调度 |
| 数据一致性 | 未明确快照代际和写后失效 | CPU2 权威端；CPU3 状态/参数/固定点快照、协议匹配、失效和重同步分离 |
| 无线处理器 | 未单列当前无线主机代码 | 新增 CPU4 章节，同时保留其证据不足和架构缺口 |
| SIL 声明 | 安全/非安全功能分类较直接 | 只说明安全相关设计边界；不把文档、静态检查或单端代码写成 SIL 通过 |

## 6. 待确认与不得越界事项

1. DM4 传感器端固件版本、代码、任务调度、诊断位产生逻辑和安全状态尚未提供。
2. CPU4 的实际板卡名称、在整机中的物理位置、CPU2/CPU3/无线模块对端接线及发布版本尚未冻结。
3. `CG01 V1.3` 中“CPU3 与 CPU4 通信串口”的接口正文仍复用了 CPU2/CPU3 描述，不能直接作为 CPU4 实现事实。
4. 整机 1 s 响应目标、FTTI、安全输出值和锁存/恢复策略仍以批准 SRS 为准；本文不凭旧文档或静态源码重新批准这些数值。
5. CPU2/CPU3 构建、主机测试、Word 渲染和 Visio 检查不等于 RS485 长线、FRAM 掉电、AO/HART、继电器、电机、目标板、现场、故障注入或 SIL 验证通过。
