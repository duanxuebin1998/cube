# ER02 软件架构设计编制工作包

更新日期：2026-08-08

## 用途

本工作包用于参考一代《ER02.软件架构设计V1.1》，编制当前二代计量仪软件架构设计。参考文档只作为章节、表格、页眉页脚、目录和 Visio 风格基线；二代处理器职责、接口、状态和调度关系以当前源码、现行协议、系统架构资料及批准材料为准。

## 当前状态

- `V0.2` Word 和九张 Visio 已按确认基线完成重编，形成 23 页中期评审稿；3 个分节、32 张表、1 个目录和 9 个可编辑 `Visio.Drawing.15` 的结构门禁通过，物理第 1 页至第 23 页视觉检查通过，当前等待用户内容验收，尚不是批准架构基线。
- `V0.1` Word 保留为内容评审未通过的历史草稿，固定 SHA-256 未改变，不得作为软件详细设计输入。
- 已建立[处理器与传感器架构确认基线](./02_编制依据与差异分析/处理器与传感器架构确认基线.md)：当前不存在 CPU0；CPU1 在 DSM、LTD、DM4 中三选一，三种传感器均向 CPU2 传输原始数据和计算结果；DM4 安全和非安全协议组织类似 LTD，当前正在添加。
- DSM、LTD 和 DM4 非安全协议均为非安全通信；SIL 配置使用 DM4 安全协议，此时仅 `CPU1（DM4）↔ CPU2` 构成安全通信链路，蓝牙只作为透明传输载体。
- CPUW（扭力）每台必装，是 CPU2 获取扭力数据的非安全串口对端，源码位于 `D:\CSS_workspace\newhall`；当前有效调用链为 CPUW 主动发送包含末尾 BCC 在内共 22 字节的 `CC 03 83` 全量帧，前 21 字节异或得到第 22 字节 BCC。CPU2 UART4 被动接收、校验并解析原始扭力，先计算 `current_weight = empty_weight - raw_weight`，再调用 `Weight_Update` 形成稳定业务扭力。CPUW 产品责任包括非安全自诊断，但当前独立诊断状态码上报闭环尚未实现。
- CPU4 当前尚未实现，已确认目标路径为 `外部实时温度计（如铂电阻温度计）→ CPU4 → CPU3 → 上位机`；CPU3、CPU4 均非安全相关，不经过 CPU2，也不得把旧 `WirelessHost_V4.1_init` 映射为 CPU4。
- 无线主机和无线从机不再作为独立 CPU，ER02 只描述蓝牙透明传输链路及必要链路管理。
- AO/HART、继电器和电机归 CPU2，所有外部数字协议归 CPU3；该责任分配不设置例外。
- V0.2 已形成 23 个物理页、32 张表和 9 个 `Visio.Drawing.15` OLE；每个 OLE Package 内 VSDX 与独立源图一致，正式目录含且仅含 F01～F09 九张 VSDX，过期 F03 未进入正式 V0.2 Visio 目录。
- V0.1 的 23 页、34 张表、9 个 `Visio.Drawing.15` OLE 和 23/23 页视觉检查结果只作为排版历史证据保留；其处理器、传感器和通信内容已由 V0.2 取代。
- CPU2/CPU3 事务语义继续保持：普通参数写以合法 ACK 作为该次写成功门禁；恢复出厂等长事务的 ACK 仅表示受理，最终完成还需依据 CPU2 后续状态/结果及重新同步。
- CPU2 软件详细设计继续冻结，等待 V0.2 通过用户复审并关闭适用评审意见后再恢复。
- 本轮未修改固件、协议或版本，未生成 PDF 交付物，未暂存、提交或推送；PDF/PNG 仅存在于 `tmp/` 作为内部逐页检查中间件。

6. 本工作包中的差异分析、编制计划和历史验证记录。

## Word 与 Visio 门禁

- 每次实质修改后更新目录、整本重排，并从物理第 1 页检查到末页。
- 流程图以一代 ER02 的白底细黑线为主；安全红色只允许用于 SIL 配置下 DM4 安全协议的 `CPU1（DM4）↔ CPU2` 端到端边界，目标合同边界使用克制语义色。节点不重叠，连线不穿框，文字不压线，箭头转折和箭头端保留明显净空。
- Word 中的正式图为 `Visio.Drawing.15` 可编辑 OLE；每个对象保留独立 VSDX。
- 不生成正式 PDF；PDF 和 PNG 只作为 `tmp/` 下的临时渲染检查产物。
- 文档结论区分源码已核对、文档合同、目标设计、待确认和未验证，不把静态或渲染检查表述为目标板、台架、现场、故障注入或 SIL 认证证据。
