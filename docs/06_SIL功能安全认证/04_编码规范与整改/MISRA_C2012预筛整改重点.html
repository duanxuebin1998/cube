最需要优先整改的几项

P0 中断中自动喂狗、打印和较长接收处理

风险：中断路径直接刷新看门狗会掩盖主循环、运动控制、传感读取或故障管理卡死；ISR 中打印和循环处理 DMA 缓冲会引入不可预测执行时间，也不符合安全路径可分析性要求。

  • LTD_MAIN_CPU2/Core/Src/stm32f4xx_it.c:323：TIM4_IRQHandler 中直接调用 HAL_IWDG_Refresh(&hiwdg)。
  • LTD_MAIN_CPU2/Core/Src/stm32f4xx_it.c:351-370：USART1_IRQHandler 中打印接收内容、遍历缓冲并修改命令状态。
  • LTD_MAIN_CPU2/Core/Src/stm32f4xx_it.c:346、:371：ISR 中调用 HAL_UART_DMAStop、HAL_UART_Receive_DMA，返回值未作为错误路径处理。

建议动作：把喂狗迁移到健康监督模型；ISR 只置位、取长度、清标志和投递事件；打印改为固定长度事件缓存或延迟日志；DMA 重新启动失败要进入通信诊断或错误记录。

P0 安全相关路径大量直接打印和阻塞等待

风险：安全动作、运动控制、测量流程和参数恢复中大量 printf 与 HAL_Delay 会降低实时性和可验证性。MISRA 审查时这类问题通常会和可预测时序、未受控副作用、不可重入调用一起被提出。

  • printf 活动命中：CPU2 1159 处，影响 54 个项目文件。
  • HAL_Delay 活动命中：CPU2 108 处，影响测量、电机、传感、参数存储和外设适配层。
  • LTD_MAIN_CPU2/Application/Src/measure.c:620、:645、:667：命令处理流程中存在 1000 ms 级阻塞。
  • LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_motion_api.c:777：运动控制路径存在 4000 ms 阻塞。
  • LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.c:465：参数恢复流程存在 100 ms 阻塞。

建议动作：安全相关路径先区分“诊断打印”和“安全决策”；安全路径移除直接打印；长延时改为状态机、超时轮询或 abortable_delay 类可中止等待，并记录最大执行时间。

P0 停机、运动和传感返回值被丢弃

风险：安全相关函数返回值被 (void) 丢弃时，停机失败、DMA 停止失败、驱动读写失败可能不会升级为错误状态。此类问题和项目规则 CUBE-C-007、MISRA 返回值处理要求直接相关。

  • LTD_MAIN_CPU2/Core/Src/main.c:118：启动安全停机 MotorCtrl_BootSafeStop() 的返回值被丢弃。
  • LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_internal.h:121：宏内调用 MotorDriver_StopAndMarkStopped() 后丢弃返回值。
  • LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_motion_api.c:130-134：多个 TMC5130 关键寄存器读取返回值被丢弃。
  • LTD_MAIN_CPU2/Services/Sensor/ch9141_at.c:406-407、ltd_sensor_communication.c:75、dsm_sensor_communication.c:88：UART DMA 停止/中止返回值被丢弃。

建议动作：安全相关返回值改为统一错误处理；若确实为尽力清理，必须加局部说明并登记 deviation record；启动安全停机失败应进入安全错误或至少记录可追溯事件。

P1 浮点和强制类型转换集中在运动、测量、扭力路径

风险：当前 CPU2 显式强制类型转换 959 处，float/double 641 处。运动边界、测量阈值和扭力碰撞判断如果依赖浮点比较或无范围证明的转换，会影响可分析性和复现性。

  • LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_position_model.c：显式转换 100 处，float/double 123 处。
  • LTD_MAIN_CPU2/Services/Weight/weight.c：显式转换 95 处，包含扭力阈值、位置和打印转换。
  • LTD_MAIN_CPU2/Application/Src/measure_density.c：显式转换 87 处，密度测量算法涉及浮点。
  • LTD_MAIN_CPU2/Application/Src/measure_tank_height.c：显式转换 69 处，罐高/罐底测量路径涉及运动边界。

建议动作：安全阈值优先改为定点单位，例如 0.1 mm、0.01 mm、0.1 g；所有宽窄转换、有无符号转换和浮点到整数转换必须通过命名 helper，helper 内完成范围检查、饱和或拒绝策略。

P1 全局/extern/volatile 状态缺少访问边界

风险：CPU2 发现 extern 全局状态 72 处、volatile 共享状态 45 处。volatile 不能保证多字节变量一致性，也不能保证状态机更新的原子性。

  • LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.h:633-635：g_measurement、g_deviceParams、new_command_ready 对外暴露。
  • LTD_MAIN_CPU2/Core/Inc/usart.h:51-66：多个 UART RX 长度和缓冲区外部可见。
  • LTD_MAIN_CPU2/Services/Encoder/encoder.h:14：编码器计数以 extern volatile 暴露。
  • LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl.h:40：运动速度全局变量暴露。

建议动作：安全相关全局变量改为模块内 static，通过 getter/setter 或快照函数访问；ISR 与主循环共享数据要定义临界区、双缓冲或一致性读取策略；对仍需全局暴露的状态建立访问矩阵和偏离记录。

P1 固定下标数组访问和通信帧边界证明不足

风险：固定下标数组访问在 CPU2 命中 451 处。并不是所有固定下标都违规，但通信帧、DMA 缓冲、Modbus 寄存器、HART 帧和测点数组必须有长度证明。

  • LTD_MAIN_CPU2/Application/Src/measure_density.c：固定下标 85 处，涉及密度测点和数组计算。
  • LTD_MAIN_CPU2/Services/Sensor/wireless_communication.c:62-69：8 字节帧按固定下标填充。
  • LTD_MAIN_CPU2/Services/Hart/hart.c:163-188：直接访问 RcvPackage->data[n] 判断帧内容。
  • LTD_MAIN_CPU2/Application/Src/measure.c:674、:738：直接访问 command[1] 解析二级命令。

建议动作：所有外部输入帧进入解析前先验证最小长度和最大长度；把固定帧解析封装为带长度参数的 helper；Modbus/HART/无线协议增加边界单元测试。

P1 函数式宏存在副作用和流程控制

风险：CPU2 发现真正函数式宏 28 处。寄存器地址宏和换算宏需要检查重复求值；含 return、函数调用和打印的宏会影响可读性、控制流分析和副作用证明。

  • LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_internal.h:103-114：CHECK_COMMAND_SWITCH_AND_STOP(retcode) 宏内调用函数、打印并返回。
  • LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_internal.h:117-124：CHECK_COMMAND_SWITCH_AND_STOP_NO_RETURN() 宏内丢弃停机返回值并返回。
  • LTD_MAIN_CPU2/Services/ParamStorage/system_parameter.h:37-40：温度/密度转换宏使用参数表达式，需要防止重复求值和范围不明。
  • LTD_MAIN_CPU2/Services/Modbus/stateformodbus.h:302-304：寄存器地址宏使用参数 i，应限定参数范围和类型。

建议动作：含流程控制的宏改为 static inline 或普通函数；数值换算宏改为命名 helper；保留的寄存器地址宏要限制只传无副作用表达式，并登记偏离理由。

P1 Modbus 功能码 switch 缺少默认兜底

风险：功能码解析虽然前置有合法性判断，但 switch 本身缺少默认分支，静态分析和代码评审仍会要求说明不可达或补兜底错误处理。

  • LTD_MAIN_CPU2/Services/Modbus/hostcommu_modbus.c:76：switch (RCV_functioncode) 未检测到 default。
  • LTD_MAIN_CPU2/Services/Modbus/hostcommu.c:293：switch (functioncode) 未检测到 default。
  • CPU3 同类问题：device_param_sync.c:18、cpu2_communicate.c:65。

建议动作：补 default，记录非法功能码并返回异常响应或不发送响应；如果由前置检查保证不可达，也要用注释和静态分析偏离记录说明。

P2 调试/测试代码进入扫描范围，需要发布隔离

风险：test.c 中存在大量 printf、HAL_Delay 和返回值丢弃。它不一定要求立即重构，但不能进入安全发布基线或作为安全功能依据。

  • LTD_MAIN_CPU2/Application/Src/test.c：打印/阻塞命中较多，(void) 丢弃返回值 16 处。
  • 现有安全相关模块清单已把 test.c 标为 S3 非安全/调试模块。

建议动作：安全发布构建显式排除 test.c；保留调试构建配置；如果调试代码必须保留在工程中，需要用编译开关隔离。
