# 测试记录文档索引

更新日期：2026-07-18

本目录用于保存现场验证记录、串口日志、联调记录、测试现象分析和版本整改后的实测资料。这里的资料强调“实际测了什么、结果是什么、还有哪些未验证风险”。

## 子目录

| 目录 | 内容 | 维护口径 |
| --- | --- | --- |
| `问题复测/` | 现场问题检查、复测输入和整改前后判断 | 可包含问题分析和修改计划，但必须回链正式问题分析或版本资料 |
| `版本验证/` | CPU2/CPU3 版本整改记录、本地验证记录和现场复测建议 | 版本发布口径仍以 `../00_构建与版本/版本改动与测试/` 为准 |
| `现场记录/` | DOCX 测试记录、DAT 串口日志等原始现场证据 | 原始附件保留扩展名，不作为唯一维护正文 |
| `协议台架验收/` | 固件 facts、工具 catalog、受控 policy、比较报告和命令闭环矩阵 | 入口见 `协议台架验收/README.md`；输入 SHA 必须闭合，`Unverifiable` 不等于失败或通过 |

## 维护规则

- 原始日志保留原扩展名，文件名尽量包含端口、日期和时间。
- 测试记录应写清测试环境、固件版本、参数状态、操作步骤、实际结果、结论和未验证项。
- 如果测试证明某个问题已关闭，应回链到对应问题分析文档和版本改动与测试方案。
- 同名 Markdown 和 PDF 同时存在时，以 Markdown 作为可维护正文，PDF 仅作为历史导出件或外发阅读件。
- `26.05.16*` 旧日期命名的当前维护文件已归入问题复测、版本验证或现场记录，并改为 `2026-05-16_主题`；未保留的历史 PDF 只在迁移记录或历史版本说明中追溯，后续新增资料禁止使用旧日期格式。
- 本目录的 DOCX 和原始日志是现场证据或附件，不作为唯一维护正文；形成结论后应补 Markdown 测试记录并回链问题/版本资料。
- 现场 DOCX、DAT 等附件的责任边界见 `../00_构建与版本/附件与源文件清单.md`；新增现场附件后，必须在 `现场记录/` README 或对应问题复测/版本验证 Markdown 中写明测试对象、固件版本和结论归属。
