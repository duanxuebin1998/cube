## 维护边界

- 维护时保留原始附件扩展名，不手工改写原始内容。
- 新增现场附件时，文件名应包含日期、对象、端口或测试主题，避免只用工具导出的默认名。
- 如果附件内容和后续 Markdown 结论冲突，先以当前源码、现场复盘 Markdown 和版本验证记录为项目结论；附件保留为当时证据。
- 引用 DAT、DOCX 形成结论时，必须在对应 Markdown 写明测试对象、固件版本、关键参数、操作步骤和结论归属。
