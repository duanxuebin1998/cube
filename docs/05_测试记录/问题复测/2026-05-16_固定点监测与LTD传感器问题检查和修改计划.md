# 2026-05-16 固定点监测与 LTD 传感器问题检查和修改计划

## 资料范围

- 源码范围：`LTD_MAIN_CPU2`、`LTD_DISPLAY_CPU3`
- 串口记录：`docs/05_测试记录/现场记录/2026-05-15_COM3串口日志_22-38-49.DAT`
- 已参考文档：`docs/05_测试记录/问题复测/2026-05-16_瓦锡兰测罐底问题分析与修改计划.md`

本文件只整理问题判定和修改计划，未修改源码。

## 总体结论

本次提出的 7 个问题在当前代码中均能找到对应触发点。其中优先级最高的是 LTD 协议 `13-13`、固定点监测退出慢、瓦锡兰第一个测点位置不准和密度/频率 0 被错误日志化。这几项会直接影响现场判断、上位显示和固定点监测体验。

方向显示问题主要不在电机实际运动，而在状态/打印映射不统一：CPU3 的 Wartsila 状态映射把某些状态固定描述为下行或测量中，没有结合 CPU2 当前电机方向；CPU2 也存在部分注释和日志文字与实际 `MOTOR_DIRECTION_UP/DOWN` 不一致。

## 问题判定

| 编号 | 问题 | 判定 | 关键证据 |
| --- | --- | --- | --- |
| 1 | 测量完罐底上行，打印信息显示下行，实际上行，其他地方也有类似问题 | 存在 | `LTD_DISPLAY_CPU3/Communication/external/wartsila_modbus/wartsila_modbus_data_analysis.c` 中 `STATE_RUNTOPOINTING` 固定映射为 `0x08,0x40`，注释为“向下运动回固定点监测”；`STATE_WARTSILA_DENSITY_OVER` 又映射为 `0x0C,0x60`，与“完成”语义不一致。 |
| 2 | LTD 传感器回零点后或读取部件参数报 13-13，传感器工作正常，怀疑协议错误 | 存在，协议实现有疑点 | `13-13` 对应 `0x000D000D / SENSOR_DEVICE_REPORTED_ERROR`。`ltd_sensor_communication.c` 中 `rx[6] == 0xFF` 直接返回该错误；`DSM_V2_SwitchMode()` 注释说模式切换参数码应为 `0x00`，但代码发送的是模式字符，和协议说明不一致。 |
| 3 | 固定点监测退出很慢 | 存在 | `CMD_SinglePointMonitoring()` 长期循环调用 `SinglePoint_ReadSensor()`；单次读取内部有密度模式切换、稳定窗口、200 ms 采样、协议重试和可打断延时。瓦锡兰测后还有固定 8 s 延时供 CPU3 读取结果。 |
| 4 | 瓦锡兰分布测量第一个点位置不准确，其他点准确 | 存在 | `Wartsila_Density_SpreadMeasurement()` 中第一个点使用到起始点后的当前位置直接采样；后续点会再次 `MotorCtrl_MoveToPosition(target_mm)` 精确到位，因此首点比后续点更容易有位置偏差。 |
| 5 | 密度为 0、频率为 0 当成错误打印，实际上只是还未稳定或还没有测到 | 存在 | `SinglePoint_ReadSensor()` 将密度 0 按 `DENSITY_INVALID` 走 `ErrorLog_Retry`；`DSM_Get_LevelMode_Frequence()` 将频率 0 按 `SONIC_FREQ_ABNORMAL` 走错误重试。 |
| 6 | 下行到固定点位置速度很慢 | 存在或高概率存在 | 固定点回位使用 `MotorCtrl_MoveToPosition()`，内部最多 10 轮小步逼近；每次 `MoveAndWait()` 都有约 1 s 启动观察窗口，并伴随运行中速度刷新和大量串口打印。 |
| 7 | 固定点监测没有打印位置 | 存在 | `SinglePoint_ReadSensor()` 只打印频率、密度、温度，没有打印 `sensor_position`；结果结构有 `temperature_position`，但普通串口行看不出当前位置。 |

## 原因拆解

### 1. 方向显示不一致

CPU2 内部运动方向定义是：

- `MOTOR_DIRECTION_DOWN = 0`
- `MOTOR_DIRECTION_UP = 1`
- `debug_data.motor_state = 1` 表示上行，`2` 表示下行

主要问题是显示/外部状态映射没有统一复用这一口径。CPU3 的 Wartsila 状态映射按业务状态硬编码，例如 `STATE_RUNTOPOINTING` 固定输出“向下运动回固定点监测”，但同一状态也可能用于从低处上行到固定点。

### 2. LTD 13-13

`13-13` 是传感器类错误第 13 项，即 `SENSOR_DEVICE_REPORTED_ERROR = 0x000D000D`。当前产生路径：

1. CPU2 发送 LTD/V2 8 字节命令。
2. 收到应答后 `DSM_V2_CheckReply()` 检查功能码和参数码。
3. 如果应答第 7 字节 `rx[6] == 0xFF`，直接认为设备返回内部错误。

协议疑点在模式切换：头文件协议说明写明“设置测量模式时使用 00”，而 `DSM_V2_SwitchMode()` 当前 `DSM_V2_MakeFrame(tx, mode, 0, mode)`，参数码实际发了 `T` 或 `D`。如果 LTD 设备严格按协议校验参数码，就可能回 `0xFF`。

读取部件参数报 13-13 的另一个触发点是 `Sensor_ReadPartParamsInternal()` 直接调用 `Read_Density()`，如果刚切模式或数据未准备好，当前会把底层设备拒绝直接升级为最终错误。

### 3. 固定点监测退出慢

固定点监测是长循环：

1. `CMD_SinglePointMonitoring()` 移动到固定点。
2. 切密度模式。
3. 循环调用 `SinglePoint_ReadSensor()`。
4. 单点读取内部等待数据稳定。

退出请求虽然在循环和延时中有检查，但底层一次协议重试、模式切换和稳定窗口之间仍会造成响应延迟。瓦锡兰流程结束后的固定 8 s 延时也会造成“已经完成但还不退出/不进入下一步”的体感。

### 4. 瓦锡兰首点不准

瓦锡兰分布测量中，首点逻辑是“到起始点附近后直接采样”，后续点逻辑是“上行到目标附近，再执行一次 `MoveToPosition()` 精确寻找密度点位”。首点缺少这一步，所以只第一个点偏差明显。

### 5. 零值日志误导

密度 0 和频率 0 在现场含义并不一定是故障，可能只是：

- 刚切密度/液位模式，数据尚未稳定；
- 传感器还没有形成有效测量；
- 工况短时间处于空气、扰动或未采到状态。

当前直接用 `ErrorLog_Retry` 打“错误重试”，会让普通等待过程看起来像真实故障。

### 6. 下行到固定点慢

固定点回位使用绝对位置移动接口。该接口为保证到位精度，会循环读取当前位置并分段逼近；每段开始后还有启动观察窗口，并且串口打印量较大。对固定点监测这种重复动作，体感会偏慢。

### 7. 固定点无位置打印

`SinglePoint_ReadSensor()` 已在最终结果中记录 `temperature_position`，但实时打印缺少位置字段。现场只能看到频率、密度、温度，不方便确认固定点监测是否停在正确位置。

## 修改计划

### 阶段 1：修 LTD/V2 协议和 13-13 定位

目标文件：

- `LTD_MAIN_CPU2/Services/Sensor/ltd_sensor_communication.c`
- `LTD_MAIN_CPU2/Services/Sensor/ltd_sensor_communication.h`
- `LTD_MAIN_CPU2/Services/Sensor/sensor.c`

修改内容：

1. 将 `DSM_V2_SwitchMode()` 的模式切换参数码改为协议要求的 `0x00`。
2. 模式切换应答校验使用独立函数，避免继续按读取/写入参数码校验。
3. 遇到 `rx[6] == 0xFF` 时打印完整 TX/RX 帧、功能码、参数码和当前操作，便于判断是设备拒绝、参数码错还是模式未准备好。
4. `Sensor_ReadPartParamsInternal()` 中读取密度前显式进入密度模式并等待稳定；读取失败时保留已经读取到的位置、扭力、电机状态，日志标记为“部分读取失败”。

验证：

- 回零点后连续读取 LTD 编号、温度、密度、液位频率。
- 连续执行读取部件参数 10 次，确认不再稳定复现 `0x000D000D`。
- 如仍出现 `rx[6] == 0xFF`，串口必须能看到原始帧用于继续定位协议差异。

### 阶段 2：统一方向显示和 Wartsila 状态映射

目标文件：

- `LTD_DISPLAY_CPU3/Communication/external/wartsila_modbus/wartsila_modbus_data_analysis.c`
- `LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_motion_api.c`
- `LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_position_model.c`

修改内容：

1. 增加统一方向文本函数，按 `MotorCtrl_GetDisplayState()` 或 `debug_data.motor_state` 输出“上行/下行/静止”。
2. CPU3 Wartsila 状态映射中，`STATE_RUNTOPOINTING` 不再固定解释为下行；如协议允许，按当前运动方向映射，否则改日志说明为“运行到固定点”。
3. `STATE_WARTSILA_DENSITY_OVER` 映射为完成态，不再沿用 `0x0C,0x60` 的测量中状态。
4. 清理明显错误注释，例如“启动电机向下运动”但实际调用 `MotorCtrl_MoveUp()` 的位置。

验证：

- 测罐底后上行、回固定点、强制上行、强制下行分别观察 CPU2 串口和 CPU3/Wartsila 状态。
- 同一实际运动方向在所有日志中显示一致。

### 阶段 3：提高固定点监测退出响应

目标文件：

- `LTD_MAIN_CPU2/Application/Src/measure_density.c`
- `LTD_MAIN_CPU2/Application/Src/measure.c`
- `LTD_MAIN_CPU2/Services/Sensor/ltd_sensor_communication.c`

修改内容：

1. `CMD_SinglePointMonitoring()` 每轮开始、进入密度读取前、稳定等待中都检查命令切换。
2. `SinglePoint_ReadSensor()` 区分“单点测量”和“固定点监测”调用场景，固定点监测使用更短的单轮等待或允许快速返回上一笔有效值。
3. LTD 协议重试间隔改为可打断延时，避免命令切换时等待完整重试周期。
4. 瓦锡兰测量完成后的 8 s 结果保留延时增加明确日志，并考虑改为参数或缩短默认值。

验证：

- 固定点监测中下发取消、回零、强制上行，记录从命令到停止的耗时。
- 传感器异常、密度 0、正常稳定三种场景都要验证退出响应。

### 阶段 4：修正瓦锡兰首点定位

目标文件：

- `LTD_MAIN_CPU2/Application/Src/wartsila_density_measurement.c`

修改内容：

1. 到达起始点后，首点也执行一次 `MotorCtrl_MoveToPosition(start_pos_mm, speed)` 精确到位。
2. 首点采样前打印：目标首点、实际首点、偏差。
3. 如果首点偏差超过阈值，重试一次；仍超限则返回明确错误码或跳过本点。
4. 后续点保留现有精确到位逻辑，并统一打印目标、实际和偏差。

验证：

- 起始点 400 mm，多次运行检查首点位置是否接近 400 mm。
- 对比首点和第二、第三点偏差是否一致。

### 阶段 5：零密度/零频率从错误日志改为等待状态

目标文件：

- `LTD_MAIN_CPU2/Application/Src/measure_density.c`
- `LTD_MAIN_CPU2/Services/Sensor/sensor.c`

修改内容：

1. 密度 0 不立即调用 `ErrorLog_Retry`，改为普通提示：`密度未稳定/暂未测到`。
2. 频率 0 不立即按 `SONIC_FREQ_ABNORMAL` 打错误，先进入等待稳定流程。
3. 只有超过最大等待时间、连续次数达到最终失败阈值，才输出错误日志。
4. 恢复时只打印一次“已获得有效密度/频率”，避免刷屏。

验证：

- 刚进入密度模式时，密度 0 不再刷 `13-4`。
- 长时间确实无有效密度时仍能最终报警。
- 频率 0 的等待过程不再被现场误判为故障。

### 阶段 6：优化下行到固定点速度

目标文件：

- `LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_motion_api.c`
- `LTD_MAIN_CPU2/Application/Src/measure_density.c`
- `LTD_MAIN_CPU2/Application/Src/measure.c`

修改内容：

1. 增加固定点回位专用接口或参数，允许使用更快速度和更少逼近轮次。
2. `MotorCtrl_MoveToPosition()` 的 1 s 启动观察窗口按移动类型缩短，固定点回位不需要每段都等待完整窗口。
3. 回位过程减少正常状态高频打印，只保留开始、到位、异常。
4. CPU3/Wartsila 下发固定点位置后，CPU2 打印目标位置和实际到位位置，排除参数未同步导致的慢或误动。

验证：

- 同一固定点距离下，修改前后记录移动耗时。
- 确认速度提升后不影响到位精度和碰撞保护。

### 阶段 7：补固定点位置打印

目标文件：

- `LTD_MAIN_CPU2/Application/Src/measure_density.c`

修改内容：

1. `单点读数` 日志增加当前位置：`位置=xxx.xmm`。
2. 固定点监测稳定输出增加目标固定点、实际位置、偏差。
3. 单点测量和固定点监测共用读数函数时，用调用方状态区分打印前缀。

验证：

- 固定点监测串口行能直接看到位置。
- 位置与 CPU3/Wartsila 寄存器显示一致。

## 建议执行顺序

1. 先修 LTD/V2 协议和 `13-13`，这是错误码根源，影响回零、读取部件参数和自动恢复。
2. 再修固定点监测退出、零值日志和位置打印，改善现场可用性。
3. 再修瓦锡兰首点定位，保证分布测量结果可信。
4. 最后统一方向显示和固定点回位速度，减少误判和等待时间。

## 版本和协议影响评估

- 仅修改 CPU2 内部 LTD/V2 协议实现、日志、流程等待策略：需要升级 CPU2 固件版本。
- 如果修改 CPU3 Wartsila 状态映射：需要升级 CPU3 固件版本。
- 如果不改变 CPU2/CPU3 共享寄存器地址、命令码、数据结构字段含义，则不需要升级 `DEVICE_PROTOCOL_VERSION`。
- 如果新增固定点回位速度参数、结果保留时间参数或新的共享状态字段，则属于 CPU2/CPU3 共享协议变化，需要同步升级协议版本并更新协议变更记录。

## 需要现场确认

1. LTD/V2 模式切换帧第 7 字节是否确认为 `0x00`，还是设备实际兼容旧实现。
2. 固定点监测退出期望耗时目标是多少，例如 1 s 内、3 s 内或只要当前采样结束即可。
3. 固定点回位是否允许使用最大速度，还是需要单独限制速度。
4. 密度 0 和频率 0 的最终报警超时时间，建议先按当前 5 分钟上限保留，再优化提示。
5. Wartsila 完成态 `STATE_WARTSILA_DENSITY_OVER` 对外应答码是否必须按客户协议固定为 `0x28,0x40`。
