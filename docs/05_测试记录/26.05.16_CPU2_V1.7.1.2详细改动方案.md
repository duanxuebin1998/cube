# CPU2 V1.7.1.2 详细改动方案

## 1. 版本信息

- 版本范围：CPU2 `V1.7.1.1` -> `V1.7.1.2`
- 提交：`84cc5b5 修复LTD协议与瓦锡兰分布测量问题`
- 日期：2026-05-16
- 协议影响：不修改 CPU2/CPU3 共享寄存器、命令码、数据结构字段含义，不升级 `DEVICE_PROTOCOL_VERSION`
- CPU3 影响：不修改 CPU3 程序，不修改本设备和瓦锡兰设备的对应关系

## 2. 修改目标

本版本集中处理现场测试中发现的传感器协议、固定点监测、瓦锡兰分布测量、找罐底上行动作和日志可读性问题。

核心目标：

1. 消除 LTD/V2 在回零点后或读取部件参数时误报 `13-13` 的问题。
2. DSM 一代响应首字母 `E/e` 时不再按设备内部错误处理，只提示传感器电压过低。
3. 固定点监测退出更快，密度/频率未稳定时不再打印错误日志。
4. 瓦锡兰分布测首点执行精确定位，并补充测后探底频次和次数日志。
5. 找罐底流程中的固定距离上行改为无扭力检测上行，避免脱离罐底时误报扭力错误。
6. 更新故障代码表和测试记录，保证错误码显示口径一致。

## 3. LTD/V2 协议与部件参数读取

### 3.1 问题现象

读取部件参数或回零点后，LTD 传感器工作正常，但设备可能显示 `13-13`。该错误实际对应：

- `0x000D000D`
- `SENSOR_DEVICE_REPORTED_ERROR`
- 传感器返回设备内部错误

### 3.2 原因分析

LTD/V2 模式切换帧的参数码和应答校验规则不一致，部分模式切换应答会返回 `rx[6] == 0xFF`。旧逻辑把该帧直接作为设备内部错误返回，最终由读取部件参数命令显示为 `13-13`。

另外，读取部件参数时如果 LTD 仍处于液位模式，直接读取密度/频率也可能导致密度频率暂时不可用。

### 3.3 修改方案

1. LTD/V2 模式切换帧参数码固定为 `0x00`。
2. 模式切换应答按模式帧规则校验，期望参数码为 `0x00`。
3. `rx[6] == 0xFF` 时只打印原始 8 字节帧，不置错误状态。
4. 读取部件参数时，LTD 先切换到密度模式并等待稳定。
5. LTD 密度/频率暂时读不到时允许部分成功，不影响位置、扭力、电机状态等其它部件参数。

### 3.4 代码位置

- `LTD_MAIN_CPU2/Services/Sensor/ltd_sensor_communication.c`
  - `DSM_V2_CheckReply()`：模式帧应答参数码按 `0x00` 校验；`rx[6] == 0xFF` 只打印不置错。
  - `DSM_V2_SwitchMode()`：模式切换帧参数码固定为 `0x00`。
  - `DSM_V2_Read_DensityFrequency()`：密度频率周期平方均值为 0 时打印等待稳定/未测到。
- `LTD_MAIN_CPU2/Services/Sensor/sensor.c`
  - 新增 `Sensor_PrepareLtdDensityModeForPartParams()`。
  - `Sensor_ReadPartParamsInternal()` 中 LTD 密度/频率失败按部分成功处理。

## 4. DSM 一代首字母 E/e 处理

### 4.1 问题现象

DSM 一代传感器响应首字母为 `E` 时，读取部件参数可能显示 `13-13`。

### 4.2 修改方案

1. DSM 所有响应包首字母为 `E/e` 时，不再按 `SENSOR_DEVICE_REPORTED_ERROR` 处理。
2. 统一只打印：

```text
DSM传感器电压过低
```

3. 该响应继续按正常数据帧解析。
4. 水位电容读取中，`resp[0] == 'E'` 不再返回 `SENSOR_DEVICE_REPORTED_ERROR`。

### 4.3 代码位置

- `LTD_MAIN_CPU2/Services/Sensor/dsm_sensor_communication.c`
  - `DSM_LogLowVoltageFrame()`：统一打印低电压提示。
  - `IsErrorResponse()`：首字母 `E/e` 直接放行。
  - `UART6_SendWithRetry()`：收到正常帧后先打印低电压提示。
  - `Read_Water_Capacitance()`：`E` 帧继续解析水位电容值。

## 5. 固定点监测体验

### 5.1 问题现象

固定点监测退出慢，传感器等待稳定或重试期间不能及时响应命令切换。密度为 0 或频率为 0 时会被当作错误打印，但现场实际含义常是尚未稳定或还未测到。

### 5.2 修改方案

1. 固定点监测中命令切换检查前置。
2. 传感器重试和稳定等待改为可被命令切换快速打断。
3. 稳定结果增加当前位置打印。
4. 密度 0、频率 0 改成普通“等待稳定/未测到”日志。
5. 只有稳定超时或最终失败时才打印错误日志。

### 5.3 代码位置

- `LTD_MAIN_CPU2/Application/Src/measure_density.c`
- `LTD_MAIN_CPU2/Application/Src/measure.c`

## 6. 瓦锡兰分布测量

### 6.1 首点定位

#### 问题现象

瓦锡兰分布测量第一个密度点位置不准确，后续点准确。

#### 修改方案

1. 第一个点也执行精确定位。
2. 精确定位继续使用原有 `MotorCtrl_MoveToPosition()`，不新增独立移动函数。
3. 首点和后续点统一打印目标位置、实际位置和偏差。
4. 偏差超限时重试一次，仍超限则返回明确点位错误。

#### 代码位置

- `LTD_MAIN_CPU2/Application/Src/wartsila_density_measurement.c`

### 6.2 结果保留和测后探底日志

#### 修改方案

1. 分布测量完成后，8 秒结果保留期间打印原因和倒计时。
2. 测后探底判断打印：
   - 测量总次数
   - 探底频次
   - 当前周期第几次
   - 本次是否执行探底
3. 探底频次参数大于 100 时按每次探底处理并打印提示。
4. 探底频次为 0 时打印不探底。

#### 代码位置

- `LTD_MAIN_CPU2/Application/Src/measure.c`

## 7. 找罐底固定距离上行

### 7.1 问题现象

找罐底程序中，触底后固定距离上行用于脱离罐底。如果该上行动作走普通检测路径，可能在脱离罐底过程中触发扭力检测错误。

### 7.2 修改方案

找罐底流程中的固定距离上行全部改为无检测上行 `MotorCtrl_MoveBlockingNoDetect()`：

1. 初始位置调整上行 100 mm。
2. 粗找失败后上行 100 mm。
3. 找罐底完成后上行 100 mm。
4. 角度找底基准采集前安全上行 100 mm。

已存在的粗找前离底分段上行和精找前上行保持无检测上行。

### 7.3 代码位置

- `LTD_MAIN_CPU2/Application/Src/measure_tank_height.c`

本版本只修改 CPU2 内部流程、日志、传感器协议处理和错误处理策略。

1. CPU2/CPU3 共享寄存器地址不变。

6. CPU2 固件版本从 `V1.7.1.1` 升至 `V1.7.1.2`，用于发布追踪。

## 13. 现场测试建议

建议按以下顺序回归：

1. LTD 传感器回零点后读取部件参数，确认不再显示 `13-13`。
2. LTD 读取部件参数时观察日志，确认先切密度模式并等待稳定。
3. DSM 一代传感器返回首字母 `E/e` 响应时，确认只打印“DSM传感器电压过低”，不再置 `13-13`。
4. 固定点监测中途退出，确认退出响应时间明显缩短。
5. 固定点监测稳定结果，确认日志包含当前位置。
6. 密度/频率为 0 的稳定等待阶段，确认不再打印错误日志。
7. 瓦锡兰分布测量首点，确认目标首点、实际首点、偏差日志存在。
8. 瓦锡兰分布测完成后，确认 8 秒结果保留倒计时和测后探底频次日志存在。
9. 找罐底触底后固定距离上行，确认不再因脱离罐底上行动作误报扭力错误。
10. 确认 CPU3 设备对应关系、瓦锡兰设备对应关系无变化。

## 14. 回退方案

如现场出现新问题，可按以下粒度回退：

1. LTD/V2 误报相关问题：回退 `ltd_sensor_communication.c` 和 `sensor.c` 中的 LTD 读部件参数改动。
2. DSM 首字母 `E/e` 处理问题：回退 `dsm_sensor_communication.c` 中 `IsErrorResponse()` 和水位电容 `E` 帧处理。
3. 固定点监测退出问题：回退 `measure_density.c` 中可打断等待和重试逻辑。
4. 瓦锡兰分布测首点问题：回退 `wartsila_density_measurement.c` 中首点精确定位和偏差重试逻辑。
5. 找罐底无检测上行问题：回退 `measure_tank_height.c` 中固定距离上行调用。

推荐优先按模块回退，不建议整体回退版本，避免同时丢失故障代码表和日志改进。
