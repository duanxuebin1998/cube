# 需求与计划文档索引

更新日期：2026-08-05

本目录用于保存需求拆解、近期工作计划、执行方案和待确认事项。为了便于追踪，Markdown 正文按实现状态拆分为 `已实现` 和 `未实现` 两类。

PDF 仅作为历史导出件保留在本目录根部，后续维护以 Markdown 正文为准。

## 目录分类

| 目录 | 用途 | 判定口径 |
| --- | --- | --- |
| `已实现/` | 已有代码、协议、菜单或版本记录落地的需求 | 能在源码、CHANGELOG、协议记录或版本改动与测试方案中找到实现依据 |
| `未实现/` | 尚未落地、只完成方案设计、仍在推进或混合待办的需求和计划 | 仍包含未完成任务、待确认项、待现场回归或尚未形成版本改动 |
| `流程模板/` | Codex 协作、影响面检查、故障对比包和工作日志模板 | 用于新任务启动前复制填写，不作为具体需求实现依据 |

## 与其他目录的边界

| 情况 | 放置位置 |
| --- | --- |
| 需求仍在确认、只是执行计划或尚未实现 | `未实现/` |
| 需求已有代码或版本改动落地，但仍需要保留需求依据 | `已实现/` |
| 已经形成具体版本改动和测试方案 | `../00_构建与版本/版本改动与测试/` |
| 需求来自外部协议地址表或映射关系 | `../01_协议与寄存器/` |
| 需求执行后发现问题并形成整改记录 | `../03_问题分析与整改/` |
| 需求验证产生现场记录、串口日志或测试报告 | `../05_测试记录/` |

## 维护规则

- 新增需求文档应写清背景、目标、影响模块、待确认项、执行步骤和验收标准。
- 新需求默认放入 `未实现/`；实现落地后再移动到 `已实现/`，并在本索引补充实现依据。
- 如果需求会改变固件行为、协议语义、参数范围或显示行为，后续实现时必须按版本规则同步版本、CHANGELOG 和改动与测试方案。
- PDF 或 docx 只作为历史导出或外部输入保存；项目内可持续维护的正文优先使用 Markdown。
- 本目录不放正式测试结果；需求完成后的实测记录应移交 `../05_测试记录/`，版本发布口径应移交 `../00_构建与版本/版本改动与测试/`。
