# 需求与计划文档索引

更新日期：2026-06-06

本目录用于保存尚未完全固化为版本改动的需求拆解、近期工作计划、执行方案和待确认事项。这里的资料强调“准备做什么、为什么做、还有哪些问题未确认”。

## 文件分类

| 分类 | 文档 | 用途 |
| --- | --- | --- |
| 综合计划 | `近期固件工作计划.md`、`2026-06-02_下一步固件工作计划.md` | 汇总阶段性固件工作、优先级和后续安排 |
| 故障恢复 | `测量失败后的自动恢复需求.md` | 自动恢复、重试、故障状态保持和人工命令抢占需求 |
| 外部协议需求 | `二代计量仪同步支持DSM_V1.228协议需求方案.md` | DSM V1.228 兼容需求、影响范围和执行方案 |
| 无线滑环 | `无线滑环最近匹配正式命令需求.md` | 无线滑环匹配命令从调试入口转正式命令的需求依据 |

## 与其他目录的边界

| 情况 | 放置位置 |
| --- | --- |
| 需求仍在确认或只是执行计划 | 本目录 |
| 已经形成具体版本改动和测试方案 | `../00_构建与版本/版本改动与测试/` |
| 需求来自外部协议地址表或映射关系 | `../01_协议与寄存器/` |
| 需求执行后发现问题并形成整改记录 | `../03_问题分析与整改/` |
| 需求验证产生现场记录、串口日志或测试报告 | `../05_测试记录/` |

## 维护规则

- 新增需求文档应写清背景、目标、影响模块、待确认项、执行步骤和验收标准。
- 如果需求会改变固件行为、协议语义、参数范围或显示行为，后续实现时必须按版本规则同步版本、CHANGELOG 和改动与测试方案。
- PDF 或 docx 只作为历史导出或外部输入保存；项目内可持续维护的正文优先使用 Markdown。
