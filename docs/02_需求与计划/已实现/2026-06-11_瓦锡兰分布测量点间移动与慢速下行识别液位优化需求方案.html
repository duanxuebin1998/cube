背景和目标

当前瓦锡兰分布测量在从一个测点向下一个测点移动时，会切换到液位模式，并在上行过程中判断是否进入空气。这个流程可以在运动中及时发现液面，但也让点间移动、液位判定和密度采集强耦合，后续维护和现场问题定位成本较高。

新的需求把流程拆成两个阶段：点间移动只负责到达目标点；到点后再用密度模式读取到的密度值和频率值判断当前点是否在空气中。若为空气点，则停止继续向上布点，切液位模式并慢速下行；识别到液体后取当前位置作为液位位置，再按该液位位置裁剪高位点。

目标

  1. 瓦锡兰分布测量从一个点到下一个点的过程中，不切换液位模式，不在运动过程中做液位模式空气检测。
  2. 到达测点后，通过密度模式读取的密度值和频率值判断当前测点是液体还是空气。
  3. 当前点为液体时，保存该点并继续运行到下一个点。
  4. 当前点为空气时，该空气点不进入最终结果；记录日志后切换液位模式并慢速下行识别液体。
  5. 识别到液体后，把当前位置作为液位位置；只有位置小于“液位位置 - 距离限制”的已保存液体点保留为有效点。
  6. 慢速下行未识别到液体、裁剪后无有效点或关键读取失败时，本次瓦锡兰分布测量失败，不更新新的有效结果，不按成功完成态对外暴露。

参数和判定规则

测量参数

参数 含义 单位
wartsila_lower_density_limit 起始点 / 最低测点高度 mm
wartsila_upper_density_limit 最高测点高度 mm
wartsila_density_interval 点间距 mm
wartsila_max_height_above_surface 有效测点距识别液位的最小允许距离 mm
oilLevelFrequency 固定频率液位阈值，用于空气判定 Hz

空气判定

条件 判定 说明
density < 100 空气 到点后密度过低，视为传感器已进入空气。
frequency > g_deviceParams.oilLevelFrequency 空气 频率超过固定频率液位阈值，视为空气。
密度读取 5 分钟超时后输出 density == 0 空气 超时兜底输出 0 不作为有效密度点。
不满足以上条件 液体 保存为有效液体测点。
只要任一空气条件成立，就停止继续向上布点。空气点不进入 single_density_data[]，也不计入 measurement_points。

点间移动

从当前测点运行到下一个测点时，新的瓦锡兰流程要求“只按位置移动”。运动过程仍需保留电机错误、驱动状态、碰撞、命令切换等安全检查，但不再做液位模式相关动作。

  1. 不切换液位模式。
  2. 不调用运动中液位状态检测。
  3. 不因为运动过程中频率达到液位阈值而提前停止。
  4. 直接按目标位置调用位置运行函数，到达下一个测点。
  5. 若点间移动失败，本次测量失败。

到点采集和空气判定

到达目标测点后，进入瓦锡兰专用采点逻辑。该逻辑需要读取密度模式下的频率、密度和温度，然后输出液体/空气判定。

液体点处理

  • 密度和频率均不触发空气条件。
  • 保存当前点到临时 DensityDistribution。
  • 记录点位、密度、温度。
  • 继续运行到下一个测点。

空气点处理

  • 空气点不保存到最终结果。
  • 记录日志：点序号、目标位置、实际位置、密度、频率、触发原因。
  • 停止继续向上布点。
  • 慢速下行识别液体。
typedef struct {

慢速下行识别液位函数契约

当某个测点判定为空气后，流程调用慢速下行识别液体函数。该函数已在 CPU2 内部实现，仍需现场硬件联调验证速度、识别稳定性和安全边界。

// 输入：当前空气点位置、测量上下文。
// 输出：识别到液体时的当前位置 level_mm。

约束 要求
返回成功 level_mm 必须是识别到液体时的当前位置，单位 mm，并作为本次液位位置使用。
返回失败 本次瓦锡兰分布测量失败，不更新新的有效结果。
命令切换 返回 STATE_SWITCH，由上层按正常中断退出。
实现范围 实现保留慢速下行、液体识别、盲区、碰撞、丢步、驱动状态、超时和命令切换处理；现场仍需联调确认。

识别液位裁剪规则

识别到液体后，根据识别到的液位位置裁剪已保存的液体点。空气点本身不在结果里，因此不需要再删除。

  1. 从最高已保存液体点开始向下检查。
  2. 先计算有效点位置边界：valid_limit_mm = level_mm - wartsila_max_height_above_surface。
  3. 只有 point.position_mm < valid_limit_mm 的液体点作为有效点保留。
  4. 如果 point.position_mm >= valid_limit_mm，说明该点距离液面太近或正好压在边界上，删除该点。
  5. 继续向下检查，直到遇到第一个满足 position_mm < valid_limit_mm 的点。
  6. 不设置“最多删除两个点”的硬限制；两个点只是典型情况。
  7. 删除后重新计算点数、平均密度和平均温度。
  8. 如果裁剪后没有有效液体点，本次测量失败。
典型场景是最后一个测点为空气点，不进入结果；倒数第二个点是液体，但如果位置不小于有效边界，也会被删除。极端情况下多个高位液体点都可能被连续删除。

结果写入和失败语义

成功写入条件

  • 至少有 1 个有效液体测点。
  • 已识别到液体并取得液位位置。
  • 高位点裁剪完成。
  • 平均值重算完成。
  • 测量过程没有未恢复错误。

失败场景处理

场景 处理
参数非法 返回参数错误，本次测量失败。
点间移动失败 返回运动错误，本次测量失败。
到点读取传感器失败 返回传感器错误，本次测量失败。
未识别到液体 本次测量失败，不更新新的有效结果。
裁剪后无有效液体点 本次测量失败。
命令切换 返回 STATE_SWITCH，按正常中断退出。
失败时不把清零临时结果覆盖为新的有效结果，也不进入 STATE_WARTSILA_DENSITY_OVER 的成功结果语义。

推荐实现方向

推荐新增瓦锡兰专用采点函数，而不是修改通用 SinglePoint_ReadSensor()。

  • 空气判定是瓦锡兰新流程专用语义，不应影响普通单点、固定点监测和其他分布测量。
  • Read_Density() 已能返回频率、密度、温度，瓦锡兰专用函数可以直接保留本次频率用于判定和日志。
  • 不需要修改 DensityMeasurement，避免改变 CPU2/CPU3 共享结果结构和外部寄存器语义。
  • 后续测试范围更容易收敛到瓦锡兰路径。
函数 责任
Wartsila_MoveToDensityPoint() 只移动到目标点，不切液位模式，不做液位空气检测。
Wartsila_ReadPointAndClassify() 读取密度、频率、温度，输出液体或空气判定。
Wartsila_MoveDownToLiquidAfterAirPoint() 已实现，空气点后切液位模式并慢速下行，识别到液体后返回当前位置。
Wartsila_TrimPointsByOilLevel() 按识别液位和最小液面距离裁剪，只保留位置小于边界的有效点并重算统计。

协议和版本影响

本轮已改变 CPU2 固件行为，提交阶段已升级 CPU2 到 V1.13.1.0。版本和协议影响如下：

  • CPU2 固件版本：V1.13.0.1 -> V1.13.1.0。
  • 如果不改 CPU2/CPU3 共享命令、寄存器、结构体、参数语义和 CPU3 消费方式，预计不需要升级 DEVICE_PROTOCOL_VERSION。
  • 失败时不优化 CPU3 外部 Wartsila 主站状态码表达；按现有错误/非成功完成语义处理，因此本方案不因失败状态表达调整 CPU3 外部协议。
  • 如果新增可配置阈值而不是复用 oilLevelFrequency，则会涉及参数、菜单、寄存器影响，需要重新评估协议和参数存储版本。
  • 版本改动与测试方案见 ../../00_构建与版本/版本改动与测试/2026-06-11_CPU2_V1.13.1.0_瓦锡兰分布测量点间移动与空气点液位识别_改动与测试方案.md。

验收标准

  1. 起始点定位和后续点间移动过程中，都不切换液位模式，不因液位阈值提前停止。
  2. 液体点实际密度值和浮点频率均在有效范围内时，点被保存。
  3. 实际密度值 < 100 时，当前点按空气处理且不保存。
  4. 浮点频率 > oilLevelFrequency 时，当前点按空气处理且不保存。
  5. 密度读取 5 分钟超时输出 0 时，当前点按空气处理。
  6. 空气点后切液位模式并慢速下行；未识别到液体时本次测量失败，不更新新的有效结果。
  7. 识别到液体后，只有 point.position_mm < level_mm - wartsila_max_height_above_surface 的点保留为有效点。
  8. 裁剪后平均温度、平均密度和点数重新计算。
  9. 裁剪后无有效点时，本次测量失败。
  10. 普通单点、固定点监测、普通分布测量、国标分布测量、密度每米测量行为不变。

已确认口径

  • 慢速下行识别液体函数已落地：使用慢速下行、液位模式运动中判定、当前位置作为液位，并保留安全保护。
  • 起始点定位同步改为不做运动中液位检测。
  • 空气判定中密度 < 100 使用实际密度值，不使用 RAW 值。
  • 频率比较使用本次读取得到的浮点频率，不使用写入 debug_data.frequency 后的整数频率。
  • 失败时不需要同步优化 CPU3 外部 Wartsila 主站的状态码表达。
