# CPU3测量结果按状态展示优化需求与计划

日期：2026-06-09

## 1. 背景

当前 CPU3 设备状态页会根据 `g_measurement` 中多个测量结果字段动态展示液位、水位、密度、温度、位置、扭力、传感器值、角度和罐高等信息。现有逻辑主要分布在 `LTD_DISPLAY_CPU3/Application/display/display.c`：

- `oled_equipment()`：负责实际绘制状态和测量值。
- `CalculateValidPara()`：负责判断哪些参数有效、分页和行号。
- `IsOilLevelSensorState()`、`IsWaterLevelSensorState()`、`IsRealHeightDisplayState()`：只覆盖了少量状态分类。

现有实现已经可以显示基本结果，但“当前状态”和“展示值来源”的对应关系不够清晰，部分状态下会显示不属于当前测量任务的历史值，容易造成现场人员误读。

## 2. 现状问题

### 2.1 密度和温度固定取单点监测结果

当前密度和温度显示固定使用：

- `g_measurement.single_point_monitoring.density`
- `g_measurement.single_point_monitoring.temperature`

这会导致以下状态显示不合理：

- `STATE_SINGLEPOINTOVER` 单点测量完成时，理论上应显示 `single_point_measurement`，而不是 `single_point_monitoring`。
- `STATE_SPREADPOINTOVER`、`STATE_GB_SPREADPOINTOVER`、`STATE_COM_METER_DENSITY_OVER`、`STATE_INTERVAL_DENSITY_OVER`、`STATE_WARTSILA_DENSITY_OVER` 等分布类完成态，理论上应显示 `density_distribution.average_density` 和 `density_distribution.average_temperature`。
- 待机或其它状态下，只要 `single_point_monitoring` 中仍有旧值，就可能继续显示旧监测结果。

### 2.2 液位显示只绑定 `STATE_FLOWOIL`

当前 `flagofoillevelvalid` 只在 `device_state == STATE_FLOWOIL` 时置位。实际业务中，以下状态也和液位结果相关：

- `STATE_FINDOIL`
- `STATE_FINDOILOVER`
- `STATE_CALIBRATIONOILING`
- `STATE_SYNTHETICING`
- `STATE_SYNTHETICING_OVER`
- 分布密度测量完成态中的 `density_distribution.Density_oil_level`

如果只在液位跟随状态显示液位，会让“寻找液位完成”或“综合测量完成”缺少关键结果。

### 2.3 水位只按数值有效性显示

当前水位只判断：

- `g_measurement.water_measurement.water_level != LEVEL_DOWNLIMITWATER`

这会导致水位旧值在非水位测量状态下仍可能参与分页显示。水位显示应该优先由状态语义触发，再判断数值是否有效。

### 2.4 传感器值按状态粗略切换

当前传感器值逻辑为：

- 液位相关状态显示频率。
- 水位相关状态显示电容。

这个方向是合理的，但状态覆盖不完整。例如液位完成态、液位跟随完成态、部分标定/综合状态没有完整纳入；同时若状态不属于液位或水位场景，不应因为旧电容值有效而显示电容。

### 2.5 显示有效性和数据源选择耦合

当前 `CalculateValidPara()` 判断是否显示，`oled_equipment()` 再直接读取全局结构字段。两个函数都隐含了一套状态和数据源关系，后续新增状态时容易漏改一边。

## 3. 优化目标

1. 建立清晰的“设备状态 -> 显示上下文 -> 数据源 -> 显示项”映射关系。
2. 避免非当前任务的旧测量值在状态页继续显示。
3. 保持 CPU3 状态页信息简洁：运行中显示过程量，完成态显示业务结果，故障态优先显示故障原因。
4. 不改变 CPU2/CPU3 共享协议字段，优先在 CPU3 显示层完成优化。
5. 为后续新增测量状态提供集中入口，避免在多个函数中散落判断。

## 4. 总体方案

新增 CPU3 显示上下文概念，由当前 `DeviceState` 决定本轮状态页应该展示哪类结果。

建议新增内部枚举：

```c
typedef enum {
    DISPLAY_RESULT_CONTEXT_NONE = 0,
    DISPLAY_RESULT_CONTEXT_OIL_LEVEL,
    DISPLAY_RESULT_CONTEXT_WATER_LEVEL,
    DISPLAY_RESULT_CONTEXT_SINGLE_POINT,
    DISPLAY_RESULT_CONTEXT_SINGLE_MONITOR,
    DISPLAY_RESULT_CONTEXT_DENSITY_DISTRIBUTION,
    DISPLAY_RESULT_CONTEXT_BOTTOM_HEIGHT,
    DISPLAY_RESULT_CONTEXT_MOTION_DEBUG,
    DISPLAY_RESULT_CONTEXT_WEIGHT,
    DISPLAY_RESULT_CONTEXT_ERROR
} DisplayResultContext;
```

建议新增内部函数：

```c
static DisplayResultContext Display_GetResultContext(DeviceState state);
static bool Display_GetDensityValue(DisplayResultContext ctx, uint32_t *density);
static bool Display_GetTemperatureValue(DisplayResultContext ctx, uint32_t *temperature);
static bool Display_ShouldShowOilLevel(DisplayResultContext ctx);
static bool Display_ShouldShowWaterLevel(DisplayResultContext ctx);
static bool Display_ShouldShowSensorValue(DisplayResultContext ctx);
```

原则：

- `CalculateValidPara()` 只根据 `DisplayResultContext` 和字段有效性判断是否显示。
- `oled_equipment()` 使用同一套 `DisplayResultContext` 选择数据源并绘制。
- 密度、温度、液位、水位、传感器值不再直接依赖“字段非零”作为第一条件。

## 5. 状态与显示项映射

### 5.1 液位测量类

| 状态 | 显示上下文 | 推荐显示项 | 数据源 |
| --- | --- | --- | --- |
| `STATE_FINDOIL` | 液位 | 位置、频率、扭力 | `debug_data.sensor_position`、`oil_measurement.current_frequency`、`debug_data.current_weight` |
| `STATE_FINDOILOVER` | 液位 | 液位 | `oil_measurement.oil_level` |
| `STATE_FLOWOIL` | 液位 | 液位、频率 | `oil_measurement.oil_level`、`oil_measurement.current_frequency` |
| `STATE_CALIBRATIONOILING` | 液位 | 位置、频率、扭力 | `debug_data`、`oil_measurement.current_frequency` |
| `STATE_SYNTHETICING` | 综合运行 | 位置、频率或电容、扭力 | 根据当前子流程可见数据，保守显示过程量 |
| `STATE_SYNTHETICING_OVER` | 综合完成 | 液位、水位、平均密度、平均温度 | 优先使用各业务结果字段 |

液位有效性规则：

- `oil_measurement.oil_level == UNVALID_LEVEL`：不显示液位。
- `oil_measurement.oil_level == OILLEVELDOWNLIMIT` 或 `LEVEL_DOWNLIMIT`：显示“低于盲区”。
- 其它值按 `0.1 mm` 精度显示为 `mm`。

### 5.2 水位测量类

| 状态 | 显示上下文 | 推荐显示项 | 数据源 |
| --- | --- | --- | --- |
| `STATE_FINDWATER` | 水位 | 位置、电容 | `debug_data.sensor_position`、`water_measurement.current_capacitance` |
| `STATE_FINDWATER_OVER` | 水位 | 水位 | `water_measurement.water_level` |
| `STATE_FOLLOW_WATER_POINT_SEARCHING` | 水位 | 位置、电容 | `debug_data.sensor_position`、`water_measurement.current_capacitance` |
| `STATE_FOLLOW_WATERING` | 水位 | 水位、电容 | `water_measurement.water_level`、`water_measurement.current_capacitance` |
| `STATE_CALIBRATE_WATERING` | 水位 | 位置、电容 | `debug_data.sensor_position`、`water_measurement.current_capacitance` |
| `STATE_CALIBRATE_WATER_OVER` | 水位 | 水位 | `water_measurement.water_level` |

水位有效性规则：

- `water_measurement.water_level == LEVEL_DOWNLIMITWATER`：不显示数值；如果状态明确是水位完成态，可显示“低于盲区”或“无有效水位”，需现场确认文案。
- `water_measurement.current_capacitance <= 0.0f`：不显示电容。

### 5.3 单点密度测量类

| 状态 | 显示上下文 | 推荐显示项 | 数据源 |
| --- | --- | --- | --- |
| `STATE_SINGLEPOINTING` | 单点测量 | 位置、扭力、温度、密度 | `debug_data`、`single_point_measurement` |
| `STATE_RUNTOPOINTING` | 单点测量过程 | 位置、扭力 | `debug_data.sensor_position`、`debug_data.current_weight` |
| `STATE_SINGLEPOINTOVER` | 单点测量 | 密度、温度、位置 | `single_point_measurement.density`、`single_point_measurement.temperature`、`single_point_measurement.temperature_position` |

有效性规则：

- `density == UNVALID_DENSITY`：不显示密度。
- `temperature == 0` 或超过合理范围：不显示温度。
- 温度仍按现有显示口径 `temperature - 20000`，小数位保持 2 位。

### 5.4 单点监测类

| 状态 | 显示上下文 | 推荐显示项 | 数据源 |
| --- | --- | --- | --- |
| `STATE_SPTESTING` | 单点监测 | 密度、温度、位置 | `single_point_monitoring` |
| 默认命令为 `CMD_MONITOR_SINGLE_DEF` 且设备处于待机/运行监测场景 | 单点监测 | 密度、温度、位置 | `single_point_monitoring` |

说明：

- `single_point_monitoring` 只应用于监测/检测语义。
- 单点测量完成态不得再使用 `single_point_monitoring`。

### 5.5 分布密度测量类

| 状态 | 显示上下文 | 推荐显示项 | 数据源 |
| --- | --- | --- | --- |
| `STATE_SPREADPOINTING` | 分布测量 | 位置、扭力、点数 | `debug_data`、`density_distribution.measurement_points` |
| `STATE_GB_SPREADPOINTING` | 分布测量 | 位置、扭力、点数 | `debug_data`、`density_distribution.measurement_points` |
| `STATE_METER_DENSITY` | 分布测量 | 位置、扭力、点数 | `debug_data`、`density_distribution.measurement_points` |
| `STATE_INTERVAL_DENSITY` | 分布测量 | 位置、扭力、点数 | `debug_data`、`density_distribution.measurement_points` |
| `STATE_WARTSILA_DENSITY_START` | 分布测量 | 状态、位置 | `debug_data.sensor_position` |
| `STATE_WARTSILA_DENSITY_MEASURING` | 分布测量 | 位置、点数 | `debug_data`、`density_distribution.measurement_points` |
| `STATE_SPREADPOINTOVER` | 分布测量完成 | 平均密度、平均温度、点数、液位 | `density_distribution` |
| `STATE_GB_SPREADPOINTOVER` | 分布测量完成 | 平均密度、平均温度、点数、液位 | `density_distribution` |
| `STATE_COM_METER_DENSITY_OVER` | 分布测量完成 | 平均密度、平均温度、点数 | `density_distribution` |
| `STATE_INTERVAL_DENSITY_OVER` | 分布测量完成 | 平均密度、平均温度、点数、液位 | `density_distribution` |
| `STATE_WARTSILA_DENSITY_OVER` | 分布测量完成 | 平均密度、平均温度、点数、液位 | `density_distribution` |

有效性规则：

- `average_density == UNVALID_DENSITY`：不显示平均密度。
- `average_temperature == 0` 或超范围：不显示平均温度。
- `measurement_points == 0`：不显示点数。
- `Density_oil_level == UNVALID_LEVEL`：不显示液位。

### 5.6 罐底和罐高类

| 状态 | 显示上下文 | 推荐显示项 | 数据源 |
| --- | --- | --- | --- |
| `STATE_FINDBOTTOM` | 罐高过程 | 位置、扭力、X角、Y角 | `debug_data` |
| `STATE_FINDBOTTOM_OVER` | 罐高完成 | 罐高、X角、Y角 | `height_measurement.current_real_height`、`debug_data.angle_x`、`debug_data.angle_y` |
| `STATE_CALIBRATE_TANKHEIGHTING` | 罐高过程 | 位置、扭力、X角、Y角 | `debug_data` |
| `STATE_CALIBRATE_TANKHEIGHT_OVER` | 罐高完成 | 罐高、X角、Y角 | `height_measurement.current_real_height`、`debug_data.angle_x`、`debug_data.angle_y` |

说明：

- 角度显示仍受 `bottom_detect_mode` 控制。
- `height_measurement.current_real_height != 0` 且状态为罐高完成类时显示罐高。

### 5.7 运动控制和维护类

| 状态 | 显示上下文 | 推荐显示项 | 数据源 |
| --- | --- | --- | --- |
| `STATE_RUNUPING` / `STATE_RUNDOWNING` | 运动调试 | 位置、扭力、电机状态 | `debug_data` |
| `STATE_RUNUPOVER` / `STATE_RUNDOWNOVER` | 运动调试 | 位置 | `debug_data.sensor_position` |
| `STATE_RUN_TO_POSITIONING` / `STATE_RUN_TO_POSITION_OVER` | 运动调试 | 位置 | `debug_data.sensor_position` |
| `STATE_FORCE_RUNUPING` / `STATE_FORCE_RUNDOWNING` | 运动调试 | 位置、扭力、电机状态 | `debug_data` |
| `STATE_FORCE_RUNUP_OVER` / `STATE_FORCE_RUNDOWN_OVER` | 运动调试 | 位置 | `debug_data.sensor_position` |
| `STATE_MAINTENANCEMODE` / `STATE_DEBUG_MODE` | 维护调试 | 位置、扭力、传感器原始值 | `debug_data` |

说明：

- 这类状态不应显示液位、水位、密度等业务结果，除非现场明确要求显示“最近一次结果”。
- 如需显示最近业务结果，建议加来源标签，避免误认成当前运动结果。

### 5.8 扭力类

| 状态 | 显示上下文 | 推荐显示项 | 数据源 |
| --- | --- | --- | --- |
| `STATE_GET_FULLWEIGHT` / `STATE_GET_EMPTYWEIGHT` | 扭力 | 扭力、位置 | `debug_data.current_weight`、`debug_data.sensor_position` |
| `STATE_GET_FULLWEIGHT_OVER` / `STATE_GET_EMPTYWEIGHT_OVER` | 扭力完成 | 扭力 | `debug_data.current_weight` |

有效性规则：

- `debug_data.current_weight > 0` 时显示扭力。
- 如现场存在 0 扭力合法场景，需要后续补充有效标志，不能继续用 `> 0` 判断。

### 5.9 故障类

| 状态 | 显示上下文 | 推荐显示项 | 数据源 |
| --- | --- | --- | --- |
| `STATE_ERROR` | 故障 | 故障码、故障原因 | `device_status.error_code` |

说明：

- 故障态首屏优先显示故障码和故障原因。
- 不建议自动混入旧测量值。
- 如果后续需要显示故障发生前的最后测量值，应新增 CPU3 本地缓存和来源标签。

### 5.10 待机类

| 状态 | 显示上下文 | 推荐显示项 | 数据源 |
| --- | --- | --- | --- |
| `STATE_STANDBY` | 无当前测量 | 最近一次有效结果摘要或空闲状态 | CPU3 本地最近结果缓存 |
| `STATE_INIT` | 初始化 | 通讯/初始化状态 | 状态文本 |

待机态建议：

- 第一阶段可以不新增最近结果缓存，只显示状态和少量稳定过程量。
- 第二阶段再增加 `last_result_context`，完成态时缓存最近业务结果，待机态按缓存显示，并增加“最近”或来源标签。

## 6. 推荐显示优先级

OLED 只有 4 行，第一行通常为设备状态。剩余行建议按以下优先级分配：

1. 故障态：故障原因优先，其它测量值隐藏。
2. 完成态：最终业务结果优先，例如液位、水位、平均密度、罐高。
3. 运行态：过程量优先，例如位置、频率、电容、扭力、角度。
4. 调试/维护态：位置、扭力、电机状态、原始传感器值优先。
5. 待机态：最近结果摘要需有来源标签；没有缓存时只显示待机。

## 7. 实施计划

### 阶段 1：显示上下文重构

目标：不改变显示文案，先集中状态判断。

任务：

1. 在 `display.c` 内新增 `DisplayResultContext` 枚举。
2. 新增 `Display_GetResultContext(DeviceState state)`。
3. 把 `IsOilLevelSensorState()`、`IsWaterLevelSensorState()`、`IsRealHeightDisplayState()` 逐步替换为上下文判断。
4. 保留现有分页结构，降低一次性改动风险。

验收：

- 各状态可以在一个函数中看到完整归类。
- 无重复散落的状态列表。

### 阶段 2：密度和温度数据源修正

目标：密度/温度按状态选源。

任务：

1. 新增 `Display_GetDensityValue()`。
2. 新增 `Display_GetTemperatureValue()`。
3. 单点测量态使用 `single_point_measurement`。
4. 单点监测态使用 `single_point_monitoring`。
5. 分布测量态使用 `density_distribution.average_density` 和 `density_distribution.average_temperature`。
6. 同步修改 `CalculateValidPara()` 和 `oled_equipment()`。

验收：

- `STATE_SINGLEPOINTOVER` 不再显示 `single_point_monitoring`。
- 分布完成态不再显示单点监测密度。
- 无效密度、无效温度不会显示。

### 阶段 3：液位和水位显示条件修正

目标：液位/水位按状态显示，避免旧值误显示。

任务：

1. 新增 `Display_ShouldShowOilLevel()`。
2. 新增 `Display_ShouldShowWaterLevel()`。
3. `STATE_FINDOILOVER`、`STATE_FLOWOIL`、综合完成态纳入液位显示。
4. `STATE_FINDWATER_OVER`、`STATE_FOLLOW_WATERING`、`STATE_CALIBRATE_WATER_OVER` 纳入水位显示。
5. 非相关状态隐藏旧液位/水位值。

验收：

- 液位完成态显示液位结果。
- 水位完成态显示水位结果。
- 运动控制和维护状态不再显示旧液位/水位。

### 阶段 4：传感器过程量和罐高显示整理

目标：过程量只在对应过程显示。

任务：

1. 频率只在液位过程/跟随状态显示。
2. 电容只在水位过程/跟随状态显示。
3. 罐高只在罐底/罐高完成态显示。
4. 角度继续受 `bottom_detect_mode` 控制。
5. 位置、扭力按运行态和调试态显示。

验收：

- 液位过程显示频率，不显示水位电容。
- 水位过程显示电容，不显示液位频率。
- 非罐高完成态不显示罐高旧值。

### 阶段 5：待机态最近结果缓存评估

目标：决定是否在待机态保留最近业务结果。

建议先不做或单独开需求，原因：

- 需要明确“最近结果”的生命周期。
- 需要定义结果来源标签。
- 需要处理故障、取消测量、重启、通讯中断后的缓存清除策略。

如后续实施，建议新增 CPU3 本地结构：

```c
typedef struct {
    DisplayResultContext context;
    uint32_t oil_level;
    uint32_t water_level;
    uint32_t density;
    uint32_t temperature;
    uint32_t position;
    uint32_t point_count;
    uint8_t valid;
} DisplayLastResult;
```

完成态刷新缓存，运行态不覆盖最终结果，故障态不覆盖结果但可记录错误码。

## 8. 版本和兼容性影响

本需求属于 CPU3 显示行为调整。

预计影响：

- 需要升级 CPU3 固件版本。
- 不改变 CPU2/CPU3 共享寄存器结构。
- 不改变 `DEVICE_PROTOCOL_VERSION`。
- 不改变外部 DSM、Wartsila、SI协议寄存器。

如果后续为待机态新增跨 CPU 结果来源标志或有效标志，则需要重新评估协议版本。

## 9. 字库和编码注意事项

第一阶段建议复用现有显示文案，避免新增字库工作。

如果新增以下中文文案，需要检查 `StockMap`、`WordStock`、`WordStock2` 是否覆盖：

- “平均”
- “点数”
- “最近”
- “无效”
- “来源”
- “监测”

修改 `display.c` 前必须确认文件编码，按现有源码编码写回，避免中文乱码。

## 10. 测试计划

### 10.1 静态检查

1. 检查 `Display_GetResultContext()` 覆盖所有 `DeviceState` 枚举值。
2. 检查密度、温度、液位、水位、罐高显示都通过统一数据源函数。
3. 检查 `CalculateValidPara()` 和 `oled_equipment()` 使用同一套上下文，不再各自维护状态判断。

### 10.2 构建验证

执行 CPU3 构建：

```powershell
cmake --build build\LTD_DISPLAY_CPU3
```

如涉及共享头文件或 CPU2 状态枚举同步，再执行 CPU2 构建：

```powershell
cmake --build build\LTD_MAIN_CPU2
```

### 10.3 手工状态验证

建议至少覆盖以下状态：

| 场景 | 期望 |
| --- | --- |
| 液位测量完成 | 显示液位，不显示旧单点监测密度 |
| 液位跟随中 | 显示液位和频率 |
| 水位测量完成 | 显示水位，不显示旧液位频率 |
| 水位跟随中 | 显示水位和电容 |
| 单点测量完成 | 显示 `single_point_measurement` 的密度、温度、位置 |
| 单点监测 | 显示 `single_point_monitoring` 的密度、温度、位置 |
| 分布测量完成 | 显示平均密度、平均温度、点数、液位 |
| 罐高测量完成 | 显示罐高，按配置显示角度 |
| 强制上/下行 | 显示位置、扭力或电机状态，不显示旧测量结果 |
| 故障态 | 优先显示故障码和故障原因 |
| 通讯异常 | 保持原有通讯尝试或初次上电提示逻辑 |

### 10.4 回归关注点

- 分页页数是否正确。
- 只有两行内容时，状态行和结果行是否仍居中/错行可接受。
- 中英文显示是否都能显示完整。
- `低于盲区` 文案是否仍能正确显示。
- 分布测量点读取逻辑不受显示修改影响。

## 11. 待确认问题

1. 水位完成但 `water_level == LEVEL_DOWNLIMITWATER` 时，现场希望显示“低于盲区”、隐藏水位，还是显示“无有效水位”？
2. 待机态是否需要显示最近一次测量结果？如果需要，是否接受新增“最近”或来源标签？
3. 综合测量完成态中，液位、水位、密度、温度的显示优先级如何排序？
4. 分布测量完成态是否需要显示点数？如果 OLED 行数不足，点数是否低于平均密度/温度优先级？
5. 运动控制完成态是否只显示位置，还是也显示最后扭力？

## 12. 建议结论

建议先实施阶段 1 到阶段 4，解决当前“不相关旧值误显示”的核心问题；待机态最近结果缓存单独作为后续增强项处理。

本次优化的关键不是新增显示内容，而是让 CPU3 状态页的每一个数值都有明确来源和状态语义。完成后，现场人员看到的结果应满足：

- 当前测量状态下，只显示当前任务相关值。
- 测量完成状态下，显示对应任务的最终结果。
- 调试或运动状态下，不把历史业务结果伪装成当前结果。
- 故障状态下，优先给出故障原因。
