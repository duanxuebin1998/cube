# 近期固件工作计划

本文用于梳理下一阶段 CPU2/CPU3 固件工作，重点围绕中断耗时、UART6 可靠性、科学仪器协议、测量点位、故障恢复、版本兼容和显示端错误信息展开。

## 一、总体目标

1. 降低中断路径耗时，避免 UART5/通信中断内阻塞打印影响 UART6、TMC5130 和测量流程。
2. 提高 UART6 DSM 通信鲁棒性，避免短帧、错帧或格式异常帧被解析为有效测量值。
3. 完成科学仪器协议及密度分布 200 点测量相关改造。
4. 故障自动恢复已接入可配置参数，后续重点做现场回归和异常注入验证。
5. 建立 CPU2/CPU3 版本匹配、错误原因显示和错误信息整理闭环。
6. 将状态切换、电机 24V 断电初始化异常等现场问题纳入明确错误处理。

## 二、实施阶段

### 阶段 1：中断时间控制与 UART6 风险收敛

- [ ] 排查中断路径内的 `printf`、`ErrorLog_*` 和其他可能阻塞的串口输出。
  - 重点检查 UART5/Modbus 接收、CRC 错误帧、0x10 写寄存器、HAL UART 回调、定时器回调。
  - ISR 内只记录轻量状态、计数器或延后日志事件，不直接打印。
- [ ] 将中断路径错误信息改为主循环延后输出。
  - 增加必要的错误计数、最近一次错误码、最近一次帧摘要。
  - 主循环或非中断上下文统一消费并打印。
- [ ] 补充 UART6 异常原因分类。
  - 区分超时、短帧、BCC 错误、格式错误、设备返回错误、硬件 ORE/FE/NE/PE。
  - 避免只打印笼统的“通信失败，重试 x/3”。
- [ ] 加强 UART6 DSM 帧格式校验。
  - 校验帧头/帧尾、长度、命令回显、地址或通道字段、ASCII 数字格式、小数点位置、BCC。
  - 对液位频率增加合理范围检查。
  - 校验失败时返回明确错误码，不更新液位频率、液位状态和测量状态。
- [ ] 评估 UART6 DMA/IDLE 或中断环形缓冲接收方案。
  - 短期方案：保持现有轮询接收，但补齐格式校验和错误分类。
  - 中期方案：USART6 使用 DMA + IDLE，主循环解析完整帧。
  - 备选方案：USART6 使用 RXNE 中断写入环形缓冲，主循环按协议取帧。
  - 需要确认 CubeMX 配置、DMA 资源占用、现有 UART6 初始化和错误回调兼容性。

### 阶段 2：科学仪器协议与密度分布测量

- [ ] 梳理科学仪器协议需求。
  - 明确协议帧格式、寄存器/命令编号、数据类型、单位、缩放倍率和兼容性。
  - 明确 CPU2 与 CPU3、上位机、显示端之间的数据边界。
- [ ] 将密度分布测量点位增加到 200 个点。
  - 排查当前点位上限、数组容量、参数存储、通信寄存器、显示缓存和导出逻辑。
  - 修改常量时同步检查 CPU2/CPU3 共用结构、Modbus 映射和 FRAM/EEPROM 存储空间。
  - 确认 200 点传输耗时、显示分页、历史数据覆盖策略和异常中断处理。
- [ ] 补充 200 点测量验证用例。
  - 覆盖 0 点、1 点、边界点、200 点、超过 200 点、测量中断、通信读取分页。

### 阶段 3：故障自动恢复与状态切换错误化

- [x] 为故障自动恢复增加变量控制。
  - 已落地运行时参数 `fault_auto_recovery_retry_limit`。
  - 来源：CPU3 参数菜单“故障自动恢复重跑次数”、内部 Modbus 参数和 CPU2 参数存储默认值。
  - 范围：`0` 关闭自动恢复重跑，`1~10` 为恢复确认成功后的原命令最多自动重跑次数，默认 `3`。
- [ ] 保持恢复期间原始错误状态。
  - 自动恢复检查期间不覆盖原错误码。
  - 恢复成功后再清除错误状态并重启失败前的完整测量命令。
- [ ] 将状态切换处理为错误。
  - 对测量中命令切换、状态机非法跳转、模式切换失败建立统一错误码和日志。
  - 错误出口统一交给 `fault_manager` 或现有最终报错路径。
- [ ] 梳理错误信息。
  - 统一错误码名称、原因、处理建议、CPU3 显示文本和串口日志字段。
  - 检查 `ErrorLog_GetCodeName()` 和 `ErrorLog_GetReasonByCode()` 覆盖完整性。
  - 更新故障代码表和错误日志整理文档。

### 阶段 4：CPU2/CPU3 版本匹配与 CPU3 错误显示

- [ ] 完善 CPU2/CPU3 版本匹配机制。
  - 使用明确的兼容宏或协议能力字段，例如协议 major/minor、必需版本、支持能力位。
  - CPU3 读取 CPU2 版本或能力信息，不匹配时给出清晰提示。
- [ ] CPU3 显示错误原因。
  - CPU2 提供错误码、错误阶段、错误原因或可显示原因索引。
  - CPU3 根据错误码映射显示中文原因，避免只显示泛化错误。
  - 对版本不匹配、通信异常、状态切换、电机 24V 异常等重点错误补齐显示文本。
- [ ] 同步版本升级规则。
  - 影响 CPU2/CPU3 通信、显示字段、协议寄存器或数据结构时，两边版本同步升级。
  - 提交前更新 `CHANGELOG.md`，说明兼容性、修改内容和验证结果。

### 阶段 5：电机 24V 断电初始化异常

- [ ] 复现并界定异常现象。
  - 明确 24V 断电时 TMC5130 读写返回、GSTAT/DRV_STATUS 状态、初始化阶段返回码。
  - 区分通信失败、驱动欠压、电荷泵欠压、初始化写入失败和位置源异常。
- [ ] 初始化流程增加明确错误处理。
  - 24V 未就绪时不要继续执行依赖驱动电源的初始化步骤。
  - 返回可识别错误码，并在 CPU3 显示具体原因。
  - 恢复 24V 后按自动恢复策略或人工复位策略重新初始化。
- [ ] 检查电机停止和安全边界。
  - 异常期间禁止启动运动命令。
  - 恢复后确认位置、驱动状态和错误码清除条件。

## 三、建议优先级

1. P0：移除中断路径阻塞打印，补 UART6 错误原因分类。
2. P0：加强 UART6 DSM 帧格式校验，防止异常帧污染测量状态。
3. P1：状态切换错误化、故障自动恢复变量现场回归。
4. P1：CPU2/CPU3 版本匹配和 CPU3 错误原因显示。
5. P1：电机 24V 断电初始化异常处理。
6. P2：科学仪器协议与密度分布 200 点。
7. P2：UART6 DMA/IDLE 或中断环形缓冲接收改造。

## 四、验证计划

- [ ] 静态检查
  - 搜索 ISR、HAL 回调和 Modbus 回调内是否仍存在阻塞打印。
  - 搜索新增错误码是否完整映射到名称、原因和 CPU3 显示文本。
- [ ] 单模块验证
  - UART6 正常帧、短帧、BCC 错帧、格式错帧、超时帧。
  - 故障自动恢复重跑次数参数 `0/1/3/>10`、恢复成功、持续失败、命令切换打断。
  - 24V 断电、恢复供电、初始化重试。
- [ ] 联调验证
  - CPU3 高频轮询下 UART6 通信稳定性。
  - 密度分布 200 点采集、显示、读取和边界处理。
  - CPU2/CPU3 版本匹配、版本不匹配提示和错误原因显示。
- [ ] 构建验证
  - CPU2：`cmake --build build\LTD_MAIN_CPU2`
  - CPU3：`cmake --build build\LTD_DISPLAY_CPU3`
  - 版本相关改动提交前运行：`py tools\check_version_bumped.py`

## 五、待确认事项

- 科学仪器协议的最终帧格式、寄存器分配和兼容策略。
- 密度分布 200 点是否需要兼容旧上位机或旧 CPU3。
- 故障自动恢复是否还需要增加恢复最长等待时间或按错误类型拆分策略。
- UART6 接收改造采用 DMA + IDLE 还是 RXNE 中断环形缓冲。
- 24V 断电后恢复策略是自动重新初始化，还是要求人工确认后恢复。
