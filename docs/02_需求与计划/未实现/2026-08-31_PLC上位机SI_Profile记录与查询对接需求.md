# PLC上位机SI Profile记录与查询对接需求

日期：2026-08-31

对象：PLC程序开发人员

状态：需求已确认，待PLC侧实现

## 1. 背景

当前PLC程序已经能够通过SI Modbus协议读取设备数据。本次不修改现有通信协议和基础读取功能，只在现有PLC程序上增加Profile测量记录、历史查询和导出功能。

Profile既可能由PLC发起，也可能由下位机屏幕或设备自动调度发起。PLC必须根据设备实际状态识别测量开始和结束，不能只记录由PLC自己下发的测量。

## 2. 本次开发范围

### 2.1 需要增加

- 自动识别一次新的Profile测量。
- Profile完整结束后读取本次全部测点。
- 每次完整Profile生成一条历史记录。
- 提供历史记录列表和条件查询。
- 提供单条记录详情、曲线、点位表格和导出。
- 记录长期保存，不自动删除。

### 2.2 不需要修改

- 不修改现有SI Modbus通信参数和寄存器地址。
- 不修改下位机Profile测量流程。
- 不区分Profile由PLC、下位机屏幕还是自动调度发起。
- 不补录PLC启动或重新连接之前已经完成的Profile。
- 取消、失败或数据未完整读出的Profile不生成成功测量记录。

## 3. 已确认需求

1. 只保存完整成功的Profile。
2. 不记录、不显示Profile发起来源。
3. PLC启动或重新连接后不补录旧结果。
4. PLC必须先在线识别到本轮测量开始，再识别到本轮测量结束，之后才读取并保存。
5. 一轮测量只执行一次结果归档，只生成一条记录。
6. Profile概要、全部有效测点、状态和报警全部保存。
7. 历史记录一直保存，不按时间或条数自动清理。
8. 支持历史列表、组合查询、详情查看、曲线和数据导出。

## 4. PLC需要监视的数据

PLC可继续使用当前已经实现的读取方式。Profile记录逻辑至少需要以下数据：

| 数据 | SI地址 | 用途 |
| --- | --- | --- |
| Profile状态 | `00004`，也可使用`30014`中的对应镜像位 | 判断是否进入或退出Profile |
| Profile完成 | `10005`，也可使用`30015`中的对应镜像位 | 判断本轮是否完整完成 |
| 探头已回液位 | `10013`，也可使用`30015`中的对应镜像位 | 判断最终结果已经发布 |
| 有效点数N | `30006` | 确定本轮需要读取和保存的测点数量 |
| Profile时间 | `30007~30010` | 保存设备给出的Profile月、日、时、分 |
| 状态和报警 | `30014~30016`或对应FC01/FC02数据 | 保存本轮完成时状态和报警 |
| Profile点阵 | `30021~30620` | 最多200点，每点为位置、温度、密度3个寄存器 |

建议PLC继续周期读取`30001~30020`，用于同时取得实时值、点数、时间和状态镜像。

## 5. Profile记录逻辑

### 5.1 等待测量开始

PLC程序启动或通信连接成功后，先建立当前状态基线。

- PLC必须先正常读到`Profile=0`。
- 之后检测到`Profile=1`，建立一条“正在测量”的临时会话。
- 无论本轮由PLC还是下位机发起，都执行相同处理。
- PLC启动或重新连接后，如果第一次读到的就是`Profile=1`或旧的`Complete=1`，不建立记录、不补录。

### 5.2 确认本轮已经开始采点

Profile刚进入时，`Complete`、点数和时间可能仍是上一轮结果，不能立即当成本轮数据。

只有看到以下状态后，才确认本轮已经开始采点：

- `Profile=1`；
- `Complete=0`；
- `N>=1`。

如果还没有出现以上组合，Profile就退出，则本轮不生成成功记录。

### 5.3 判断本轮完整结束

已经确认开始采点后，同时满足以下条件，才认为本轮Profile完整结束：

- `Profile=0`；
- `Complete=1`；
- `AtLevel=1`；
- `N`在`1~200`范围内。

不满足完整结束条件时，不读取点阵、不生成成功记录。

### 5.4 读取并保存一次

识别到完整结束后，执行一次结果归档：

1. 锁存最终点数N、Profile时间、状态和报警。
2. 从`30021`开始读取前N个测点，每点读取位置、温度和密度。
3. 受单次Modbus读取数量限制时，可以分块读取；这些分块属于同一次结果归档，不是重复记录。
4. 确认实际读到N个完整测点后，一次性保存主记录和全部测点。
5. 保存成功后立即关闭本轮临时会话，返回等待下一轮开始。
6. 即使`Complete=1`保持多个PLC扫描周期，也不能再次读取或再次保存。

不需要额外计算点阵指纹。使用“当前会话已保存”标志即可保证一轮只保存一次。

## 6. 异常处理

- Point0前取消：不保存，不能把上一轮的Complete、点数和时间保存为新记录。
- 采点后取消或失败：不生成成功记录。
- 单次轮询失败：按现有通信策略重试，不立即创建或结束会话。
- 通信被判定为断开：放弃当前未保存会话；重新连接后重新建立基线，不补录。
- 点阵未读全：不保存半条记录，允许在当前最终完成状态下重试读取。
- 存储失败：显示或记录保存失败，不得显示为已成功归档。
- PLC程序重启：清除未完成会话，重启后不补录旧结果。

## 7. 保存内容

### 7.1 Profile主记录

每条记录至少保存：

- 记录编号；
- 设备名称或设备编号；
- Modbus站号；
- PLC识别到的测量开始时间；
- PLC识别到的测量完成时间；
- 设备Profile时间`30007~30010`；
- 有效点数N；
- 完成时`30001~30020`全部数据；
- 完成时Profile、Auto、Complete、AtLevel、Interlock状态；
- 完成时全部报警状态。

### 7.2 Profile测点

前N个有效测点全部保存，每点至少包含：

- 点序号；
- 位置原始值和工程值，单位mm；
- 温度原始值和工程值，单位摄氏度；
- 密度原始值和工程值，单位`kg/m3`；
- 数据是否有效。

温度`0xB1E0`按无效温度保存；密度0按当前SI协议的无效密度保存。无效值需要保留原始值并标记无效，不能直接删除该测点。

## 8. 历史查询功能

### 8.1 历史列表

列表至少显示：

- 测量完成时间；
- 设备或站号；
- 有效点数；
- 是否存在报警；
- 查看详情和导出操作。

历史记录默认按完成时间倒序显示，并采用分页方式加载。

### 8.2 查询条件

至少支持以下条件组合查询：

- 开始日期和结束日期；
- 设备或Modbus站号；
- 是否存在报警；
- 点数范围；
- 记录编号。

### 8.3 记录详情

详情页至少显示：

- 本次Profile概要和状态；
- 全部点位表格；
- 位置—温度曲线；
- 位置—密度曲线；
- 全部报警状态；
- 导出功能。

详情页只用于查看历史数据，不提供启动、停止或参数写入操作。

### 8.4 导出

- 支持导出单条Profile的概要和全部点位。
- 支持CSV；现有系统方便时可同时支持XLSX。
- 导出内容必须包含设备、时间、点序号、单位、原始值、工程值和有效性。

## 9. 数据保存要求

- 历史记录一直保存，不自动删除。
- 一条主记录和N个测点必须作为一个整体保存，不能出现只有概要没有点位的记录。
- 存储空间不足时必须产生明确提示，不得静默覆盖旧记录。
- PLC同事需要根据实际PLC/HMI/上位机的存储介质，确认数据库或历史存储位置、可用容量和备份方式。
- 如果PLC本体不适合长期保存大量点阵，应把记录存放在配套HMI、工控机或已有历史数据库中，但功能和查询入口仍按本需求实现。

## 11. PLC同事需要反馈的信息

开发前请PLC同事反馈以下信息，用于确定具体实现方式：

1. 当前PLC/HMI型号、开发平台和程序版本。
2. 当前SI轮询周期和单次允许读取的最大寄存器数量。
3. 历史数据计划保存到PLC、HMI、工控机还是现有数据库。
4. 可用存储容量、备份方式和容量不足时的处理方式。
5. 当前系统是否已有历史查询、分页、曲线和CSV/XLSX导出组件可复用。
6. 实际接入设备数量、各设备站号和预计Profile执行频率。

以上信息只影响PLC侧实现方案，不改变本需求已经确认的记录和查询规则。
