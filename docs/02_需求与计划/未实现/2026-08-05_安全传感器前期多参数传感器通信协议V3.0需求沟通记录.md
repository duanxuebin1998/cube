# 安全传感器前期多参数传感器通信协议 V3.0 需求沟通记录

更新时间：2026-08-05

这份文档先用于和传感器部门沟通需求，后续有新的要求继续往这里补。

## 当前怎么做

安全协议先不接，先以现有的多参数传感器通信协议 V3.0为基础增加需要的数据，做出一版可以联调和测试的程序。V3.0是当前LTD传感器使用的协议版本；LTD是传感器类型，不作为协议名称。

这版传感器程序要使用新的版本号，和以前的程序区分开。具体增加哪些寄存器、数据格式怎么定，双方确认后再固化到协议里。

## 现有代码实际用到的内容

根据当前 CPU2 代码，LTD 传感器正常使用过程中实际会用到下面这些命令和寄存器：

| 命令或寄存器 | 当前含义 | 当前用途 |
| --- | --- | --- |
| `D` | 切换密度模式 | 测密度、温度和密度通道频率前使用 |
| `T` | 切换液位模式 | 找液位、读取空气或液体频率前使用 |
| `R04` | 液位频率，整数，单位 Hz | 液位模式下读取频率；当前程序把 0 或大于 6500 Hz 判断为异常 |
| `R06` | 温度，浮点数 | 密度测量和读取部件参数时使用 |
| `R07` | 密度，浮点数 | 密度测量和读取部件参数时使用 |
| `R17` | 45°通道周期平方均值，浮点数 | 当前程序用它换算密度通道主频率 |
| `R18` | 22.5°通道周期平方均值，浮点数 | 作为第二路振动数据读取和检查 |
| `R22` | 传感器编号，整数 | 上电识别 LTD 传感器时使用 |

当前正常业务不读取也不写入 `R20～R114` 的密度标定参数。作为传感器使用方，我们只需要测量结果和状态，不需要通过协议读取或修改密度标定数据。

动力黏度 `R08`、运动黏度 `R09` 目前只在测试代码中出现，也不列入这次正常使用需求。

## 新版需要增加或确认的内容

在保留上面现有用法的基础上，新版还需要增加或确认以下数据：

- 软件版本：现有协议中是 `R00`，新版程序必须使用新的版本号，并保证可以稳定读取；
- 磁零点电压：现有协议中有 `R03` 零点电压，需要确认它是不是这里需要的磁零点电压，并明确单位；
- X、Y 方向角度；
- 电压检测值：需要确认具体检测的是哪一路电压；
- 水位电容值：需要返回电容值，不是原来的水位电压；
- 密度、温度和频率是否有效，以及数据是否还在更新。

寄存器地址可以由传感器部门安排，但不要改变 `R04、R06、R07、R17、R18、R22` 现有含义。如果确实需要调整，提前列出新旧对应关系。

### X、Y 角度

板上使用的是 ADXL345。它输出三轴加速度，X、Y 倾角由传感器程序根据重力方向计算，计量仪侧直接读取角度结果。

这里需要先确认几件事：

- 传感器水平放置时，X、Y 角都为 0°；
- X、Y 轴在结构上的方向和正负方向；
- 能做到的角度精度和刷新时间；
- 传感器运动或振动较大、角度暂时不可信时，要有有效/无效状态，不能直接把 0° 当作正常结果。

具体算法可以由传感器程序内部处理，但双方对坐标方向、零点和角度单位的定义必须一致。

## 驱动方式和模式

现在先比较数字驱动和模拟驱动两种方案，最终用哪一种根据测试结果确定。

### 1. 数字驱动

如果继续使用数字驱动，需要保留单独的液位模式。

液位模式的扫频范围要同时覆盖空气频率和液体频率。从探头进入空气或液体，到能够读到新的有效频率，最大响应时间要求小于 2 秒。

目前试过密度模式，正常大约需要 10 秒，最慢测到过 18 秒才变化，不能满足找液位时的响应要求。

### 2. 模拟驱动

如果模拟驱动能够稳定使用，可以考虑只保留一个模式，不再区分密度模式和液位模式。探头在空气中返回空气频率，在液体中返回液体频率。

模拟驱动能不能使用，主要看异常高频问题能不能解决。这个问题没有确认前，暂时不能直接定模拟方案。

驱动方式切换接口先保留，方便两种方案对比测试。

## 之前遇到的问题

下面几个问题测试时需要重点关注：

1. 模拟传感器出现过 16 kHz～20 kHz 以上的异常高频，重新上电后也有概率继续高频。这个问题影响比较大，需要说明原因以及怎么判断和处理。
2. 数字传感器的液位模式出现过异常退出，退出后频率不再变化。
3. 数字传感器进入液体后，频率有时会卡在液体频率，之后不再更新。
4. 探头在液面附近时，出现过密度为 0、频率扫不到的情况。稍微移动后又能扫到，但在某个位置可能一直扫不到。

以上问题除了看最终数值，还要关注程序是否仍在正常扫频、当前是什么模式、数据有没有继续更新。

## 希望增加的状态

为了让计量仪能够判断当前数据是不是正常的，希望增加以下状态：

- 密度有效标志：说明当前密度能不能使用；
- 密度更新计数：每得到一次新的密度结果加 1；
- 频率有效标志或频率更新计数：用于判断频率是否还在刷新；
- 当前模式和扫频状态：如果实现方便，希望可以读取。

更新计数应该在传感器真正得到新结果时变化，主机读取一次寄存器不能算一次更新。没有测到结果时，也不要只返回 0，最好同时给出无效状态。

## 这次需要传感器部门回复的内容

| 项目 | 需要回复 |
| --- | --- |
| 现有寄存器 | `R04、R06、R07、R17、R18、R22` 的含义和数据格式是否保持不变 |
| 新增数据 | 软件版本、磁零点电压、X/Y角度、电压检测值、水位电容分别使用哪个寄存器、什么单位 |
| 数字驱动 | 液位模式能否稳定保留，空气和液体频率能否都在 2 秒内测到 |
| 模拟驱动 | 异常高频的原因、处理办法和当前试验结果 |
| 角度 | ADXL345 的坐标方向、零点、精度、刷新时间和无效状态怎么定义 |
| 状态信息 | 密度有效、密度更新、频率更新、当前模式和扫频状态哪些可以增加 |
| 已知问题 | 模式退出、频率卡死、液面附近扫不到等问题准备怎么验证和处理 |
| 程序版本 | 新版本号怎么定，什么时候可以提供联调版本 |

回复时可以直接标注“可以实现”“需要进一步沟通”或者“暂时不能实现”，有不确定的地方再单独讨论。

## 后续方向

后面正式做安全协议时，方向上考虑由传感器主动上发数据，不再区分密度模式和液位模式。Wartsila、SI 和均友目前也是传感器单向发送数据。

这一部分先作为后续方向记录，本次仍以多参数传感器通信协议 V3.0联调为主。
