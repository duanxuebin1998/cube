3.1 Wartsila 读写保持寄存器

Wartsila 只支持 0x03 和 0x10。读前把设备参数/测量值刷到 g_holding_regs，写后解析寄存器并下发 CPU2。

Wartsila 顶层wartsila_modbus_communication.c:151-207 modbus_rtu_process 校验地址/CRC，处理 0x03/0x10。
写后回调wartsila_modbus_communication.c:211-247 modbus_on_holding_written 将写入解析为命令或参数下发。
参数转发wartsila_modbus_communication.c:249-272 ForwardParamsToLowerDevice 只转发瓦锡兰密度区间相关参数。

3.2 SI7000 快照同步与功能码处理

SI7000 在地址和 CRC 通过后才刷新 CPU3 快照，读写函数码都会生成正常或异常响应；分发层只要有响应帧就视为成功。

快照刷新si7000_modbus_slave.c:997-1012 si7000_modbus_sync_from_system 汇总刷新四类数组。
处理入口si7000_modbus_slave.c:1016-1080 地址/CRC 通过后才同步系统状态并按功能码处理。
分发表适配si7000_modbus_slave.c:1083-1096 只要已生成响应帧，COM 分发层就按成功处理并发送。

4. 问题点与优化建议

1. Wartsila 0x10 字节数校验疑似错误

handle_0x10 中检查 bytes != qty，但后续又用 pdu_len == 6 + 2*bytes，并按 2*i 取数据；标准 Modbus 的 byteCount 应为 qty*2。

建议：确认现场 Wartsila 协议是否非标；如果不是非标，应改为 bytes == qty*2 并补充测试帧。

wartsila_modbus_communication.c:102-113

2. Wartsila 参数转发范围很窄

非 0x0006 写入只转发 4 个密度区间参数，其他写入会解析到 g_deviceParams 但不一定同步 CPU2。

建议：列出 Wartsila 可写寄存器清单，逐项确认是否需要下发 CPU2。

wartsila_modbus_communication.c:249-272

3. SI7000 写操作是否同步 CPU2 需要单独核对

SI7000 写单线圈/单寄存器在模块内处理，页面证据显示主入口负责快照和响应，写后对 CPU2 的影响需要按具体 handler 继续核对。

建议：把 SI7000 05/06 的业务动作整理成协议表，区分只改本地快照、下发 CPU2、占位回显三类。

si7000_modbus_slave.c:1016-1080

4. Wartsila 特殊地址 0x0672 返回固定版本字符串

0x0672 读取固定返回一段版本文本，不走寄存器池，后续版本变化时容易遗漏同步。

建议：把固定字符串集中成宏或从版本定义生成。

wartsila_modbus_communication.c:55-76
