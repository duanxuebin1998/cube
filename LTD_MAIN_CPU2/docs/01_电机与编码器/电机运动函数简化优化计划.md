# 电机运动函数简化优化计划

更新日期：2026-06-12

## 1. 背景

当前 CPU2 电机控制代码集中在 `LTD_MAIN_CPU2/Services/MotorControl/motor_ctrl_motion_api.c`。该文件同时承载正式距离运动、绝对位置运动、ticks 运动、Jog 点动、强制无检测运动、停机等待、速度刷新、位置快照、丢步检查和错误收尾逻辑。

从当前源码看，安全边界比较完整，但多个函数重复维护以下流程：

- 临时速度切换和恢复。
- 命令切换停机检查。
- TMC5130 位置/速度刷新。
- 驱动通信、配置和 24V 功率级健康检查。
- 主动位置源快照和位置范围校验。
- 运动结束时清理显示状态、同步位置和恢复速度。

本计划覆盖从第一轮无行为结构重构，到后续等待状态机收敛、运动策略评估、台架验证、文档同步和发布准备的完整路线。第一轮目标是先做结构简化，减少重复代码和误导性分支，不改变电机运动策略；后续轮次必须在前一轮验证通过后再展开。

## 3. 优化目标

### 3.1 必须保持不变

- 不改变电机方向宏语义。
- 不改变 `speed_x100`、`cable_length`、`sensor_position`、`XACTUAL`、`XTARGET` 等单位口径。
- 不改变正式运动、Jog 运动、强制无检测运动的对外函数签名。
- 不改变命令切换返回值和停机语义。
- 不降低运动前门控、驱动健康检查、撞底检测、丢步检测和位置源检查强度。
- 不主动升级 CPU2 固件版本。

### 3.2 允许优化

- 抽取只服务本文件的 `static` helper。
- 删除不可达或误导性的重试分支。
- 合并重复的速度恢复和错误返回代码。
- 复用已有主动位置源快照和位置合法性校验 helper。
- 让函数职责更清晰：入口函数负责参数和业务语义，内部 helper 负责等待、收尾和公共检查。

## 5. 函数分组与简化方向

| 分组 | 函数 | 当前问题 | 优化方向 |
| --- | --- | --- | --- |
| 正式距离运动 | `MotorCtrl_MoveAndWait()` | 临时速度收尾重复；`attempt` 重试框架基本不可达；位置快照直接读全局值 | 删除误导性重试分支；复用速度收尾 helper；按当前有效位置源刷新位置 |
| ticks 运动 | `MotorCtrl_MoveByTicksAndWait()` | 下发前后诊断、等待启动、等待到位和速度恢复混在一个长函数 | 抽取启动变化确认、ticks 到位等待、速度 scope 收尾 |
| 绝对位置运动 | `MotorCtrl_MoveToPosition()` | 自己实现位置范围保护；分段调用 `MoveAndWait()` 时双层速度 scope | 复用主动位置快照 helper；评估是否保留外层速度 scope，避免重复恢复 |
| Jog 相对/绝对入口 | `MotorCtrl_JogMoveAndWait()`、`MotorCtrl_JogMoveToPosition()` | 入口已较清晰，但前置门控和快照逻辑重复 | 抽取公共入口准备函数，不改变 Jog 策略 |
| 目标规划 | `MotorMotionTargetPlan`、`MotorMotion_BuildRelativeTargetPlan()`、`MotorMotion_BuildAbsoluteTargetPlan()` | 正式位置模式和 Jog 点动模式重复计算方向、距离、目标范围和到位状态 | 统一目标规划，保留位置目标执行和速度点动执行两套策略 |
| 运行前门控和启动观察 | `MotorMotion_CheckReadyForProtectedMotion()`、`MotorMotion_CheckCommandAbortWithSpeedScope()`、`MotorMotion_WaitMoveStartObservation()` | 多个入口重复处理就绪门控、命令切换和正式运动启动观察 | 收敛机械流程，但保留各入口健康检查强度、强制调试边界和 100 次、10ms 启动窗口 |
| Jog 内部状态机 | `MotorMotion_JogMoveToTargetInternal()`、`MotorMotion_CheckJogRuntimeGuards()` | 循环内命令切换、位置刷新、健康检查、丢步/撞底检查较长 | 已抽取单轮运行保护 helper，保留减速、提前停机和慢停恢复在 Jog 状态机内 |
| 无检测运动 | `MotorMotion_MoveBlockingNoDetectInternal()` | 与普通等待循环重复，但保护强度不同 | 只抽公共命令切换、速度刷新、驱动同步；保留“无检测只记录日志”的边界 |
| 等待循环公共运行检查 | `MotorMotion_CheckAbortRefreshAndHealth()`、`MotorMotion_WaitTicksStartChanged()`、`MotorMotion_MoveBlockingNoDetectInternal()`、`MotorMotion_WaitStopAbortable()` | 命令切换、运行中速度刷新和 TMC 同步/健康检查重复 | 第二轮已抽窄 helper；调用方仍决定是否恢复速度、是否记录无检测日志、是否继续路径专属检查 |
| 停稳后刷新收尾 | `MotorMotion_CheckStoppedAndRefresh()`、`MotorMotion_WaitStopAbortable()`、`MotorMotion_WaitUntilStopWithTarget()`、`MotorMotion_WaitStoppedAfterStopCommand()` | 停稳后最终位置同步和活动状态清理重复 | 第二轮已抽窄 helper；同步失败时不清活动状态，保持原错误返回 |
| 停机等待 | `MotorMotion_WaitStopAbortable()`、`MotorMotion_WaitUntilStopWithTarget()`、`MotorMotion_WaitStoppedAfterStopCommand()` | 轮询结构相似但职责不同 | 只收敛可等价复用的公共检查和停稳收尾；`WaitUntilStopWithTarget()` 仍保留目标判断、撞底、健康错误归因和超时日志 |

## 6. 第一轮：无行为结构重构实施计划

### 阶段 0：准备和保护

1. 确认 worktree 干净。
2. 再次确认 `motor_ctrl_motion_api.c` 编码为 GBK/936。
3. 保留当前基线构建结果，后续每个阶段至少构建一次 CPU2。

验收：

- `git status --short` 只显示本任务相关文件。
- `cmake --build build\LTD_MAIN_CPU2` 通过。

### 阶段 1：抽取临时速度 scope

新增文件内 `static` 结构：

```c
typedef struct
{
    bool restore_needed;
    uint32_t restore_speed_x100;
} MotorMotionSpeedScope;
```

新增 helper：

```c
static uint32_t MotorMotion_BeginSpeedScope(MotorMotionSpeedScope *scope,
                                            uint32_t speed_x100);
static uint32_t MotorMotion_EndSpeedScope(const MotorMotionSpeedScope *scope);
static uint32_t MotorMotion_ReturnWithSpeedScope(uint32_t ret,
                                                 const MotorMotionSpeedScope *scope);
static uint32_t MotorMotion_CheckErrorWithSpeedScope(uint32_t ret,
                                                     const MotorMotionSpeedScope *scope,
                                                     int line);
```

替换范围：

- `MotorCtrl_MoveByTicksAndWait()`
- `MotorCtrl_MoveAndWait()`
- `MotorCtrl_MoveToPosition()`
- `MotorMotion_MoveBlockingNoDetectInternal()`
- `MotorMotion_JogMoveToTargetInternal()`
- `MotorMotion_StopJogAndRestore()`

约束：

- `ret != NO_ERROR` 时必须优先返回原始运动错误。
- 只有运动本身成功时，速度恢复失败才作为最终错误返回。
- 不改变现有 `MotorDriver_*` 对外内部接口。

### 阶段 2：抽取命令切换、速度刷新和健康同步

新增 helper：

```c
static uint32_t MotorMotion_CheckAbortRefreshAndHealth(TMC5130TypeDef *tmc5130,
                                                       uint32_t *last_vel_refresh_tick);
```

职责：

1. 检查命令切换并停机。
2. 运行中按卷筒长度刷新速度。
3. 同步位置或检查驱动健康。

替换范围：

- ticks 启动变化等待循环。
- ticks 到位确认循环。
- `MotorMotion_WaitStopAbortable()`。
- `MotorMotion_WaitUntilStopWithTarget()`。
- `MotorMotion_MoveBlockingNoDetectInternal()` 的等待循环。
- `MotorMotion_JogMoveToTargetInternal()` 的循环内公共检查。

约束：

- 不改变各函数原有轮询周期。
- 不改变撞底检测和丢步检测相对顺序，除非代码里已有顺序不一致且需要显式记录。
- 不把无检测运动误改成正式丢步保护。

### 阶段 3：统一位置快照和范围检查

复用现有 helper：

```c
static uint32_t MotorMotion_RefreshActivePositionMm(float *pos_mm);
static bool MotorMotion_IsPositionSnapshotValid(float pos_mm);
```

调整：

- `MotorCtrl_MoveAndWait()` 开始和结束位置读取改成主动刷新后快照。
- `MotorCtrl_MoveToPosition()` 删除重复的 `tankHeight` 范围计算，改用 `MotorMotion_IsPositionSnapshotValid()`。
- `MotorCtrl_JogMoveAndWait()` 和 `MotorCtrl_JogMoveToPosition()` 保持现有口径。

约束：

- 电机记步模式下必须通过 `MotorCtrl_RefreshPositionFromActiveSource()` 刷新。
- 编码轮记步模式下保持编码轮刷新。
- 位置异常仍返回 `MEASUREMENT_POSITION_ERROR`。

### 阶段 4：清理 `MotorCtrl_MoveAndWait()` 无效重试结构

当前结构：

- `while (attempt < MOTOR_MOVE_RETRY_MAX && remain_mm > 0.0f)`。
- `MotorMotion_WaitUntilStopWithTarget()` 返回错误后直接 `return`。
- 后续 `else { ErrorLog_Retry(...) }` 基本不可达。

计划：

1. 删除不可达的 `else` 重试分支。
2. 删除无效的 `attempt`、`remain_mm` 重试控制变量，保留必要的目标位置和最终偏差判断。
3. 保留最终 `diff_pct` 丢步判断。

不做：

- 不把它改成真正多次重试。
- 不改变 `MOTOR_MOVE_RETRY_MAX` 其他潜在用途。

### 阶段 5：拆分 ticks 运动内部小流程

对 `MotorCtrl_MoveByTicksAndWait()` 抽取两个内部 helper：

```c
static uint32_t MotorMotion_WaitTicksStartChanged(int32_t requested_ticks,
                                                  int32_t xactual_before,
                                                  const MotorMotionSpeedScope *scope);
static uint32_t MotorMotion_WaitTicksReachTarget(int32_t target_ticks,
                                                 char *detail,
                                                 size_t detail_size);
```

目标：

- 主函数保留“参数检查、门控、下发、等待、恢复”的主线。
- 详细错误日志仍在 helper 内保留。
- 不改变 500ms 启动变化确认和 `1024 ticks` 到位容差。

### 阶段 6：保守整理 Jog 状态机

允许：

- 把“刷新位置并检查越界/有效性”抽成 helper。
- 把“计算剩余距离并判断到位”抽成 helper。
- 把“slow_mode 切换到爬行速度”抽成 helper。

不允许：

- 不改 `MOTOR_JOG_*` 阈值。
- 不改变速度模式启动方式。
- 不用 Jog 替代普通 `MoveToPosition()`。

- Jog 运动仍保留主动位置反馈、减速、提前停机和越界检查。

## 8. 风险和控制措施

| 风险 | 影响 | 控制措施 |
| --- | --- | --- |
| 抽 helper 时改变错误优先级 | 故障原因被覆盖，现场难排查 | `ret != NO_ERROR` 时优先返回原始错误；仅成功路径考虑恢复速度错误 |
| 误降低强制调试路径门控 | 强制运动可能绕过 TMC 初始化或健康检查 | `ForceDebug` 只允许绕过编码器首帧，不绕过驱动初始化和健康检查 |
| 普通运动误走无检测逻辑 | 丢步、撞底或命令切换保护缺失 | 保留正式运动和无检测运动的独立入口和检查项 |
| 位置源刷新口径变化 | 电机记步/编码轮记步下位置判断不一致 | 统一通过 `MotorCtrl_RefreshPositionFromActiveSource()` 刷新 |
| GBK 源码写成 UTF-8 | 中文注释和打印乱码 | 修改源码时显式按 GBK/936 写回 |
| 重构后构建通过但现场运动细节变化 | 台架行为偏差 | 第一轮不改阈值、不改轮询周期、不改运动模式；现场验证另列测试项 |

## 12. 第二轮：等待状态机收敛计划

第二轮只在第一轮构建和保护调用检查通过后执行。目标是把多个等待循环中的公共机械动作收敛出来，同时保留每条运动路径自己的安全边界。

### 12.1 候选抽取对象

| 候选对象 | 适用路径 | 不得合并的差异 |
| --- | --- | --- |
| 命令切换停机检查 | 普通运动、ticks、Jog、无检测 | 各路径返回错误码和日志上下文不能被覆盖 |
| 运行中速度刷新 | 普通运动、ticks、Jog、无检测 | 轮询周期、刷新节奏和速度来源不能改变 |
| TMC 位置/速度同步 | 停机等待、到位等待、Jog 循环 | Jog 的主动位置反馈和边界判断不能被削弱 |
| 驱动健康检查 | 所有阻塞等待 | 强制调试只允许绕过编码器首帧，不能绕过 TMC 初始化和 24V 健康检查 |
| 停机后确认 | `WaitStoppedAfterStopCommand()`、命令切换停机 | 停机命令发送、等待静止、位置同步的顺序不能改变 |

### 12.2 推荐接口形态

先选择窄 helper，而不是一步到位抽象成统一大循环：

```c
static uint32_t MotorMotion_CheckAbortRefreshAndHealth(TMC5130TypeDef *tmc5130,
                                                       uint32_t *last_vel_refresh_tick);
static uint32_t MotorMotion_CheckStoppedAndRefresh(TMC5130TypeDef *tmc5130);
```

只有当第二轮完成后仍存在明显重复，再评估上下文结构：

```c
typedef struct
{
    TMC5130TypeDef *tmc5130;
    uint32_t last_vel_refresh_tick;
    bool enable_lost_step_check;
    bool enable_collision_check;
} MotorMotionLoopContext;
```

该结构不能在第二轮直接替代所有循环。先用一个路径验证，再扩展到其他路径。

### 12.3 第二轮验收

- 当前已完成第一刀：`MotorMotion_CheckAbortRefreshAndHealth()` 被 `MotorMotion_WaitTicksStartChanged()`、`MotorMotion_MoveBlockingNoDetectInternal()` 和 `MotorMotion_WaitStopAbortable()` 使用。
- 当前已完成第二刀：`MotorMotion_CheckStoppedAndRefresh()` 被 `MotorMotion_WaitStopAbortable()`、`MotorMotion_WaitUntilStopWithTarget()` 和 `MotorMotion_WaitStoppedAfterStopCommand()` 使用。
- `MotorMotion_WaitStopAbortable()`、`MotorMotion_WaitUntilStopWithTarget()`、`MotorMotion_MoveBlockingNoDetectInternal()` 和 `MotorMotion_JogMoveToTargetInternal()` 的保护差异仍能从代码上直接看清。
- 无检测路径仍不触发正式丢步保护。
- 普通运动仍保留撞底检测和丢步检测。
- 命令切换时仍先停机，再返回命令切换错误。
- CPU2 构建通过，并执行关键保护调用 `rg` 检查。
- 暂不把 `MotorMotion_WaitUntilStopWithTarget()` 的主体强行纳入该 helper，因为它的 `CHECK_ERROR`、目标停机、撞底、驱动健康和超时日志需要保留当前位置和错误归因语义。

## 13. 第三轮：运动策略评估计划

第三轮不是默认实现项，只做评估和受控实验。当前不建议直接用 Jog 状态机替换 `MotorCtrl_MoveToPosition()`，原因是普通绝对位置运动和 Jog 反馈运动的停止策略、减速阈值、位置闭环来源和错误收尾不完全相同。

### 13.1 评估问题

| 问题 | 需要收集的证据 |
| --- | --- |
| 普通 `MoveToPosition()` 是否存在到位误差或过冲 | 不同速度、不同方向、不同距离下的最终位置偏差 |
| Jog 反馈策略是否更稳定 | 相同工况下的偏差、耗时、提前停机距离和慢速段行为 |
| 编码轮记步和电机记步是否一致 | 两种位置源下的起点、终点、刷新频率和异常返回 |
| 运动中命令切换是否可靠 | 切换到其他命令时的停机耗时、返回码和显示状态 |
| 低速爬行是否影响生产节拍 | 目标距离接近时的总耗时和可接受范围 |

### 13.2 可选实验方式

优先使用可回退方式：

1. 增加仅限调试的内部开关，默认关闭。
2. 或增加临时串口测试命令，命令名和返回内容必须在测试记录中写清。
3. 或只在台架分支验证，不合入正式分支。

不允许：

- 未经台架数据确认就改变 `MotorCtrl_MoveToPosition()` 默认路径。
- 直接删除普通位置模式下的 `MoveAndWait()` 分段逻辑。
- 为了复用 Jog 而降低丢步、撞底、越界或命令切换保护。

### 13.3 第三轮退出条件

- 如果 Jog 策略没有明显收益，保留第一、二轮结构优化结果，不做行为替换。
- 如果 Jog 策略收益明确，先形成行为变更方案和测试矩阵，再进入代码实现。
- 任何默认策略变化都必须进入第四轮完整验证和第六轮版本影响评估。

### 13.4 当前评估结论

当前第三轮只执行策略评估，不做固件代码变更。审计结论如下：

- `MotorCtrl_MoveToPosition()` 继续作为正式业务绝对位置入口，通过主动位置刷新、目标规划和 `MotorCtrl_MoveAndWait()` 分段执行。
- `MotorCtrl_JogMoveToPosition()` 继续作为 `BJP` 调试入口，用于验证速度模式、主动位置反馈、减速距离和提前停机。
- 现有台架数据只覆盖 `T04`、`T07`、`T08`、`T09`、`T10` 等有限场景，主要是 `1.0m/min` 和小行程，不能支撑默认策略替换。
- 后续若继续推进，只允许先增加默认关闭、可回退的台架实验入口或内部开关，并按同目标、同速度、同起点做 A/B 对比。
- 详细评估记录见《电机运动第三轮策略评估记录.md》。

### 14.2 串口和台架命令矩阵

| 场景 | 代表命令或入口 | 预期 |
| --- | --- | --- |
| 正式向上/向下运动 | `MotorCtrl_MoveUp()`、`MotorCtrl_MoveDown()` | 运动完成后位置同步，速度恢复，显示状态清理 |
| 绝对位置运动 | `MotorCtrl_MoveToPosition()` | 目标范围内正常到位，目标越界返回参数超限 |
| ticks 运动 | `MotorCtrl_MoveByTicksAndWait()` | 启动变化确认有效，到位容差保持 `1024 ticks` |
| Jog 相对点动 | `BJ` / `MotorCtrl_JogMoveAndWait()` | 按方向移动，接近目标时减速，到位后停机 |
| Jog 绝对点动 | `BJP` / `MotorCtrl_JogMoveToPosition()` | 使用主动位置反馈，越界或位置无效时停机返回错误 |
| 强制无检测运动 | 强制调试入口 | 只绕过允许项，不绕过驱动初始化和健康检查 |
| 命令切换 | 运动中切换到其他命令 | 先停机，再返回命令切换错误 |
| 编码器首帧缺失 | 启动前制造首帧缺失 | 非强制路径拒绝运动，强制路径只绕过首帧 |
| TMC 或 24V 故障 | 断开或模拟故障 | 返回驱动健康相关错误，不能继续运动 |
| 位置源切换 | 电机记步、编码轮记步 | 两种模式都能刷新主动位置并执行范围判断 |
