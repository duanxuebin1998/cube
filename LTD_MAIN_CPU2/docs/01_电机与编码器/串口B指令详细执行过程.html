串口 B / BE 指令详细执行过程

本文记录 CPU2 串口调试指令 B<mm>、BE<mm>、以及 S 后缀的最终执行流程。当前实现目标是：B/BE 测试过程不参与业务错误状态；电机运行函数只负责直接写 TMC5130 运动寄存器；BE 只用编码值判断目标，不读取任何错误码。

适用固件CPU2 V1.8.1.0
入口文件LTD_MAIN_CPU2/Application/Src/measure.c
执行文件LTD_MAIN_CPU2/Application/Src/test.c
最终策略：B/BE 在 process_command() 内先于通用 MeasureStart() 分流。两条指令不调用 MotorCtrl_Init()、MotorCtrl_MoveNoWait()、stpr_waitMove()，避免称重异常、电机过热、驱动状态、24V 功率级等业务错误检查导致退出。

一、命令格式

命令含义退出/错误策略

B100S
B100,1		 同 B100，每段运动停稳后按当前 sensorType 只发一次传感器读命令并打印结果。 S 不切液位模式，不读液位频率，只打印结果并恢复进入前的 device_state/error_code。

BE100,1		 同 BE100，编码器下行和上行完成后打印通信结果。 S 后缀不参与退出和错误状态。

二、串口接收到命令

  1. UART 接收完整命令后进入 process_command(command)。
  2. 先处理正式业务命令和 SC 通信测试。
  3. 如果首字节是 B，立即进入 B/BE 分支；这一分支位于通用 MeasureStart() 之前。
  4. 解析第二个字符是否为 E：B 为普通电机模型测试，BE 为编码器反馈测试。
  5. 从 B 或 BE 后解析距离值；扫描后续字符，如果发现 S 或 ,1，打开通信结果打印。
  6. 距离值小于等于 0 时直接打印参数异常并返回；这是命令输入无效，不属于运行期错误重试。

三、B 指令执行过程

1. 准备阶段

  1. 调用 Test_MotorTextClearIgnoredError() 清掉进入前可能残留的全局错误码。
  2. 调用 Test_MotorTextPrepareNoExit("B")，内部只尽量写 TMC5130 基础配置和 VMAX，不根据返回错误码退出。
  3. 初始化失败时只打印 ret，延时 200ms 后重试；不把错误码留在全局状态中。
  4. 调用 stpr_setPos(&stepper, 0) 设置本轮测试零点。设置失败时先停止并等待停稳，再重新初始化并重试。

2. 每轮循环

  1. 下行阶段：Test_MotorTextMoveByNoCheck(run_distance_mm, MOTOR_DIRECTION_DOWN) 按现有卷筒模型换算 ticks，然后直接写 RAMPMODE、VMAX、XTARGET，不根据任何返回错误码决定流程。
  2. 下发成功后必须调用 Test_WaitMotorStoppedNoErrorCheck("B DOWN")，只读取 TMC5130_RAMPSTAT；第一次满足 VZERO 后延时 200ms，再次读取仍为 VZERO 才允许下一步，避免换向瞬间误判。
  3. 如果带 S 后缀，调用 Test_SensorCommCheckAndPrintOnly("after DOWN")，内部按 sensorType 区分 DSM 一代和 LTD/V2 后只发一次读命令：DSM 一代读取频率/密度/温度，LTD/V2 读取密度；不切液位模式，不读液位频率，随后恢复进入通信检查前的状态和错误码。
  4. 上行回零阶段：调用 Test_MotorTextMoveToNoCheck(0, MOTOR_DIRECTION_UP)，直接写 RAMPMODE、VMAX、XTARGET=0。
  5. 再次等待 RAMPSTAT.VZERO 二次确认，确认速度持续归零后才进入下一轮。
  6. 任何下发失败、停止命令失败或停止状态读取失败，都只打印并在停稳后重试当前阶段，不退出 B 测试。

四、BE 指令执行过程

1. 准备阶段

  1. 检查距离和编码器轮周长参数能否换算出有效编码器计数；无效输入直接返回。
  2. 调用 Test_MotorTextPrepareNoExit("BE") 做原始 TMC5130 初始化，不调用通用电机健康检查。
  3. 编码器采集定时器由上电初始化启动，BE 不重复启动定时器，只读取当前编码器计数和最近一次编码器错误。
  4. 读取当前编码器值作为固定原点 origin_encoder，下行目标固定为 origin_encoder + run_encoder_count；BE 循环期间不重新计算起始点和终止点。

2. 下行和上行闭环

  1. 进入阶段前不查看任何错误码，包括称重超时、电机状态和编码器错误码。
  2. 下发保护行程：调用 Test_MotorTextMoveByNoCheck(guard_mm, dir)，内部直接写 RAMPMODE、VMAX、XTARGET。guard_mm 大于目标距离，只给编码器闭环留足运动空间。
  3. 运动中循环读取编码器值。下行目标始终是固定 down_target_encoder，上行目标始终是固定 origin_encoder。
  4. 到达编码器目标后调用 stpr_stop()，再等待 RAMPSTAT.VZERO，确认速度归零后返回本阶段成功。
  5. 运动中不读取编码器错误码；BE 不重启编码器定时器，也不因错误码重试或退出。
  6. 如果电机速度已经为 0 但编码器未到目标，需要经过 200ms 后二次读取仍为 VZERO，才认为本阶段已结束；下行结束后记住实际上行起点用于日志，上行仍回到固定 origin_encoder。
  7. 带 S 后缀时，编码器下行和上行完成后分别只发一次传感器读命令并打印结果，但通信结果不改变 BE 的退出条件。

六、源码位置

  • LTD_MAIN_CPU2/Application/Src/measure.c：process_command() 中 B/BE 分支前置到 MeasureStart() 之前。
  • LTD_MAIN_CPU2/Application/Src/test.c：motor_text()、motor_text_encoder()、Test_MoveUntilEncoderTarget() 和 B/BE 专用低检测 helper。
  • LTD_MAIN_CPU2/Drivers/Peripherals/src/TMC5130.c：B/BE 运动阶段只使用 stpr_writeInt() 直接写运动寄存器，停转判断仍读取 RAMPSTAT.VZERO。
  • LTD_MAIN_CPU2/Drivers/Peripherals/src/AS5145.c：BE 不读取编码器错误码，只使用编码计数。
