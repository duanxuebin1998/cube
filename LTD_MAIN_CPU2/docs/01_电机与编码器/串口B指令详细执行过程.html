串口 B 指令程序流程梳理

本文按当前 CPU2 源码梳理串口调试命令 B<mm>、BE<mm> 以及 S/,1 后缀的实际执行路径。重点说明入口优先级、循环阶段、退出条件和哪些错误会被主动忽略。

当前固件CPU2 V1.12.0.0
命令入口process_command()
B 执行函数motor_text()
BE 执行函数motor_text_encoder()
历史/专题流程提示

串口 B 入口和运动执行细节的旧专题梳理；当前权威流程以 CPU2 电机与位置模型页为准。

当前权威流程：电机与位置模型程序流程统一入口
结论：B 是串口调试指令，不是正式测量命令。主循环收到完整串口命令后直接调用 process_command(received_buffer)，process_command() 在调用 MeasureStart() 之前拦截 B...。因此 B/BE 不进入正式 CommandType 业务状态机，也不会执行通用测量前的健康检查。
现场注意：B/BE 会无限往返循环，正常不会自动结束。退出主要依赖新的有效命令触发 HasEffectiveCommandSwitchRequest()，随后停止 TMC5130、清理调试状态并返回主循环。

一、入口总览

1
USART1 中断收包

USART1_IRQHandler() 在 IDLE 中断后停止 DMA，遍历 USART1_RX_BUF。收到 \r\n 时，把 \r 改成字符串结束符，置位 new_command_ready=1，命令内容保存在 received_buffer[64]。

2
主循环优先处理原始串口命令

App_MainLoop() 每轮先轮询后台状态，再检查 new_command_ready。如果有新命令，先取消自动恢复任务，清掉 new_command_ready，然后调用 process_command(received_buffer)。

3
process_command() 前置分流

函数先处理正式单字母业务命令、SC 通信测试和 SP... 无线匹配调试。若首字节是 B，立即进入 B/BE 分支并 return，不会继续向下执行 MeasureStart()。

二、命令格式

命令 解析结果 核心行为
B100 use_encoder_count=0，距离 100mm，不启用传感器通信检查。 按电机/卷筒模型把距离换算成 TMC5130 ticks，下行 100mm，再上行回本轮 XTARGET=0，循环执行。
B100S
B100,1		 同 B100，同时 enable_sensor_comm=1。 每个下行和上行阶段结束后各做一次传感器通信读取，只打印结果，不改变 B 的退出条件。
BE100 use_encoder_count=1，距离 100mm，按编码轮周长换算目标编码增量。 记录进入 BE 时的固定编码原点，下行到固定目标编码值，再上行回固定原点，循环执行。
BE100S
BE100,1		 同 BE100，同时 enable_sensor_comm=1。 编码器下行和上行阶段结束后各做一次传感器通信读取，只打印结果。

参数解析规则

  • command[0] == 'B' 才进入该分支。
  • command[1] == 'E' 表示 BE，否则按普通 B 处理。
  • B 从 command[1] 开始 atoi()，BE 从 command[2] 开始 atoi()。
  • 从距离字段开始向后扫描，遇到 S 或 ,1 就启用通信检查。
  • 距离 <=0 时只打印参数无效并返回。

入口优先级

  • 正式业务命令 I/G/K/R/W/O/P/Q 会被映射为 CommandType 并交给主循环执行。
  • SC 和 SP... 是独立调试入口，先于 B 判断。
  • B/BE 判断完成后直接调用 motor_text() 或 motor_text_encoder()。
  • B/BE 分支之后才是通用串口调试动作的 MeasureStart()。

三、B 指令流程

B1
进入 motor_text(run_distance_mm, enable_sensor_comm)

进入时先用 Test_MotorTextCaptureErrorState() 保存原 device_state/error_code 快照，再清零 s_motor_text_raw_target 并调用 Test_MotorTextClearIgnoredError()。B/BE 不修改 TMC5130 A1/AMAX/D1/DMAX 斜坡寄存器；退出时统一调用 Test_MotorTextExit() 恢复进入前错误快照，避免诊断清错影响正常程序。

B2
原始初始化 TMC5130

Test_MotorTextPrepareNoExit("B") 只检查是否有命令切换。随后 Test_MotorTextRawInit() 校正电机电流参数、更新速度、调用 stpr_initStepper()、使能驱动、写入 VMAX。这些写入返回值被忽略，失败不会让 B 流程按业务错误退出。

B3
建立本轮 TMC5130 零点

B 写 RAMPMODE=POSITION，并把 XACTUAL 和 XTARGET 写为 0。后续下行使用累计目标 s_motor_text_raw_target，上行使用绝对目标 0。

B4
无限循环：下行阶段

Test_MotorTextRunMoveStageNoExit("B DOWN", ...) 调用 Test_MotorTextMoveByNoCheck(run_distance_mm, MOTOR_DIRECTION_DOWN)。距离先按当前 cable_length、位置计数模式、卷筒模型或本地周长换算成 ticks，然后直接写 RAMPMODE、VMAX、XTARGET。

B5
等待下行停稳

Test_WaitMotorStoppedNoErrorCheck() 只读 TMC5130_RAMPSTAT 并检查 VZERO。第一次读到 VZERO 后延时 200ms 再读一次，两次均为 VZERO 且至少经过 50ms settle 才认为停稳。读取失败不退出，只按 1 秒间隔打印并继续等待。

B6
可选通信检查

如果命令带 S 或 ,1，下行停稳后调用 Test_SensorCommCheckAndPrintOnly("after DOWN")。该函数保存并恢复进入前的 device_state 和 error_code。

B7
上行回零并进入下一轮

上行阶段调用 Test_MotorTextMoveToNoCheck(0, MOTOR_DIRECTION_UP)，直接把目标写回 XTARGET=0，再执行同样的 VZERO 二次确认。若启用通信检查，上行结束后再读一次传感器，随后 loop_cnt++ 并开始下一轮。

四、BE 子模式流程

BE 是 B 命令家族里的编码器反馈测试模式。它仍绕过 MeasureStart()，但运动阶段不是按 TMC5130 目标位置直接判断到位，而是按编码器计数判断目标是否到达。

E1
换算编码器目标

Test_EncoderDistanceMmToCount() 使用 encoder_wheel_circumference_mm 把输入距离换算为编码计数，公式基于一圈 4096 角度单位和参数单位 0.001mm。若距离无效或编码轮周长为 0，直接返回。

E2
计算保护行程

Test_EncoderDistanceToGuardMm() 用 distance * 1.20 + 5mm 得到保护行程，且最小不低于 10mm。BE 每个阶段先下发保护行程，实际结束点由编码器目标或电机停转决定。

E3
记录固定原点和固定下行目标

BE 完成原始初始化后调用 Test_GetEncoderValue()，内部先 update_sensor_height_from_encoder()，再返回 -g_encoder_count。进入 BE 时的值作为固定 origin_encoder，下行目标固定为 origin_encoder + run_encoder_count。

E4
下行编码器闭环

Test_MoveUntilEncoderTarget(down_target_encoder, origin_encoder, DOWN, guard_mm, "BE下行") 先下发保护行程，然后每 10ms 读取一次当前编码器值。下行方向满足 current >= target 时打印“编码器到位触发”，写 VMAX=0 停车，等待 VZERO 二次确认后再打印“停稳结果”和停稳偏差。

E5
电机提前停转也结束当前阶段

BE 给启动阶段留 500ms 宽限。超过宽限后，如果电机已经连续确认 VZERO，即使编码器未到固定目标，也把当前阶段视为完成。这里不会读取编码器错误码，也不会把业务错误带出。

E6
上行回固定原点

下行结束后记录实际上行起点用于日志，但上行目标仍是最初的 origin_encoder。上行方向满足 current <= origin_encoder 时停车并等待 VZERO。之后可选执行 after ENCODER UP 通信检查，进入下一轮。

五、S 后缀通信检查

传感器类型 调用动作 对 B/BE 流程的影响
DSM_SENSOR 调用 DSM_Read_Frequency_Density_Temp() 读取频率、密度、温度。 只打印成功或失败结果，不改变 B/BE 是否继续循环。
LTD_SENSOR 调用 DSM_V2_Read_Density() 读取密度。 只打印成功或失败结果，随后恢复原 device_state 和 error_code。
其他类型 打印未知传感器类型和累计失败次数。 不退出，不进入业务错误处理。

六、退出与错误规则

会退出

  • 串口收到下一条完整原始命令，new_command_ready != 0。
  • Modbus 或其他路径写入新的正式命令，g_deviceParams.command != CMD_NONE。
  • 输入距离小于等于 0，或 BE 编码轮周长为 0 等准备期参数无效。

会等待或继续

  • RAMPSTAT 读取失败时继续等待，只周期性打印。
  • 通信检查失败时只打印，不影响循环。
  • BE 中电机提前停稳但编码器未到目标时，当前阶段结束，循环继续。

主动忽略

  • B/BE 进入时保存原业务错误状态，运行中清除临时 error_code/STATE_ERROR，退出时恢复快照。
  • TMC5130 原始初始化和运动寄存器写入的返回值。
  • 称重异常、业务电机健康检查、24V 功率级等正式流程错误。
  • BE 运行中的编码器错误码，BE 只看编码值和电机停稳状态。
调试边界：B/BE 的设计目标是排查低层运动、编码器和传感器通信，不适合作为正式测量动作。它绕过了正式测量入口中的统一状态维护、自动恢复和部分硬件健康检查。

七、打印信息口径

日志前缀/阶段 触发位置 含义
B电机测试 motor_text() 入口、参数异常、整轮完成 普通 B 指令总体状态，字段使用 距离、传感器通信、运行距离。
B下行、B上行回零 B 每一段运动开始和完成 使用 [第N轮] 标识循环次数，便于对齐下行、上行和通信检查日志。

BE下行、BE上行 BE 编码器闭环阶段 打印 当前、目标、上行起点、固定原点 等字段，明确是编码器目标到位还是电机停稳结束。
B下行后、B上行后、BE下行后、BE上行后 S/,1 后缀通信检查 作为传感器通信检查的中文 tag，打印 [正常] 或 [异常] 结果，不参与 B/BE 退出条件。
等待停稳、保护行程已下发、编码器到位触发、停稳结果、保护行程停稳 B/BE 公共低层 helper 用于定位底层 TMC5130 停稳判断、BE 保护行程、编码器触发位置和最终停稳偏差。
