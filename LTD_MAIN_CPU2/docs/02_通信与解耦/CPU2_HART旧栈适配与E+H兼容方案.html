1. 结论

首要门槛：不能直接无脑链接旧库。

旧工程的 COMMU/HartM3.lib 是 ARM EABI archive，目标属性显示为 Cortex-M3、Thumb-2、软浮点风格；当前 CPU2 工程工具链使用 Cortex-M4 hard-float：-mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 -mfloat-abi=hard。如果没有 M4/GCC/hard-float 版本的库或源码，直接移植可能在链接阶段失败，或引入浮点 ABI 风险。

推荐路线

拿到匹配当前工具链的 HART 库或源码后，移植旧工程的 interface.h、hart_protocol.c、hart_dd.c/h 逻辑，并新写 HAL 适配层。

保留内容

保留当前工程 USART2、PB7 HART_RTS、AD5421、g_deviceParams、g_measurement、主循环命令消费模型。

不建议照搬

不要复制旧工程 UART4、PD4、DMA2_CH5、Timer1 寄存器级硬件代码；这些和当前 STM32F429 HAL/CubeMX 工程不匹配。

3. 目标架构

目标不是把旧工程全部搬进当前工程，而是把“协议栈/私有命令/DD 映射”作为独立服务，下面接当前 HAL 和业务数据。

模块 职责 建议来源
interface.h 定义 ST_HART、ST_PARA_HART、回调函数类型和库 API。 从旧工程移植，必要时按当前类型风格调整。
hart_protocol.c 初始化 HART 数据、注册回调、更新 PV/SV/TV/FV、电流和私有命令分发。 移植旧工程逻辑，去掉旧硬件初始化。
hart_dd.c/h 实现 DD 参数读写、测量值读取、命令下发、E+H 读数据和下发命令。 移植旧工程表结构，重做字段映射。
hart_port_hal.c 封装 USART2、DMA、RTS、5ms tick、发送完成回接收。 当前工程新写，禁止照搬旧寄存器级代码。
hart_snapshot.c 把当前测量结果和参数转换为 HART/DD/E+H 所需数据。 当前工程新写，集中处理单位和缩放。

4. 关键适配点

4.1 初始化顺序

  1. init_device_params() 先加载当前设备参数。
  2. AD5421 初始化归属要统一，建议保留在模拟输出/BSP 层，不再让 HartInit() 内部重复初始化。
  3. HartInit() 只负责 HART 参数加载、ST_HART 回调注册、hrtInit() 和 DD 初始化。
  4. USART2 RX DMA 或 RXNE 接收启动由当前 HAL 串口层负责。

4.2 接收路径

方案 做法 评价
RXNE 单字节 USART2 每收到 1 字节，写入 HartData.RxdData 后调用 hrtGetChar()。 最贴近旧库调用模型，但要确认回调中不会触发重处理、打印或阻塞。
DMA + IDLE 批量喂入 沿用当前 DMA IDLE 收帧，收到一段数据后循环逐字节调用 hrtGetChar()。 改动较小，但要验证库内部对字节间隔、前导符和超时判断是否依赖实时 5ms tick。
中断边界要求

无论采用哪种路径，私有命令最终不要在中断里直接执行测量流程。HART 回调只解析并写入 g_deviceParams.command 或轻量状态，实际测量仍由 App_MainLoop() 统一消费。

4.3 发送路径

  1. 库调用 HartSendDataFunc 时，先将 PB7 HART_RTS 拉低进入发送。
  2. 调用 HAL_UART_Transmit_DMA(&huart2, pData, len)。
  3. 发送完成后等待 UART TC，确认最后一位已经移出，再拉高 PB7 回接收。
  4. 重新启动 RX DMA 或继续打开 RXNE 接收。

4.4 动态变量映射

HART 变量 旧工程来源 当前建议来源 单位口径
PV / 液位 result.OilLevel / 10.0 g_measurement.oil_measurement.oil_level 确认当前字段为 0.1mm 后转换为 mm。
SV / 温度 result.TemperatureValueAverage / 10.0 g_measurement.density_distribution.average_temperature 或单点温度 当前字段常见为 0.01°C，需统一转换。
TV / 密度 result.DensityValueAverage / 10.0 g_measurement.density_distribution.average_density 或单点密度 按当前密度单位确认缩放。
QV / 水位 result.WaterValue / 10.0 g_measurement.water_measurement.water_level 确认当前字段为 0.1mm 后转换为 mm。
电流/百分比 result.CurrentValue AO 输出缓存或按 PV 经 IoutProcessValue() 计算 必须和 AD5421 实际输出保持一致。

5. E+H 兼容方案

旧工程的 E+H 兼容不是单独的 Modbus/E+H 协议栈，而是放在 HART DD 私有命令里，通过命令 194/195 承载 E+H NMS 语义。

5.1 私有命令

命令 名称 当前适配要求
170 读取测量值 从当前 g_measurement 或 Modbus 输入寄存器快照读取。
171 读取参数 读取映射到当前 g_deviceParams 或 HART 独立参数块的数据。
172 写参数 写入前必须先检查权限、状态和范围，不能照搬旧工程“先写 RAM 后校验”的顺序。
175 下发 DD coil 命令 转换为当前 CommandType，由主循环执行。
194 E+H 读数据 按 3 字节地址返回过程状态、命令状态、距离、密度、停止液位等数据。
195 E+H 下发命令 解析 0x037E00 + 2 字节命令码，转换为当前 CommandType。

5.2 E+H 数据地址映射

E+H 地址 语义 当前建议来源 待确认点
0x037200 Process condition 默认返回通用过程条件 2577。 是否需要按液面稳定/扰动扩展。
0x037E00 Gauge command/status 由 g_measurement.device_status.device_state/current_command 映射。 状态到 E+H 命令码的优先级。
0x03DA00 Distance 优先使用探头/浮子当前位置或罐高减液位。 现场主站期望“空高”还是“浮子距离”。
0x03E200 Upper density 密度分布上层点或平均密度。 没有分层结果时的降级策略。
0x03E300 Middle density 密度分布中层点或平均密度。 同上。
0x03E400 Lower density 密度分布下层点或平均密度。 同上。
0x040B00 Low stop level g_deviceParams.blindZone 或下限停止液位。 当前工程是否已有独立低停止参数。
0x040C00 High stop level g_deviceParams.tankHeight 或高停止液位。 是否需要扣除盲区或机械保护距离。
0x044100 Profile density 密度分布平均密度或最近一次 profile 密度。 是否要锁存最近一次完成结果。

6. 参数存储与版本影响

6.1 HART 参数存储

建议：HART 环境参数单独建 FRAM 块。

旧工程 ST_PARA_HART 是 128 字节并带 CRC，包含 tag、long tag、description、polling address、trim、PV range、IOUT range、DV map 等。当前 DeviceParameters 有 struct_size、DEVICE_PARAM_VERSION 和 A/B 分区校验。若只是 HART 自有参数，单独存储可以避免扰动主参数结构。

方案 优点 风险 建议
独立 HART FRAM 块 不改变 DeviceParameters 布局；CPU3 协议不一定受影响。 需要规划地址、CRC 和默认恢复逻辑。 优先
并入 DeviceParameters 统一参数读写和备份。 会改变结构体大小，涉及 DEVICE_PARAM_VERSION、升级清参数风险和版本文档。 仅在 CPU3 也要配置时考虑

6.2 CPU2/CPU3 协议版本

  • 如果 HART 只在 CPU2 内部运行，不新增 CPU3 菜单/寄存器/共享字段，通常不需要改变 DEVICE_PROTOCOL_VERSION。
  • 如果要在 CPU3 显示或配置 HART tag、地址、E+H 模式、DD 参数，则属于 CPU2/CPU3 共享协议变化，必须同步 CPU2 和 CPU3 的 DEVICE_PROTOCOL_VERSION。
  • 如果新增或改变 DeviceParameters 字段，必须评估 DEVICE_PARAM_VERSION、旧 FRAM 是否加载失败、升级是否会恢复出厂参数。

7. 推荐落地计划

阶段 目标 主要动作 退出标准
阶段 0 库兼容性验证 获取 M4/GCC/hard-float 库或源码；最小工程链接 hrtInit、hrt5msCycle、hrtGetChar。 当前工具链可稳定链接，无浮点 ABI 错误。
阶段 1 HAL 端口层 实现 USART2 收发、PB7 RTS、TX 完成回接收、5ms tick。 逻辑分析仪可看到前导符、RTS 时序和完整响应帧。
阶段 2 标准 HART 命令 接通 0/1/2/3/6，PV/SV/TV/FV 和电流来自当前测量快照。 HART 主站读取基本变量正常，AD5421 电流一致。
阶段 3 DD 私有命令 移植 170/171/172/175，建立参数、结果、命令映射表。 读写参数、读取结果、下发命令都有明确响应码和状态限制。
阶段 4 E+H 兼容 实现 194/195，完成 E+H 地址表和命令码映射。 E+H 设备或主站能读取关键地址并触发液位/水位/密度命令。
阶段 5 文档和版本收口 补映射表、联调记录、协议影响、参数升级说明和测试报告。 代码、文档、版本影响判断一致。

8. 验证清单

构建验证
  • 确认 HART 库和当前工具链 ABI 匹配。
  • 运行 cmake --build build\LTD_MAIN_CPU2。
  • 检查 map 文件中 HART 库符号是否按预期链接。
协议帧验证
  • 命令 0/1/2/3/6 golden frame。
  • 私有命令 170/171/172/175/194/195 golden frame。
  • 错误帧、短地址、长地址、BCC、长度异常。
硬件时序验证
  • USART2 1200 波特率和奇偶校验。
  • RTS 发送前拉低、最后一位发完后拉高。
  • HART 调制解调器载波和前导符数量。
E+H 联调验证
  • 读 0x037200、0x037E00、0x03DA00。
  • 下发 1334、1336、1374、1390、1690/1691。
  • 确认 E+H 主站状态码和测量结果刷新符合预期。
业务安全验证
  • 非待机状态写参数被拒绝。
  • 命令只进入主循环，不在中断里直接执行。
  • 错误状态和取消命令不会导致电机异常动作。
参数兼容验证
  • HART 参数 CRC 错误时恢复默认或上报明确错误。
  • 如改变 DeviceParameters，验证旧 FRAM 升级路径。
  • CPU3 是否需要显示/配置 HART 参数已经明确。
