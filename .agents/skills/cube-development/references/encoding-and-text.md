# 编码、中文和显示文字

## 编码安全

- 修改已有文件时保留原编码和换行风格。
- 避免使用会静默转换编码、导致中文乱码的写入方式。
- 不要为了“修复乱码”批量转换文件编码，除非用户明确要求。
- 对已经存在历史乱码的文件，只做局部必要修改，不重写整文件。
- 修改含中文的文件后，要确认中文内容仍能正确显示。
- 如果文件编码不明确，先检查再做大范围编辑。
- 在 CPU2/CPU3 既有源码里写入中文前，先用字节检测确认编码。
- 能按 GBK 正常解码的文件，写回时必须继续使用 GBK/936，例如 PowerShell 的 `[Text.Encoding]::GetEncoding(936)` 配合 `[IO.File]::ReadAllText/WriteAllText`。
- 避免用 `Set-Content`、`Out-File`、PowerShell 管道传递中文脚本、或默认 UTF-8 的脚本去改 GBK 文件；这些方式容易把中文写成两个英文问号、替换字符或 UTF-8/GBK 混合内容。
- 新增源码文件如果会被 GBK 源码 include，且包含中文宏、中文注释或中文打印，优先按 GBK 创建。
- 文档、skill、工具脚本等已确认是 UTF-8 的文件按 UTF-8 维护。
- 修改后同时检查工作区和暂存区：工作区用原编码解码确认没有两个英文问号、`U+FFFD`、替换字符加问号；提交前还要检查 `git diff --cached`。
- Windows 下父脚本捕获子进程输出时，显式统一 UTF-8，例如设置 `PYTHONIOENCODING=utf-8`，或在 Python入口调用 `sys.stdout.reconfigure(encoding="utf-8")`；不要让父进程固定按 UTF-8 解码而子进程仍输出 CP936。
- 新增真实子进程回归测试时同时验证终端直出和 PIPE 捕获两种模式，避免“检查通过但中文输出乱码”。

## PowerShell 读取和搜索

- 在 PowerShell 中搜索源码时，优先把目录传给 `rg`，例如 `rg -n "关键词" LTD_DISPLAY_CPU3/Application/display`。
- 需要按扩展名过滤时使用 `rg -g '*.c' -g '*.h' "关键词" <目录>`，不要把 `LTD_DISPLAY_CPU3\Application\display\*.c` 当作路径参数传给 `rg`。
- 遇到 `os error 123` 时，先检查是否把 Windows 反斜杠 glob 当成了文件路径；改用目录搜索或 `-g` 过滤。
- 读取 UTF-8 文档时优先显式指定 UTF-8；读取 GBK 源码时使用 936 编码，不要依赖终端默认编码。
- 终端显示中文乱码时，不要把乱码内容当作业务证据；先用正确编码重读文件，或暂时以符号名、调用点、行号和二进制检查作为证据。
- 如果只需要定位函数、宏、寄存器或调用链，优先搜索英文符号名，减少中文终端渲染对判断的影响。

## 中文注释和日志文字

- 对重要业务逻辑、复杂分支、非显然算法和项目特定行为，添加简洁中文注释。
- 新增函数必须添加中文函数注释，说明用途、调用场景、关键约束；如果可能在中断上下文调用，要明确是否只记录、不打印、不阻塞。
- 修改已有函数中的关键判断、提前返回、故障恢复、命令切换、硬件状态判定和错误传播语句时，也要补充简洁中文内部注释，说明“为什么这样处理”。
- C/C++ 源码注释必须使用 `/* ... */` 块注释格式，满足 SIL 编程规范；不要新增 `//` 行注释。
- 单行短注释写成 `/* 说明 */`，行尾说明写成 `code; /* 说明 */`，多行函数说明写成普通块注释：
  ```c
  /*
   * 函数用途：说明函数负责的业务动作。
   * 调用场景：说明由哪个流程或中断/任务调用。
   * 关键约束：说明阻塞、打印、硬件状态或错误传播限制。
   */
  ```
- 批量生成或转换注释后，对目标 `.c/.h` 范围做原始文本扫描，确认没有新增 `//`；如块注释内部的旧调试文本含 `//`，也改写为 `/* ... */` 或移除双斜杠文本，避免 SIL 文本规则误报。
- 新增或修改现场打印时尽量使用中文；日志详情字段也尽量中文，例如 `长度=`、`地址=`、`功能码=`、`起始地址=`、`抑制=`。
- 不要给显而易见的赋值、简单包装或自解释代码添加空泛注释；注释应解释现场语义、硬件约束、状态机约束或错误归因。

## 显示字库

- 每次新增或修改 CPU3 显示内容、状态栏文字、详情行、菜单文案、提示语或故障原因中文时，必须同步检查显示字库。
- 重点检查 `StockMap`、`WordStock`、`WordStock2` 及对应索引，确认所有新增汉字都有点阵。
- 发现缺字时先明确列出缺失汉字和建议索引，等用户补字库后再继续显示落地。

## 文件命名

- 新生成的文档类文件优先使用中文文件名，包括 `.md`、`.pdf`、`.docx`、`.xlsx` 等。
- 技术词如 `CPU2`、`UART6`、`TMC5130` 可保留英文和数字。
- 避免 `fault_retry_log_summary.md` 这类英文摘要名，除非是工具或外部接口强依赖。
