## 阶段判定

- 按完整请求和已有授权判断，不用单个关键词覆盖整句话。“检查问题并修复”授权分析、实现和必要验证；只要求解释、审查或“先分析、不修改、等我审批”时保持只读。
- 只要求规划或方案时，仅交付用户要求的方案资料，不把建议写成已实现事实。明确要求方案后继续实现时，按已授权的完整目标推进。
- 实现授权包含为完成目标所需的局部修改、相关验证和本次改动导致的修复；文件边界可从目标和现有调用链推导，无需用户逐个批准文件。
- “升版、暂存、提交、amend、发布”进入发布阶段；重新读取 Git/版本 references，不沿用实现阶段的旧快照。
- “继续”承接已授权的整体目标；只有用户明确设置的审批点才要求阶段确认。不增加未授权的分册、版本、提交或推送。
- “先输出理解，我来纠正”保持只读，先列事实、推断、矛盾和待确认项；收到纠正后重新形成基线再写入。
- 用户中途停止、缩小范围或替换目标时，立即停止旧范围的新写入；补充问题、纠正或状态询问默认是对当前目标的补充，回答后继续未完成工作。
- 已有授权持续有效。缺少会改变产品语义、安全动作、兼容性或写入权限的决定时，只暂停依赖该决定的动作，并指出具体规则、影响和所缺信息；可独立完成的已授权工作继续进行。

## 事实裁决

按所回答的问题选择证据，不把需求决定、程序实现和现场现象排成统一优先级：

- 目标与授权：以用户最新明确决定为准；已批准且仍适用的需求、协议和设计定义预期行为。用户决定可以修订目标，不等于程序已经实现该目标。
- 程序实现：以问题所对应版本的源码、配置和调用链为准。说明当前行为时区分 HEAD、暂存区和工作区；解释旧现场行为时先核对现场固件对应的历史实现，再比较当前版本。
- 现场现象：以对应设备、时间和配置的原始日志、抓包及测量记录为准。源码可解释触发条件，不能代替未采集的现场值；当前源码也不能否定旧版本已经记录的现象。
- 验证结论：构建、测试、渲染和硬件证据只证明其实际覆盖的输入、版本和条件，不能跨版本或跨验证层级复用。
- 旧对话、记忆和计划可用于寻找线索；缺少对应原始资料时说明证据缺口，不把推测写成已验证事实。

发现预期行为、实现和现场证据冲突时，分别列出其版本、来源和影响，指出缺少的证据或产品决定。正式文档可能正是待纠正对象；不得用旧资料覆盖新决定，也不把目标设计写成当前实现。

## 最小范围台账

局部只读任务只需定位相关资料，必要时核对 Git 状态；不要求固件版本、全工程地图或 JSON。局部写入核对 Git 三层状态、编码和文件范围，按 `AGENTS.md` 执行目录门禁及租约。

长任务、跨仓库、发布或需恢复的任务使用上下文快照，按实际关联记录以下信息；与任务无关的设备、版本或仓库不扩大盘点：

- 本轮目标、交付物和明确不做的内容。
- 当前阶段允许的动作：只读、方案资料、实现、升版、暂存、提交或推送。
- 目标文件、业务调用链和关联仓库。
- staged、unstaged、untracked、删除和混合状态文件。
- 用户改动、其它任务改动、本轮改动及本机不提交资料。
- 当前版本轴、已有验证、证据边界和下一步。
- 用户已确认决定、仍在使用的假设、开放问题和已经被新决定替代的旧结论。
- 当前事实所依据的源码提交、文档版本、现场固件、原始证据和最近批准交付物。

审查“本次改动”时明确采用 HEAD、index、worktree 或指定提交。目标文件为 `MM`、`AM` 等混合状态时分别读取 cached 和 worktree diff。

## 并行工作和长任务恢复

- 未执行写入时 Git 状态或文件哈希发生变化，视为存在并行任务；重新锁定边界，只继续安全分离的文件。
- 同一路径只允许一个写入者；路径不重叠且依赖可分离的任务按租约协作。独立审查者默认只读，共享生成源、正式产物、构建目录及 Git 暂存/提交操作不得并发写入。
- 需要写入的非简单任务先运行 `scripts/manage_task_lease.py --action acquire` 声明最小写入路径。路径与活动租约重叠时不得继续写入；独立改动优先切换到 `.worktrees/`，无法隔离时等待原任务关闭租约。
- 租约只声明写入所有权，不代表文件内容正确、允许提交或获得了发布授权。任务正常收尾使用 `--action close` 把自己的租约标为关闭，不删除其它任务记录。
- 不通过 reset、checkout、覆盖、清理或重新生成来消除其它任务改动。
- 长任务、跨仓库和发布任务使用 `scripts/snapshot_cube_context.ps1` 保存可恢复状态；跨仓库时显式传入 `-RelatedRepoPath`。示例：

  ```powershell
  & .\.agents\skills\cube-development\scripts\snapshot_cube_context.ps1 `
    -RepoRoot D:\CUBE `
    -OutputPath tmp\<任务号>\cube-context.json `
    -TaskId <任务号> `
    -Objective "<当前目标>" `
    -Stage "<read-only|plan|implement|release>" `
    -AllowedPath @("<允许路径>") `
    -ExcludedPath @("<保留路径>") `
    -CompletedCheck @("<已完成检查>") `
    -OpenRisk @("<开放风险>") `
    -ConfirmedDecision @("<用户已确认决定>") `
    -Assumption @("<仍在使用的假设>") `
    -OpenQuestion @("<开放问题>") `
    -SourceBaseline @("<事实来源和版本>") `
    -LastApprovedDeliverable "<最近批准交付物>" `
    -WritePath @("<最小写入路径>") `
    -WatchPath @("<恢复前必须核对哈希的文件>") `
    -NextStep "<下一步>" `
    -RelatedRepoPath @("<关联仓库绝对路径>")
  ```
- 上下文压缩或任务恢复后，有任务 JSON 时先运行 `scripts/check_context_snapshot.py --snapshot <任务JSON>`；没有快照时重新核对目标、相关文件和 Git 状态，不声称旧证据仍有效。相关基线变化时先锁定边界，不直接续写。
- 正式产物或生成源哈希变化后，依赖旧哈希的渲染、页级验收或构建结论失效；只重跑受影响链路，不重复已证明未变化的范围。

## 用户用语和目录语义

- “Git库文档区、项目正式文档区、我的Git库中的文档”指 `docs/`。
- “本机预览”指 `docs-site/`；它不是业务事实来源。
- “临时产物”指 `tmp/<任务号>/`；“长期本机证据”指 `outputs/<任务号>/`。
- `docs/00_程序流程导航/` 和 `tools/` 本机维护但不提交。
- “我的库、文档区域、资料库”等仍可能对应多个位置时，先检查当前项目语境；无法唯一确定再询问，不自行移动到 Windows Documents、云端库或其它仓库。

## 计划外问题

- 属于当前目标且不扩大用户授权的缺陷，可以补入范围并说明。
- 只相关但不属于当前交付物的问题，记录证据、影响和建议，不顺手修改。
- 需要改变尚未确认的产品语义、硬件动作、协议兼容、存储迁移、版本或提交范围时，明确决策点；用户已经批准的同一决定不重复确认。

## 按任务类型完成

| 任务类型 | 最低完成条件 |
| --- | --- |
| 只读分析 | 相关证据、事实与推断分离、结论和实际未决项；不运行固件构建 |
| 文字或注释调整 | 编码、最终 diff、相关链接或格式检查；不新增镜像实现的测试 |
| 固件行为修改 | 最终 diff、相关静态检查、行为测试和受影响固件构建；开发中可增量构建 |
| 工具或检查器修改 | 受影响逻辑的回归测试，不触发固件构建 |
| 参数修改 | 入口、校验、持久化、运行态、消费点、启动加载和迁移 |
| 协议修改 | 通信两端、帧与状态、异常、兼容性、版本和真实联调边界 |
| 文档修改 | 正式来源、路径、链接、结构、必要的全本或视觉检查，不默认生成 PDF |
| 故障分析 | 触发时间线、为何之前未触发、底层原因、影响和证据边界 |
| 提交 | all/scoped 范围、完整四段式正文、版本标题、提交后剩余状态；固件相关提交执行最终源码的 clean-first 门禁 |
| 发布 | 版本、协议、存储、CHANGELOG、方案、构建、产物和 Git 范围一致 |

必要检查通过后结束验证；只因输入变化、失败或具体未决风险重跑受影响链路。实际缺少的硬件、台架和现场证据按影响说明，不把软件验证扩大为设备结论。
