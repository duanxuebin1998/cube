# CUBE docs-site 本机预览

## 权威边界

- `docs/` 是正式业务源；`docs-site/` 只负责同步、索引、搜索、样式和本机阅读体验。
- `src/content/docs/repository`、归档副本、索引和 `dist` 等生成内容不作为业务事实来源，不手工修正源内容。
- 正式内容先在 `docs/` 修改，再通过生成器同步到预览层。

## 受控构建

- 使用 `docs-site` 当前维护说明规定的同步、稳定构建和验证入口，不绕过外层资源/进程保护直接拼接长命令。
- 开始前记录工作树指纹、源文档哈希和现有预览进程；结束时记录构建指纹、退出码和残余进程。
- 外层 fail-closed 包装器失败时检查内层任务的真实退出码、日志和产物，不能把包装器状态直接等同于内容构建失败或成功。
- 工作区或生成源变化后，旧 `dist`、旧搜索索引和旧视觉结果失效，必须重新同步和验证。

## 固定预览

- CUBE 本机正式预览入口使用 `http://127.0.0.1:4330/`。
- 使用 `Manage-DocsSitePreview.ps1` 管理启动、停止和状态；端口被占用时先识别进程和所有者，不用其它端口掩盖旧进程问题。
- 启动后检查HTTP 200、页面版本/指纹、当前工作树一致性和关键页面；结束时确认没有孤儿Node、锁文件或残留子进程。

## 修改和验证

- 生成器问题修改生成源和回归测试，不在生成结果中补丁式修复。
- 内容同步检查目录页、版本目录、相对链接、图片、HTML嵌入、搜索索引和移动端布局。
- 样式或交互修改执行受影响页面视觉检查、键盘/焦点和移动端检查；构建成功不能替代浏览器验证。
- 预览层默认不进入 Git，不作为发布网站或外发资料；需要改变这一边界时先取得明确批准。

## 完成定义

- 正式内容仍以 `docs/` 为唯一来源，生成结果可由受控命令重复得到。
- 构建和预览对应当前源指纹，固定端口可访问，验证结果和已知失败明确分开。
- 预览生命周期已收尾，没有用旧产物或残留服务冒充当前验证。
