# CPU2/CPU3 共享协议、参数存储和运行态

## 协议版本

- CPU2 和 CPU3 固件版本独立；固件版本不用于判断板间协议兼容。
- CPU2/CPU3 共享契约使用 `DEVICE_PROTOCOL_VERSION`。
- 共享版本通过 `DeviceParameters.protocolVersion` / `HOLDREGISTER_DEVICEPARAM_PROTOCOL_VERSION` / `COM_NUM_DEVICEPARAM_PROTOCOL_VERSION` 发布和读取；旧程序未写入时通常为 0。
- 修改共享寄存器、结构字段、命令、状态、错误码或字段解释时，两端同步提升协议版本，并保持严格相等判断。
- 不使用固件 major/minor 或 `>=` 替代共享协议版本检查。

## 共享契约检查

检查最终 diff 是否改变：

- 共享 Modbus 地址、长度、功能码或异常响应。
- `DeviceParameters` 字段、结构大小和 CRC 范围。
- signedness、单位、倍率、范围、默认值和补码解释。
- 命令码、ACK、状态位、错误码和完成条件。
- CPU3 对 CPU2 快照、参数、状态和错误的消费方式。
- 外部协议依赖的共享数据容量或生命周期。

发生变化时同步：CPU2/CPU3 定义与解析、运行期版本检查、协议变更记录、受影响固件版本、兼容性说明和双端测试。协议变更记录写清首个匹配 CPU2/CPU3 固件版本及旧组合的拦截行为。

## 网关和快照语义

- CPU2 是业务数据和动作的权威端；CPU3 可从已确认快照响应外部读取，但不能把未确认缓存伪装成最新值。
- 写命令必须等待 CPU2 ACK 后再向外成功；ACK 失败或超时不得先修改本地镜像。
- 写成功后使相关快照失效并补读；补读完成前按协议返回忙或明确不可用状态。
- CPU2断线、协议不匹配、快照未建立或参数刷新中时，不返回陈旧数据。
- 检查三路外部 COM、CPU3 周期轮询和写事务之间的仲裁，避免把外部高频请求直接放大到 UART5。

## 参数是否生效

参数任务必须追踪：

1. 菜单、寄存器、命令或默认表入口。
2. 类型、范围、单位和归一化。
3. FRAM/Flash 写入、写后读回和失败回滚。
4. 实际运行态变量或快照。
5. 业务消费点。
6. 上电加载、迁移和恢复默认。

写入持久化成功但未同步运行态时，只能说明“重启后生效”；不要依据菜单读回或寄存器存在判断立即生效。

## CPU2 参数存储兼容性

- 修改 `DEVICE_PARAM_VERSION`、`DeviceParameters`、`struct_size`、`magic`、CRC范围、A/B区加载或恢复出厂逻辑时，逐版本判断旧 FRAM 是否能迁移。
- 参数存储版本提升不等于固件必须升 `MAJOR`：能可靠迁移且不清现场参数时通常按功能影响升 `MINOR`。
- 无法兼容加载、升级会恢复出厂或必须重新下发现场参数时，固件升 `MAJOR`，并在执行前明确告知用户。
- 复用 `reserved*`、新增字段或改变默认值时，优先提供旧版本迁移和新字段补默认值，避免无必要清参。
- `CHANGELOG.md` 维护 CPU2 程序版本与 `DEVICE_PARAM_VERSION` 对照；升级清参时写清旧版本范围、原因、升级前备份和升级后复核/下发动作。

## 测试重点

- 双端版本相同和不同时的启动/运行行为。
- 完整参数快照、写入 ACK、失败回滚和补读。
- 最小/最大/负数补码、单位倍率和历史存储值。
- 冷启动、掉电中断、CRC损坏、A/B区回退和恢复出厂。
- CPU2忙、断链、坏帧、重复命令和多端口并发。
- 版本文档中的参数结构大小、存储版本和清参结论与代码一致。
