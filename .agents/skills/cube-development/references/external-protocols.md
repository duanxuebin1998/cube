# 外部协议适配、协议卷和工具闭环

## 适用协议

覆盖 CPU3 对外 DSM、Wartsila、SI、LTD 标准 Modbus、协议切换，以及 CPU2 调试串口命令和现场兼容协议。CPU2/CPU3 板间共享协议读取 `internal-protocol-and-storage.md`；其中 LTD 标准 Modbus 的共享区与板间共享契约是同一协议，不是独立适配映射。

## 证据和实施状态分离

每个协议结论同时标注两类状态：

**依据类型**

- 正式协议或供应商资料。
- 现场抓包/真实设备行为。
- 当前源码和测试。
- 用户已确认的产品决定。
- 推测或建议。

**实施状态**

- 当前已实现。
- 用户已批准、待实现。
- 待抓包/待资料/待决策。
- 明确暂缓或不支持。

不要用“已确认”同时表达抓包已证实和用户已批准；抓包分析页只记录现场事实，设计方案页记录产品决定，不把后续设计反写成原始抓包事实。

## 全量盘点

全协议整理或整体评审时盘点以下链路；局部适配或问题分析只检查与目标相关的层次及依赖，不因读取本参考自动扩大范围：

1. 物理层：端口、波特率、数据位、校验、停止位、站号和帧间隔。
2. 帧层：功能码、长度、CRC、字节序、广播和异常响应。
3. 地址层：线圈、离散量、保持/输入寄存器、私有字段和保留区。
4. 行为层：读、写、命令 ACK、取消、忙、失败和重试。
5. 生命周期：启动、测量、Profile、Point0、进度、完成、旧结果和报警发布。
6. 参数：默认值、范围、单位、signedness、持久化、迁移和恢复默认。
7. 状态/报警：来源、快照一致性、无效值和跨 CPU 传递。
8. 兼容性：当前偏差、现场依赖、旧主机行为和明确不支持项。
9. 交付物：正式协议卷、映射表、抓包证据、工具/配置、生成说明和联调测试。

用户说“整理全部方案”时，先生成这份清单，再写正文；不能从最近讨论的几个寄存器向外推断全部范围。

## 适配原则

- 外部协议优先由 CPU3 做转换；CPU2只新增真实业务所需的最小共享数据和命令。
- CPU2业务动作和数据是权威端；CPU3读取可使用已确认快照，写操作必须获得 CPU2 ACK。
- CPU3断链、快照无效、协议不匹配或参数刷新中时返回明确忙/失败，不返回旧数据或伪成功。
- 未知字段可以做本地兼容影子，但不得猜测业务含义或参与控制；读写、范围和持久化策略必须由用户确认。
- LTD 标准 Modbus 的共享保持寄存器、共享输入寄存器、命令值和字段语义直接跟随 CPU2/CPU3 共享契约；修改这些对象时同步两端源码、CPU3 对外响应、`DEVICE_PROTOCOL_VERSION`、正式协议资料和契约测试，不得只改板间或对外一侧。
- CPU3 本机 `0x7000` 高地址段不属于 CPU2/CPU3 共享区；只改该段时按 CPU3 对外行为处理，不自动提升 `DEVICE_PROTOCOL_VERSION`。
- 除 LTD 共享区外，DSM、Wartsila、SI 等外部适配行为变化只影响相关 CPU 的固件版本；固件升版在提交/发布或用户明确要求时执行。只有 CPU2/CPU3 共享契约变化时才同步提升 `DEVICE_PROTOCOL_VERSION`。

## 协议设计负面检查

- 请求原帧回显不能被上位机当作设备 ACK；应答格式应可区分。
- 修改串口参数前等待旧参数应答发送完成；切换后不得继续用旧参数接收并把旧帧交给新解析器。
- DMA/UART续发失败、超时和保存失败要取消 pending 状态并回滚。
- FRAM保存要有写后读回或可验证结果；运行期成功但持久化失败不能打印永久保存成功。
- 同一端口协议切换不影响其它端口；多端口写请求需要仲裁。
- 上位机工具覆盖本地回显、非标准参数、超时、目标参数复验和退出码。

## 协议文档结构

正式协议方案优先按以下顺序：

1. 一页结论、目标状态和适用版本。
2. 当前实现—现场设备—目标方案总矩阵。
3. 全量唯一项目清单，每项有编号、依据类型和实施状态。
4. 关键状态机或时序。
5. 分批实施包、代码边界和版本影响。
6. 可执行验收矩阵。
7. 待抓包、待用户决策、明确暂缓三张独立清单。
8. 详细地址和抓包证据放入附录或可展开区。

HTML页面要先呈现决策，再下钻证据；不要把历史实现说明、抓包事实和未来建议堆在同一主表。

## 交付物闭环

协议行为改变后按需要同步：

- 正式协议卷和地址映射。
- 受控偏差/兼容性清单。
- golden frame、契约测试和异常帧。
- 上位机工具、串口助手配置或PLC示例。
- 配置生成脚本及“下次如何生成”的维护说明。
- 联调测试清单、真实硬件未验证项和版本影响。

生成的 JSON/配置应以脚本或明确维护源为唯一来源，检查仓库版与现场/桌面版一致；不要只交付一次性手改文件。

## 格式技能路由

- 编辑 `.docx`、`.xlsx` 或复杂 HTML 时，同时使用对应文档、电子表格或浏览器/站点技能完成格式与视觉检查。
